Terraform root configuration for managing centralized AWS infrastructure state and cross-account IAM access for the Fleet MDM load testing environment.

## Key Components

| Resource | Description |
|---|---|
| `provider "aws"` (primary) | AWS provider targeting `us-east-2` (primary region) |
| `provider "aws" (replica)` | AWS provider targeting `us-west-1` for S3 state replication |
| `backend "s3"` | Remote state stored in S3 with DynamoDB locking and KMS encryption |
| `module.remote-state-s3-backend` | Provisions encrypted S3 bucket + DynamoDB lock table via `nozaq/remote-state-s3-backend` |
| `local.accounts` | Map of 7 AWS account IDs (dogfood, loadtesting, fleet-cloud, etc.) |
| `aws_iam_role.main` | Per-account IAM roles (`terraform-<account>`) allowing cross-account assume-role |
| `aws_iam_policy.main` | Per-account policies granting scoped S3, DynamoDB, and KMS permissions |

## Usage Example

Each child account assumes its corresponding IAM role to read/write Terraform state scoped to its own prefix:

```bash
# Assume the cross-account role from a child account (e.g., dogfood)
aws sts assume-role \
  --role-arn arn:aws:iam::<root-account-id>:role/terraform-dogfood \
  --role-session-name tf-session

# Initialize Terraform using the shared S3 backend
terraform init \
  -backend-config="key=dogfood/unique_key/terraform.tfstate"
```

## Notes

- State is encrypted at rest using KMS key `9f98a443-ffd7-4dbe-a9c3-37df89b2e42a`
- Each account's IAM policy restricts S3 access to its own prefix (`<account-key>/*`)
- DynamoDB table `tf-remote-state-lock` prevents concurrent state modifications
