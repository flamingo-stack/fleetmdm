Terraform configuration that provisions AWS GuardDuty alerting infrastructure, routing security findings to a Slack channel via SNS and Lambda.

## Key Components

| Component | Description |
|---|---|
| `provider "aws"` | Targets `us-east-2` with default environment tags |
| `backend "s3"` | Remote state stored in S3 with DynamoDB locking and KMS encryption |
| `variable "slack_webhook"` | Required input for the Slack incoming webhook URL |
| `module "guardduty-to-sns"` | Uses [`rhythmictech/guardduty-to-sns`](https://registry.terraform.io/modules/rhythmictech/guardduty-to-sns/aws) to forward GuardDuty findings to an SNS topic |
| `module "notify_slack"` | Uses [`terraform-aws-modules/notify-slack`](https://registry.terraform.io/modules/terraform-aws-modules/notify-slack/aws) to deliver SNS messages to `#g-infra` via Lambda |

## Usage Example

```bash
# Initialize with remote S3 backend
terraform init

# Select or create a workspace (used to namespace SNS topic and Lambda)
terraform workspace select production

# Apply, supplying the required Slack webhook
terraform apply -var="slack_webhook=https://hooks.slack.com/services/..."
```

## Notes

- **Workspace-scoped naming:** Both the SNS topic and Lambda function are named `guardduty-<workspace>`, allowing multi-environment deployments from the same configuration.
- **Alert destination:** Findings are posted to the `#g-infra` Slack channel under the username `monitoring`.
- **AWS provider:** Pinned to `~> 4.62.2` for stability.
- **Source reference:** [`flamingo-stack/fleetmdm`](https://github.com/flamingo-stack/fleetmdm) — see `infrastructure/guardduty-alerts/` for the full module context.
