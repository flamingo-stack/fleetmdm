Terraform configuration for AWS spend alerting infrastructure that monitors estimated AWS charges and delivers anomaly-based billing alerts to a Slack channel.

## Key Components

| Component | Type | Description |
|-----------|------|-------------|
| `aws` provider | Provider | Targets `us-east-1` with default environment and ownership tags |
| S3 backend | Remote State | Stores Terraform state in `fleet-terraform-state20220408141538466600000002` with DynamoDB locking and KMS encryption |
| `notify_slack` | Module | [`terraform-aws-modules/notify-slack`](https://registry.terraform.io/modules/terraform-aws-modules/notify-slack/aws/6.0.0) — creates an SNS topic and Lambda to forward alerts to `#g-infra` |
| `aws_cloudwatch_metric_alarm.total_charge` | Resource | Watches `AWS/Billing > EstimatedCharges` (USD, daily max) and triggers when the value exceeds the anomaly detection band |
| `var.slack_webhook` | Variable | Required string — Slack incoming webhook URL passed at apply time |
| `output.slack_topic_arn` | Output | Exposes the SNS topic ARN created by the notify-slack module |

## Usage Example

```bash
# Initialize with the remote S3 backend
terraform init

# Plan, supplying the required Slack webhook
terraform plan -var="slack_webhook=https://hooks.slack.com/services/XXX/YYY/ZZZ"

# Apply
terraform apply -var="slack_webhook=https://hooks.slack.com/services/XXX/YYY/ZZZ"
```

## Alarm Logic

```text
metric  : AWS/Billing > EstimatedCharges (USD, 86400 s period, Maximum stat)
detector: ANOMALY_DETECTION_BAND(m1, 2)   ← 2 standard-deviation band
trigger : GreaterThanUpperThreshold        ← fires when charge exceeds upper bound
actions : SNS → Lambda → Slack #g-infra   ← on ALARM and on OK recovery
```

> **Note:** The `slack_webhook` variable is sensitive. Pass it via `-var` flag, a `.tfvars` file, or an environment variable (`TF_VAR_slack_webhook`) rather than committing it to source control.
