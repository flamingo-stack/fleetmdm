Terraform configuration that provisions AWS CloudTrail organization-wide audit logging, including an S3 bucket for log storage and the CloudTrail trail resource itself, with state stored remotely in S3.

## Key Components

- **S3 Backend** — Remote state stored in `fleet-terraform-state20220408141538466600000002` with DynamoDB locking and KMS encryption in `us-east-2`.
- **`aws.security` Provider** — A secondary AWS provider that assumes the `admin` role in account `353365949058`, used specifically for creating the log bucket.
- **`module.cloudtrail`** — Uses `terraform-aws-modules/s3-bucket/aws` to create a private, versioned S3 bucket (`fleet-cloudtrail-logs`) with all public access blocked.
- **`data.aws_iam_policy_document.cloudtrail`** — IAM policy granting the `cloudtrail.amazonaws.com` service principal `s3:GetBucketAcl` and `s3:PutObject` on the log bucket. Source ARN conditions are present but commented out.
- **`resource.aws_cloudtrail.main`** — Enables a multi-region, organization-wide CloudTrail trail with log file validation, writing to the S3 bucket prefixed by the current account ID.

## Usage Example

```bash
# Initialize with the S3 backend
terraform init

# Review planned changes
terraform plan

# Apply (assumes AWS credentials with rights to assume terraform-root role)
terraform apply
```

```bash
# To target a specific workspace
terraform workspace select <workspace_name>
terraform plan
```

## Notes

- The `aws_organizations_organization` and `aws_caller_identity` data sources are used to scope policies and S3 key prefixes to the current org and account.
- Source ARN conditions on the S3 bucket policy are commented out — uncomment and test before enabling in production to restrict CloudTrail write access per-account.
- Default tags applied to all resources include `environment`, `terraform` source URL, and remote state path for traceability.
