Terraform configuration that provisions an EC2 instance and associated security group for the `fleetbot` service on AWS.

## Key Components

- **`aws_instance.fleetbot`** — Deploys a `t3.medium` Ubuntu 24.04 LTS instance (AMI `ami-0d1b5a8c13042c939`, us-east-2) into the first private subnet of the VPC module, with a 50 GiB root volume and an SSH key named `dogfood-fleetbot`.
- **`aws_security_group.fleetbot`** — Creates a security group scoped to the module VPC, tagged `<customer>-fleetbot-sg`.
- **`aws_vpc_security_group_ingress_rule.fleetbot_ssh`** — Allows inbound SSH (TCP port 22) only from the `10.255.0.0/16` CIDR (internal network).
- **`aws_vpc_security_group_egress_rule.fleetbot_any`** — Permits all outbound traffic (`0.0.0.0/0`, protocol `-1`).

## Usage Example

```bash
# Plan and apply the EC2 resources
terraform plan -target=aws_instance.fleetbot
terraform apply -target=aws_instance.fleetbot
```

Ensure the `module.main` VPC module is initialized and `local.customer` is defined in your locals before applying:

```hcl
locals {
  customer = "flamingo"
}
```

> The instance is placed in a **private subnet** with no direct internet ingress. SSH access is restricted to internal IP range `10.255.0.0/16`, suitable for access via a bastion host or VPN.
