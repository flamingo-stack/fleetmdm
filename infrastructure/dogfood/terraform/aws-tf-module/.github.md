Configures AWS IAM OIDC federation for GitHub Actions, enabling keyless authentication from CI/CD pipelines by trusting GitHub's token issuer and granting broad AWS service permissions to the assumed role.

## Key Components

| Resource / Data Source | Purpose |
|---|---|
| `tls_certificate.github` | Fetches the TLS certificate from GitHub's OIDC discovery endpoint to extract the SHA-1 thumbprint |
| `aws_iam_openid_connect_provider.github` | Registers GitHub Actions as a trusted OIDC identity provider in AWS IAM |
| `aws_iam_role.gha_role` | IAM role (`github-actions-role`) assumed by GitHub Actions workflows via web identity |
| `aws_iam_role_policy.gha_role_policy` | Attaches the permissions policy inline to the GHA role |
| `gha_assume_role` (policy document) | Trust policy restricting `AssumeRoleWithWebIdentity` to the `fleetdm/fleet` repository |
| `gha-permissions` (policy document) | Grants broad AWS service access plus the ability to assume a specific Terraform role |

## Usage Example

After applying, configure your GitHub Actions workflow to assume the role:

```yaml
permissions:
  id-token: write
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::<ACCOUNT_ID>:role/github-actions-role
          aws-region: us-east-1
```

## Customization Notes

- **Repository scope** — the `StringLike` condition on `token.actions.githubusercontent.com:sub` is currently set to `repo:fleetdm/fleet:*`. Update this value to restrict or broaden which repos/branches can assume the role.
- **Permissions** — `gha-permissions` grants wildcard access to a large set of AWS services. Scope these down to only what your deployment pipeline requires before production use.
- **Terraform role** — the `sts:AssumeRole` statement targets a hardcoded account ID (`353365949058`) for the `terraform-dogfood` role; update to match your target account.
