Terraform root configuration for the FleetDM dogfood (staging/internal) environment on AWS, wiring together VPC, RDS Aurora MySQL, Redis, ECS Fargate, and supporting AWS services via the `fleet-terraform` module.

## Key Components

| Component | Description |
|---|---|
| `provider "aws"` | AWS provider with dogfood environment default tags |
| `backend "s3"` | Remote state stored in `fleet-terraform-remote-state` S3 bucket with DynamoDB locking |
| `module "main"` | Root fleet-terraform module (`tf-mod-root-v1.26.1`) configuring VPC, RDS, Redis, ECS, and Fleet app |
| `locals.extra_environment_variables` | Fleet app environment config: OpenTelemetry/SigNoz tracing, MySQL tuning, calendar integration, MDM flags |
| `locals.sidecars` | Alpine-based sidecar container that fetches the AWS RDS TLS CA certificate at task startup |
| `locals.geolite2_image` | Dynamically constructed ECR image tag appending `-geolite2-<timestamp>` to the Fleet image digest |

## Key Variables

| Variable | Purpose |
|---|---|
| `fleet_image` | ECR image URI for Fleet (defaults to a pinned digest) |
| `fleet_license` | Fleet EE license key |
| `otel_bearer_token` | Sensitive bearer token for SigNoz OTLP ingest |
| `cloudfront_public_key` / `cloudfront_private_key` | CloudFront signing keys for software installers |
| `fleet_calendar_periodicity` | Calendar integration refresh interval (default `30s`) |

## Usage Example

```bash
# Initialize with remote state
terraform init

# Plan with required secrets
terraform plan \
  -var="fleet_license=$FLEET_LICENSE" \
  -var="geolite2_license=$GEOLITE2_LICENSE" \
  -var="fleet_sentry_dsn=$SENTRY_DSN" \
  -var="elastic_url=$ELASTIC_URL" \
  -var="elastic_token=$ELASTIC_TOKEN" \
  -var="android_service_credentials=$ANDROID_CREDS" \
  -var="dogfood_sidecar_enroll_secret=$ENROLL_SECRET" \
  -var="cloudfront_public_key=$CF_PUB" \
  -var="cloudfront_private_key=$CF_PRIV" \
  -var="webhook_url=$WEBHOOK_URL" \
  -var="otel_bearer_token=$OTEL_TOKEN"
```

## Notes

- RDS Aurora MySQL 8.0 (`aurora.3.10.3`) uses TLS client authentication; the sidecar downloads the CA cert identified by `ca_cert_thumbprint` at container start.
- ECS tasks autoscale between 2–5 instances targeting 70% CPU/memory.
- Software installers use a versioned S3 bucket with KMS encryption and a CloudFront distribution for delivery.
