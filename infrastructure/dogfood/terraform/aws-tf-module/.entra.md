Terraform configuration that provisions AWS infrastructure for securely storing and accessing a Microsoft Entra (Azure AD) Conditional Access API key using AWS Secrets Manager and IAM.

## Key Components

| Resource | Name | Purpose |
|---|---|---|
| `variable` | `entra_api_key` | Input variable for the Entra API key value |
| `aws_iam_policy` | `entra_conditional_access` | IAM policy granting `GetSecretValue` on the secret |
| `aws_iam_policy_document` | `entra_conditional_access` | Policy document restricting access to the specific secret ARN |
| `aws_secretsmanager_secret` | `entra_conditional_access` | Secret container named `dogfood-entra-conditional-access` |
| `aws_secretsmanager_secret_version` | `entra_api_key` | Stores the base64-encoded API key as the secret value |

## Usage Example

Pass the Entra API key at apply time and attach the generated IAM policy to any role that needs to retrieve it:

```bash
terraform apply -var="entra_api_key=<your-entra-api-key>"
```

```bash
# Retrieve the secret at runtime (e.g., from an EC2 instance or Lambda with the policy attached)
aws secretsmanager get-secret-value \
  --secret-id dogfood-entra-conditional-access \
  --query SecretString \
  --output text | base64 --decode
```

## Notes

- The API key is **base64-encoded** before storage via `base64encode()`.
- Access is **least-privilege**: the IAM policy only permits `secretsmanager:GetSecretValue` scoped to this specific secret ARN.
- The secret name `dogfood-entra-conditional-access` indicates this targets a **dogfood/staging** environment.
