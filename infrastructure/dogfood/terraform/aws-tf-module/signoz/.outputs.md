Terraform outputs file that exposes key values from the EKS cluster and observability stack deployment for use by other modules or operators.

## Key Components

| Output | Description |
|---|---|
| `cluster_name` | EKS cluster name from the `eks` module |
| `cluster_endpoint` | API server endpoint for the EKS cluster |
| `cluster_certificate_authority_data` | CA certificate data for authenticating to the cluster |
| `configure_kubectl` | Ready-to-run `aws` CLI command to configure local kubeconfig |
| `signoz_ui_url` | HTTPS URL for the SigNoz observability dashboard |
| `otel_collector_endpoint` | Internal HTTPS endpoint for the OpenTelemetry collector on port 443 |

## Usage Example

After applying the Terraform configuration, retrieve outputs to connect to your cluster:

```bash
# Get all outputs
terraform output

# Configure kubectl directly
$(terraform output -raw configure_kubectl)

# Send telemetry to the OTLP collector
terraform output -raw otel_collector_endpoint
# → https://otlp.internal.example.com:443
```

To reference these outputs from another Terraform module:

```bash
module "fleetmdm_infra" {
  source = "./path/to/module"
}

locals {
  kubeconfig_endpoint = module.fleetmdm_infra.cluster_endpoint
  signoz_url          = module.fleetmdm_infra.signoz_ui_url
}
```

## Notes

- `configure_kubectl` interpolates both the current AWS region (via `data.aws_region.current`) and the cluster name at apply time.
- `otel_collector_endpoint` is intended for **internal** service-to-service communication via a private LoadBalancer hostname.
- `signoz_ui_url` and `otel_collector_endpoint` domains are derived from `local.signoz_domain` and `local.otlp_domain` respectively, defined in the module's `locals` block.
