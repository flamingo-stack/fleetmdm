Terraform configuration that deploys the FleetMDM backend as a Google Cloud Run service, along with supporting infrastructure for networking, secrets management, and IAM.

## Key Components

| Resource | Description |
|---|---|
| `google_cloud_run_service.default` | Core Cloud Run service running the Fleet backend container with H2C (HTTP/2 cleartext) on port 8080 |
| `google_compute_region_network_endpoint_group.neg` | Serverless NEG connecting the Cloud Run service to a load balancer |
| `google_cloud_run_service_iam_policy.noauth` | Grants `allUsers` the `run.invoker` role (public access via load balancer) |
| `google_secret_manager_secret.secret` | Stores the Fleet MySQL database password |
| `google_secret_manager_secret.private_key` | Stores the Fleet server private key (randomly generated) |
| `google_secret_manager_secret_iam_member` | Grants the default compute service account access to both secrets |

## Cloud Run Container Configuration

The Fleet container is configured with the following key environment variables injected at runtime:

- **MySQL**: address, username, database name, and password (via Secret Manager)
- **Redis**: host and port for caching
- **S3-compatible storage**: GCS bucket credentials via HMAC key for software installers
- **Server**: TLS disabled (terminated at load balancer), H2C forced, JSON logging enabled

Autoscaling is configured from 1 to 1,000 instances. The service runs with VPC connector egress for private network access to Cloud SQL and Redis, and ingress is restricted to internal traffic and Cloud Load Balancing only.

## Usage Example

```bash
terraform apply \
  -var="prefix=fleetmdm" \
  -var="region=us-central1" \
  -var="image=fleetdm/fleet:latest" \
  -var="fleet_cpu=2" \
  -var="fleet_memory=2Gi"
```
