Terraform configuration for provisioning Google Cloud Storage resources used by FleetMDM to store software installers, including a dedicated service account, HMAC key for S3-compatible access, and a GCS bucket with IAM bindings.

## Key Components

| Resource | Name | Purpose |
|---|---|---|
| `google_client_config` | `current` | Reads active GCP project/region from caller credentials |
| `google_service_account` | `fleet-svc` | Dedicated service account for FleetMDM storage operations |
| `google_storage_hmac_key` | `key` | HMAC key bound to `fleet-svc` for S3-compatible API access |
| `google_storage_bucket` | `software_installers` | GCS bucket storing software installer packages |
| `google_storage_bucket_iam_member` | `hmac_sa_storage_admin` | Grants `roles/storage.objectAdmin` to `fleet-svc` on the bucket |

## Usage Example

```bash
# Apply with a custom bucket name
terraform apply -var="software_installers_bucket_name=my-fleet-installers"
```

Required input variable in your `terraform.tfvars` or via `-var`:

```text
software_installers_bucket_name = "my-org-fleet-software-installers"
```

After apply, retrieve the HMAC key credentials for FleetMDM configuration:

```bash
terraform output -raw hmac_access_id
terraform output -raw hmac_secret
```

## Notes

- The bucket uses **uniform bucket-level access** (no per-object ACLs).
- `force_destroy = true` allows Terraform to delete the bucket even if it contains objects — use caution in production.
- Bucket region is inherited from the active GCP client config (`data.google_client_config.current.region`).
