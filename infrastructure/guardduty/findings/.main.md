Terraform configuration that provisions the AWS infrastructure required to store Amazon GuardDuty findings in an encrypted, private S3 bucket with remote state management.

## Key Components

**Backend & Provider**
- Remote state stored in S3 (`fleet-terraform-state20220408141538466600000002`) with DynamoDB locking
- AWS provider targeting `us-east-2`, assuming the `terraform-root` / `admin` IAM roles
- Default tags applied per workspace: `environment`, `terraform`, `state`

**IAM Policy Documents**
- `bucket_pol` — Grants `guardduty.amazonaws.com` service principal `s3:PutObject` and `s3:GetBucketLocation` on the findings bucket
- `kms_pol` — Allows GuardDuty to call `kms:GenerateDataKey`; grants the account root full KMS key management

**Resources**

| Resource | Purpose |
|---|---|
| `aws_s3_bucket.gd_bucket` | `fleet-guardduty-findings` bucket (force-destroy enabled) |
| `aws_s3_bucket_acl` | Sets bucket ACL to `private` |
| `aws_s3_bucket_policy` | Attaches GuardDuty-scoped bucket policy |
| `aws_kms_key.gd_key` | Customer-managed KMS key (7-day deletion window) |
| `aws_s3_bucket_public_access_block` | Blocks all public access |
| `aws_s3_bucket_server_side_encryption_configuration` | Enforces SSE-KMS using `gd_key` |
| `aws_s3_bucket_versioning` | Enables versioning on the findings bucket |

**Output**
- `kms_key` — Exposes the full `aws_kms_key` object for downstream reference

## Usage Example

```bash
# Initialize with the S3 backend
terraform init

# Deploy to a named workspace (sets the environment tag)
terraform workspace new prod
terraform apply
```

```bash
# Retrieve the KMS key ARN after apply
terraform output kms_key
```

> **Note:** The `deletion_window_in_days = 7` and the `kms:*` root grant are marked in-code as temporary/test configurations and should be hardened before production use. See [infrastructure source](https://github.com/flamingo-stack/fleetmdm/blob/main/infrastructure/guardduty/findings/main.tf) for the full context.
