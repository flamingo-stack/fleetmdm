Terraform root module that configures AWS GuardDuty organization-wide threat detection, including delegating administration to a security account, enabling automatic member enrollment, and publishing findings to an S3 bucket.

## Key Components

| Resource / Data Source | Purpose |
|---|---|
| `aws_guardduty_organization_admin_account.main` | Delegates GuardDuty admin to the central security account (`353365949058`) |
| `aws_guardduty_detector.root` | Enables GuardDuty in the root/management account |
| `aws_guardduty_member.root` | Enrolls the root account as a member under the security account's detector |
| `aws_guardduty_organization_configuration.main` | Auto-enables GuardDuty for all current and future organization member accounts |
| `aws_guardduty_publishing_destination.main` | Streams findings to the `fleet-guardduty-findings` S3 bucket, encrypted with a remote-state-sourced KMS key |
| `data.terraform_remote_state.findings` | Reads KMS key ARN output from the sibling `guardduty/findings` Terraform state |

## Provider Layout

Three AWS provider aliases are used:

| Alias | Region | Role |
|---|---|---|
| *(default)* | `terraform.workspace` | Root/management account operations |
| `security` | `us-east-2` | Security account, fixed region (S3 bucket lookup) |
| `security-region` | `terraform.workspace` | Security account, workspace-driven region (detector/member/config) |

## Usage Example

```bash
# Select workspace matching the target AWS region
terraform workspace select us-east-1

# Plan and apply
terraform init
terraform plan
terraform apply
```

> **Note:** The S3 backend uses workspace-prefixed state keys. Set `workspace_key_prefix` and the `key` path to match your account alias before applying to a new environment.
