Terraform entry point that provisions the `osquery-perf` load-testing addon for a Fleet MDM environment, wiring together remote infrastructure state outputs with a pinned upstream Fleet Terraform module.

## Key Components

| Element | Description |
|---|---|
| `aws_caller_identity.current` | Retrieves the active AWS account identity |
| `aws_region.current` | Retrieves the active AWS region |
| `git_repository.tf` | Reads the local Git repository root (four levels up) |
| `module.osquery_perf` | Instantiates the pinned `osquery-perf` addon from the upstream `fleetdm/fleet-terraform` registry at `tf-mod-addon-osquery-perf-v1.2.2` |

### `module.osquery_perf` Inputs

| Variable | Source |
|---|---|
| `ecs_cluster`, `vpc_subnets`, `security_groups`, `ecs_arn`, `ecs_execution_arn` | `terraform_remote_state.infra` outputs |
| `server_url` | Internal ALB DNS from remote state |
| `osquery_perf_image` | ECR repository URL tagged with `loadtest-<local.loadtest_tag>` |
| `extra_flags`, `task_size` | Input variables (`var.*`) |
| `logging_options`, `enroll_secret_arn` | Remote state outputs |

## Usage Example

```bash
# Initialize and apply from the loadtest workspace
terraform init
terraform apply -var="extra_flags=--enroll_secret=abc123" -var='task_size={"cpu":512,"memory":1024}'
```

## Notes

- Module source is **pinned** to `tf-mod-addon-osquery-perf-v1.2.2`; update the `ref` to upgrade.
- All networking and IAM resources are consumed from a shared `infra` remote state — ensure that workspace is applied first.
- The container image is expected in the sibling `aws_ecr_repository.loadtest` resource (defined elsewhere in this configuration).
