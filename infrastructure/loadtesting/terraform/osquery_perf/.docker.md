Manages Docker image building and ECR repository provisioning for load testing infrastructure. It builds a load test Docker image locally and pushes it to a dedicated AWS ECR repository with KMS encryption.

## Key Components

| Resource | Description |
|---|---|
| `aws_ecr_repository.loadtest` | Dedicated ECR repo (`<customer>-osq`) with KMS encryption and image scanning on push |
| `aws_kms_key.main` | KMS key for ECR encryption with 10-day deletion window and automatic key rotation |
| `docker_image.loadtest` | Builds the load test image from `../docker/loadtest.Dockerfile` targeting `linux/amd64` |
| `docker_registry_image.loadtest` | Pushes the built image to ECR and retains it remotely after destroy |
| `random_pet.rand_image_key` | Generates a unique suffix for the KMS key description |
| `data.aws_ecr_repository.fleet` | References the existing customer ECR repository by `local.customer` |
| `data.aws_ecr_authorization_token.token` | Retrieves ECR auth credentials for Docker provider authentication |

## Usage Example

The image is tagged using `local.loadtest_tag` and pushed to the customer-scoped ECR repository:

```text
Image name: <ecr_repo_url>:loadtest-<loadtest_tag>
Dockerfile: ../docker/loadtest.Dockerfile
Platform:   linux/amd64
Build arg:  TAG=<loadtest_tag>
```

The `keep_remotely = true` flag on `docker_registry_image` ensures the pushed image persists in ECR even when the Terraform resource is destroyed, preventing accidental image loss.

## Notes

- ECR `force_delete = true` allows repository teardown even when images are present
- `pull_parent = true` ensures the base image is always refreshed during builds
- KMS key name format: `<customer>-osq-<random_pet_id>`
