Terraform locals block that defines reusable computed values for the Fleet load testing infrastructure, scoped to the active Terraform workspace.

## Key Components

| Local | Value | Description |
|---|---|---|
| `customer` | `"fleet-${terraform.workspace}"` | Namespaced identifier combining a `fleet-` prefix with the active workspace name |
| `loadtest_containers` | `var.loadtest_containers` | Alias for the load test container count variable |
| `loadtest_tag` | `var.git_tag_branch` | Git tag or branch used to version the load test deployment |

> The `fleet_image` local is commented out — previously sourced from `var.tag`, now superseded by `loadtest_tag` via `var.git_tag_branch`.

## Usage Example

Reference these locals elsewhere in the module:

```hcl
resource "aws_ecs_service" "loadtest" {
  name    = local.customer
  # Pull image using resolved tag
  task_definition = "${local.customer}:${local.loadtest_tag}"
  desired_count   = local.loadtest_containers
}
```

Workspace-driven naming ensures isolated deployments per environment:

```bash
terraform workspace new staging
# local.customer → "fleet-staging"

terraform workspace new production
# local.customer → "fleet-production"
```

## Notes

- Workspace isolation makes `local.customer` safe to use as a unique resource name prefix across environments.
- `loadtest_tag` should align with a valid image tag pushed to your container registry.
- See [`variables.tf`](https://github.com/flamingo-stack/fleetmdm/blob/main/variables.tf) for the upstream variable definitions driving these locals.
