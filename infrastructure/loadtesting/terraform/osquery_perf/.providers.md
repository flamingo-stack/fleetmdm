Terraform provider and backend configuration for the FleetMDM load testing (osquery performance / `osqp`) environment. Declares required providers, configures an encrypted S3 remote state backend with DynamoDB locking, and wires up remote state data sources for shared infrastructure dependencies.

## Key Components

| Block | Purpose |
|---|---|
| `terraform.required_providers` | Pins `aws` (≥ 5.68.0), `docker` (~> 3.6.0 via kreuzwerker), and `git` (2025.10.10 via metio) |
| `backend "s3"` | Remote state stored in `fleet-terraform-state20220408141538466600000002`, key `loadtesting/loadtesting/osqp/terraform.tfstate`, encrypted with KMS, locked via DynamoDB |
| `provider "aws"` | Targets `us-east-2`; injects default tags (`environment`, `terraform`, `state`, `workspace`) on all resources |
| `data.terraform_remote_state.infra` | Reads workspace-scoped shared infra state (`loadtesting/loadtesting/terraform.tfstate`) |
| `data.terraform_remote_state.shared` | Reads non-workspace shared state (`loadtesting/loadtesting/shared/terraform.tfstate`) |
| `provider "docker"` | Authenticates to the account-specific ECR registry using a dynamically fetched ECR authorization token |
| `provider "git"` | Enabled with default configuration for git-based data lookups |

## Usage Example

```bash
# Initialise with the S3 backend (role assumed automatically)
terraform init

# Select or create a load-test workspace
terraform workspace select osquery-perf || terraform workspace new osquery-perf

# Preview changes scoped to this osqp environment
terraform plan

# Apply — all resources will be tagged with the active workspace name
terraform apply
```

> **IAM assumption:** All S3/DynamoDB backend operations and AWS provider calls assume `arn:aws:iam::353365949058:role/terraform-loadtesting` automatically; ensure the executing principal has `sts:AssumeRole` on that role.
