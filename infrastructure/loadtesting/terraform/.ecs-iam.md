Defines IAM roles, policies, and attachments required for the Fleet ECS task and execution roles to interact with AWS services securely.

## Key Components

| Resource / Data Source | Purpose |
|---|---|
| `aws_iam_policy_document.fleet` | Task role policy granting access to CloudWatch, Secrets Manager, RDS IAM auth (dynamic replica support), Kinesis Firehose, and KMS |
| `aws_iam_policy_document.assume_role` | Trust policy allowing `ecs.amazonaws.com` and `ecs-tasks.amazonaws.com` to assume the roles |
| `aws_iam_policy_document.fleet-execution` | Execution role policy scoped to Secrets Manager access for DB password and Fleet server private key |
| `aws_iam_role.main` | ECS task role used by the running Fleet container |
| `aws_iam_role.execution` | ECS execution role used by the ECS agent to pull images and secrets at startup |
| `aws_iam_role_policy_attachment.role_attachment` | Attaches AWS-managed `AmazonECSTaskExecutionRolePolicy` to the task role |
| `aws_iam_role_policy_attachment.execution_extras` / `task_extras` | Iterates `local.extra_execution_iam_policies` to attach any additional policies to both roles |

## Usage Example

```bash
# Apply IAM resources as part of the full ECS stack
terraform apply -target=aws_iam_role.main -target=aws_iam_role.execution
```

Key design decisions:
- **RDS IAM auth** uses a wildcard `dbuser:*/<master_username>` resource ARN to support dynamic Aurora read-replica autoscaling without enumerating instance IDs.
- A commented-out `dynamic` block is retained for static cluster deployments where instance `dbi_resource_ids` are known ahead of time.
- Extra policies can be injected at deploy time via `local.extra_execution_iam_policies` without modifying this file directly.

## Notes

- Both roles share the same `assume_role` trust policy.
- KMS permissions intentionally use wildcards (suppressed via `#tfsec:ignore:aws-iam-no-policy-wildcards`) to cover key operations across the main KMS key and the shared ECR KMS key from remote state.
