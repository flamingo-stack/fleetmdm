Terraform variable definitions for a FleetMDM load testing environment, declaring configurable inputs for deployment tag, container counts, and infrastructure instance types.

## Key Components

| Variable | Type | Default | Description |
|---|---|---|---|
| `tag` | string | required | Deployment tag matching the branch name |
| `git_branch` | string | `null` | Git branch for building load test containers when it differs from the Docker tag |
| `fleet_config` | map(string) | `{}` | Fleet environment variable configuration map |
| `loadtest_containers` | number | `0` | Number of load test containers to spin up |
| `fleet_containers` | number | `10` | Number of Fleet application containers |
| `db_instance_type` | string | `db.r6g.4xlarge` | RDS instance type for load testing database |
| `redis_instance_type` | string | `cache.m6g.large` | ElastiCache instance type for Redis |

## Usage Example

```bash
# Apply with custom load test configuration
terraform apply \
  -var="tag=main" \
  -var="git_branch=main" \
  -var="loadtest_containers=5" \
  -var="fleet_containers=20" \
  -var="db_instance_type=db.r6g.8xlarge" \
  -var="redis_instance_type=cache.m6g.xlarge" \
  -var='fleet_config={"FLEET_LOGGING_DEBUG":"true","FLEET_SERVER_TLS":"false"}'
```

Or via a `terraform.tfvars` file:

```text
tag                 = "main"
loadtest_containers = 5
fleet_containers    = 20
fleet_config = {
  "FLEET_LOGGING_DEBUG" = "true"
}
```

## Notes

- `tag` is the only required variable with no default value
- `git_branch` is only necessary when the Docker image tag does not match the Git branch name
- `fleet_config` entries are passed directly as environment variables to Fleet containers
