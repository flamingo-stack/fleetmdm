Terraform configuration that provisions an AWS KMS key and alias for encrypting sensitive data stored in Terraform state, scoped per workspace.

## Key Components

- **`aws_kms_key.customer_data_key`** — Creates a customer-managed KMS key dedicated to encrypting sensitive Terraform-managed data.
- **`aws_kms_alias.alias`** — Assigns a human-readable alias to the KMS key, namespaced by the active Terraform workspace (e.g., `alias/production-terraform-encrypted`).
- **`output.kms_key_id`** — Exposes the KMS key ID for reference by other modules or configurations.

## Usage Example

Reference the KMS key ID output in another module or resource:

```hcl
module "kms" {
  source = "./kms"
}

resource "aws_secretsmanager_secret" "example" {
  name       = "my-secret"
  kms_key_id = module.kms.kms_key_id
}
```

Switch workspaces to isolate key aliases per environment:

```bash
terraform workspace select production
terraform apply
# Creates: alias/production-terraform-encrypted
```

## Notes

- The KMS key alias is automatically namespaced using `terraform.workspace`, ensuring environment isolation across `staging`, `production`, etc.
- No key policy is explicitly defined, so the key inherits the default AWS KMS policy granting the account root full access.
- Consider enabling `deletion_window_in_days` and `enable_key_rotation` for production hardening.
