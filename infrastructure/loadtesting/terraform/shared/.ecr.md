Terraform configuration that provisions an AWS ECR repository for the `prometheus-to-cloudwatch` container image, secured with a KMS encryption key and immutable image tags.

## Key Components

| Resource | Name | Purpose |
|---|---|---|
| `aws_kms_key` | `main` | Customer-managed KMS key with 10-day deletion window and automatic key rotation enabled |
| `aws_ecr_repository` | `prometheus-to-cloudwatch` | ECR repository with immutable tags, push-time vulnerability scanning, and KMS-at-rest encryption |

## Configuration Details

- **Image tag mutability:** `IMMUTABLE` — prevents overwriting existing tags, enforcing strict image versioning
- **Scan on push:** `true` — triggers automated vulnerability scanning on every image push
- **Encryption:** KMS using the locally defined `aws_kms_key.main`, not the default AWS-managed key
- **KMS key rotation:** Enabled annually, 10-day deletion protection window

## Usage Example

```bash
# Initialize and apply
terraform init
terraform plan
terraform apply

# Authenticate Docker to ECR after provisioning
aws ecr get-login-password --region <region> | \
  docker login --username AWS \
  --password-stdin <account_id>.dkr.ecr.<region>.amazonaws.com

# Tag and push image
docker tag prometheus-to-cloudwatch:latest \
  <account_id>.dkr.ecr.<region>.amazonaws.com/prometheus-to-cloudwatch:v1.0.0

docker push \
  <account_id>.dkr.ecr.<region>.amazonaws.com/prometheus-to-cloudwatch:v1.0.0
```

## Dependencies

- Requires `local.prefix` and `random_pet.main` to be defined in the root module for KMS key naming
- See the full infrastructure configuration at [`ecr.tf`](https://github.com/flamingo-stack/fleetmdm/blob/main/ecr.tf)
