Terraform configuration that establishes GitHub Actions as a trusted CI/CD identity provider in AWS using OpenID Connect (OIDC), enabling keyless authentication for automated deployments.

## Key Components

| Resource | Description |
|---|---|
| `tls_certificate.github` | Fetches the TLS certificate from GitHub's OIDC discovery endpoint to extract the thumbprint |
| `aws_iam_openid_connect_provider.github` | Registers GitHub Actions as a trusted OIDC provider in AWS IAM |
| `aws_iam_role.gha_role` | IAM role (`github-actions-role`) assumed by GitHub Actions workflows; 3-hour max session |
| `aws_iam_role_policy.gha_role_policy` | Attaches the permissions policy to the GHA role |
| `gha_assume_role` (policy document) | Trust policy restricting `AssumeRoleWithWebIdentity` to the `fleetdm/fleet` repository |
| `gha-permissions` (policy document) | Broad AWS permissions granted to the role, covering EC2, ECS, RDS, S3, IAM, Route53, and more |

## Usage Example

After applying, configure your GitHub Actions workflow to assume the role:

```yaml
permissions:
  id-token: write
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::<ACCOUNT_ID>:role/github-actions-role
          aws-region: us-east-1
```

## Customization Points

- **Repository filter**: Update the `StringLike` condition in `gha_assume_role` — currently scoped to `repo:fleetdm/fleet:*` — to match your repository.
- **Permissions**: Trim the broad wildcard actions in `gha-permissions` to follow least-privilege principles for your deployment needs.
- **Session duration**: `max_session_duration` is set to `10800` seconds (3 hours); adjust based on your pipeline runtime.

> **Note:** The `sts:AssumeRole` statement in `gha-permissions` references a hardcoded account ID (`353365949058`) for a `terraform-loadtesting` role. Update or remove this for your environment.
