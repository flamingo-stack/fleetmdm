Terraform configuration defining AWS Application Load Balancer (ALB) resources for internal Fleet MDM load testing infrastructure, including listeners, listener rules, and target groups.

## Key Components

| Resource | Name | Purpose |
|---|---|---|
| `aws_lb.internal` | `${local.prefix}-internal` | Internal ALB placed in private subnets with a 905s idle timeout |
| `aws_lb_listener.internal` | — | HTTP:80 listener forwarding traffic to the internal target group |
| `aws_lb_listener_rule.main` | — | Routes workspace-specific load test hostnames to the main target group |
| `aws_lb_target_group.internal` | `${local.prefix}-internal` | IP-based target group on port 8080 with least-outstanding-requests balancing |
| `aws_lb_target_group.main` | `${local.prefix}` | Primary IP-based target group with identical health check and balancing config |

## Key Design Decisions

- **Internal only** — ALB is not internet-facing; security group and subnets are sourced from shared remote state.
- **Host-header routing** — `aws_lb_listener_rule.main` matches `${terraform.workspace}.loadtest.fleetdm.com`, isolating each Terraform workspace to its own traffic path.
- **Health checks** — Both target groups check `/healthz` expecting HTTP 200, with a 10s timeout and 15s interval (5 consecutive checks required to change state).
- **Deregistration delay** — Set to 30 seconds (down from the AWS default of 300s) to reduce drain time during deployments.

## Usage Example

```bash
# Deploy ALB resources for a specific load test workspace
terraform workspace select my-loadtest
terraform apply -target=aws_lb.internal \
                -target=aws_lb_listener.internal \
                -target=aws_lb_target_group.internal \
                -target=aws_lb_target_group.main
```
