Terraform configuration that provisions an AWS ECR repository with KMS encryption for Fleet MDM container images and builds/pushes two Docker images (standard and load test) to that registry.

## Key Components

- **`aws_kms_key.main`** — Creates a KMS key with automatic rotation for encrypting ECR image storage.
- **`aws_ecr_repository.fleet`** — Provisions an immutable, KMS-encrypted ECR repository with scan-on-push enabled.
- **`aws_ecr_authorization_token.token`** — Retrieves ECR authentication credentials for Docker registry access.
- **`docker_registry_image.fleet`** — Builds and pushes the standard Fleet image from DockerHub, tagged with the version and digest hash.
- **`docker_registry_image.loadtest`** — Builds and pushes a load test variant using `loadtest.Dockerfile`, targeting `linux/amd64`, tagged with a branch or version identifier.
- **`data.docker_registry_image.dockerhub`** — Fetches the upstream `fleetdm/fleet` image digest from DockerHub to produce deterministic, content-addressed tags.
- **`locals.loadtest_tag`** — Resolves the load test image tag, preferring `var.git_branch` over `var.tag` when set.

## Usage Example

```bash
# Deploy with a specific Fleet version tag
terraform apply \
  -var="tag=v4.50.0" \
  -var="git_branch=main"
```

```text
ECR image tag format:
  Fleet:     <repo_url>:<tag>-<sha256_short>
  Loadtest:  <repo_url>:loadtest-<branch_or_tag>-<sha256_short>
```

Both images are built from the `docker/` directory relative to the Terraform working directory. The `keep_remotely = true` flag ensures images are not deleted from ECR when the Terraform resource is destroyed.
