Defines Terraform local values that centralize naming conventions, IAM role configurations, environment variables, network CIDR blocks, and KMS/secrets policies for a FleetDM deployment scoped to the active Terraform workspace.

## Key Components

| Local | Purpose |
|---|---|
| `name` / `prefix` | Workspace-scoped resource identifiers (`fleetdm-<workspace>`, `fleet-<workspace>`) |
| `iam` | IAM role and policy name mappings for task and execution roles |
| `additional_env_vars` | Merged list of Fleet + APM environment variables passed to the ECS task; merges defaults with `var.fleet_config` |
| `vpn_cidr_blocks` | Private subnet CIDR ranges (`10.255.1-3.0/24`) for VPN VPC ingress rules |
| `software_installers_kms_policy` | KMS policy statement granting encrypt/decrypt access to the software installers key |
| `extra_secrets` / `secrets` | Secret ARN mappings projected into ECS `secrets` format (`name` + `valueFrom`) |
| `cloudfront_key_basename` | Base name for CloudFront signing key resources |

## Usage Example

```bash
# Reference locals in other .tf files within the same module
resource "aws_iam_role" "task" {
  name = local.iam.role.name  # → "<workspace>-role"
}

# Environment variable list consumed by ECS task definition
environment = local.additional_env_vars

# KMS policy attached inline
dynamic "statement" {
  for_each = local.software_installers_kms_policy
  ...
}
```

## Notes

- `ELASTIC_APM_SERVICE_VERSION` is dynamically composed from `var.tag` and the Docker image digest, enabling per-deployment APM tracing.
- The `extra_execution_iam_policies` and `extra_secrets` blocks contain commented-out CloudFront module references — placeholders for re-enabling the software installers CDN integration.
- All names are workspace-scoped, making this configuration safe for multi-environment deployments (e.g., `loadtest`, `staging`, `prod`).
