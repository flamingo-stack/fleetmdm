Terraform configuration that integrates SigNoz OpenTelemetry tracing into the Fleet load testing environment by reading its deployment outputs via S3-backed remote state.

## Key Components

| Component | Description |
|---|---|
| `data.terraform_remote_state.signoz` | Conditionally fetches SigNoz state from S3 when `var.enable_otel` is `true` |
| `output.signoz_cluster_name` | Exposes the EKS cluster name hosting SigNoz |
| `output.signoz_otel_collector_endpoint` | Exposes the internal OTLP collector endpoint for Fleet instrumentation |
| `output.signoz_configure_kubectl` | Exposes the `kubectl` configuration command for the SigNoz cluster |

## Configuration Details

- **State backend:** S3 bucket `fleet-terraform-state20220408141538466600000002`, region `us-east-2`
- **State key:** `loadtesting/loadtesting/signoz/terraform.tfstate`
- **Locking:** DynamoDB table `tf-remote-state-lock`
- **IAM role:** `arn:aws:iam::353365949058:role/terraform-loadtesting`
- **Workspace:** Inherits the current Terraform workspace automatically

## Usage Example

Enable SigNoz integration by setting the feature flag:

```bash
terraform apply -var="enable_otel=true"
```

Reference the OTLP endpoint in dependent modules:

```text
module.fleet.otel_endpoint = data.terraform_remote_state.signoz[0].outputs.otel_collector_endpoint
```

All three outputs gracefully degrade — returning `"SigNoz not deployed yet"` if the remote state exists but the specific output is missing, or `null` when `enable_otel` is `false`.
