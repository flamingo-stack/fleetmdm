Manages the Docker image pipeline for FleetDM, pulling from Docker Hub and pushing to a customer-specific AWS ECR repository with KMS encryption and image scanning enabled.

## Key Components

| Resource | Description |
|---|---|
| `aws_kms_key.main` | KMS key for ECR repository encryption, with rotation enabled |
| `aws_ecr_repository.fleet` | Private ECR repo named after the customer, with immutable tags and scan-on-push |
| `docker_image.dockerhub` | Pulls the `fleetdm/fleet` image from Docker Hub at the specified `var.tag` |
| `docker_tag.fleet` | Retags the pulled image with the ECR URL, appending the image digest for traceability |
| `docker_registry_image.fleet` | Pushes the retagged image to ECR and retains it remotely |
| `random_pet.db_secret_postfix` | Generates a unique suffix for the KMS key description |

## Image Tag Format

The final ECR image tag follows this pattern:

```text
<ecr_repo_url>:<var.tag>-<sha256_short_digest>
```

For example:

```text
123456789.dkr.ecr.us-east-1.amazonaws.com/customer-name:v4.50.0-abc123def456
```

## Usage Example

This file is driven by the `var.tag` variable and the `local.customer` local. Ensure both are defined before applying:

```bash
terraform apply -var="tag=v4.50.0"
```

The pipeline will:
1. Pull `fleetdm/fleet:v4.50.0` from Docker Hub
2. Create an ECR repository named after the customer with KMS encryption
3. Retag and push the image to ECR with a digest-based suffix

## Notes

- `force_delete = true` allows ECR repository deletion even when images exist
- `keep_remotely = true` prevents Terraform from deleting the image from ECR on destroy
- ECR authorization is handled automatically via `aws_ecr_authorization_token`
