Terraform configuration that provisions an internal AWS Application Load Balancer (ALB) with associated security group, listeners (HTTP and HTTPS), and a target group for routing traffic to private subnet resources.

## Key Components

| Resource | Name Pattern | Purpose |
|---|---|---|
| `aws_security_group.internal` | `{prefix}-int` | Open ingress/egress security group attached to the internal ALB |
| `aws_lb.internal` | `{prefix}-int` | Internal (private) ALB deployed across private subnets with access logging |
| `aws_lb_listener.internal` | — | HTTP listener on port 80, forwards to the internal target group |
| `aws_lb_listener.internal_https` | — | HTTPS listener on port 443 with TLS 1.3 policy; returns 404 by default |
| `aws_lb_target_group.internal` | `{prefix}-int` | IP-mode target group using least-outstanding-requests with `/healthz` health checks |

## Notable Configuration Decisions

- **Internal ALB** — not internet-facing; placed on private subnets from shared VPC state
- **TLS policy** — `ELBSecurityPolicy-TLS13-1-2-2021-06` enforces TLS 1.3 minimum on the HTTPS listener
- **Default HTTPS action** — returns a `404 Not Found` fixed response; actual routing is handled via listener rules added elsewhere
- **Health check** — polls `/healthz` every 15 seconds, requires 5 consecutive successes/failures to change state
- **Access logs** — written to an S3 bucket managed by the `logging_alb` module, prefixed by `local.customer`
- **Idle timeout** — set to 905 seconds to accommodate long-running Fleet MDM connections

## Usage Example

```bash
# Deploy the internal ALB alongside the rest of the stack
terraform init
terraform plan -target=aws_lb.internal
terraform apply -target=aws_lb.internal
```
