Terraform provider and backend configuration for the FleetMDM load testing infrastructure, declaring required providers and remote state management.

## Key Components

**Required Providers**
- `hashicorp/aws` (`>= 5.68.0`) — AWS resource management
- `kreuzwerker/docker` (`3.6.2`) — Docker registry authentication for ECR
- `metio/git` (`2025.10.10`) — Git data source support

**S3 Backend**
- Bucket: `fleet-terraform-state20220408141538466600000002`
- State key path: `loadtesting/loadtesting/terraform.tfstate`
- Region: `us-east-2`, encrypted with KMS key `9f98a443-ffd7-4dbe-a9c3-37df89b2e42a`
- State locking via DynamoDB table `tf-remote-state-lock`
- Assumes IAM role `arn:aws:iam::353365949058:role/terraform-loadtesting`

**AWS Provider**
- Region: `us-east-2`
- Default tags applied to all resources: `environment=loadtest`, `terraform` (source URL), `state` (S3 path), `workspace` (current Terraform workspace)

**Remote State Data Source (`shared`)**
- Reads shared infrastructure state from `loadtesting/loadtesting/shared/terraform.tfstate` in the same S3 bucket/region/KMS configuration

**Docker Provider**
- Authenticates to the account-specific ECR registry using dynamic credentials from `aws_ecr_authorization_token`

**Git Provider**
- Declared with no additional configuration (uses defaults)

## Usage Example

```bash
# Initialize with workspace targeting
terraform init
terraform workspace new <env-name>

# Plan against the load testing environment
terraform plan

# Access shared state outputs in other modules
data.terraform_remote_state.shared.outputs.<output_name>
```

## Notes

- The `workspace_key_prefix` and state key should be updated to match the target account alias when adapting this configuration to a new environment.
- Source reference: [`https://github.com/flamingo-stack/fleetmdm`](https://github.com/flamingo-stack/fleetmdm)
