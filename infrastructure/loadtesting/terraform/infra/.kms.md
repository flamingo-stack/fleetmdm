Terraform configuration that provisions an AWS KMS customer-managed key (CMK) for encrypting sensitive data stored in Terraform state or managed resources.

## Key Components

| Resource/Output | Description |
|---|---|
| `aws_kms_key.customer_data_key` | Creates a customer-managed KMS key for encrypting sensitive Terraform-managed data |
| `aws_kms_alias.alias` | Assigns a human-readable alias using the `local.customer` local value, following the pattern `alias/<customer>-terraform-encrypted` |
| `output.kms_key_id` | Exports the KMS key ID for reference by other Terraform modules or configurations |

## Usage Example

```bash
# Apply this configuration standalone or as part of a root module
terraform init
terraform apply
```

Reference the exported key ID in another module:

```text
module "kms" {
  source = "./kms"
}

resource "aws_s3_bucket_server_side_encryption_configuration" "example" {
  bucket = aws_s3_bucket.example.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm     = "aws:kms"
      kms_master_key_id = module.kms.kms_key_id
    }
  }
}
```

## Notes

- Requires `local.customer` to be defined in the root module's `locals` block before applying.
- The alias format `alias/<customer>-terraform-encrypted` makes keys identifiable per customer/tenant in multi-tenant deployments.
- The exported `kms_key_id` output can be consumed by sibling modules to enforce consistent encryption across resources.
