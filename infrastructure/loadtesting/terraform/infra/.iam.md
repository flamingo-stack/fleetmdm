Defines AWS IAM policies and attachments granting the Fleet application least-privilege access to AWS Secrets Manager for license and enrollment secrets.

## Key Components

| Resource | Name | Purpose |
|---|---|---|
| `aws_iam_policy_document.license` | — | Policy document allowing `secretsmanager:GetSecretValue` on the license secret ARN |
| `aws_iam_policy.license` | `<customer>-license-iam-policy` | Managed IAM policy created from the license document |
| `aws_iam_policy_document.enroll` | — | Policy document allowing `secretsmanager:GetSecretValue` on the enroll secret ARN |
| `aws_iam_policy.enroll` | `<customer>-enroll-policy` | Managed IAM policy for Fleet application resource access |
| `aws_iam_role_policy_attachment.enroll` | — | Attaches the enroll policy to the customer execution role |

## Usage Example

These resources are consumed automatically by the Fleet application's execution role. The `local.customer` prefix namespaces all resources per tenant.

```bash
# Plan IAM changes in isolation
terraform plan -target=aws_iam_policy.license -target=aws_iam_policy.enroll

# Apply after the loadtest module is provisioned (enforced via depends_on)
terraform apply
```

> **Note:** `aws_iam_role_policy_attachment.enroll` explicitly depends on `module.loadtest`, ensuring the target execution role exists before the attachment is attempted.

## Notes

- Both policies follow least-privilege: only `secretsmanager:GetSecretValue` is granted, scoped to specific secret ARNs.
- The license policy has no `description`; consider adding one for consistency.
