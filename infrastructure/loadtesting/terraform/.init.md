Terraform initialization file for the FleetMDM load testing infrastructure, configuring AWS, Docker, and Git providers alongside remote S3 backend state management.

## Key Components

### Providers

| Provider | Source | Version | Purpose |
|---|---|---|---|
| `aws` | `hashicorp/aws` | `~> 5.0` | Core AWS infrastructure in `us-east-2` |
| `docker` | `kreuzwerker/docker` | `~> 2.16.0` | ECR image management with registry auth |
| `git` | `metio/git` | `2025.10.10` | Reads local Git repository metadata |

### Backend (S3)

Remote state is stored in S3 with DynamoDB locking and KMS encryption:

```text
Bucket:    fleet-terraform-state20220408141538466600000002
Key:       loadtesting/loadtesting/terraform.tfstate
Workspace: loadtesting/<workspace_name>/
Region:    us-east-2
Lock:      tf-remote-state-lock (DynamoDB)
Role:      arn:aws:iam::353365949058:role/terraform-loadtesting
```

### Data Sources

- `aws_caller_identity.current` — resolves the active AWS account ID (used to build the ECR registry URL)
- `aws_region.current` — resolves the active AWS region
- `git_repository.tf` — reads the repository root (`../../../`) for version/commit metadata
- `terraform_remote_state.shared` — reads shared infrastructure outputs from a separate shared state file in the same S3 bucket

### Default Tags

All AWS resources are automatically tagged with:

```text
environment = "loadtest"
terraform   = <source repo URL>
state       = <full S3 state path>
workspace   = <terraform.workspace>
```

## Usage Example

```bash
# Initialize with workspace isolation
terraform init
terraform workspace new my-loadtest
terraform plan
```

> Each Terraform workspace maps to an isolated state path: `s3://<bucket>/loadtesting/<workspace>/loadtesting/loadtesting/terraform.tfstate`.
