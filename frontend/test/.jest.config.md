Jest configuration file for the Fleet frontend test suite, defining the test environment, module resolution, and transform settings needed to support both CommonJS and ESM dependencies.

## Key Components

- **`esModules` array** — Allowlist of ESM-only packages (e.g., `react-markdown`, `unified`, `uuid`) that must be transpiled by Jest instead of being excluded from transformation
- **`config` object** — Core Jest configuration exported as a CommonJS module:
  - `rootDir` — Points two levels up to the monorepo root
  - `moduleDirectories` — Resolves modules from both `node_modules` and the `frontend` directory
  - `testEnvironment` — Uses `jest-fixed-jsdom` for browser-like DOM simulation
  - `moduleNameMapper` — Stubs static assets (images, fonts, media, CSS), shell scripts, and maps browser-safe polyfills for `vfile` internals and a custom SQL parser build
  - `testMatch` — Matches any file ending in `*tests.js`, `*tests.ts`, `*tests.jsx`, or `*tests.tsx`
  - `setupFilesAfterEnv` — Runs `frontend/test/test-setup.ts` after the test framework is installed
  - `transformIgnorePatterns` — Allows Babel/ts-jest to transpile the ESM packages listed above
  - `globals` — Injects `TransformStream` and an empty `featureFlags` object into the test environment

## Usage Example

```bash
# Run all tests from the repository root
npx jest --config frontend/jest.config.js

# Run a specific test file
npx jest path/to/component.tests.tsx
```

```javascript
// Adding a new ESM package to the transform allowlist

```

> **Note:** Static assets and stylesheets are mocked automatically — no manual stubbing needed in individual test files. See [`frontend/__mocks__/fileMock.js`](https://github.com/flamingo-stack/fleetmdm/blob/main/frontend/__mocks__/fileMock.js) and [`frontend/test/test-setup.ts`](https://github.com/flamingo-stack/fleetmdm/blob/main/frontend/test/test-setup.ts) for the underlying mock implementations.
