MSW (Mock Service Worker) request handlers for Fleet MDM setup experience API endpoints, used in component tests to intercept and mock HTTP responses.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `defaultSetupExperienceScriptHandler` | Handler | GET handler returning a default mock setup experience script response |
| `createSetupExperienceScriptHandler` | Factory | Configurable GET handler for setup experience script with optional overrides |
| `errorNoSetupExperienceScriptHandler` | Handler | GET handler simulating a 404 for a missing setup experience script |
| `createSetupExperienceSoftwareHandler` | Factory | Configurable GET handler for setup experience software install data |
| `createSetupExperienceBootstrapMetadataHandler` | Factory | Configurable GET handler for MDM bootstrap package metadata |
| `errorNoBootstrapPackageMetadataHandler` | Handler | GET handler simulating a 404 for missing bootstrap package metadata |
| `createSetuUpExperienceBootstrapSummaryHandler` | Factory | Configurable GET handler for MDM bootstrap package summary |

## Usage Example

```typescript
import { createSetupExperienceScriptHandler, errorNoBootstrapPackageMetadataHandler } from "handlers/setup-experience-handlers";
import { renderWithSetup } from "test/test-utils";
import { server } from "test/jest-setup-file";

it("renders setup experience with custom script", () => {
  server.use(
    createSetupExperienceScriptHandler({ script: { name: "custom.sh" } }),
    errorNoBootstrapPackageMetadataHandler
  );

  renderWithSetup(<SetupExperience />);
});
```

Factory handlers accept `Partial<IGetSetupExperienceScriptResponse>` (or the relevant response type) as `overrides`, merging them with the base mock. Fixed handlers (`default*`, `error*`) require no arguments.
