Mock Service Worker (MSW) handler definitions for configuration profile API endpoints used in tests.

## Key Components

- **`createGetConfigHandler`** — Factory function that returns an MSW `GET` handler for `/configuration_profiles`. Accepts optional `Partial<IConfig>` overrides to customize the mock config response.
- **`defaultConfigProfileStatusHandler`** — Pre-built MSW `GET` handler for `/configuration_profiles/:uuid/status` that returns a fixed status payload with `verified`, `verifying`, `pending`, and `failed` counts.

## Usage Example

```typescript
import { createGetConfigHandler, defaultConfigProfileStatusHandler } from "./config-profiles";
import { server } from "test/test-utils";

// Use default config mock
server.use(createGetConfigHandler());

// Override specific config fields
server.use(
  createGetConfigHandler({ mdm: { enabled_and_configured: true } })
);

// Use the pre-built status handler
server.use(defaultConfigProfileStatusHandler);
```

## Notes

- Built on [MSW](https://mswjs.io/) (`msw`) for request interception in Jest/test environments.
- `createGetConfigHandler` delegates to `createMockConfig` from `__mocks__/configMock`, so only fields relevant to a test need to be overridden.
- The status handler always returns the same hardcoded values (`verified: 0`, `verifying: 1`, `pending: 2`, `failed: 3`); create a custom handler if dynamic status values are needed.
