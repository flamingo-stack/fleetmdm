MSW (Mock Service Worker) request handlers for the `/activities` API endpoint, providing reusable mock responses for activity-related tests.

## Key Components

| Export | Description |
|--------|-------------|
| `defaultActivityHandler` | Returns 3 mock activities with no pagination (no next or previous results) |
| `activityHandlerHasMoreActivities` | Returns 3 mock activities with `has_next_results: true` for testing forward pagination |
| `activityHandlerHasPreviousActivities` | Returns 3 mock activities with `has_previous_results: true` for testing backward pagination |

## Usage Example

```typescript
import { defaultActivityHandler, activityHandlerHasMoreActivities } from "test/handlers/activity-handlers";
import { renderWithSetup } from "test/test-utils";
import { server } from "test/server";

// Use the default handler in your test suite
const server = setupServer(defaultActivityHandler);

// Override with a pagination-specific handler for a single test
it("shows load more button when more activities exist", async () => {
  server.use(activityHandlerHasMoreActivities);

  renderWithSetup(<ActivityFeed />);

  expect(await screen.findByText("Load more")).toBeInTheDocument();
});

// Test backward pagination state
it("shows previous button when prior activities exist", async () => {
  server.use(activityHandlerHasPreviousActivities);

  renderWithSetup(<ActivityFeed />);

  expect(await screen.findByText("Load previous")).toBeInTheDocument();
});
```

## Notes

- All handlers intercept `GET /activities` via MSW's `http.get`
- Each handler returns exactly 3 mock activities using `createMockActivity()`
- Handlers differ only in their `meta` pagination flags, making it straightforward to test all pagination states in isolation
- Intended for use with `server.use(...)` to override the default within individual test cases
