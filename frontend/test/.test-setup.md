Global Jest test environment setup file that configures browser API mocks, a mock HTTP server, and filters known console warnings to create a stable testing environment.

## Key Components

- **`@testing-library/jest-dom`** — Extends Jest with custom DOM matchers (e.g., `toBeInTheDocument`)
- **`mockServer`** — MSW (Mock Service Worker) server instance imported from `./mock-server`
- **`window.CSS.supports`** — Mocked via `jest.fn()` to support `react-tooltip-5` in JSDOM
- **`global.ResizeObserver`** — Mocked implementation with `observe`, `unobserve`, and `disconnect` stubs, required since JSDOM does not natively support `ResizeObserver`
- **Lifecycle hooks** — `beforeAll`/`afterEach`/`afterAll` wiring for mock server start, handler reset, and teardown
- **Console warning filter** — Suppresses known spurious `[react-tooltip]` opacity warnings that surface due to JSDOM/`react-tooltip` incompatibilities

## Usage Example

This file is referenced in the Jest configuration (typically `jest.config.ts` or `package.json`) as a `setupFilesAfterFramework` entry:

```typescript
// jest.config.ts
export default {
  setupFilesAfterFramework: ["<rootDir>/test-setup.ts"],
};
```

Once registered, all tests automatically benefit from:

```typescript
// Any test file — no manual server setup needed
it("fetches device list", async () => {
  render(<DeviceList />);
  // mockServer intercepts HTTP requests automatically
  expect(await screen.findByText("MacBook Pro")).toBeInTheDocument();
});
```

## Notes

- The `ResizeObserver` mock must be assigned to `global` (not `window`) to satisfy TypeScript and JSDOM scoping
- `mockServer.resetHandlers()` runs after each test to prevent handler bleed-through between tests
- The `console.warn` override preserves all other warnings; only `[react-tooltip]` opacity messages are silenced
