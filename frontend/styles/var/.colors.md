Defines the application's color system, providing both static fallback hex values and a browser-aware `COLORS` proxy that returns CSS custom property references for automatic light/dark mode adaptation.

## Key Components

- **`STATIC_COLORS`** — Internal constant mapping all color token names to their hex fallback values, organized into branding, secondary, core, UI, status, and static (un-themed) categories.
- **`Colors`** — TypeScript union type derived from `STATIC_COLORS` keys, enabling type-safe color token references throughout the codebase.
- **`COLORS`** — Public `Proxy`-wrapped record that returns `var(--token-name, #fallback)` CSS references in browser environments, or raw hex values during SSR/testing.

## Usage Example

```typescript
import { COLORS, Colors } from "./colors";

// In a React component with inline styles
const style = {
  backgroundColor: COLORS["core-fleet-green"],  // → "var(--core-fleet-green, #009A7D)" in browser
  color: COLORS["core-fleet-white"],             // → "var(--core-fleet-white, #FFFFFF)" in browser
};

// Type-safe token reference
const token: Colors = "ui-success"; // ✅ valid
const bad: Colors = "nonexistent"; // ❌ TypeScript error

// SSR / test environments return plain hex
// (document is undefined) → COLORS["core-fleet-green"] === "#009A7D"
```

## Notes

- **Never** reference `STATIC_COLORS` directly in components; always use `COLORS` to ensure theme adaptability.
- Static (un-themed) tokens like `static-white` and `static-black` are intentionally identical in light and dark mode and should only be used as foreground on always-colored surfaces (toasts, tooltips).
- CSS custom properties must be defined in your stylesheet for dark mode overrides to take effect; the fallbacks ensure graceful degradation if a variable is missing.
