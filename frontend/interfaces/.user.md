Defines PropTypes validation shape and TypeScript interfaces for Fleet MDM user entities, covering user roles, authentication settings, and form data structures.

## Key Components

- **Default export** — PropTypes shape for runtime validation of user objects
- **`USERS_ROLES`** — Readonly tuple of valid role strings: `admin`, `maintainer`, `observer`, `observer_plus`, `technician`
- **`IUserRole`** — Type derived from `USERS_ROLES` for strict role assignment
- **`UserRole`** — Broader union type including display variants (e.g. `"Observer+"`, `"GitOps"`, `"Unassigned"`)
- **`IUser`** — Core user interface with auth fields (`sso_enabled`, `mfa_enabled`), team assignments, and a `fleets` field (future replacement for `teams`)
- **`IUserUpdateFormData`** — Request body shape for user update API calls
- **`IUserFormErrors`** — Validation error map for user creation/edit forms
- **`ICreateUserFormData`** / **`IUpdateUserFormData`** — Separate form data shapes for create vs. update flows
- **`ICreateUserWithInvitationFormData`** — Payload for accepting an invite and registering
- **`ILoginUserData`** — Minimal shape for login credentials
- **`IResetPasswordForm`** / **`IResetPasswordFormErrors`** — Password reset form and its error map

## Usage Example

```typescript
import userInterface, { IUser, IUserRole, ICreateUserFormData } from "./user";

// Type-safe user object
const currentUser: IUser = {
  id: 42,
  name: "Ada Lovelace",
  email: "ada@example.com",
  global_role: "admin",
  force_password_reset: false,
  sso_enabled: false,
  api_only: false,
  teams: [],
  fleets: [],
};

// Build create payload
const newUser: ICreateUserFormData = {
  email: "ada@example.com",
  name: "Ada Lovelace",
  global_role: "maintainer",
  teams: [],
  sso_enabled: false,
};
```

## Notes

- `fleets` on `IUser` is an intentional duplicate of `teams` kept for backward compatibility during a planned migration
- `UserRole` includes both lowercase API values (`"admin"`) and title-case display values (`"Admin"`) — prefer `IUserRole` for strict validation
