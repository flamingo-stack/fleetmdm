Defines PropTypes validation and TypeScript interfaces for Fleet query pack entities, including API response shapes and form data structures.

## Key Components

- **Default export** — PropTypes shape validator for pack objects used in React component prop validation
- **`IPack`** — Core interface representing a Fleet query pack with metadata, counts, and associated hosts, labels, and teams
- **`IStoredPacksResponse`** / **`IStoredPackResponse`** — API response wrappers for list and single pack endpoints
- **`IUpdatePack`** — Partial interface for pack update payloads
- **`IEditPackFormData`** — Form data structure for the pack edit UI

## Usage Example

```typescript
import PackPropTypes, {
  IPack,
  IUpdatePack,
  IEditPackFormData,
} from "interfaces/pack";

// Type-safe pack object
const pack: IPack = {
  id: 1,
  name: "Security Checks",
  description: "Weekly security audit queries",
  type: "global",
  created_at: "2024-01-01T00:00:00Z",
  updated_at: "2024-01-15T00:00:00Z",
  disabled: false,
  query_count: 5,
  total_hosts_count: 42,
  hosts: [],
  host_ids: [1, 2, 3],
  labels: [],
  label_ids: [],
  teams: [],
  team_ids: [10],
};

// Update payload (all fields optional)
const update: IUpdatePack = {
  name: "Updated Security Checks",
  disabled: true,
};

// React component with PropTypes validation
MyPackComponent.propTypes = {
  pack: PackPropTypes,
};
```

## Notes

- `IUpdatePack` references [`ITarget`](https://github.com/flamingo-stack/fleetmdm/blob/main/interfaces/target.ts) to support host, label, and team targeting in a unified structure
- `total_hosts_count` (on `IPack`) differs from `total_host_count` (on the PropTypes shape) — be aware of this naming inconsistency when mapping API responses
