Defines TypeScript interfaces for Fleet MDM user invitations, covering invite records and form data for creating and editing invites.

## Key Components

- **`IInvite`** — Represents a persisted invite record returned from the API, including metadata (`id`, `created_at`, `updated_at`), identity fields (`email`, `name`), auth settings (`sso_enabled`, `mfa_enabled`), and role/team assignments (`global_role`, `teams`).
- **`ICreateInviteFormData`** — Shape of the payload submitted when creating a new invite. Requires `email`, `name`, `global_role`, and `teams`; auth flags are optional.
- **`IEditInviteFormData`** — Shape of the payload submitted when editing an existing invite. Includes `password: null` (required by the API contract) and makes most fields optional except `global_role` and `sso_enabled`.

## Usage Example

```typescript
import { IInvite, ICreateInviteFormData, IEditInviteFormData } from "./invite";
import { UserRole } from "./user";

// Creating a new invite
const newInvite: ICreateInviteFormData = {
  email: "technician@example.com",
  name: "Jane Doe",
  global_role: UserRole.GitOpsAdmin,
  sso_enabled: true,
  teams: [],
};

// Editing an existing invite
const editPayload: IEditInviteFormData = {
  global_role: null,
  password: null,
  sso_enabled: false,
  mfa_enabled: true,
  teams: [{ id: 1, name: "Helpdesk" }],
};

// Typing an API response
const invite: IInvite = await fetchInvite(42);
console.log(invite.email, invite.global_role);
```

## Notes

- `global_role` accepts `null` to represent team-only scoped users (no global role assigned).
- `api_only` on `IInvite` marks service accounts that authenticate via API token only.
