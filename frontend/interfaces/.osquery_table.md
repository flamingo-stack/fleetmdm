Defines PropTypes shape validation and TypeScript interfaces for osquery table schema objects, including column definitions and platform metadata used throughout the Fleet MDM query interface.

## Key Components

- **Default export** – PropTypes shape validator for basic osquery table objects (columns, description, name, platform)
- **`ColumnType`** – Union type for supported osquery column data types (`integer`, `bigint`, `double`, `text`, `unsigned_bigint`, `STRING`, `string`)
- **`TableSchemaPlatform`** – Union of `QueryableDisplayPlatform` and `QueryablePlatform` to bridge schema format inconsistencies
- **`IQueryTableColumn`** – Interface describing a single table column with name, type, visibility, and platform constraints
- **`IOsQueryTable`** – Interface for a complete osquery table definition including columns, platforms, evented/cacheable flags, and optional examples/notes
- **`DEFAULT_OSQUERY_TABLE`** – Pre-populated `users` table constant used as a default value and in tests

## Usage Example

```typescript
import { IOsQueryTable, IQueryTableColumn, DEFAULT_OSQUERY_TABLE } from "./osquery_table";

// Use the default table as a fallback or test fixture
const table: IOsQueryTable = DEFAULT_OSQUERY_TABLE;

// Type a custom table column
const column: IQueryTableColumn = {
  name: "uid",
  description: "User ID",
  type: "bigint",
  hidden: false,
  required: false,
  index: false,
  platforms: ["macOS", "Linux"],
};

// Access column metadata
console.log(`${column.name}: ${column.type}`); // "uid: bigint"
```

## Notes

- `ColumnType` includes both `"STRING"` and `"string"` alongside `"text"` due to inconsistencies in `osquery_fleet_schema.json` — a known TODO in the codebase
- `TableSchemaPlatform` is a temporary dual-type union pending schema standardization between `osquery_fleet_schema.json` formats
