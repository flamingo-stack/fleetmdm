Unit test suite for the `charts` module, validating the `isHistoricalDataEnabled` function and associated constants (`HISTORICAL_DATA_CONFIG_KEYS`, `DATASET_CONFIG_KEY`, `DATASET_LABEL`).

## Key Components

| Test Suite | What It Covers |
|---|---|
| `isHistoricalDataEnabled` | Logic for enabling/disabling historical data per chart key, across global and fleet-level settings |
| `HISTORICAL_DATA_CONFIG_KEYS` | Validates the array of supported config keys (`uptime`, `vulnerabilities`) |
| `DATASET_CONFIG_KEY` | Verifies internal dataset name → config key mapping (`cve` → `vulnerabilities`) |
| `DATASET_LABEL` | Verifies human-readable labels per config key |

## Usage Example

```typescript
import {
  isHistoricalDataEnabled,
  IHistoricalDataSettings,
} from "./charts";

const globalSettings: IHistoricalDataSettings = {
  uptime: true,
  vulnerabilities: false,
};

const fleetSettings: IHistoricalDataSettings = {
  uptime: true,
  vulnerabilities: true,
};

// Returns true — both sides agree uptime is on
isHistoricalDataEnabled(globalSettings, fleetSettings, "uptime"); // true

// Returns false — global has vulnerabilities disabled
isHistoricalDataEnabled(globalSettings, fleetSettings, "vulnerabilities"); // false

// Returns true — both undefined defaults to enabled
isHistoricalDataEnabled(undefined, undefined, "uptime"); // true
```

## Key Behaviors Tested

- **Defaults to enabled** when both global and fleet settings are `undefined`
- **Either side can disable** — if global _or_ fleet sets a key to `false`, the feature is off
- **Per-key isolation** — disabling `vulnerabilities` does not affect `uptime` evaluation
- **Internal name mapping** — `cve` maps to the `vulnerabilities` config key; unknown names return `undefined`
