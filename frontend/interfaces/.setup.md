Defines TypeScript types and constants for device setup workflow steps, including step statuses, step types, and the shape of individual setup step objects returned from the Fleet MDM API.

## Key Components

- **`SETUP_STEP_STATUSES`** — Const tuple of valid step lifecycle states: `"pending"`, `"running"`, `"success"`, `"failure"`, `"cancelled"`
- **`SetupStepStatus`** — Union type derived from `SETUP_STEP_STATUSES`
- **`SETUP_STEP_TYPES`** — Array of step classification strings: `"software_install"`, `"software_script_run"`, `"script_run"`
- **`SetupStepType`** — Union type derived from `SETUP_STEP_TYPES`
- **`ISetupStep`** — Interface describing a single setup step as returned by the API, including display metadata and error state

## Usage Example

```typescript
import { ISetupStep, SetupStepStatus, SetupStepType } from "./setup";

const step: ISetupStep = {
  name: "Install Chrome",
  status: "running",
  type: "software_install",
  source: "apps",
  display_name: "Google Chrome",
  icon_url: "https://example.com/chrome-icon.png",
  error: null,
};

function isStepComplete(status: SetupStepStatus): boolean {
  return status === "success" || status === "failure" || status === "cancelled";
}

function getStepLabel(type: SetupStepType): string {
  const labels: Record<string, string> = {
    software_install: "Software Installation",
    software_script_run: "Package Script",
    script_run: "Script Execution",
  };
  return labels[type] ?? type;
}
```

## Notes

- `"software_script_run"` steps are distinguished from `"software_install"` at the API level by checking if `source` equals `"sh_packages"` or `"ps1_packages"`
- The server is expected to aggregate `"cancelled"` statuses with failures; the `"cancelled"` value is retained here as a defensive fallback
