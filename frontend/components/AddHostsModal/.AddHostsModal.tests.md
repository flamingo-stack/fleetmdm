Test suite for the `AddHostsModal` component, verifying rendering behavior across loading states, platform tabs, MDM configurations, and enroll secret scenarios.

## Key Components

| Test Case | Description |
|-----------|-------------|
| `renders loading state` | Verifies the spinner appears when `isLoading` is `true` |
| `renders platform tabs` | Validates tab content for macOS, Windows, Linux, ChromeOS, iOS/iPadOS, Android, Advanced, and Plain osquery |
| `renders enroll url input for iOS & iPadOS` | Checks MDM enrollment URL display when Mac MDM is enabled |
| `renders enroll url input for Android` | Checks enrollment instructions when Android MDM is enabled |
| `renders installer with secret` | Confirms the enroll secret (`ENROLL_SECRET`) appears in the installer command |
| `renders no enroll secret cta` | Validates the error state and CTA when no enroll secret exists |
| `excludes --enable-scripts flag` | Ensures `--enable-scripts` is omitted across all tabs when `scripts_disabled` is `true` |

## Usage Example

```typescript
// Running the test suite
import { createCustomRenderer } from "test/test-utils";
import createMockConfig from "__mocks__/configMock";
import AddHostsModal from "./AddHostsModal";

const render = createCustomRenderer({
  withBackendMock: true,
  context: {
    app: {
      isPreviewMode: false,
      config: createMockConfig(),
    },
  },
});

// Render with scripts disabled
const mockConfig = createMockConfig();
mockConfig.server_settings.scripts_disabled = true;

render(
  <AddHostsModal
    isAnyTeamSelected
    enrollSecret="abcdefg12345678"
    isLoading={false}
    onCancel={noop}
  />
);
```

## Notes

- Uses `createCustomRenderer` with `withBackendMock: true` to simulate backend responses.
- MDM-specific tabs (`iOS & iPadOS`, `Android`) conditionally render enrollment content based on `isMacMdmEnabledAndConfigured` and `isAndroidMdmEnabledAndConfigured` context flags.
- Source: [`flamingo-stack/fleetmdm`](https://github.com/flamingo-stack/fleetmdm)
