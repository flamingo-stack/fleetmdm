Test suite for the `ProgressBar` component, validating rendering behavior, section styling, and background color customization.

## Key Components

- **`renders with the correct sections and colors`** — Verifies the progressbar role is present with the default `ui-fleet-black-10` background, that sections render with correct `data-testid` attributes, and that width percentages and colors are applied correctly per section.
- **`applies custom background color when provided`** — Confirms the `backgroundColor` prop overrides the default container background.

## Usage Example

```typescript
// ProgressBar component usage (from test context)
const sections = [
  { color: "green", portion: 0.7 },
  { color: "red", portion: 0.1 },
];

render(<ProgressBar sections={sections} />);
// Container renders with role="progressbar"
// Sections accessible via data-testid="section-0", "section-1", etc.

// Custom background
render(<ProgressBar sections={sections} backgroundColor="blue" />);
```

## Notes

- Color assertions use a try/catch pattern to handle CI vs. local environment differences — JSDOM may resolve named CSS colors (e.g., `"green"`) as `rgb(0, 128, 0)` on CI but keep them as named values locally.
- Section widths are derived from the `portion` value multiplied by 100 (e.g., `0.7` → `70%`).
- The default container background uses the design token `COLORS["ui-fleet-black-10"]` from `styles/var/colors`.
