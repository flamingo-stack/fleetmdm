Test suite for the `SoftwareScriptDetailsModal` React component, validating rendering behavior of the `StatusMessage` and `ModalButtons` sub-components across different user contexts (device user page, host details page, software library page).

## Key Components

- **`StatusMessage` tests** — Verifies correct icons, text, host/package names, timestamps, and contact links render based on `status` (`pending_install`, `failed_install`, `installed`) and `isMyDevicePage` flag
- **`ModalButtons` tests** — Verifies correct button sets (Rerun/Cancel vs. Close) render per status and device context, and that click handlers fire with correct arguments

## Usage Example

```typescript
// Example: testing StatusMessage for a failed install on the device user page
render(
  <StatusMessage
    installResult={
      createMockSoftwareInstallResult({
        status: "failed_install",
      }) as ISoftwareScriptResult
    }
    isMyDevicePage
    contactUrl="http://support"
  />
);

expect(screen.getByText(/failed to run/)).toBeInTheDocument();
expect(
  screen.getByRole("link", { name: /contact your IT admin/ })
).toHaveAttribute("href", "http://support");

// Example: testing ModalButtons Rerun handler
const onRerun = jest.fn();
const { user } = renderWithSetup(
  <ModalButtons
    deviceAuthToken="token123"
    installResultStatus="failed_install"
    hostSoftwareId={99}
    onCancel={jest.fn()}
    onRerun={onRerun}
  />
);
await user.click(screen.getByRole("button", { name: "Rerun" }));
expect(onRerun).toHaveBeenCalledWith(99, true);
```

## Coverage Notes

- Host name is intentionally **omitted** on `isMyDevicePage` to protect user privacy
- Contact link only renders when `contactUrl` prop is provided
- Rerun button only appears on the device user page (`deviceAuthToken` present) with a `failed_install` status
