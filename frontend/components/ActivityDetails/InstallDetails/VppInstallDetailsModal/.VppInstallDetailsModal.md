Displays VPP (Volume Purchase Program) app install status details in a modal, including MDM command results, status messages, and retry functionality for failed installs.

## Key Components

### `getStatusMessage`
Generates contextual status message JSX based on install state, MDM acknowledgment status, platform, actor identity, and failure reasons. Handles edge cases including pre-4.57 `"pending"` status, `NotNow` MDM responses, verification timeouts, and Fleet-initiated failures.

### `ModalButtons`
Renders modal footer actions — shows a **Retry** button when on the My Device page with a failed install, otherwise shows **Close**.

### `VppInstallDetailsModal`
Main modal component. Fetches MDM command results via `commandAPI` (admin context) or `deviceUserAPI` (My Device page), then renders:
- Status icon and message
- Inventory versions (from `hostSoftware`)
- Decoded command output in a collapsible `<Textarea>`

### `IVppInstallDetails`
Data shape passed to the modal, including `fleetInstallStatus`, `commandUuid`, `appName`, `hostDisplayName`, `platform`, `failureReason`, `actorFullName`, `fleetInitiated`, and `selfService`.

## Usage Example

```typescript
import { VppInstallDetailsModal } from "./VppInstallDetailsModal";

<VppInstallDetailsModal
  details={{
    fleetInstallStatus: "failed_install",
    hostDisplayName: "Johns MacBook",
    appName: "Slack",
    commandUuid: "abc-123",
    platform: "darwin",
    actorFullName: "Jane Smith",
    fleetInitiated: false,
    selfService: false,
  }}
  hostSoftware={hostSoftwareRecord}
  onCancel={() => setShowModal(false)}
  onRetry={(id) => handleRetry(id)}
/>
```

> **Note:** For iOS/iPadOS `.ipa` packages (`ios_apps` / `ipados_apps`), use `SoftwareIpaInstallDetailsModal` with `command_uuid` instead.
