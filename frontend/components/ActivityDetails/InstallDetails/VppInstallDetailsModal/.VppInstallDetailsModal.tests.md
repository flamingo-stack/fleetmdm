Test suite for the `VppInstallDetailsModal` component, validating the `getStatusMessage` helper function and `ModalButtons` export across various MDM install status scenarios and platforms.

## Key Components

- **`getStatusMessage` tests** — Covers all status message rendering branches: `NotNow`, `pending_install` (acknowledged), `failed_install` (per platform), timeout copy, actor attribution (admin, Fleet, end user, self-service), and the "override failure with installed" edge case
- **`ModalButtons` export** — Imported but tested as part of modal composition
- **Mock utilities** — Uses `createMockHostAppStoreApp`, `createMockHostSoftware`, `createCustomRenderer`, `renderWithSetup`, and `mockServer` (MSW) for isolated rendering

## Usage Example

```typescript
// Run all tests in this suite
npx jest VppInstallDetailsModal.tests.tsx

// Run a specific test by name
npx jest VppInstallDetailsModal.tests.tsx -t "renders 'Fleet' as the actor"
```

## Test Coverage Summary

| Scenario | Platform | Assertion |
|---|---|---|
| `isMDMStatusNotNow` | any | "locked or battery/Power Nap" copy |
| `pending_install` + acknowledged | any | "not been verified" + Refetch button |
| `failed_install` + actor (admin) | ipados | Actor name + "failed to install" |
| `failed_install` + Fleet-initiated | ipados | "Fleet" as actor |
| `failed_install` + self-service | ipados | "End user" as actor |
| `failed_install` + MDM command fail | windows | "Please re-attempt" copy |
| `failed_install` + MDM command fail | darwin/ios/ipados | Apple-specific "failed. Please try again." |
| `failed_install` + timeout | darwin/ios/ipados | Timeout minutes in copy |
| My Device page timeout | darwin | Host display name omitted |
| Override failure with installed | darwin/ios | "is installed." copy |
