Test suite for the `GitOpsModeTooltipWrapper` component, verifying tooltip display and child interactivity based on GitOps Mode (GOM) configuration and entity-type exceptions.

## Key Components

- **`describe("GitOpsModeTooltipWrapper")`** — Five test cases covering all GOM states
- **`createCustomRenderer`** — Custom renderer injecting mock `app` context with `gitops` config
- **`gitops_mode_enabled`** — Boolean flag controlling whether GOM restrictions apply
- **`exceptions`** — Per-entity-type overrides (`labels`, `software`, `secrets`) that can bypass GOM restrictions
- **`entityType`** prop — Optional prop passed to the wrapper to check against exceptions

## Test Cases

| Scenario | GOM Enabled | Exception | Expected Behavior |
|---|---|---|---|
| GOM disabled | `false` | — | Button clickable, no tooltip |
| GOM enabled | `true` | — | Button disabled, tooltip shown |
| GOM enabled + entity excepted | `true` | `labels: true` | Button clickable, no tooltip |
| GOM enabled + entity not excepted | `true` | `labels: false` | Button disabled, tooltip shown |
| GOM enabled + no `entityType` specified | `true` | all `true` | Button disabled regardless |

## Usage Example

```typescript
// Rendering the wrapper in a test context
const { user } = render(
  <GitOpsModeTooltipWrapper
    entityType="labels"
    renderChildren={(disableChildren) => (
      <Button disabled={disableChildren} onClick={onSave}>
        Save
      </Button>
    )}
  />
);

// Verify tooltip appears on hover when GOM is active
await user.hover(screen.getByText("Save"));
await waitFor(() => {
  expect(screen.getByRole("tooltip")).toBeInTheDocument();
});
```
