A reusable wrapper component that renders common UI elements for host activity feed items, including avatars, timestamps, show-details, and cancel controls.

## Key Components

### Interfaces & Types

- **`IShowActivityDetailsData`** — Shape of the data passed to the show-details handler, including activity `type`, `details`, `created_at`, `actor_full_name`, and `fleet_initiated` flag.
- **`ShowActivityDetailsHandler`** — Typed callback used to surface activity details to a parent component (e.g., for opening a details modal).
- **`IActivityItemProps`** — Props for the `ActivityItem` component, covering the activity object, slot children, visibility/state flags, and event callbacks.

### Component

- **`ActivityItem`** — Wraps `FeedListItem` with activity-specific logic: resolves Gravatar URL from `actor_email`, safely parses `created_at` into a `Date`, and wires up `onShowDetails`/`onCancel` handlers with `stopPropagation` to prevent modal interference.

## Usage Example

```typescript
import ActivityItem, { ShowActivityDetailsHandler } from "components/ActivityItem";

const handleShowDetails: ShowActivityDetailsHandler = ({ type, details, created_at }) => {
  console.log("Show details for:", type, details);
};

<ActivityItem
  activity={activity}
  isSoloActivity={false}
  hideShowDetails={false}
  hideCancel={false}
  disableCancel={false}
  onShowDetails={handleShowDetails}
  onCancel={() => console.log("Activity cancelled")}
>
  <p>Ran script: deploy.sh</p>
</ActivityItem>
```

## Notes

- `fleet_initiated` activities (e.g., policy enforcement, auto-updates) render a Fleet avatar instead of a user Gravatar.
- `actor_api_only` triggers an API-only avatar variant via `FeedListItem`.
- Both button handlers call `e.stopPropagation()` to avoid unintended modal `onEnter` triggers.
