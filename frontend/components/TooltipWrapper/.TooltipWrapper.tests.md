Test suite for the `TooltipWrapper` component, validating tooltip rendering behavior, disabled states, and CSS class application.

## Key Components

- **`renders children and tooltip content`** — Verifies tooltip text appears in the DOM after hovering the trigger element
- **`does not render tooltip when disableTooltip is true`** — Confirms tooltip content is suppressed when the `disableTooltip` prop is set
- **`applies underline class by default`** — Checks that the wrapper element receives both the base and underline CSS classes when no `underline` prop is provided
- **`does not apply underline class when underline is false`** — Ensures the underline class is absent when `underline={false}` is passed

## Usage Example

```typescript
// Run the test suite
import { renderWithSetup } from "test/test-utils";
import TooltipWrapper from "./TooltipWrapper";

// Hover interaction test pattern
const { user } = renderWithSetup(
  <TooltipWrapper tipContent="Tooltip text">
    <span>Hover me</span>
  </TooltipWrapper>
);
await user.hover(screen.getByText("Hover me"));
await waitFor(() => {
  expect(screen.getByText("Tooltip text")).toBeInTheDocument();
});
```

## Notes

- Uses `renderWithSetup` from `test/test-utils` for user-event interaction support (hover simulation)
- Uses `waitFor` for async tooltip visibility assertions
- CSS classes follow the `component__tooltip-wrapper__*` naming convention
