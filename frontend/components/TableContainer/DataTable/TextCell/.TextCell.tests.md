Test suite for the `TextCell` component, verifying its rendering behavior across edge cases including null/empty values, boolean coercion, numeric zero, and custom formatter functions.

## Key Components

- **`renders booleans as string`** — Confirms `false` renders as the string `"false"` rather than being treated as falsy/empty.
- **`renders a default value for null/undefined/empty string`** — Validates that missing or empty `value` props fall back to `DEFAULT_EMPTY_CELL_VALUE`.
- **`renders default value after formatting produces empty`** — Ensures the fallback applies even when a `formatter` function returns `null`, `undefined`, or `""`.
- **`uses the provided formatter function`** — Verifies that a valid `formatter` return value replaces the raw `value` in output.
- **`renders the value '0' as a number`** — Guards against `0` being incorrectly treated as falsy and replaced with the empty cell fallback.

## Usage Example

```typescript
// Rendering TextCell with various prop combinations
render(<TextCell value={false} />);
// → displays "false"

render(<TextCell value={null} />);
// → displays DEFAULT_EMPTY_CELL_VALUE (e.g. "---")

render(<TextCell value="foo" formatter={() => "bar"} />);
// → displays "bar"

render(<TextCell value={0} />);
// → displays "0"
```

## Notes

- The `DEFAULT_EMPTY_CELL_VALUE` constant (from `utilities/constants`) is the expected fallback for any empty, null, or undefined display value — both before and after formatting.
- The boolean and zero tests are critical safeguards against falsy-value bugs common in table cell renderers.
