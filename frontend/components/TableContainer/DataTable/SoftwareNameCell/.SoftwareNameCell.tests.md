Test suite for the `SoftwareNameCell` component, verifying correct icon rendering and tooltip content based on installer type and page context.

## Key Components

### Test Suite: `SoftwareNameCell icon rendering`

Covers four icon states across three page contexts (`default/Software Title`, `hostDetails`, `hostDetailsLibrary`):

| Icon | Condition | Test IDs |
|------|-----------|----------|
| None | No installer | `install-icon`, `user-icon`, `refresh-icon`, `automatic-self-service-icon` all absent |
| `install-icon` | Manual installer | Hidden on `hostDetailsLibrary` (all items there have installers) |
| `user-icon` | Self-service | Shown across all three contexts |
| `refresh-icon` | Auto-install policies | Policy count reflected in tooltip text |
| `automatic-self-service-icon` | Self-service + auto-install combined | Tooltip shows both policy count and end-user install message |

### Default Props

```typescript
const defaultProps = {
  name: "Fleet Desktop",
  source: "fleet",
  router: mockRouter,
  path: "/software/1",
};
```

## Usage Example

```typescript
// Render with a manual installer on the Host Inventory page
render(
  <SoftwareNameCell
    {...defaultProps}
    hasInstaller
    pageContext="hostDetails"
  />
);

// Verify tooltip text on hover
const icon = screen.getByTestId("install-icon");
await userEvent.hover(icon);
expect(await screen.findByText(/on the Library tab/i)).toBeInTheDocument();
```

## Coverage Notes

- **11 test cases** total across `no installer`, `manual`, `self-service`, `auto-install`, and `self-service + auto-install` scenarios
- The `hostDetailsLibrary` + no installer combination is intentionally skipped — that state cannot occur in production
- Policy count pluralization is validated (e.g., `A policy triggers install.` vs. `2 policies trigger install.`)
