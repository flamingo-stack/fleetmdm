Test suite for the `InstallerActionCell` component, validating its three rendering states based on installer availability and installation status.

## Key Components

- **`InstallerActionCell` tests** — Three test cases covering the component's conditional rendering logic based on the `value` prop shape

## Test Cases

| Scenario | `value` prop | Expected Output |
|---|---|---|
| Installer available | `{ id, platform }` | "Add" button |
| Installer unavailable | `undefined` | `---` placeholder |
| Already installed | `{ id, platform, software_title_id }` | Success checkmark icon |

## Usage Example

```typescript
// Renders "Add" button when installer is available
render(<InstallerActionCell value={{ id: 1, platform: "darwin" }} />);
expect(screen.getByText(/add/i)).toBeInTheDocument();

// Renders placeholder when no installer exists
render(<InstallerActionCell />);
expect(screen.getByText(/---/i)).toBeInTheDocument();

// Renders success icon when software is already installed
render(
  <InstallerActionCell
    value={{ id: 1, platform: "darwin", software_title_id: 1 }}
  />
);
expect(screen.getByTestId("success-icon")).toBeInTheDocument();
```

The presence of `software_title_id` in the `value` prop signals an already-added installer, while a `value` with only `id` and `platform` indicates an available-but-not-yet-added installer. An absent `value` prop renders the unavailable state.
