Test suite for the `Radio` component, verifying rendering, interaction, and prop-driven behavior including labels, checked/disabled states, tooltips, and custom class names.

## Key Components

- **`renders the radio label text`** — Confirms the `label` prop renders visible text
- **`passes the radio input value when checked`** — Asserts `onChange` fires with the correct `value` string on click
- **`renders the correct selected state`** — Validates the `checked` prop marks the input as checked
- **`renders the correct disabled state`** — Verifies `disabled` disables the input and applies the `radio__disabled` CSS class
- **`render a tooltip from the tooltip prop`** — Checks that hovering the label displays the tooltip content
- **`adds the custom class name`** — Ensures the `className` prop is applied to the component root

## Usage Example

```typescript
// Example: testing onChange fires with the correct value
const changeHandlerSpy = jest.fn();

render(
  <Radio
    label="Option A"
    value="option-a"
    id="radio-a"
    onChange={changeHandlerSpy}
  />
);

const radio = screen.getByRole("radio", { name: "Option A" });
await userEvent.click(radio);

expect(changeHandlerSpy).toHaveBeenCalledWith("option-a");
```

## Notes

- Uses `@testing-library/user-event` for realistic user interaction simulation
- Tooltip tests rely on `renderWithSetup` from [`test/test-utils`](https://github.com/flamingo-stack/fleetmdm/blob/main/test/test-utils.ts) to get the pre-configured `user` instance alongside `waitFor` for async tooltip rendering
- The `testId` prop enables direct DOM queries via `getByTestId` for class assertions
