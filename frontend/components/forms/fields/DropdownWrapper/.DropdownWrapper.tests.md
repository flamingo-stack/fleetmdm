Test suite for the `DropdownWrapper` component, covering rendering behavior, user interactions, and variant-specific logic.

## Key Components

- **`sampleOptions`** — Shared fixture of two `CustomOptionType` entries used across all test cases
- **`mockOnChange`** — Jest mock function tracking `onChange` callback invocations

## Test Coverage

| Test | Description |
|------|-------------|
| Renders with help text | Verifies label and `helpText` prop render correctly |
| `onChange` on selection | Confirms the full `CustomOptionType` object is passed to the callback |
| Error message rendering | Validates the `error` prop displays an error string |
| Empty options state | Checks "no results found" appears when `options={[]}` |
| Button variant display | Asserts placeholder is preserved after selection (selected value not shown) |
| Button variant reopen state | Regression test for [#45853](https://github.com/flamingo-stack/fleetmdm/issues/45853) — ensures no option carries `--is-selected` class on dropdown reopen |

## Usage Example

```typescript
import { render, screen } from "@testing-library/react";
import userEvent from "@testing-library/user-event";
import DropdownWrapper from "./DropdownWrapper";

test("example: onChange fires with full option object", async () => {
  const handleChange = jest.fn();
  render(
    <DropdownWrapper
      options={[{ label: "Opt A", value: "a" }]}
      value="a"
      onChange={handleChange}
      name="example"
      label="Example"
    />
  );
  await userEvent.click(screen.getByText(/opt a/i));
  expect(handleChange).toHaveBeenCalledWith(
    expect.objectContaining({ value: "a" })
  );
});
```

> **Note:** The button variant regression test (final case) verifies that `react-select`'s internal `selectValue` state is overridden by forcing `value` to `null`, preventing visual re-highlighting of a previously selected option on reopen.
