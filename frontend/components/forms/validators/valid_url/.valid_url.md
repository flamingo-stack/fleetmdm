Thin wrapper around the `validator.js` `isURL` function that validates URLs with configurable protocol, localhost, and file-protocol support.

## Key Components

### `IValidUrl` Interface
| Property | Type | Description |
|---|---|---|
| `url` | `string` | The URL string to validate |
| `protocols` | `("http" \| "https" \| "file")[]` | Optional allowed protocols; enforces `require_protocol` when set |
| `allowLocalHost` | `boolean` | Disables TLD requirement for localhost URLs (default: `false`) |

### Default Export (Validator Function)
Accepts an `IValidUrl` object and returns a `boolean` indicating URL validity. Internally builds `IsURLOptions` for `validator.js`, with special handling for the `file` protocol:

- Enables underscores in paths
- Allows protocol-relative URLs
- Removes host requirement

## Usage Example

```typescript
import validUrl from "./valid_url";

// Standard HTTPS URL
validUrl({ url: "https://flamingo.run" }); // true

// Restrict to HTTPS only
validUrl({
  url: "http://flamingo.run",
  protocols: ["https"],
}); // false

// Allow localhost (e.g., for local dev environments)
validUrl({
  url: "http://localhost:8080",
  allowLocalHost: true,
}); // true

// File protocol URL
validUrl({
  url: "file:///home/user/config.yaml",
  protocols: ["file"],
}); // true
```

## Notes

- When `protocols` is omitted, protocol presence is **not** required.
- The `file` protocol automatically relaxes host and path constraints to accommodate local filesystem paths.
- Backed by [`validator.js`](https://github.com/validatorjs/validator.js) — see the [validator.js README](https://github.com/validatorjs/validator.js/blob/master/README.md#validators) for the full option reference.
