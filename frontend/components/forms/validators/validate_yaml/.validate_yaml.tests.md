Test suite for the `validateYaml` utility, verifying correct rejection of malformed/blank YAML input and acceptance of valid YAML strings.

## Key Components

- **`malformedYaml`** — Array of invalid YAML strings (bad indentation, missing colon delimiter)
- **`validYaml`** — Array of well-formed YAML strings using 2-space indentation
- **`describe("validateYaml")`** — Jest test suite with three test cases

## Test Cases

| Test | Description |
|------|-------------|
| `rejects malformed yaml` | Expects `valid: false`, a `"Syntax Error"` name, a truthy `reason`, and `line > 0` |
| `rejects blank entries` | Expects `valid: false` and error message `"YAML text must be present"` |
| `accepts valid yaml` | Expects `valid: true` and a falsy `error` |

## Usage Example

```javascript
import validateYaml from "./index";

// Valid YAML
const { error, valid } = validateYaml("spec:\n  config:\n    key: value\n");
// valid === true, error is falsy

// Malformed YAML
const { error, valid } = validateYaml("spec:\nconfig:\n    key: value\n");
// valid === false
// error.name === "Syntax Error"
// error.reason — human-readable message
// error.line   — line number where parse failed

// Blank input
const { error, valid } = validateYaml();
// valid === false, error === "YAML text must be present"
```

## Notes

- Indentation standard enforced is **2 spaces**; 4-space or missing indentation triggers a syntax error
- The `validateYaml` implementation lives at [`./index`](https://github.com/flamingo-stack/fleetmdm/blob/main/validate_yaml/index.js)
- Run with any Jest-compatible runner: `npx jest validate_yaml.tests.js`
