Test suite for the `validateQuery` utility, verifying correct acceptance/rejection of SQL queries and regression coverage for specific `node-sql-parser` edge cases.

## Key Components

- **`malformedQueries`** – Array of syntactically invalid SQL strings expected to fail validation
- **`validQueries`** – Array of valid SQL strings (SELECT, INSERT, CREATE TABLE, complex CTEs/JOINs) expected to pass
- **`validateQuery` test suite** – Three `it` blocks covering rejection of malformed queries, blank/empty inputs, and acceptance of valid queries
- **`node-sql-parser` integration suite** – Regression tests for specific parser bugs:
  - `#30109` – Custom escape characters in `LIKE` clauses (e.g. `ESCAPE '\\'`)
  - `#34635` – `VALUES` in CTEs and table names used directly inside `IN` clauses

## Usage Example

```typescript
import { validateQuery, EMPTY_QUERY_ERR, INVALID_SYNTAX_ERR } from ".";

// Valid query
const { valid, error } = validateQuery("SELECT * FROM users");
// valid === true, error is falsy

// Empty input
const { valid, error } = validateQuery("");
// valid === false, error === EMPTY_QUERY_ERR

// Malformed SQL
const { valid, error } = validateQuery("this is not a thing");
// valid === false, error matches INVALID_SYNTAX_ERR
```

## Notes

- Tests import `validateQuery`, `EMPTY_QUERY_ERR`, and `INVALID_SYNTAX_ERR` from the sibling index module
- Blank input detection covers `undefined`, empty string, whitespace-only, tab, and newline
- The `node-sql-parser` integration tests guard against real-world query regressions — do not remove without verifying the underlying parser still handles those cases
