Test suite for the generic `List` component, validating rendering behavior, loading states, click interactions, CSS class application, and custom key resolution.

## Key Components

| Export / Symbol | Purpose |
|---|---|
| `renderList` | Helper factory that merges partial props with defaults and renders `<List>` |
| `ITestItem` | Local interface (`id`, `name`) used as the generic type parameter in most tests |
| `describe("List")` | Top-level test suite grouping all seven behavioral assertions |

## Test Coverage

| Test case | What is verified |
|---|---|
| `renders heading when provided` | Optional `heading` ReactNode appears in the DOM |
| `renders help text when provided` | `helpText` string is rendered |
| `renders list items with data` | Each item's rendered row is present via `renderItemRow` |
| `shows loading overlay when isLoading is true` | `.loading-overlay` element mounts when `isLoading={true}` |
| `calls onClickRow when row is clicked` | Handler fires once with the correct item object |
| `applies clickable class when onClickRow is provided` | `.list__row--clickable` class is added to rows |
| `uses custom idKey when provided` | Generic `idKey` prop resolves non-default key fields; confirms React `key` is not exposed to the DOM |

## Usage Example

```typescript
// Run the full suite
npx jest List.test.tsx

// Run a single test by name
npx jest List.test.tsx -t "calls onClickRow when row is clicked"
```

Adding a new test follows the `renderList` helper pattern:

```typescript
it("renders empty state when data is empty", () => {
  renderList({ data: [], emptyState: <p>No items</p> });
  expect(screen.getByText("No items")).toBeInTheDocument();
});
```
