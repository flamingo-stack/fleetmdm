Unit tests for the `FleetPicker` component, validating rendering, selection state, click interactions, and empty/no-match states within a `cmdk` Command context.

## Key Components

| Export/Symbol | Description |
|---|---|
| `renderPicker` | Helper that wraps a component in a `cmdk` `Command` context for rendering |
| `renderPickerWithInput` | Helper that adds a `Command.Input` to enable `cmdk`'s internal search/filter state |
| `describe("FleetPicker")` | Top-level test suite covering all `FleetPicker` behaviours |

## Test Cases

| Test | Assertion |
|---|---|
| Renders all fleet items | All `availableTeams` entries appear in the DOM |
| Selected fleet class | Current team label carries `__item-label--selected`; others do not |
| `onSelect` callback | Clicking a row calls `onSelect` with the fleet's numeric `id` |
| Undefined `availableTeams` | No items are rendered |
| Search with no match | Displays `No fleets match "…".` empty-state copy |
| Empty `availableTeams` array | Displays `No fleets found.` empty-state copy |

## Usage Example

```typescript
// Run the full suite
npx jest FleetPicker.tests.tsx

// Minimal props signature exercised by these tests
<FleetPicker
  availableTeams={[{ id: 1, name: "Engineering" }]}
  currentTeam={{ id: 1, name: "Engineering" }}
  search=""
  onSelect={(id: number) => console.log(id)}
/>
```

## Notes

- `Element.prototype.scrollIntoView` is stubbed globally because JSDOM does not implement it and `cmdk` calls it internally.
- `renderPickerWithInput` is required for the "no match" test — `cmdk` drives its filter logic off the live `Command.Input` value, so typing via `userEvent` is necessary to trigger `Command.Empty`.
- Source: [`flamingo-stack/fleetmdm`](https://github.com/flamingo-stack/fleetmdm)
