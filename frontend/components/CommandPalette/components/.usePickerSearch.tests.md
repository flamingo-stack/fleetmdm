Test suite for the `usePickerSearch` hook, validating debouncing behavior, input trimming, and item selection from query responses.

## Key Components

- **`Probe<TResponse, TItem>`** — Generic test component that mounts `usePickerSearch` and exposes `isLoading`, `debouncedQuery`, and `items.length` via `data-testid` attributes for assertion.
- **`renderWithClient`** — Helper that wraps UI in a `QueryClientProvider` with retries disabled and zero cache time to ensure isolated, predictable query behavior.
- **Test suite (`usePickerSearch`)** — Three focused test cases covering the hook's core contracts.

## Test Cases

| Test | What it verifies |
|---|---|
| `debounces the search prop` | Rapid re-renders with changing `search` values do not invoke `queryFn` until after the debounce window; intermediate values are swallowed |
| `trims the search input` | Whitespace-padded strings are trimmed before being passed to `queryFn` |
| `uses selectItems to extract the displayed array` | The `selectItems` selector correctly maps the raw query response to the rendered item count |

## Usage Example

```typescript
// Minimal queryFn + selectItems pair used in tests
const queryFn = jest.fn().mockResolvedValue({ inner: { items: [1, 2, 3] } });
const selectItems = (d?: { inner: { items: number[] } }) =>
  d?.inner?.items ?? [];

const { getByTestId } = renderWithClient(
  <Probe search="" queryFn={queryFn} selectItems={selectItems} />
);

await waitFor(() => {
  expect(getByTestId("count").textContent).toBe("3");
});
```
