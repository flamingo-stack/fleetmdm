Defines value prefixes for cmdk `Command.Item` entries that have already been server-filtered, ensuring local cmdk substring matching is bypassed for those results.

## Key Components

- **`RESULT_PREFIXES`** — A `const` object mapping entity types (`host`, `software`, `report`, `policy`) to their corresponding string prefixes, applied to cmdk `value` props to identify pre-filtered results.
- **`isPreFilteredResult(value)`** — A predicate that returns `true` if the given cmdk value starts with any known `RESULT_PREFIXES` entry, signaling the parent dialog's `filter` prop to pass the item through unconditionally.

## Usage Example

```typescript
import { RESULT_PREFIXES, isPreFilteredResult } from "./constants";

// Tag a server-returned host result
const itemValue = `${RESULT_PREFIXES.host}${host.id}`;

// In the cmdk Command dialog's filter prop — skip local filtering
// for any item the server already filtered
<Command
  filter={(value, search) => {
    if (isPreFilteredResult(value)) return 1;
    return value.toLowerCase().includes(search.toLowerCase()) ? 1 : 0;
  }}
>
  <Command.Item value={itemValue}>{host.hostname}</Command.Item>
</Command>
```

## Notes

- All prefix strings include a trailing space to prevent accidental collisions with entity IDs that might share a prefix substring.
- Adding a new entity type requires only a new key in `RESULT_PREFIXES`; `isPreFilteredResult` picks it up automatically.
