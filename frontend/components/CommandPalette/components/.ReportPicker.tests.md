Unit tests for the `ReportPicker` component, verifying API scoping behavior and empty-state rendering across different team contexts.

## Key Components

- **`renderPicker`** — Custom renderer created with `withBackendMock: true` for isolated component testing
- **`mockedQueries`** — Typed Jest mock of `queriesAPI.loadAll`, reset before each test via `beforeEach`
- **`emptyQueriesResponse`** — Minimal, fully-typed `IQueriesResponse` fixture returning zero queries

## Test Cases

| Test | Description |
|------|-------------|
| Real team scoping | Asserts `loadAll` is called with `teamId: 5`, `mergeInherited: true`, `scope: "queries"` |
| All fleets scoping | Asserts `teamId` is `undefined` when team `id` is `-1` |
| Fleet empty state | Renders `"No reports found in Engineering."` |
| Search empty state | Renders `"No reports match 'missing' in Engineering."` |
| Unassigned empty state | Renders `"No reports found in this fleet."` |
| All fleets empty state | Renders `"No reports found."` (no fleet suffix) |

## Usage Example

```typescript
// Running the tests
npx jest ReportPicker.tests.tsx

// Rendering the component under test directly
renderPicker(
  <ReportPicker
    search=""
    currentTeam={{ id: 5, name: "Engineering" }}
    onSelect={jest.fn()}
  />
);
```

## Notes

- `IQueriesResponse` is used as an explicit type on the mock fixture so that future API renames surface as compile errors rather than silent runtime failures
- The `id: -1` convention signals "All fleets" (global scope), while `id: 0` signals "Unassigned"
- Source: [`flamingo-stack/fleetmdm`](https://github.com/flamingo-stack/fleetmdm)
