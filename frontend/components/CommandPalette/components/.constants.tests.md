Unit tests for the `isPreFilteredResult` utility and `RESULT_PREFIXES` constant from `./constants`.

## Key Components

- **`isPreFilteredResult`** — Function under test; returns `true` when a string begins with a known `RESULT_PREFIXES` value.
- **`RESULT_PREFIXES`** — Enum/object of known prefix strings used to classify pre-filtered search/navigation results.

## Test Coverage

| Scenario | Expected |
|---|---|
| String starts with a valid `RESULT_PREFIXES` value | `true` |
| Arbitrary or unrelated strings | `false` |
| Singular/typo variants (e.g. `HOSTS_RESULT`, `HOST_RESULTS`) | `false` |

## Usage Example

```typescript
import { RESULT_PREFIXES, isPreFilteredResult } from "./constants";

// Valid pre-filtered result
isPreFilteredResult(`${RESULT_PREFIXES.HOSTS}42`); // true

// Arbitrary string
isPreFilteredResult("dashboard home"); // false

// Typo guard — singular form must not match
isPreFilteredResult("HOSTS_RESULT 1"); // false
```

## Notes

- The **typo guard** suite explicitly protects against future contributors accidentally adding a prefix in singular form (e.g. `HOSTS_RESULT ` instead of `HOSTS_RESULTS `), ensuring the prefix registry stays consistent.
- Tests iterate dynamically over `Object.values(RESULT_PREFIXES)`, so adding a new prefix to the constant automatically extends the happy-path coverage with no test changes required.
