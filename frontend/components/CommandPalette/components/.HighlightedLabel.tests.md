Test suite for the `HighlightedLabel` component, validating substring highlighting behavior used in the command palette's label rendering.

## Key Components

- **`HighlightedLabel`** — Component under test; accepts `text` and `query` props to render text with matched substrings wrapped in `<mark>` elements
- **Test cases** — Five scenarios covering the core highlighting logic

## Test Coverage

| Scenario | Description |
|---|---|
| Empty query | Renders plain text with no `<mark>` elements |
| Single token match | Wraps matched substring in `<mark>` with correct CSS class |
| Case-insensitive match | Matches `ENG` in `Engineering`, preserves original casing (`Eng`) |
| Multi-token query | Splits `"view det"` into tokens, highlights each match independently |
| No match | Renders plain text when query has no substring match |

## Usage Example

```typescript
// Component usage (inferred from tests)
import HighlightedLabel from "./HighlightedLabel";

// Plain render — no marks
<HighlightedLabel text="Engineering" query="" />

// Single match — wraps "gin" in <mark class="command-palette__item-label-match">
<HighlightedLabel text="Engineering" query="gin" />

// Multi-token — highlights "View" and "det" separately
<HighlightedLabel text="View host details" query="view det" />
```

## Notes

- Matched `<mark>` elements receive the `command-palette__item-label-match` CSS class
- Query tokens are split by whitespace; each token is matched independently
- Case-insensitive matching preserves the **original casing** of the source `text`
