Unit tests for the `SoftwarePicker` component, verifying API call parameters, empty state copy variants, and software title display name normalization across different team and scope configurations.

## Key Components

- **`renderPicker`** — Custom renderer with backend mock support via `createCustomRenderer`
- **`renderPickerInCommand`** — Wraps the picker in a `cmdk` `Command` root, required for `Command.Item` context
- **`mockedSoftware`** — Typed Jest mock of `softwareAPI` with a default empty response in `beforeEach`

## Test Coverage

| Scenario | What is verified |
|---|---|
| `scope="library"` | `getSoftwareTitles` called with `availableForInstall: true` |
| Default (inventory) scope | `getSoftwareTitles` called with `availableForInstall: undefined` |
| Library empty state | Shows `"No software in <team>'s library."` |
| Inventory empty state | Shows `"No software found in <team>."` |
| `id: 0` ("Unassigned") | Substitutes `"this fleet"` / `"this fleet's library"` |
| `id: -1` ("All fleets") | Shows `"No software found."` with no suffix |
| Display name normalization | Prefers `display_name`; strips vendor prefix (e.g. `Microsoft.CompanyPortal` → `Company Portal`) |

## Usage Example

```typescript
// Render the picker in inventory scope for a specific team
renderPicker(
  <SoftwarePicker
    search=""
    currentTeam={{ id: 5, name: "Engineering" }}
    onSelect={jest.fn()}
  />
);

// Render in library scope (filters to installable software only)
renderPicker(
  <SoftwarePicker
    search=""
    currentTeam={{ id: 5, name: "Engineering" }}
    scope="library"
    onSelect={jest.fn()}
  />
);
```

> **Note:** Tests that render `Command.Item` nodes must use `renderPickerInCommand` to provide the required `cmdk` context. A global `scrollIntoView` stub is applied because JSDOM does not implement it.
