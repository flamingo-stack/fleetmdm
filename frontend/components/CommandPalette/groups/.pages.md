Builds the "Pages" group of command palette items, mapping top-level Fleet navigation routes to searchable labels and keywords based on the current user's permissions and tier context.

## Key Components

### `buildPagesItems(ctx, derived): ICommandItem[]`

The sole export. Accepts a `ICommandPaletteContext` and `IDerivedContext` and returns a filtered array of navigable page entries for the command palette.

**Context parameters used:**

| Parameter | Purpose |
|---|---|
| `canAccessControls` | Gates the Controls page entry |
| `canAccessSettings` | Gates the Settings page entry |
| `isPremiumTier` | Further restricts Controls to premium users |
| `withTeamId` | Injects current team ID into route paths |
| `search` | Enables the lazy-loaded Packs entry |

**Conditional entries:**

- **Controls** — shown only when `canAccessControls && hasTeamOrUnassigned && isPremiumTier`
- **Settings** — shown only when `canAccessSettings`
- **Packs** — shown only when `search` matches `/packs|create new pack|add new pack/` (legacy feature, kept discoverable without cluttering the default list)

## Usage Example

```typescript
import buildPagesItems from "./pages";

const items = buildPagesItems(
  {
    search: "host",
    canAccessControls: true,
    canAccessSettings: false,
    isPremiumTier: true,
    withTeamId: (path) => `${path}?team_id=3`,
    // ...other ctx fields
  },
  {
    hasTeamOrUnassigned: true,
    switchesFromUnassigned: "Team A",
    switchesFromAllFleets: undefined,
  }
);
// Returns Items[] for Dashboard, Hosts, Controls, Software, etc.
// Settings entry is omitted (canAccessSettings: false)
```

## Notes

- The `Reports` entry preserves `"queries"` / `"query"` as legacy keywords since the page was renamed from "Queries".
- `Users` is intentionally omitted here — it appears only in the Settings group to avoid duplicate palette destinations.
