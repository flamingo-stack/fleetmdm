Builds the list of automation-related command palette items, gating each entry on the current user's permissions and fleet/team context.

## Key Components

### `buildAutomationsItems(ctx, derived)`
The sole export. Accepts a `ICommandPaletteContext` and `IDerivedContext` and returns an `ICommandItem[]` containing up to four conditional entries:

| Item ID | Label | Visibility Gate |
|---|---|---|
| `manage-software-automations` | Manage software automations | `canManageSoftwareAutomations` + no team selected (or Primo Mode) |
| `manage-activity-automations` | Manage activity automations | `canAccessSettings` (global admin) |
| `manage-report-automations` | Manage report automations | `canManageReportAutomations` |
| `manage-policy-automations` | Manage policy automations | `canManagePolicyAutomations` |

Each item opens its destination page via a `?manage_automations=1` query parameter that triggers the relevant modal. Policy automation keywords are dynamically expanded — `calendar` keywords are appended only for team-scoped fleets, and `conditional access` keywords are appended for teams or the unassigned fleet.

## Usage Example

```typescript
import buildAutomationsItems from "./automations";

const items = buildAutomationsItems(
  {
    canAccessSettings: true,
    canManageSoftwareAutomations: true,
    canManagePolicyAutomations: true,
    canManageReportAutomations: false,
    hasTeamSelected: false,
    isPrimoMode: false,
    withTeamId: (path) => path,
  },
  { isUnassigned: false, switchesFromUnassigned: undefined }
);
// Returns items for software, activity, and policy automations;
// report automations is omitted due to missing permission.
```

## Notes

- All paths use the `paths` router constants and append `?manage_automations=1` — the destination pages own the actual modal-open logic.
- `withTeamId` is applied to report and policy paths so team context is preserved in the URL.
- `switchesFromUnassigned` is forwarded as `teamName` on the report item to signal a context switch in the palette UI.
