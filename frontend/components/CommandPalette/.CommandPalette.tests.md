Test suite for the `CommandPalette` component, covering open/close behavior, keyboard shortcuts, rendering, role-based visibility, and multi-platform modifier key logic.

## Key Components

- **`adminRender` / `observerRender`** — Pre-configured custom renderers with full app context (admin vs. observer roles, MDM state, team assignments)
- **`setPlatform`** — Helper that overrides `navigator.platform` to simulate macOS (`MacIntel`) or Windows (`Win32`) environments
- **`openPalette`** — Convenience helper that fires `Cmd+K` and awaits the search input
- **Platform fixture** (`beforeEach`/`afterEach`) — Defaults every test to `MacIntel`; restores the original property descriptor after each test to prevent descriptor leakage

## Test Coverage

| Group | What's tested |
|---|---|
| Opening/closing | Renders nothing when closed; `Cmd+K` opens; `Ctrl+K` behavior differs by platform; `Escape` closes; toggle closes; search resets on reopen |
| Rendering items | Page items and group headings visible; team name shown on scoped actions |
| Fleet switcher | Header button shows current fleet; click navigates to switch-fleet picker |
| Keyboard shortcuts | `Cmd+Shift+F` opens switch-fleet (Mac); `Ctrl+Shift+F` on non-Mac; platform guards for both; `Escape` returns to root from sub-pages; `Backspace` on empty input navigates back |

## Usage Example

```typescript
// Run all tests
npx jest CommandPalette.tests.tsx

// Run a specific describe block
npx jest CommandPalette.tests.tsx -t "Opening and closing"
```

## Notes

- `Element.prototype.scrollIntoView` is mocked globally — `cmdk` calls it internally but JSDOM doesn't implement it
- The `it.todo` for "No results found" is intentionally deferred; `cmdk` filtering doesn't respond to synthetic DOM events in JSDOM
