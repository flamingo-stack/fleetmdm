Test suite for the `TargetsInput` component, verifying that both the search results table and selected hosts table render correctly based on custom column configurations.

## Key Components

- **`TargetsInput`** — The component under test; renders host search results and targeted host tables
- **`ITargestInputHostTableConfig`** — Interface defining column configuration (`Header`, `accessor`) for both table views
- **`createMockHost`** — Factory utility for generating mock `IHost` objects in tests

## Test Cases

| Test | Description |
|---|---|
| Search table config | Verifies search results table renders only columns defined in `searchResultsTableConfig` |
| Results table config | Verifies targeted hosts table renders only columns defined in `selectedHostsTableConifg` |

Both tests assert that columns and data specified in the config are rendered, while fields **not** included in the config (e.g., `computer_name`) are absent from the DOM.

## Usage Example

```typescript
// Rendering with a custom search results table configuration
render(
  <TargetsInput
    searchText="test"
    searchResults={testHosts}
    isTargetsLoading={false}
    hasFetchError={false}
    targetedHosts={[]}
    searchResultsTableConfig={[
      { Header: "Name", accessor: "display_name" },
      { Header: "IP Address", accessor: "public_ip" },
    ]}
    selectedHostsTableConifg={[]}
    setSearchText={noop}
    handleRowSelect={noop}
  />
);
```
