Test suite for the `Button` component, validating rendering, interaction handling, accessibility, and visual state behaviors using React Testing Library.

## Key Components

| Test Case | Description |
|---|---|
| `renders button with correct text` | Verifies button renders provided children text |
| `applies correct class names` | Checks BEM-style classes including `button--disabled` when `disabled` prop is set |
| `calls onClick when clicked` | Confirms click handler fires on mouse click |
| `calls onClick when Enter key is pressed` | Validates keyboard accessibility via `keyDown` Enter event |
| `does not call onClick when disabled` | Ensures click handler is suppressed when `disabled` is true |
| `renders spinner when isLoading is true` | Checks spinner element renders and text gets `transparent-text` class |
| `applies custom className` | Verifies passthrough `className` prop merges correctly |
| `renders with correct title attribute` | Confirms `title` attribute is applied for tooltip/accessibility support |

## Usage Example

```typescript
// Run the full test suite
npx jest Button.tests.tsx

// Example of the patterns tested
import { render, fireEvent, screen } from "@testing-library/react";
import Button from "./Button";

// Click handler suppression when disabled
const handleClick = jest.fn();
render(<Button onClick={handleClick} disabled>Disabled</Button>);
fireEvent.click(screen.getByText("Disabled"));
expect(handleClick).not.toHaveBeenCalled();

// Loading state renders spinner
render(<Button isLoading>Loading</Button>);
expect(screen.getByTestId("spinner")).toBeInTheDocument();
```

## Notes

- Tests use `jest.fn()` for handler mocking — no external mock setup required.
- BEM class convention (`button--default`, `button--disabled`) is enforced by the `applies correct class names` test.
- Keyboard accessibility (Enter key) is explicitly tested, aligning with WCAG interaction requirements.
