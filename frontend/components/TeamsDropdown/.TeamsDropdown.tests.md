Unit tests for the `TeamsDropdown` component, verifying correct rendering of selected teams and default fallback behavior based on user context and props.

## Key Components

- **`renders the given selected team from selectedTeamId`** — Confirms the dropdown displays the team matching the provided `selectedTeamId` prop.
- **`renders the first team option when includeAllTeams is false`** — Validates that when `includeAllTeams={false}` and no `selectedTeamId` is given, the first non-"All fleets" team is shown.
- **Global team context suite** — Tests behavior when `isOnGlobalTeam: true`:
  - Defaults to "All fleets" when no `selectedTeamId` is provided.
  - Falls back to the first team when `includeAllTeams={false}`.
- **Non-global team context suite** — Tests behavior when `isOnGlobalTeam: false`, filtering out the `APP_CONTEXT_NO_TEAM_ID` entry and confirming the first real team renders by default.

## Usage Example

```typescript
// Running the test suite
// From the repository root:
// npx jest TeamsDropdown.tests.tsx

// Example: rendering TeamsDropdown in a global-team context
renderWithAppContext(
  <TeamsDropdown
    currentUserTeams={[
      { id: -1, name: "All fleets" },
      { id: 1, name: "Team 1" },
    ]}
    onChange={noop}
  />,
  { contextValue: { isOnGlobalTeam: true } }
);

expect(screen.getByText("All fleets")).toBeInTheDocument();
```

## Notes

- Uses `renderWithAppContext` (flagged for replacement with `createCustomRenderer`) to inject app-level context.
- `APP_CONTEXT_NO_TEAM_ID` (value `-1`) is used to filter out the "All fleets" pseudo-team for non-global users.
