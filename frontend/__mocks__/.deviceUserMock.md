Provides factory functions and default mock data for device user–related entities used in tests and Storybook stories.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `createMockDeviceUser` (default) | Factory | Creates an `IDeviceUser` mock with optional overrides |
| `createMockDeviceSoftware` | Factory | Creates an `IDeviceSoftware` mock with optional overrides |
| `createMockDeviceSoftwareResponse` | Factory | Creates a paginated `IGetDeviceSoftwareResponse` mock |
| `createMockSetupStepStatus` | Factory | Creates a single `ISetupStep` mock (default: `"Slack"`, `"pending"`) |
| `createMockSetupSoftwareStatusesResponse` | Factory | Creates a full `IGetSetupExperienceStatusesResponse` with varied statuses |

## Usage Example

```typescript
import createMockDeviceUser, {
  createMockDeviceSoftware,
  createMockDeviceSoftwareResponse,
  createMockSetupStepStatus,
  createMockSetupSoftwareStatusesResponse,
} from "__mocks__/deviceUserMock";

// Basic device user mock
const user = createMockDeviceUser({ email: "admin@example.com" });

// Device software with overrides
const software = createMockDeviceSoftware({ name: "Custom App.app", status: "installed" });

// Paginated software response
const response = createMockDeviceSoftwareResponse({ count: 5 });

// Setup step with specific status
const step = createMockSetupStepStatus({ name: "Zoom", status: "success" });

// Full setup experience response with override
const setupResponse = createMockSetupSoftwareStatusesResponse({
  setup_experience_results: {
    software: [createMockSetupStepStatus({ name: "Slack", status: "running" })],
    scripts: [],
  },
});
```

All factories accept a `Partial<T>` overrides argument and shallow-merge it with the default mock, keeping test setup minimal and readable.
