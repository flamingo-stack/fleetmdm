Provides factory functions for creating mock MDM command objects used in tests, with sensible defaults that can be overridden per test case.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `createMockCommand` | Factory function | Creates a mock `ICommand` with a default pending `InstallProfile` state |
| `createMockGetCommandsResponse` | Factory function | Creates a mock `IGetCommandsResponse` with a single result and no pagination |
| `createMockAppleMdmCommandResult` | Factory function | Creates a mock `ICommandResult` representing an acknowledged Apple MDM command with base64-encoded payload and result |

## Usage Example

```typescript
import {
  createMockCommand,
  createMockGetCommandsResponse,
  createMockAppleMdmCommandResult,
} from "__mocks__/commandMock";

// Basic mock with defaults
const command = createMockCommand();

// Override specific fields
const failedCommand = createMockCommand({
  command_status: "error",
  status: "Error",
  hostname: "test-device",
});

// Mock a paginated commands response
const response = createMockGetCommandsResponse({
  count: 2,
  meta: { has_next_results: true, has_previous_results: false },
});

// Mock an Apple MDM command result
const commandResult = createMockAppleMdmCommandResult({
  status: "Error",
  hostname: "My MacBook",
});
```

## Notes

- All factories use the spread pattern (`...defaults, ...overrides`), so only fields that need to differ from the defaults must be specified.
- The `payload` and `result` fields in `DEFAULT_COMMAND_RESULT_MOCK` are Base64-encoded XML strings matching the Apple MDM protocol format.
- Source: [`flamingo-stack/fleetmdm`](https://github.com/flamingo-stack/fleetmdm)
