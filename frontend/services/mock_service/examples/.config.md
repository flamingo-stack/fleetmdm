Configures the mock service layer for the Fleet API, defining request/response mappings, wildcard patterns, and timing controls for simulated async behavior.

## Key Components

- **`DELAY`** — Simulates async latency (default: `1000ms`); adjust to test loading states
- **`ENDPOINT`** — Base API path (`/latest/fleet`); align with your API spec
- **`WILDCARDS`** — Characters recognized as URL parameter placeholders (`:`、`*`、`{`、`}`)
- **`REQUEST_RESPONSE_MAPPINGS`** — Dictionary mapping HTTP methods + URL patterns to static `RESPONSES` fixtures; supports exact paths, query params, and wildcard segments
- **`IResponses`** — Type alias enforcing the three-level `method → path → response` structure

## Usage Example

```typescript
// Copy this file to ../mocks/config.ts before editing.
// Add a new GET mapping with a wildcard route param:
const REQUEST_RESPONSE_MAPPINGS: IResponses = {
  GET: {
    // Exact match
    "/hosts?page=0&per_page=20": RESPONSES.ALL_HOSTS,

    // Wildcard: matches any host ID
    "/hosts/*id": RESPONSES.HOST_ID,

    // Wildcard: matches any team ID in query param
    "/hosts?team_id={team_id}": RESPONSES.HOSTS_TEAM_ID,
  },
  POST: {
    "/:id/refetch": {}, // Returns empty JSON for any ID
  },
};
```

> ⚠️ **Do not edit this file directly.** Copy it to `../mocks/config.ts` and modify only that copy. See the project [README](https://github.com/flamingo-stack/fleetmdm/blob/main/README.md) for full mock service setup instructions.

**Wildcard precedence:** Exact paths are matched first; wildcard patterns serve as fallbacks, enabling targeted overrides (e.g., `/hosts/1337` takes priority over `/hosts/*id`).
