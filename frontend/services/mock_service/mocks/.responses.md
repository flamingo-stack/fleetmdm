Provides static mock data fixtures used in frontend tests and development, exporting pre-built API response shapes for hosts, labels, queries, counts, and policies.

## Key Components

- **`count`** — Mock target count object with `targets_count`, `targets_online`, `targets_offline`, and `targets_missing_in_action` fields.
- **`hosts`** — Array of 6 offline mock hosts across Ubuntu and RHEL/CentOS platforms with full hardware/network metadata.
- **`labels`** — Array of 7 built-in Fleet labels (All Hosts, macOS, Ubuntu Linux, CentOS Linux, MS Windows, Red Hat Linux, All Linux).
- **`globalQueries`** — Partial mock query array ("SchedulableQueries") used for developing the scheduled queries frontend (related to issue #7765), with multi-platform and interval configurations.
- **`createMockIosHostResponse`** / **`createMockPoliciesResponse`** — Re-exported factory functions from `__mocks__/hostMock` and `__mocks__/policyMock` for generating iOS host and policy response shapes.

## Usage Example

```typescript
import { count, hosts, labels, globalQueries } from "./responses";

// Use in a mock API handler (e.g., MSW or Jest)
server.use(
  rest.get("/api/v1/fleet/hosts", (_req, res, ctx) => {
    return res(ctx.json(hosts));
  }),
  rest.get("/api/v1/fleet/labels", (_req, res, ctx) => {
    return res(ctx.json(labels));
  }),
  rest.get("/api/v1/fleet/targets/count", (_req, res, ctx) => {
    return res(ctx.json(count));
  })
);
```

> **Note:** All host entries in `hosts` share the same UUID and are marked `status: "offline"`, making this fixture suitable for offline/edge-case UI testing scenarios.
