Defines the mock API server configuration for local frontend development, mapping HTTP methods and endpoint patterns to their corresponding response handlers.

## Key Components

- **`MockEndpointHandler`** — Exported union type accepting either a static response object or a function returning a response (sync or async).
- **`DELAY`** — Fixed 500ms simulated network latency applied to all mock responses.
- **`ENDPOINT`** — Base path prefix (`/latest/fleet`) prepended to all matched routes.
- **`WILDCARDS`** — Characters (`:`, `*`, `{`, `}`) used to identify dynamic route segments during URL pattern matching.
- **`REQUEST_RESPONSE_MAPPINGS`** — The core routing table, keyed by HTTP method (`GET`, `POST`, `DELETE`), mapping endpoint path patterns to response handlers imported from `responses`.

## Usage Example

```typescript
import config from "./config";
import type { MockEndpointHandler } from "./config";

const { DELAY, ENDPOINT, WILDCARDS, REQUEST_RESPONSE_MAPPINGS } = config;

// Check if a path segment contains a wildcard
const isDynamic = (segment: string) =>
  WILDCARDS.some((w) => segment.includes(w));

// Look up a handler for a given method and path
const handler: MockEndpointHandler = REQUEST_RESPONSE_MAPPINGS["GET"]["queries"];

// If handler is a function, call it with the URL; otherwise use directly
const response =
  typeof handler === "function" ? await handler(`${ENDPOINT}/queries`) : handler;
```

## Notes

- Wildcard patterns like `targets?query={*}` and `custom_variables?page=*&per_page=*` allow a single entry to match multiple dynamic URLs.
- Inline `POST` entries can be defined directly as plain objects rather than importing from `responses`, suitable for simple static payloads.
- See [`responses.ts`](https://github.com/flamingo-stack/fleetmdm/blob/main/responses.ts) for the full set of imported mock response fixtures.
