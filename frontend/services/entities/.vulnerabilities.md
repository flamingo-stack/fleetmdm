API service module for fetching vulnerability data, providing functions to retrieve paginated lists of CVEs and detailed vulnerability information including affected OS versions and software.

## Key Components

### Interfaces

| Interface | Description |
|---|---|
| `IGetVulnerabilitiesQueryParams` | Query params for listing vulnerabilities (pagination, filtering, team scoping) |
| `IGetVulnerabilitiesQueryKey` | Extends query params with a `scope` field for React Query cache keying |
| `IGetVulnerabilityQueryKey` | Query key for a single CVE lookup, scoped to `"softwareVulnByCVE"` |
| `IVulnerabilitiesResponse` | Paginated response shape including count, metadata, and nullable vulnerability array |
| `IVulnerabilityResponse` | Single vulnerability detail with affected OS versions and software |
| `IVulnerabilitiesEmptyStateReason` | Union type for categorizing why a vulnerability list is empty |

### Functions

- **`getVulnerabilities(params?)`** — `GET /vulnerabilities` with optional filters for team, ordering, pagination, exploit flag, and search query
- **`getVulnerability({ vulnerability, teamId })`** — `GET /vulnerability/:cve` for a single CVE, optionally scoped to a team

## Usage Example

```typescript
import vulnerabilitiesAPI from "services/entities/vulnerabilities";

// Fetch paginated, exploit-only vulnerabilities for a team
const { vulnerabilities, count } = await vulnerabilitiesAPI.getVulnerabilities({
  teamId: 3,
  exploit: true,
  page: 0,
  per_page: 25,
  order_key: "cvss_score",
  order_direction: "desc",
});

// Fetch details for a specific CVE
const { vulnerability, os_versions, software } =
  await vulnerabilitiesAPI.getVulnerability({
    vulnerability: "CVE-2024-12345",
    teamId: 3,
  });
```

## Notes

- `IVulnerabilitiesResponse.vulnerabilities` can be `null` per the API contract — callers should guard against this.
- `IVulnerabilitiesEmptyStateReason` is used by UI components to render contextual empty states (`"unknown-cve"`, `"invalid-cve"`, `"known-vuln"`, `"no-matching-items"`, `"no-vulns-detected"`).
