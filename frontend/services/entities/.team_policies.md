Provides CRUD operations and query utilities for managing team-scoped policies via the Fleet MDM API.

## Key Components

### Types & Interfaces

| Name | Description |
|---|---|
| `AutomationType` | Union type for policy automation categories: `"software"`, `"scripts"`, `"calendar"`, `"conditional_access"`, `"other"` |
| `IPoliciesApiParams` | Query parameters for listing team policies, including pagination, ordering, and `mergeInherited` flag |
| `ITeamPoliciesQueryKey` | React Query key shape for team policy list queries |
| `ITeamPoliciesCountQueryKey` | React Query key shape for policy count queries |
| `IPoliciesCountApiParams` | Parameters for fetching a team's policy count |

### Exported API Methods

| Method | HTTP | Description |
|---|---|---|
| `create(data)` | `POST` | Creates a new policy under the specified team |
| `update(id, data)` | `PATCH` | Updates an existing policy, including automation fields |
| `destroy(teamId, ids)` | `POST` | Bulk-deletes policies by ID; rejects invalid team IDs |
| `load(team_id, id)` | `GET` | Loads a single policy by ID |
| `loadAll(team_id)` | `GET` | Loads all policies for a team (legacy, no pagination) |
| `loadAllNew(params)` | `GET` | Loads policies with pagination, ordering, and filtering |
| `getCount(params)` | `GET` | Returns the total policy count for a team |

### Utilities

- `convertParamsToSnakeCase` — Converts camelCase query param keys to `snake_case` before building the request URL.

## Usage Example

```typescript
import teamPoliciesAPI from "services/entities/team_policies";

// Fetch paginated policies, including inherited ones
const response = await teamPoliciesAPI.loadAllNew({
  teamId: 42,
  page: 0,
  perPage: 20,
  orderKey: "name",
  orderDirection: "asc",
  mergeInherited: true,
});

// Get the policy count for a team
const { count } = await teamPoliciesAPI.getCount({
  teamId: 42,
  mergeInherited: true,
});

// Delete multiple policies
await teamPoliciesAPI.destroy(42, [1, 2, 3]);
```

## Notes

- Automation-related fields (`calendar_events_enabled`, `conditional_access_enabled`, etc.) are only included in `update`, not `create` — they are set separately by the UI.
- `destroy` guards against invalid team IDs, rejecting calls where `teamId` is `undefined` or less than `API_NO_TEAM_ID`.
