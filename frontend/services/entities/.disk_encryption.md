Service module for managing disk encryption operations across macOS, Windows, and Linux platforms via the Fleet MDM API.

## Key Components

### Types & Interfaces

- **`IDiskEncryptionStatusAggregate`** — Per-platform counts (`macos`, `windows`, `linux`) for a given encryption status
- **`IDiskEncryptionSummaryResponse`** — Full summary keyed by `DiskEncryptionStatus`, mapping each status to its platform aggregate counts

### `diskEncryptionService`

| Method | Description |
|---|---|
| `getDiskEncryptionSummary(teamId?)` | Fetches disk encryption status summary; scopes to a team via query param when `teamId` is provided |
| `updateDiskEncryption(enable, requireBitLockerPIN, teamId?)` | Enables/disables disk encryption; routes to `CONFIG` endpoint when `teamId === 0` (no-team context) or `UPDATE_DISK_ENCRYPTION` for team-scoped updates |
| `triggerLinuxDiskEncryptionKeyEscrow(token)` | Triggers Linux disk encryption key escrow for a specific device token |

## Usage Example

```typescript
import diskEncryptionService from "services/disk_encryption";

// Fetch summary for a specific team
const summary = await diskEncryptionService.getDiskEncryptionSummary(42);
// summary.verified => { macos: 10, windows: 5, linux: 2 }

// Enable disk encryption + BitLocker PIN for a team
await diskEncryptionService.updateDiskEncryption(true, true, 42);

// Enable for no-team context (routes to CONFIG endpoint)
await diskEncryptionService.updateDiskEncryption(true, false, 0);

// Trigger Linux key escrow for a device
await diskEncryptionService.triggerLinuxDiskEncryptionKeyEscrow("device-token-abc");
```

## Notes

- When `teamId === 0`, `updateDiskEncryption` uses the `CONFIG` endpoint (PATCH) instead of `UPDATE_DISK_ENCRYPTION` (POST) due to a server-side limitation with the no-team context
- `fleet_id` is sent as `undefined` (not `0`) for the no-team case, as the server expects `nil` rather than `0`
