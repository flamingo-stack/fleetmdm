Provides a React context and provider for managing application-level redirect state, enabling components to read and set a pending redirect location without prop drilling.

## Key Components

- **`RoutingContext`** — React context exposing `redirectLocation` (current redirect path or `null`) and `setRedirectLocation` (setter function)
- **`RoutingProvider`** — Context provider component that wraps children and manages redirect state via `useReducer`
- **`reducer`** — Handles the `SET_REDIRECT_LOCATION` action to update `redirectLocation` in state

## Usage Example

```typescript
// Wrap your app or router root with the provider
import RoutingProvider, { RoutingContext } from "./routing";

function App() {
  return (
    <RoutingProvider>
      <MyRouter />
    </RoutingProvider>
  );
}

// Consume the context in any child component
import { useContext } from "react";
import { RoutingContext } from "./routing";

function LoginPage() {
  const { redirectLocation, setRedirectLocation } = useContext(RoutingContext);

  const handleLogin = () => {
    // Navigate to the stored redirect location after login
    if (redirectLocation) {
      navigate(redirectLocation);
      setRedirectLocation(null); // Clear after use
    }
  };

  return <button onClick={handleLogin}>Log in</button>;
}
```

## Notes

- `redirectLocation` is initialized to `null`; set it before redirecting a user (e.g., after authentication)
- The provider uses `useReducer` internally, making it straightforward to extend with additional routing actions if needed
