Thin wrapper around Lodash's `debounce` that applies sensible MSP-friendly defaults (leading-edge execution, no trailing call, 1-second timeout).

## Key Components

| Name | Type | Description |
|------|------|-------------|
| `IOptions` | Interface | Configuration shape for debounce behaviour |
| `leading` | `boolean` | Fire on the leading edge of the timeout (default: `true`) |
| `trailing` | `boolean` | Fire on the trailing edge of the timeout (default: `false`) |
| `timeout` | `number` | Debounce window in milliseconds (default: `1000`) |
| `DEFAULT_TIMEOUT` | `const` | Fallback timeout — 1 call per second |
| Default export | `function` | Factory that returns a debounced version of the supplied function |

## Usage Example

```typescript
import debounce from "./index";

// Uses defaults: leading=true, trailing=false, timeout=1000ms
const handleSearch = debounce((query: string) => {
  fetchResults(query);
});

// Custom options
const handleResize = debounce(
  () => recalculateLayout(),
  { leading: false, trailing: true, timeout: 300 }
);

// Call as normal — debounce is handled internally
handleSearch("macbook");
handleResize();
```

## Notes

- **Leading edge** execution means the function fires immediately on the first call, then is suppressed for the duration of `timeout`. This avoids the perceived delay of trailing-edge debounces in UI interactions.
- Swap `leading: false, trailing: true` for input-validation scenarios where you want to wait until the user stops typing.
