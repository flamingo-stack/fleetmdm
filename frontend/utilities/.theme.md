Manages light/dark/system theme state for the Fleet MDM UI, persisting the user's preference to `localStorage` and synchronizing it with the DOM and OS-level media queries.

## Key Components

| Export | Type | Description |
|---|---|---|
| `ThemeMode` | Type | Union: `"system" \| "light" \| "dark"` |
| `getThemeMode` | Function | Reads persisted preference from `localStorage`; falls back to `"system"` |
| `isDarkMode` | Function | Returns `true` if the resolved theme (accounting for OS preference) is dark |
| `setThemeMode` | Function | Persists a new mode, updates the DOM, and fires a `fleet-theme-change` event |
| `initTheme` | Function | Bootstraps the theme on page load and attaches an OS preference change listener |

## Usage Example

```typescript
import { initTheme, setThemeMode, getThemeMode, isDarkMode } from "./theme";

// Call once at app startup
initTheme();

// Read current preference
const mode = getThemeMode(); // "system" | "light" | "dark"
const dark = isDarkMode();   // true | false (OS-resolved)

// Change the theme
setThemeMode("dark");
setThemeMode("system"); // clears localStorage, re-follows OS

// Listen for theme changes from any source
window.addEventListener("fleet-theme-change", (e: Event) => {
  const { dark } = (e as CustomEvent<{ dark: boolean }>).detail;
  console.log("Theme changed, dark:", dark);
});
```

## Behaviour Notes

- **Transition guard** — `setThemeMode` only animates (via the `theme-transition` CSS class, held for 300 ms) when the resolved dark state *actually changes*, preventing gradient flicker when selecting a mode that matches the current state.
- **Restricted environments** — all `localStorage` access is wrapped in `try/catch`; DOM updates still apply even if persistence fails.
- **OS sync** — `initTheme` attaches a `matchMedia` listener that reacts to OS preference changes in real time, but is silently skipped when the user has an explicit `"light"` or `"dark"` preference set.
