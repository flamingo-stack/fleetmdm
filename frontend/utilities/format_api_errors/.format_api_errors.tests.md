Test suite for the `formatApiErrors` utility, verifying that raw API error responses are correctly transformed into a flat key-value map suitable for use with the Form HOC.

## Key Components

- **`formatApiErrors`** — Imported utility under test; converts structured API error arrays into a flat object keyed by field name.
- **`errorStub`** — Fixture representing a typical API error response containing a `response.errors` array with `name`/`reason` pairs.

## Usage Example

```typescript
import formatApiErrors from "utilities/format_api_errors";

const apiError = {
  response: {
    errors: [
      { name: "email", reason: "is not the correct format" },
      { name: "server_url", reason: "must be present" },
    ],
  },
};

formatApiErrors(apiError);
// Returns: { email: "is not the correct format", server_url: "must be present" }
```

## Test Coverage

| Scenario | Expected Output |
|---|---|
| Multiple field errors in response | Flat object with field names as keys and reason strings as values |

## Notes

- The utility flattens `response.errors[]` into `{ [name]: reason }` pairs, making errors directly consumable by form validation handlers.
- See the source at [`utilities/format_api_errors`](https://github.com/flamingo-stack/fleetmdm/blob/main/utilities/format_api_errors.ts) for implementation details.
