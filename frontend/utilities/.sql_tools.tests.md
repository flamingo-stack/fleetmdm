Unit tests for the `checkTable` SQL parsing utility, validating table extraction behavior across real tables, virtual/CTE tables, aliased columns, and invalid SQL inputs.

## Key Components

- **`checkTable` import** — Function under test from `./sql_tools`, which parses SQL and returns identified table names and any parse errors
- **Test suite: `"checkTable"`** — Four test cases covering core parsing scenarios

## Test Cases

| Test | Description |
|------|-------------|
| Default behavior | Returns only real (non-CTE) tables from a complex CTE query |
| `includeVirtualTables: true` | Returns real tables plus CTE-defined virtual tables |
| Alias disambiguation | Ensures column-reference aliases (`m`, `d`) are not mistaken for table names |
| Invalid SQL | Confirms a parse error is returned for malformed SQL input |

## Usage Example

```typescript
import { checkTable } from "./sql_tools";

// Extract only real tables (default)
const { tables, error } = checkTable("SELECT * FROM file JOIN parse_json ON ...");
// tables => ["file", "parse_json"]

// Include CTE virtual tables
const { tables: allTables } = checkTable(complexCteSQL, true);
// allTables => ["file", "parse_json", "cte_one", "cte_two", ...]

// Handle invalid SQL
const { error } = checkTable("SELECTx * FROM users");
// error !== null
```

## Notes

- The test SQL is sourced from real Fleet issues ([#26366](https://github.com/fleetdm/fleet/issues/26366), [#30109](https://github.com/fleetdm/fleet/issues/30109), [#34628](https://github.com/fleetdm/fleet/issues/34628), [#40117](https://github.com/fleetdm/fleet/issues/40117)), covering edge cases like bitwise operators, `GLOB`, `ESCAPE` clauses, and `OVER (PARTITION BY)` windows
- Function-style table references (e.g., `json_each`) are explicitly excluded even when `includeVirtualTables` is `true`
