Test suite for utility helper functions used across the FleetMDM frontend, covering OS version string manipulation, semantic version comparison, expiry date checking, and registration setup data processing.

## Key Components

| Function Under Test | Description |
|---|---|
| `removeOSPrefix` | Strips Apple OS prefix (e.g. `macOS`, `iOS`, `iPadOS`) from version strings |
| `compareVersions` | Semantic version comparator returning `-1`, `0`, or `1` |
| `willExpireWithinXDays` | Checks whether a date falls within a future window of N days |
| `helpers.setupData` | Transforms `IRegistrationFormData` into a JSON-safe setup payload |

## Usage Example

```typescript
import {
  removeOSPrefix,
  compareVersions,
  willExpireWithinXDays,
} from "./helpers";

// Strip OS name prefix
removeOSPrefix("macOS 14.1.2"); // → "14.1.2"
removeOSPrefix("iPadOS 17.5.1"); // → "17.5.1"

// Compare semantic versions
compareVersions("14.4.1", "14.4.2"); // → -1 (older)
compareVersions("14.4.4", "14.4.3"); // →  1 (newer)
compareVersions("14.3",   "14.3.0"); // →  0 (equal)

// Expiry window check
const soon = getFutureDate(5);
willExpireWithinXDays(soon, 10);  // → true  (expires within 10 days)
willExpireWithinXDays(soon, 3);   // → false (expires after 3-day window)

const past = getPastDate(5);
willExpireWithinXDays(past, 10);  // → false (already expired)
```

## Test Coverage Notes

- **`compareVersions`** is exercised across mixed-depth version strings (`"14"` vs `"14.0.0"`, `"14.3"` vs `"14.3.0"`) to confirm zero-padding equivalence.
- **`willExpireWithinXDays`** validates three states: within window, outside window, and already expired — using `getFutureDate`/`getPastDate` test utilities.
- **`setupData`** asserts that `org_logo_file` (a `File` object) is excluded from the serialised payload, ensuring binary data does not leak into JSON API calls.
