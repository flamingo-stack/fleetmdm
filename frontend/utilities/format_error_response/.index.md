Utility for normalizing Fleet API error responses into a flat, key-indexed object suitable for form error display or centralized error handling.

## Key Components

- **`formatServerErrors(errors: IFleetApiError[])`** — Transforms an array of Fleet API error objects into a `{ [name]: reason }` map. When multiple errors share the same `name`, their reasons are joined with a comma. Ensures a `base` fallback key is always populated.

- **`formatErrorResponse(errorResponse: any)`** — Entry point that extracts error arrays from two possible response shapes (`message.errors` or `data.errors`), delegates to `formatServerErrors`, and appends the HTTP status code under `http_status`.

## Usage Example

```typescript
import formatErrorResponse from "utilities/errors";

try {
  await someFleetApiCall();
} catch (errorResponse) {
  const formattedErrors = formatErrorResponse(errorResponse);

  // Access a base error message
  console.error(formattedErrors.base);

  // Access HTTP status
  console.error(formattedErrors.http_status); // e.g. 422

  // Access field-specific errors (keyed by error `name`)
  console.error(formattedErrors.email); // e.g. "Email is invalid, Email is taken"
}
```

## Notes

- Relies on `IFleetApiError` from [`interfaces/errors`](https://github.com/flamingo-stack/fleetmdm/blob/main/interfaces/errors.ts) for input typing; the returned shape is currently typed as `any` pending a migration to a stricter `IOldApiError` type.
- Multiple errors sharing the same `name` field are coalesced into a single comma-separated string rather than an array.
