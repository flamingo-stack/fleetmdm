Test suite for the `scripts_encoding` module, validating Base64 encoding behavior for script content transmitted via the `X-Fleet-Scripts-Encoded` HTTP header.

## Key Components

- **`SCRIPTS_ENCODED_HEADER`** — Verifies the constant equals `"X-Fleet-Scripts-Encoded"`
- **`encodeScriptBase64`** — Tests encoding across multiple input scenarios

## Test Coverage

| Scenario | Description |
|---|---|
| `undefined` input | Returns `undefined` |
| Empty string | Returns `""` |
| Simple strings | Encodes `"Hello World"` → `"SGVsbG8gV29ybGQ="` |
| PowerShell `${env:VAR}` patterns | Correctly encodes dollar-brace syntax that may trigger WAFs |
| PowerShell install scripts | Verifies round-trip decode via `atob()` |
| Multiline scripts | Handles `\n` within script bodies |
| Unicode/quoted strings | Validates UTF-8 safe round-trip |
| WAF-triggering patterns | Batch-tests known problematic strings for Go-compatible Base64 output |

## Usage Example

```typescript
import { encodeScriptBase64, SCRIPTS_ENCODED_HEADER } from "./scripts_encoding";

// Encode a PowerShell script before sending to Fleet API
const script = '$logFile = "${env:TEMP}/fleet-install.log"';
const encoded = encodeScriptBase64(script);

fetch("/api/scripts", {
  headers: { [SCRIPTS_ENCODED_HEADER]: "true" },
  body: encoded,
});

// Round-trip verification
console.log(atob(encoded!)); // '$logFile = "${env:TEMP}/fleet-install.log"'
```

## Notes

- Tests use `atob()` for round-trip decode verification, ensuring compatibility with Go's `base64.StdEncoding`
- PowerShell `${env:VAR}` patterns are explicitly covered due to known WAF-blocking behavior on raw script payloads
- `eslint-disable no-template-curly-in-string` comments suppress linting false positives on intentional dollar-brace literals
