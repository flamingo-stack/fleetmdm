Manages real-time live query campaign state updates by processing incoming WebSocket messages and transforming them into updated campaign state objects.

## Key Components

### Types
- **`IResult`** — WebSocket message containing query results for a single host
- **`IIncomingCampaignStatus`** — WebSocket message with campaign execution status and host counts
- **`ITotals`** — WebSocket message with aggregate host online/offline counts
- **`IError`** — WebSocket message for campaign-level errors
- **`ISocketData`** — Union type of all possible incoming socket message types

### Internal Helpers
- **`updateCampaignStateFromTotals`** — Merges host count totals into the campaign object
- **`updateCampaignStateFromResults`** — Appends per-host query results or errors, incrementing `uiHostCounts` accordingly; adds a fallback error message for osquery versions below 4.4.0
- **`updateCampaignStateFromStatus`** — Updates campaign status and server-side host counts; sets `queryIsRunning` to `false` when status is `"finished"`

### Exports
- **`updateCampaignState(socketData)`** — Primary export; returns a state updater function compatible with React state setters, dispatching to the appropriate handler based on `socketData.type`. Handles Redis connection failures with a user-facing flash notification.

## Usage Example

```typescript
import { updateCampaignState } from "path/to/index";

// Typically called inside a WebSocket message handler
socket.on("message", (rawData: ISocketData) => {
  setCampaignState(updateCampaignState(rawData));
});

// The returned updater receives the current ICampaignState
// and returns a partial state update:
// { campaign: ICampaign, queryIsRunning?: boolean }
```

> **Note:** `updateCampaignState` internally calls `useContext(NotificationContext)`, which means the outer function returned by `updateCampaignState` must be invoked within a React component render or effect context to comply with React's Rules of Hooks.
