Test suite for the `setThemeMode` utility, validating theme switching behavior including CSS class management, transition timing, custom event dispatching, and localStorage persistence.

## Key Components

- **`setThemeMode` import** — the function under test, sourced from `./theme`
- **Five test cases** covering:
  - No-op transition suppression (same visual state)
  - CSS class application (`dark-mode`, `theme-transition`)
  - Transition class cleanup after 300ms
  - `fleet-theme-change` custom event dispatching and payload
  - `localStorage` persistence and clearing for `system` mode

## Usage Example

```typescript
// Behavior validated by these tests:

// 1. No flicker on no-op mode change
setThemeMode("light"); // body already light → theme-transition NOT added

// 2. Real state flip adds transition class
setThemeMode("dark");  // body becomes dark → theme-transition IS added
//   → class removed after 300ms automatically

// 3. Event dispatched on every call
window.addEventListener("fleet-theme-change", (e) => {
  console.log(e.detail); // { dark: true } or { dark: false }
});

// 4. Persistence
setThemeMode("dark");   // localStorage["fleet-theme"] === "dark"
setThemeMode("system"); // localStorage["fleet-theme"] === null
```

## Test Setup

Each test resets `document.body.className` and `localStorage`, and uses `jest.useFakeTimers()` to control the 300ms transition window deterministically via `jest.advanceTimersByTime(300)`.
