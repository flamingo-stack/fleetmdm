Renders an "Access denied" page for API-only Fleet users who attempt to access the Fleet UI, automatically redirecting them based on their authentication state.

## Key Components

- **`ApiOnlyUser`** — Default export. A React component that validates the current user's type on mount and renders an access denial message with a logout redirect button.
- **`useEffect` (fetchCurrentUser)** — On mount, calls `usersAPI.me()` to determine user state:
  - No user → redirects to `/login`
  - Non-API-only user → redirects to `/dashboard`
  - API-only user → remains on the denial page
- **`AuthenticationFormWrapper`** — Wraps the content in the shared auth page layout with an "Access denied" header.

## Usage Example

```typescript
import ApiOnlyUser from "pages/ApiOnlyUser/ApiOnlyUser";

// Typically registered as a route handler in the Fleet router
<Route path={paths.API_ONLY_USER} component={ApiOnlyUser} />
```

The component receives `router` via React Router's injection:

```typescript
// InjectedRouter is passed automatically by React Router v3
const ApiOnlyUser = ({ router }: IApiOnlyUserProps): JSX.Element => {
  // Redirects to LOGOUT path on button click
  const handleClick = () => router.push(paths.LOGOUT);
  // ...
};
```

## Notes

- Redirects happen silently on mount — the denial UI is only shown when a confirmed API-only user is detected.
- The external docs link points to the FleetDM CLI documentation on API-only users.
