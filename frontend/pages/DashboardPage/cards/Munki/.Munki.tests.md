Test suite for the `Munki` dashboard card component, verifying that Munki issues and version data render correctly across the Issues and Versions tabs.

## Key Components

- **`describe("Munki card")`** — Top-level test suite scoped to the Munki card component
- **`renders data normally when present`** — Single test case covering both the Issues tab (default view) and the Versions tab (after user interaction)
- **`createCustomRenderer`** — Sets up a render context with `isPremiumTier`, `isGlobalAdmin`, and a mock current user
- **`IMunkiIssuesAggregate` / `IMunkiVersionsAggregate`** — Typed mock data representing Munki issue records (with `id`, `name`, `type`, `hosts_count`) and version records (with `version`, `hosts_count`)

## Usage Example

```typescript
// Running the test suite
// From the repository root:
```

```bash
npx jest Munki.tests.tsx
```

```typescript
// Core render pattern used in the test
const render = createCustomRenderer({
  context: {
    app: {
      isPremiumTier: true,
      isGlobalAdmin: true,
      currentUser: createMockUser(),
    },
  },
});

const { user } = render(
  <Munki
    errorMacAdmins={null}
    isMacAdminsFetching={false}
    munkiIssuesData={munkiIssuesData}
    munkiVersionsData={munkiVersionsData}
    selectedTeamId={undefined}
  />
);

// Verify Issues tab columns
expect(screen.getByText("Issue")).toBeInTheDocument();

// Switch to Versions tab
await user.click(screen.getByText("Versions"));
expect(screen.getByText("1.2.3")).toBeInTheDocument();
```

## What Is Tested

| Tab | Assertions |
|---|---|
| Issues (default) | Column headers (`Issue`, `Type`, `Hosts`), issue names, type labels (`Warning`, `Error`), host counts |
| Versions (after tab click) | Column headers (`Version`, `Hosts`), version string, host count |
