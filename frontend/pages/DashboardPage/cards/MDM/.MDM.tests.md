Test suite for the `MDM` dashboard card component, verifying correct data aggregation and rendering of MDM solutions and enrollment status rows.

## Key Components

- **"rolls up the data by mdm solution name"** — Verifies that multiple MDM solution entries sharing the same `name` are deduplicated into a single rendered row, and that entries with an empty `name` render as `"Unknown"`.
- **"render the correct number of Enrollment status"** — Simulates a tab click to the `"Status"` view and asserts that each enrollment status row (`On (automatic)` → `On (company-owned)`, `On (manual)`, `On (personal)` → `On (BYOD)`, `Off`, `Pending`) appears with the correct host count.

## Usage Example

```typescript
// Running the test suite
// From the repository root:
```

```bash
npx jest MDM.tests.tsx
```

```typescript
// Key mock factory used in tests
import { createMockMdmSummaryMdmSolution } from "__mocks__/mdmMock";

// Default mock (name: "MDM Solution")
createMockMdmSummaryMdmSolution();

// Override specific fields
createMockMdmSummaryMdmSolution({ name: "Test Solution", id: 3 });

// Empty name renders as "Unknown"
createMockMdmSummaryMdmSolution({ name: "", id: 8 });
```

## Notes

- Uses `renderWithSetup` (from `test/test-utils`) to access the `user` event object for simulating tab interactions via `userEvent`.
- Status label mapping is tested implicitly: the API value `"On (automatic)"` must render as `"On (company-owned)"` and `"On (personal)"` as `"On (BYOD)"`.
