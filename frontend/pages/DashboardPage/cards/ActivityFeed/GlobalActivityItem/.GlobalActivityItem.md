Renders individual activity feed entries for the global activity log, mapping each `ActivityType` to a human-readable JSX message with contextual details like host names, team assignments, platform labels, and performance impact.

## Key Components

- **`ACTIVITIES_WITH_DETAILS`** — Set of activity types that support expandable detail views via `ShowActivityDetailsHandler`
- **`TAGGED_TEMPLATES`** — Object of template functions keyed by activity type, each returning a JSX element or string describing the activity (e.g., `liveQueryActivityTemplate`, `mdmEnrolled`, `deletedHost`)
- **`getProfileMessageSuffix`** — Builds platform-aware team assignment copy for MDM profile activities
- **`getHostTeamAssignmentSuffix`** — Returns JSX suffix indicating team assignment or unassigned status
- **`getHistoricalDatasetLabel`** — Resolves a `HistoricalDataConfigKey` to its display label with graceful fallback for unknown keys
- **`getMacOSSetupAssistantMessage`** — Generates copy for Setup Assistant add/delete actions
- **`getProfilesPlatformDisplayName`** — Maps `"apple" | "windows" | "android"` to a user-friendly platform string

## Usage Example

```typescript
import GlobalActivityItem from "components/GlobalActivityItem";

<GlobalActivityItem
  activity={activity}
  isPremiumTier={true}
  onShowDetails={(activity) => openDetailsModal(activity)}
/>
```

## Notes

- Template functions receive an `IActivity` and optional `isPremiumTier: boolean`, destructuring `activity.details` for context-specific copy
- MDM enrollment messages handle platform branching (`microsoft`, `android`, `iOS/iPadOS`, and Apple MDM legacy fallback)
- Serial number display is suppressed when already embedded in `host_display_name` (e.g., `"Model (Serial)"` format)
