Test suite for the `ActivityFeed` component, validating activity rendering and pagination behavior using MSW mock handlers.

## Key Components

- **`describe("Activity Feed")`** — Top-level test suite grouping four behavioral tests
- **`activityHandlerHasMoreActivities`** / **`activityHandlerHasPreviousActivities`** — MSW handlers that override default server responses to simulate paginated activity states
- **`createCustomRenderer`** — Custom render utility with `withBackendMock: true` to enable MSW interception
- **`createMockRouter`** — Provides a mock Next.js-style router required by `ActivityFeed`

## Test Cases

| Test | Assertion |
|---|---|
| Renders correct number of activities | Three mock users (`Test User`, `Test User 2`, `Test User 3`) are present in the DOM |
| Hides pagination on single page | Previous/Next buttons are absent when all activities fit one page |
| Enables "Next" when more activities exist | Next button is enabled when `activityHandlerHasMoreActivities` handler is active |
| Enables "Previous" after navigating forward | Clicking Next then asserting Previous becomes enabled via `activityHandlerHasPreviousActivities` |

## Usage Example

```typescript
// Overriding the default MSW handler for a specific pagination scenario
import mockServer from "test/mock-server";
import { activityHandlerHasMoreActivities } from "test/handlers/activity-handlers";

mockServer.use(activityHandlerHasMoreActivities);

render(
  <ActivityFeed
    setShowActivityFeedTitle={noop}
    setRefetchActivities={noop}
    isPremiumTier
    router={createMockRouter()}
  />
);

await screen.findByRole("button", { name: "Next" });
expect(screen.getByRole("button", { name: "Next" })).toBeEnabled();
```
