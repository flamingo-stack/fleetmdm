React Testing Library test suite for the Dashboard Software card component, verifying correct rendering of both all-software and vulnerable-software views.

## Key Components

- **`describe("Dashboard software card")`** — Top-level test suite wrapping two scenarios
- **`vulnSwInfo` / `noVulnSwInfo`** — Fixture data representing software with and without CVEs
- **`allSwResponse` / `vulnSwResponse`** — Mock `ISoftwareResponse` payloads used to drive each test case
- **`Software`** — The component under test, imported from `./Software`

## Usage Example

```typescript
// Render the Software card with a mock router and software response
render(
  <Software
    errorSoftware={null}
    isSoftwareFetching={false}
    isSoftwareEnabled
    navTabIndex={0}         // 0 = All Software tab
    onTabChange={jest.fn()}
    onQueryChange={jest.fn()}
    software={allSwResponse}
    teamId={-1}
    router={createMockRouter()}
    softwarePageIndex={0}
  />
);

// Assert table headers are present
expect(screen.getByText("Name")).toBeInTheDocument();
expect(screen.getByText("Version")).toBeInTheDocument();
expect(screen.getByText("Hosts")).toBeInTheDocument();
```

## Test Cases

| Test | `navTabIndex` | Fixture Used | What's Verified |
|---|---|---|---|
| Renders all software | `0` | `allSwResponse` (1 vuln + 1 clean entry) | Table headers + all `noVulnSwInfo` field values visible |
| Renders vulnerable software | `1` | `vulnSwResponse` (1 vuln entry only) | Table headers + all `vulnSwInfo` field values visible |

Both tests use `screen.getAllByText` with a custom matcher (`element?.textContent === String(value)`) to handle cases where values may be rendered inside composite DOM nodes, ensuring name, version, and host count are all displayed correctly.
