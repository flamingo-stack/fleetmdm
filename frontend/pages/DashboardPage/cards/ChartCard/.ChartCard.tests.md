Test suite for the `ChartCard` component, covering visualization rendering, empty states, data collection toggle behavior, and role-based UI differences using MSW for API mocking.

## Key Components

- **`MockResizeObserver`** — Stub that synchronously fires resize callbacks with fixed dimensions (`600×400`), enabling deterministic layout-dependent rendering (e.g., SVG `<rect>` elements in `CheckerboardViz`)
- **`generateMockChartResponse`** — Factory that produces synthetic chart API responses for a given `metric` and `days` count, with half-hourly data points
- **`chartHandler`** / **`emptyChartHandler`** — MSW request handlers intercepting `GET /charts/:metric` to return populated or empty data respectively

## Test Cases

| Test | Assertion |
|---|---|
| Checkerboard renders for `uptime` | SVG `<rect>` elements present; legend labels visible |
| Empty API response | Displays `"No chart data available yet."` |
| Dataset heading | `"Hosts online"` heading rendered (single dataset, no dropdown) |
| Admin empty state | Shows `"Data collection is disabled"` + **Turn on** button |
| Non-admin empty state | Shows `"Data collection is disabled"` + ask-admin copy; **Turn on** button absent |
| Collection enabled | Chart renders normally; empty-state message absent |

## Usage Example

```typescript
// Run the full suite
npx jest ChartCard.tests.tsx

// Use handlers independently in other test files
import { http, HttpResponse } from "msw";
import { baseUrl } from "test/test-utils";
import mockServer from "test/mock-server";

mockServer.use(
  http.get(baseUrl("/charts/:metric"), ({ params }) => {
    return HttpResponse.json(generateMockChartResponse(params.metric as string, 7));
  })
);
```
