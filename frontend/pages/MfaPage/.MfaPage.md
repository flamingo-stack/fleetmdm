Handles the Multi-Factor Authentication (MFA) completion flow, verifying a one-time MFA token from URL params, exchanging it for a session, and redirecting users to the appropriate post-login destination.

## Key Components

- **`MfaPage`** — Default export. React page component that manages three UI states: pending login confirmation, processing/spinner, and expired/invalid token error.
- **`finishMFA`** — Async handler that calls `sessionsAPI.finishMFA`, saves the auth token, hydrates global app state (`currentUser`, `availableTeams`, `config`), and routes the user based on role/password-reset requirements.
- **`shouldFinishMFA`** — State flag (seeded from `localStorage` key `auth_pending_mfa`) that triggers the MFA exchange automatically on mount when set.
- **`isExpired`** — State flag set to `true` on API failure, rendering the "Invalid token" error UI.

## Usage Example

```typescript
// Rendered by the router when navigating to /mfa/:token
import MfaPage from "pages/MfaPage";

// Route definition (react-router v3)
<Route path="/mfa/:token" component={MfaPage} />
```

```typescript
// Initiating MFA from a prior login step — sets the flag before redirect
local.setItem("auth_pending_mfa", "true");
router.push(`/mfa/${mfaToken}`);
```

**Redirect logic after successful MFA:**

| Condition | Destination |
|---|---|
| No role and no teams | `NO_ACCESS` |
| `force_password_reset` | `RESET_PASSWORD` |
| Default | `redirectLocation` or `DASHBOARD` |

## Notes

- The `auth_pending_mfa` localStorage item is cleared immediately on component mount to prevent replay.
- If `currentUser` is already set in `AppContext`, the page short-circuits to `DASHBOARD` via a `useEffect`.
