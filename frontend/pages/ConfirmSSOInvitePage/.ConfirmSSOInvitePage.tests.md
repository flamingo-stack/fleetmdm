Test suite for the `ConfirmSSOInvitePage` component, verifying SSO invite confirmation flows including successful user creation with SSO initialization and invalid token error handling.

## Key Components

- **`renderPage(token)`** — Helper that wraps `ConfirmSSOInvitePage` in a `QueryClientProvider` with retry/cache disabled, accepting an optional invite token string
- **`"calls usersAPI.create..."`** — Tests the happy path: verifies the invite, pre-fills the email field (disabled), submits the form, and asserts `usersAPI.create` and `sessionsAPI.initializeSSO` are called with correct payloads
- **`"renders the invalid invite token message..."`** — Tests the failure path: rejects `inviteAPI.verify` with a 404 error and asserts the error message renders without the form

## Mocked APIs

| Mock | Module |
|------|--------|
| `mockInviteAPI` | `services/entities/invites` |
| `mockUsersAPI` | `services/entities/users` |
| `mockSessionsAPI` | `services/entities/sessions` |

## Usage Example

```typescript
// Run these tests with Jest
jest.mock("services/entities/invites");
jest.mock("services/entities/users");
jest.mock("services/entities/sessions");

// Happy path: mock a valid invite and assert SSO flow
mockInviteAPI.verify.mockResolvedValue({ invite: { email: "user@example.com", ... } });
mockUsersAPI.create.mockResolvedValue({} as IUser);
mockSessionsAPI.initializeSSO.mockRejectedValue(new Error("redirect skipped"));
// initializeSSO is intentionally rejected to prevent JSDOM navigation errors
// while still asserting it was called
```

> **Note:** `sessionsAPI.initializeSSO` is deliberately rejected in the success test to short-circuit `window.location.href` assignment, which JSDOM does not support.
