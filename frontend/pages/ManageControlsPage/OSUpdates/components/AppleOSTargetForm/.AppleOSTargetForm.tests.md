Test suite for the `AppleOSTargetForm` component, validating rendering and save behavior across Apple platforms (macOS, iOS, iPadOS) with MSW-mocked backend requests.

## Key Components

- **`describe("AppleOSTargetForm")`** — Top-level test suite covering three Apple platform variants
- **`updateTeamConfigHandler`** — MSW handler intercepting `PATCH /api/latest/fleet/fleets/1` to capture request payloads
- **`renderWithBackend`** — Custom renderer with backend mock support enabling user interaction simulation

## Test Cases

| Test | Platform | What it validates |
|------|----------|-------------------|
| Renders correct form for macOS | `darwin` | Min version, deadline inputs + "Update new hosts" checkbox presence |
| Saves `update_new_hosts` for macOS | `darwin` | Checkbox toggling reflects in `mdm.macos_updates` payload |
| Renders correct form for iOS | `ios` | Min version, deadline inputs; "Update new hosts" checkbox **absent** |
| Saves config for iOS | `ios` | `update_new_hosts` not sent in `mdm.ios_updates` payload |
| Renders correct form for iPadOS | `ipados` | Min version, deadline inputs; "Update new hosts" checkbox **absent** |
| Saves config for iPadOS | `ipados` | `update_new_hosts` not sent in `mdm.ipados_updates` payload |

## Usage Example

```typescript
// Running the test suite
import { render, screen } from "@testing-library/react";
import AppleOSTargetForm from "./AppleOSTargetForm";

render(
  <AppleOSTargetForm
    currentTeamId={1}
    applePlatform="darwin"
    defaultMinOsVersion="14.0"
    defaultDeadline="2025-06-30"
    defaultUpdateNewHosts={false}
    refetchAppConfig={jest.fn()}
    refetchTeamConfig={jest.fn()}
  />
);
```

## Key Behaviors Verified

- **macOS only**: "Update new hosts" checkbox is rendered and its toggled state is persisted in the `PATCH` request body under `mdm.macos_updates.update_new_hosts`
- **iOS / iPadOS**: The checkbox is intentionally absent and `update_new_hosts` is never included in the respective `mdm.ios_updates` / `mdm.ipados_updates` payloads
