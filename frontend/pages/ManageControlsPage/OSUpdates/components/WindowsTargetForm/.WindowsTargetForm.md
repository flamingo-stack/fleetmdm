Form component for configuring Windows OS update enforcement settings (deadline and grace period days) per team or globally, with validation and API submission.

## Key Components

### Interfaces
- **`IWindowsTargetFormData`** — Form state shape: `deadlineDays` and `gracePeriodDays` as strings
- **`IWindowsTargetFormProps`** — Component props: team ID, defaults, and refetch callbacks
- **`IWindowsMdmConfigData`** — MDM API payload shape for Windows update config

### Validation Helpers
- **`validateDeadlineDays`** — Accepts integers `0–30`; rejects empty strings
- **`validateGracePeriodDays`** — Accepts integers `0–7`; rejects empty strings
- **`validateForm`** — Cross-field validation: both fields empty clears enforcement; grace period requires a deadline to be set

### Component: `WindowsTargetForm`
- Submits to `configAPI.update` (no-team context) or `teamsAPI.update` (team-scoped)
- Optimistic error UX: on change, only clears/updates errors that already exist; full validation fires on blur
- GitOps mode awareness: disables all inputs and the Save button via `GitOpsModeTooltipWrapper`

## Usage Example

```typescript
<WindowsTargetForm
  currentTeamId={selectedTeamId}
  defaultDeadlineDays="7"
  defaultGracePeriodDays="2"
  refetchAppConfig={refetchAppConfig}
  refetchTeamConfig={refetchTeamConfig}
/>
```

## Notes

- Both fields empty is treated as a valid "clear enforcement" state (sends `null` to the API)
- A known edge case exists when the user switches teams or tabs during form submission — the component unmounts mid-request, leaving the save in an unresolved state (marked `FIXME` in source)
