Utility module for handling Bootstrap package upload error messages, mapping API error reasons to user-friendly messages with optional React content.

## Key Components

### `UPLOAD_ERROR_MESSAGES`
A map of named error conditions with:
- `condition(reason)` — predicate matching against the API error string
- `message` — a string or JSX element to display to the user

| Key | Trigger | Message |
|---|---|---|
| `wrongType` | `"invalid file type"` | Prompt to use a `.pkg` file |
| `unsigned` | `"file is not"` | Prompt to sign the package |
| `noDistribution` | `"Bootstrap package must be a distribution package"` | JSX with a "Learn more" link |
| `default` | Never matches | Generic retry message |

### `getErrorMessage(err)`
Accepts an Axios API error response, extracts the first error `reason`, and returns the matching message (string or JSX). Falls back to the `default` message if no condition matches.

## Usage Example

```typescript
import { getErrorMessage } from "./helpers";

try {
  await uploadBootstrapPackage(file);
} catch (err) {
  const message = getErrorMessage(err.response);
  // message may be a string or a React node
  showFlashMessage(message);
}
```

## Notes

- Messages may be either `string` or `React.ReactNode` — rendering components should handle both types.
- The `noDistribution` error includes a [`CustomLink`](https://github.com/flamingo-stack/fleetmdm/blob/main/components/CustomLink) pointing to `/macos-distribution-packages` docs.
- The `default` condition always returns `false`, making it a safe fallback when no other condition matches.
