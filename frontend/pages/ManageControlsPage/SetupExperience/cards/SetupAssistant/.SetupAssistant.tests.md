Integration tests for the `SetupAssistant` component, verifying rendering behavior across three MDM configuration states: MDM not configured, MDM configured with no profile uploaded, and MDM configured with an existing profile.

## Key Components

- **`setupMdmConfigured`** — Helper that registers MSW handlers simulating a fully configured MDM environment
- **`setupMdmNotConfigured`** — Helper that registers MSW handlers simulating MDM disabled (`enabled_and_configured: false`)
- **Test suite** — Three `it` blocks covering the main conditional rendering paths of `SetupAssistant`

## Test Cases

| Scenario | Expected Behavior |
|---|---|
| MDM not configured | Shows "Additional configuration required" empty state |
| MDM configured, no profile | Shows "Add profile" button and uploader UI |
| MDM configured, profile uploaded | Shows uploaded profile card with filename |

## Usage Example

```typescript
// Run the full suite
// npx jest SetupAssistant.tests.tsx

// The tests use MSW to mock two endpoints:
// GET /enrollment_profiles/automatic        → per-team profile
// GET /enrollment_profiles/automatic/default → default/fallback profile

// Example: override a handler inside a test
mockServer.use(
  http.get(enrollmentProfileUrl, () => {
    return HttpResponse.json({
      team_id: 1,
      name: "test-profile.json",
      uploaded_at: "2024-01-01T00:00:00Z",
      enrollment_profile: {},
    });
  })
);
```

## Dependencies

- [`msw`](https://mswjs.io/) for API mocking via `mockServer`
- `@testing-library/react` for `screen` and `waitFor` assertions
- Custom test utilities: `createCustomRenderer`, `createMockRouter`, `baseUrl`
- Mock factories: `createGetConfigHandler`, `createGetTeamHandler`, `createMockMdmConfig`
