Test suite for the `RunScript` component, validating rendering behavior across MDM configuration states and script upload scenarios in the setup experience flow.

## Key Components

- **`RunScript` component under test** — Renders the setup experience script configuration UI
- **Mock handlers used:**
  - `errorNoSetupExperienceScriptHandler` — Simulates no script uploaded
  - `createSetupExperienceScriptHandler` — Simulates an existing uploaded script
  - `createGetConfigHandler` — Controls MDM configuration state
  - `createGetTeamHandler` — Provides team context
- **`createMockMdmConfig`** — Factory for MDM config mock data

## Test Cases

| Scenario | Expected Behavior |
|---|---|
| MDM not configured | Shows page description + "Turn on MDM and automatic enrollment" |
| MDM configured, ABM disabled | Shows "Turn on MDM and automatic enrollment" |
| MDM fully configured, no script uploaded | Shows "Upload" button |
| MDM fully configured, script uploaded | Shows script name and setup label |

## Usage Example

```typescript
// Typical test pattern used in this suite
const render = createCustomRenderer({ withBackendMock: true });

mockServer.use(errorNoSetupExperienceScriptHandler);
mockServer.use(createGetConfigHandler({
  mdm: createMockMdmConfig({ enabled_and_configured: false }),
}));
mockServer.use(createGetTeamHandler({}));

render(<RunScript router={createMockRouter()} currentTeamId={1} />);

expect(
  await screen.findByText(/Turn on MDM and automatic enrollment/i)
).toBeInTheDocument();
```

> **Note:** Tests account for a 250ms anti-flash spinner delay — mocked requests resolve before the spinner renders, so `queryByTestId("spinner")` is expected to be absent throughout.
