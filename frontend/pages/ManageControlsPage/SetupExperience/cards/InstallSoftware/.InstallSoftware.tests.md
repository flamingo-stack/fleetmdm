Test suite for the `InstallSoftware` component, validating rendering behavior across MDM configuration states and platform types (macOS, Android).

## Key Components

- **`setupMdmNotConfigured`** — Configures mock server with MDM disabled (`enabled_and_configured: false`)
- **`setupMdmConfigured`** — Configures mock server with MDM fully enabled using default config handlers
- **Test Suite (`InstallSoftware`)** — Three test cases covering:
  - Empty state rendering when MDM is not configured (macOS)
  - Software form rendering when MDM is configured (macOS)
  - Android-specific empty state with correct messaging

## Usage Example

```typescript
// Running the test suite
// From the repository root:
// npx jest InstallSoftware.tests.tsx

// Example: adding a new platform test case
it("renders the Windows empty state", async () => {
  mockServer.use(createSetupExperienceSoftwareHandler());
  mockServer.use(
    createGetConfigHandler({
      mdm: createMockMdmConfig({ enabled_and_configured: false }),
    })
  );
  mockServer.use(createGetTeamHandler({}));

  const render = createCustomRenderer({ withBackendMock: true });

  render(
    <InstallSoftware
      router={createMockRouter()}
      currentTeamId={1}
      urlPlatformParam="windows"
    />
  );

  await waitFor(() => {
    expect(screen.getByText(/Turn on MDM/)).toBeInTheDocument();
  });
});
```

## Test Coverage

| Scenario | Platform | MDM State | Expected Output |
|---|---|---|---|
| MDM not configured | macOS | Disabled | "Turn on MDM and automatic enrollment" empty state |
| MDM configured | macOS | Enabled | Software form with "Save" button |
| Android MDM not configured | Android | Disabled | "Turn on Android MDM" empty state |
