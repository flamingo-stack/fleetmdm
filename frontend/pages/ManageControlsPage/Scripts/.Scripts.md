Renders the top-level Scripts page, providing team-scoped navigation for managing scripts across macOS, Windows, and Linux hosts.

## Key Components

- **`Scripts`** – Main page component that reads the active `section` URL param, resolves the current team via `useTeamIdParam`, and renders the appropriate sub-section card inside a `SideNav` layout.
- **`ScriptsLocation`** – Interface describing the expected URL shape (`fleet_id`, `status`, `page`, `add_script` query params).
- **`IScriptsProps`** – Props interface for `Scripts`, accepting `router`, `location`, and `params`.

## Usage Example

```typescript
// Rendered by the router when the user navigates to /controls/scripts/:section
<Scripts
  router={router}
  location={location}
  params={{ section: "saved-scripts" }}
/>
```

## Behavior Notes

- Uses `useTeamIdParam` to derive `teamIdForApi`; falls back to `API_NO_TEAM_ID` when no team is selected.
- Nav items are sourced from `useScriptNavItems(teamIdForApi)`, so available sections can vary by team context.
- If the `:section` URL param does not match any known nav item, the component redirects to the default section path and returns `null` to prevent a flash of incorrect content.
- The active card receives `teamId` as a required prop to ensure scripts are always scoped to a team.
