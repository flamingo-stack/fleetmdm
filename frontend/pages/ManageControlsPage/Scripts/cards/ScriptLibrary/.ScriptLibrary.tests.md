Test suite for the `ScriptLibrary` component, validating empty-state rendering and `?add_script=1` deep-link behavior across different user roles and script configuration states.

## Key Components

- **`ScriptLibrary empty state`** – Tests that verify the Upload CTA and info text render correctly based on user role (`isGlobalAdmin`, `isGlobalTechnician`, `isTeamTechnician`) and the `scripts_disabled` server setting.
- **`ScriptLibrary ?add_script=1 deep-link`** – Tests covering the modal open/close lifecycle when the `add_script` query parameter is present, including re-opening after dismissal and role-based access control.
- **`emptyScriptsHandler`** – MSW handler intercepting `GET /scripts` to return an empty list, used across all test cases.
- **`baseProps`** – Shared props (`router`, `teamId`, `location`) passed to `ScriptLibrary` in most test cases.

## Usage Example

```typescript
// Run the full suite
npx jest ScriptLibrary.tests.tsx

// Example: Render with deep-link location
render(
  <ScriptLibrary
    router={createMockRouter()}
    teamId={1}
    location={{
      pathname: "/controls/scripts/library",
      query: { add_script: "1" },
      search: "?add_script=1",
    }}
  />
);

// Expect modal to open and query param to be stripped
await waitFor(() => {
  expect(screen.getAllByText("Add script")).toHaveLength(2);
});
expect(router.replace).toHaveBeenCalledWith({
  pathname: "/controls/scripts/library",
  query: {},
});
```
