A confirmation modal component for deleting scripts in Fleet MDM, handling the delete API call with loading state and error/success notifications.

## Key Components

### `IDeleteScriptModalProps`
| Prop | Type | Description |
|------|------|-------------|
| `scriptName` | `string` | Display name of the script to delete |
| `scriptId` | `number` | ID passed to the delete API call |
| `onCancel` | `() => void` | Callback to close the modal without deleting |
| `afterDelete` | `() => void` | Callback invoked after the delete attempt (success or failure) |
| `isHidden` | `boolean?` | Optionally hides the modal (default: `false`) |

### `DeleteScriptModal`
The default export. Renders a `Modal` with a warning message and two action buttons (`Delete` / `Cancel`). Calls `scriptAPI.deleteScript` on confirm, surfaces a flash notification for success or error, and handles a special case where policy automation errors are forwarded verbatim.

## Usage Example

```typescript
import DeleteScriptModal from "components/DeleteScriptModal";

<DeleteScriptModal
  scriptName="remediate_malware.sh"
  scriptId={42}
  onCancel={() => setShowDeleteModal(false)}
  afterDelete={() => {
    setShowDeleteModal(false);
    refetchScripts();
  }}
/>
```

## Behavior Notes

- **Loading state**: the `Delete` button shows a spinner and the modal content is disabled while the API call is in flight.
- **Error handling**: generic errors show `"Couldn't delete. Please try again."` Policy automation errors surface the raw API message.
- **Enter key**: `onEnter` is wired to the delete handler, so pressing Enter confirms deletion.
- **Pending executions**: the modal warns that pending executions are cancelled, but any script already running on a host will complete without returning results to Fleet.
