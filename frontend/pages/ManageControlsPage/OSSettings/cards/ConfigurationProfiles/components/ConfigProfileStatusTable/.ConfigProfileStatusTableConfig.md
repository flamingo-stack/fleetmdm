Defines the table configuration and data transformation for displaying MDM configuration profile status summaries, mapping profile statuses to visual indicators and host counts.

## Key Components

### Constants
- **`STATUS_ORDER`** – Defines the fixed display order: `verified → verifying → pending → failed`
- **`STATUS_DISPLAY_OPTIONS`** – Maps each `MdmProfileStatus` to a display name and `IndicatorStatus` (e.g., `"verified"` → `"success"`, `"failed"` → `"error"`)

### Interfaces
- **`IConfigProfileRowData`** – Row shape with `status: string` and `hosts: number`
- **`IStatusCellValue`** – Cell value shape containing `displayName` and `statusName`

### Exported Functions
- **`generateTableConfig(teamId, uuid, profileStatus, onClickResend)`** – Returns the two-column `react-table` config:
  - **Status column** – Renders a `StatusIndicatorWithIcon` using mapped display options
  - **Hosts column** – Renders a `ConfigProfileHostCountCell` with resend callback
- **`generateTableData(profileStatus)`** – Transforms an `IGetConfigProfileStatusResponse` into ordered `IConfigProfileRowData[]` rows, always following `STATUS_ORDER`

## Usage Example

```typescript
import {
  generateTableConfig,
  generateTableData,
} from "./ConfigProfileStatusTableConfig";

const columns = generateTableConfig(
  teamId,
  profileUuid,
  profileStatus,
  (hostCount, status) => handleResend(hostCount, status)
);

const data = generateTableData(profileStatus);
// → [
//   { status: "verified", hosts: 42 },
//   { status: "verifying", hosts: 5 },
//   { status: "pending", hosts: 10 },
//   { status: "failed", hosts: 3 },
// ]
```

> **Note:** `generateTableData` always returns rows in `STATUS_ORDER` regardless of the key order in the API response.
