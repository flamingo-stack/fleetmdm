A React modal component for adding a new certificate by collecting form data (name, certificate authority, subject name, and SAN), validating inputs, and submitting to the certificates API.

## Key Components

- **`IAddCertFormData`** — Exported interface defining the form fields: `name`, `certAuthorityId`, `subjectName`, and `subjectAlternativeName`
- **`IAddCertModalProps`** — Props interface with `onExit`, `onSuccess` callbacks and optional `currentTeamId`
- **`AddCertModal`** — Default export; orchestrates form state, client-side validation, server error handling, and CA dropdown population via `react-query`
- **`formValidation`** — Derived via `useMemo` from `formData` + `attemptedSubmit`; avoids redundant state per React best practices
- **`serverErrors`** — Tracks field-level server errors (name conflict, invalid SAN) cleared on user edit

## Usage Example

```typescript
import AddCertModal, { IAddCertFormData } from "./AddCertificateModal";

const MyPage = () => {
  const [showModal, setShowModal] = useState(false);

  return (
    <>
      {showModal && (
        <AddCertModal
          currentTeamId={42}
          onExit={() => setShowModal(false)}
          onSuccess={() => {
            // Refresh certificate list or perform post-add logic
            refetchCertificates();
          }}
        />
      )}
    </>
  );
};
```

## Behavior Notes

- Fetches available certificate authorities on mount via `certificatesAPI.getCertificateAuthoritiesList()`; renders `<Spinner />` while loading and `<DataError />` on failure
- Client-side validation runs on every render but error messages surface only after the first submit attempt (`attemptedSubmit`)
- Server errors for `already exists` (name) and `subject_alternative_name` are mapped to their respective fields; all other API errors show a flash notification
- Links to the Certificate Authorities admin page (`paths.ADMIN_INTEGRATIONS_CERTIFICATE_AUTHORITIES`) within the CA dropdown help text
