Validation helpers for the "Add Certificate" modal form, providing form validation logic, error message constants, and type definitions for the `IAddCertFormData` shape.

## Key Components

- **`IAddCertFormValidation`** — Interface describing per-field validation state (`isValid`, optional `message`) plus a top-level `isValid` flag.
- **Error message constants** — `INVALID_NAME_MSG`, `NAME_TOO_LONG_MSG`, `NAME_REQUIRED_MSG`, `CA_REQUIRED_MSG`, `SUBJECT_NAME_REQUIRED_MSG` for consistent user-facing error strings.
- **`generateFormValidations()`** — Builds and returns the full validation config (`IFormValidations`) covering `name`, `certAuthorityId`, `subjectName`, and `subjectAlternativeName` fields.
- **`validateFormData()`** — Runs all validations against current form data, returning an `IAddCertFormValidation` result. Required-field messages are suppressed until the first submit attempt; format errors surface immediately as the user types.

## Usage Example

```typescript
import {
  generateFormValidations,
  validateFormData,
} from "./helpers";

const validationConfig = generateFormValidations();

// During typing (attemptedSubmit = false): required errors suppressed
const liveResult = validateFormData(formData, validationConfig, false);

// On submit (attemptedSubmit = true): all errors shown
const submitResult = validateFormData(formData, validationConfig, true);

if (!submitResult.isValid) {
  console.log(submitResult.name?.message);        // "Name must be completed."
  console.log(submitResult.certAuthorityId?.message); // "Certificate authority must be completed."
}
```

> **Note:** `subjectAlternativeName` has no client-side validations — format and length errors are returned by the server as `422` responses and surfaced in `AddCertificateModal.tsx`.
