Validation helper for the Add Custom Variable modal form, providing field-level validation rules and a `validateFormData` function for the `name` and `value` fields.

## Key Components

- **`IAddCustomVariableFormValidation`** — Interface describing the validation result shape, including per-field `isValid` flags and optional error messages.
- **`FORM_VALIDATIONS`** — Internal constant defining all validation rules per field:
  - `name`: required, alphanumeric/underscore only (`^[a-zA-Z0-9_]+$`), max 255 characters, must not begin with `FLEET_SECRET_`
  - `value`: required
- **`validateFormData(formData, isSaving?)`** — Main exported function that runs all field validations and returns an `IAddCustomVariableFormValidation` object. Required-field checks are skipped unless `isSaving` is `true`.

## Usage Example

```typescript
import { validateFormData } from "./helpers";

// During typing (required checks skipped)
const liveValidation = validateFormData({ name: "MY_VAR!", value: "" });
// liveValidation.name => { isValid: false, message: "Name may only include uppercase letters, numbers, and underscores" }

// On form submit (all checks run)
const submitValidation = validateFormData({ name: "MY_VAR", value: "" }, true);
// submitValidation.value => { isValid: false, message: "Value is required" }
// submitValidation.isValid => false

if (submitValidation.isValid) {
  // safe to save
}
```

## Notes

- The `required` validation is intentionally bypassed during live typing (`isSaving = false`) to avoid showing errors before the user has interacted with a field.
- A TODO exists in the source to abstract this pattern into a shared validator, as similar logic exists in other form validation files in the repository.
