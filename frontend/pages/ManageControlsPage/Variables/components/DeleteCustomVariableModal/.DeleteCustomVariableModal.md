Modal component for confirming and executing the deletion of a custom Fleet MDM variable, with error handling for in-use variables (HTTP 409).

## Key Components

- **`DeleteCustomVariableModal`** — Default export. A confirmation modal that calls `variablesAPI.deleteVariable` and handles success/error flash notifications.
- **`DeleteCustomVariableModalProps`** — Interface defining:
  - `variable: IVariable | undefined` — The variable to delete
  - `onExit: () => void` — Callback to close the modal
  - `onDeleteVariable: () => void` — Callback invoked on successful deletion
- **`isInUseError`** — Detects HTTP 409 conflicts when the variable is referenced by a profile or script, surfacing the API's error message directly.

## Usage Example

```typescript
import DeleteCustomVariableModal from "components/DeleteCustomVariableModal";

<DeleteCustomVariableModal
  variable={selectedVariable}
  onExit={() => setShowDeleteModal(false)}
  onDeleteVariable={() => {
    setShowDeleteModal(false);
    refetchVariables();
  }}
/>
```

## Error Handling

| Scenario | Behavior |
|---|---|
| Successful deletion | Flash success, calls `onDeleteVariable` |
| 409 "used by" conflict | Flash the API error message, calls `onExit` |
| Other API error | Flash generic error message, calls `onExit` |

## Notes

- The `variable` prop guard (`if (!variable) return`) prevents deletion when the prop is undefined.
- The variable name is rendered via `TooltipTruncatedText` to safely handle long names.
