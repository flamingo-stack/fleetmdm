A two-step live query page that orchestrates target selection and query execution for Fleet's live query workflow.

## Key Components

- **`RunQueryPage`** — Main page component managing the two-step live query flow:
  - **Step 1:** `SelectTargets` — choose hosts, labels, and teams to query
  - **Step 2:** `RunQuery` — execute the query against selected targets

- **Context consumers:**
  - `AppContext` — reads `live_query_disabled` server setting to gate access
  - `QueryContext` — syncs query metadata and selected targets across the app

- **Key queries (react-query):**
  - `["query", queryId]` — loads stored query details and populates `QueryContext`
  - `"hostFromURL"` — pre-selects a host passed via `?host_id=` query param

## Usage Example

```typescript
// Rendered via React Router at the live query route
<RunQueryPage
  router={router}
  params={{ id: "42" }}
  location={{
    pathname: "/queries/42/live",
    query: { host_id: "7", fleet_id: "3" },
    search: "",
  }}
/>
```

```typescript
// Step progression
setStep(LIVE_QUERY_STEPS[1]); // SelectTargets (default)
setStep(LIVE_QUERY_STEPS[2]); // RunQuery
```

## Notes

- If `live_query_disabled` is `true` in server settings, users are immediately redirected to the query report/editor instead of the live flow.
- The `host_id` query param is consumed once (`queryParamHostsAdded` flag) then cleared from the URL via `router.replace`.
- Target state (`targetedHosts`, `targetedLabels`, `targetedTeams`) is kept in sync with `QueryContext` via a `useEffect`.
- Browser tab title updates dynamically: `Run <QueryName> | Reports | Fleet`.
