React page component for editing and creating Fleet MDM queries, handling RBAC permissions, query persistence, and navigation to query report details.

## Key Components

| Export / Symbol | Description |
|---|---|
| `EditQueryPage` | Default page component for creating or editing an osquery-based report/query |
| `IEditQueryPageProps` | Props interface accepting `router`, `params`, and `location` |
| `onSubmitNewQuery` | Debounced handler that calls `queryAPI.create` and redirects to the report details page |
| `onUpdateQuery` | Handler that diffs current form state against last-saved context and calls `queryAPI.update` |
| `detectIsFleetQueryRunnable` | Checks live query service availability via `statusAPI.live_query()` |
| `renderLiveQueryWarning` | Renders an `InfoBanner` when live queries are unavailable |

## Usage Example

```typescript
// Rendered by the Fleet router at /queries/:id/edit
import EditQueryPage from "pages/queries/edit/EditQueryPage";

// Router configuration (react-router v3 style)
<Route
  path={PATHS.EDIT_QUERY(":id")}
  component={EditQueryPage}
/>
```

## Behavior Notes

- **RBAC redirect**: Observers, Observer+, and team-level users without edit rights are redirected from `/:id/edit` → `/:id` (report view).
- **Team URL fix**: For non-global users, the query's `team_id` is pushed into the URL via `fleet_id` query param to ensure correct team context.
- **Context hydration**: On load, populates `QueryContext` fields (`setLastEditedQueryName`, `setLastEditedQueryBody`, etc.) from the fetched stored query.
- **Duplicate name handling**: Both create and update paths surface user-friendly backend validation errors when a report name conflict is detected.
- **Browser tab title**: Dynamically set to `Editing <query name> | Reports | Fleet`.
