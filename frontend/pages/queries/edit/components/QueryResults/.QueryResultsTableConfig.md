Generates `react-table` column configurations dynamically from live query result rows, with automatic hostname promotion, host detail linking, and text truncation for long cell values.

## Key Components

### `generateColumnConfigsFromRows<T>` *(default export)*
Derives a full array of `Column<T>` configs from query result rows by:
- Inferring column types (numeric vs. string) via `getUniqueColsAreNumTypeFromRows`
- Excluding `host_id` from visible columns (used internally for linking)
- Rendering the `Host` column as a `LinkCell` pointing to `PATHS.HOST_DETAILS`
- Truncating cell values exceeding 300 characters via `internallyTruncateText`
- Setting `sortType` to `"alphanumeric"` or `"caseInsensitive"` based on inferred column type

### `_unshiftHostname<T>` *(internal)*
Repositions `host_display_name` to the front of the column array (renamed to `"Host"`), and strips the legacy `host_hostname` column retained temporarily for pre-v5 API compatibility.

## Usage Example

```typescript
import generateColumnConfigsFromRows from "./QueryResultsTableConfig";

// Query result rows from Fleet API
const rows = [
  { host_id: 1, host_display_name: "macbook-pro", os_version: "14.0" },
  { host_id: 2, host_display_name: "linux-box",   os_version: "22.04" },
];

const columns = generateColumnConfigsFromRows(rows);

// Pass to react-table or TableContainer
<TableContainer columns={columns} data={rows} />;
```

## Notes

- The `host_id` field must be present in row data for host detail links to resolve correctly, even though it is hidden from the rendered table.
- `@ts-ignore` is used when accessing `host_id` from `row.original` due to the generic `T` constraint; this is safe given the expected API shape.
- The legacy `host_hostname` removal is marked for cleanup after Fleet API v5.
