Renders and asserts display logic for the `NoResults` component, covering all combinations of user permissions (`canEditQuery`, `canLiveQuery`) and query schedule state.

## Key Components

- **`baseProps`** — shared baseline props (`queryId`, `disabledCaching`, `loggingSnapshot`, etc.) reused across all test cases
- **`no interval set` suite** — four cases exercising the 2×2 matrix of `canEditQuery` × `canLiveQuery` when `queryInterval={0}`
- **`has interval but no results yet` suite** — two cases for a scheduled query that hasn't collected data yet (`queryInterval={3600}`, `queryUpdatedAt` set to epoch)

## Usage Example

```typescript
// Run the full suite
npx jest NoResults.tests.tsx

// Run a specific describe block
npx jest --testNamePattern="no interval set"
```

## Test Coverage Summary

| Scenario | `canEditQuery` | `canLiveQuery` | Expected UI |
|---|---|---|---|
| No interval | ✅ | ✅ | "Add an interval" + live report link to `/reports/42/live` |
| No interval | ✅ | ❌ | "Add an interval" only |
| No interval | ❌ | ✅ | Live report link only |
| No interval | ❌ | ❌ | Static "does not collect data on a schedule" message |
| Has interval | — | ✅ | "Nothing to report yet" + live report link |
| Has interval | — | ❌ | "Nothing to report yet", no live report link |

## Notes

- Live report links are validated via `toHaveAttribute("href", expect.stringContaining("/reports/42/live"))`, confirming `queryId` is interpolated correctly
- Uses `screen.queryByText` (returns `null`) vs `screen.getByText` (throws) intentionally — absence assertions always use `queryByText`
- Component source: [`NoResults.tsx`](https://github.com/flamingo-stack/fleetmdm/blob/main/NoResults.tsx)
