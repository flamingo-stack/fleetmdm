Integration tests for the `QueryDetailsPage` component, specifically validating back-navigation logic across three URL resolution scenarios.

## Key Components

- **`setupQueryHandlers`** — Registers MSW interceptors for `/reports/:id` and `/reports/:id/report` endpoints, providing mock query and report data.
- **`createProps`** — Builds router/location props for the component, optionally injecting a `host_id` query parameter.
- **`baseAppContext`** — Shared app context fixture using `isFreeTier: true` to bypass team reconciliation redirects during testing.
- **`renderPage`** — Composes the renderer with context overrides and resolves the `back-button` test element.
- **`BackButton` mock** — Replaces the real `BackButton` with a plain `<button>` that exposes `path` and `text` as testable attributes without depending on `react-router`.

## Usage Example

```typescript
// The parameterized test suite covers three back-navigation cases:
it.each([
  {
    name: "hostId wins over filteredQueriesPath",
    app: { filteredQueriesPath: "/queries/manage?fleet_id=1" },
    hostId: 42,
    expectText: "Back to host details",
    expectPathContains: "/hosts/42/details",
  },
  {
    name: "falls back to filteredQueriesPath when no hostId",
    app: { filteredQueriesPath: "/queries/manage?fleet_id=1" },
    hostId: undefined,
    expectText: "Back to reports",
    expectPathContains: "/queries/manage?fleet_id=1",
  },
  {
    name: "falls back to manage reports when neither is set",
    app: {},
    hostId: undefined,
    expectText: "Back to reports",
    expectPathContains: "/reports/manage",
  },
])("$name", async ({ app, hostId, expectText, expectPathContains }) => {
  const back = await renderPage(app, hostId);
  expect(back).toHaveTextContent(expectText);
  expect(back.getAttribute("data-path")).toContain(expectPathContains);
});
```

## Back-Navigation Priority

```text
host_id query param → /hosts/:hostId/details
filteredQueriesPath → stored filtered queries path
default            → /reports/manage
```
