Renders the detailed view of a single Fleet query report, displaying query metadata, report data, and action buttons (show query, live report, edit) based on the user's RBAC permissions.

## Key Components

### `QueryDetailsPage`
Main page component that:
- Fetches query details via `queryAPI.load()` and report data via `queryReportAPI.load()`
- Populates `QueryContext` with the loaded query's properties
- Resolves navigation back path based on whether the user arrived from host details or the reports list
- Derives permission flags (`canLiveQuery`, `canEditQuery`, `canRunLiveReport`) from `AppContext` roles

### Permission Logic
| Flag | Condition |
|---|---|
| `canLiveQuery` | Observer can run OR observer+/admin/maintainer/technician role |
| `canEditQuery` | Global admin/maintainer OR team maintainer/admin with a team-scoped query |
| `canRunLiveReport` | `canLiveQuery` AND live query not globally disabled |

### Key Hooks
- `useTeamIdParam` — resolves `currentTeamId` from URL params
- `useQuery` (react-query) — fetches `storedQuery` and `queryReport` independently
- `useErrorHandler` — delegates fetch errors to the React error boundary

## Usage Example

```typescript
// Rendered by the router; receives params, router, and location automatically
<QueryDetailsPage
  router={router}
  params={{ id: "42" }}
  location={{
    pathname: "/reports/42",
    query: { fleet_id: "3", order_key: "host_name", order_direction: "asc" },
    search: "?fleet_id=3",
  }}
/>
```

> **Note:** Invalid `queryId` values (non-numeric) immediately redirect to `PATHS.MANAGE_REPORTS`. A team-level user whose URL `fleet_id` mismatches the query's `team_id` is automatically redirected to the correct team URL to avoid RBAC inconsistencies.
