Test suite for `getDeleteLabelErrorMessages`, a helper that maps API error responses to user-facing messages when deleting labels.

## Key Components

- **`make422`** — Local factory function that constructs a 422 error shape `{ status, errors }` for use across test cases.
- **`getDeleteLabelErrorMessages`** — The function under test (imported from `./helpers`), which maps error objects to localized UI strings.

## Test Coverage

| Scenario | Expected Message |
|---|---|
| Built-in label error (422) | `"Built-in labels can't be modified or deleted."` |
| Label used by a configuration profile (422) | `"Couldn't delete. A configuration profile targets this label..."` |
| Label used by a software target (other 422) | `"Couldn't delete. Software uses this label as a custom target..."` |
| Generic `Error` object (non-422) | `"Could not delete label. Please try again."` |
| Unknown error shape (e.g., `{ status: 500 }`) | `"Could not delete label. Please try again."` |

## Usage Example

```typescript
// Mirrors how getDeleteLabelErrorMessages is exercised in tests
import getDeleteLabelErrorMessages from "./helpers";

const error = {
  status: 422,
  errors: [{ name: "label", reason: "cannot delete built-in label" }],
};

const message = getDeleteLabelErrorMessages(error);
// → "Built-in labels can't be modified or deleted."
```

## Notes

- The helper distinguishes between specific 422 reasons (`"cannot delete built-in label"`, `"used by a configuration profile"`) and all other 422 reasons (treated as software-target errors).
- Any non-422 or structurally unexpected error falls back to a generic retry message, ensuring safe handling of network or server errors.
