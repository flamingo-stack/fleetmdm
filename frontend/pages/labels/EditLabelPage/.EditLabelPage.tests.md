Integration test suite for the `EditLabelPage` component, verifying correct rendering behavior across built-in, dynamic, and manual label types.

## Key Components

- **`generateMockRouterProps`** — Helper that constructs minimal mock router props with optional overrides, simulating React Router's injected route properties
- **`getLabelHandler`** — MSW request handler that mocks the label fetch API with configurable label attributes
- **`getLabelHostsHandler`** — MSW request handler that mocks the label hosts fetch API with a configurable host list
- **Test suite (`EditLabelPage`)** — Three test cases covering the main rendering branches of the page

## Test Cases

| Test | Condition | Expected Output |
|------|-----------|----------------|
| Built-in label | `label_type: "builtin"` | Displays "Built in labels cannot be edited" message |
| Dynamic label | `label_membership_type: "dynamic"` | Renders `DynamicLabelForm` with Query/Platform fields and immutability notice |
| Manual label | `label_membership_type: "manual"` | Renders `ManualLabelForm` with host selector and host list |

## Usage Example

```typescript
// Running a single test case
import { getLabelHandler } from "test/handlers/label-handlers";
import mockServer from "test/mock-server";

mockServer.use(getLabelHandler({ label_membership_type: "manual" }));

const render = createCustomRenderer({ withBackendMock: true });
render(
  <EditLabelPage
    routeParams={{ label_id: "1" }}
    location={{}}
    params={{}}
    route={{}}
    router={[]}
  />
);

const selectHostsLabel = await screen.findByText("Select hosts");
expect(selectHostsLabel).toBeInTheDocument();
```

## Notes

- All tests use `mockServer.use(...)` from MSW to intercept API calls without a real backend
- `createCustomRenderer({ withBackendMock: true })` wraps the component with necessary providers
- The `generateMockRouterProps` helper is flagged with a `TODO` to be extracted into a shared test utility
