Test suite for the `DynamicLabelForm` component, verifying form rendering and submission behavior.

## Key Components

- **Test: renders Fleet Ace and Select Platform input** — Confirms the query editor (`"Query"`) and platform selector (`"All platforms"`) are rendered on mount.
- **Test: passes form data on valid submission** — Simulates user input for name, description, and uses default query/platform props, then asserts `onSave` is called with the correct payload.

## Usage Example

```typescript
// Minimal render test
render(<DynamicLabelForm onSave={noop} onCancel={noop} teamName={null} />);
expect(screen.getByText("Query")).toBeInTheDocument();

// Submission test with renderWithSetup (includes userEvent setup)
const { user } = renderWithSetup(
  <DynamicLabelForm
    onSave={onSave}
    onCancel={noop}
    defaultQuery="SELECT * FROM users;"
    defaultPlatform="darwin"
    teamName={null}
  />
);
await user.type(screen.getByLabelText("Name"), "Test Name");
await user.click(screen.getByRole("button", { name: "Save" }));

expect(onSave).toHaveBeenCalledWith({
  name: "Test Name",
  description: "Test Description",
  query: "SELECT * FROM users;",
  platform: "darwin",
});
```

## Notes

- Uses `renderWithSetup` from [`test/test-utils`](https://github.com/flamingo-stack/fleetmdm/blob/main/test/test-utils.ts) to obtain a pre-configured `userEvent` instance for realistic user interactions.
- `defaultQuery` and `defaultPlatform` props seed the form state without user input, representing pre-filled or edit scenarios.
- `teamName={null}` is required by the component interface; tests cover the no-team context.
