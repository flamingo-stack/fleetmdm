Test suite for the `LabelsTable` component, validating rendering behavior when given builtin-only or mixed label collections.

## Key Components

- **`LabelsTable` (component under test)** — renders a table of custom labels, filtering out builtin labels
- **`createMockLabel`** — factory for generating label fixtures with configurable `label_type` and `label_membership_type`
- **`createMockUser`** — factory for generating a mock current user
- **`createCustomRenderer`** — test utility that wraps the render function with required providers

## Test Cases

| Test | Description |
|------|-------------|
| Empty state for builtin-only labels | Asserts `"No labels"` and helper text appear; builtin labels are not rendered |
| Custom labels rendered with builtins filtered | Asserts all three custom labels appear (name + description + type badge); builtin labels are hidden; table headers are present |

## Usage Example

```typescript
// Render LabelsTable with a mix of builtin and custom labels
const render = createCustomRenderer();
render(
  <LabelsTable
    labels={labels}
    onClickAction={noop}
    currentUser={mockUser}
  />
);

// Verify only custom labels appear
expect(screen.queryAllByText("Custom label 1")).toHaveLength(2); // row + tooltip
expect(screen.queryByText("All hosts")).not.toBeInTheDocument();
```

## Key Behaviors Verified

- Builtin labels (`label_type: "builtin"`) are **always filtered out** from display
- When no custom labels exist, an empty state is shown
- Each custom label renders its name in both the row and a tooltip (hence `toHaveLength(2)`)
- Membership types (`dynamic`, `manual`, `host_vitals`) are displayed as human-readable badges (`"Dynamic"`, `"Manual"`, `"Host vitals"`)
- Column headers `Name`, `Description`, and `Type` are present when custom labels exist
