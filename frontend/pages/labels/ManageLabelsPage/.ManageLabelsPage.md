Page component for managing Fleet MDM labels, providing a full CRUD interface for listing, creating, editing, and deleting device labels with GitOps mode awareness.

## Key Components

| Export / Symbol | Description |
|---|---|
| `ManageLabelsPage` | Default export — main page component rendering the labels table and action controls |
| `IManageLabelsPageProps` | Props interface requiring an `InjectedRouter` for programmatic navigation |
| `canAddLabel` | Permission gate derived from role context; controls visibility of the "Add label" button |
| `onClickAction` | Dispatcher handling `view_hosts`, `edit`, and `delete` table row actions |
| `onConfirmDelete` | Async handler that calls `labelsAPI.destroy`, flashes success/error, and refetches |
| `renderTable` | Conditional render helper returning `<Spinner>`, `<DataError>`, or `<LabelsTable>` |
| `labelsGitOpsManaged` | Boolean from `useGitOpsMode("labels")` controlling read-only behaviour when GitOps is active |

## Usage Example

```typescript
// Rendered by the router — no manual instantiation required.
// Route definition (illustrative):
import ManageLabelsPage from "pages/labels/ManageLabelsPage";

<Route path={PATHS.MANAGE_LABELS} component={ManageLabelsPage} />
```

```typescript
// Internal action dispatch handled by LabelsTable callbacks:
onClickAction("edit", label);     // → router.push(PATHS.EDIT_LABEL(label.id))
onClickAction("delete", label);   // → opens DeleteLabelModal
onClickAction("view_hosts", label); // → router.push(PATHS.MANAGE_HOSTS_LABEL(label.id))
```

## Permission Model

| Role | Can Add/Edit/Delete Labels |
|---|---|
| Global Admin | ✅ |
| Global Maintainer | ✅ |
| Global Technician | ✅ |
| Any Team Maintainer / Admin | ✅ |
| Any Team Technician | ✅ |
| Other roles | ❌ (read-only view) |

> When GitOps mode is enabled for `"labels"`, mutations are managed via the connected repository (`repoURL`) and the UI reflects a managed/read-only state via `LabelsTable`.
