A call-to-action card component that prompts users to wire up patch automation for policies that target a software package but don't yet have an install automation configured.

## Key Components

- **`PatchAutomationCta`** — Default export. Renders a card with a software name label and an "Add automation" button. Returns `null` when the policy is not a patch policy, has no `patch_software` target, already has a software automation, or the user lacks edit permissions.

### Props (`IPatchAutomationCtaProps`)

| Prop | Type | Description |
|---|---|---|
| `storedPolicy` | `IPolicy` | The current policy object |
| `canEditPolicy` | `boolean` | Whether the user has write access |
| `onAddAutomation` | `() => void` | Callback fired when the button is clicked |
| `isAddingAutomation` | `boolean?` | Shows a loading state on the button |

## Usage Example

```typescript
<PatchAutomationCta
  storedPolicy={policy}
  canEditPolicy={currentUser.canEditPolicies}
  onAddAutomation={handleAddAutomation}
  isAddingAutomation={isSaving}
/>
```

> **Note:** The component renders `null` silently when conditions aren't met, so callers can include it unconditionally without conditional guards.

## Render Conditions

The CTA renders only when **all** of the following are true:

- `storedPolicy.type === "patch"`
- `storedPolicy.patch_software` is defined
- `storedPolicy.install_software` is not yet set
- `canEditPolicy` is `true`

The button is wrapped in `GitOpsModeTooltipWrapper`, which automatically disables it when GitOps mode is active.
