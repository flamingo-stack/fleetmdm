Test suite for the `PolicyAutomationsList` component, verifying rendering of automation rows (software, script, calendar, conditional access, webhook/ticket) and footer text variants based on policy configuration.

## Key Components

### `createMockPolicy(overrides?)`
Factory function returning a minimal `IPolicy` object with sensible defaults, accepting partial overrides for targeted test scenarios.

### `SoftwareIcon` Mock
Stubs the `SoftwareIcon` component to expose `name` and `url` props as `data-testid` attributes, enabling assertion of icon-forwarding behavior without asset resolution.

### Test Groups

| Suite | Coverage |
|---|---|
| `automations list` | Empty state, software/script/calendar/conditional-access rows, icon URL/name forwarding, display name precedence, webhook vs ticket label |
| `footer text` | Default footer, continuous automations footer, footer visible in empty state |

## Usage Example

```bash
# Run this test file in isolation
npx jest PolicyAutomationsList.tests.tsx
```

```typescript
// Relevant prop shapes exercised by these tests
<PolicyAutomationsList
  storedPolicy={createMockPolicy({
    install_software: {
      name: "Zoom",
      display_name: "Zoom Workplace", // shown to users; raw name still passed to SoftwareIcon
      software_title_id: 42,
      icon_url: ENDPOINTS.SOFTWARE_ICON(42),
    },
    continuous_automations_enabled: true,
  })}
  currentAutomatedPolicies={[1]}
  otherAutomationType="webhook" // "webhook" | "ticket" | undefined
/>
```

## Notable Regression Test

`#47123` — Verifies that `SoftwareIcon` always receives the raw `install_software.name` (not `display_name`) so fallback icon matching against well-known software names remains functional even when a custom display name is set.
