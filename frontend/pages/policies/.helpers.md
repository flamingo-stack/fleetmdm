Provides utility functions for policy automation configuration and software option display in the Fleet MDM UI.

## Key Components

### `ITicketOrWebhookInfo`
Interface describing the current state of a policy's "other workflow" automation — either `"webhook"`, `"ticket"`, or `"disabled"` — along with the associated policy IDs.

### `getTicketOrWebhookInfo(automationsConfig)`
Inspects a `IConfig` or `ITeamConfig` object to determine whether a webhook or ticket integration (Jira/Zendesk) is active for failing-policy automations. Returns a normalized `ITicketOrWebhookInfo` object.

### `getTicketOrWebhookLabel(state)`
Maps a `TicketOrWebhookState` value to a human-readable UI label string.

### `generateSoftwareOptionHelpText(title)`
Builds a display string for a software title option (e.g. in a policy automation dropdown), handling VPP App Store apps and installable packages with platform and version details.

## Usage Example

```typescript
import {
  getTicketOrWebhookInfo,
  getTicketOrWebhookLabel,
  generateSoftwareOptionHelpText,
} from "./helpers";

// Resolve automation state from team or global config
const { state, policyIds } = getTicketOrWebhookInfo(teamConfig);
// e.g. { state: "ticket", policyIds: [1, 3, 7] }

// Get UI label for the resolved state
const label = getTicketOrWebhookLabel(state);
// e.g. "Create ticket"

// Build help text for a software title option
const helpText = generateSoftwareOptionHelpText(softwareTitle);
// e.g. "Windows (.exe) • 1.2.3"
// or   "macOS (App Store) • 14.0"
```

## Notes

- Both webhook and ticket integrations store their policy membership under `webhook_settings.failing_policies_webhook.policy_ids` on the backend.
- `generateSoftwareOptionHelpText` returns an empty string for titles with no resolvable platform or version.
