Manages the edit/view experience for a single Fleet policy, loading an existing policy by ID, wiring up the query editor, and rendering an optional osquery schema sidebar.

## Key Components

| Export / Symbol | Type | Description |
|---|---|---|
| `PolicyPage` | `React.FC` (default export) | Main page component that orchestrates policy loading, context sync, and layout |
| `IPolicyPageProps` | Interface | Props shape: `router`, `params`, `location` with `fleet_id` query param |
| `baseClass` | `string` | CSS namespace `"edit-policy-page"` |

## Key Behaviours

- **Policy loading** – fetches a stored policy via `policiesAPI.load(policyId)` using `react-query`; populates `PolicyContext` with all editable fields on success.
- **Team ID sync** – reconciles the URL `fleet_id` param (via `useTeamIdParam`) with `PolicyContext.policyTeamId`; redirects team-level users when the stored policy's `team_id` differs from the URL.
- **Policy creation** – exposes a `createPolicy` mutation that routes to either `teamPoliciesAPI.create` or `globalPoliciesAPI.create` depending on `team_id`.
- **Live query check** – calls `statusAPI.live_query()` on mount; disables the live-run flow if the endpoint is unavailable.
- **Sidebar** – shows the `QuerySidePanel` (osquery schema browser) only for admins and maintainers.
- **Document title** – updates the browser tab to `<policy name> | Policies | Fleet`.

## Usage Example

```typescript
// Rendered by the Fleet router — not instantiated manually.
// Route: /policies/:id?fleet_id=<teamId>

<PolicyPage
  router={router}
  params={{ id: "42" }}
  location={{
    pathname: "/policies/42",
    search: "?fleet_id=3",
    query: { fleet_id: "3" },
  }}
/>
```
