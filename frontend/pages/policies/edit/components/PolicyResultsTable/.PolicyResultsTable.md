Renders a table displaying policy execution results across hosts, showing which hosts passed or failed a given policy check.

## Key Components

### `PolicyResultsTable`
Main functional component that wraps `TableContainer` with policy-results-specific configuration.

**Props (`IPolicyResultsTableProps`):**

| Prop | Type | Description |
|---|---|---|
| `hostResponses` | `IPolicyHostResponse[]` | Array of host policy response data |
| `isLoading` | `boolean` | Controls loading state of the table |
| `resultsTitle` | `string` (optional) | Custom label for results count; defaults to `"policies"` |

### Supporting Utilities
- **`generateTableHeaders()`** — Builds column configuration from `PolicyResultsTableConfig`
- **`generateDataSet(hostResponses)`** — Transforms raw `IPolicyHostResponse[]` into table-ready rows

## Usage Example

```typescript
import PolicyResultsTable from "components/PolicyResultsTable";
import { IPolicyHostResponse } from "interfaces/host";

const hostResponses: IPolicyHostResponse[] = [
  { host_id: 1, host_name: "macbook-01", query_results: "pass" },
  { host_id: 2, host_name: "linux-02", query_results: "fail" },
];

<PolicyResultsTable
  hostResponses={hostResponses}
  isLoading={false}
  resultsTitle="results"
/>
```

## Notes

- Table sorts by `query_results` ascending by default
- Displays an `"No hosts are online"` empty state when there are no results
- Uses client-side pagination
- Result count display is disabled (`disableCount`)
- ⚠️ Styles overlap with `PolicyErrorsTable` — tracked for future refactoring to extract shared styles into a common base class
