Displays detailed information for a single Fleet policy, including its metadata, automations, platform targets, label filters, and author — with role-based controls for editing, running, and managing patch automations.

## Key Components

### `PolicyDetailsPage`
Main page component that:
- Loads a policy by ID from route params via `policiesAPI.load`
- Syncs policy state into `PolicyContext` on fetch success
- Derives team display name from `policy.team_id` (not the URL's `fleet_id`) to correctly handle inherited policies
- Computes edit/run permissions from user role flags (`isGlobalAdmin`, `isTeamMaintainerOrTeamAdmin`, etc.)
- Handles patch automation via `teamPoliciesAPI.update` with optimistic cache invalidation

### Helper: `getPolicyFleetName`
Resolves the human-readable fleet/team name from a policy and team API response, handling global-all-teams and no-team edge cases.

### Render Helpers
| Function | Purpose |
|---|---|
| `renderAuthor` | Avatar + name display (shows "You" for current user) |
| `renderPlatforms` | Platform icon list parsed from comma-separated `platform` field |
| `renderLabels` | Label-scoped targeting (`have any`, `have all`, `exclude any`) with clickable pill buttons |
| `renderHeader` | Back button + policy name with optional critical badge |

## Usage Example

```typescript
// Rendered by the router; receives props from React Router
<PolicyDetailsPage
  router={router}
  params={{ id: "42" }}
  location={{
    pathname: "/policies/42",
    search: "",
    query: { fleet_id: "5" },
  }}
/>
```

The component guards against invalid `policyId` by redirecting to `PATHS.MANAGE_POLICIES`. Team data is fetched only when `policy.team_id` is a valid non-null value, keeping queries minimal for global policies.
