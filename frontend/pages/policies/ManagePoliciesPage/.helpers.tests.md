Unit tests for the `helpers` module in the policy management feature, covering error message generation for install software/run script automations and the `getAutomationsForPolicy` utility.

## Key Components

### `getInstallSoftwareErrorMessage` Tests
Validates JSX error message construction when a software installation policy update fails, covering:
- Correct substitution of software name, ID, and team name from API error payloads
- Graceful fallback when the software title ID is unknown
- Graceful fallback when `currentTeamName` is omitted

### `getRunScriptErrorMessage` Tests
Mirrors the install software suite for script-based policy automations:
- Correct substitution of script name, ID, and team name
- Unknown script ID fallback
- Missing `currentTeamName` fallback

### `getAutomationsForPolicy` Tests
Exhaustive coverage of automation descriptor assembly:
- Empty result when no automations are configured
- Software automation: `display_name` preferred over `name`, `icon_url` passthrough, `iconName` preserved for fallback icon matching (regression #47123)
- Name normalization via `getDisplayedSoftwareName` (e.g., `Microsoft.CompanyPortal` → `Company Portal`)
- Script, calendar, conditional access, and webhook/ticket automation types
- Correct ordering when multiple automation types are present simultaneously

## Usage Example

```typescript
import {
  getAutomationsForPolicy,
  getInstallSoftwareErrorMessage,
} from "./helpers";

// Build an ordered list of active automations for a policy
const automations = getAutomationsForPolicy(
  {
    install_software: { name: "Zoom", software_title_id: 42 },
    calendar_events_enabled: true,
    conditional_access_enabled: false,
    webhook: "On",
  },
  "ticket"
);
// => [{ type: "software", name: "Zoom", ... }, { type: "calendar", ... }, { type: "other", name: "Ticket" }]
```
