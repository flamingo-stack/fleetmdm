Utility module for policy automation display logic, providing helpers to resolve configured automations for a policy and format user-facing error messages for automation update failures.

## Key Components

### Types

- **`AutomationDisplayType`** — Union type of possible automation categories: `"software"`, `"script"`, `"calendar"`, `"conditional_access"`, `"other"`
- **`IAutomationData`** — Discriminated union describing either a software automation (with icon/title metadata) or a non-software automation (name only)

### Functions

- **`getAutomationsForPolicy`** — Derives an ordered `IAutomationData[]` list from a policy's configured automations (`install_software`, `run_script`, `calendar_events_enabled`, `conditional_access_enabled`, `webhook`)
- **`getInstallSoftwareErrorMessage`** — Parses a rejected API result for install-software failures and returns a JSX element with bolded software names and team names substituted inline
- **`getRunScriptErrorMessage`** — Same pattern as above, but for run-script automation failures, substituting script names and team names into the error message

## Usage Example

```typescript
import {
  getAutomationsForPolicy,
  getInstallSoftwareErrorMessage,
} from "./helpers";

// Resolve automations for a policy
const automations = getAutomationsForPolicy(policy, "ticket");
// [{ type: "software", name: "Acme App", iconName: "acme", ... }, ...]

// Format a rejected install-software API error for display
const errorElement = getInstallSoftwareErrorMessage(
  rejectedResult,
  installFormData,
  "Engineering"
);
// Renders: "Could not update policy. <b>Acme App</b> (ID: 42) ... <b>Engineering</b>"
```

> **Note:** `iconName` on software automations preserves the raw software name for `SoftwareIcon` fallback matching, distinct from the display-formatted `name` field.
