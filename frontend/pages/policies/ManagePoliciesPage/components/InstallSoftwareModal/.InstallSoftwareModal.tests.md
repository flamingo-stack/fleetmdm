Unit test file for three pure utility functions exported from `InstallSoftwareModal`: `getOriginalSoftwareState`, `getCurrentSoftwareState`, and `getTrulyDirtyInstallSoftwareItems`.

## Key Components

- **`getOriginalSoftwareState`** — Extracts the originally-saved software enablement state and software title ID from a policy's `install_software` field
- **`getCurrentSoftwareState`** — Normalizes the current form state (`installSoftwareEnabled`, `swIdToInstall`) into a consistent shape, coercing absent IDs to `null`
- **`getTrulyDirtyInstallSoftwareItems`** — Filters a list of "dirty" policies down to only those where enablement or software selection actually changed relative to the saved state

## Usage Example

```typescript
import {
  getOriginalSoftwareState,
  getCurrentSoftwareState,
  getTrulyDirtyInstallSoftwareItems,
} from "./InstallSoftwareModal";

const policy = {
  id: 1,
  install_software: { software_title_id: 20, name: "1Password", display_name: "" },
  installSoftwareEnabled: true,
  swIdToInstall: 30, // changed from 20 to 30
};

const { originallyEnabled, originalSwId } = getOriginalSoftwareState(policy);
// originallyEnabled: true, originalSwId: 20

const { nowEnabled, nowSwId } = getCurrentSoftwareState(policy);
// nowEnabled: true, nowSwId: 30

const changed = getTrulyDirtyInstallSoftwareItems([policy]);
// [policy] — software ID changed, so it is included
```

## Test Coverage

| Test | Scenario |
|---|---|
| `getOriginalSoftwareState` | Reads `software_title_id` when `install_software` is set |
| `getCurrentSoftwareState` | Coerces `undefined` swId to `null`; passes through enabled + ID |
| `getTrulyDirtyInstallSoftwareItems` | Excludes unchanged; includes turned-on, turned-off, software-swapped policies |

> **Design note:** Full integration tests for `onSubmit` are intentionally omitted. Standing up `PoliciesPaginatedList` with pagination and react-query would add brittle setup for marginal confidence gain over these focused unit tests.
