Modal component for configuring policy automation workflows, allowing users to set up either webhook or ticket-based integrations (Jira/Zendesk) when hosts fail policies.

## Key Components

### Exports
- **`OtherWorkflowsModal`** — `forwardRef` component exposing an `IAutomationFormHandle` with `getFormData()`, `validate()`, and `isDirty()` methods via `useImperativeHandle`
- **`IOtherWorkflowsModalSubmit`** — Interface defining the submit payload shape containing `webhook_settings` and `integrations`

### Internal Helpers
- **`findEnabledIntegration`** — Finds the currently enabled Jira or Zendesk integration from the automation config
- **`getIntegrationType`** — Determines whether a given integration is `"jira"` or `"zendesk"` based on its identifier fields

### State
| State | Purpose |
|---|---|
| `isPolicyAutomationsEnabled` | Master toggle for policy automations |
| `isWebhookEnabled` | Selects webhook vs. ticket workflow |
| `destinationUrl` | Webhook destination URL input |
| `selectedIntegration` | Currently selected Jira/Zendesk integration |
| `errors` | Validation error messages keyed by field |

## Usage Example

```typescript
const modalRef = useRef<IAutomationFormHandle<IOtherWorkflowsModalSubmit>>(null);

// Validate and retrieve form data
const handleSave = () => {
  if (modalRef.current?.validate()) {
    const data = modalRef.current.getFormData();
    // data.webhook_settings or data.integrations
    submitAutomations(data);
  }
};

<OtherWorkflowsModal
  ref={modalRef}
  router={router}
  automationsConfig={automationsConfig}
  availableIntegrations={integrations}
  gitOpsModeEnabled={false}
/>
```

## Notes

- When `gitOpsModeEnabled` is `true`, all form controls are disabled
- Workflow type (ticket/webhook) is selected via radio buttons; only one can be active at a time
- Jira/Zendesk integrations are discovered from `availableIntegrations` and flattened into a single dropdown
- Source: [`flamingo-stack/fleetmdm`](https://github.com/flamingo-stack/fleetmdm)
