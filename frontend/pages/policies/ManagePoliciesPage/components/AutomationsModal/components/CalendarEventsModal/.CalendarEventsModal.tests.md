Test suite for the `CalendarEventsModal` component, verifying rendering behavior across three configuration and role-based scenarios.

## Key Components

- **`createCustomRenderer`** — Custom test utility that injects app-level context (admin roles) into the render tree
- **`CalendarEventsModal`** — The component under test, accepting `configured`, `enabled`, and `url` props

## Test Cases

| Scenario | Role | `configured` | Expected Behavior |
|---|---|---|---|
| Configured & enabled | Global Admin | `true` | Renders "Resolution webhook URL" field |
| Not configured | Global Admin | `false` | Renders link to Settings → Integrations → Calendars |
| Not configured | Team Admin | `false` | Renders "Settings" text but **no** navigation link |

## Usage Example

```typescript
// Run the test suite
// From the repository root:
// npx jest CalendarEventsModal.tests.tsx

// Example: rendering the modal in a test
const render = createCustomRenderer({
  context: {
    app: {
      isGlobalAdmin: true,
      isTeamAdmin: false,
    },
  },
});

render(
  <CalendarEventsModal
    configured
    enabled
    url="https://server.com/example"
  />
);

expect(
  screen.queryByText(/Resolution webhook URL/i)
).toBeInTheDocument();
```

## Notes

- Global admins see a direct link to **Settings → Integrations → Calendars** when the calendar integration is not yet configured, enabling self-service setup.
- Team admins see a plain text reference to Settings without a navigable link, reflecting their reduced permissions scope.
