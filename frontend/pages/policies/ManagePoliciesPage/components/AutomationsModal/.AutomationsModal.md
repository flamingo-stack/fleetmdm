Modal component for managing Fleet MDM policy automations, supporting webhook/ticket workflows, calendar events, and conditional access configuration across global, team, and "No team" scopes.

## Key Components

- **`AutomationsModal`** — Default export. Renders a multi-section form modal that orchestrates three sub-forms via imperative refs, validates them collectively, and persists changes to the appropriate API endpoint based on the current team scope.
- **`IAutomationsModalProps`** — Props interface defining team context (`isAllTeamsSelected`, `teamIdForApi`), config sources (`globalConfig`, `teamConfig`), and callbacks (`refetchPolicies`, `onExit`).
- **Sub-form refs** — `otherFormRef`, `calendarFormRef`, `conditionalAccessFormRef` each implement `IAutomationFormHandle<T>`, exposing `validate()` and `getFormData()` methods for coordinated submission.
- **Scope-aware save logic** (`handleSubmit`) — Routes API calls differently for three scopes:
  - **All teams**: updates global config only (Other Workflows)
  - **No team**: splits writes between `teamsAPI` (webhooks/integrations) and `configAPI` (conditional access)
  - **Specific team**: merges all data into a single `teamsAPI.update` call

## Usage Example

```typescript
<AutomationsModal
  router={router}
  isAllTeamsSelected={false}
  teamIdForApi={42}
  globalConfig={globalConfig}
  teamConfig={teamConfig}
  gitOpsModeEnabled={false}
  refetchPolicies={() => queryClient.invalidateQueries("policies")}
  onExit={() => setShowModal(false)}
/>
```

## Notes

- Calendar events section is hidden for the "All teams" view and the `API_NO_TEAM_ID` (unassigned) scope — it is a team-only feature.
- Conditional access section is hidden in the "All teams" view; for "No team", the enabled flag is written to global config rather than the team record.
- React Query cache (`queryClient.setQueryData`) is updated optimistically on success to avoid a full refetch of config/team data.
