Defines the `IAutomationFormHandle` interface — a standardized imperative handle contract for automation sub-form modals, enabling a parent `AutomationsModal` to validate and collect form data via a React `ref`.

## Key Components

### `IAutomationFormHandle<TData>`
A generic interface exposing three imperative methods that each automation sub-form modal must implement:

| Method | Returns | Description |
|--------|---------|-------------|
| `getFormData` | `TData \| null` | Returns the section's submit data, or `null` if unconfigured |
| `validate` | `boolean` | Validates the form, surfaces field errors, returns `false` if invalid |
| `isDirty` | `boolean` | Indicates whether form values differ from their initially loaded state |

## Usage Example

```typescript
import { useImperativeHandle, forwardRef } from "react";
import { IAutomationFormHandle } from "./types";

interface MyFormData {
  name: string;
  enabled: boolean;
}

const MyAutomationForm = forwardRef<IAutomationFormHandle<MyFormData>>(
  (props, ref) => {
    useImperativeHandle(ref, () => ({
      getFormData: () => ({ name: "My Automation", enabled: true }),
      validate: () => {
        // run validation, surface errors
        return true;
      },
      isDirty: () => false,
    }));

    return <form>{/* fields */}</form>;
  }
);

// Parent modal usage
const formRef = useRef<IAutomationFormHandle<MyFormData>>(null);
if (formRef.current?.validate()) {
  const data = formRef.current.getFormData();
}
```

## Notes

- `TData` is generic — each sub-form defines its own data shape.
- `getFormData` returning `null` signals the section is unconfigured or has nothing to submit, allowing the parent to skip it gracefully.
