Test suite for the `PoliciesTable` React component, verifying rendering behavior across various states including empty states, policy badges, inherited policies, checkboxes, and automations.

## Key Components

| Test Case | Description |
|---|---|
| Empty state (free tier) | Verifies "No policies yet" message and disabled search when no policies exist |
| Empty state (all teams) | Verifies "No policies apply to all fleets" message on premium tier |
| Empty state (specific team) | Verifies "No policies for this fleet" message for a named team |
| Primo mode empty states | Verifies generic "No policies yet" header overrides team-specific messages |
| Empty search state | Verifies "No matching policies" when a search query returns no results |
| Critical badge | Verifies critical policy badge and tooltip render on hover |
| Inherited badge | Verifies inherited badge appears for global policies on team pages |
| Checkbox count | Verifies only team policies (not inherited) have selectable checkboxes |
| Patch badge | Verifies "Patch" badge renders for `type: "patch"` policies only |
| Automations column | Verifies automations column renders with correct values |

## Usage Example

```typescript
// Run the full test suite
npx jest PoliciesTable.tests.tsx

// Run a specific test by name
npx jest PoliciesTable.tests.tsx -t "Renders a critical badge"
```

## Notes

- Uses `createCustomRenderer` from `test/test-utils` to inject app context (user, tier, config)
- Uses `createMockUser` and `createMockPolicy` for controlled test fixtures
- Primo mode (`enable_primo: true`) suppresses team-specific empty state labels in favor of a generic fallback
- Inherited policies (those with `team_id: null`) are excluded from checkbox selection on team pages; only team-owned policies are deletable
