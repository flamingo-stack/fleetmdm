Unit tests for the `helpers` module, verifying three utility functions: `getSelfServiceTooltip`, `getAutomaticInstallPoliciesCount`, and `getDisplayedSoftwareName`.

## Key Components

### `getSelfServiceTooltip` Tests
Validates tooltip content rendering across three platform scenarios:
- **Android Play Store** (`isAndroidPlayStoreApp: true`) — expects Play Store messaging
- **iOS/iPadOS** (`isIosOrIpadosApp: true`) — expects self-service link pointing to `/deploy-self-service-to-ios`
- **Fleet Desktop** (both flags `false`) — expects Fleet Desktop messaging with a `/self-service-software` link

### `getAutomaticInstallPoliciesCount` Tests
Parameterized over `[0, 1, 3]` policy counts, covering all four combinations of software type × host type:
- `ISoftwareTitle` with `software_package` or `app_store_app`
- `IHostSoftware` with `software_package` or `app_store_app`
- Falls back to `0` when both fields are `null`

### `getDisplayedSoftwareName` Tests
Covers the display name resolution priority chain:
- Explicit `display_name` wins over raw name
- Known raw names (e.g. `"Microsoft.CompanyPortal"`) are normalized case-insensitively via `WELL_KNOWN_SOFTWARE_TITLES`
- Unknown raw names are returned as-is
- Whitespace-only or empty `display_name` is treated as absent
- Returns `"Software"` as the final fallback when both inputs are absent or whitespace

## Usage Example
