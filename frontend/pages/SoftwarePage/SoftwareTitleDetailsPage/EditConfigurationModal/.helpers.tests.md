Test suite for the `helpers` utility module, validating error handling, JSON/XML validation, and platform label formatting functions used in MDM configuration workflows.

## Key Components

| Function Under Test | Description |
|---|---|
| `isErrorWithMessage` | Type guard that checks if an unknown value has a `message` property |
| `getErrorMessage` | Extracts human-readable error messages from API error responses, with Android-specific handling and `$FLEET_VAR_`/`$FLEET_SECRET_` variable error formatting |
| `validateJson` | Returns `null` for valid JSON or an error string for malformed input |
| `validateXml` | Returns `null` for valid XML plist structures or a descriptive error string; enforces `<dict>` as root element |
| `getPlatformLabel` | Maps platform identifiers (`ios`, `ipados`, `android`) to display labels |

## Usage Example

```typescript
import {
  getErrorMessage,
  isErrorWithMessage,
  validateJson,
  validateXml,
  getPlatformLabel,
} from "./helpers";

// Type guard usage
if (isErrorWithMessage(caughtError)) {
  console.log(caughtError.message);
}

// API error extraction (isAndroid = false for Android platform)
const msg = getErrorMessage(apiError, false);

// Validate user-supplied config before submission
const jsonErr = validateJson('{"key": "value"}'); // null = valid
const xmlErr = validateXml("<dict><key>k</key><string>v</string></dict>"); // null = valid

// Display-friendly platform name
getPlatformLabel("ipados"); // → "iPadOS"
```

## Key Test Scenarios

- **`getErrorMessage`** covers Android-specific JSX responses for `managedConfiguration` and `workProfileWidgets` errors, raw reason passthrough for iOS/iPadOS, `$FLEET_VAR_` unknown variable messages, known profile-only variables (e.g. `NDES_SCEP_CHALLENGE`, `DIGICERT_DATA_*`), and single/multiple missing `$FLEET_SECRET_` variables.
- **`validateXml`** covers bare `<dict>`, plist-wrapped dicts, full XML declarations with DOCTYPE, self-closing tags, nested dicts, mismatched tags, and non-`<dict>` root rejections.
