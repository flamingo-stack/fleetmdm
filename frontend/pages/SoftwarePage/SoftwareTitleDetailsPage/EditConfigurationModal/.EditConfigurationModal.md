Modal component for editing software configuration (XML for iOS/iPadOS apps, JSON for Android apps). Handles validation, submission, and cursor placement for both Apple and Android managed app configurations.

## Key Components

### `EditConfigurationModal`
The default export. A modal form component that renders an Ace-powered editor pre-populated with the current configuration, validates input on change, and submits via the appropriate API method based on installer type.

**Props (`IEditConfigurationModalProps`):**
| Prop | Type | Description |
|------|------|-------------|
| `softwareId` | `number` | ID of the software title |
| `teamId` | `number` | ID of the owning team |
| `softwareInstaller` | `IAppStoreApp \| ISoftwarePackage` | Installer metadata |
| `isApplePlatform` | `boolean` | Switches between XML (Apple) and JSON (Android) modes |
| `refetchSoftwareTitle` | `() => void` | Callback to refresh parent data after save |
| `onExit` | `() => void` | Callback to close the modal |

### `ISoftwareConfigurationFormData`
Exported interface describing the form payload shape — a single `configuration` string field.

## Key Behaviors

- **Apple (iOS/iPadOS):** Editor uses XML mode with an `<dict>` scaffold as default empty state; cursor is auto-positioned inside the empty `<dict>` block on load
- **In-house `.ipa`:** Submits via `softwareAPI.editSoftwarePackage` (multipart PATCH)
- **VPP / Android:** Submits via `softwareAPI.editAppStoreApp` (JSON PATCH)
- **Validation** runs on every keystroke; the Save button is disabled until valid

## Usage Example

```typescript
<EditConfigurationModal
  softwareId={42}
  teamId={1}
  softwareInstaller={myAppStoreApp}
  isApplePlatform={true}
  refetchSoftwareTitle={() => refetch()}
  onExit={() => setModalVisible(false)}
/>
```
