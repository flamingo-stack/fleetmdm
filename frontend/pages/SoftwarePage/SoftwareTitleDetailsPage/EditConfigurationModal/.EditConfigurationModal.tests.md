Test suite for the `EditConfigurationModal` component, verifying rendering behavior and form validation across Android (JSON) and iOS/iPadOS (XML) software installer configurations.

## Key Components

- **Test fixtures** — `ANDROID_PROPS`, `IOS_VPP_PROPS`, `IOS_IN_HOUSE_PROPS`: Pre-configured prop sets for each platform/installer type using mock factory functions
- **Three describe blocks** — Organized by platform: Android JSON, iOS VPP (App Store), and iOS in-house `.ipa`
- **`createCustomRenderer`** — Custom test renderer with backend mock support used consistently across all test cases

## Test Coverage

| Scenario | Assertions |
|---|---|
| Android (JSON) | Modal title, config editor, help text, Save button, Android label, JSON validation, disabled state on invalid input, learn more URL |
| iOS VPP (XML) | Modal title, XML help text, App Store (VPP) label, Cancel + Save buttons, XML validation, learn more URL |
| iOS in-house `.ipa` (XML) | Modal title, XML help text, package details, Cancel + Save buttons, empty config handling, `onExit` callback on Cancel |

## Usage Example

```typescript
// Running a specific test suite
// From the repo root:
// npx jest EditConfigurationModal.tests.tsx

// Example: testing invalid JSON disables Save
it("disables Save when JSON is invalid", async () => {
  const render = createCustomRenderer({ withBackendMock: true });
  const { user } = render(<EditConfigurationModal {...ANDROID_PROPS} />);

  const configInput = screen.getByRole("textbox", { name: /Cursor at row/ });
  await user.clear(configInput);
  await user.type(configInput, "{{ invalid json");

  await waitFor(() => {
    expect(screen.getByRole("button", { name: "Save" })).toBeDisabled();
  });
});
```
