Modal component for confirming and executing software deletion in Fleet MDM, with platform-specific messaging and error handling for policy/setup experience conflicts.

## Key Components

### `DeleteSoftwareModal`
Default export. A confirmation modal that calls `softwareAPI.deleteSoftwareInstaller` and surfaces contextual error messages based on the failure reason.

**Props (`IDeleteSoftwareModalProps`):**

| Prop | Type | Description |
|------|------|-------------|
| `softwareId` | `number` | ID of the software to delete |
| `teamId` | `number` | Team scope for the deletion |
| `onExit` | `() => void` | Callback to close the modal |
| `onSuccess` | `() => void` | Callback fired on successful deletion |
| `gitOpsModeEnabled` | `boolean?` | Shows GitOps re-appearance warning |
| `isAppStoreApp` | `boolean?` | VPP/App Store app — pending commands won't be cancelled |
| `isAndroidApp` | `boolean?` | Android app — software will be actively uninstalled |

### `getPlatformMessage`
Internal helper returning platform-specific JSX describing uninstall behavior for Android, App Store, or standard installers.

### Error Constants
Three specific error messages mapped from API error reasons:
- `DELETE_SW_USED_BY_PATCH_POLICY_ERROR_MSG` — patch policy conflict
- `DELETE_SW_USED_BY_POLICY_ERROR_MSG` — policy automation conflict
- `DELETE_SW_INSTALLED_DURING_SETUP_ERROR_MSG` — setup experience conflict

## Usage Example

```typescript
<DeleteSoftwareModal
  softwareId={42}
  teamId={1}
  onExit={() => setShowModal(false)}
  onSuccess={() => refetchSoftwareList()}
  gitOpsModeEnabled={false}
  isAppStoreApp={false}
  isAndroidApp={false}
/>
```
