Test suite for the `DeleteSoftwareModal` component, validating conditional rendering based on software type and GitOps mode state.

## Key Components

- **`renderModal`** – Helper that renders `DeleteSoftwareModal` with sensible defaults (`softwareId: 1`, `teamId: 1`, no-op callbacks), accepting partial prop overrides.
- **`DeleteSoftwareModal` test suite** – Four focused test cases covering the modal's content variations.

## Test Cases

| Test | Prop | Expected Behavior |
|------|------|-------------------|
| GitOps banner | `gitOpsModeEnabled: true` | Displays GitOps reappearance warning |
| Default platform | _(none)_ | Shows "won't be uninstalled" + pending cancellation message |
| App Store app | `isAppStoreApp: true` | Shows "won't be uninstalled" + pending installs won't be canceled |
| Android app | `isAndroidApp: true` | Shows "will be uninstalled" message |

## Usage Example

```typescript
// Run the full suite
// jest DeleteSoftwareModal.tests.tsx

// Or render a specific variant in isolation
renderModal({ isAndroidApp: true });
renderModal({ gitOpsModeEnabled: true });
```

## Notes

- Uses `jest.resetAllMocks()` in `beforeEach` to prevent cross-test pollution.
- Assertions rely on `toBeVisible()` (requires `@testing-library/jest-dom`) rather than just presence checks, ensuring the content is actually rendered in the viewport.
- Source component: [`DeleteSoftwareModal.tsx`](https://github.com/flamingo-stack/fleetmdm/blob/main/frontend/components/DeleteSoftwareModal/DeleteSoftwareModal.tsx)
