Modal component for configuring automatic software update settings, including enable/disable toggle, update time window inputs, and deployment target label selection for App Store apps.

## Key Components

- **`ISoftwareAutoUpdateConfigFormData`** — Exported interface defining the form schema: `autoUpdateEnabled`, `autoUpdateStartTime`, `autoUpdateEndTime`, `targetType`, `customTarget`, and `labelTargets`
- **`EditAutoUpdateConfigModal`** — Default export; a controlled modal form component that reads existing config from `softwareTitle` and submits changes via `softwareAPI.editAppStoreApp`
- **Form validation** — Uses `validateFormData` from local `./helpers`; errors surface inline on blur; window-length cross-field errors are distributed across both time inputs
- **GitOps mode guard** — Wraps the Save button in `GitOpsModeTooltipWrapper`; disables the form visually when GitOps mode is active

## Props

| Prop | Type | Description |
|------|------|-------------|
| `teamId` | `number` | Team context for label and API calls |
| `softwareTitle` | `ISoftwareTitleDetails` | Source of existing config values |
| `refetchSoftwareTitle` | `() => void` | Called after successful save |
| `onExit` | `() => void` | Closes the modal |

## Usage Example

```typescript
import EditAutoUpdateConfigModal from "./EditAutoUpdateConfigModal";

<EditAutoUpdateConfigModal
  teamId={currentTeam.id}
  softwareTitle={selectedTitle}
  refetchSoftwareTitle={() => refetch()}
  onExit={() => setShowModal(false)}
/>
```

## Notes

- Time inputs enforce `HH:MM` 24-hour format (max 5 chars, non-numeric characters stripped)
- Validation errors are suppressed while typing; they appear only on field blur or form submit
- Target label changes also affect self-service deployments (surfaced in the UI subtitle)
- Currently hardcoded to `editAppStoreApp`; a future refactor may branch by software title type
