Test suite for the `EditAutoUpdateConfigModal` component, validating UI behavior and form validation logic for configuring auto-update settings and maintenance windows on software titles.

## Key Components

- **`labelSummariesHandler`** — MSW request handler mocking the `/api/latest/fleet/labels/summary` endpoint with sample label data
- **`mockLabels`** — Sample `ILabelSummary` fixtures used for label dropdown population
- **`render`** — Custom renderer with backend mock, premium tier, and global admin context
- **Test suites:**
  - `Auto updates options` — Visibility toggling of maintenance window fields based on checkbox state
  - `Maintenance window validation` — Form validation rules for time field formats and required fields

## Usage Example

```typescript
// Renders the modal with auto updates pre-configured
render(
  <EditAutoUpdateConfigModal
    softwareTitle={createMockSoftwareTitleDetails({
      auto_update_enabled: true,
      auto_update_window_start: "02:00",
      auto_update_window_end: "04:00",
    })}
    teamId={1}
    refetchSoftwareTitle={jest.fn()}
    onExit={jest.fn()}
  />
);

// Asserts maintenance window fields are visible and pre-populated
expect(screen.getByLabelText("Earliest start time")).toHaveValue("02:00");
expect(screen.getByLabelText("Latest start time")).toHaveValue("04:00");
```

## Test Coverage Summary

| Scenario | Assertion |
|---|---|
| Auto updates disabled (default) | Maintenance window fields hidden |
| Auto updates pre-enabled | Fields shown with pre-filled times |
| Checkbox toggled on | Empty time fields appear |
| Checkbox toggled off | Time fields removed from DOM |
| Invalid time format (`19:99`) | Error label + Save button disabled |
| Only one time field filled | Required error on missing field |
| Both fields empty on save | Both required errors shown |
