Brief test suite for the `AddPatchPolicyModal` component, verifying UI behavior based on GitOps mode configuration.

## Key Components

- **`renderModal`** — Helper factory that wraps `createCustomRenderer` with a configurable app context, injecting `gitops_mode_enabled` and default props (`softwareId`, `teamId`, `onExit`, `onSuccess`) into the modal.
- **`AddPatchPolicyModal`** — The component under test, imported from the sibling module.

## Tests

| Test | Assertion |
|---|---|
| GitOps mode enabled | "Add" button is disabled and hoverable |

## Usage Example

```typescript
// Run this test file directly
// jest AddPatchPolicyModal.tests.tsx

// To extend with additional cases:
it("renders add button as enabled when gitOpsModeEnabled is false", () => {
  renderModal({ gitOpsModeEnabled: false });
  const addButton = screen.getByRole("button", { name: "Add" });
  expect(addButton).not.toBeDisabled();
});
```

## Notes

- Uses `createCustomRenderer` from `test/test-utils` to inject a mock app context — required for components that read `config.gitops.gitops_mode_enabled`.
- `jest.resetAllMocks()` in `beforeEach` ensures test isolation.
- `noop` from lodash is used as a no-op stub for the `onExit` and `onSuccess` callbacks.
