Test suite for the `EditIconModal` component, validating rendering, user interactions, display name logic, and API integration for editing software appearance in Fleet MDM.

## Key Components

- **`MOCK_PROPS`** — Shared fixture providing `softwareId`, `teamIdForApi`, `previewInfo`, and mock callbacks used across all test cases
- **`createCustomRenderer`** — Custom render utility with backend mock support
- **`createMockSoftwareTitle` / `createMockSoftwarePackage`** — Factory helpers that generate realistic software fixture data

## Test Coverage

| Describe Block | Tests |
|---|---|
| Root `EditIconModal` | Modal title, UI elements, software preview info, Escape key exit |
| `Display name tests` | Default blank value, pre-fill on modified name, save with trimmed whitespace, clearing custom name, API error handling |

## Usage Example

```typescript
// Running specific test cases
// All tests use createCustomRenderer with withBackendMock: true

// Spy pattern used for API assertions
const editSoftwarePackageSpy = jest
  .spyOn(softwareAPI, "editSoftwarePackage")
  .mockResolvedValue({});

// After save action, verify API called with trimmed display name
expect(editSoftwarePackageSpy).toHaveBeenCalledWith({
  data: { displayName: "New Name" },
  softwareId: 123,
  teamId: 456,
});

// Verify icon APIs were NOT called when only name changed
expect(deleteSoftwareIconSpy).not.toHaveBeenCalled();
expect(editSoftwareIconSpy).not.toHaveBeenCalled();
```

> **Note:** E2E coverage for file upload, preview rendering, save, and icon removal is delegated to QA Wolf per inline test comment.
