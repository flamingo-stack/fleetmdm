Detail page component for displaying OS version information at the `software/os/:id` route, showing host counts, vulnerabilities, and kernel details with team-scoped filtering.

## Key Components

- **`SoftwareOSDetailsPage`** — Main page component; fetches OS version data via `osVersionsAPI.getOSVersion`, manages team context, and conditionally renders vulnerability or kernel tables based on platform type (Linux vs. non-Linux)
- **`SummaryCard`** — Displays OS name, host count, and last-updated timestamp using `SoftwareDetailsSummary`
- **`VulnerabilitiesCard`** — Renders `SoftwareVulnerabilitiesTable` for supported platforms or a `VulnsNotSupported` fallback for unsupported ones
- **`KernelsCard`** — Renders `OSKernelsTable` for Linux-like platforms, where vulnerabilities are kernel-scoped rather than OS-scoped

## Usage Example

```typescript
// Rendered by the router at software/os/:id
<SoftwareOSDetailsPage
  routeParams={{ id: "42" }}
  router={router}
  location={location}
/>

// Exported sub-cards can be used independently
<SummaryCard
  osVersion={osVersion}
  countsUpdatedAt="2024-01-15T10:00:00Z"
  teamIdForApi={1}
/>

<VulnerabilitiesCard
  osVersion={osVersion}
  isLoading={false}
  router={router}
  teamIdForApi={1}
/>

<KernelsCard
  osVersion={osVersion}
  isLoading={false}
  router={router}
  teamIdForApi={1}
/>
```

## Notes

- Linux platforms (`isLinuxLike`) show the **KernelsCard** instead of **VulnerabilitiesCard**, since vulnerabilities are tied to specific kernel versions
- `maxVulnerabilities` starts at `0` and is set to `undefined` after the first successful fetch if vulnerabilities exist, triggering a full vulnerability load
- 403/404 errors are silently ignored; all other errors are forwarded to the error boundary
- Team header is hidden for Primo partnership configurations (`config?.partnerships?.enable_primo`)
