Renders the software inventory view for Fleet MDM, managing data fetching for both software titles (`/software/inventory`) and versions (`/software/versions`) views with conditional empty-state logic.

## Key Components

### `SoftwareInventory` (default export)
Main component that orchestrates three `react-query` queries:

| Query | Scope | Enabled When |
|-------|-------|--------------|
| `titlesData` | `software-titles` | Path is `SOFTWARE_INVENTORY` |
| `versionsData` | `software-versions` | Path is `SOFTWARE_VERSIONS` |
| `titlesAvailableForInstallResponse` | `software-titles` (AFI) | Versions loaded and count is `0` |

The third query ("available for install") determines which empty-state message to display in the versions view — it only fires after the versions query confirms an empty result set, avoiding unnecessary API calls during navigation.

### `ISoftwareInventoryProps`

| Prop | Type | Description |
|------|------|-------------|
| `router` | `InjectedRouter` | For navigation |
| `isSoftwareEnabled` | `boolean` | Feature flag |
| `query` | `string` | Search filter |
| `perPage` | `number` | Pagination size |
| `orderDirection` | `"asc" \| "desc"` | Sort direction |
| `orderKey` | `string` | Sort column |
| `vulnFilters` | `ISoftwareVulnFilters` | Vulnerability filters |
| `currentPage` | `number` | Current page index |
| `teamId` | `number?` | Optional team scope |
| `onAddFiltersClick` | `() => void` | Filter panel handler |

## Usage Example

```typescript
<SoftwareInventory
  router={router}
  isSoftwareEnabled={true}
  query=""
  perPage={20}
  orderDirection="asc"
  orderKey="name"
  vulnFilters={{ exploit: false }}
  currentPage={0}
  teamId={1}
  onAddFiltersClick={() => setShowFilterPanel(true)}
/>
```

> Renders a `<Spinner />` while loading and `<TableDataError />` on fetch failure; otherwise delegates rendering to [`SoftwareInventoryTable`](https://github.com/flamingo-stack/fleetmdm/blob/main/frontend/pages/SoftwarePage/SoftwareInventory/SoftwareInventoryTable).
