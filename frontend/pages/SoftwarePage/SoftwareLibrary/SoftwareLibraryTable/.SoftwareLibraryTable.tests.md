Test suite for the `SoftwareLibraryTable` component, validating rendering behavior across disabled states, empty states, role-based UI differences, and navigation interactions.

## Key Components

### Test Cases

| Test | Description |
|------|-------------|
| `isSoftwareEnabled={false}` | Renders "Software inventory disabled" page-wide state |
| Empty library (admin) | Shows empty state with "Add software" CTA, disabled search, and self-service toggle |
| Self-service filter active | Renders filtered empty state with "No items match" message |
| Categories navigation | Verifies router push to `/software/library/categories?fleet_id=4` |
| Observer role | Empty state renders without "Add software" button |

### Dependencies

- `createCustomRenderer` / `createMockRouter` — test utilities for rendering with context and routing
- `createMockUser` — generates mock user objects with configurable roles
- `createMockSoftwareTitlesResponse` — generates mock API response for software titles

## Usage Example

```typescript
// Rendering with a specific user role and software state
const render = createCustomRenderer({
  context: {
    app: {
      isGlobalAdmin: true,
      currentUser: createMockUser(),
    },
  },
});

render(
  <SoftwareLibraryTable
    router={mockRouter}
    isSoftwareEnabled={false}
    data={createMockSoftwareTitlesResponse({ software_titles: [] })}
    query=""
    perPage={50}
    orderDirection="asc"
    orderKey="hosts_count"
    selfServiceOnly={false}
    currentPage={0}
    teamId={1}
    isLoading={false}
  />
);

expect(screen.getByText("Software inventory disabled")).toBeInTheDocument();
```
