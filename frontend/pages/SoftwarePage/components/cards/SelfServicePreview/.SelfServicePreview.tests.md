Unit tests for the `SelfServicePreview` component, validating rendering behavior across mobile (iOS/iPadOS) and desktop preview modes.

## Key Components

- **`SelfServicePreview` test suite** — Four test cases covering the component's core rendering scenarios

| Test Case | Description |
|-----------|-------------|
| Mobile preview render | Verifies icon, display name, and version label are visible |
| `displayName` fallback | Falls back to `name` when `displayName` is an empty string |
| Desktop with categories | Confirms `All` dropdown renders when `hasCategories` is `true` |
| Desktop without categories | Confirms `All` dropdown is absent when `hasCategories` is `false` |

## Usage Example

```typescript
// Run all tests
npx jest SelfServicePreview.tests.tsx

// Run a specific test by name
npx jest SelfServicePreview.tests.tsx -t "falls back to name"
```

```typescript
// Props exercised by these tests
<SelfServicePreview
  isIosOrIpadosApp={false}
  contactUrl="https://example.com/help"
  name="App name"
  displayName="Display name"
  versionLabel="1.2.3"
  hasCategories={true}
  renderIcon={() => <MyIcon />}
  renderTable={() => <MyTable />}
/>
```

## Notes

- Mobile path (`isIosOrIpadosApp={true}`) checks for the screenshot alt text `"Preview icon on Fleet Desktop > Self-service"` and renders an inline icon/name/version layout.
- Desktop path (`isIosOrIpadosApp={false}`) renders a search input (`"Search by name"`) and conditionally includes the `"All"` category dropdown based on `hasCategories`.
- Uses `renderIcon` and `renderTable` render-prop pattern to inject mock content without external dependencies.
