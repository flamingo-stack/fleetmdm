Tests for the `SoftwareOptionsSelector` component, verifying toggle behavior, self-service category rendering (dynamic API-fetched and static hardcoded), empty/error states, and conditional category list visibility.

## Key Components

### Test Helpers
- **`getSwitchByLabelText(text)`** — Locates a `<button role="switch">` within a Fleet slider wrapper by its label text, used to interact with toggle controls in tests.
- **`defaultProps`** — Baseline prop set with `selfService: false`, `automaticInstall: false`, and no-op jest mock callbacks.
- **`renderComponent(props?)`** — Factory using `createCustomRenderer` with a backend mock context, merging overrides onto `defaultProps`.

### Test Suites
- **Toggle behavior** — Verifies `onToggleSelfService` fires on click, and that iOS/iPadOS platforms keep the switch enabled while `disableOptions: true` disables it.
- **Dynamic categories (`teamId` provided)** — Uses `mockServer` MSW handlers to test API-fetched category checkboxes, `teamId: 0` (no-team) queries, empty state with `Add category` link (including correct `fleet_id` query param), loading suppression of empty state, API error display, checkbox toggle firing `onSelectCategory`, and pre-selected category checked state.
- **Category list visibility (`canSelectSoftwareCategories`)** — Confirms categories are hidden when self-service is off, or when not in edit mode.
- **Static categories (no `teamId`)** — Asserts the hardcoded fallback category list renders when no `teamId` is provided.

## Usage Example

```typescript
// Run all tests for SoftwareOptionsSelector
// From repo root:
// npx jest SoftwareOptionsSelector.tests.tsx

// Example: override a single prop and assert on a category checkbox
renderComponent({
  formData: { ...defaultProps.formData, selfService: true },
  isEditingSoftware: true,
  teamId: 1,
});
const checkbox = await screen.findByRole("checkbox", { name: "🌎 Browsers" });
expect(checkbox).toBeInTheDocument();
```
