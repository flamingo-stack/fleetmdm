Test suite for the `InstalledPathCell` component, verifying rendering behavior for null, empty, single, and multiple installed paths.

## Key Components

- **`renders empty cell when installedVersion is null`** — Asserts the default empty cell value is shown when `installedVersion` prop is `null`
- **`renders empty cell when no paths are present`** — Asserts empty state when `installed_paths` is an empty array
- **`renders single installed path`** — Asserts a single path string is displayed when only one path exists
- **`renders button for multiple unique paths and calls handler`** — Asserts a button labeled `"2 paths"` is rendered for deduplicated paths and that `onClickMultiplePaths` is invoked on click

## Usage Example

```typescript
// Run the test suite
npx jest InstalledPathCell.tests.tsx

// Component under test
<InstalledPathCell
  installedVersion={[
    {
      ...DEFAULT_INSTALLED_VERSION,
      installed_paths: ["/Applications/App1.app", "/Applications/App2.app"],
      signature_information: [
        {
          installed_path: "/Applications/mock.app",
          team_identifier: "12345TEAMIDENT",
          hash_sha256: null,
        },
      ],
    },
  ]}
  onClickMultiplePaths={() => console.log("multiple paths clicked")}
/>
```

## Notes

- Uses `DEFAULT_INSTALLED_VERSION` from `__mocks__/hostMock` as a base fixture for `installedVersion` entries
- Duplicate entries in `installed_paths` are deduplicated before rendering — only unique paths contribute to the path count label
- `DEFAULT_EMPTY_CELL_VALUE` from `utilities/constants` defines the expected fallback display string
