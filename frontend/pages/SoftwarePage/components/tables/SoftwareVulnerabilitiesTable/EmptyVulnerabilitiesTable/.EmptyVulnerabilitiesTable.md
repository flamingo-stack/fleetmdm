Renders the appropriate empty state UI for the vulnerabilities table based on contextual conditions such as software inventory status, search filters, CVE validity, and tier.

## Key Components

### `IEmptyVulnerabilitiesTableProps`
Props interface controlling empty state rendering:
- `isPremiumTier` — adjusts messaging for exploited filter behavior
- `teamId` — scopes "known-vuln" header to a specific fleet
- `exploitedFilter` — when active, prompts the user to remove the filter
- `isSoftwareDisabled` — short-circuits to a "software disabled" state
- `emptyStateReason` — drives selection from the `emptyStateDetails` map

### `emptyStateDetails`
A record mapping each `IVulnerabilitiesEmptyStateReason` to partial `IEmptyStateProps`:

| Reason | Header |
|---|---|
| `no-vulns-detected` | No vulnerabilities detected |
| `no-matching-items` | No items match the current search criteria |
| `invalid-cve` | That vulnerability (CVE) is not valid |
| `unknown-cve` | This is not a known CVE |
| `known-vuln` | Known CVE not detected on any hosts |

### `LearnMoreLink`
Internal helper component rendering a `CustomLink` to Fleet's vulnerability processing docs, used inline within `unknown-cve` and `known-vuln` states.

## Usage Example

```typescript
<EmptyVulnerabilitiesTable
  isPremiumTier={true}
  teamId={42}
  exploitedFilter={true}
  isSoftwareDisabled={false}
  emptyStateReason="no-matching-items"
/>
```

Priority resolution order:
1. `isSoftwareDisabled` → renders a static "Software inventory disabled" state
2. `emptyStateReason` → selects from `emptyStateDetails`, with overrides for `teamId` and `exploitedFilter`
3. Falls back to the default "No items match" state
