Test suite for the `HashCell` component, validating rendering behavior across null, empty, single-hash, and multiple-hash scenarios.

## Key Components

- **`renders empty cell when installedVersion is null`** — Verifies `DEFAULT_EMPTY_CELL_VALUE` is displayed when `installedVersion` is `null`.
- **`renders empty cell when no hashes are present`** — Verifies `DEFAULT_EMPTY_CELL_VALUE` is displayed when `signature_information` entries have `hash_sha256: null`.
- **`renders single hash`** — Confirms the component displays the first 7 characters of a SHA-256 hash with an ellipsis.
- **`renders button for multiple unique hashes`** — Confirms a button labeled `"3 hashes"` is rendered when multiple distinct `hash_sha256` values are present.

## Usage Example

```typescript
// Example props structure exercised by these tests
<HashCell
  installedVersion={[
    {
      ...DEFAULT_INSTALLED_VERSION,
      signature_information: [
        {
          installed_path: "/Applications/mock.app",
          team_identifier: "12345TEAMIDENT",
          hash_sha256: "abcdef1234567890",
        },
      ],
    },
  ]}
  onClickMultipleHashes={jest.fn()}
/>
```

## Notes

- Uses `DEFAULT_INSTALLED_VERSION` from `__mocks__/hostMock` as a base object spread for installed version fixtures.
- `onClickMultipleHashes` is passed as `jest.fn()` or `noop` depending on whether invocation tracking is needed.
- Single-hash rendering is verified with `{ exact: false }` to accommodate the truncated display format (`abcdef1` + ellipsis).
