Test suite for the `getErrorMessage` helper function, validating error message extraction and formatting from Axios HTTP error responses.

## Key Components

- **`getErrorMessage`** — The function under test, imported from `./helpers`
- **Axios mock** — Overrides `isAxiosError` to always return `true`, simulating Axios error conditions
- **Two test cases** covering distinct error response shapes from the Fleet API

## Test Coverage

| Scenario | Input `reason` | Expected Output |
|---|---|---|
| Pending install/uninstall | `"Couldn't install. Host already has a pending install/uninstall..."` | Prepends `"Couldn't add. "` |
| Script validation failure | `"Couldn't add. Script validation failed: ..."` | Returns reason as-is |

## Usage Example

```typescript
// Running the tests
jest --testPathPattern="helpers.tests.tsx"
```

```typescript
// What the tested function handles — a 400 response with Fleet error shape
const err = {
  response: {
    status: 400,
    data: {
      errors: [
        {
          name: "Error",
          reason: "Couldn't install. Host already has a pending install/uninstall for this installer.",
        },
      ],
    },
  },
};

getErrorMessage(err);
// → "Couldn't add. Couldn't install. Host already has a pending install/uninstall for this installer."
```

## Notes

- The mock ensures `isAxiosError` returns `true` for all test inputs, isolating the logic from real Axios internals
- The "pending install" case reveals that `getErrorMessage` prefixes `"Couldn't add. "` when the reason doesn't already include it
