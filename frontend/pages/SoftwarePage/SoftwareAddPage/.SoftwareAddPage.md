A layout and navigation container for the "Add Software" workflow, providing tabbed sub-navigation between Fleet-maintained apps, App Store, and Custom Package sections, with an optional osquery reference side panel.

## Key Components

### `SoftwareAddPage` (default export)
The main page wrapper component that handles:
- **Tab navigation** across three sub-routes: Fleet-maintained, App store, and Custom package
- **Side panel toggling** for the `QuerySidePanel` (osquery table reference)
- **Team ID (`fleet_id`) guard** — redirects to "No team" context if the query param is absent
- **Child prop injection** — passes `router`, `currentTeamId`, `isSidePanelOpen`, and `setSidePanelOpen` down to routed child pages via `React.cloneElement`

### `ISoftwareAddPageQueryParams`
Exported interface describing expected URL query parameters:

| Param | Type |
|---|---|
| `fleet_id` | `string` (required for function) |
| `query` | `string` |
| `page` | `string` |
| `order_key` | `string` |
| `order_direction` | `"asc" \| "desc"` |
| `platform` | `FmaPlatformValue` |
| `status` | `FmaStatusValue` |

### `getTabIndex(path)`
Utility that maps the current pathname to the correct tab index by prefix-matching against `addSoftwareSubNav`.

## Usage Example

```typescript
// Rendered by the router — children is the active sub-route component
<SoftwareAddPage
  router={router}
  location={location} // must include location.query.fleet_id
>
  <FleetMaintainedAppsPage />
</SoftwareAddPage>
```

> **Note:** `fleet_id` must be present in the URL query string. If missing, the page immediately redirects to the same path with `fleet_id` set to `APP_CONTEXT_NO_TEAM_ID`.
