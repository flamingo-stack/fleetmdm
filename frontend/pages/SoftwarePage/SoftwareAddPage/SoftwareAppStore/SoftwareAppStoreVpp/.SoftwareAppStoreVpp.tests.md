Integration test suite for the `SoftwareAppStoreVpp` component, verifying VPP (Volume Purchasing Program) UI states based on token availability and user role (admin vs. non-admin).

## Key Components

| Element | Description |
|---|---|
| `emptyVppHandler` | MSW handler returning an empty VPP tokens list |
| `teamMismatchVppHandler` | MSW handler returning a VPP token assigned to a different team |
| `labelsHandler` | MSW handler returning an empty labels summary |
| `createCustomRenderer` | Test utility for rendering with app context (tier, admin role) |
| `createMockRouter` | Test utility providing a mock router instance |

## Test Cases

| Scenario | User Role | Expected Behavior |
|---|---|---|
| No VPP tokens exist | Admin | Shows "VPP isn't enabled" message + **Enable VPP** button |
| No VPP tokens exist | Non-admin | Shows "ask your admin" copy, no **Enable VPP** button |
| Team not in VPP token | Admin | Shows "fleet isn't added to VPP" message + **Edit VPP** button |
| Team not in VPP token | Non-admin | Shows "ask your admin" copy, no **Edit VPP** button |

## Usage Example

```typescript
// Run the full test suite
// All tests use MSW handlers reset after each case via afterEach

mockServer.use(emptyVppHandler, labelsHandler);

const render = createCustomRenderer({
  withBackendMock: true,
  context: {
    app: {
      isPremiumTier: true,
      isGlobalAdmin: true,
    },
  },
});

render(<SoftwareAppStoreVpp currentTeamId={1} router={router} />);

await waitFor(() => {
  expect(screen.getByRole("button", { name: "Enable VPP" })).toBeInTheDocument();
});
```
