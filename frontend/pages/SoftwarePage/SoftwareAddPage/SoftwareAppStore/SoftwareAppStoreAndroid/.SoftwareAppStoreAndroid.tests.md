React component test suite for `SoftwareAppStoreAndroid` that verifies UI rendering based on Android MDM configuration state and user role permissions.

## Key Components

- **`SoftwareAppStoreAndroid`** — The component under test, rendered with varying app context configurations
- **`createCustomRenderer`** — Test utility for injecting context (tier, admin role, MDM state)
- **`createMockRouter`** — Provides a mock router instance passed as a prop

## Test Cases

| Scenario | Context | Expected Behavior |
|---|---|---|
| Admin + MDM disabled | `isGlobalAdmin: true`, `isAndroidMdmEnabledAndConfigured: false` | Shows "Enable Android MDM" button |
| Non-admin + MDM disabled | `isGlobalAdmin: false`, `isAndroidMdmEnabledAndConfigured: false` | Shows "ask your admin" copy, no button |
| MDM enabled | `isAndroidMdmEnabledAndConfigured: true` | Hides the MDM-not-enabled message, shows Android form |

## Usage Example

```typescript
// Rendering the component in tests with custom context
const render = createCustomRenderer({
  context: {
    app: {
      isPremiumTier: true,
      isGlobalAdmin: true,
      isAndroidMdmEnabledAndConfigured: false,
    },
  },
});

render(<SoftwareAppStoreAndroid currentTeamId={1} router={router} />);

expect(
  screen.getByRole("button", { name: "Enable Android MDM" })
).toBeInTheDocument();
```

## Notes

- All tests run under `isPremiumTier: true` — no free-tier coverage included
- The component conditionally renders either an enable-MDM prompt or the Android app store form based on `isAndroidMdmEnabledAndConfigured`
- Role-based rendering (`isGlobalAdmin`) gates the "Enable Android MDM" action button
