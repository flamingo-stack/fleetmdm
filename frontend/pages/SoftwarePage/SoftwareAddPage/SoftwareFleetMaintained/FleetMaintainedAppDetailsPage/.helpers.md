Utility helpers for the Fleet-maintained apps software addition flow, providing policy metadata generation and structured error message formatting for the add-software workflow.

## Key Components

### Constants & Maps

- **`NameToIdentifierMap`** — Maps human-readable app names (e.g., `"Google Chrome"`) to their Fleet app identifiers (e.g., `"google-chrome"`) for lookup against the maintained apps catalog.

### Internal Helpers

- **`getFleetAppData(name)`** — Looks up a Fleet maintained app entry from `apps.json` using `NameToIdentifierMap`.

### Exports

| Function | Description |
|---|---|
| `getFleetAppPolicyName(appName)` | Returns the standardized policy name: `[Install software] <appName>` |
| `getFleetAppPolicyDescription(appName)` | Returns the automatic install policy description string |
| `getFleetAppPolicyQuery(name)` | Returns the `automatic_policy_query` for a given app name, or `undefined` if not found |
| `getErrorMessage(err)` | Classifies and formats errors from the add-software API call into user-facing messages |

## Usage Example

```typescript
import {
  getFleetAppPolicyName,
  getFleetAppPolicyDescription,
  getFleetAppPolicyQuery,
  getErrorMessage,
} from "./helpers";

// Generate policy metadata for a maintained app
const name = getFleetAppPolicyName("Slack");
// → "[Install software] Slack"

const desc = getFleetAppPolicyDescription("Slack");
// → "Policy triggers automatic install of Slack on each host that's missing this software."

const query = getFleetAppPolicyQuery("Slack");
// → "SELECT 1 FROM apps WHERE name = 'Slack'..." (from apps.json)

// Handle API errors gracefully
try {
  await addSoftware(payload);
} catch (err) {
  const message = getErrorMessage(err);
  // Handles: timeouts (504/408), "already available", secret variable errors
  showToast(message);
}
```

## Notes

- `getErrorMessage` handles four distinct error cases: request timeouts (504/408 or slow JSON decode errors), duplicate software (`"already"` in reason), secret variable validation errors, and generic API errors.
- `NameToIdentifierMap` requires manual maintenance when new apps are added to the Fleet catalog — a TODO exists in the source to improve this matching mechanism.
