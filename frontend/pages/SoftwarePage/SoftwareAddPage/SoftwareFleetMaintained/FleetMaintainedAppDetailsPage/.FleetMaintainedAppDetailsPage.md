Detail page component for configuring and adding a Fleet-maintained app to a team's software library, handling data fetching, form submission, and modal management.

## Key Components

### `FleetAppSummary` (internal)
A card component displaying app name, platform, version, and a "Show details" button. When version is `"latest"`, wraps it in a `TooltipWrapper` directing users to download via URL for the actual version number.

### `FleetMaintainedAppDetailsPage` (default export)
The main page component responsible for:
- Fetching fleet-maintained app data via `softwareAPI.getFleetMaintainedApp`
- Rendering the `FleetAppDetailsForm` for install/uninstall script configuration
- Submitting via `softwareAPI.addFleetMaintainedApp` and invalidating relevant query caches
- Gating content behind `isPremiumTier` check
- Managing two modals: `AddFleetAppSoftwareModal` (loading state during submission) and `FleetAppDetailsModal` (app metadata preview)

## Exported Types

| Type | Description |
|------|-------------|
| `IFleetMaintainedAppDetailsQueryParams` | URL query params shape (`fleet_id`) |
| `IAddFleetMaintainedData` | Form data extended with `appId` for API submission |

## Usage Example

```typescript
// Rendered via react-router; expects routeParams.id as the app ID
// and location.query.fleet_id as the team ID

<FleetMaintainedAppDetailsPage
  location={location} // includes { query: { fleet_id: "42" } }
  router={router}
  routeParams={{ id: "7" }}
/>
```

On successful submission, invalidates `software-titles`, `software-library`, and `fleet-maintained-apps` query scopes, flashes a success notification, and redirects to the software title details page.

> **Note:** Requires a premium Fleet tier. Free-tier users see a `PremiumFeatureMessage` in place of the form.
