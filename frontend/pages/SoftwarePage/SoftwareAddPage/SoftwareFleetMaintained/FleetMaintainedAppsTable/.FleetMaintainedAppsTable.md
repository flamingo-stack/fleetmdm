Renders the Fleet Maintained Apps table within the software add flow, combining per-platform API entries into unified rows and synchronizing all filters, sort, search, and pagination state with the URL.

## Key Components

- **`FleetMaintainedAppsTable`** — Default export. Main table component that wraps `TableContainer` with server-side pagination, sorting, and filtering.
- **`combineAppsByPlatform`** — Pure utility that merges separate `darwin`/`windows` `IFleetMaintainedApp` entries from the API response into a single `ICombinedFMA` row per app name.
- **`EmptyFleetAppsTable`** — Empty state component shown when no results match, with a link to the Fleet feature request page.
- **`determineQueryParamChange`** — Identifies which query parameter changed on a table update to selectively reset the page index to `0`.
- **`generateNewQueryParams`** — Builds the next URL query parameter object from table state, collapsing `"all"` filter values to `undefined`.
- **`renderCustomControls`** — Renders `FmaStatusFilter` and `FmaPlatformFilter` dropdowns above the table.

## Usage Example

```typescript
import FleetMaintainedAppsTable from "./FleetMaintainedAppsTable";

<FleetMaintainedAppsTable
  teamId={1}
  isLoading={isFetching}
  data={fleetMaintainedAppsResponse}
  router={router}
  query={queryParam}
  perPage={20}
  orderDirection="asc"
  orderKey="name"
  platformParam="darwin"   // "darwin" | "windows" | "all" | undefined
  statusParam="available"  // "available" | "added" | "all" | undefined
  currentPage={0}
/>
```

All filter and pagination changes call `router.replace(...)` with updated query params, keeping the URL as the single source of truth and preserving browser back/forward navigation.
