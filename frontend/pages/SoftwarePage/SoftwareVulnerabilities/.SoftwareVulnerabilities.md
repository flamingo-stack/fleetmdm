Manages data fetching and state for the Software Vulnerabilities tab, handling both paginated list queries and exact CVE lookup via quoted search strings.

## Key Components

### `SoftwareVulnerabilities` (default export)
Main React component that orchestrates two distinct query strategies:

- **List query** (`getVulnerabilities`) — fires for standard/filtered searches, supports pagination, sorting, team filtering, and exploit-only filtering.
- **Exact match query** (`softwareVulnAPI.getVulnerability`) — fires when the user wraps a search term in quotes (e.g., `"CVE-2021-44228"`), hitting the single-CVE endpoint and normalizing the response into list format.

### `ISoftwareVulnerabilitiesProps`
Props interface accepting router, pagination controls (`perPage`, `currentPage`, `orderDirection`, `orderKey`), optional `teamId`, `query`, and `showExploitedVulnerabilitiesOnly` flag.

### Empty State Reasons (`IVulnerabilitiesEmptyStateReason`)
Derived from API responses and error codes to distinguish between: `"no-vulns-detected"`, `"no-matching-items"`, `"known-vuln"`, `"invalid-cve"`, and `"unknown-cve"`.

## Usage Example

```typescript
<SoftwareVulnerabilities
  router={router}
  isSoftwareEnabled={true}
  perPage={20}
  query={searchQuery}
  orderDirection="desc"
  orderKey="cvss_score"
  currentPage={0}
  teamId={3}
  showExploitedVulnerabilitiesOnly={false}
/>
```

## Notable Behaviors

- **Exact match detection** — regex `/^(['"]).*\1$/` identifies quoted queries and switches to the single-CVE endpoint.
- **Exploit toggle re-fetch** — a `useEffect` re-fetches exact match results when `showExploitedVulnerabilitiesOnly` changes, since the list query won't re-run in exact match mode.
- **Spinner strategy** — `!tableData` guard prevents spinner flashing on subsequent refreshes; spinner only shows on first load.
- HTTP `400` → `"invalid-cve"`, `404` → `"unknown-cve"` or `"invalid-cve"` based on FE CVE format validation.
