Unit tests for the `FilterPill` component, verifying rendering behavior, icon display, tooltip interactions, and the clear/remove callback.

## Key Components

| Test Case | Description |
|---|---|
| `renders the pill text` | Verifies the `label` prop renders correctly |
| `renders icon properly` | Confirms icon renders inside the status role element |
| `renders a passed in string tooltip` | Validates string `tooltipDescription` appears on hover |
| `renders a passed in ReactNode tooltip` | Validates JSX `tooltipDescription` appears on hover |
| `calls the onCancel callback` | Confirms `onClear` fires when the close icon button is clicked |

## Usage Example

```typescript
// Rendering a basic FilterPill in tests
render(<FilterPill label="Test Pill" onClear={noop} />);
expect(screen.getByText("Test Pill")).toBeInTheDocument();

// Testing tooltip on hover
const { user } = renderWithSetup(
  <FilterPill
    label="OS Filter"
    tooltipDescription="Filter by operating system"
    onClear={noop}
  />
);
await user.hover(screen.getByText("OS Filter"));
await waitFor(() => {
  expect(screen.getByText("Filter by operating system")).toBeInTheDocument();
});

// Testing clear callback
const spy = jest.fn();
const { user } = renderWithSetup(
  <FilterPill label="Test Pill" onClear={spy} />
);
await user.click(within(screen.getByRole("button")).getByTestId("close-icon"));
expect(spy).toHaveBeenCalled();
```

## Notes

- Uses `renderWithSetup` from `test/test-utils` for user-event interaction support
- Tooltip tests rely on `waitFor` to handle async rendering
- Icon presence is asserted within the `status` ARIA role element
