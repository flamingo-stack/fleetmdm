Form validation helpers for the `RunScriptBatchModal` schedule form, providing date/time validation logic with support for both "run now" and "schedule" execution modes.

## Key Components

### Types & Interfaces

- **`IRunScriptBatchModalFormValidation`** — Validation result shape containing an `isValid` boolean and optional per-field `{ isValid, message }` objects for `date` and `time`.
- **`IValidation`** — Internal interface defining a named validation rule with an `isValid` predicate and optional error message (string or function).
- **`FORM_VALIDATIONS`** — Static validation rule map covering:
  - `date`: required, `yyyy-MM-dd` format check, and not-in-past check (evaluated at end of day)
  - `time`: required, `HH:mm` format check, and not-in-past check (skipped when date is already invalid)

### Exports

- **`validateFormData(formData, runMode)`** — Primary validation entry point. Returns a no-op `{ isValid: true }` result for `"run_now"` mode; runs all field validations sequentially for `"schedule"` mode, short-circuiting on the first failing rule per field.

## Usage Example

```typescript
import { validateFormData } from "./helpers";

const formData = {
  date: "2025-12-01",
  time: "14:30",
};

// Run now — always valid, no checks performed
const runNowResult = validateFormData(formData, "run_now");
// → { isValid: true }

// Schedule — validates date and time fields
const scheduleResult = validateFormData(formData, "schedule");
// → {
//     isValid: true,
//     date: { isValid: true },
//     time: { isValid: true },
//   }

// Invalid past date example
const pastResult = validateFormData({ date: "2020-01-01", time: "00:00" }, "schedule");
// → {
//     isValid: false,
//     date: { isValid: false, message: "Date (UTC) cannot be in the past" },
//     time: { isValid: true },
//   }
```

## Notes

- All date/time comparisons are performed in **UTC**.
- The `notInPast` time validation is skipped when the date field is already invalid, preventing compounding error messages.
- A validator abstraction is planned (see TODO in source) to unify this pattern across other modal form validation files.
