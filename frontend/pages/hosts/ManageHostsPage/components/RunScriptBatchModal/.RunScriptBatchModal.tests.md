Integration test suite for the `RunScriptBatchModal` component, validating script selection, scheduling UI behavior, and API call correctness for batch script execution.

## Key Components

- **`selectScript`** — Helper that simulates clicking a script in the list and asserts Run/Cancel buttons appear
- **`getScheduleSelector`** — Helper that asserts and returns the "Schedule for later" / "Run now" radio buttons
- **`getScheduleUI`** — Helper that asserts and returns the date/time UTC inputs shown when scheduling
- **`RunScriptBatchModal` mock** — Replaces `RunScriptBatchPaginatedList` with a minimal stub exposing `windows script` and `linux script` click targets
- **MSW handlers** — `GET /scripts` returns two test scripts; `POST /scripts/run/batch` captures call payloads via `runBatchFn`

## Usage Example

```typescript
// Render the modal and simulate selecting a script then running immediately
const { user } = render(<RunScriptBatchModal {...defaultProps} />);
const { runButton } = await selectScript(user, "windows");
await user.click(runButton);

// Assert the correct API payload was sent
const body = await runBatchFn.mock.calls[0][0].request.json();
expect(body).toEqual({
  script_id: 123,
  host_ids: [1, 2],
});
```

## Test Coverage

| Scenario | Assertion |
|---|---|
| Script list renders | Both scripts visible in DOM |
| Empty state | "No scripts available" + "Add a script" link shown |
| Platform heading | Correct OS label displayed after script selection |
| Run now (default) | No date/time inputs rendered |
| Schedule for later | Date/UTC and Time/UTC inputs appear |
| Date validation | Invalid format, past date, and future date messages |
| Time validation | Invalid format, past time errors |
| Run now API call | `host_ids` sent, no `not_before` param |
| Filter-based run | `filters` object sent instead of `host_ids` |
