Integration tests for the `HostReportsTab` component, verifying rendering behavior across empty and populated report states with permission-based UI variations.

## Key Components

- **`createHostReportsHandler`** — MSW request handler factory for mocking `GET /hosts/:id/reports` responses
- **`emptyReportsResponse`** — Fixture for a zero-report API response
- **`populatedReportsResponse`** — Fixture with a single report entry including metadata fields
- **`baseProps`** — Shared prop baseline (`hostId`, `hostName`, `router`, `location`) passed to all rendered instances

## Test Cases

| Test | Scenario |
|------|----------|
| Empty state (admin) | Renders "No reports scheduled", disabled search, "0 reports" count, and Schedule CTA button |
| Empty state (observer) | Renders empty state copy without schedule CTA or button when `canScheduleReport={false}` |
| Populated state | Renders "1 report" count with enabled search input |

## Usage Example

```typescript
// Pattern used to mount the component under test with a mocked backend
mockServer.use(createHostReportsHandler(emptyReportsResponse));

const render = createCustomRenderer({
  withBackendMock: true,
  context: {
    app: {
      isGlobalAdmin: true,
      currentUser: createMockUser(),
    },
  },
});

render(
  <HostReportsTab
    hostId={1}
    hostName="test-host"
    router={mockRouter}
    location={{ pathname: "/hosts/1", query: {} }}
    canScheduleReport
    onScheduleReport={jest.fn()}
  />
);

expect(await screen.findByText("No reports scheduled")).toBeInTheDocument();
```

## Notes

- Uses [MSW](https://mswjs.io/) via `mockServer` for network interception
- `createCustomRenderer` injects app context (auth role, current user) without a full Redux store
- Permission gating is tested by toggling `canScheduleReport` and `isOnlyObserver` context flags
