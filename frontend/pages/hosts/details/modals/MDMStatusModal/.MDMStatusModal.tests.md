Test suite for the `MDMStatusModal` component, verifying rendering behavior, async data loading, navigation, and user interactions related to MDM enrollment status and DEP (Device Enrollment Program) profile assignment.

## Key Components

- **`mockDepAssignmentResponse`** — Fixture object simulating a successful DEP assignment API response, including `dep_device` and `host_dep_assignment` fields
- **Test cases** — 10 `it` blocks covering:
  - Enrollment status text rendering
  - Conditional profile assignment section visibility (premium tier + Apple device gating)
  - Loading spinner display during async fetch
  - Error state rendering on API failure
  - Profile assignment error row with throttled/failed response codes
  - Router navigation on MDM status and profile error row clicks
  - Zero-value timestamp display as `"Never"`
  - `onExit` callback invocation on modal close

## Usage Example

```typescript
// Run the full suite
jest.mock("services/entities/hosts");

(hostAPI.getDepAssignment as jest.Mock).mockResolvedValue(mockDepAssignmentResponse);

render(
  <MDMStatusModal
    hostId={3}
    enrollmentStatus="On (manual)"
    router={mockRouter}
    isPremiumTier
    isAppleDevice
    onExit={jest.fn()}
  />
);

expect(await screen.findByText("Profile assignment")).toBeInTheDocument();
```

## Notes

- Uses `createCustomRenderer` with `withBackendMock: true` for isolated rendering
- Mocks `hostAPI.getDepAssignment` via `jest.mock` — reset after each test via `jest.resetAllMocks()`
- Navigation assertions validate that `router.push` is called with URLs containing `paths.MANAGE_HOSTS` and the appropriate query parameters (`mdm_enrollment_status`, `dep_assign_profile_response`)
