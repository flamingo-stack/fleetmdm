Test suite for the `LocationModal` component, verifying rendering behavior across geolocation display states, iOS/iPadOS MDM device status scenarios, and footer button visibility.

## Key Components

- **`makeIosDetails`** — Helper factory that builds `iosOrIpadosDetails` props with a given `HostMdmDeviceStatusUIState` and optional `isIosOrIpadosHost` flag
- **`createMockHostGeolocation`** — Mock factory imported from `__mocks__/hostMock` providing default geolocation data (Minneapolis, US at coordinates `-93.2602, 44.9844`)
- **Test suite (`describe("LocationModal")`)** — Eight test cases covering:
  - Basic geolocation rendering and Google Maps link construction
  - `LastUpdatedText` display with a relative timestamp
  - iOS-specific status messages (`unlocked`, `locking`, `locating`, unrecognized/fallback states)
  - Footer button rendering (`Lock`/`Cancel` vs. `Close`)

## Usage Example

```typescript
// Running a subset of tests
import { render, screen } from "@testing-library/react";
import { createMockHostGeolocation } from "__mocks__/hostMock";
import LocationModal from "./LocationModal";

render(
  <LocationModal
    hostGeolocation={createMockHostGeolocation()}
    onExit={() => {}}
    onClickLock={() => {}}
  />
);

expect(screen.getByText("Minneapolis, US")).toBeVisible();
expect(screen.getByRole("link", { name: /Open in Google Maps/i })).toHaveAttribute(
  "href",
  "https://www.google.com/maps?q=-93.2602,44.9844"
);
```

## Coverage Summary

| Scenario | Expected Outcome |
|---|---|
| `hostGeolocation` provided | City/country label + Google Maps link visible |
| `detailsUpdatedAt` 2 days ago | "Updated 2 days ago" text rendered |
| iOS `unlocked` status | Lost Mode requirement message + Lock/Cancel buttons |
| iOS `locking` status | Lost Mode message + lock-pending message |
| iOS `locating` status | Location-pending message |
| iOS `wiping` (no geolocation) | "Location not available" + Refetch button |
| iOS `wiping` (with geolocation) | Falls back to standard location view |
| Non-iOS host | Close button rendered instead of Lock/Cancel |
