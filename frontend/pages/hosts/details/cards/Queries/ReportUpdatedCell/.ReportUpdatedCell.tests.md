Test suite for the `ReportUpdatedCell` component, verifying rendering behavior across different combinations of query scheduling, data retention, and report availability states.

## Key Components

- **`HUMAN_READABLE_DATETIME_REGEX`** – Regex pattern matching localized datetime strings (e.g., `1/15/2024, 3:45:22 PM`) used to assert tooltip content
- **Test: interval + discard_data + automations_enabled** – Asserts "No report" text with informational tooltip and no "View report" link
- **Test: interval + discard_data off + no `last_fetched`** – Asserts `---` placeholder with a "Fleet is collecting" tooltip
- **Test: `last_fetched` present + active interval** – Asserts relative time display (e.g., "10 days ago"), human-readable datetime tooltip on hover, and "View data" link
- **Test: `last_fetched` present + no interval** – Same assertions as above but with `interval={0}`, confirming static query results still render correctly

## Usage Example

```typescript
// Rendering the component under test with various prop combinations
renderWithSetup(
  <ReportUpdatedCell
    interval={1000}
    discard_data={false}
    automations_enabled={false}
    should_link_to_hqr
    last_fetched={new Date().toISOString()}
    queryId={3}
    hostId={4}
  />
);

// Asserting relative time display
const timeAgo = screen.getByText(/\d+.+ago/);
expect(timeAgo).toBeInTheDocument();

// Asserting tooltip shows full datetime on hover
await user.hover(timeAgo);
await waitFor(() => {
  expect(screen.getByText(HUMAN_READABLE_DATETIME_REGEX)).toBeInTheDocument();
});
```

## Notes

- Uses `renderWithSetup` from `test/test-utils` to include user-event support for hover interactions
- Tooltip assertions use `waitFor` due to async rendering; the first test omits `await` on `waitFor`, which is a known testing pattern gap
