Test suite for the `Vitals` card component, validating conditional rendering of device vitals (hardware model, serial number, enrollment ID, IP addresses, and location) across different host platforms and MDM enrollment states.

## Key Components

- **`describe("Vitals Card component")`** — Core test suite covering field visibility rules for Android, iOS, iPadOS, and macOS (darwin) hosts under various MDM enrollment statuses (`On (personal)`, `On (manual)`, `On (automatic)`, and unenrolled)
- **`describe("Location vital")`** — Focused tests for the location field, including the `toggleLocationModal` callback and ADE (Automatic Device Enrollment) host handling
- **`renderLocationVital`** — Helper factory that builds a mock host and renders `<Vitals>` with optional ADE mode, toggle support, and host overrides

## Conditional Rendering Rules Tested

| Platform | Enrollment | Shows |
|---|---|---|
| Android | Non-personal | Serial number |
| Android / iOS / iPadOS | Personal | Enrollment ID |
| iOS / iPadOS | Manual/Automatic | Serial number |
| macOS | Personal | Enrollment ID + IPs |
| macOS | Manual/Automatic/None | Serial number + IPs |

## Usage Example

```typescript
// Render a personally-enrolled Android host
const mockHost = createMockHost({
  platform: "android",
  hardware_model: "Pixel 6",
  uuid: "enrollment-id-12345",
  mdm: createMockHostMdmData({ enrollment_status: "On (personal)" }),
});

render(<Vitals vitalsData={mockHost} mdm={mockHost.mdm} />);

expect(screen.getByText("Enrollment ID")).toBeInTheDocument();
expect(screen.queryByText("Serial number")).not.toBeInTheDocument();
```
