Test suite for the `FailedToRotateManagedLocalAccountPasswordActivityItem` component, verifying rendering behavior for Fleet-initiated failed managed local account password rotation activity items.

## Key Components

- **`FailedToRotateManagedLocalAccountPasswordActivityItem`** — The component under test, imported from the sibling `FailedToRotateManagedLocalAccountPassword` module
- **`createMockHostPastActivity`** — Mock factory used to generate activity fixtures with `fleet_initiated: true` and `ActivityType.FailedToRotateManagedLocalAccountPassword`

## Test Cases

| Test | Assertion |
|---|---|
| Renders Fleet-initiated activity content | Actor name `"Fleet"` and failure message are visible |
| No cancel icon | `close-icon` test ID is absent from the DOM |
| No details icon | `info-outline-icon` test ID is absent from the DOM |

## Usage Example

```typescript
render(
  <FailedToRotateManagedLocalAccountPasswordActivityItem
    activity={createMockHostPastActivity({
      actor_full_name: "Fleet",
      fleet_initiated: true,
      type: ActivityType.FailedToRotateManagedLocalAccountPassword,
    })}
    tab="past"
  />
);

expect(
  screen.getByText(/failed to rotate the managed local account password/i)
).toBeVisible();
```

## Notes

- All three test cases share the same `fleet_initiated: true` activity fixture
- The suite confirms this activity type renders as a read-only item — no cancellation or detail-expansion affordances are present
- Uses `@testing-library/react` with standard `render`/`screen` queries
