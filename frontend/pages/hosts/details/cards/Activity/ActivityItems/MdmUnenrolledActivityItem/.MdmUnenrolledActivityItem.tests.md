Renders and verifies the `MdmUnenrolledActivityItem` component across platform and actor combinations in the host activity feed.

## Key Components

- **`renderItem(platform, actor)`** — Helper that mounts `MdmUnenrolledActivityItem` with a mocked `MdmUnenrolled` activity for the given platform and actor name.
- **`cases` table** — Parameterized test matrix covering `ios`, `android`, and `darwin` platforms with and without an actor, asserting the correct copy variant is displayed.
- **Actor visibility assertion** — When an actor is present, confirms the actor's full name is rendered.
- **Icon absence test** — Confirms neither the cancel (`close-icon`) nor the info (`info-outline-icon`) action icons are rendered for this activity type.

## Usage Example

```typescript
// Platform/actor matrix tested
const cases: Array<[Platform, string, RegExp]> = [
  ["ios",     "Admin User", /told Fleet to unenroll this host/i],
  ["android", "Admin User", /told Fleet to unenroll this host/i],
  ["android", "",           /This host is unenrolled from Fleet/i],
  ["darwin",  "Admin User", /told Fleet to turn off mobile device management \(MDM\) for this host/i],
  ["darwin",  "",           /Mobile device management \(MDM\) was turned off for this host/i],
];

it.each(cases)("renders %s copy (actor=%j)", (platform, actor, expected) => {
  renderItem(platform, actor);
  if (actor) expect(screen.getByText(actor)).toBeVisible();
  expect(screen.getByText(expected)).toBeVisible();
});
```

## Notes

- iOS and Android share the same "unenroll" phrasing regardless of actor presence (actor=`""` only tested for Android).
- Darwin (macOS) uses MDM-specific language and has distinct actor/no-actor variants.
