Maps host activity types to their corresponding React components for rendering past and upcoming host activity items in the Fleet MDM host activity timeline.

## Key Components

### Interfaces

- **`IHostActivityItemComponentProps`** — Base props interface all host activity item components must implement. Includes `activity`, `tab` (`"past" | "upcoming"`), `isSoloActivity`, and `hideCancel`.
- **`IHostActivityItemComponentPropsWithShowDetails`** — Extends the base props with `onShowDetails` and optional `onCancel` handlers for activities requiring a detail view.

### Component Maps

- **`pastActivityComponentMap`** — A `Record` mapping every `IHostPastActivityType` enum value to its corresponding React component (e.g., `ActivityType.RanScript → RanScriptActivityItem`). Covers 27 activity types including script runs, software installs/uninstalls, host lock/wipe/unlock, certificate management, and managed local accounts.
- **`upcomingActivityComponentMap`** — A `Record` mapping `IHostUpcomingActivityType` values to components. Covers 6 activity types: script runs, software installs/uninstalls, App Store installs, and host lock/unlock.

## Usage Example

```typescript
import {
  pastActivityComponentMap,
  upcomingActivityComponentMap,
} from "./ActivityConfig";
import { IHostPastActivity } from "interfaces/activity";

const renderActivity = (activity: IHostPastActivity) => {
  const ActivityComponent = pastActivityComponentMap[activity.type];
  if (!ActivityComponent) return null;

  return (
    <ActivityComponent
      activity={activity}
      tab="past"
      isSoloActivity={false}
      onShowDetails={(activityType, details) => console.log(details)}
    />
  );
};
```

> **Note:** Some activity types (e.g., `UninstalledSoftware`, `InstalledAppStoreApp`) intentionally reuse existing components like `InstalledSoftwareActivityItem` since their rendering logic is shared.
