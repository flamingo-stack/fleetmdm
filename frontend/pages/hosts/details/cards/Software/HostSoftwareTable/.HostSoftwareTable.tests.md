Renders and verifies the `HostSoftwareTable` component across empty states, filter interactions, platform-specific behaviors, and macOS inventory filter states.

## Key Components

- **`baseProps`** — Shared default props used across all test cases, including mock router, mock software response, and no-op callbacks
- **`renderWithContext`** — Helper that wraps `HostSoftwareTable` with a custom renderer providing `isGlobalAdmin: true` app context
- **Test suites** — Eight `it` blocks covering distinct rendering scenarios

## Test Coverage

| Scenario | Assertion |
|---|---|
| Truly empty state (no software, no filters) | Empty copy, `0 items`, disabled search and filter button |
| Filtered empty state (search query present) | Standard "no items match" copy, search input **enabled** |
| Active vuln filter | Filter button rendered |
| Vuln filter + iPad/iPhone platform | `VulnsNotSupported` message shown |
| Truly empty state on iPad/iPhone | "No software found" rendered |
| macOS + `macosApplicationsFilter: true` | "Applications" dropdown option shown |
| macOS + `macosApplicationsFilter: false` | "Full inventory" dropdown option shown |
| Non-macOS platform | Neither "Applications" nor "Full inventory" rendered |

## Usage Example

```typescript
import { createCustomRenderer } from "test/test-utils";
import { createMockGetHostSoftwareResponse } from "__mocks__/hostMock";
import HostSoftwareTable from "./HostSoftwareTable";

const render = createCustomRenderer({
  context: { app: { isGlobalAdmin: true, currentUser: createMockUser() } },
});

render(
  <HostSoftwareTable
    data={createMockGetHostSoftwareResponse({ count: 0, software: [] })}
    platform="darwin"
    macosApplicationsFilter={true}
    // ...other required props
  />
);
```
