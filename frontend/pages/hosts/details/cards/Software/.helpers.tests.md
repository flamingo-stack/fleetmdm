Test suite for the `helpers.ts` utility module in the host software UI, validating version comparison logic, UI status derivation, and software subheader generation.

## Key Components

### `compareVersions` Tests
Covers the full range of version string formats handled by the comparison utility:
- Standard SemVer patch/minor/major ordering
- Pre-release tag ordering (`alpha` < `beta` < `rc` < stable)
- Build metadata (`+build`, parenthesized `(build ...)`) treated as equal
- Edge cases: leading `v`, leading zeros, trailing zeros, date-based versions, alphanumeric suffixes
- Real-world vendor quirks: `Build NNNN` prefix (Sublime Text), `.CE` edition suffix (MySQL Workbench), `-latest` channel tag (Lens)

### `getUiStatus` Tests
Validates the UI status string returned based on:
- Install/uninstall failure states with and without available updates
- Pending operations vs. host online/offline state (`installing` vs. `pending_install`, `updating` vs. `pending_update`)
- Time-based transitions: `recently_installed`, `recently_updated`, `update_available`, `recently_uninstalled` derived from `lastInstallDate` vs. `hostSoftwareUpdatedAt`

### `getSoftwareSubheader` Tests
*(Partially shown)* — tests subheader string generation for host software entries.

## Usage Example

```typescript
import { compareVersions, getUiStatus } from "./helpers";
import { createMockHostSoftware, createMockHostSoftwarePackage } from "__mocks__/hostMock";

// Version comparison
compareVersions("1.0.0-rc.1", "1.0.0"); // -1 (rc is less than stable)
compareVersions("8.0 (build 6300)", "8.0"); // 0 (build metadata ignored)

// UI status derivation
const sw = createMockHostSoftware({
  status: "pending_install",
  software_package: createMockHostSoftwarePackage({ version: "2.0.0" }),
});
getUiStatus(sw, true);  // "updating"  (online, update available)
getUiStatus(sw, false); // "pending_update" (offline)
```
