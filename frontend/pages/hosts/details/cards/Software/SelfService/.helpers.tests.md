Unit tests for the `helpers` module within the self-service software feature, covering `countUninstalledForInstallAll`, `hasInProgressInstallAllItems`, and `filterSoftwareByCustomCategory`.

## Key Components

### Test Suites

- **`countUninstalledForInstallAll`** — Verifies which `ui_status` values are counted as eligible for "Install All" (e.g., `uninstalled`, `failed_install*`, `never_ran_script`) and which are excluded (e.g., `installed`, `update_available`, in-progress, pending states).
- **`hasInProgressInstallAllItems`** — Verifies detection of any in-progress or pending status (`installing`, `uninstalling`, `updating`, `running_script`, `pending_*`) that should block a new "Install All" action.
- **`filterSoftwareByCustomCategory`** — Verifies category-based filtering of device software items, including edge cases like undefined category ID (returns all), missing category list, stale URL mismatches, case-insensitive name matching, and support for both `software_package` and `app_store_app` sources.

### Helper Factory

- **`makeItem(ui_status, overrides?)`** — Local factory composing `createMockDeviceSoftware()` with a given `ui_status` and optional field overrides, reducing boilerplate across all test cases.

## Usage Example

```typescript
// Running tests
npx jest helpers.tests.ts

// Typical assertion pattern used throughout
expect(
  countUninstalledForInstallAll([
    makeItem("uninstalled"),
    makeItem("failed_install"),
  ])
).toBe(2);

// Category filtering with a matched category ID
const categories = [createMockSelfServiceCategory({ id: 1, name: "🌎 Browsers" })];
expect(
  filterSoftwareByCustomCategory([browserItem, securityItem], categories, 1)
).toEqual([browserItem]);
```
