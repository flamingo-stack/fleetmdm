Orchestrates the self-service software panel for device users, handling data fetching, filtering, category management, and rendering for both desktop (table) and mobile (tile) layouts.

## Key Components

### `SelfServiceCard` (default export)
Main component that composes the self-service UI. Responsibilities include:
- Fetching device-scoped categories via `selfServiceCategoriesAPI.getDeviceCategories`
- Filtering software by selected category using `filterSoftwareByCustomCategory`
- Computing install-all eligibility (`uninstalledCount`, `hasInProgress`)
- Syncing URL query params for search, sort, pagination, and category selection
- Recovering from stale `category_id` URL params (deleted/unknown categories)
- Rendering a `Card`+`SelfServiceTable` layout for desktop or a tile-based layout for mobile

### `SelfServiceQueryParams`
Interface defining URL-driven query state: `query`, `category_id`, `order_key`, `order_direction`, `page`, `per_page`.

### `ISelfServiceCardProps`
Full prop contract for the component including device token, router, software data, loading/error states, and callbacks.

## Usage Example

```typescript
<SelfServiceCard
  contactUrl="https://help.example.com"
  deviceToken="abc123"
  queryParams={{
    query: "",
    category_id: undefined,
    order_key: "name",
    order_direction: "asc",
    page: 0,
    per_page: 20,
  }}
  enhancedSoftware={softwareList}
  selfServiceData={apiResponse}
  isLoading={false}
  isError={false}
  isFetching={false}
  isEmpty={false}
  router={router}
  pathname="/device/self-service"
  isMobileView={false}
  onClickInstallAction={(id, isScript) => handleInstall(id, isScript)}
  onInstallAllSuccess={() => refetchSoftware()}
/>
```

> **Note:** `deviceToken` scopes the category fetch to the specific device's fleet, preventing cross-device cache bleed. Categories with a `category_id` not found in the loaded list are automatically cleared from the URL to keep the view consistent.
