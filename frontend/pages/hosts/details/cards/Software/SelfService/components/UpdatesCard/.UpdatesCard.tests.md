Test suite for the `UpdatesCard` React component, verifying rendering, pagination, loading/error states, and conditional display logic for device software updates.

## Key Components

- **`createEnhancedSoftware(count, overrides)`** — Helper factory that generates an array of `IDeviceSoftwareWithUiStatus` mock objects, defaulting `ui_status` to `"update_available"`.
- **Test cases:**
  - Header, subheader, and "Update all" button rendering
  - Paginated `UpdateSoftwareItem` display (3 items per page in jsdom)
  - Next-page navigation via pagination controls
  - "Update all" button disabled state when all items have `ui_status: "updating"`
  - Spinner visibility during loading (accounts for anti-flash delay)
  - Error view when `isError` is `true`
  - Renders nothing when no software has an update-needed status

## Usage Example

```typescript
// Running the test suite
// From the repository root:
// npx jest UpdatesCard.tests.tsx

// Example: rendering the component in a test
const updates = createEnhancedSoftware(3);
render(
  <UpdatesCard
    enhancedSoftware={updates}
    onClickUpdateAction={noop}
    onClickUpdateAll={noop}
    onClickFailedUpdateStatus={noop}
    isLoading={false}
    isError={false}
  />
);
expect(screen.getByRole("button", { name: "Update all" })).toBeEnabled();
```

## Notes

- Uses `createCustomRenderer` with `withBackendMock: true` to support components that make backend calls.
- Pagination page size is derived from `getUpdatesPageSize`, which defaults to 3 items in a jsdom environment (no real viewport width).
- Responsive sizing behavior is explicitly out of scope for this suite.
