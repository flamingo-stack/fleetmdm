Integration test suite for the `InstallAllInCategoryButton` component, verifying rendering behavior, disabled states, modal interactions, API call parameters, and error handling.

## Key Components

- **`baseProps`** — Default prop fixture (`IInstallAllInCategoryButtonProps`) shared across test cases
- **`createCustomRenderer`** — Custom render helper configured with `withBackendMock: true`
- **`mockServer`** — MSW mock server used to intercept and inspect `POST /device/:token/software/install_all` requests

## Test Coverage

| Scenario | Assertion |
|---|---|
| Renders uninstalled count in label | Button shows `"Install all (3)"` |
| `uninstalledCount === 0` | Button is disabled |
| `hasInProgressInCategory === true` | Button is disabled |
| Button clicked | Confirmation modal opens with correct copy |
| Singular count (`1`) | Modal uses `"app"` instead of `"apps"` |
| Cancel clicked | Modal closes, no POST fired |
| Confirm clicked | POSTs with `category_id` query param; `onSuccess` called |
| `categoryId` is `undefined` | POST URL omits `category_id` param |
| API returns 500 | `onSuccess` not called; modal stays open for retry |

## Usage Example

```typescript
// Running the test suite
import { describe, it, expect } from "@jest/globals";

// Key pattern: intercepting the install_all endpoint
mockServer.use(
  http.post(baseUrl("/device/:token/software/install_all"), ({ request }) => {
    const url = request.url;
    // Assert query params, e.g. url.includes("category_id=1")
    return new HttpResponse(null, { status: 202 });
  })
);
```
