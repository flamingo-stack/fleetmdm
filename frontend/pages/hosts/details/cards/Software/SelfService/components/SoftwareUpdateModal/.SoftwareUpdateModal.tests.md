Test suite for the `SoftwareUpdateModal` component, verifying UI rendering, button behavior, and status-driven messaging across different software install states and user contexts.

## Key Components

- **`SoftwareUpdateModal` (subject under test)** — Modal component for initiating or viewing software update operations on a host
- **`createMockHostSoftware`** — Factory helper from `__mocks__/hostMock` used to generate typed mock software data with optional overrides
- **`renderWithSetup`** — Custom test utility that wraps `@testing-library/react` render with user-event setup for interaction testing

## Test Coverage

| Scenario | Assertions |
|---|---|
| Default update state | Modal title, Update/Cancel buttons present; Close absent |
| `pending_install` status | Only Close button rendered; Update/Cancel absent |
| `pending_install` message | Pending icon, correct host name, app bundle identifier |
| `isDeviceUser` prop | "when it comes online" messaging rendered |
| Generic update message | Error icon, software name, host name, update prompt |
| Single installed version | Renders `"Current version:"` (singular) |
| Multiple installed versions | Renders `"Current versions:"` (plural) |
| Empty `installed_versions` | Neither version label rendered |
| `pending_install` + versions | Version labels suppressed |

## Usage Example

```typescript
// Running the full test suite
// From the repository root:
// npx jest SoftwareUpdateModal.tests.tsx

// Creating a mock with a specific install status
const pendingMock = createMockHostSoftware({ status: "pending_install" });

// Simulating user interaction with renderWithSetup
const { user } = renderWithSetup(
  <SoftwareUpdateModal
    hostDisplayName="My Host"
    software={pendingMock}
    onExit={jest.fn()}
    onUpdate={jest.fn()}
  />
);
await user.click(screen.getByRole("button", { name: "Close" }));
```
