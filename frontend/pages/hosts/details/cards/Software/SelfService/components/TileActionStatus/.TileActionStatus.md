React component that renders the action button and status indicator for a software tile in the self-service UI, handling install, update, reinstall, retry, run, and rerun actions alongside pending/in-progress states.

## Key Components

### `TileActionStatus` (default export)
The main component that conditionally renders either an active-state spinner with label or an action button (with optional error indicator) based on the software's `ui_status`.

### `getTileActionLabel(uiStatus)`
Maps a `IHostSoftwareUiStatus` value to a user-facing button label (`"Install"`, `"Retry"`, `"Update"`, `"Reinstall"`, `"Run"`, `"Rerun"`).

### `getPendingOrRunningLabel(uiStatus)`
Maps in-progress/pending statuses to animated label strings (`"Installing..."`, `"Updating..."`, `"Running..."`, `"Uninstalling..."`).

### Props (`TileActionStatusProps`)
| Prop | Type | Description |
|------|------|-------------|
| `software` | `IDeviceSoftwareWithUiStatus` | Software item including current `ui_status` |
| `onActionClick` | `(software) => void` | Callback fired when the action button is clicked |

## Usage Example

const handleAction = (software: IDeviceSoftwareWithUiStatus) => {
  // trigger install / uninstall / script via Fleet API

## Behaviour Notes

- **Immediate disable**: The action button is disabled locally via `disableAction` state on click, preventing double-submits on slow connections before the API responds.
- **Auto-reset**: A `useEffect` re-enables the button once the status leaves an in-progress/pending state.
- **Error display**: When `isSoftwareErrorStatus` is `true`, an `"error"` icon and `"Failed"` label appear alongside the retry button.
- **Mobile note**: `failed_uninstall` maps to `"Reinstall"` because the mobile self-service UI only exposes install-side actions.
