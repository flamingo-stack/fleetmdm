Renders a single software update card for a device, displaying the software's icon, name, version, install status, and an update action button with support for pending, failed, and recently-updated UI states.

## Key Components

- **`UpdateSoftwareItem`** — Root export; wraps the card layout combining `InstallerInfo` and `InstallerStatusAction`.
- **`InstallerInfo`** — Displays the software icon, display name, and version from either a package or VPP app source.
- **`InstallerStatus`** — Renders a tooltip-wrapped status indicator; shows a clickable "Failed" button when the last install failed.
- **`InstallerStatusAction`** — Manages the primary action area, cycling through `updating` (spinner), `recently_updated` (success icon + tooltip), or the default `Update` button based on `ui_status`.
- **`STATUS_CONFIG`** — Maps each `SoftwareInstallStatus` (`installed`, `pending_install`, `failed_install`) to an icon, display text, and dynamic tooltip renderer.

## Usage Example

```typescript
import UpdateSoftwareItem from "./UpdateSoftwareItem";

<UpdateSoftwareItem
  software={deviceSoftwareWithUiStatus}
  onClickUpdateAction={(id) => {
    // Trigger install/update flow for the given software ID
    handleUpdate(id);
  }}
  onShowInstallerDetails={(uuid) => {
    // Open a detail panel or modal for the install command
    openDetailsPanel(uuid);
  }}
/>
```

## Notes

- `ui_status` drives optimistic UI transitions (`updating` → `recently_updated` → default) independently of the server-side `status` field.
- The failed-install status path renders an inline `Button` rather than a plain icon, allowing the user to view installer details before retrying.
- A `useRef` mount guard in `InstallerStatusAction` prevents state updates after unmount during async install flows.
