Unit tests for the `getInstallErrorMessage` helper function, validating error message formatting across various software installation failure scenarios in Fleet MDM.

## Key Components

- **`makeErr(reason)`** — Local test factory that constructs a mock API error object with a `base` error entry, matching the shape returned by Fleet's API.
- **`getInstallErrorMessage`** — The function under test (imported from `./helpers`), responsible for mapping raw API error reasons to user-facing install error messages.

## Test Cases

| Scenario | Input Reason | Expected Behavior |
|---|---|---|
| Fleetd conflict | `"host has fleetd installed from another source"` | Contains `"fleetd installed"` |
| macOS-only software | `"software can be installed only on darwin"` | Maps `darwin` → `macOS` |
| MDM turned off | `"MDM is turned off."` | Strips trailing period |
| No available licenses | `"No available licenses."` | Strips trailing period |
| Missing Managed Apple ID | Long Apple ID message | Passes through (strips period) |
| Unresolvable Fleet variable | `"apple_mdm: unresolvable Fleet variable..."` | Returns custom resolution message |
| Unknown error | `"something unexpected"` | Falls back to default message |
| Malformed/empty error | `{}` | Falls back to default message |

## Usage Example

```typescript
import { getInstallErrorMessage } from "./helpers";

const apiError = {
  response: {
    data: {
      errors: [{ name: "base", reason: "MDM is turned off." }],
    },
  },
};

const message = getInstallErrorMessage(apiError);
// → "MDM is turned off"
```
