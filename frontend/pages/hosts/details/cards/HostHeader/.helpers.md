Defines configuration maps for MDM device status UI states, providing tag metadata and tooltip messages for locked, wiped, and pending action states displayed on host detail pages.

## Key Components

### Types

- **`IDeviceStatusTag`** — Interface describing a status tag with a `title`, `tagType` (`"warning"` | `"error"`), and a platform-aware `generateTooltip` function returning a `React.ReactNode`
- **`HostMdmDeviceStatusUIStateNoUnlock`** — Utility type that excludes `"unlocked"` from `HostMdmDeviceStatusUIState`, since no tag is rendered for unlocked hosts
- **`DeviceStatusTagConfig`** — Record type mapping each non-unlocked MDM state to an `IDeviceStatusTag`

### Exports

- **`DEVICE_STATUS_TAGS`** — Configuration map for all renderable device status tags. Covers: `locked`, `locating`, `unlocking`, `locking`, `wiped`, `wiping`, and `clearing_passcode`. The `locked` and `locating` states generate platform-specific tooltip content (iPad/iPhone vs macOS vs default).
- **`REFETCH_TOOLTIP_MESSAGES`** — Static JSX map of tooltip messages shown when a data refetch is blocked, covering all non-unlocked MDM states plus `"offline"`.

## Usage Example

```typescript
import {
  DEVICE_STATUS_TAGS,
  REFETCH_TOOLTIP_MESSAGES,
} from "./helpers";

// Render a status tag for a locked macOS host
const status = "locked";
const tag = DEVICE_STATUS_TAGS[status];

console.log(tag.title);    // "Locked"
console.log(tag.tagType);  // "warning"

const tooltip = tag.generateTooltip("darwin"); // macOS-specific tooltip JSX

// Get refetch tooltip for an offline host
const refetchTooltip = REFETCH_TOOLTIP_MESSAGES["offline"];
```

## Notes

- `locating` (device locked while a location action is pending) intentionally renders identically to `locked` — both show the `"Locked"` title and same tooltip text.
- `locking` also covers the edge case where `device_status` is `"unlocked"` and `pending_action` is `"location"`, as this is part of the locking flow.
