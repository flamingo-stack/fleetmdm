Test suite for the `HostHeader` component, validating rendering behavior, refetch interactions, MDM device status badges, and platform-specific UI logic.

## Key Components

- **`defaultSummaryData`** — Shared fixture with `platform`, `status`, `display_name`, and `detail_updated_at` for reuse across tests
- **`renderActionDropdown`** — Mocked render prop returning a `<div data-testid="dropdown" />`
- **Test suite (`describe("HostHeader")`)** — 12 test cases covering:
  - Display name and last-fetched timestamp rendering
  - `deviceUser` mode showing "My device" and unavailable date
  - Platform-conditional refetch button (hidden on Android)
  - Refetch button disabled state when host is offline
  - Refetch spinner text during active fetch
  - `onRefetchHost` callback invocation
  - Offline tooltip on refetch button hover
  - MDM device status tooltip priority over offline tooltip
  - MDM device status tag/tooltip rendering (e.g. "Locked")
  - Linux wipe status badge cycling (`wiping` → `wiped`)
  - Android MDM badges: `locking`, `wiped`, `wiping` (COBO), `clearing_passcode`

## Usage Example

```typescript
// Run all HostHeader tests
npx jest HostHeader.tests.tsx

// Run a specific test by name
npx jest HostHeader.tests.tsx -t "disables refetch button when host is offline"
```

## Notes

- Uses both `render` (from `@testing-library/react`) and `renderWithSetup` (from `test/test-utils`) — the latter provides a `user` event object for hover/pointer interactions
- `HostMdmDeviceStatusUIState` values are cast explicitly (e.g. `"locked" as HostMdmDeviceStatusUIState`) since tests exercise specific string literals
- COBO Android wipe behavior and `clearing_passcode` badge are explicitly tied to issue [#41683](https://github.com/flamingo-stack/fleetmdm/issues/41683)
