Test suite for the `PolicyDetailsModal` component, verifying rendering behavior across different policy states including content display, empty states, device user messaging, and conditional access controls.

## Key Components

- **`createMockPolicy`** — Factory function that generates a default `IHostPolicy` fixture with optional overrides for test isolation
- **Test: full content rendering** — Verifies policy name, description, and resolution text render correctly together
- **Test: partial content rendering** — Validates that description-only or resolution-only policies render without triggering empty states
- **Test: empty state (admin)** — Confirms the "missing description and resolution instructions" message appears when both fields are absent
- **Test: empty state (device user)** — Checks that the IT admin contact message is included for device users viewing incomplete policies
- **Test: conditional access "Resolve later" button** — Ensures the button only renders for failing (`response: "fail"`) conditional access policies, not passing ones

## Usage Example

```typescript
// Running the full suite
// Jest picks this up automatically via the test file naming convention

// Manually invoking the mock factory with overrides
const policy = createMockPolicy({
  name: "Disk encryption enabled",
  description: "Checks that FileVault is enabled.",
  resolution: "Enable FileVault in System Settings.",
  conditional_access_enabled: true,
  response: "fail",
});
```

## Notes

- Uses `renderWithSetup` from the shared test utilities (`test/test-utils`) for consistent provider wrapping
- Each multi-case scenario calls `unmount()` between renders to avoid cross-test DOM pollution
- `noop` from lodash serves as the `onCancel` stub where callback behavior is not under test
