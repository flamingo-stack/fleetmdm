Test suite for the `User` card component, verifying rendering of IdP user data, permission-gated action buttons, and optional email/profile fields.

## Key Components

| Test Group | Description |
|---|---|
| `IdP data` | Validates rendering of username, full name, groups, department, and write-permission-gated `Add user` / `Edit user` buttons |
| `My device button` | Verifies the "My device" button is hidden by default and shown only when `canViewMyDeviceLink` is true |
| Chrome profiles | Confirms `Google Chrome profiles` field renders when `other_emails` contains `google_chrome_profiles` source entries |
| Other emails | Confirms `Other emails` field renders when `other_emails` contains `custom` source entries |

## Usage Example

```typescript
// Rendering User card with full IdP data and write permission
const endUsers = [createMockHostEndUser()];
render(
  <User
    endUsers={endUsers}
    canWriteEndUser
    onClickUpdateUser={noop}
  />
);

// Rendering with "My device" link enabled
render(
  <User
    endUsers={[]}
    canViewMyDeviceLink
    onClickMyDevice={noop}
    onClickUpdateUser={noop}
  />
);
```

## Key Behaviors Tested

- **No write permission**: Neither `Add user` nor `Edit user` buttons appear, even when an IdP user exists
- **Write permission + no user**: `Add user` button is shown; `Edit user` is absent
- **Write permission + existing user**: `Edit user` button is shown; `Add user` is absent
- **Overflow display**: Groups and email lists truncate to show the first item and a `+ N more` badge
- **Source-based field routing**: `other_emails` entries are split into `Google Chrome profiles` vs `Other emails` based on the `source` field
