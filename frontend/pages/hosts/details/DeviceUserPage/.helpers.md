Utility helpers for the host setup/enrollment flow, providing functions to evaluate setup step statuses, detect failed software installs, and identify the client device platform.

## Key Components

| Export | Description |
|---|---|
| `getErrorMessage` | Formats a generic refetch error message scoped to a host name |
| `hasRemainingSetupSteps` | Returns `true` if any setup step is in `pending` or `running` state |
| `getFailedSoftwareInstall` | Returns the first failed `software_install` or `software_script_run` step, preferring one with an error message |
| `isSoftwareScriptSetup` | Checks if a setup step is a script-only package (`sh_packages` or `ps1_packages`) |
| `isRecentlyEnrolled` | Returns `true` if the host enrolled within the last 10 minutes, suppressing false "offline" banners during initial orbit check-in |
| `isIPhone` / `isIPad` / `isMac` | User-agent helpers for platform detection during OTA enrollment |

## Usage Example

```typescript
import {
  hasRemainingSetupSteps,
  getFailedSoftwareInstall,
  isRecentlyEnrolled,
  isSoftwareScriptSetup,
} from "./helpers";

// Poll until all steps complete
if (hasRemainingSetupSteps(setupStatuses)) {
  scheduleRefetch();
}

// Surface the first actionable failure
const failed = getFailedSoftwareInstall(setupStatuses);
if (failed) {
  showError(failed.error ?? "Installation failed");
}

// Suppress offline banner for freshly enrolled hosts
if (isRecentlyEnrolled(host.last_enrolled_at)) {
  hideOfflineBanner();
}

// Differentiate script-only vs. package installs
if (isSoftwareScriptSetup(step)) {
  renderScriptUI(step);
}
```

## Notes

- `isRecentlyEnrolled` guards against clock skew: a future `lastEnrolledAt` timestamp is never treated as recent (delta must be ≥ 0).
- iPad detection falls back to checking `maxTouchPoints > 1` on `Macintosh` user-agent strings, matching the pattern used in [`enroll-ota.html`](https://github.com/flamingo-stack/fleetmdm/blob/main/templates/enroll-ota.html).
- The 10-minute enrollment threshold (`RECENTLY_ENROLLED_THRESHOLD_MS`) accounts for the delay before a host's first osquery distributed-read check-in.
