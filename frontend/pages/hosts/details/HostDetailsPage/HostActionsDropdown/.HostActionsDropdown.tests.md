Test suite for the `HostActionsDropdown` component, verifying conditional rendering of host action menu items based on user roles, host status, platform, and MDM enrollment state.

## Key Components

- **Transfer action tests** — Validates visibility for global admin, maintainer, and technician roles; confirms team-scoped technicians cannot see the Transfer option
- **Query (Live report) action tests** — Checks that the action renders for online hosts and is disabled (with tooltip) for offline, locked, or updating hosts
- **Show disk encryption key tests** — Confirms the action appears for macOS (Fleet MDM connected), Linux, and Windows hosts with stored keys; hidden for iOS, Android, and macOS devices not connected to Fleet MDM
- **Turn off MDM action tests** — Verifies rendering based on MDM enrollment status (test truncated in source)

## Usage Example

```typescript
// Example: rendering the dropdown in a test with custom context
const render = createCustomRenderer({
  context: {
    app: {
      isPremiumTier: true,
      isGlobalAdmin: true,
      currentUser: createMockUser(),
    },
  },
});

const { user } = render(
  <HostActionsDropdown
    hostTeamId={null}
    onSelect={noop}
    hostStatus="online"
    hostMdmEnrollmentStatus={null}
    hostMdmDeviceStatus="unlocked"
    hostScriptsEnabled
  />
);

await user.click(screen.getByText("Actions"));
expect(screen.getByText("Transfer")).toBeInTheDocument();
```

## Notes

- Uses `createCustomRenderer` from `test/test-utils` to inject app context (tier, role, current user)
- `HostMdmDeviceStatusUIState` is imported but drives prop values like `"unlocked"`, `"locked"`, `"locking"`
- Tooltip assertions use `waitFor` + `user.hover` to handle async rendering
