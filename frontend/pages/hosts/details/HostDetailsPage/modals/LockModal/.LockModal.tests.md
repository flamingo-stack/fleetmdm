Test suite for the `LockModal` component, verifying rendering behavior, platform-specific content, and user interaction across macOS (`darwin`) and iOS/iPadOS platforms.

## Key Components

- **`MOCK_PROPS`** — Shared default props (`id`, `platform`, `hostName`, `onSuccess`, `onClose`) used across all test cases
- **`createCustomRenderer`** — Custom test renderer with backend mock support
- **Test cases:**
  - macOS description and confirm text rendering
  - iOS/iPadOS Lost Mode description, preview card, and lock screen image
  - Wi-Fi disconnection warning visibility (iOS only)
  - Lock button disabled state until confirm checkbox is checked
  - `onClose` callback invocation on Cancel click

## Usage Example

```typescript
// Run tests
npx jest LockModal.tests.tsx

// Run a specific test case
npx jest LockModal.tests.tsx -t "disables Lock button until confirm checkbox is checked"
```

## Test Coverage Summary

| Scenario | Platform | Assertion |
|---|---|---|
| macOS description + unlock PIN notice | `darwin` | Text content present |
| iOS Lost Mode description + preview image | `ios` | Text + `<img>` alt present |
| Wi-Fi warning | `ios` | Warning text present |
| No Wi-Fi warning | `darwin` | Warning text absent |
| Lock button gating | any | Disabled → enabled on checkbox |
| Cancel button | any | `onClose` called |

## Notes

- `jest.resetAllMocks()` runs before each test to prevent mock state bleed between cases
- The Lock button is intentionally **disabled by default** and only enabled after the user checks the confirmation checkbox — tests explicitly assert this gate
- Platform branching (`darwin` vs `ios`) drives both content rendering and warning visibility
