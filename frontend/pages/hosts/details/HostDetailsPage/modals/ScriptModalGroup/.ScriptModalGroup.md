Orchestrates a multi-step modal workflow for host script management, coordinating navigation between five interconnected modals: run, confirm run, script details, run details, and delete.

## Key Components

### `ModalGroupOption` Enum
Defines the five modal states:
- `Run` — script selection table
- `ConfirmRun` — pre-execution confirmation
- `ViewScriptDetails` — script content viewer
- `ViewRunDetails` — execution result details
- `Delete` — script deletion confirmation

### `ScriptModalGroup` Component
Manages shared state and navigation across all child modals:

| State | Purpose |
|---|---|
| `currentModal` / `previousModal` | Tracks active modal and enables back-navigation |
| `selectedScript` | Holds the `IHostScript` selected for action |
| `selectedExecutionId` | Tracks script execution ID for run details |
| `runScriptTablePage` | Pagination for the scripts list |
| `isRunningScript` | Loading state during script execution |

**Queries:**
- `getHostScripts` — paginated list of available scripts for the host
- `downloadScript` — fetches script content (only when `ViewScriptDetails` is active)

**Key handlers:**
- `onConfirmRunScript` — calls `scriptsAPI.runScript`, shows flash notification, refreshes list
- `goBack` — restores `previousModal` as `currentModal`

## Usage Example

```typescript
<ScriptModalGroup
  currentUser={currentUser}
  host={selectedHost}
  onCloseScriptModalGroup={() => setShowScriptModal(false)}
  teamIdForApi={host.team_id ?? undefined}
/>
```

> **Note:** Script metadata and script content require two separate API calls per the [Fleet REST API](https://fleetdm.com/docs/rest-api/rest-api#example-get-script). Script name is passed via props to avoid an extra request.
