Test suite for the `SelectReportModal` component, verifying rendering behavior across different user roles and API response states using MSW for request mocking.

## Key Components

- **`createReportsHandler`** — MSW handler factory that intercepts `GET /reports` and returns a configurable list of report objects
- **`baseProps`** — Shared props fixture (`onCancel`, `hostId`, `hostTeamId`, `router`, `currentTeamId`) used across all test cases
- **`describe("SelectReportModal")`** — Test suite covering five scenarios:
  - Empty state with "Create a report" link (admin user)
  - Empty state without "Create a report" link (observer-only user)
  - Report list rendering when reports exist
  - Description with create link for non-observer users
  - Description without create link for observer-only users

## Usage Example

```typescript
// Run the test suite
npx jest SelectReportModal.tests.tsx

// Adding a new test case
it("renders report with observer_can_run disabled", async () => {
  mockServer.use(
    createReportsHandler([
      { id: 2, name: "Restricted Report", observer_can_run: false },
    ])
  );
  const render = createCustomRenderer({
    withBackendMock: true,
    context: {
      app: {
        isOnlyObserver: true,
        currentUser: createMockUser({ global_role: "observer" }),
      },
    },
  });

  render(<SelectReportModal {...baseProps} isOnlyObserver />);

  await screen.findByText("Restricted Report");
});
```

## Test Patterns

| Scenario | User Role | API Response | Expected UI |
|---|---|---|---|
| Empty, can create | Admin | `[]` | "No saved reports" + "Create a report" link |
| Empty, observer | Observer | `[]` | "No saved reports", no create link |
| Reports exist | Admin | `[{...}]` | Report name + description visible |
| List + create link | Admin | `[{...}]` | "create a report" link present |
| List, observer | Observer | `[{...}]` | No "create a report" link |
