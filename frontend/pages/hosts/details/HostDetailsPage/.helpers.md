Utility helper for generating user-friendly error messages in the context of MDM (Mobile Device Management) host operations.

## Key Components

- **`getErrorMessage(e, hostName)`** — Formats an error into a readable string scoped to a specific host. Attempts to extract a known MDM reason (e.g., `"Host does not have MDM turned on"`) from the error; falls back to a generic `"refetch error."` message if no specific reason is found.

## Usage Example

```typescript
import { getErrorMessage } from "./helpers";

try {
  await refetchHostMDMData(host);
} catch (e) {
  const message = getErrorMessage(e, host.hostname);
  // e.g., 'Host "acme-macbook" Host does not have MDM turned on'
  // or:   'Host "acme-macbook" refetch error.'
  renderFlash("error", message);
}
```

## Notes

- Relies on [`getErrorReason`](https://github.com/flamingo-stack/fleetmdm/blob/main/interfaces/errors.ts) with a `reasonIncludes` filter to match known MDM-specific error strings.
- The fallback message (`"refetch error."`) is intentionally generic to handle unexpected or unrecognized error shapes.
