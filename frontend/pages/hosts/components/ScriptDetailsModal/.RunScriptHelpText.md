Renders contextual help text explaining how to run a script on hosts, with content varying based on user role and script permissions.

## Key Components

### `IRunScriptHelpTextProps`
| Prop | Type | Description |
|------|------|-------------|
| `className` | `string` | Optional CSS class for the wrapper element |
| `isTechnician` | `boolean` | Renders technician-specific instructions when `true` |
| `canRunScripts` | `boolean` | Controls visibility of the policy automation hint |
| `teamId` | `number` | Optional team ID used to scope host/policy page links |

### `RunScriptHelpText`
A display component with three rendering branches:
- **Technician** — links to the Hosts page and instructs using **Actions > Run script**
- **Standard + `canRunScripts`** — links to Hosts page and adds a policy automation tip linking to the Policies page
- **Standard without `canRunScripts`** — shows only the Hosts page link

## Usage Example

```typescript
// Technician view
<RunScriptHelpText
  isTechnician={true}
  canRunScripts={false}
  teamId={42}
/>

// Admin/standard user with script run permissions
<RunScriptHelpText
  className="script-help"
  isTechnician={false}
  canRunScripts={true}
  teamId={42}
/>
```

## Notes

- Team-scoped links are built via `getPathWithQueryParams`, appending `fleet_id` to both `MANAGE_HOSTS` and `MANAGE_POLICIES` paths
- When `teamId` is `undefined`, links fall back to global (unscoped) host and policy pages
