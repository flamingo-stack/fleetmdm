Test suite for the `IssuesIndicator` component, verifying that issue counts render correctly and tooltip details appear on hover.

## Key Components

- **`describe("Issues indicator")`** — Test suite wrapping all `IssuesIndicator` behavioral tests.
- **Hover interaction test** — Simulates a user hovering over the total issues count and asserts that tooltip content for critical vulnerabilities and failing policies becomes visible.

## Usage Example

```typescript
// Run this test with Jest/Vitest alongside the component
renderWithSetup(
  <IssuesIndicator
    totalIssuesCount={5}
    criticalVulnerabilitiesCount={3}
    failingPoliciesCount={2}
  />
);

// Hover triggers tooltip with breakdown details
await user.hover(screen.getByText("5"));
await waitFor(() => {
  expect(screen.getByText(/Critical vulnerabilities/i)).toBeInTheDocument();
  expect(screen.getByText(/Failing policies/i)).toBeInTheDocument();
});
```

## Test Coverage

| Scenario | Assertion |
|---|---|
| Total count displayed | Text `"5"` is rendered and hoverable |
| Tooltip — vulnerabilities | `/Critical vulnerabilities/i` appears in DOM after hover |
| Tooltip — policies | `/Failing policies/i` appears in DOM after hover |

## Notes

- Uses `renderWithSetup` from [`test/test-utils`](https://github.com/flamingo-stack/fleetmdm/blob/main/test/test-utils.ts) for consistent user-event setup.
- `waitFor` ensures tooltip content is asserted only after async DOM updates settle.
- Relies on `@testing-library/react` for querying and interaction simulation.
