Renders and verifies the `IntegrationsPage` component across its major integration sections, ensuring correct sidenav and content rendering based on configuration and license context.

## Key Components

- **`describe("MDM")`** — Verifies MDM sidenav and content render when `isMacMdmEnabledAndConfigured` is `true`
- **`describe("Conditional access")`** — Tests that conditional access is hidden for self-hosted instances (`managed_cloud: false`) and shown for managed cloud instances
- **`describe("SSO")`** — Confirms Single sign-on sidenav and card render correctly when the `sso` section param is active
- **`describe("Host status webhook")`** — Confirms host status webhook sidenav and card render when the `host-status-webhook` section param is active

## Usage Example

```typescript
// Typical test pattern used throughout this file
mockServer.use(createGetConfigHandler());

const render = createCustomRenderer({
  withBackendMock: true,
  context: {
    app: {
      isMacMdmEnabledAndConfigured: true,
      config: createMockConfig(),
    },
  },
});

render(
  <IntegrationsPage
    router={createMockRouter()}
    params={{ section: "mdm" }}
  />
);

expect(
  await screen.findAllByText("Mobile device management (MDM)")
).toHaveLength(1);
```

## Notes

- Uses `createCustomRenderer` and `createMockRouter` from `test/test-utils` for isolated rendering
- `mockServer.use(createGetConfigHandler())` intercepts backend config requests via MSW
- `createMockConfig` with `DEFAULT_LICENSE_MOCK` controls license-gated feature visibility (e.g., `managed_cloud` flag drives conditional access rendering)
- See source: [`flamingo-stack/fleetmdm`](https://github.com/flamingo-stack/fleetmdm/blob/main/frontend/pages/admin/IntegrationsPage/IntegrationPage.tests.tsx)
