Manages the Ticket Destinations settings page, allowing administrators to view, add, and delete Jira and Zendesk integrations for automated ticket creation on vulnerability or policy failures.

## Key Components

- **`TicketDestinations`** — Main page component rendered under the admin integrations settings section
- **`onAddSubmit`** — Handles adding a new Jira or Zendesk integration via `configAPI.update`, with granular error handling for validation failures, duplicate entries, bad credentials, and unknown errors
- **`onDeleteSubmit`** — Removes an existing integration by splicing it from the current list and patching the config
- **`onActionSelection`** — Dispatches row-level table actions (currently only `"delete"`)
- **`renderTable`** — Conditionally renders a loading spinner, error state, or a `TableContainer` with an empty state prompt when no integrations exist
- **`tableHeaders` / `tableData`** — Memoized values derived from `generateTableHeaders` and `combineDataSets` (Jira + Zendesk merged)

## Usage Example

```typescript
// Rendered as a route-level page within admin settings
import TicketDestinations from "./TicketDestinations";

const IntegrationsPage = () => (
  <TicketDestinations />
);
```

```typescript
// Internal add flow — integrationSubmitData is the full updated array,
// integrationDestination is either "jira" or "zendesk"
onAddSubmit(updatedJiraList, "jira");

// Internal delete flow — triggered from table row action
onActionSelection("delete", selectedIntegrationRow);
```

## Error Handling

| API response message | Flash message shown |
|---|---|
| `"Validation Failed"` + duplicate | Integration already exists |
| `"Validation Failed"` (other) | Generic validation error |
| `"Bad request"` | Invalid credentials or URL |
| `"Unknown Error"` | Retry later message |
| Other | Generic retry message |
