Test suite for the `CustomESTForm` component, validating submit button behavior across form validation states, submission state, and dirty state tracking.

## Key Components

- **`createTestFormData`** — Factory helper that generates a default `ICustomESTFormData` object with optional overrides for isolated test scenarios
- **`describe("CustomESTForm")`** — Test suite covering six behavioral cases for the form component

## Test Cases

| Test | Description |
|------|-------------|
| Custom button text | Verifies `submitBtnText` prop renders correctly |
| Valid form enables submit | Submit button is enabled when all required fields are populated |
| Invalid form disables submit | Submit button is disabled when `name` is empty |
| `isSubmitting` disables submit | Submit button is disabled while a submission is in progress |
| `isDirty={false}` disables submit | Submit button is disabled when form has no unsaved changes |
| `isDirty={true}` enables submit | Submit button is enabled when form has unsaved changes |

## Usage Example

```typescript
// Minimal render pattern used throughout the suite
render(
  <CustomESTForm
    formData={createTestFormData({ name: "" })} // override specific fields
    isSubmitting={false}
    submitBtnText="Submit"
    isDirty={true}
    onChange={noop}
    onSubmit={noop}
    onCancel={noop}
  />
);

expect(screen.getByRole("button", { name: "Submit" })).toBeDisabled();
```

## Notes

- Submit button disability is controlled by **three independent gates**: form validity, `isSubmitting`, and `isDirty`
- Uses `@testing-library/react` with role-based queries (`getByRole`) for accessibility-aligned assertions
