Form validation helpers for the Custom EST (Enrollment over Secure Transport) CA configuration form, providing validation logic for name, URL, username, and password fields.

## Key Components

- **`ICustomESTFormValidation`** — Interface describing the validation result shape, with per-field `isValid` flags and optional error messages.
- **`generateFormValidations`** — Factory function that builds the field validation ruleset. Accepts existing integrations and an `isEditing` flag to conditionally enforce uniqueness checks on the `name` field.
- **`validateFormData`** — Runs all validation rules against the provided form data and returns a populated `ICustomESTFormValidation` object, setting `isValid: false` on the root and the failing field when any rule fails.

## Validation Rules

| Field | Rules |
|---|---|
| `name` | Required, alphanumeric + underscores only, unique across `custom_est_proxy` entries (skipped when editing) |
| `url` | Required, must pass `valid_url` check |
| `username` | Required |
| `password` | Required |

## Usage Example

```typescript
import {
  generateFormValidations,
  validateFormData,
} from "./helpers";

const validationConfig = generateFormValidations(
  existingIntegrations, // ICertificateAuthorityPartial[]
  false                 // isEditing
);

const result = validateFormData(
  { name: "my_est", url: "https://est.example.com", username: "admin", password: "secret" },
  validationConfig
);

if (!result.isValid) {
  console.error(result.name?.message); // e.g. "Name is already used by another custom EST CA."
}
```
