Test suite for the `AddCertAuthorityModal` component, verifying rendering behavior, dropdown-driven form switching, and conditional option availability based on existing certificate authority configurations.

## Key Components

- **`AddCertAuthorityModal`** — The component under test; renders a modal for adding certificate authorities
- **`CA_LABEL_BY_TYPE`** — Helper mapping CA type keys to human-readable labels used for assertions
- **`createMockCertificateAuthorityPartial`** — Mock factory for generating test certificate authority data
- **`renderWithSetup`** — Test utility providing a pre-configured `user` event instance for interaction testing

## Test Cases

| Test | Description |
|---|---|
| Default render | Confirms the Custom EST form fields (`Name`, `URL`, `Username`, `Password`) are visible on initial mount |
| Dropdown selection | Simulates selecting `custom_scep_proxy` from the combobox and asserts SCEP-specific fields appear |
| NDES option disabled | Verifies the NDES option is not selectable when an NDES CA already exists in `certAuthorities` |

## Usage Example

```typescript
// Running the test suite
// From the repository root:
// npx jest AddCertAuthorityModal.tests.tsx

// Example: asserting a disabled dropdown option via absence
await user.click(screen.getByRole("combobox"));
expect(
  screen.queryByRole("option", {
    name: CA_LABEL_BY_TYPE.ndes_scep_proxy,
  })
).toBeNull(); // null = option is disabled/hidden
```

## Notes

- Disabled dropdown options are validated by asserting `queryByRole` returns `null`, since Testing Library cannot interact with disabled `<option>` elements
- The modal defaults to the `custom_est_proxy` CA type on first render
