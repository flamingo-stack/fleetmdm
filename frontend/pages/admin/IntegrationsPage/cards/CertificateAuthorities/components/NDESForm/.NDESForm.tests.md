Test suite for the `NDESForm` component, validating rendering behavior, form validation states, submission control, and dirty-state logic.

## Key Components

- **`createTestFormData`** — Factory helper that returns a valid `INDESFormData` object with sensible defaults, accepting partial overrides for targeted test scenarios.
- **`NDESForm` test suite** — Five `describe`/`it` blocks covering the core props and UI states of the NDES configuration form.

## Test Cases

| Test | Description |
|---|---|
| Custom button text | Verifies the submit button renders with the provided `submitBtnText` label |
| Form validation | Clears the SCEP URL field and asserts the submit button toggles from enabled → disabled |
| `isSubmitting` prop | Asserts the submit button is disabled while a submission is in progress |
| `isDirty={false}` | Asserts submit is disabled when the form has no unsaved changes |
| `isDirty={true}` | Asserts submit is enabled when the form has pending changes |

## Usage Example

```typescript
// Minimal render for snapshot/unit testing
render(
  <NDESForm
    formData={createTestFormData({ scepURL: "https://custom.example.com" })}
    isSubmitting={false}
    submitBtnText="Save"
    isDirty
    onChange={noop}
    onSubmit={noop}
    onCancel={noop}
  />
);

// Assert submit is accessible and enabled
expect(screen.getByRole("button", { name: "Save" })).toBeEnabled();
```

## Notes

- Uses `renderWithSetup` (from `test/test-utils`) for tests requiring user interaction simulation (e.g., `user.clear`).
- Standard `render` from `@testing-library/react` is used for static assertion tests.
