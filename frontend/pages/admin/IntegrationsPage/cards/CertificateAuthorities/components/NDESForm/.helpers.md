Validation and error-handling utilities for the NDES (Network Device Enrollment Service) SCEP configuration form.

## Key Components

### Interfaces
- **`INDESFormValidation`** — Validation result shape containing `isValid` flag and per-field validation state (scepURL, adminURL, username, password)

### Functions
- **`validateFormData(formData)`** — Runs all field validations against the provided form data and returns an `INDESFormValidation` result with per-field pass/fail status and messages
- **`getErrorMessage(err, formData)`** — Maps API error reasons to user-friendly error strings, handling NDES-specific failure scenarios

### Internal Constants
- **`FORM_VALIDATIONS`** — Declarative validation rules per field (required check + URL format validation for scepURL/adminURL)
- Error message constants for known NDES failure states (bad credentials, cache full, timeout, insufficient permissions, invalid SCEP URL)

## Usage Example

```typescript
import { validateFormData, getErrorMessage } from "./helpers";

// Validate form before submission
const validation = validateFormData({
  scepURL: "https://ndes.example.com/certsrv/mscep/mscep.dll",
  adminURL: "https://ndes.example.com/certsrv/mscep_admin",
  username: "admin",
  password: "secret",
});

if (!validation.isValid) {
  console.log(validation.scepURL?.message); // "Must be a valid URL."
}

// Map API errors to user-facing messages
try {
  await submitNDESConfig(formData);
} catch (err) {
  const message = getErrorMessage(err, formData);
  // e.g. "Couldn't add. Admin URL or credentials are invalid."
  showError(message);
}
```

> **Note:** There is a known bug in `getErrorMessage` — the `INSUFFICIENT_PERMISSIONS_ERROR` branch is missing a `return` statement, so it always falls through to `DEFAULT_ERROR`.
