Test suite for the `CustomSCEPForm` component, validating submit button state, form validation logic, and challenge field character restrictions.

## Key Components

- **`createTestFormData`** — Factory helper that generates valid `ICustomSCEPFormData` with sensible defaults (`name`, `scepURL`, `challenge`), accepting partial overrides.
- **`CustomSCEPForm` test suite** — Seven focused test cases covering:
  - Custom submit button text rendering
  - Submit enable/disable based on form validity
  - Submit disabled when `isSubmitting` is `true`
  - Submit gated by `isDirty` prop (both `false` and `true` states)
  - Challenge field rejection of non-printable/invalid characters
  - Bypass of challenge validation when editing with an unchanged (masked) API response value

## Usage Example

```typescript
// Run the test suite
npx jest CustomSCEPForm.tests.tsx

// Simulating the factory helper pattern in other tests
const formData = createTestFormData({ name: "My SCEP" });
// → { name: "My SCEP", scepURL: "https://test.com", challenge: "test-challenge" }
```

## Notes

- Uses `renderWithSetup` (from `test/test-utils`) for tests requiring user interaction simulation (e.g., clearing inputs).
- The `UNCHANGED_PASSWORD_API_RESPONSE` constant is used to represent a masked challenge value returned by the API during edit flows — the form must allow submission in this state without triggering the invalid-character error.
- The `isDirty` prop acts as an external dirty-state signal; when explicitly `false`, the submit button is disabled regardless of field validity.
