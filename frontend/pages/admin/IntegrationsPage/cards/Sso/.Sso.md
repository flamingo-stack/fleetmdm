Renders the SSO (Single Sign-On) settings card for the Fleet admin integrations page, providing tabbed configuration for both Fleet user and end-user authentication via SAML identity providers.

## Key Components

- **`ISsoFormData`** — Interface defining form fields: IdP name, entity ID, image URL, metadata, metadata URL, and SSO feature flags
- **`ISsoFormErrors`** — Interface for per-field validation error messages
- **`validate()`** — Pure validation function that enforces required fields and URL format when SSO is enabled
- **`AUTH_TARGETS_BY_INDEX`** — Exported constant mapping tab indices to route subsections (`"fleet-users"` | `"end-users"`)
- **`Sso`** (default export) — Main component rendering a two-tab settings section:
  - **Fleet Users tab** — SAML SSO form with IdP name, entity ID, metadata, JIT provisioning (premium), and GitOps mode awareness
  - **End Users tab** — Delegates to `EndUserAuthSection` for MDM enrollment authentication

## Usage Example

```typescript
// Used as a settings card within the integrations admin page
<Sso
  appConfig={appConfig}
  handleSubmit={async (formData) => {
    const success = await updateAppConfig(formData);
    return success;
  }}
  isPremiumTier={true}
  isUpdatingSettings={false}
  router={router}
  subsection="fleet-users" // or "end-users"
/>
```

**Dirty-state guard:** Switching tabs while the form has unsaved changes triggers a native `confirm()` dialog before discarding edits and resetting both the Fleet SSO and end-user form states to their original values.
