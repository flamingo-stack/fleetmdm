Manages the Conditional Access settings page for integrating Microsoft Entra and Okta identity providers with Fleet's MDM conditional access enforcement.

## Key Components

### `ConditionalAccess` (default export)
Main page component that orchestrates the full conditional access settings UI. Handles:
- Microsoft Entra integration lifecycle via `EntraPhase` state machine
- Okta SAML integration configuration
- Bypass mode toggle for disabling conditional access enforcement
- Premium tier gating via `AppContext`

### `EntraPhase` (enum)
State machine for Microsoft Entra configuration flow:

| Phase | Description |
|---|---|
| `NotConfigured` | No tenant ID present |
| `ConfirmingConfigured` | Polling confirmation API |
| `ConfirmationError` | API call failed |
| `AwaitingOAuth` | Tenant ID saved, waiting for admin OAuth consent |
| `Configured` | Fully connected |
| `ConsentMissing` | Admin did not grant required permissions |

### `DeleteConditionalAccessModal`
Confirmation modal for disconnecting either provider. Calls `conditionalAccessAPI.deleteMicrosoftConditionalAccess()` for Entra or clears Okta fields via `configAPI.update()`.

## Usage Example

```typescript
// Rendered automatically via settings route
// Entra phase transitions are driven by config + useEffect:

useEffect(() => {
  if (entraTenantId && !entraConfigured) {
    setEntraPhase(EntraPhase.ConfirmingConfigured); // triggers useQuery
  } else if (entraTenantId && entraConfigured) {
    setEntraPhase(EntraPhase.Configured);
  } else {
    setEntraPhase(EntraPhase.NotConfigured);
  }
}, [entraTenantId, entraConfigured, entraPhase]);
```

## Notes

- Requires `isPremiumTier` — renders `PremiumFeatureMessage` otherwise
- Microsoft Entra integration is restricted to **managed cloud** deployments (`config.license.managed_cloud`)
- Entra confirmation uses `react-query` with `enabled: entraPhase === EntraPhase.ConfirmingConfigured`
