Storybook stories for the `ConditionalAccess` component, covering all identity provider configuration states and tier access scenarios.

## Key Components

| Export | Description |
|--------|-------------|
| `NotConfigured` | Premium tier with no IdP configured |
| `EntraConfigured` | Microsoft Entra tenant connected and active |
| `OktaConfigured` | Okta SAML IdP configured with ACS URL, audience URI, and certificate |
| `BothConfigured` | Both Microsoft Entra and Okta providers simultaneously configured |
| `FreeTier` | Free tier view demonstrating premium feature gate |

## Usage Example

```typescript
// Run stories in Storybook dev server
// npx storybook dev

// Reference a specific story in tests
import { NotConfigured } from "./ConditionalAccess.stories";

// Each story wraps ConditionalAccess with:
// - QueryClientProvider (React Query, retry disabled)
// - AppContext (isPremiumTier, config, setConfig)
// - NotificationContext (renderFlash, hideFlash mocks)
```

## Notes

- All stories set `isPremiumTier: true` except `FreeTier`, which exercises the premium feature gate with `isPremiumTier: false`.
- A `CustomQueryClientProvider` wrapper resolves a React Query v3 / React 18 type incompatibility (same pattern used in `frontend/router/index.tsx`).
- `conditional_access` config shape covers `microsoft_entra_tenant_id`, `microsoft_entra_connection_configured`, `okta_idp_id`, `okta_assertion_consumer_service_url`, `okta_audience_uri`, and `okta_certificate`.
