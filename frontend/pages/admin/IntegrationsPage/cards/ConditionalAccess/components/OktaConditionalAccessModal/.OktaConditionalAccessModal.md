Modal component for configuring Okta conditional access integration in Fleet MDM, allowing administrators to set up SAML 2.0 IdP settings including IdP ID, assertion consumer service URL, audience URI, and certificate.

## Key Components

### Interfaces
- **`IFormData`** — Form state shape with fields for `okta_idp_id`, `okta_acs_url`, `okta_audience_uri`, and `okta_certificate`
- **`IFormErrors`** — Optional error messages keyed to each form field
- **`IOktaConditionalAccessModalProps`** — Props: `onCancel` callback and `onSuccess(updatedConfig)` callback

### Validation (`validate`)
Client-side validation enforcing:
- Non-empty IdP ID (max 2048 chars)
- Valid HTTP/HTTPS URL for assertion consumer service URL (max 2048 chars)
- Non-empty Audience URI (max 2048 chars)
- Valid PEM certificate content (max 8192 chars)

### `OktaConditionalAccessModal` Component
Main modal component handling:
- **Apple profile fetch** — Loads read-only user scope profile via `conditionalAccessAPI.getIdpAppleProfile`
- **Signing cert download** — Triggers browser download of `fleet-idp-signing-cert.pem` via `conditionalAccessAPI.getIdpSigningCert`
- **Certificate file upload** — Validates `.pem/.crt/.cer/.cert` extensions and PEM format before accepting
- **Form submission** — Calls `configAPI.update` with Okta settings, preserving existing Microsoft Entra config

## Usage Example

```typescript
import OktaConditionalAccessModal from "./OktaConditionalAccessModal";

<OktaConditionalAccessModal
  onCancel={() => setModalVisible(false)}
  onSuccess={(updatedConfig) => {
    setConfig(updatedConfig);
    setModalVisible(false);
  }}
/>
```

## Notes

- Errors are shown **on blur or submit** only; existing errors update live as the user types
- Preserves `microsoft_entra_tenant_id` from existing config on save to avoid overwriting parallel integrations
