Test suite for the `AddEntraClientIDModal` component, validating duplicate client ID detection with case-insensitive comparison before making API calls.

## Key Components

- **`createTestMockData`** — Helper that builds a mock render context with premium tier config, MDM settings, and notification stubs
- **`EXISTING_UPPERCASE_ID`** — Fixture UUID in uppercase simulating a client ID stored via GitOps or the API
- **Duplicate rejection test** — Verifies that submitting a lowercase version of an existing uppercase UUID triggers an error flash and skips the `configAPI.update` call

## Usage Example

```typescript
// Run the test suite
jest.mock("services/entities/config");

describe("AddEntraClientIdModal", () => {
  it("rejects a case-insensitive duplicate without calling the API", async () => {
    const render = createCustomRenderer(mockData);
    const { user } = render(<AddEntraClientIdModal onExit={jest.fn()} />);

    await user.type(input, EXISTING_UPPERCASE_ID.toLowerCase());
    await user.click(screen.getByRole("button", { name: "Add" }));

    expect(renderFlash).toHaveBeenCalledWith("error", "...");
    expect(configAPI.update).not.toHaveBeenCalled();
  });
});
```

## Test Coverage

| Scenario | Expected Behaviour |
|---|---|
| Lowercase duplicate of uppercase stored ID | Error flash shown, API not called |

## Notes

- Uses `createCustomRenderer` for context-aware rendering with app/notification providers
- `configAPI` is fully mocked via `jest.mock` to prevent real network calls
- `afterEach(() => jest.clearAllMocks())` ensures test isolation across the suite
