Unit tests for the `AndroidMdmCard` component, verifying correct UI rendering based on Android MDM enabled/disabled state.

## Key Components

- **`describe("AndroidMdmCard")`** — Test suite covering two conditional rendering states of the card
- **`createCustomRenderer`** — Custom test utility that injects app context, specifically the `isAndroidMdmEnabledAndConfigured` flag
- **Test: MDM turned off** — Asserts "Turn on Android MDM" text and a "Turn on" button are visible
- **Test: MDM turned on** — Asserts "Android MDM turned on." text and an "Edit" button are visible

## Usage Example

```typescript
// Run tests for this component
// From repo root:
// npx jest AndroidMdmCard.tests.tsx

// Example: adding a new test case
import { createCustomRenderer } from "test/test-utils";
import AndroidMdmCard from "./AndroidMdmCard";

test("calls turnOffAndroidMdm when turn off is triggered", () => {
  const mockTurnOff = jest.fn();

  const render = createCustomRenderer({
    context: {
      app: { isAndroidMdmEnabledAndConfigured: true },
    },
  });

  render(
    <AndroidMdmCard
      turnOffAndroidMdm={mockTurnOff}
      editAndroidMdm={noop}
    />
  );

  // Assert callback wiring
  expect(mockTurnOff).not.toHaveBeenCalled();
});
```

## Notes

- Uses `@testing-library/react` for DOM queries — queries are accessibility-role-based (`getByRole`) ensuring semantic correctness
- `noop` from `lodash` is used as a no-op placeholder for required callback props
- Context injection via `createCustomRenderer` mirrors the real app context shape — keep `isAndroidMdmEnabledAndConfigured` in sync with the actual context type
