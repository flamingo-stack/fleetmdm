Unit tests for the `AppleMdmCard` component, verifying rendering across three states: MDM disabled (no APNS info), MDM enabled (with APNS info), and error conditions.

## Key Components

| Test Case | Description |
|---|---|
| `no appleAPNInfo` | Verifies "Turn on Apple MDM" prompt renders when APNS info is absent |
| `with appleAPNInfo` | Verifies "Apple MDM turned on" message renders when APNS info is present |
| `non-404 error state` | Verifies error message renders on 500 errors; 404 is treated as a non-error |

## Usage Example

```typescript
// Run tests for AppleMdmCard
import { render, screen } from "@testing-library/react";
import { noop } from "lodash";
import createMockMdmApple from "__mocks__/appleMdm";
import createMockAxiosError from "__mocks__/axiosError";
import AppleMdmCard from "./AppleMdmCard";

// Simulate disabled MDM state
render(
  <AppleMdmCard
    appleAPNSInfo={undefined}
    errorData={null}
    turnOnAppleMdm={noop}
    viewDetails={noop}
  />
);

// Simulate enabled MDM state
render(
  <AppleMdmCard
    appleAPNSInfo={createMockMdmApple()}
    errorData={null}
    turnOnAppleMdm={noop}
    viewDetails={noop}
  />
);

// Simulate 500 error state
render(
  <AppleMdmCard
    appleAPNSInfo={createMockMdmApple()}
    errorData={createMockAxiosError({ status: 500 })}
    turnOnAppleMdm={noop}
    viewDetails={noop}
  />
);
```

## Notes

- Uses `createMockMdmApple` and `createMockAxiosError` factory helpers for test data isolation
- 404 errors are intentionally excluded from the error UI — only non-404 errors (e.g., 500) trigger the `"Something's gone wrong"` message
- Source: [`AppleMdmCard.tests.tsx`](https://github.com/flamingo-stack/fleetmdm/blob/main/AppleMdmCard.tests.tsx)
