Admin settings page for configuring Windows automatic MDM enrollment via Microsoft Entra, displaying MDM URLs and managing Entra tenant IDs and application client IDs.

## Key Components

- **`WindowsAutomaticEnrollmentPage`** — Default export. Main page component that renders the Microsoft Entra MDM configuration UI.
- **`generateMdmTermsOfUseUrl(domain)`** — Utility that builds the MDM terms of use endpoint URL (`/api/mdm/microsoft/tos`).
- **`generateMdmDiscoveryUrl(domain)`** — Utility that builds the MDM discovery/enrollment endpoint URL (`/api/mdm/microsoft/discovery`).
- **`renderEntraTenants()`** — Internal renderer for the Entra tenant IDs list, with empty state and add/delete controls.
- **`renderEntraClientIds()`** — Internal renderer for the Entra application client IDs list, with empty state and add/delete controls.

**Modals managed:**
- `AddEntraTenantModal` / `DeleteEntraTenantModal`
- `AddEntraClientIDModal` / `DeleteEntraClientIDModal`

## Usage Example

```typescript
// Rendered via the router at the Windows automatic enrollment admin route
import WindowsAutomaticEnrollmentPage from "./WindowsAutomaticEnrollmentPage";

// Router definition (example)
<Route
  path={PATHS.ADMIN_INTEGRATIONS_WINDOWS_AUTOMATIC_ENROLLMENT}
  component={WindowsAutomaticEnrollmentPage}
/>
```

The page reads `config.mdm.windows_entra_tenant_ids` and `config.mdm.windows_entra_client_ids` from `AppContext` to populate the tenant and client ID lists. Adding or deleting entries triggers the corresponding modal. Both lists are wrapped with `GitOpsModeTooltipWrapper` to disable mutation actions when GitOps mode is active.
