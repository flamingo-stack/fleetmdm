Modal component that confirms and executes the disabling of Android MDM integration, handling API calls, cache updates, and navigation on success.

## Key Components

**`TurnOffAndroidMdmModal`** — Default export. A confirmation modal rendered when an admin wants to disable Android Enterprise MDM. Accepts:

| Prop | Type | Description |
|---|---|---|
| `onExit` | `() => void` | Callback to close/dismiss the modal |
| `router` | `InjectedRouter` | Used to redirect after successful deletion |

**Internal State & Side Effects:**

- `isDeleting` — Boolean flag to disable buttons and show a loading spinner during the async API call.
- `onClickConfirm` — Memoized async handler that:
  1. Calls `mdmAndroidAPI.turnOffAndroidMdm()` to delete the Android MDM configuration.
  2. On success, patches the in-memory React Query `["config"]` cache and the `AppContext` config so the parent MDM page reflects the change immediately on redirect (without a refetch).
  3. Flashes a persistent success notification and redirects to `PATHS.ADMIN_INTEGRATIONS_MDM`.
  4. On failure, exits the modal and flashes an error notification.

## Usage Example

```typescript
import TurnOffAndroidMdmModal from "./TurnOffAndroidMdmModal";

const ParentPage = ({ router }) => {
  const [showModal, setShowModal] = useState(false);

  return (
    <>
      <Button onClick={() => setShowModal(true)}>Turn off Android MDM</Button>
      {showModal && (
        <TurnOffAndroidMdmModal
          onExit={() => setShowModal(false)}
          router={router}
        />
      )}
    </>
  );
};
```

## Notes

- The optimistic cache patch (`queryClient.setQueryData`) ensures `android_enabled_and_configured` flips to `false` immediately in the UI without waiting for a background refetch after the redirect.
- The success flash uses `persistOnPageChange: true` so the notification survives the route transition to the MDM integrations page.
