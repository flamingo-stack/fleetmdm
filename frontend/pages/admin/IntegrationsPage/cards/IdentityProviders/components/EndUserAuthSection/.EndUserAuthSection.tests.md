Unit tests for the `EndUserAuthSection` component, validating Save button enable/disable logic and form error clearing behavior based on IdP form data state.

## Key Components

- **`EMPTY_FORM_DATA`** — Fixture representing a blank `IFormDataIdp` object with all fields empty.
- **`FILLED_FORM_DATA`** — Fixture representing a fully populated `IFormDataIdp` object with valid Okta IdP values.
- **`createTestRenderer`** — Factory that builds a custom renderer with premium tier app context and a mock notification flash handler.
- **`renderEndUserAuthSection`** — Helper that renders `EndUserAuthSection` with sensible defaults, accepting prop overrides for targeted test scenarios.

## Test Cases

| Scenario | Expected Behavior |
|---|---|
| All fields cleared, original had values | Save **enabled** (dirty state) |
| Form starts empty and remains empty | Save **disabled** (no change) |
| All required fields filled with valid data | Save **enabled** |
| Required fields only partially filled | Save **disabled** |
| User clears all fields | Form errors cleared, `setFormData` called with `idp_name: ""` |

## Usage Example

```typescript
// Render with custom overrides for a specific test scenario
renderEndUserAuthSection({
  formData: EMPTY_FORM_DATA,
  originalFormData: {
    current: FILLED_FORM_DATA,
  } as MutableRefObject<IFormDataIdp>,
});

expect(screen.getByRole("button", { name: "Save" })).toBeEnabled();
```
