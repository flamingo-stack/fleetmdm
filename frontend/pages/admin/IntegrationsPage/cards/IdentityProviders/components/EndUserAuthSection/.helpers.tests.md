Unit tests for the `IdPSection` helper functions used in Identity Provider (IdP) configuration form management within the Fleet MDM settings UI.

## Key Components

Tests cover four helper functions imported from `./helpers`:

- **`isEmptyFormData`** — Checks whether all IdP form fields are empty strings
- **`isMissingAnyRequiredField`** — Validates that all required fields are populated (note: `metadata` and `metadata_url` satisfy the requirement if at least one is present)
- **`validateFormDataIdp`** — Returns field-level error messages for invalid form state, or `null` for valid/fully-empty forms
- **`newFormDataIdp`** — Constructs a normalized form data object from an `IEndUserAuthentication` config, trimming whitespace and defaulting missing fields to empty strings

## Usage Example

```typescript
import {
  isEmptyFormData,
  isMissingAnyRequiredField,
  validateFormDataIdp,
  newFormDataIdp,
} from "./helpers";

// Check if the form is entirely empty (valid for clearing settings)
isEmptyFormData({ entity_id: "", idp_name: "", metadata: "", metadata_url: "" });
// → true

// Validate form — returns null if valid, or an error map
validateFormDataIdp({
  entity_id: "entityId",
  idp_name: "My IdP",
  metadata: "",
  metadata_url: "https://idp.example.com/metadata",
});
// → null

// Normalize raw config into form shape
newFormDataIdp({
  entity_id: "  entityId  ",
  idp_name: "My IdP",
  issuer_uri: "issuerUri",
  metadata: "metadata",
  metadata_url: "https://idp.example.com/metadata",
});
// → { entity_id: "entityId", idp_name: "My IdP", metadata: "metadata", metadata_url: "https://idp.example.com/metadata" }
```

## Notes

- `validateFormDataIdp` accepts a fully empty form as valid, enabling users to clear saved IdP settings
- URL validation enforces both format correctness and an explicit `https://` or `http://` protocol prefix
- `newFormDataIdp` safely handles `undefined` input, returning a blank form object
