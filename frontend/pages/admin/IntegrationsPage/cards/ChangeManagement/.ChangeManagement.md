Settings page component for configuring GitOps-based change management, allowing admins to enable GitOps mode, set a git repository URL, and define exceptions for labels, software, and secrets.

## Key Components

- **`ChangeManagement`** — Default export; premium-tier-only React component that renders a settings form for GitOps configuration
- **`IChangeManagementFormData`** — Interface defining form state: `gitOpsModeEnabled`, `repoURL`, and three exception flags (`exceptLabels`, `exceptSoftware`, `exceptSecrets`)
- **`IChangeManagementFormErrors`** — Interface for validation error state, scoped to `repository_url`
- **`validate()`** — Pure validation function that enforces a required, protocol-valid URL when GitOps mode is enabled

## Usage Example

```typescript
// Rendered automatically within the admin integrations settings route.
// The component self-fetches config via react-query on mount.

import ChangeManagement from "pages/admin/integrations/ChangeManagement";

const AdminPage = () => (
  <ChangeManagement />
);
```

## Behavior Notes

- **Premium gate:** Non-premium tiers receive a `<PremiumFeatureMessage />` instead of the form
- **Config hydration:** Uses `react-query` (`["integrations"]` key) to call `configAPI.loadAll()` and seed form state from `data.gitops`
- **Validation strategy:** Errors surface on blur or submit; existing errors update live on input change, but new errors are deferred until blur/submit
- **Exceptions:** Three checkboxes let admins opt specific resource types (labels, software, enroll secrets) out of GitOps management
- **Submission:** Calls `configAPI.update()` with the `gitops` payload, then syncs global `AppContext` config and flashes a success/error notification
