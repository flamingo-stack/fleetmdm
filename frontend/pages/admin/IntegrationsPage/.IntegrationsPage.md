Renders the Integrations settings page, managing config loading, section routing, and settings submission for Fleet MDM's integration configuration UI.

## Key Components

### `IntegrationsPage`
Main page component that orchestrates the integrations settings UI. Handles:
- **Section routing** — resolves the active nav section from `params.section`/`params.subsection`, defaulting to `"sso"` when only a subsection is present
- **Config fetching** — uses `react-query` to load the full `IConfig` object via `configAPI.loadAll()`
- **Settings submission** (`onUpdateSettings`) — diffs incoming form updates against current config, skips the API call if unchanged, and patches only the delta via `configAPI.update()`

### `onUpdateSettings`
Shared submission handler passed down to each integration card. Uses `deepDifference` to avoid unnecessary API calls and always forwards `agent_options` in full to prevent partial override issues.

### `SideNav` + `getIntegrationSettingsNavItems`
Renders the side navigation. The active card (`CurrentCard`) is resolved from the nav items list by matching `urlSection` to the current route section.

## Usage Example

```typescript
// Rendered by the router; receives router and params as props
<IntegrationsPage
  router={router}
  params={{ section: "ticket-destinations", subsection: undefined }}
/>
```

```typescript
// onUpdateSettings signature consumed by child cards
handleSubmit={async (formUpdates: DeepPartial<IConfig>) => {
  const success = await onUpdateSettings(formUpdates);
  if (success) { /* navigate or reset form */ }
}}
```

## Notes

- Returns `<></>` early if `appConfig` is not yet available to avoid rendering with stale state
- Shows a `<Spinner />` while `isLoadingAppConfig` or `isFetchingAppConfig` is true
