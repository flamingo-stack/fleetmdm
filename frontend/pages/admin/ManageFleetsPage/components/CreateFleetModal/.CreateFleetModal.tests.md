Test suite for the `CreateFleetModal` component, validating form behavior including button state management, input validation, form submission, and backend error handling.

## Key Components

- **`defaultProps`** — Baseline props including `onCancel`, `onSubmit`, `backendValidators`, and `isUpdatingFleets`
- **`render`** — Custom renderer created via `createCustomRenderer()` for consistent test context
- **Test cases** — Seven behaviorally-focused tests covering the full modal interaction lifecycle

## Test Coverage

| Scenario | Assertion |
|---|---|
| Initial render | "Create" button is disabled |
| Valid name entered | "Create" button becomes enabled |
| Whitespace-only input (spaces) | "Create" button remains disabled |
| Whitespace-only input (tabs) | "Create" button remains disabled |
| Form submission | `onSubmit` called with trimmed name |
| Backend validation errors | Error message rendered in DOM |
| User types after error | Error message cleared |

```typescript
// Example: testing submit with trimmed input
const nameInput = screen.getByLabelText("Fleet name");
await userEvent.type(nameInput, "  Engineering  ");
await userEvent.click(screen.getByRole("button", { name: "Create" }));

expect(defaultProps.onSubmit).toHaveBeenCalledWith({ name: "Engineering" });
```

## Notes

- Whitespace trimming is validated both on button state (disabled for spaces/tabs) and on submission payload
- Backend errors passed via `backendValidators.name` are displayed inline and cleared on user input
- `jest.clearAllMocks()` runs before each test to prevent cross-test contamination
