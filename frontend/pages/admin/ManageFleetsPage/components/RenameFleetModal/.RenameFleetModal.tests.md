Test suite for the `RenameFleetModal` component, validating form behavior including input validation, button state management, and submission handling.

## Key Components

- **`defaultProps`** — Shared mock props including `onCancel`, `onSubmit`, `defaultName`, `backendValidators`, and `isUpdatingFleets`
- **Test cases** — Five focused tests covering modal rendering, save button enable/disable states, and `onSubmit` call behavior

## Test Coverage

| Scenario | Expected Behavior |
|---|---|
| Default name loaded | Save button is enabled |
| Name input cleared | Save button is disabled |
| Whitespace-only input | Save button is disabled |
| Name with surrounding spaces | `onSubmit` called with trimmed value |
| Whitespace-only on submit attempt | `onSubmit` not called |

## Usage Example

```typescript
// Running the test suite
import { createCustomRenderer } from "test/test-utils";
import userEvent from "@testing-library/user-event";
import RenameFleetModal from "./RenameFleetModal";

const render = createCustomRenderer();

// Example: verifying trimmed submission
render(<RenameFleetModal
  onSubmit={jest.fn()}
  onCancel={jest.fn()}
  defaultName="My Fleet"
  backendValidators={{}}
  isUpdatingFleets={false}
/>);

const nameInput = screen.getByLabelText("Fleet name");
await userEvent.type(nameInput, "  Trimmed Name  ");
await userEvent.click(screen.getByRole("button", { name: "Save" }));
// onSubmit called with { name: "Trimmed Name" }
```

## Notes

- Uses `@testing-library/user-event` for realistic DOM interactions
- `jest.clearAllMocks()` runs before each test to prevent state leakage
- Trim validation is enforced at the UI level — the Save button is disabled for whitespace-only input, and `onSubmit` receives a trimmed string
