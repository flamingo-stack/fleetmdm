Renders a checkbox control for enabling or disabling host expiry at the team level, accounting for global host expiry settings and GitOps mode.

## Key Components

### `ITeamHostExpiryToggle` Interface

| Prop | Type | Description |
|------|------|-------------|
| `globalHostExpiryEnabled` | `boolean` | Whether host expiry is enabled globally |
| `globalHostExpiryWindow` | `number?` | Global expiry window in days |
| `teamExpiryEnabled` | `boolean` | Current team-level expiry toggle state |
| `setTeamExpiryEnabled` | `(value: boolean) => void` | Callback to update team expiry state |
| `gitopsModeEnabled` | `boolean?` | Disables the checkbox when GitOps mode is active |

### `TeamHostExpiryToggle` (default export)

A React component wrapping a `Checkbox` that:
- **Disables itself** when `globalHostExpiryEnabled` or `gitopsModeEnabled` is `true`
- **Shows a checked state** even when disabled, if global expiry is active
- **Renders help text** with an "Add custom expiry window" button when global expiry is on but team-level expiry is not yet set
- **Shows a tooltip** explaining host expiry behavior and defaults

## Usage Example

```typescript
<TeamHostExpiryToggle
  globalHostExpiryEnabled={true}
  globalHostExpiryWindow={30}
  teamExpiryEnabled={false}
  setTeamExpiryEnabled={(val) => setFormState({ teamExpiryEnabled: val })}
  gitopsModeEnabled={false}
/>
```

## Behavior Notes

- The checkbox is **read-only** when global expiry is enabled — the user must click "Add custom expiry window" to opt into a team-specific window.
- When `gitopsModeEnabled` is `true`, the checkbox is disabled regardless of other settings, preventing manual edits managed by GitOps.
