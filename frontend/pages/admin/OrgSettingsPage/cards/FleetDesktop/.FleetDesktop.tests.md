Test suite for the `FleetDesktop` settings component, covering rendering behavior, GitOps mode restrictions, form validation, and form submission logic.

## Key Components

- **`FleetDesktop` (component under test)** — Fleet Desktop settings form rendered only for premium tier users
- **`createMockConfig`** — Factory for generating mock app configuration objects with optional overrides
- **`renderWithSetup` / `createMockRouter`** — Test utilities providing user-event setup and router context

## Test Coverage

| Suite | Cases |
|---|---|
| **Rendering** | Hidden for non-premium, visible for premium, pre-populated values, default transparency URL fallback |
| **GitOps Mode** | Inputs disabled when `gitops_mode_enabled: true` |
| **Form Validation** | Invalid/valid transparency URLs, invalid/valid browser hostnames, hostnames with ports, IP addresses |
| **Form Submission** | Correct data shape passed to `handleSubmit`, submit button disabled on validation errors |

## Usage Example

```typescript
// Minimal premium-tier render
renderWithSetup(
  <FleetDesktop
    appConfig={createMockConfig()}
    handleSubmit={jest.fn()}
    isPremiumTier
    isUpdatingSettings={false}
    router={createMockRouter()}
  />
);

// With custom fleet_desktop config
renderWithSetup(
  <FleetDesktop
    appConfig={createMockConfig({
      fleet_desktop: {
        transparency_url: "https://example.com/transparency",
        alternative_browser_host: "fleet.example.com:9809",
      },
    })}
    handleSubmit={jest.fn()}
    isPremiumTier
    isUpdatingSettings={false}
    router={createMockRouter()}
  />
);
```

## Notes

- The component renders `null` when `isPremiumTier={false}`, verified via `container.firstChild`
- Transparency URL validation requires an explicit protocol (e.g., `https://`)
- Browser host field accepts hostnames, hostnames with ports, and IP address/port combinations
- Source: [`flamingo-stack/fleetmdm`](https://github.com/flamingo-stack/fleetmdm)
