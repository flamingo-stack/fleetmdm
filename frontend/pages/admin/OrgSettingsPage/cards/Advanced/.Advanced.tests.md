Integration tests for the `Advanced` settings component, verifying the "Activity & data retention" section UI behavior and form submission logic.

## Key Components

### `renderAdvanced(overrides?)`
A test helper that renders the `Advanced` component with a premium-tier mock config. Accepts optional overrides for:
- `historicalData` — initial `uptime`/`vulnerabilities` toggle states
- `handleSubmit` — custom mock for the form submission handler

## Test Coverage

| Scenario | Description |
|---|---|
| Section rendering | Verifies heading and both checkboxes are present in the DOM |
| Initial state (enabled) | Both checkboxes are checked when collection is enabled |
| Initial state (disabled) | Checkboxes reflect per-field disabled state from config |
| Save without disabling | Submits directly with no confirmation modal shown |
| Disable triggers modal | Unchecking a dataset and saving opens the `"Disable data collection"` modal |
| Modal confirmation | `handleSubmit` is called with the updated payload only after modal confirmation |
| Re-enabling skips modal | Toggling a previously-disabled dataset on saves immediately without a modal |

## Usage Example

```typescript
// Render with default (all enabled) config
const { user, handleSubmit } = renderAdvanced();

// Render with uptime collection disabled
const { user } = renderAdvanced({
  historicalData: { uptime: false, vulnerabilities: true },
});

// Render with a custom submit spy
const handleSubmit = jest.fn().mockResolvedValue(true);
renderAdvanced({ handleSubmit });
```
