Handles user authentication for the Fleet web application, managing both standard credential-based login and SSO (Single Sign-On) flows, along with session initialization and post-login routing.

## Key Components

### `LoginPage` (default export)
The main page component that orchestrates the login experience.

**State & Data:**
- `errors` — Tracks form-level validation/API errors
- `isSubmitting` — Controls submit button loading state
- `pendingEmail` — Flags MFA pending state (anti-scanner protection, see [#26976](https://github.com/flamingo-stack/fleetmdm/issues))
- `ssoSettings` — Fetched via `react-query` from `sessionsAPI.ssoSettings()`

**Key Handlers:**
- `onSubmit` — Authenticates via `sessionsAPI.login()`, saves auth token, sets user/team context, then redirects to dashboard, password reset, or no-access page as appropriate
- `ssoSignOn` — Initiates SSO via `sessionsAPI.initializeSSO()` and redirects to the identity provider URL

**Side Effects:**
- Gravatar availability check on mount (cached in `localStorage`)
- Auto-redirect when a valid session already exists (`currentUser`, `availableTeams`, `config` all present)
- SSO status message flash on redirect back from IdP (reads `?status=` query param)

## Usage Example

```typescript
// Registered as a route in the application router
import LoginPage from "pages/LoginPage/LoginPage";

<Route path={paths.LOGIN} component={LoginPage} />
```

## Notes

- Skips SSO settings fetch if `currentUser` is already present
- MFA pending state (`auth_pending_mfa`) is set in `localStorage` to prevent auto-redemption by email link scanners
- `renderFlash` is intentionally omitted from the `useEffect` dependency array to avoid infinite re-renders
