Centralized route definitions for the Fleet MDM frontend application, exporting a single object of typed URL constants and path-builder functions for all application pages.

## Key Components

**Static Path Constants** — Pre-built URL strings for fixed routes across all major sections:

| Section | Examples |
|---|---|
| Controls | `CONTROLS_OS_UPDATES`, `CONTROLS_DISK_ENCRYPTION`, `CONTROLS_SCRIPTS` |
| Dashboard | `DASHBOARD_MAC`, `DASHBOARD_WINDOWS`, `DASHBOARD_ANDROID` |
| Admin/Settings | `ADMIN_USERS`, `ADMIN_ORGANIZATION`, `ADMIN_INTEGRATIONS_MDM` |
| Software | `SOFTWARE_LIBRARY`, `SOFTWARE_VULNERABILITIES`, `SOFTWARE_OS` |
| Auth/Error | `LOGIN`, `LOGOUT`, `FLEET_403`, `FLEET_404`, `FLEET_500` |

**Dynamic Path Builders** — Functions that accept IDs or tokens and return typed URL strings:

- `HOST_DETAILS(id, teamId?)` — Appends `?fleet_id=` query param when `teamId` is provided
- `CONTROLS_INSTALL_SOFTWARE(platform)` — Accepts `SetupExperiencePlatform` type
- `DEVICE_USER_DETAILS(deviceAuthToken)` — Generates device-scoped routes
- `FLEET_DETAILS_USERS/OPTIONS/SETTINGS(teamId?)` — Falls back to `/settings/fleets` when no valid team ID
- `SOFTWARE_TITLE_DETAILS(id)`, `SOFTWARE_VULNERABILITY_DETAILS(cve)`, `LABEL_EDIT(labelId)`, etc.

## Usage Example

```typescript
import PATHS from "router/paths";

// Static route
navigate(PATHS.MANAGE_HOSTS);

// Dynamic route with required param
navigate(PATHS.HOST_DETAILS(42));

// Dynamic route with optional team scoping
navigate(PATHS.HOST_DETAILS(42, 7));
// → "/settings/hosts/42/details?fleet_id=7"

// Platform-specific setup experience
navigate(PATHS.CONTROLS_INSTALL_SOFTWARE("darwin"));

// Device-scoped user page
navigate(PATHS.DEVICE_USER_DETAILS_SELF_SERVICE(authToken));
```

> **Note:** Any changes to `paths.ts` should be reflected in the companion `page_titles.ts` file to keep route-to-title mappings in sync.
