Entry point for a CLI tool that exports a SQLite software library database into a portable SQL dump file, including schema and data.

## Key Components

| Function | Description |
|---|---|
| `main()` | Parses CLI flags (`-db`, `-output`, `-verbose`) and invokes `run` |
| `run()` | Orchestrates the export: validates paths, opens the DB, and writes schema + data |
| `writeHeader()` | Emits a timestamped SQL file header comment |
| `writeSchema()` | Writes hardcoded `CREATE TABLE` and index DDL for the `software` table |
| `writeSoftwareData()` | Queries all software rows and writes batched `INSERT` statements wrapped in a transaction |
| `writeInsertBatch()` | Flushes a slice of `VALUES` clauses as a single `INSERT` statement |
| `writeFooter()` | Appends a summary comment with row count and timestamp |
| `escapeSQL()` | Single-quote escapes string values for safe SQL embedding |
| `getCurrentTimestamp()` | Returns current UTC time formatted as `YYYY-MM-DD HH:MM:SS UTC` |

## Usage Example

```bash
# Default paths (../../software.db → ../../software.sql)
go run main.go

# Custom paths with verbose progress output
go run main.go -db /data/software.db -output /tmp/dump.sql -verbose

# Recreate the database from the generated dump
sqlite3 software.db < software.sql
```

The tool excludes `linux-image-*` Debian packages from the export and writes inserts in batches of 1,000 rows for efficiency. Verbose mode logs progress every 10,000 rows.

## Notes

- The database is opened read-only (`?mode=ro`) to prevent accidental writes.
- Schema is hardcoded in `writeSchema` rather than read from the live DB, making it the single source of truth.
