Provides SQLite-backed software data loading and mutation utilities for osquery-perf load testing, supporting macOS, Windows, and Ubuntu platforms.

## Key Components

### Types
- **`DB`** — Container holding loaded software slices for all three platforms (`Darwin`, `Windows`, `Ubuntu`)
- **`DarwinSoftware`** / **`WindowsSoftware`** / **`UbuntuSoftware`** — Platform-specific structs representing software entries with fields like `Name`, `Version`, `Source`, optional `Vendor`, `ExtensionID`, and platform-specific fields

### Functions
- **`LoadFromDatabase(dbPath string) (*DB, error)`** — Opens a SQLite database (auto-generating it from `software.sql` if absent) and loads platform-specific software into a `DB`
- **`MaybeMutateSoftware(indices []uint32, maxPoolSize int) []uint32`** — Simulates install/uninstall churn; mutates 20% of the time by randomly adding/removing up to 20 entries
- **`RandomSoftwareCount(platform string) int`** — Returns a random software item count within production-realistic bounds per platform
- **`(*DB).DarwinToMaps`** / **`WindowsToMaps`** / **`UbuntuToMaps`** — Convert indexed software entries to `map[string]string` for osquery result formatting

### Constants
| Constant | Value | Purpose |
|---|---|---|
| `SoftwareMutationProb` | `0.2` | 20% chance of mutation per cycle |
| `MaxSoftwareAdd` | `20` | Max items added per mutation |
| `MaxSoftwareRemove` | `20` | Max items removed per mutation |
| `MaxSoftwarePerPlatform` | `50000` | Load cap per platform |

## Usage Example

```go
db, err := softwaredb.LoadFromDatabase("./software-library/software.db")
if err != nil {
    log.Fatal(err)
}

// Build initial index set for a Darwin host
count := softwaredb.RandomSoftwareCount("darwin") // e.g. 450
indices := make([]uint32, count)
for i := range indices {
    indices[i] = uint32(rand.IntN(len(db.Darwin)))
}

// Simulate software churn each poll cycle
indices = softwaredb.MaybeMutateSoftware(indices, len(db.Darwin))

// Convert to osquery result maps
rows := db.DarwinToMaps(indices)
```

## Notes

- String interning (`vendorPool`, `sourcePool`) reduces memory overhead when many hosts share the same vendor/source strings.
- Platform counts reflect production averages: Ubuntu ~2,460, Darwin ~453, Windows ~251 (±20%).
