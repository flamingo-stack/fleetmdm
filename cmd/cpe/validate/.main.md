Validates vulnerability database artifacts by parsing and integrity-checking CPE translations, Mac Office release notes, MSRC bulletins, and an NVD SQLite database from a specified directory.

## Key Components

| Function | Description |
|---|---|
| `main` | Entry point; accepts `--db_dir` flag and runs all four validation checks |
| `checkCPETranslations` | Parses `cpe_translations.json` using `nvd.LoadCPETranslations` |
| `checkMacOfficeNotes` | Scans for `fleet_macoffice*.json` files and unmarshals each as `macoffice.ReleaseNotes` |
| `checkMSRCVulnerabilities` | Scans for `fleet_msrc*.json` files and parses each via `parsed.UnmarshalBulletin` |
| `checkSqliteDb` | Locates a `*.sqlite.gz` file, decompresses it, opens the resulting DB, and validates the `cpe_2` table |

## Usage Example

```bash
# Run against the default directory (/tmp/vulndbs)
go run main.go

# Run against a custom directory
go run main.go --db_dir /path/to/vulndbs
```

Expected directory layout:

```text
/path/to/vulndbs/
├── cpe_translations.json
├── fleet_macoffice_2024-01.json
├── fleet_msrc_2024-01.json
└── nvd_cve_2024.sqlite.gz
```

Any parse or structural failure causes an immediate `panic` with a descriptive message, making this suitable as a CI sanity-check step for vulnerability database releases.

## Notes

- All checks are fatal on error (`panic`); this tool is intended for pre-release validation pipelines, not production services.
- The SQLite decompression copies in 100 MiB chunks to avoid excessive memory allocation.
- Source: [`flamingo-stack/fleetmdm`](https://github.com/flamingo-stack/fleetmdm)
