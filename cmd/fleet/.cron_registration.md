Registers and wires up all cron schedules for the Fleet server, grouping them by functional domain (cleanup/maintenance, vulnerability processing, worker jobs, MDM, premium features, and miscellaneous).

## Key Components

### `cronSchedulesDeps` struct
Dependency container carrying all runtime dependencies (datastore, services, config, logger, MDM commanders, stores, etc.) needed by cron schedule factories. Acts as a single parameter passed through all registration functions.

### `register(failMsg string, newSchedule func() (fleet.CronSchedule, error))`
Helper method on `cronSchedulesDeps` that calls `StartCronSchedule` and routes any registration error through `initFatal`, eliminating repetitive error-check boilerplate at each registration site.

### `startCronSchedules(ctx, deps)`
Top-level entry point that orchestrates all domain-grouped registration functions and logs the names of all successfully started schedules.

### Domain-grouped registration functions

| Function | Schedules Registered |
|---|---|
| `registerCleanupAndMaintenanceCrons` | Chart data collection, cron_stats cleanup, software migrations, frequent cleanups, query results TTL, cleanups+aggregation, usage statistics, batch activities |
| `registerVulnerabilityCrons` | Vulnerability processing schedule or remote trigger proxy (when disabled on this instance) |
| `registerWorkerCrons` | Automations, worker integrations |
| `registerMDMCrons` | Apple MDM worker, DEP profile assigner, service discovery, Apple/Windows/Android profile managers, Android device reconciler |

### `vulnerabilityProcessingDisabled(cfg)`
Pure helper that returns `true` if vulnerability processing is disabled via `disable_schedule` or instance-check config, used to decide between registering the real schedule vs. a remote trigger proxy.

## Usage Example

```go
deps := cronSchedulesDeps{
    instanceID:    instanceID,
    config:        &fleetConfig,
    license:       licenseInfo,
    logger:        logger,
    cronSchedules: cronSchedules,
    ds:            datastore,
    svc:           fleetService,
    // ... other fields
    initFatal: func(err error, msg string) { initFatal(err, msg) },
}

startCronSchedules(ctx, deps)
```

> **Note:** `registerCleanupAndMaintenanceCrons` includes an OpenFrame-specific extension (`OPENFRAME(query-results-ttl)`) that activates a time-based `query_results` TTL cleanup schedule only when `fleet.IsOpenframeMode()` is true and `Server.QueryResultsTTL > 0`.
