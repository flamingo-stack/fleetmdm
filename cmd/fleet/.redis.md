Initializes and configures the Redis connection pool and datastore wrappers used by the Fleet/OpenFrame server, including host caching and license-enforced host limits.

## Key Components

- **`buildRedisPoolConfig`** — Translates `config.RedisConfig` into a `redis.PoolConfig`, stripping any `redis://` URI scheme prefix for compatibility with managed Redis providers (e.g., Render). Passes through all connection, TLS, and pool settings including the `KeyPrefix` for per-tenant Redis namespace isolation.
- **`validateRedisConfig`** — Validates that host-cache configuration is consistent (requires `HostCacheTTL > 0` when `HostCacheEnabled` is `true`). Designed to be unit-testable without a live Redis connection.
- **`initRedis`** — Wires up the full Redis-backed datastore chain: `mysqlredis → cached_mysql → base datastore`. Handles pool creation, optional host-limit enforcement, and optional host-lookup caching. Returns both the `fleet.Datastore` interface and the concrete `*mysqlredis.Datastore` for callers that need direct access.

## Usage Example

```go
redisPool, wrappedDS, redisDS := initRedis(
    ctx,
    cfg,
    license,
    baseDatastore,
    logger,
    func(err error, msg string) {
        log.Fatalf("%s: %v", msg, err)
    },
)

// redisPool — use for direct cache operations
// wrappedDS  — use as fleet.Datastore throughout the app
// redisDS    — use where *mysqlredis.Datastore is required
```

## Notes

- `initRedis` is safe to call in tests with a non-terminating `initFatal` recorder; all failure paths return `nil` values.
- The `KeyPrefix` field supports multi-tenant Redis namespacing per the OpenFrame Redis key-prefix design (`openframe/docs/redis-key-prefix.md`).
- Host-limit enforcement is only applied when `license.DeviceCount > 0` and `cfg.License.EnforceHostLimit` is `true`.
