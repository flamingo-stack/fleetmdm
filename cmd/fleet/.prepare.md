Defines the `prepare` CLI subcommand for initializing and migrating Fleet's MySQL database schema, including OpenFrame-specific multitenancy and host-assignment migrations.

## Key Components

- **`createPrepareCmd`** — Builds the root `prepare` cobra command and registers the `db` subcommand. Accepts a `config.Manager` to load runtime configuration.
- **`dbCmd`** — The `prepare db` subcommand that drives the full migration lifecycle:
  - Acquires an advisory MySQL lock (`AcquireOpenframeMigrationLock`) when running under OpenFrame multitenancy to prevent concurrent DDL races.
  - Checks and repairs mis-numbered v4.73.2 migrations via `FixFleetv4732Migrations`.
  - Runs `MigrateTables`, `MigrateData`, and `MigrateOpenframe` (OpenFrame host-assignment tables) in sequence.
  - Optionally prints table row counts after migration (`--with-table-stats`).
- **`printUnknownMigrationsMessage`** / **`printMissingMigrationsPrompt`** — User-facing warnings for unrecognized or missing migrations.
- **`printFleetv4732FixMessage`** / **`printFleetv4732UnknownStateMessage`** — Warnings specific to the v4.73.2 migration numbering bug.
- **`tablesAndDataToString`** — Formats table and data migration ID slices into a readable string for warning output.

## Usage Example

```bash
# Run database migrations non-interactively (e.g., in a Kubernetes Job)
fleet prepare db --no-prompt

# Run with developer mode and post-migration table stats
fleet prepare db --dev --with-table-stats
```

```go
// Registering the command in main
rootCmd.AddCommand(createPrepareCmd(configManager))
```

## Flags

| Flag | Default | Description |
|---|---|---|
| `--no-prompt` | `false` | Skip interactive confirmation before migrating |
| `--dev` | `false` | Enable developer mode (applies dev DB flags, disables prompts) |
| `--with-table-stats` | `false` | Print approximate row counts per table after migration |

> **OpenFrame note:** When `fleet.IsOpenframeMultitenancy()` is true, `prepare db` serializes concurrent migration runs using a named MySQL advisory lock with a 15-minute timeout, preventing DDL races on the shared `hosts` table across clusters.
