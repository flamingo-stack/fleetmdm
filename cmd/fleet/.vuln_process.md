Standalone CLI command that runs Fleet's vulnerability processing pipeline as an externally-managed process, intended for deployments where the built-in scheduled cron (`vulnerabilities.disable_schedule=true`) is disabled.

## Key Components

### `createVulnProcessingCmd`
Builds the `vuln_processing` Cobra subcommand. On execution it:
1. Loads config and initializes the logger and license.
2. Connects to MySQL and validates that all database migrations are complete.
3. Acquires a distributed lock (shared name with the internal cron job to prevent double-execution) scoped to `--lock_duration`.
4. Resolves the vulnerability databases path via `configureVulnPath`.
5. Runs each `NamedVulnFunc` in sequence, returning a non-zero exit code on any failure.

### `configureVulnPath`
Resolves the vulnerability databases path with explicit precedence:
1. Fleet server config (`vulnConfig.DatabasesPath`) wins when both sources are set.
2. Falls back to app config (`appConfig.VulnerabilitySettings.DatabasesPath`).
3. Logs a warning if neither is configured.

### `NamedVulnFunc`
A named wrapper around a `func(ctx context.Context) error` used to structure the sequential processing pipeline.

### `getVulnFuncs`
Returns the ordered slice of vulnerability processing steps:

| Name | Action |
|---|---|
| `update_os_versions` | Refreshes aggregated OS version stats |
| `cron_vulnerabilities` | Core CVE scan |
| `cron_sync_host_software` | Syncs host↔software records |
| `cron_cleanup_software_titles` | Prunes stale software titles |
| `cron_sync_hosts_software_titles` | Syncs host↔software title mappings |
| `update_host_issues_vulnerabilities_counts` | Updates per-host issue counts |
| `insert_kernel_software_mapping` | Maps kernel versions to software entries |

## Usage Example

```bash
# Run with defaults (60-minute lock, production config)
fleet vuln_processing

# External cron with a tighter lock window
fleet vuln_processing --lock_duration 30m

# Development mode with a test license
fleet vuln_processing --dev --dev_license
```

```go
// Registering the command in main
rootCmd.AddCommand(createVulnProcessingCmd(configManager))
```

> **Note:** Set `FLEET_VULNERABILITIES_DISABLE_SCHEDULE=true` (or `vulnerabilities.disable_schedule: true` in config) before using this command to prevent the Fleet server from racing against the external job.
