Initializes and configures the Fleet mail service at application startup, handling mutual exclusivity between SMTP and alternative email backends.

## Key Components

- **`shouldForceSMTPBackend(appCfg, emailBackend)`** — Returns `true` when SMTP is already enabled in the app config and a competing email backend is also configured, signaling that SMTP should take precedence.
- **`initMailService(ctx, cfg, appCfg, logger)`** — Constructs the `fleet.MailService` instance. If SMTP conflicts with a configured backend, it clears the backend and emits a warning. Failures during construction are logged but do not abort startup (best-effort initialization).

## Usage Example

```go
mailService := initMailService(ctx, fleetConfig, appConfig, logger)
if mailService == nil {
    // mail is unavailable but server continues
}
```

## Behavior Notes

- SMTP and a custom `EmailBackend` are mutually exclusive; an active SMTP configuration always wins.
- Construction errors are non-fatal — the returned `fleet.MailService` may be `nil` if `mail.NewService` fails.
