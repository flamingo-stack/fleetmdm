Orchestrates all background cron schedules for the Fleet MDM server, including vulnerability scanning, MDM sync, policy enforcement, and webhook automation.

## Key Components

- **`newVulnerabilitiesSchedule`** — Creates a recurring schedule for vulnerability scanning using configurable periodicity and per-phase jobs.
- **`cronVulnerabilities`** — Entry point for the vulnerability cron; checks app config, resolves the vuln path, and delegates to `scanVulnerabilities`.
- **`scanVulnerabilities`** — Runs all vulnerability scanner phases sequentially: NVD, OVAL, OSV, RHEL-OSV, Goval Dictionary, Mac Office, Win Office, custom CVEs, and Windows MSRC. Cleans up orphaned records after scanning.
- **`updateVulnHostCounts`** — Updates per-vulnerability host counts with configurable concurrency after scanning completes.
- **`errHandler`** — Shared error logging helper that logs via `slog` and routes errors through `ctxerr`.

## Usage Example

```go
// Create and start the vulnerabilities schedule
vulnSchedule, err := newVulnerabilitiesSchedule(
    ctx,
    instanceID,
    ds,
    logger,
    &config.VulnerabilitiesConfig{
        Periodicity:    1 * time.Hour,
        MaxConcurrency: 4,
    },
)
if err != nil {
    log.Fatal(err)
}
vulnSchedule.Start()
```

## Automation Dispatch

After scanning, if a vuln automation is configured (mutually exclusive), recent vulnerabilities are dispatched via:

| Automation | Mechanism |
|---|---|
| `webhook` | `webhooks.TriggerVulnerabilitiesWebhook` |
| `jira` | `worker.QueueJiraVulnJobs` |
| `zendesk` | `worker.QueueZendeskVulnJobs` |

Premium licenses use `utils.RecentVulns` with CVE metadata to filter to only newly observed CVEs within the configured `RecentVulnerabilityMaxAge` window.
