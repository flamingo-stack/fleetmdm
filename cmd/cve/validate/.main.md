Entry point for a vulnerability database integration test tool that validates NVD (National Vulnerability Database) feed data and Goval Dictionary databases to ensure enrichment, CVSS scoring, and data integrity are correct.

## Key Components

- **`main`** — Parses CLI flags (`-db_dir`, `-debug`), configures structured JSON logging, and orchestrates both check functions.
- **`checkNVDVulnerabilities`** — Loads NVD JSON feed files and runs spot-checks against specific CVEs to verify:
  - VulnCheck enrichment populated CPE configuration nodes (CVE-2025-0938, CVE-2024-6286)
  - Correct `versionEndExcluding` values for Citrix LTSR entries (CVE-2024-6286)
  - Primary and secondary CVSSv3 score extraction (CVE-2025-3196, CVE-2024-54559, CVE-2024-0450, CVE-2024-0540)
  - Product name normalization (`docker_desktop` → `desktop`, CVE-2023-0626)
- **`checkGovalDictionaryVulnerabilities`** — Iterates all `oval.SupportedGovalPlatforms`, temporarily renames Goval SQLite files to match Fleet's expected naming convention, loads each database, runs `Verify()`, and restores the original filename.
- **`platformFromString`** — Converts a `"host_version"` string (e.g., `"amzn_2"`) into an `oval.Platform` struct.

## Usage Example

```bash
# Run against a local vulnerability database directory
go run main.go -db_dir /tmp/vulndbs

# Enable debug logging
go run main.go -db_dir /tmp/vulndbs -debug
```

```go
// The tool expects NVD feed files in the target directory, e.g.:
// /tmp/vulndbs/nvdcve-1.1-2025.json.gz
// /tmp/vulndbs/nvdcve-1.1-2024.json.gz
// /tmp/vulndbs/nvdcve-1.1-2023.json.gz
// /tmp/vulndbs/amzn_2.sqlite3  (Goval Dictionary databases)
```

> This tool is intended for CI pipeline validation of vulnerability database releases. Any failed spot-check panics with a descriptive error, causing the pipeline to fail fast.
