Implements the `fleetctl login` command, handling interactive and flag/environment-based authentication against a Fleet server, then persisting the resulting token to the CLI config.

## Key Components

- **`loginCommand()`** — Returns a `*cli.Command` configured with `--email` and `--password` flags (also readable from `EMAIL`/`PASSWORD` env vars), plus shared `--config`, `--context`, and `--debug` flags.
- **SSO detection** — Calls `fleet.SSOSettings()` before attempting login; prints a warning to stderr if SSO is enabled on the server.
- **Interactive prompts** — Falls back to `fmt.Scanln` for email and `terminal.ReadPassword` for password when values are not supplied, avoiding credentials in shell history.
- **`definedAsEnvOnly()`** — Helper that distinguishes env-var-supplied values from CLI-flag-supplied values to show an informational message when the env var is used.
- **Token persistence** — After a successful `fleet.Login()` call, writes `email` and `token` into the active config context via `setConfigValue`.

## Usage Example

```bash
# Interactive prompts for both email and password
fleetctl login

# Non-interactive via flags (password in history — not recommended)
fleetctl login --email admin@example.com --password hunter2

# Non-interactive via environment variables
EMAIL=admin@example.com PASSWORD=hunter2 fleetctl login

# Target a specific config context
fleetctl login --config ~/.fleet/config --context staging
```

> **SSO note:** If the Fleet server has SSO enabled, a warning is printed but credential-based login is still attempted. Accounts with SSO enforced must use the token flow described at [fleetctl SSO docs](https://fleetdm.com/guides/fleetctl#users-with-single-sign-on-sso-or-email-two-factor-authentication-2-fa).
