Implements the `fleetctl setup` CLI command, which performs initial configuration of a Fleet instance by creating an admin user and organization, then persisting the authentication token to the local config.

## Key Components

- **`setupCommand()`** — Returns a `*cli.Command` that registers the `setup` subcommand with the following flags:
  - `--email` / `EMAIL` — Admin user email (required)
  - `--name` / `NAME` — Admin user display name (required)
  - `--password` / `PASSWORD` — Admin password (optional flag; falls back to interactive prompt)
  - `--org-name` / `ORG_NAME` — Organization name (required)

## Behavior

1. Creates an unauthenticated Fleet API client via `unauthenticatedClientFromCLI`.
2. If `--password` is omitted, prompts for password and confirmation via `terminal.ReadPassword` (secure, no echo).
3. Calls `fleet.Setup(...)` to provision the admin account; handles `service.SetupAlreadyErr` as a distinct error case.
4. Persists `email` and `token` into the active `fleetctl` config context using `setConfigValue`.

## Usage Example

```bash
# Interactive password entry (recommended)
fleetctl setup \
  --email admin@example.com \
  --name "Fleet Admin" \
  --org-name "Acme Corp"

# Non-interactive (e.g., CI pipelines)
EMAIL=admin@example.com \
NAME="Fleet Admin" \
PASSWORD=supersecret \
ORG_NAME="Acme Corp" \
fleetctl setup
```

> **Note:** Using `--password` or the `PASSWORD` environment variable is discouraged in interactive sessions since the value may be recorded in shell history. Prefer the secure prompt.
