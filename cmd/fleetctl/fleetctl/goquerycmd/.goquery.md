Brief description: Implements the `fleetctl goquery` interactive REPL by bridging the [AbGuthrie/goquery](https://github.com/AbGuthrie/goquery) library to the Fleet API, isolated in its own package to prevent init-time side effects from leaking into other binaries.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `goqueryClient` | struct | Adapts Fleet's `service.Client` to the goquery host/query interface; tracks in-flight queries and UUID-to-hostname mappings |
| `newGoqueryClient` | constructor | Initializes a `goqueryClient` wrapping a Fleet API client |
| `CheckHost` | method | Resolves a host by UUID, hostname, or computer name via Fleet's `SearchTargets` API |
| `ScheduleQuery` | method | Submits a live query to Fleet and asynchronously collects results into the internal query map |
| `FetchResults` | method | Returns the status and rows of a previously scheduled query by name |
| `Run` | func | Entry point — starts the interactive goquery REPL; registered with `fleetctl` via `fleetctl.SetGoqueryRunner` |

## Usage Example

```go
// In the fleetctl binary's main package:
import (
    "github.com/flamingo-stack/fleetmdm/server/service"
    "github.com/flamingo-stack/fleetmdm/fleetctl/goquerycmd"
)

fleetClient, _ := service.NewClient(serverURL, true, "", "")

if err := goquerycmd.Run(fleetClient); err != nil {
    log.Fatal(err)
}
```

## Notes

- **Isolation**: The `github.com/AbGuthrie/goquery/v2` dependency and its init-time side effects are confined to this sub-package, keeping the Fleet server binary unaffected.
- **Async results**: `ScheduleQuery` spawns a goroutine to receive from the live query result/error channels, satisfying goquery's expectation that scheduling and result retrieval are separate operations.
- **UUID ↔ hostname mapping**: goquery identifies hosts by UUID; Fleet live queries target by hostname. The `hostnameByUUID` map bridges this gap inside `CheckHost` and `ScheduleQuery`.
