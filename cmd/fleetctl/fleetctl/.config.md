Manages the `fleetctl` CLI configuration file, providing read/write access to named contexts that store Fleet server connection settings (address, credentials, TLS options, and custom headers).

## Key Components

- **`configFile`** — Top-level struct representing the YAML config file, holding a map of named `Context` entries
- **`Context`** — Per-context connection settings: `Address`, `Email`, `Token`, `TLSSkipVerify`, `RootCA`, `URLPrefix`, and `CustomHeaders`
- **`configFlag()` / `contextFlag()`** — Reusable `cli.Flag` definitions for `--config` (default: `~/.fleet/config`) and `--context` (default: `"default"`)
- **`readConfig` / `writeConfig`** — YAML marshal/unmarshal helpers for the config file (permissions: `0600`)
- **`getConfigValue` / `setConfigValue`** — Key-based accessors that auto-create the config file and context if missing
- **`configSetCommand`** — `fleetctl config set` subcommand; sets one or more context values via flags or env vars
- **`configGetCommand`** — `fleetctl config get` subcommand; prints a single context value by key name

## Usage Example

```bash
# Set the Fleet server address and API token in the default context
fleetctl config set --address https://fleet.example.com --token abc123

# Use a named context
fleetctl config set --context staging --address https://staging.fleet.example.com

# Retrieve a value
fleetctl config get address
# Output:  default.address => https://fleet.example.com

# Set custom headers
fleetctl config set --custom-header "X-Tenant-ID:acme" --custom-header "X-Feature:beta"

# Skip TLS verification (not recommended for production)
fleetctl config set --tls-skip-verify
```

The config file is stored at `~/.fleet/config` by default and can be overridden via `--config` or the `CONFIG` environment variable.
