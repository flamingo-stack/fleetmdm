Implements the `gitops` CLI command for Fleet's GitOps workflow, parsing and applying one or more YAML configuration files to manage global and team-level Fleet settings, software, labels, policies, and controls — with support for dry runs, concurrent icon uploads, and soft exceptions for software/labels.

## Key Components

- **`gitopsCommand()`** — Returns the `*cli.Command` definition registered under `fleetctl gitops`, wiring all flags and the main `Action` handler.
- **`LabelUsage`** — Struct tracking a label's name and type for validation/conflict detection.
- **`ConfigFile`** (referenced inline) — Holds a parsed `*spec.GitOps` config, its source filename, and a global-config flag.
- **`filenameMaxLength`** — Constant (255) enforcing a max length on provided filenames.
- **`ReapplyingTeamForVPPAppsMsg`** — Formatted log message emitted when a team config is re-applied to set VPP apps.

### Flags

| Flag | Env Var | Description |
|---|---|---|
| `-f` | `FILENAME` | GitOps YAML file(s) to apply (required, repeatable) |
| `--dry-run` | `DRY_RUN` | Validate only, no writes |
| `--delete-other-fleets` | `DELETE_OTHER_FLEETS` | Delete teams absent from config |
| `--allow-unknown-keys` | `ALLOW_UNKNOWN_KEYS` | Warn instead of error on unknown keys |
| `--icons-concurrent-uploads` | `ICONS_CONCURRENT_UPLOADS` | Parallel icon upload limit (default 4) |
| `--icons-concurrent-updates` | `ICONS_CONCURRENT_UPDATES` | Parallel icon update limit (default 10) |

## Usage Example

```bash
# Dry-run validation against multiple config files
fleetctl gitops --dry-run \
  -f global.yml \
  -f teams/engineering.yml \
  -f teams/unassigned.yml

# Apply configs and remove teams not in config
fleetctl gitops \
  -f global.yml \
  -f teams/engineering.yml \
  --delete-other-fleets
```
