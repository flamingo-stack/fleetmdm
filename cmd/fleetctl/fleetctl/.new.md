Scaffolds a new Fleet GitOps repository structure by rendering embedded templates with organization-specific variables via the `fleetctl new` CLI command.

## Key Components

- **`newTemplateFS`** — Embedded filesystem containing template files from `templates/new`, bundled at compile time via `//go:embed`.
- **`renderTemplate(content, vars)`** — Renders a template using `<%= %>` delimiters, substituting provided variables into template content.
- **`printNextSteps(w, outputDir)`** — Writes post-scaffolding instructions to the output writer, guiding users through repository setup, GitOps user creation, and secret configuration.
- **`newCommand()`** — Returns the `fleetctl new` CLI command with flags for `--org-name`, `--dir` (default: `it-and-security`), and `--force`.

## Usage Example

```bash
# Interactive: prompts for organization name
fleetctl new --dir my-fleet-repo

# Non-interactive: specify org name directly
fleetctl new --org-name "Acme Corp" --dir my-fleet-repo

# Write into an existing directory
fleetctl new --org-name "Acme Corp" --dir my-fleet-repo --force
```

```go
// Registered in the fleetctl CLI app
app.Commands = append(app.Commands, newCommand())
```

## Behavior Notes

- Prevents overwriting an existing directory unless `--force` is passed.
- Organization name is validated (non-empty, ≤ 255 characters, control characters stripped).
- The org name is YAML-marshaled before template injection to ensure safe scalar escaping.
- Template files named with `.template.` in their extension (e.g., `foo.template.yml`) are written with that segment stripped (e.g., `foo.yml`).
- After scaffolding, `printNextSteps` guides the user to push the directory to GitHub/GitLab and configure `FLEET_URL` and `FLEET_API_TOKEN` secrets.
