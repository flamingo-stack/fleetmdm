Anti-corruption layer adapter that translates between the `activity` bounded context and legacy Fleet types, ensuring the activity package remains decoupled from Fleet internals.

## Key Components

| Symbol | Kind | Description |
|---|---|---|
| `UsersByIDsLookup` | Interface | Minimal datastore interface for direct user lookup by ID, bypassing service-layer authz |
| `FleetServiceAdapter` | Struct | Implements `activity.UserProvider`, `activity.HostProvider`, `activity.AppConfigProvider`, and `activity.UpcomingActivityActivator` using Fleet service/datastore |
| `NewFleetServiceAdapter` | Constructor | Creates an adapter wiring both `fleet.ActivityLookupService` and a direct `UsersByIDsLookup` datastore |
| `UsersByIDs` | Method | Fetches and converts `fleet.UserSummary` → `activity.User`, bypassing service authz (host authz already applied upstream) |
| `FindUserIDs` | Method | Searches users by name/email prefix via `fleet.ActivityLookupService.ListUsers` |
| `GetHostLite` | Method | Returns minimal `activity.Host` (ID + TeamID) for authorization checks |
| `GetActivitiesWebhookConfig` | Method | Translates Fleet webhook settings into `activity.ActivitiesWebhookSettings` |
| `ActivateNextUpcomingActivity` | Method | Delegates queue activation to the Fleet service |
| `convertUser` | Function (private) | Maps `*fleet.UserSummary` fields to `*activity.User` |

## Usage Example

```go
// Wire up the adapter at the composition root
adapter := activityacl.NewFleetServiceAdapter(
    fleetSvc,       // fleet.ActivityLookupService
    datastoreLayer, // UsersByIDsLookup (direct DS, no authz)
)

// Pass the adapter to the activity service as its providers
activitySvc := activitysvc.New(adapter, adapter, adapter, adapter)

// The activity service can now resolve users without re-authorizing
users, err := adapter.UsersByIDs(ctx, []uint{1, 2, 3})

// Or look up a host for team-scoped authorization
host, err := adapter.GetHostLite(ctx, hostID)
```

## Design Notes

- `UsersByIDs` uses a **direct datastore call** (not the Fleet service) to avoid a double-authz bug ([#46009](https://github.com/flamingo-stack/fleetmdm/issues)) where team-scoped viewers were incorrectly rejected on host activity lists.
- Compile-time interface assertions (`var _ activity.X = (*FleetServiceAdapter)(nil)`) catch drift between the adapter and the interfaces it satisfies.
- This file is the **sole import boundary** between `activity` and `fleet` types; all other packages in the activity context depend only on `activity`-owned interfaces.
