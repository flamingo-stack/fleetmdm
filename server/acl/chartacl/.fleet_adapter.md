Anti-corruption layer adapter that translates Fleet's viewer context into the minimal team-scope information required by the chart bounded context.

## Key Components

| Symbol | Kind | Description |
|---|---|---|
| `FleetViewerAdapter` | struct | Stateless adapter implementing `api.ViewerProvider`; bridges Fleet's viewer context to chart service scope resolution |
| `NewFleetViewerAdapter()` | constructor | Returns a `*FleetViewerAdapter` for injection into `chart/bootstrap.New` |
| `ViewerScope(ctx)` | method | Reads the authenticated user from context and returns global access flag or team ID list |

## Usage Example

```go
import (
    "github.com/flamingo-stack/fleetmdm/server/chart/bootstrap"
    "github.com/flamingo-stack/fleetmdm/server/chart/chartacl"
)

// Wire the adapter at application startup.
adapter := chartacl.NewFleetViewerAdapter()

svc, err := bootstrap.New(bootstrap.Config{
    ViewerProvider: adapter,
    // ...other config
})
```

At request time, `ViewerScope` resolves to one of three outcomes:

```go
isGlobal, teamIDs, err := adapter.ViewerScope(ctx)
// err != nil   → no authenticated viewer; reject the request
// isGlobal     → user holds a global role; unrestricted data access
// !isGlobal    → teamIDs contains the teams the user may query
```

## Notes

- This package is the **sole** location permitted to import both `chart` types and `server/contexts/viewer`; the architecture test enforces this boundary.
- `FleetViewerAdapter` carries no state and has no Fleet service dependency — the viewer context is its only input, keeping it trivially testable.
- An absent or `nil` viewer always returns an error; chart endpoints sit behind authenticated middleware so this state indicates a misconfigured request pipeline.
