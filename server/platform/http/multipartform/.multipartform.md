Provides a helper for parsing `multipart/form-data` request bodies with built-in field migration, handling the deprecation of `team_id` in favor of `fleet_id`.

## Key Components

- **`Parse(ctx, r, maxMemory)`** — Parses the multipart form on the incoming HTTP request and transparently migrates any `team_id` field to `fleet_id`, emitting a structured deprecation warning via the logging context when the deprecated topic is enabled.

## Usage Example

```go
import "github.com/flamingo-stack/fleetmdm/server/multipartform"

func handleUpload(ctx context.Context, w http.ResponseWriter, r *http.Request) error {
    const maxMemory = 32 << 20 // 32 MB

    if err := multipartform.Parse(ctx, r, maxMemory); err != nil {
        return err
    }

    // Access fields — callers use "fleet_id" regardless of whether
    // the client submitted "team_id" or "fleet_id".
    fleetID := r.FormValue("fleet_id")
    _ = fleetID
    return nil
}
```

## Notes

- The migration is transparent to downstream handlers: `team_id` is removed from both `r.Form` and `r.MultipartForm.Value` before returning.
- Deprecation warnings are only logged when `platform_logging.DeprecatedFieldTopic` is enabled, keeping noise low in production.
- Lives in its own subpackage to avoid import cycles between `server/contexts/logging` and `server/platform/http`.
