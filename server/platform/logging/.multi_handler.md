A `slog.Handler` implementation that fans out log records to multiple handlers simultaneously, enabling log output to be sent to several destinations in parallel.

## Key Components

| Symbol | Description |
|---|---|
| `MultiHandler` | Struct holding a slice of `slog.Handler` instances |
| `NewMultiHandler` | Constructor accepting variadic `slog.Handler` arguments |
| `Enabled` | Returns `true` if **any** handler accepts the given log level |
| `Handle` | Dispatches a cloned record to all enabled handlers; collects errors via `errors.Join` |
| `WithAttrs` | Returns a new `MultiHandler` with attributes propagated to all child handlers |
| `WithGroup` | Returns a new `MultiHandler` with the group name propagated to all child handlers |

## Usage Example

```go
// Fan out logs to both stdout (text) and a JSON file handler
textHandler := slog.NewTextHandler(os.Stdout, nil)
fileWriter, _ := os.OpenFile("app.log", os.O_CREATE|os.O_APPEND|os.O_WRONLY, 0644)
jsonHandler := slog.NewJSONHandler(fileWriter, nil)

multi := logging.NewMultiHandler(textHandler, jsonHandler)
logger := slog.New(multi)

logger.Info("server started", "port", 8080)
// Record is written to both stdout and app.log
```

## Notes

- Each record passed to `Handle` is **cloned** before dispatch, preventing handlers from mutating shared state.
- `Handle` is **fault-tolerant**: a failure in one handler does not prevent others from receiving the record; all errors are aggregated and returned via `errors.Join`.
- The compile-time assertion `var _ slog.Handler = (*MultiHandler)(nil)` ensures the interface is fully satisfied.
