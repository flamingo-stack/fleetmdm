Structured logging setup using `slog` with support for JSON/text output formats, OpenTelemetry trace correlation, and multi-handler log export.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `Options` | struct | Configuration for log format, level, output destination, and OTel integration |
| `NewSlogLogger` | func | Constructs a `*slog.Logger` from the given `Options` |
| `OtelTracingHandler` | struct | `slog.Handler` wrapper that injects `trace_id` and `span_id` from active OTel spans |
| `NewOtelTracingHandler` | func | Constructor for `OtelTracingHandler` |
| `replaceAttr` | func (internal) | Normalizes log keys for go-kit/log backward compatibility (`ts`, lowercase levels) |

## Usage Example

```go
import "github.com/flamingo-stack/fleetmdm/pkg/logging"

// Development (text output)
logger := logging.NewSlogLogger(logging.Options{
    Debug: true,
})

// Production (JSON + OTel trace correlation)
logger := logging.NewSlogLogger(logging.Options{
    JSON:           true,
    TracingEnabled: true,
    AddSource:      true,
})

// With OTEL log export
logger := logging.NewSlogLogger(logging.Options{
    JSON:            true,
    TracingEnabled:  true,
    OtelLogsEnabled: true,
    LoggerProvider:  myLoggerProvider,
})

logger.InfoContext(ctx, "request completed", "status", 200)
// Output: {"ts":"2025-01-01T00:00:00Z","level":"info","msg":"request completed","status":200,"trace_id":"...","span_id":"..."}
```

## Notes

- Output defaults to `os.Stderr` when `Options.Output` is nil
- Log timestamps use `ts` key in RFC3339 format and level values are lowercased for go-kit/log compatibility
- When both `TracingEnabled` and `OtelLogsEnabled` are set, logs are fanned out via `MultiHandler` — once to stderr and once to the OTel collector
- `TopicFilterHandler` is applied as the outermost layer so disabled topics are dropped before reaching any downstream handler
