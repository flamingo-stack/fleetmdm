Provides a thread-safe, opt-out topic filtering system for structured logging, where all topics are enabled by default and can be selectively disabled at runtime.

## Key Components

| Symbol | Type | Description |
|---|---|---|
| `DeprecatedFieldTopic` | `const` | Predefined topic name (`"deprecated-field-names"`) for flagging deprecated field usage |
| `EnableTopic(name string)` | `func` | Removes a topic from the disabled set, re-enabling it |
| `DisableTopic(name string)` | `func` | Adds a topic to the disabled set, suppressing related log output |
| `TopicEnabled(name string) bool` | `func` | Returns `true` unless the topic has been explicitly disabled |
| `ResetTopics()` | `func` | Clears all disabled topics; intended for test isolation |

**Internal:** `disabledTopics` (`map[string]bool`) stores only disabled topics; `disabledTopicsMu` (`sync.RWMutex`) guards concurrent access.

## Usage Example

```go
// Suppress deprecated field warnings during a migration
logging.DisableTopic(logging.DeprecatedFieldTopic)

// Later, re-enable it
logging.EnableTopic(logging.DeprecatedFieldTopic)

// Guard log output with a topic check
if logging.TopicEnabled(logging.DeprecatedFieldTopic) {
    log.Warn("deprecated field used", "field", fieldName)
}

// In tests — reset state between test cases
func TestSomething(t *testing.T) {
    t.Cleanup(logging.ResetTopics)
    logging.DisableTopic("my-noisy-topic")
    // ...
}
```

## Notes

- **Opt-out model:** topics not in the disabled map are implicitly enabled — no registration required.
- **Concurrency safe:** write operations (`Enable`/`Disable`/`Reset`) acquire a write lock; `TopicEnabled` uses a read lock, allowing safe concurrent reads.
