Routes `slog` structured log output through `testing.TB.Log`, so log lines appear only on test failure (or with `-v`) and stay grouped with their test in parallel runs.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `TestLogger` | `func(testing.TB) *slog.Logger` | Returns a `*slog.Logger` backed by the test's log sink |
| `tLogWriter` | `struct` | Internal `io.Writer` adapter that forwards bytes to `t.Log` |

## Usage Example

```go
func TestMyService(t *testing.T) {
    logger := testutils.TestLogger(t)
    svc := mypackage.NewService(logger)

    result, err := svc.DoSomething()
    require.NoError(t, err)
    // Log lines only appear if the test fails, or when running with -v
}
```

Works with parallel sub-tests too — each sub-test gets its own scoped logger:

```go
func TestParallel(t *testing.T) {
    t.Parallel()
    logger := testutils.TestLogger(t)
    // logs are grouped under this sub-test, never interleaved with siblings
    _ = logger
}
```

## Notes

- Pass `testing.T`, `testing.B`, or `testing.F` — anything satisfying `testing.TB`.
- The underlying handler is `slog.NewTextHandler` with default options (level `INFO`, no source).
- No setup or teardown needed; the logger is valid for the lifetime of the test.
