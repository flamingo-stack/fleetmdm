Handles MySQL transaction retry logic with exponential backoff, and manages fatal database error handling for Aurora failover scenarios.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `SetFatalErrorHandler` | Function | Registers a callback invoked (at most once) on fatal DB errors such as read-only failover |
| `TriggerFatalError` | Function | Invokes the registered fatal error handler, or panics if none is set |
| `WithRetryTxx` | Function | Wraps a `TxFn` in a transaction with automatic rollback and exponential backoff retry |
| `RetryableError` | Function | Returns `true` for MySQL deadlock/lock-wait errors or `DoRetryErr` sentinel |
| `DoRetryErr` | Sentinel error | Can be returned from a `TxFn` to explicitly trigger a retry |
| `TxFn` / `ReadTxFn` | Types | Transaction function signatures accepted by retry wrappers |

## Usage Example

```go
// Register a graceful shutdown handler for Aurora failover
mysql.SetFatalErrorHandler(func(ctx context.Context, err error) {
    slog.ErrorContext(ctx, "fatal DB error, shutting down", "err", err)
    os.Exit(1)
})

// Execute a transaction with automatic retry on deadlock/lock-wait
err := mysql.WithRetryTxx(ctx, db, func(tx sqlx.ExtContext) error {
    _, err := tx.ExecContext(ctx, "UPDATE hosts SET updated_at = NOW() WHERE id = ?", hostID)
    if err != nil {
        return err
    }
    // Signal an explicit retry from business logic
    if needsRetry {
        return mysql.DoRetryErr
    }
    return nil
}, logger)
```

**Retry behavior:** Up to 5 attempts with exponential backoff capped at 1 minute. Read-only errors bypass retries and immediately trigger the fatal error handler.
