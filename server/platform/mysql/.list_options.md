Provides SQL query building utilities for appending pagination and sorting clauses (`ORDER BY`, `LIMIT`, `OFFSET`) to MySQL queries, with both a secure allowlist-based approach and a legacy sanitization-based approach.

## Key Components

- **`OrderKeyAllowlist`** — Maps user-facing sort key names to actual SQL column expressions; prevents arbitrary column exposure.
- **`InvalidOrderKeyError`** — Returned when a sort key is not in the allowlist; implements HTTP 422 validation error and client-error logging interfaces.
- **`ListOptions`** — Interface defining pagination/sorting inputs: page, per-page, order key, direction, cursor, and secondary sort.
- **`SanitizeColumn`** — Strips disallowed characters from a column name and backtick-wraps parts for safe SQL embedding. *(Used by the deprecated path.)*
- **`AppendListOptionsWithParamsSecure`** — Preferred function; validates the order key against an explicit allowlist before building the query clause. Panics if allowlist is `nil` (programming guard).
- **`AppendListOptionsWithParams`** — Deprecated; uses `SanitizeColumn` instead of an allowlist. Prefer the `Secure` variant for new code.

## Usage Example

```go
allowlist := mysql.OrderKeyAllowlist{
    "hostname":   "h.hostname",
    "created_at": "h.created_at",
}

sql := "SELECT * FROM hosts h WHERE h.team_id = ?"
params := []any{teamID}

sql, params, err := mysql.AppendListOptionsWithParamsSecure(sql, params, listOpts, allowlist)
if err != nil {
    // Returns InvalidOrderKeyError (HTTP 422) for unknown sort keys
    return err
}
// sql => "SELECT * FROM hosts h WHERE h.team_id = ? ORDER BY h.hostname ASC LIMIT 26 OFFSET 0"
```

> **Note:** Pass an empty `OrderKeyAllowlist{}` (not `nil`) to disallow all sorting. Passing `nil` will panic.
