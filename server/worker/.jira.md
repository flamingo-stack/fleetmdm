Handles asynchronous Jira issue creation for Fleet's vulnerability and failing policy integrations, processing queued worker jobs and managing Jira API client lifecycle.

## Key Components

- **`Jira`** — Main job processor struct implementing the `worker.Job` interface, holding Fleet URL, datastore, logger, and a thread-safe cache of `JiraClient` instances keyed by integration type and team ID.
- **`JiraClient`** — Interface abstracting Jira API calls (`CreateJiraIssue`, `JiraConfigMatches`) for testability.
- **`jiraTemplates`** — Pre-compiled Go text templates for vulnerability and failing policy issue summaries and descriptions, using Jira wiki markup.
- **`jiraArgs`** — Discriminated union payload (either `vulnArgs` or `failingPolicyArgs`) deserialized from the worker job queue.
- **`getClient()`** — Resolves the appropriate `JiraClient` for a job, checking app config or team config, reusing cached clients when configuration is unchanged.
- **`Run()`** — Entry point dispatching jobs to `runVuln()` or `runFailingPolicy()` based on args type.
- **`QueueJiraVulnJobs()`** — Groups recent `SoftwareVulnerability` records by CVE and enqueues worker jobs with associated EPSS/CVSS/CISA metadata.

## Usage Example

```go
// Register the Jira job with the worker
jiraJob := &worker.Jira{
    FleetURL:  "https://fleet.example.com",
    Datastore: ds,
    Log:       logger,
    NewClientFunc: func(opts *externalsvc.JiraOptions) (worker.JiraClient, error) {
        return externalsvc.NewJiraClient(opts)
    },
}
w.AddJob(jiraJob)

// Queue vulnerability jobs (called after vulnerability ingestion)
err := worker.QueueJiraVulnJobs(ctx, ds, logger, recentVulns, cveMeta)
```

Issues are created as Jira `Task` type, capped at 50 affected hosts per ticket, with premium licenses including EPSS probability, CVSS score, CISA known exploit status, and CVE publish date.
