Implements a test double for `JiraClient` and `ZendeskClient` interfaces that injects controlled failures into automation workflows, enabling error-handling validation at scale in load-testing environments.

## Key Components

### `TestAutomationFailer` struct
A wrapper around real Jira and Zendesk clients that selectively forces errors based on two configurable strategies:

| Field | Description |
|---|---|
| `FailCallCountModulo` | Forces a failure every N calls (`callCounts % FailCallCountModulo == 0`). Disabled when `<= 0` |
| `AlwaysFailCVEs` | List of CVE strings that always trigger a failure, regardless of call count |
| `JiraClient` | Underlying Jira client used for non-failing calls |
| `ZendeskClient` | Underlying Zendesk client used for non-failing calls |

### Methods

- **`CreateJiraIssue`** — Checks `issue.Fields.Summary` for forced-failure conditions before delegating to the real client
- **`CreateZendeskTicket`** — Checks `ticket.Subject` for forced-failure conditions before delegating to the real client
- **`JiraConfigMatches`** / **`ZendeskConfigMatches`** — Pass-through to the wrapped clients
- **`forceErr`** — Core failure logic; increments call counter and evaluates both failure strategies

## Usage Example

```go
failer := &TestAutomationFailer{
    FailCallCountModulo: 5,           // fail every 5th call
    AlwaysFailCVEs:      []string{"CVE-2021-44228"}, // always fail for this CVE
    JiraClient:          realJiraClient,
    ZendeskClient:       realZendeskClient,
}

// Use failer anywhere a JiraClient or ZendeskClient is accepted
_, err := failer.CreateJiraIssue(ctx, issue)
if err != nil {
    // handle forced or real failure
}
```
