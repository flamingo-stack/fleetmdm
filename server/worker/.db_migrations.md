Handles background worker jobs for database migrations that cannot be performed during the standard `fleet prepare db` command, currently supporting VPP token migration tasks.

## Key Components

- **`DBMigration`** — Job processor struct implementing the worker job interface, requiring a `fleet.Datastore` and `*slog.Logger`.
- **`DBMigrationTask`** — String type enumerating supported migration tasks; currently only `DBMigrateVPPTokenTask` (`"migrate_vpp_token"`).
- **`Run`** — Dispatches execution based on the `task` field in the JSON payload.
- **`migrateVPPToken`** — Finds the legacy VPP token (identified by an empty location), extracts its metadata, and updates both the token record and its team associations to target "All teams".
- **`extractVPPTokenFromMigration`** — Parses the nested token structure (JSON → base64 → raw token), extracts org name, location, and expiration date, and reports whether any metadata fields differed from stored values.

## Usage Example

This job is never enqueued via application code. It is inserted directly by a database migration using a raw SQL `INSERT` into the `jobs` table:

```go
// Example SQL inserted by a DB migration (not application code):
// INSERT INTO jobs (name, args, state)
// VALUES ('db_migration', '{"task":"migrate_vpp_token"}', 'queued');

// The worker picks it up and calls Run with the serialized args:
job := &DBMigration{
    Datastore: ds,
    Log:       slog.Default(),
}

argsJSON := json.RawMessage(`{"task":"migrate_vpp_token"}`)
if err := job.Run(ctx, argsJSON); err != nil {
    log.Fatal(err)
}
```

> **Note:** Do not add a `QueueDBMigrationJob` helper. Enqueuing via direct SQL INSERT is intentional — it avoids coupling migrations to application code that may change over time.
