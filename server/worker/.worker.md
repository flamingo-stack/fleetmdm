Worker orchestrates background job processing for Fleet integrations (Jira, Zendesk, vulnerability notifications, etc.), providing job registration, queuing, retry logic, and OpenTelemetry tracing.

## Key Components

### `Job` Interface
Defines the contract for all background jobs:
- `Name() string` — unique job identifier
- `Run(ctx context.Context, argsJSON json.RawMessage) error` — executes the job

### `Worker` Struct
Central job processor. **Not safe for concurrent use.**
- Maintains a registry of named `Job` implementations
- Reads/writes job state via `fleet.Datastore`
- Applies configurable retry delays (`delayPerRetry`, default: `defaultDelayPerRetry`)
- Emits OpenTelemetry spans per job execution

### Key Functions

| Function | Description |
|---|---|
| `NewWorker(ds, log)` | Creates a new `Worker` instance |
| `Register(jobs...)` | Registers one or more jobs; panics on duplicate names |
| `QueueJob(ctx, ds, name, args)` | Marshals args to JSON and enqueues a job immediately |
| `QueueJobWithDelay(...)` | Enqueues a job with a `NotBefore` delay |
| `ProcessJobs(ctx)` | Polls and processes all queued jobs in a loop |

### Retry Behavior
Jobs are retried up to `maxRetries` (5) times with increasing delays:

```text
Retry 1: immediate  →  Retry 2: 5m  →  Retry 3: 10m  →  Retry 4: 1h  →  Retry 5: 2h
```

After 5 failures, the job transitions to `fleet.JobStateFailure`.

## Usage Example

```go
// Initialize and register jobs
w := worker.NewWorker(ds, logger)
w.Register(jiraJob, zendeskJob)

// Queue a vulnerability notification job
err := worker.QueueJob(ctx, ds, "jira", vulnArgs{
    CVE:             "CVE-2024-1234",
    EPSSProbability: ptr.Float64(0.85),
})

// Queue with a delay (e.g., wait 10 minutes before processing)
err = worker.QueueJobWithDelay(ctx, ds, "zendesk", args, 10*time.Minute)

// Process all pending jobs (called by the cron scheduler)
err = w.ProcessJobs(ctx)
```
