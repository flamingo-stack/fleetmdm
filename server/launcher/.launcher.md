Provides the gRPC transport layer that bridges Kolide Launcher clients to Fleet's osquery service, translating Launcher protocol calls into Fleet's internal `OsqueryService` API.

## Key Components

### `launcherWrapper`
The core struct that wraps `fleet.OsqueryService` and implements the Launcher gRPC service interface.

| Method | Description |
|---|---|
| `RequestEnrollment` | Enrolls a Launcher host using an enroll secret and host identifier |
| `RequestConfig` | Retrieves osquery config, stripping Launcher-managed plugin options (`distributed_plugin`, `logger_plugin`) |
| `RequestQueries` | Fetches pending distributed queries including discovery queries and acceleration settings |
| `PublishLogs` | Routes status, snapshot, or string logs to the appropriate Fleet submission endpoint |
| `PublishResults` | Submits distributed query results including per-query execution stats |
| `CheckHealth` | Runs all registered health checkers and returns `0` (healthy) or `1` (unhealthy) |
| `authenticateHost` | Internal helper that validates a node key and injects the authenticated host into context |

### `nodeInvalidErr`
Interface used to detect authentication errors that require a `NodeInvalid` response back to the client.

## Usage Example

```go
wrapper := &launcherWrapper{
    tls:            osquerySvc,
    logger:         slog.Default(),
    healthCheckers: map[string]health.Checker{
        "mysql": mysqlChecker,
    },
}

// The wrapper satisfies the Launcher gRPC service interface
nodeKey, invalid, err := wrapper.RequestEnrollment(ctx, enrollSecret, hostID, details)
if err != nil {
    // handle enrollment failure
}

config, invalid, err := wrapper.RequestConfig(ctx, nodeKey)
```

## Notes

- Plugin options (`distributed_plugin`, `logger_plugin`) are removed from config responses since Launcher manages its own plugins.
- Authentication is handled per-request via `authenticateHost` rather than middleware, as Launcher's protocol requires explicit `NodeInvalid` returns.
- Query stats (`WallTimeMs`, `UserTime`, `SystemTime`, `Memory`) are mapped from Launcher's format to Fleet's `fleet.Stats` struct.
