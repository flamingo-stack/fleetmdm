Aggregates stored context errors into a JSON summary with occurrence counts, reduced stack traces, and vital error metadata for Fleet MDM diagnostics.

## Key Components

- **`ErrorAgg`** — struct representing an aggregated error entry with count, stack locations, and optional metadata
- **`Aggregate(ctx)`** — retrieves all stored errors via `Retrieve`, builds `ErrorAgg` slices capped at 3 stack frames, and returns a marshalled JSON array
- **`aggregateStack(chain, maxStack)`** — flattens stack traces across an error chain into a single slice, truncated to `maxStack` entries
- **`vitalErrorData`** — internal struct for deserialising vital fleetd error payloads (source, version, message, additional info)
- **`getVitalMetadata(chain)`** — walks the error chain looking for vital fleetd errors; returns a sanitised JSON metadata object (no sensitive fields) or `nil`

## Usage Example

```go
import (
    "context"
    "fmt"
    "github.com/flamingo-stack/fleetmdm/pkg/ctxerr"
)

func reportErrors(ctx context.Context) {
    summary, err := ctxerr.Aggregate(ctx)
    if err != nil {
        // handle aggregation failure
        return
    }
    // summary is a JSON array of ErrorAgg entries, e.g.:
    // [{"count":3,"loc":["server.go:42","handler.go:17"],"metadata":{...}}]
    fmt.Println(string(summary))
}
```

## Notes

- Returns `[]` (empty JSON array) on retrieval or unmarshal failure to keep callers safe
- Stack traces are capped at **3 frames** (`maxTraceLen`) to reduce noise
- Only errors explicitly marked `vital: true` in their fleetd payload produce metadata; sensitive fields are intentionally excluded before export
