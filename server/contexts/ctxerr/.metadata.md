Defines the `ErrorContextProvider` interface and context utilities for attaching diagnostic and telemetry metadata to errors within the `ctxerr` package.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `ErrorContextProvider` | Interface | Supplies contextual metadata for error storage and observability systems |
| `GetDiagnosticContext()` | Method | Returns attributes persisted to Redis/logs (e.g. platform, versions, status flags — no PII) |
| `GetTelemetryContext()` | Method | Returns attributes forwarded to OpenTelemetry/Sentry; return `nil` if unavailable |
| `AddErrorContextProvider` | Function | Appends a provider to the context without replacing existing ones |
| `getErrorContextProviders` | Function (internal) | Retrieves the provider slice stored in the context |

## Usage Example

```go
// Implement the interface for your service context
type ServiceContext struct {
    Platform string
    Version  string
}

func (s *ServiceContext) GetDiagnosticContext() map[string]any {
    return map[string]any{
        "platform": s.Platform,
        "version":  s.Version,
    }
}

func (s *ServiceContext) GetTelemetryContext() map[string]any {
    return map[string]any{
        "service.version": s.Version,
    }
}

// Attach the provider to the context
ctx := context.Background()
ctx = ctxerr.AddErrorContextProvider(ctx, &ServiceContext{
    Platform: "linux",
    Version:  "1.4.2",
})

// Multiple providers can be chained without overwriting prior ones
ctx = ctxerr.AddErrorContextProvider(ctx, anotherProvider)
```

## Notes

- Providers are accumulated in a slice; each call to `AddErrorContextProvider` appends rather than replaces.
- `GetDiagnosticContext` data is intended for durable storage — avoid including personally identifiable information (PII).
- `GetTelemetryContext` is optional; returning `nil` is a valid no-op.
