Initializes and exposes OpenTelemetry metric counters for tracking HTTP client (4xx) and server (5xx) errors within the `ctxerr` package.

## Key Components

| Symbol | Type | Description |
|---|---|---|
| `meter` | `metric.Meter` | Package-level OTel meter scoped to `"fleet"` |
| `clientErrorsCounter` | `metric.Int64Counter` | Counts client errors (`fleet.http.client_errors`) |
| `serverErrorsCounter` | `metric.Int64Counter` | Counts server errors (`fleet.http.server_errors`) |
| `clientErrorCounterAttrs` | `func` | Returns `metric.AddOption` with `error.type` attribute for client errors |
| `serverErrorCounterAttrs` | `func` | Returns `metric.AddOption` with `error.type` attribute for server errors |

Both counters are registered in `init()` and will panic if meter creation fails.

## Usage Example

```go
// Increment client error counter (e.g., 401 Unauthorized)
clientErrorsCounter.Add(ctx, 1, clientErrorCounterAttrs("unauthorized"))

// Increment server error counter (e.g., 500 Internal Server Error)
serverErrorsCounter.Add(ctx, 1, serverErrorCounterAttrs("internal_server_error"))
```

Both attribute helpers attach an `error.type` string label, enabling metric queries grouped by error category in your OTel-compatible backend (e.g., Prometheus, Grafana).

> These metrics follow [OTel semantic conventions](https://opentelemetry.io/docs/specs/semconv/http/http-metrics/): 4xx errors are treated as client errors and excluded from server error alerting.
