Provides context-based storage and retrieval of Fleet client capabilities parsed from HTTP request headers.

## Key Components

- **`capabilitiesKey`** — Unexported context key used to store capabilities without collision.
- **`NewContext`** — Parses the `fleet.CapabilitiesHeader` from an HTTP request, populates a `fleet.CapabilityMap`, and stores it in the returned context.
- **`FromContext`** — Retrieves the `fleet.CapabilityMap` from a context, returning the map and a boolean indicating presence.

## Usage Example

```go
// Middleware: inject capabilities into context from incoming request
func CapabilitiesMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        ctx := capabilities.NewContext(r.Context(), r)
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}

// Handler: read capabilities from context
func MyHandler(ctx context.Context) {
    caps, ok := capabilities.FromContext(ctx)
    if !ok {
        // no capabilities present
        return
    }
    if caps.Has(fleet.CapabilityXYZ) {
        // feature-flag logic
    }
}
```

## Notes

- The context key is a private typed integer (`key`), preventing accidental collisions with other packages using plain `int` or `string` keys.
- Capability data originates from the `fleet.CapabilitiesHeader` HTTP header, making this pattern suitable for feature negotiation between Fleet server and clients.
