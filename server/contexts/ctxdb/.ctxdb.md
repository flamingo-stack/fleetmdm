Context-propagated database routing flags for controlling primary/replica selection and MySQL cache bypass behavior within a request lifecycle.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `RequirePrimary` | `func` | Embeds a primary-required flag into the context |
| `IsPrimaryRequired` | `func` | Reads the primary-required flag from the context |
| `BypassCachedMysql` | `func` | Embeds a cache-bypass flag into the context |
| `IsCachedMysqlBypassed` | `func` | Reads the cache-bypass flag from the context |

## Usage Example

```go
// Force reads to go to the primary DB after a write
ctx = ctxdb.RequirePrimary(ctx, true)
if ctxdb.IsPrimaryRequired(ctx) {
    // route query to primary instance
}

// Bypass MySQL cache when reading data you intend to mutate
ctx = ctxdb.BypassCachedMysql(ctx, true)
if ctxdb.IsCachedMysqlBypassed(ctx) {
    // fetch directly from DB, skipping cache layer
}
```

## Notes

- Both flags default to `false` when not set — replica reads and cache usage are the standard path.
- Use `RequirePrimary` after writes where you need to immediately read back consistent data (avoids replica lag).
- Use `BypassCachedMysql` when reading data **with intent to modify**, preventing stale cache reads from overwriting newer DB state.
- Context keys use an unexported `key` type to prevent collisions with other packages.
