Defines the `SqlDialect` interface and provides concrete implementations for PostgreSQL, MySQL, and SQLite3, abstracting database-specific SQL syntax for goose's migration version tracking table.

## Key Components

### Interface

- **`SqlDialect`** — Core interface with three methods:
  - `createVersionTableSql(name string) string` — Generates DDL to create the version tracking table
  - `insertVersionSql(name string) string` — Generates the initial version row insert statement
  - `dbVersionQuery(db *sql.DB, name string) (*sql.Rows, error)` — Queries applied migrations ordered by ID descending

### Dialect Implementations

| Struct | Database | Parameter Style |
|---|---|---|
| `PostgresDialect` | PostgreSQL | `$1, $2` |
| `MySqlDialect` | MySQL | `?, ?` |
| `Sqlite3Dialect` | SQLite3 | `?, ?` |

### Functions

- **`GetDialect()`** — Returns the current global dialect
- **`SetDialect(d string) error`** — Sets the global dialect by name (`"postgres"`, `"mysql"`, `"sqlite3"`)
- **`(*Client).SetDialect(d string) error`** — Sets the dialect on a specific `Client` instance

## Usage Example

```go
// Set dialect globally
if err := goose.SetDialect("postgres"); err != nil {
    log.Fatal(err)
}

// Or on a specific client
client := &goose.Client{}
if err := client.SetDialect("mysql"); err != nil {
    log.Fatal(err)
}

// Retrieve the active dialect
dialect := goose.GetDialect()
```

## Notes

- Passing an unrecognized dialect string returns an error: `"<name>": unknown dialect`
- The version table schema differs slightly per dialect — notably, SQLite3 uses `INTEGER PRIMARY KEY AUTOINCREMENT` and `datetime('now')` instead of `serial`/`timestamp default now()`
- SQL queries concatenate the table `name` directly; callers are responsible for providing a safe, validated name (noted via `#nosec G202` annotations)
