Entrypoint for the `goose` database migration package, defining the `Client` struct and the global `Run` dispatcher that routes migration commands to their corresponding methods.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `Client` | struct | Holds migration state: table name, SQL dialect, and registered migrations |
| `New` | func | Constructor for `Client`; accepts a table name and `SqlDialect` |
| `Run` | func | Global command dispatcher; routes string commands to the appropriate migration operation |
| `minVersion` / `maxVersion` | `int64` | Sentinel version bounds used internally for range checks |

### Supported `Run` Commands

| Command | Description |
|---------|-------------|
| `up` | Apply all pending migrations |
| `up-by-one` | Apply the next pending migration only |
| `create` | Scaffold a new migration file (`go` or `sql`) |
| `down` | Roll back the most recent migration |
| `redo` | Roll back and re-apply the latest migration |
| `status` | Print current migration status |
| `version` | Print the active schema version |

## Usage Example

```go
// Preferred: create a scoped client
client := goose.New("schema_migrations", goose.DialectPostgres)
if err := client.Up(db, "./migrations"); err != nil {
    log.Fatal(err)
}

// Alternatively: use the global Run dispatcher
if err := goose.Run("up", db, "./migrations"); err != nil {
    log.Fatal(err)
}

// Create a new migration file
if err := goose.Run("create", db, "./migrations", "add_users_table", "sql"); err != nil {
    log.Fatal(err)
}
```

> **Prefer `New`** over the global `Run` function when managing multiple databases or dialects — the `Client` struct keeps migration state and configuration isolated per instance.
