Parses and executes SQL migration scripts, handling directional annotations (`Up`/`Down`) and multi-statement blocks for the goose migration framework.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `endsWithSemicolon` | `func(string) bool` | Detects statement-terminating semicolons, skipping inline `--` comments |
| `splitSQLStatements` | `func(io.Reader, bool) []string` | Splits a SQL script into executable statements, respecting `Up`/`Down` direction and `StatementBegin`/`StatementEnd` blocks |
| `runSQLMigration` | `func(*sql.DB, string, int64, bool) error` | Opens a SQL file, executes all directional statements in a transaction, and finalizes the migration version |
| `sqlCmdPrefix` | `const` | The annotation prefix `"-- +goose "` used to identify goose directives in SQL files |

## Supported SQL Annotations

```text
-- +goose Up             # begins an up-migration block
-- +goose Down           # begins a down-migration block
-- +goose StatementBegin # disables semicolon splitting (for PL/pgSQL etc.)
-- +goose StatementEnd   # re-enables semicolon splitting
```

## Usage Example

```go
// A typical goose SQL migration file layout:
//
// -- +goose Up
// CREATE TABLE users (id SERIAL PRIMARY KEY, name TEXT);
//
// -- +goose Down
// DROP TABLE users;

client := &goose.Client{}
db, _ := sql.Open("postgres", dsn)

// Run the Up migration (direction=true) for version 20240101
err := client.runSQLMigration(db, "./migrations/001_create_users.sql", 20240101, true)
if err != nil {
    log.Fatal(err)
}
```

> **Note:** Statements within a `StatementBegin`/`StatementEnd` block are executed as a single unit, enabling support for procedural SQL (e.g., PL/pgSQL functions). Missing `StatementEnd` or unterminated statements without a semicolon will emit warnings via `log.Println`.
