Defines the core data structures, validation logic, and error types for Fleet policy management, including creation payloads, modification payloads, and label-scoping rules.

## Key Components

### Structs
- **`PolicyPayload`** — Full policy creation payload supporting query ID references, platform targeting, label scopes, software/script automations, and patch policy configuration
- **`NewTeamPolicyPayload`** — Team-scoped policy creation payload with similar fields tailored for team context
- **`ModifyPolicyPayload`** — Partial-update payload using pointer fields and `optjson.Any` for optional zero-value handling (e.g., unsetting a script)

### Validation Functions
- **`(PolicyPayload).Verify()`** — Validates a creation payload, enforcing patch policy constraints, query/platform rules, and label scope consistency
- **`verifyPolicyLabelScopes()`** — Ensures at most one include scope and one exclude scope are set, with no label overlap between include and exclude lists
- **`PolicyVerifyConditionalAccess()`** — Exported validator ensuring conditional access is only enabled on `darwin`/`windows` policies
- **`verifyPolicyPlatforms()`** — Validates platform strings against allowed values: `windows`, `linux`, `darwin`, `chrome`

### Constants & Errors
- **`PolicyNoTeamID`** — Sentinel `uint(0)` for "No team" policies
- **`MaxPolicyAutomationRetries`** — Cap of `3` retries for failed policy automations
- Exported errors: `ErrPolicyConflictingIncludeLabels`, `ErrPolicyConflictingExcludeLabels`

## Usage Example

```go
payload := fleet.PolicyPayload{
    Name:             "Disk Encryption",
    Query:            "SELECT 1 FROM disk_encryption WHERE encrypted = 1;",
    Platform:         "darwin,windows",
    LabelsIncludeAny: []string{"production"},
    Critical:         true,
}

if err := payload.Verify(); err != nil {
    log.Fatalf("invalid policy: %v", err)
}
```
