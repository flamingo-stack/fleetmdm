Defines types and interfaces for managing software title icons in Fleet MDM, including storage operations, URL generation, and authorization.

## Key Components

| Component | Description |
|---|---|
| `SoftwareTitleIconURLRegex` | Compiled regex for matching icon URL paths with `team_id` or `fleet_id` query params |
| `SoftwareTitleIconSignedURLExpiry` | Default expiry duration (6 hours) for signed icon URLs |
| `UploadSoftwareTitleIconPayload` | Payload struct for uploading a new software title icon |
| `SoftwareTitleIcon` | Core entity representing a stored icon, with authz and URL generation methods |
| `SoftwareTitleIconStore` | Interface for icon blob storage operations (put, get, exists, cleanup, sign) |
| `DetailsForSoftwareIconActivity` | Aggregated details struct for activity-log entries related to software icons |

## Usage Example

```go
// Generate icon URLs for API and device-token contexts
icon := &fleet.SoftwareTitleIcon{
    SoftwareTitleID: 42,
    TeamID:          7,
    StorageID:       "icons/abc123",
    Filename:        "app.png",
}

apiURL    := icon.IconUrl()
// → "/api/latest/fleet/software/titles/42/icon?fleet_id=7"

deviceURL := icon.IconUrlWithDeviceToken("tok_xyz")
// → "/api/latest/fleet/device/tok_xyz/software/titles/42/icon"

// Check authorization type (used by rego policies)
authType := icon.AuthzType() // → "installable_entity"

// Validate an inbound URL matches the expected icon path format
matched := fleet.SoftwareTitleIconURLRegex.MatchString(
    "fleet/software/titles/42/icon?team_id=7",
) // → true
```

## Notes

- `SoftwareTitleIcon.TeamID` is JSON-tagged as `team_id` specifically so rego authorization policies can deserialize it correctly; this tag does not affect external API responses.
- `SoftwareTitleIconStore.Sign` returns a pre-signed URL valid for the provided duration (typically `SoftwareTitleIconSignedURLExpiry`).
- `DetailsForSoftwareIconActivity` supports VPP apps (via `AdamID`/`VPPIconUrl`), in-house apps, and standard installer packages in a single struct.
