Defines types and constants for managing in-house (enterprise) mobile app distribution in Fleet MDM.

## Key Components

| Name | Type | Description |
|------|------|-------------|
| `InHouseAppSignedURLExpiry` | `const` | 5-minute TTL for pre-signed download URLs |
| `InHouseAppInstallTokenTTL` | `const` | 6-hour TTL for install tokens, matching `BootstrapPackageSignedURLExpiry` to accommodate offline devices |
| `InHouseAppInstallTokenMetadata` | `struct` | Tracks an active install token with its associated host, team, and software title |
| `InHouseAppPayload` | `struct` | Full payload describing an in-house app to be uploaded or updated |

## Usage Example

```go
// Build a payload for uploading a new in-house iOS app
payload := fleet.InHouseAppPayload{
    TeamID:      ptr.Uint(42),
    Title:       "Acme Corp App",
    Filename:    "acme-corp.ipa",
    BundleID:    "com.acme.corp",
    StorageID:   "s3://bucket/acme-corp.ipa",
    Platform:    "ios",
    Version:     "2.1.0",
    SelfService: true,
    Configuration: []byte(`<dict><key>ServerURL</key><string>https://mdm.acme.com</string></dict>`),
}

// Token metadata stored after issuing an install token
meta := fleet.InHouseAppInstallTokenMetadata{
    Token:           "abc123",
    SoftwareTitleID: 7,
    TeamID:          42,
    HostID:          100,
    ExpiresAt:       time.Now().Add(fleet.InHouseAppInstallTokenTTL),
}
```

## Notes

- `InHouseAppInstallTokenTTL` is intentionally long (6 hours) to handle devices that are offline when an `InstallApplication` MDM command is issued.
- `Configuration` on `InHouseAppPayload` is raw XML and applies only to iOS/iPadOS managed app configurations.
- `ValidatedLabels` scopes app visibility to specific host labels.
