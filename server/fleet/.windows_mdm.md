Validates and structures Windows MDM configuration profile data, including SyncML XML parsing, LocURI format enforcement, and BitLocker state tracking for Fleet-managed Windows hosts.

## Key Components

### Types

- **`MDMWindowsBitLockerSummary`** — Aggregates BitLocker enforcement state counts across Windows hosts into six mutually exclusive categories (`Verified`, `Verifying`, `ActionRequired`, `Enforcing`, `Failed`, `RemovingEnforcement`).
- **`MDMWindowsConfigProfile`** — Represents a Windows MDM SyncML profile with metadata (UUID, team, labels, timestamps) and raw SyncML content.
- **`windowsProfileValidator`** — Internal stateful XML stream validator tracking element context, SCEP state, and Atomic/non-Atomic profile structure.

### Key Functions

- **`MDMWindowsConfigProfile.ValidateUserProvided()`** — Entry point for profile validation; checks for reserved profile names, empty content, and delegates to the XML validator.
- **`newWindowsProfileValidator(syncML []byte)`** — Constructs a strict-mode XML decoder-backed validator.
- **`validateLocURIFormat(locURI string)`** — Enforces OMA-DM LocURI rules: rejects empty values, leading `/`, and `..` path traversal segments.
- **`validateFleetProvidedLocURI(locURI string)`** — Blocks Fleet-reserved URIs (e.g., BitLocker) from being overridden in user-supplied profiles.

### Validation Rules Enforced

- At least one `<Replace>`, `<Add>`, `<Exec>`, or `<Atomic>` top-level element must be present.
- `<Atomic>` must wrap all elements if used; cannot coexist with sibling top-level elements.
- `<LocURI>` must be non-empty, must not start with `/`, and must not contain `..` segments.
- Processing instructions (`<?...?>`) are disallowed.

## Usage Example

```go
profile := &fleet.MDMWindowsConfigProfile{
    Name:   "CustomPolicy",
    SyncML: []byte(`<Replace><Item><Target><LocURI>./Vendor/MSFT/Policy/Config/Example</LocURI></Target></Item></Replace>`),
}

if err := profile.ValidateUserProvided(); err != nil {
    log.Fatalf("invalid profile: %v", err)
}
```
