Defines the `LiveQueryStore` interface for managing live query lifecycle and result tracking within the Fleet system.

## Key Components

### Interface: `LiveQueryStore`

| Method | Description |
|--------|-------------|
| `RunQuery` | Starts a named query targeting specific host IDs |
| `StopQuery` | Halts a running query; hosts stop receiving it immediately |
| `QueriesForHost` | Returns active query name-to-SQL map for a given host |
| `QueryCompletedByHost` | Marks a query as completed for a host; suppresses future delivery |
| `CleanupInactiveQueries` | Removes stale queries (designed for cron job use, e.g. Redis cleanup) |
| `LoadActiveQueryNames` | Lists all currently active query names |
| `GetQueryResultsCounts` | Bulk-fetches result counts by query ID; missing keys return `0` |
| `IncrQueryResultsCounts` | Increments result counts by given amounts per query ID |
| `SetQueryResultsCount` | Sets a query's result count to a specific value (used post-cleanup) |
| `DeleteQueryResultsCount` | Removes the result count key for a deleted query |

## Usage Example

```go
// Implement LiveQueryStore backed by Redis
type redisLiveQueryStore struct{ client *redis.Client }

func (s *redisLiveQueryStore) RunQuery(name, sql string, hostIDs []uint) error {
    // store query in Redis targeting hostIDs
    return nil
}

func (s *redisLiveQueryStore) QueriesForHost(hostID uint) (map[string]string, error) {
    // return active queries assigned to this host
    return map[string]string{"query1": "SELECT * FROM osquery_info"}, nil
}

// Cron job cleanup
func scheduledCleanup(store fleet.LiveQueryStore, ctx context.Context) {
    inactiveIDs := []uint{42, 99}
    if err := store.CleanupInactiveQueries(ctx, inactiveIDs); err != nil {
        log.Printf("cleanup failed: %v", err)
    }
}
```

## Notes

- Designed to back a Redis store for ephemeral live query state.
- `CleanupInactiveQueries` is intended for scheduled cron execution to recover from missed `StopQuery` calls.
- Result count methods (`Get`, `Incr`, `Set`, `Delete`) are separate from query lifecycle to support rate-limiting and quota enforcement.
