Manages the lifecycle hook and scrub-job enqueueing for `historical_data` configuration changes in Fleet, coordinating activity emission and background data cleanup when historical dataset settings are toggled.

## Key Components

### Interfaces

- **`HistoricalDataActivityEmitter`** — Abstracts activity emission via `NewActivity`; satisfied by both free and EE service implementations.
- **`HistoricalDataScrubEnqueuer`** — Abstracts job queuing via `NewJob` and `HasQueuedJobWithArgs`; satisfied by `fleet.Datastore`. Defined locally to avoid worker-package import cycles.

### Functions

- **`OnHistoricalDataChanged`** — Primary hook called after a `SaveAppConfig` or `SaveTeam` commit. Iterates over tracked sub-keys (`uptime`, `vulnerabilities`) and for each changed value:
  - **Disable flip (`true→false`)**: enqueues a scrub job first, then emits a `disabled` activity.
  - **Enable flip (`false→true`)**: emits an `enabled` activity only; no scrub needed.
- **`enqueueHistoricalDataScrub`** — Internal helper that marshals job arguments and enqueues either a `chart_scrub_dataset_global` or `chart_scrub_dataset_fleet` job depending on scope (`fleetID == nil`). Deduplicates against already-queued identical jobs via `HasQueuedJobWithArgs`.

### Constants & Local Types

- **`chartScrubDatasetGlobalJobName` / `chartScrubDatasetFleetJobName`** — Job name constants mirrored from `server/worker/chart_scrub.go` to avoid import cycles.
- **`chartScrubGlobalArgs` / `chartScrubFleetArgs`** — Local payload structs whose JSON shape must stay in sync with the worker package.

## Usage Example

```go
err := fleet.OnHistoricalDataChanged(
    ctx,
    activityEmitter,   // HistoricalDataActivityEmitter
    datastore,         // HistoricalDataScrubEnqueuer
    currentUser,
    oldConfig.HistoricalData,
    newConfig.HistoricalData,
    nil,  // nil = global scope; pass *uint for team-scoped flip
    nil,
)
if err != nil {
    return fmt.Errorf("historical data hook: %w", err)
}
```

> **⚠️ Caller ordering requirement:** `OnHistoricalDataChanged` must be called **after** the config commit succeeds. Enqueueing before commit risks the worker picking up the scrub job before the updated config is visible, racing the collection cron.
