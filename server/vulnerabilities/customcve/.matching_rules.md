Defines custom CVE matching rules that address false negatives in NVD data by mapping software name patterns to specific CVEs and their resolved versions.

## Key Components

- **`CVEMatchingRule`** — Struct defining a single matching rule with fields for software name pattern (`NameLikeMatch`), optional exclusion pattern (`ExcludeIfNameContains`), source filter, CVE list, and resolved version
- **`CVEMatchingRules`** — Slice type for a collection of rules with bulk validation support
- **`getCVEMatchingRules()`** — Returns the hardcoded list of custom rules (currently covering Microsoft 365, git-gui Homebrew, and Windows Notepad CVEs)
- **`CVEMatchingRule.match()`** — Queries the datastore for matching software and returns `SoftwareVulnerability` records for any software with a version below `ResolvedInVersion`
- **`CVEMatchingRules.ValidateAll()`** — Validates all rules, ensuring each has CVEs, a name pattern, and a resolved version
- **`CheckCustomVulnerabilities()`** — Top-level entry point that runs all rules, inserts new vulnerabilities, and cleans up stale ones

## Usage Example

```go
vulns, err := customcve.CheckCustomVulnerabilities(
    ctx,
    datastore,
    slogLogger,
    time.Now(),
)
if err != nil {
    log.Fatal(err)
}
fmt.Printf("Found %d new custom vulnerabilities\n", len(vulns))
```

To add a new rule, append a `CVEMatchingRule` entry inside `getCVEMatchingRules()`:

```go
{
    NameLikeMatch:     "SomeApp",
    SourceMatch:       "programs",
    CVEs:              []string{"CVE-2025-12345"},
    ResolvedInVersion: "2.1.0",
},
```
