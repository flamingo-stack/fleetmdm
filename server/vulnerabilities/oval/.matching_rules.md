Defines OVAL vulnerability false-positive suppression rules for software packages where OVAL version metadata mismatches cause incorrect CVE matches.

## Key Components

- **`SoftwareMatchingRule`** — Struct representing a suppression rule with a package name, the resolved (fixed) version, a set of CVEs to suppress, and an optional conditional matcher function.
- **`SoftwareMatchingRules`** — Slice type of `SoftwareMatchingRule` with methods for bulk operations.
- **`GetKnownOVALBugRules()`** — Returns the hardcoded list of known false-positive rules (e.g., `microcode_ctl` date-vs-semver mismatches, `shim-x64` CVE set). Validates all rules before returning.
- **`MatchesAny(s fleet.Software, cve string) bool`** — Returns `true` if a given software/CVE pair matches any suppression rule, using `nvd.SmartVerCmp` for version comparison and an optional `MatchIf` guard for release-based filtering.
- **`Validate() error`** — Validates that a rule has non-empty `Name`, `VersionResolved`, and CVE entries.

## Usage Example

```go
rules, err := oval.GetKnownOVALBugRules()
if err != nil {
    log.Fatal(err)
}

sw := fleet.Software{
    Name:    "microcode_ctl",
    Version: "2.1",
    Release: "70.fc42",
}

if rules.MatchesAny(sw, "CVE-2024-28956") {
    // Suppressed — known OVAL false positive; skip reporting
}
```

## Notes

- Rules suppress findings only when `s.Version >= r.VersionResolved` (i.e., the package is already at or past the fix version), preventing true positives from being hidden.
- The optional `MatchIf` func allows release-string guards (e.g., Fedora release suffixes) for packages where the same version string appears across multiple distro generations.
