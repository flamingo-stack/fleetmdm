Defines the `StateMatchType` enum for OVAL (Open Vulnerability and Assessment Language) check enumeration, mapping string-based OVAL check types to integer constants and providing evaluation logic.

## Key Components

- **`StateMatchType`** — Integer enum representing OVAL `CheckEnumeration` values
- **Constants** — Four match type variants: `All`, `AtLeastOne`, `NoneSatisfy`, `OnlyOne`
- **`NewStateMatchType(val string)`** — Constructor that parses an OVAL `CheckEnumeration` string into a `StateMatchType`; defaults to `All` for unrecognized values
- **`Eval(nObjects, nState int) bool`** — Evaluates whether the number of objects matching the desired state (`nState`) satisfies the match type rule against the total matching objects (`nObjects`)

## Usage Example

```go
// Parse an OVAL check enumeration string
matchType := oval_parsed.NewStateMatchType("at least one")

// Evaluate: 3 total objects, 1 satisfies the state
satisfied := matchType.Eval(3, 1)
// satisfied == true (AtLeastOne requires nState >= 1)

// "none satisfy" / "none exist" both map to NoneSatisfy
noneType := oval_parsed.NewStateMatchType("none exist")
satisfied = noneType.Eval(5, 0)
// satisfied == true (NoneSatisfy requires nState == 0)

// All: every object must satisfy the state
allType := oval_parsed.NewStateMatchType("all")
satisfied = allType.Eval(3, 3)
// satisfied == true
satisfied = allType.Eval(3, 2)
// satisfied == false
```

## Notes

- Conforms to the [OVAL 5.10.1 CheckEnumeration spec](https://oval.mitre.org/language/version5.10.1/ovaldefinition/documentation/oval-common-schema.html#CheckEnumeration)
- Both `"none satisfy"` and `"none exist"` map to `NoneSatisfy` for backward compatibility
- Unknown string values fall back to `All` behavior
