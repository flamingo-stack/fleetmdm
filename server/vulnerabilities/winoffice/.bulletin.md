Defines the core data structures and serialization logic for Windows Office vulnerability bulletins used in Fleet's vulnerability detection pipeline.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `OfficeVersionPrefix` | `const` | Major.minor version prefix (`"16.0."`) shared by Office 2016 through Microsoft 365 |
| `SecurityUpdate` | `struct` | Maps a CVE identifier to the build version that resolves it |
| `VersionBulletin` | `struct` | Holds a slice of `SecurityUpdate` entries for a given version branch |
| `BulletinFile` | `struct` | Top-level bulletin envelope: schema version, build prefix index, and per-branch security data |
| `BulletinFile.Serialize` | `method` | Marshals the bulletin to JSON and writes it to a date-stamped file in the given directory |

## Usage Example

```go
bulletin := &winoffice.BulletinFile{
    Version: 1,
    BuildPrefixes: map[string]string{
        "19725": "2602",
    },
    Versions: map[string]*winoffice.VersionBulletin{
        "2602": {
            SecurityUpdates: []winoffice.SecurityUpdate{
                {
                    CVE:               "CVE-2025-12345",
                    ResolvedInVersion: "16.0.19725.20172",
                },
            },
        },
    },
}

if err := bulletin.Serialize(time.Now(), "/var/fleet/bulletins"); err != nil {
    log.Fatal(err)
}
```

The `BuildPrefixes` map lets callers resolve a raw build number (e.g., `"19725"`) to a named release branch (e.g., `"2602"`) before looking up `SecurityUpdates` in `Versions`. File naming is delegated to [`io.WinOfficeFileName`](https://github.com/flamingo-stack/fleetmdm/blob/main/server/vulnerabilities/io).
