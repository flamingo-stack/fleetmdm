Defines VulnCheck API data structures for CVE ingestion, extending the standard NVD API types with VulnCheck-specific fields.

## Key Components

| Type | Description |
|------|-------------|
| `VulnCheckCVEItem` | Wrapper struct that holds a single `VulnCheckCVE` entry, matching the `{"cve": ...}` JSON envelope |
| `VulnCheckCVE` | Extends `nvdapi.CVE` with an additional `vcConfigurations` field for VulnCheck-specific CPE configurations |
| `VulnCheckBackupResponse` | Top-level response from the VulnCheck backup API, containing a list of download URLs |
| `VulnCheckBackupData` | Holds a single backup file URL returned by the VulnCheck backup endpoint |
| `VulnCheckBackupDataFile` | Represents the contents of a downloaded VulnCheck backup file, containing a slice of `VulnCheckCVEItem` |

## Usage Example

```go
// Unmarshal a VulnCheck backup index response
var backupResp VulnCheckBackupResponse
if err := json.Unmarshal(body, &backupResp); err != nil {
    return err
}

// Iterate over backup file URLs and fetch each one
for _, entry := range backupResp.Data {
    // Download entry.URL and decode the file contents
    var dataFile VulnCheckBackupDataFile
    if err := json.Unmarshal(fileBody, &dataFile); err != nil {
        return err
    }
    // Access VulnCheck-specific configurations alongside standard NVD CVE fields
    for _, item := range dataFile.Vulnerabilities {
        cve := item.Item
        _ = cve.CVEID          // standard NVD field via embedded nvdapi.CVE
        _ = cve.VcConfigurations // VulnCheck-extended CPE configs
    }
}
```

## Notes

- `VulnCheckCVE` embeds `nvdapi.CVE` directly, so all standard NVD fields are available without wrapping.
- `vcConfigurations` is omitted from JSON output when empty (`omitempty`), keeping payloads compact.
