Manages SQLite database creation and population for the NVD CPE (Common Platform Enumeration) dictionary, providing schema initialization and bulk data insertion utilities.

## Key Components

| Function | Description |
|---|---|
| `sqliteDB` | Opens a read-write SQLite connection at the given path |
| `sqliteDBReadOnly` | Opens a read-only SQLite connection with 1GB memory-map optimization |
| `applyCPEDatabaseSchema` | Creates the `cpe_2` table, `cpe` compatibility view, `deprecated_by` table, FTS5 virtual table, and associated indexes |
| `generateCPEItem` | Transforms a `CPEItem` into flat insert values and a deprecation map |
| `GenerateCPEDB` | Orchestrates full CPE database generation: removes existing file, applies schema, bulk-inserts CPEs and deprecations, and populates FTS index |
| `bulkInsertCPEs` | Batch-inserts CPE records into `cpe_2` using parameterized multi-row `INSERT` |
| `bulkInsertDeprecations` | Batch-inserts deprecation relationships into `deprecated_by` using subquery lookups |

## Usage Example

```go
items, err := cpedict.Load("official-cpe-dictionary.xml")
if err != nil {
    log.Fatal(err)
}

err = nvd.GenerateCPEDB("/var/fleet/cpe.db", items)
if err != nil {
    log.Fatal(err)
}

db, err := sqliteDBReadOnly(ctx, "/var/fleet/cpe.db", logger)
if err != nil {
    log.Fatal(err)
}
defer db.Close()
```

## Notes

- Inserts are batched at **800 records** (`batchSize`) to avoid SQLite bind-parameter limits.
- The `cpe` view preserves backward compatibility for older Fleet versions that use `SELECT * FROM cpe`.
- FTS5 full-text search on `title` and `target_sw` is populated after all CPE rows are inserted for efficiency.
- Read-only connections apply `PRAGMA mmap_size = 1073741824` (1 GB) as a best-effort performance optimization.
