Schedules and manages Google Calendar events for Fleet hosts that are failing MDM compliance policies, running as a periodic cron job across teams.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `NewCalendarSchedule` | func | Creates and registers the calendar cron schedule with two jobs: cleanup and event processing |
| `cronCalendarEvents` | func | Entry point for event processing; loads app config and iterates over all teams |
| `cronCalendarEventsForTeam` | func | Processes calendar events for a single team, orchestrating passing/failing host logic |
| `processCalendarFailingHosts` | func | Fan-out worker pool (18 consumers) that processes failing hosts concurrently |
| `processFailingHostExistingCalendarEvent` | func | Handles calendar event updates for hosts with existing events, using distributed locking |
| `filterHostsWithSameEmail` | func | Deduplicates hosts sharing the same email, keeping the lowest host ID |
| `calendarConsumers` | const | Worker pool size (18) for concurrent host processing |
| `reloadFrequency` | const | Cache reload interval (30 minutes) |

## Usage Example

```go
calendarSchedule, err := cron.NewCalendarSchedule(
    ctx,
    instanceID,
    datastore,
    distributedLock,
    config.CalendarConfig{
        Periodicity: 5 * time.Minute,
    },
    logger,
)
if err != nil {
    log.Fatal(err)
}
calendarSchedule.Start()
```

## Notes

- Requires a Google Calendar integration configured at the app level (`appConfig.Integrations.GoogleCalendar`).
- Only one host per email is processed per team run (lowest `HostID` wins via `filterHostsWithSameEmail`).
- Distributed locking via `fleet.Lock` prevents race conditions between the cron job and calendar webhook callbacks during event updates.
- Hosts passing all policies have their calendar events removed; hosts failing policies get events created or updated.
- Hosts with no associated email are logged separately and skipped.
