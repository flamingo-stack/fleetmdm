Handles parsing, validation, and decoding of SAML authorization responses for the SSO package, including protection against XML canonicalization bomb attacks.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `DecodeSAMLResponse` | Function | Base64-decodes a raw SAMLResponse string |
| `ParseAndVerifySAMLResponse` | Function | Validates XML shape, then parses and cryptographically verifies a SAMLResponse via the SAML service provider |
| `validateSAMLResponseShape` | Function (internal) | Guards against canonicalization bombs by enforcing `maxSAMLResponseDepth` (100) and `maxSAMLResponseElements` (5000) limits before any signature checks |
| `validateAudiences` | Function (internal) | Ensures the assertion's audience restrictions match expected values |
| `resp` | Struct | Implements `fleet.Auth`; wraps a verified `*saml.Assertion` and exposes `UserID()`, `UserDisplayName()`, and `AssertionAttributes()` |
| `validDisplayNameAttrs` | Map | Canonical set of SAML/LDAP attribute names used to resolve a human-readable display name |

## Usage Example

```go
// Decode the raw SAMLResponse POST parameter
decoded, err := sso.DecodeSAMLResponse(r.FormValue("SAMLResponse"))
if err != nil {
    // handle decode error
}

// Parse and verify the response against the SAML service provider
auth, err := sso.ParseAndVerifySAMLResponse(
    samlProvider,
    decoded,
    requestID,  // original AuthnRequest ID
    acsURL,     // Assertion Consumer Service URL
)
if err != nil {
    // handle invalid/malformed response
}

// Access identity details
fmt.Println(auth.UserID())           // e.g. "alice@example.com"
fmt.Println(auth.UserDisplayName())  // e.g. "Alice Smith"

for _, attr := range auth.AssertionAttributes() {
    fmt.Printf("%s: %v\n", attr.Name, attr.Values)
}
```

## Security Notes

- XML shape validation (`validateSAMLResponseShape`) runs **before** any cryptographic checks to prevent canonicalization bomb DoS attacks on the unauthenticated SSO callback endpoint.
- Display name resolution iterates `validDisplayNameAttrs`, covering common LDAP (`cn`, `displayname`) and AD FS claim URIs to handle IdP inconsistencies.
