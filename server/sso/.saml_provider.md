Constructs `saml.ServiceProvider` instances for validating SAML responses across three SSO flows: metadata-only, session-based, and hybrid (session or IdP-initiated).

## Key Components

| Function | Description |
|---|---|
| `SAMLProviderFromConfiguredMetadata` | Builds a SAML provider using IdP metadata from Fleet's configured `SSOProviderSettings`. Used during SSO initiation. |
| `SAMLProviderFromSession` | Builds a SAML provider from a stored `Session`, returning the request ID, original URL, and `SSORequestData` for response validation. |
| `SAMLProviderFromSessionOrConfiguredMetadata` | Unified factory for the SSO callback — uses a session-backed provider for SP-initiated flows, or falls back to configured metadata when IdP-initiated login is enabled and no session ID is present. |

## Usage Example

```go
// SP-initiated: build provider from session on callback
provider, requestID, originalURL, reqData, err := sso.SAMLProviderFromSession(
    ctx,
    session,
    acsURL,
    entityID,
    expectedAudiences,
)

// IdP-initiated or session-backed (unified callback handler)
provider, requestID, redirectURL, err := sso.SAMLProviderFromSessionOrConfiguredMetadata(
    ctx,
    sessionID, // empty string triggers IdP-initiated path
    sessionStore,
    acsURL,
    ssoSettings,
    expectedAudiences,
)

// Metadata-only (no session, e.g. for validation preview)
provider, err := sso.SAMLProviderFromConfiguredMetadata(
    ctx,
    entityID,
    acsURL,
    &settings.SSOProviderSettings,
)
```

## Notes

- All three functions populate `IDPMetadata` via `GetMetadata` or `ParseMetadata` and configure `ValidateAudienceRestriction` where audience validation is required.
- `SAMLProviderFromSessionOrConfiguredMetadata` sets `AllowIDPInitiated` on the returned provider, gating IdP-initiated logins behind `settings.EnableSSOIdPLogin`.
- Session ID cookie usage (instead of URL parameters) is intentional — it prevents CSRF attacks as documented in the package-level comment.
