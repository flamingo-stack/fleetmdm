Constructs SAML authorization requests for initiating SSO login flows, creating sessions and generating IdP redirect URLs.

## Key Components

- **`CreateAuthorizationRequest`** — Primary entry point that builds a SAML `AuthnRequest`, stores a new SSO session in the provided `SessionStore`, and returns a session ID along with the IdP redirect URL.
- **`getDestinationURL`** — Extracts the HTTP Redirect Binding SSO endpoint URL from IdP metadata; returns an error if the binding is unsupported.
- **`generateSessionID`** — Generates a 24-character random session identifier used to correlate the IdP callback with the originating request.
- **`cacheLifetimeSeconds`** — Default session TTL constant (300 seconds / 5 minutes), used when `sessionTTLSeconds` is not provided.

## Usage Example

```go
sessionID, idpRedirectURL, err := sso.CreateAuthorizationRequest(
    ctx,
    samlProvider,    // *saml.ServiceProvider configured with IdP metadata
    sessionStore,    // SessionStore implementation (e.g., Redis-backed)
    "/dashboard",   // originalURL to redirect after successful auth
    0,               // 0 = use default 5-minute TTL
    sso.SSORequestData{},
)
if err != nil {
    return fmt.Errorf("initiating SSO: %w", err)
}

// Redirect the user's browser to the IdP
http.Redirect(w, r, idpRedirectURL, http.StatusFound)

// Store sessionID in a cookie so it can be matched on callback
http.SetCookie(w, &http.Cookie{Name: "sso_session", Value: sessionID})
```

## Notes

- The SAML request uses `HTTPRedirectBinding` for outbound requests and `HTTPPostBinding` for the expected IdP response.
- IdP metadata is serialized and cached alongside the session so response signatures can be validated on callback.
- `RelayState` is intentionally left empty — Fleet does not currently use it.
