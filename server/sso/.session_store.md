Manages SSO session state persistence using Redis, storing and retrieving SAML authentication session data across process boundaries during the single sign-on flow.

## Key Components

| Name | Type | Description |
|------|------|-------------|
| `Session` | struct | Holds SAML session state: request ID, IdP metadata, original URL, and optional request data |
| `SSORequestData` | struct | Optional payload attached to a session (host UUID, initiator) |
| `SessionStore` | interface | Defines create/get/expire/Fullfill operations against the backing Redis store |
| `NewSessionStore` | func | Constructor that wraps a `fleet.RedisPool` in a concrete `store` |
| `Fullfill` | method | Atomically fetches and deletes a session, preventing replay |

## Usage Example

```go
// Initialize the session store
pool := getRedisPool() // fleet.RedisPool
sessionStore := sso.NewSessionStore(pool)

// Creating a session during SSO initiation
err := sessionStore.create(
    sessionID,
    samlRequestID,
    "https://app.example.com/dashboard",
    idpMetadataXML,
    300, // 5-minute TTL
    sso.SSORequestData{HostUUID: "abc-123"},
)

// Consuming a session during SSO callback (fetch + delete in one call)
session, err := sessionStore.Fullfill(sessionID)
if err != nil {
    // session not found, expired, or already consumed
}
// session.RequestID must match InResponseTo in the SAMLResponse
```

## Notes

- Sessions are stored as JSON strings via Redis `SETEX`, automatically expiring after `lifetimeSecs`
- `get` always uses the primary Redis connection (not a replica) to avoid read-after-write inconsistency during the auth callback flow
- `Fullfill` deletes the session immediately after retrieval, preventing session reuse before TTL expiry
- Session IDs must be at least 8 characters; shorter IDs are rejected on `create`
