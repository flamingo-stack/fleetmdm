Manages Redis persistence for the Windows MDM reconciliation cursor, enabling the `mdm_windows_profile_manager` cron to perform paginated, bounded host processing across ticks.

## Key Components

- **`windowsReconCursorKey`** — Redis key constant (`mdm:windows:recon_cursor`) used to store the `host_uuid` cursor.
- **`GetMDMWindowsReconcileCursor`** — Retrieves the current cursor value; returns `""` if unset (key missing or Redis flushed), signalling the cron to restart from the beginning.
- **`SetMDMWindowsReconcileCursor`** — Persists the cursor value after each cron tick. An empty string signals a completed full pass.

## Usage Example

```go
// Retrieve the current reconciliation cursor
cursor, err := datastore.GetMDMWindowsReconcileCursor(ctx)
if err != nil {
    return err
}
// cursor == "" means start from the beginning

hosts, nextCursor, err := listHostsBatch(ctx, cursor)
if err != nil {
    return err
}

// Persist the cursor for the next tick
if err := datastore.SetMDMWindowsReconcileCursor(ctx, nextCursor); err != nil {
    return err
}
```

## Notes

- A missing Redis key is a safe no-op; the cron simply restarts from the beginning of the host list. Because reconciliation predicates skip already-converged hosts, redundant passes are low-cost.
- No TTL is set on the key intentionally — the cron overwrites it on every tick, so Redis eviction only causes one extra full pass at worst.
