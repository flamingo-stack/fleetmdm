Wraps a MySQL `fleet.Datastore` with Redis-backed operations, adding host enrollment limiting and optional host lookup caching on top of standard datastore functionality.

## Key Components

| Symbol | Type | Description |
|---|---|---|
| `Datastore` | struct | Embeds `fleet.Datastore` and a `fleet.RedisPool`; extends it with enrollment limiting and host caching |
| `Option` | func type | Functional option for configuring a `Datastore` at construction time |
| `WithEnforcedHostLimit` | Option | Enables host count enforcement based on the current license limit |
| `WithHostCache` | Option | Enables a Redis-backed TTL cache (with ±10% jitter) for `LoadHostByNodeKey` / `LoadHostByOrbitNodeKey` |
| `New` | func | Constructs a configured `Datastore` wrapping the provided `fleet.Datastore` and `fleet.RedisPool` |

## Usage Example

```go
import (
    "time"

    "github.com/fleetdm/fleet/v4/server/datastore/mysqlredis"
)

// Wrap an existing MySQL datastore with Redis-backed features.
ds := mysqlredis.New(
    mysqlDS,   // fleet.Datastore (MySQL)
    redisPool, // fleet.RedisPool
    mysqlredis.WithEnforcedHostLimit(500),        // reject enrollments beyond 500 hosts
    mysqlredis.WithHostCache(5 * time.Minute),    // cache node-key lookups for ~5 min
)

// ds satisfies fleet.Datastore and fleet.EnrollHostLimiter.
```

## Notes

- When `hostCacheEnabled` is `false` (no `WithHostCache` call, or TTL ≤ 0), all cache helpers short-circuit and Redis is never touched for lookups.
- A `singleflight.Group` (`hostCacheSF`) coalesces concurrent cache-miss fetches for the same key, preventing thundering-herd on Redis.
- Host cache details are implemented in the companion file [`host_cache.go`](https://github.com/flamingo-stack/fleetmdm/blob/main/server/datastore/mysqlredis/host_cache.go).
