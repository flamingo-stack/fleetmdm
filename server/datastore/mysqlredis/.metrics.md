Defines OpenTelemetry metrics instrumentation for the host lookup cache in the `mysqlredis` package, registering three labeled `Int64Counter` instruments via the global `MeterProvider`.

## Key Components

| Symbol | Type | Description |
|---|---|---|
| `hostCacheLookups` | `metric.Int64Counter` | Counts cache read attempts; `result` label: `hit`, `negative_hit`, `miss` |
| `hostCacheErrors` | `metric.Int64Counter` | Counts Redis/JSON errors; `op` label: `get`, `set`, `del` |
| `hostCacheInvalidations` | `metric.Int64Counter` | Counts invalidation events; `reason` label: `update`, `enroll`, `team`, `delete`, `cert` |
| `hostCacheLookupAttrs(result)` | helper | Returns `metric.AddOption` with `result` attribute |
| `hostCacheErrorAttrs(op)` | helper | Returns `metric.AddOption` with `op` attribute |
| `hostCacheInvalidationAttrs(reason)` | helper | Returns `metric.AddOption` with `reason` attribute |

All counters are registered under the `"fleet"` meter scope during `init()`. When no global `MeterProvider` is configured (e.g. in tests), `otel.Meter` returns a no-op meter and all counter operations silently succeed.

## Usage Example

```go
// Recording a cache hit
hostCacheLookups.Add(ctx, 1, hostCacheLookupAttrs("hit"))

// Recording a Redis GET error
hostCacheErrors.Add(ctx, 1, hostCacheErrorAttrs("get"))

// Recording an invalidation triggered by a host update
hostCacheInvalidations.Add(ctx, 1, hostCacheInvalidationAttrs("update"))
```

> These instruments are inactive until the host cache is enabled via `WithHostCache`. No explicit setup is required in test environments — the no-op meter handles all calls transparently.
