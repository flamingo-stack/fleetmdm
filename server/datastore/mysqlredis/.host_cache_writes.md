Cache invalidation wrapper layer for the `mysqlredis` datastore, ensuring Redis-backed host cache entries are purged after successful MySQL write operations on host records.

## Key Components

### Public Write Wrappers

| Method | Invalidation Strategy | Reason Label |
|---|---|---|
| `UpdateHost` | By node key (direct DEL via `invalidateAfterHostUpdate`) | `update` |
| `SerialUpdateHost` | By node key (direct DEL via `invalidateAfterHostUpdate`) | `update` |
| `UpdateHostOsqueryIntervals` | By host ID | `update` |
| `UpdateHostRefetchRequested` | By host ID | `update` |
| `UpdateHostRefetchCriticalQueriesUntil` | By host ID | `update` |
| `EnrollOrbit` | By host ID + direct key clear | `enroll` |
| `AddHostsToTeam` | Pipelined batch by IDs | `team` |
| `UpdateHostIdentityCertHostIDBySerial` | By host ID | `cert` |

### Private Helpers

- **`invalidateAfterHostUpdate`** — Optimized tail for update paths. Skips reverse-index GETs by DELing known node key entries directly via `pipelinedDEL`. Falls back to `hostCacheDeleteByID` when `NodeKey` is absent.
- **`invalidateAfterHostEnroll`** — Tail for enrollment paths that may create a host or rotate its node key. Adds a direct-key clear on top of `hostCacheDeleteByID` to close the pre-enrollment negative-cache race window.

## Usage Example

```go
// All wrappers follow this pattern: delegate → invalidate on success
func (d *Datastore) UpdateHost(ctx context.Context, host *fleet.Host) error {
    if err := d.Datastore.UpdateHost(ctx, host); err != nil {
        return err // short-circuit; do NOT invalidate on failure
    }
    d.invalidateAfterHostUpdate(ctx, host, "update")
    return nil
}
```

> **Important:** Invalidation is always skipped on inner errors to avoid poisoning the cache on transient MySQL failures. Reason labels (`update`, `enroll`, `team`, `delete`, `cert`) must match the low-cardinality set expected by the metrics collector in `metrics.go`.
