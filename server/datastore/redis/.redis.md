Redis connection pool management for Fleet MDM, providing both standalone and cluster Redis pool implementations with multi-tenant key prefix namespacing (OpenFrame extensions) and cluster-aware connection utilities.

## Key Components

### Types

- **`standalonePool`** — Wraps `redis.Pool` for single-node Redis; adds connection wait timeout support and key prefix namespacing via `Get()`.
- **`clusterPool`** — Wraps `redisc.Cluster` for Redis Cluster mode; supports read replicas and follow-redirections.
- **`PoolConfig`** — Configuration struct for pool creation, including TLS, auth, timeouts, cluster options, and the `KeyPrefix` field for multi-tenant namespacing.

### Functions

| Function | Description |
|---|---|
| `NewPool(config PoolConfig)` | Creates a `fleet.RedisPool`; auto-detects standalone vs. cluster mode. |
| `ReadOnlyConn(pool, conn)` | Marks a connection as read-only for Redis Cluster replica reads. |
| `ConfigureDoer(pool, conn)` | Wraps a connection with retry-on-redirect for cluster mode. |
| `SplitKeysBySlot(pool, keys...)` | Groups keys by Redis Cluster hash slot; returns all in one group for standalone. |
| `EachNode(pool, replicas, fn)` | Iterates over each cluster node (or single standalone node), calling `fn` with a prefixed connection. |
| `BindConn(pool, conn, keys...)` | Binds a connection to the node serving the given keys (cluster-aware). |
| `normalizeKeyPrefix(p)` | Validates and normalizes key prefix strings; rejects `{`/`}` characters. |
| `splitSeedNodes(server)` | Parses comma-separated or `redis://`-prefixed addresses into seed node slices. |
| `keyPrefixOf(pool)` | Helper to extract `KeyPrefix` from any `fleet.RedisPool` implementation. |

## Usage Example

```go
pool, err := redis.NewPool(redis.PoolConfig{
    Server:    "localhost:6379",
    Password:  "secret",
    KeyPrefix: "tenant1", // normalized to "tenant1:"
    ConnTimeout:  5 * time.Second,
    MaxIdleConns: 10,
    MaxOpenConns: 20,
})
if err != nil {
    log.Fatal(err)
}

conn := pool.Get()
defer conn.Close()

// Keys are automatically prefixed: "tenant1:mykey"
conn.Do("SET", "mykey", "value")

// Split keys by cluster slot before pipelining
groups := redis.SplitKeysBySlot(pool, "key1", "key2", "key3")
for _, group := range groups {
    // safe to pipeline within each group
}
```

> **OpenFrame Extension:** The `KeyPrefix` field on `PoolConfig` enables per-tenant Redis key namespacing. Prefixes must not contain `{` or `}` (which would collapse all keys into a single cluster hash slot). A trailing `:` is appended automatically if omitted.
