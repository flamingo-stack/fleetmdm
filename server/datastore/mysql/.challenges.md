Provides MySQL datastore implementations for one-time challenge lifecycle management: generation, atomic consumption, and expiration cleanup.

## Key Components

| Function | Description |
|---|---|
| `NewChallenge` | Generates a cryptographically random 24-byte, base64url-encoded challenge and persists it to the `challenges` table |
| `newChallenge` | Internal helper accepting any `sqlx.ExecerContext`, enabling challenge creation within existing transactions |
| `ConsumeChallenge` | Atomically validates and deletes a challenge within a retryable transaction; returns `sql.ErrNoRows` for missing, already-consumed, or expired challenges |
| `CleanupExpiredChallenges` | Bulk-deletes challenges older than `fleet.OneTimeChallengeTTL`; returns the number of rows removed |

## Usage Example

```go
// Generate a new one-time challenge
challenge, err := ds.NewChallenge(ctx)
if err != nil {
    log.Fatal(err)
}

// Later, validate and consume the challenge (e.g., during attestation)
err = ds.ConsumeChallenge(ctx, challenge)
if errors.Is(err, sql.ErrNoRows) {
    // challenge missing, already used, or expired
}

// Run periodically to purge stale challenges
deleted, err := ds.CleanupExpiredChallenges(ctx)
if err != nil {
    log.Fatal(err)
}
log.Printf("Removed %d expired challenges", deleted)
```

## Notes

- Challenges are consumed **exactly once**: the transaction reads, deletes, and validates expiry atomically, preventing replay attacks.
- An empty string passed to `ConsumeChallenge` is rejected immediately without a database round-trip.
- Expiry is governed by `fleet.OneTimeChallengeTTL`; challenges exceeding this TTL are treated as invalid on consumption and removed in bulk by `CleanupExpiredChallenges`.
