MySQL datastore implementation for managing user invitations in the Fleet MDM platform, handling CRUD operations for invite records and their associated team memberships.

## Key Components

- **`inviteAllowedOrderKeys`** — Security allowlist restricting `ListInvites` sort columns to `name`, `email`, `created_at`, `updated_at`, and `id`, preventing token/sensitive column disclosure via ordering.
- **`NewInvite`** — Creates an invite record with role validation and bulk-inserts team associations in a single transaction.
- **`ListInvites`** — Returns paginated/filtered invites using cursor-based listing with search support across `name` and `email` columns.
- **`Invite`** — Fetches a single invite by primary key ID.
- **`InviteByEmail`** / **`InviteByToken`** — Lookup helpers for invite retrieval by unique fields.
- **`DeleteInvite`** — Removes an invite record by ID.
- **`UpdateInvite`** — Updates invite fields and replaces team associations atomically within a transaction.
- **`loadTeamsForInvites`** — Private helper that batch-loads team memberships for a slice of invites using a single `IN` query, initializing `Teams` to an empty slice (never `null`) for consistent JSON output.

## Usage Example

```go
// Create a new invite with team membership
invite := &fleet.Invite{
    InvitedBy:  1,
    Email:      "newuser@example.com",
    Name:       "New User",
    Token:      "abc123token",
    SSOEnabled: false,
    GlobalRole: null.StringFrom("observer"),
    Teams: []fleet.UserTeam{
        {Team: fleet.Team{ID: 42}, Role: "maintainer"},
    },
}
created, err := ds.NewInvite(ctx, invite)

// List invites with search and pagination
invites, err := ds.ListInvites(ctx, fleet.ListOptions{
    MatchQuery: "example.com",
    OrderKey:   "created_at",
    Page:       0,
    PerPage:    20,
})

// Look up by token during acceptance flow
inv, err := ds.InviteByToken(ctx, tokenFromURL)
```
