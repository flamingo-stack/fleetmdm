MySQL datastore implementation for user CRUD operations, including creating, finding, listing, updating, and loading associated team/API endpoint data for Fleet users.

## Key Components

| Function | Description |
|---|---|
| `NewUser` | Inserts a new user record and associates teams and API endpoints within a transaction |
| `findUser` | Generic lookup by column (email or ID), loads teams and API endpoints |
| `HasUsers` | Returns whether any users exist in the database |
| `ListUsers` | Lists users with filtering, search, cursor-based pagination, and secure column ordering |
| `UsersByIDs` | Returns lightweight `UserSummary` records for a set of IDs |
| `UserByEmail` / `UserByID` | Convenience wrappers around `findUser` |
| `UserOrDeletedUserByID` | Looks up an active user, falls back to `users_deleted` table |
| `SaveUser` / `SaveUsers` | Persists updated user fields including settings (JSON-marshalled) |
| `loadTeamsForUsers` | Batch-loads team memberships for a slice of users |
| `loadAPIEndpointsForUsers` | Batch-loads allowed API endpoints for API-only users |
| `userAllowedOrderKeys` | Allowlist preventing sensitive column exposure via sort injection |

## Usage Example

```go
// Create a new user
user, err := ds.NewUser(ctx, &fleet.User{
    Name:       "Alice",
    Email:      "alice@example.com",
    GlobalRole: ptr.String(fleet.RoleAdmin),
})

// Lookup by email
user, err := ds.UserByEmail(ctx, "alice@example.com")

// List users on a specific team with search
users, err := ds.ListUsers(ctx, fleet.UserListOptions{
    TeamID:     42,
    MatchQuery: "alice",
    ListOptions: fleet.ListOptions{
        PerPage: 25,
        OrderKey: "name",
    },
})

// Save updated user
user.Name = "Alice Smith"
err = ds.SaveUser(ctx, user)
```

## Notes

- `settings` column is intentionally **excluded** from `userSelectColumns` and only persisted on `SaveUser`; use `UserSettings` to retrieve it explicitly.
- SSO-enabled users have `AdminForcedPasswordReset` suppressed at read time without modifying the database.
- `userAllowedOrderKeys` guards against SQL column injection via sort parameters; sensitive columns (`password`, `salt`) are excluded.
