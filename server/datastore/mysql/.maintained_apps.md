MySQL datastore implementation for Fleet-maintained apps (FMAs), providing CRUD and listing operations against the `fleet_maintained_apps` table with team-aware join logic.

## Key Components

| Function | Description |
|---|---|
| `UpsertMaintainedApp` | Inserts or updates an FMA record; on darwin, backfills `software_titles` and `software` table names using the FMA's canonical name when the row is new or changed |
| `GetMaintainedAppByID` | Fetches a single FMA by primary key, optionally including team-specific install status via `teamFMATitlesJoin` |
| `GetMaintainedAppBySlug` | Same as above but looks up by slug |
| `ListAvailableFleetMaintainedApps` | Paginated listing with name-based pagination, optional platform/match/available-only filters, and total count |
| `GetFMANamesByIdentifier` | Returns a `map[bundle_identifier]canonical_name` for all darwin FMAs |
| `ClearRemovedFleetMaintainedApps` | Deletes FMA rows whose slug is not in the provided keep-list (truncated in source) |
| `fleetMaintainedAppsTeamJoin` | Shared SQL fragment: LEFT JOINs `software_installers` and `vpp_apps_teams` to detect whether an FMA is already added to a team |
| `maintainedAppsAllowedOrderKeys` | Allowlist restricting `ORDER BY` to `fma.name` |

## Usage Example

```go
// Upsert a maintained app
app, err := ds.UpsertMaintainedApp(ctx, &fleet.MaintainedApp{
    Name:             "Google Chrome",
    Slug:             "google-chrome",
    Platform:         "darwin",
    UniqueIdentifier: "com.google.Chrome",
})

// List available apps for a team with pagination
teamID := uint(42)
apps, meta, err := ds.ListAvailableFleetMaintainedApps(ctx, &teamID, fleet.MaintainedAppListOptions{
    MatchQuery:    "chrome",
    Platform:      "darwin",
    AvailableOnly: true,
    ListOptions:   fleet.ListOptions{Page: 0, PerPage: 20},
})

// Look up canonical FMA names by bundle identifier (darwin only)
names, err := ds.GetFMANamesByIdentifier(ctx)
// names["com.google.Chrome"] == "Google Chrome"
```

## Notes

- **Name pagination**: `ListAvailableFleetMaintainedApps` paginates by distinct `fma.name` so that an app's macOS and Windows rows are never split across pages, while the total count reflects individual platform entries.
- **Windows matching**: The team join uses a `LIKE` pattern for Windows apps because `upgrade_code` is not surfaced in the FMA table; the shorter of `fma.name`/`fma.unique_identifier` is used as the prefix.
- **`ON DUPLICATE KEY UPDATE` semantics**: `RowsAffected == 0` means no change; the darwin name backfill is skipped in that case to avoid unnecessary UPDATE churn.
