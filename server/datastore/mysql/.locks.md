MySQL datastore implementation for distributed lock management and database lock inspection.

## Key Components

- **`Lock(ctx, name, owner, expiration)`** — Attempts to acquire a named lock using a priority chain of three strategies: extend an existing owned lock, overwrite an expired lock, or create a new lock. Returns `true` if the lock was obtained.
- **`Unlock(ctx, name, owner)`** — Releases a lock by setting its expiry to `CURRENT_TIMESTAMP`.
- **`DBLocks(ctx)`** — Queries InnoDB transaction lock waits, returning blocking/waiting thread info. Handles MySQL 5.x (`information_schema.innodb_lock_waits`) vs MySQL 8+ (`performance_schema.data_lock_waits`) via a one-time atomic check.
- **`innodbLockWaitsTableExists`** — Package-level `atomic.Int64` used as a thread-safe, one-time cache for the InnoDB table existence check (`0` = unchecked, `1` = exists, `-1` = absent).

## Usage Example

```go
// Acquire a distributed lock
acquired, err := ds.Lock(ctx, "cron:vulnerability_processing", "fleet-instance-1", 5*time.Minute)
if err != nil {
    log.Fatal(err)
}
if !acquired {
    log.Println("lock held by another owner, skipping")
    return
}
defer ds.Unlock(ctx, "cron:vulnerability_processing", "fleet-instance-1")

// Inspect current DB-level lock contention
locks, err := ds.DBLocks(ctx)
if err != nil {
    log.Fatal(err)
}
for _, l := range locks {
    fmt.Printf("blocking trx %s is blocking trx %s\n", l.BlockingTrxID, l.WaitingTrxID)
}
```

## Notes

- The lock chain in `Lock` tries `extendLockIfAlreadyAcquired` → `overwriteLockIfExpired` → `createLock`, stopping at the first successful row write.
- `DBLocks` always queries the **primary writer** to reflect real-time lock state, bypassing read replicas.
- The DB user must have `PROCESS` and `SELECT` privileges on `*.*` for `DBLocks` to succeed; an `accessDeniedError` is returned otherwise.
