Provides MySQL binary log and replica status inspection utilities for the Fleet MDM datastore, used to monitor replication lag and position across writer/reader nodes.

## Key Components

- **`MasterStatus` struct** — Holds the binary log `File` name and `Position` for the current writer node.
- **`Datastore.MasterStatus`** — Executes `SHOW BINARY LOG STATUS` (MySQL 8.4+) or `SHOW MASTER STATUS` (MySQL 8.0.x) on the writer, parsing results dynamically by column name for forward compatibility.
- **`Datastore.ReplicaStatus`** — Executes `SHOW REPLICA STATUS` on the reader, returning all columns as a `map[string]any` with `nil` values for SQL `NULL` fields.

## Usage Example

```go
// Get writer's current binary log position
ms, err := ds.MasterStatus(ctx, "8.4.0")
if err != nil {
    log.Fatal(err)
}
fmt.Printf("Binary log: %s @ position %d\n", ms.File, ms.Position)

// Get full replica status from reader
status, err := ds.ReplicaStatus(ctx)
if err != nil {
    log.Fatal(err)
}

// Check replication lag
if lag, ok := status["Seconds_Behind_Source"]; ok {
    fmt.Printf("Replica lag: %v seconds\n", lag)
}
```

## Notes

- **Version-aware SQL**: Automatically selects the correct statement based on the MySQL version prefix (`"8.0"` uses the deprecated `SHOW MASTER STATUS`; all other versions use `SHOW BINARY LOG STATUS`).
- **Dynamic column scanning**: Both methods scan columns by name rather than position, making them resilient to schema changes across MySQL versions.
- **Validation**: `MasterStatus` returns an error if either `File` or `Position` is empty/zero, preventing silent failures when the binary log is not configured.
