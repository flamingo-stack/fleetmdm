MySQL datastore implementation for managing conditional access bypass records for Fleet-managed hosts.

## Key Components

| Function | Description |
|---|---|
| `ConditionalAccessBypassDevice` | Grants a bypass for a host if it has no failing critical conditional-access policies; inserts or updates the `host_conditional_access` record |
| `ConditionalAccessConsumeBypass` | Atomically reads and deletes a bypass record, returning the `bypassed_at` timestamp (or `nil` if none exists); uses `FOR UPDATE SKIP LOCKED` to prevent concurrent consumption |
| `ConditionalAccessClearBypasses` | Truncates all bypass records from `host_conditional_access` |
| `ConditionalAccessBypassedAt` | Read-only lookup of the `bypassed_at` timestamp for a given host without consuming the record |

## Usage Example

```go
// Grant a bypass only if the host passes all critical conditional-access policies
err := ds.ConditionalAccessBypassDevice(ctx, hostID)
if err != nil {
    // Returns fleet.BadRequestError if host has failing critical policies
    log.Errorf("bypass denied: %v", err)
}

// Atomically consume the bypass (e.g., during MDM check-in)
bypassedAt, err := ds.ConditionalAccessConsumeBypass(ctx, hostID)
if err != nil {
    log.Errorf("consume bypass: %v", err)
}
if bypassedAt != nil {
    log.Infof("host %d bypass granted at %s", hostID, bypassedAt)
}

// Read bypass timestamp without consuming it
bypassedAt, err = ds.ConditionalAccessBypassedAt(ctx, hostID)

// Clear all bypasses (e.g., on policy reset)
err = ds.ConditionalAccessClearBypasses(ctx)
```

## Notes

- `ConditionalAccessBypassDevice` blocks if `policy_membership` contains any row where `conditional_access_enabled = 1`, `critical = 1`, and `passes = 0` for the given host.
- `ConditionalAccessConsumeBypass` wraps its SELECT + DELETE in a transaction using `FOR UPDATE SKIP LOCKED`, making concurrent consumers safe.
