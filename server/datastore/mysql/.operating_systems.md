MySQL datastore implementation for managing operating system records associated with Fleet-managed hosts.

## Key Components

| Function | Description |
|---|---|
| `ListOperatingSystems` | Retrieves all operating system records from the database |
| `ListOperatingSystemsForPlatform` | Filters operating systems by platform (e.g., `darwin`, `windows`) |
| `UpdateHostOperatingSystem` | Updates the OS association for a host, creating the OS record if needed |
| `GetHostOperatingSystem` | Returns the operating system record for a specific host |
| `CleanupHostOperatingSystems` | Removes orphaned OS records no longer associated with any host |
| `getOrGenerateOperatingSystemDB` | Fetches an existing OS record or inserts a new one |
| `isHostOperatingSystemUpdateNeeded` | Checks if the host's stored OS differs from the reported OS to avoid unnecessary writes |
| `upsertHostOperatingSystemDB` | Upserts the `host_operating_system` join table using `ON DUPLICATE KEY UPDATE` to avoid enrollment deadlocks |
| `getOSVersionID` / `nextOSVersionID` | Resolves or generates a shared `os_version_id` for OS name+version groupings |

## Usage Example

```go
// Update a host's operating system after an osquery report
hostOS := fleet.OperatingSystem{
    Name:          "macOS",
    Version:       "14.4.1",
    Arch:          "arm64",
    KernelVersion: "23.4.0",
    Platform:      "darwin",
    DisplayVersion: "14.4.1",
}

if err := ds.UpdateHostOperatingSystem(ctx, hostID, hostOS); err != nil {
    return err
}

// Retrieve the stored OS for a host
os, err := ds.GetHostOperatingSystem(ctx, hostID)
if err != nil {
    return err
}

// List all macOS operating systems
oses, err := ds.ListOperatingSystemsForPlatform(ctx, "darwin")
```

## Notes

- **Write optimization**: `UpdateHostOperatingSystem` performs a read-first check via `isHostOperatingSystemUpdateNeeded` to skip the transaction entirely when the OS hasn't changed.
- **`INSERT IGNORE`**: Used in `newOperatingSystemDB` to handle concurrent inserts safely, with a fallback re-query to recover the stored record.
- **`DisplayVersion`** is capped at 10 characters per the DB schema; longer values return an error before any DB write occurs.
