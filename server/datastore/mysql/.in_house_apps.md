MySQL datastore layer for managing in-house (`.ipa`) app records, including insert, update, delete, metadata retrieval, and configuration management for iOS and iPadOS platforms.

## Key Components

| Function | Description |
|---|---|
| `insertInHouseApp` | Creates paired `ios` + `ipados` rows in `in_house_apps` for a single `.ipa` upload, with duplicate detection and optional configuration |
| `getOrGenerateInHouseAppTitleID` | Optimistic get-or-insert for `software_titles`, keyed on `bundle_identifier` + `source` |
| `insertInHouseAppDB` | Low-level transactional insert into `in_house_apps` with label and category association |
| `inHouseAppHostStatusNamedQuery` | Builds a SQL `CASE` expression resolving install status (`installed`, `failed`, `pending`) from join aliases |
| `GetInHouseAppMetadataByTeamAndTitleID` | Fetches full installer metadata including labels, categories, display name, icon, and configuration |
| `SaveInHouseAppUpdates` | Transactionally updates installer fields, labels, categories, display name, and configuration |
| `DeleteInHouseApp` | Removes an in-house app and its associated pending installs and display name entries |

## Usage Example

```go
// Insert a new in-house app
installerID, titleID, err := ds.insertInHouseApp(ctx, &fleet.InHouseAppPayload{
    TeamID:          ptr.Uint(42),
    Title:           "My App",
    BundleID:        "com.example.myapp",
    Filename:        "myapp.ipa",
    StorageID:       "s3-object-key",
    Version:         "1.0.0",
    SelfService:     true,
    ValidatedLabels: &fleet.LabelIdentsWithScope{},
    Configuration:   []byte(`<plist>...</plist>`),
})

// Retrieve metadata by team + title
meta, err := ds.GetInHouseAppMetadataByTeamAndTitleID(ctx, ptr.Uint(42), titleID)

// Update an existing installer
err = ds.SaveInHouseAppUpdates(ctx, &fleet.UpdateSoftwareInstallerPayload{
    InstallerID: installerID,
    StorageID:   "new-s3-key",
    Filename:    "myapp-v2.ipa",
    Version:     "2.0.0",
})
```

> **Note:** Each `.ipa` upload creates two `in_house_apps` rows — one per platform (`ios`, `ipados`) — sharing the same storage object but with separate installer IDs. Configuration is written under both rows so platform-specific install command builders resolve it correctly.
