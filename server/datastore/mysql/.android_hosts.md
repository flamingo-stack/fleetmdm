Provides MySQL datastore operations for managing Android device records, including upsert logic with duplicate detection and graceful conflict resolution.

## Key Components

| Function | Description |
|---|---|
| `CreateDeviceTx` | Upserts an Android device within a transaction — inserts if new, updates if exists, or resolves duplicates |
| `UpdateDeviceTx` | Updates an existing Android device record within a transaction |
| `insertDevice` | Inserts a new row into `android_devices` and returns the device with its generated ID |
| `updateDevice` | Updates all fields of an existing `android_devices` row by ID using named parameters |
| `deleteDuplicate` | Logs and resolves an unexpected duplicate state by deleting one conflicting record |
| `deleteDevice` | Deletes a single `android_devices` row by ID |

## Usage Example

```go
// Create or update a device within a transaction
device := &android.Device{
    DeviceID:             "abc123",
    EnterpriseSpecificID: "eid-xyz",
    HostID:               42,
    LastPolicySyncTime:   time.Now(),
    AppliedPolicyID:      &policyID,
    AppliedPolicyVersion: 3,
}

err := ds.DB.WithTx(ctx, func(tx sqlx.ExtContext) error {
    result, err := ds.CreateDeviceTx(ctx, tx, device)
    if err != nil {
        return err
    }
    log.Printf("Device ID: %d", result.ID)
    return nil
})

// Update an existing device
err = ds.DB.WithTx(ctx, func(tx sqlx.ExtContext) error {
    return ds.UpdateDeviceTx(ctx, tx, device)
})
```

## Duplicate Handling

`CreateDeviceTx` queries by both `device_id` and `enterprise_specific_id` and follows this decision tree:

```text
0 matches → INSERT
1 match   → UPDATE
2 matches → DELETE one duplicate, UPDATE the other
3+ matches → error (should never occur)
```

Duplicates are treated as unexpected data integrity issues — an error is logged before resolution.
