Database migration that updates built-in host labels, replacing the previous label set (from `20161229171615`) with a revised set of platform-specific built-in labels.

## Key Components

- **`Labels2()`** — Returns the updated set of five built-in `fleet.Label` definitions targeting `All Hosts`, `macOS`, `Ubuntu Linux`, `CentOS Linux`, and `MS Windows`, each using osquery's `os_version` table.
- **`Up_20170223171234(tx *sql.Tx)`** — Applies the migration: removes old labels via `Down_20161229171615`, then inserts the new labels using `INSERT IGNORE`.
- **`Down_20170223171234(tx *sql.Tx)`** — Rolls back the migration: removes the new labels by name/type/query, then restores the old labels via `Up_20161229171615`.
- **`init()`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the Fleet migration client. The `Labels2()` function can also be referenced directly when seeding or validating label state:

```go
for _, label := range Labels2() {
    fmt.Printf("Label: %s | Query: %s\n", label.Name, label.Query)
}
```

## Notes

- The `Up` migration is **idempotent** — it first tears down the prior label set before inserting, and uses `INSERT IGNORE` to avoid duplicate errors.
- The `Down` migration restores the previous label set by delegating back to `Up_20161229171615`, ensuring clean reversibility.
