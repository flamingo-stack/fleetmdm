Database migration file that inserts the initial set of built-in platform labels into the Fleet `labels` table.

## Key Components

- **`Labels1() []fleet.Label`** — Returns the canonical set of five built-in labels: `All Hosts`, `Mac OS X`, `Ubuntu Linux`, `CentOS Linux`, and `MS Windows`. Each label uses an osquery SQL query against `osquery_info` to match hosts by `build_platform`.
- **`Up_20161229171615(tx *sql.Tx) error`** — Idempotent migration (uses `INSERT IGNORE`) that inserts all labels from `Labels1()` into the `labels` table.
- **`Down_20161229171615(tx *sql.Tx) error`** — Rolls back by deleting each built-in label matched by `name`, `label_type`, and `query`.
- **`init()`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This file is invoked automatically by the migration framework. The `Labels1()` function can also be referenced directly in tests or seeding logic:

```go
package main

import (
    "fmt"
    "github.com/fleetdm/fleet/v4/server/datastore/mysql/migrations/data"
)

func main() {
    for _, label := range data.Labels1() {
        fmt.Printf("Label: %s | Platform: %s | Query: %s\n",
            label.Name, label.Platform, label.Query)
    }
}
```

> **Note:** `Up_20161229171615` uses `INSERT IGNORE`, making it safe to re-run without producing duplicate labels. `Down_20161229171615` performs exact-match deletes, so only labels matching all three fields (`name`, `label_type`, `query`) are removed.
