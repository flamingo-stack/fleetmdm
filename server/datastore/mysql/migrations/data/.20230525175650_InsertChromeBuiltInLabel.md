Database migration that inserts a built-in Chrome OS label into Fleet's labels table, enabling device grouping for Chrome OS hosts.

## Key Components

- **`Up_20230525175650`** — Inserts an idempotent `chrome` built-in label using `INSERT IGNORE`, targeting hosts where `platform = 'chrome'` via an `os_version` query
- **`Down_20230525175650`** — No-op rollback; the label insertion is not reversed
- **`init`** — Registers both migration functions with `MigrationClient`

## Label Details

| Field | Value |
|---|---|
| Name | `chrome` |
| Query | `select 1 from os_version where platform = 'chrome';` |
| Description | All Chrome hosts |
| Label Type | `LabelTypeBuiltIn` |

## Usage Example

```go
// Migration runs automatically via MigrationClient during fleet server startup.
// The INSERT IGNORE ensures idempotency — safe to run multiple times.

label := fleet.Label{
    Name:        "chrome",
    Query:       "select 1 from os_version where platform = 'chrome';",
    Description: "All Chrome hosts",
    LabelType:   fleet.LabelTypeBuiltIn,
}
```

This migration is part of Fleet's database versioning system. The `INSERT IGNORE` clause makes it safe to re-run without creating duplicate labels. The down migration is intentionally a no-op, as removing a built-in label could disrupt existing host groupings.
