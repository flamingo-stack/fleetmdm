Database migration that scopes label name uniqueness from a global constraint to a per-team constraint, enabling shared-database multitenancy where different teams can define labels with the same name.

## Key Components

| Symbol | Description |
|--------|-------------|
| `Up_20260620000001` | Forward migration: adds a virtual generated column `openframe_team_key` and replaces the global `UNIQUE(name)` index with a composite `UNIQUE(name, openframe_team_key)` |
| `Down_20260620000001` | Rollback stub (no-op; intentionally left empty) |
| `openframe_team_key` | `INT UNSIGNED VIRTUAL` generated column computing `IFNULL(team_id, 0)`, collapsing `NULL` team rows onto sentinel `0` to preserve MySQL unique-key semantics |
| `idx_label_team_name` | Replacement composite unique index over `(name, openframe_team_key)` |
| `idx_label_unique_name` | Legacy global unique index dropped after the new index is in place |

## Usage Example

This migration is registered automatically via `init()` and executed by the migration runner. No manual invocation is needed.

```go
// Registered automatically on package import:
func init() {
    MigrationClient.AddMigration(Up_20260620000001, Down_20260620000001)
}
```

## Design Notes

- **NULL-safe uniqueness**: MySQL treats `NULL` as distinct in unique keys, breaking upsert semantics for global (`team_id = NULL`) labels. The virtual column maps `NULL → 0` (a sentinel; real team IDs start at `1`) to enforce exactly-one-name-per-team.
- **Idempotent**: Each step guards with `columnExists` / `indexExists` checks before executing DDL, making the migration safe to re-run.
- **Prefix-query compatible**: Index column order `(name, openframe_team_key)` preserves existing `WHERE name = ?` prefix lookups.
- **Upstream watch**: Marked in [`openframe/docs/upstream-sync-conflict-resolution.md`](https://github.com/flamingo-stack/fleetmdm/blob/main/openframe/docs/upstream-sync-conflict-resolution.md) — must be re-verified if upstream Fleet alters the `labels` table schema.
