Database migration that adds the `openframe_tenant_uuid` bridge column and unique index to the Fleet `teams` table, enabling shared-database multitenancy by mapping Flamingo tenant UUIDs to Fleet integer team IDs.

## Key Components

| Symbol | Description |
|---|---|
| `Up_20260629000001` | Idempotent migration that adds `CHAR(36) NULL` column `openframe_tenant_uuid` and a unique index `idx_teams_openframe_tenant_uuid` to the `teams` table |
| `Down_20260629000001` | No-op rollback — column and index are left in place on downgrade |
| `init()` | Registers both migration functions with `MigrationClient` at package init |

## Usage Example

This migration runs automatically via the `MigrationClient` at Fleet startup. To invoke manually in tests or scripts:

```go
db, _ := sql.Open("mysql", dsn)
tx, _ := db.Begin()

if err := Up_20260629000001(tx); err != nil {
    tx.Rollback()
    log.Fatal(err)
}
tx.Commit()
```

## Design Notes

- **Bridge pattern** — `teams.openframe_tenant_uuid` links the Flamingo platform identity (UUID, used by `FLEET_OPENFRAME_TENANT_UUID`) to Fleet's integer `team_id` without altering existing foreign keys.
- **NULL semantics** — the column is `NULL` for non-OpenFrame teams; MySQL treats each `NULL` as distinct, so the unique index permits multiple non-OpenFrame teams while enforcing one team per tenant UUID.
- **Idempotency** — `columnExists` and `indexExists` guards prevent duplicate-column/index errors on re-run.
- **Upstream sync risk** — documented in `openframe/docs/upstream-sync-conflict-resolution.md`; re-verify if a future upstream Fleet release rebuilds the `teams` table.
