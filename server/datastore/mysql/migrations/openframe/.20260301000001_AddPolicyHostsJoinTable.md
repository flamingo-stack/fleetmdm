Database migration that creates the `policy_hosts` join table, establishing a many-to-many relationship between policies and hosts.

## Key Components

- **`Up_20260301000001`** — Creates the `policy_hosts` table if it does not already exist. The table includes:
  - `policy_id` and `host_id` foreign keys with `ON DELETE CASCADE` referencing `policies` and `hosts` respectively
  - A unique composite index on `(policy_id, host_id)` to prevent duplicate associations
  - Auto-incremented primary key and a `created_at` timestamp
- **`Down_20260301000001`** — No-op rollback; the table is left in place on downgrade
- **`init()`** — Registers both migration functions with `MigrationClient` at package load time

## Usage Example

This migration runs automatically as part of the standard migration lifecycle. No manual invocation is needed.

```go
// Migration is registered via init() and executed by the migration client:
MigrationClient.AddMigration(Up_20260301000001, Down_20260301000001)

// The resulting schema creates associations such as:
// INSERT INTO policy_hosts (policy_id, host_id) VALUES (42, 7);
// Duplicate (policy_id, host_id) pairs are rejected by the unique index.
// Deleting a policy or host automatically removes related rows via CASCADE.
```

## Notes

- The migration is **idempotent** (`CREATE TABLE IF NOT EXISTS`), making it safe to re-run.
- The empty `Down` function means this migration does not support automated rollback — manual intervention is required to drop the table if needed.
