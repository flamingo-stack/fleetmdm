Database migration that creates the `query_hosts` join table, establishing a many-to-many relationship between queries and hosts.

## Key Components

| Function | Description |
|---|---|
| `Up_20260301000002` | Creates the `query_hosts` table with foreign keys to `queries` and `hosts` |
| `Down_20260301000002` | No-op rollback (table removal not implemented) |

**Table Schema — `query_hosts`:**

| Column | Type | Notes |
|---|---|---|
| `id` | `int unsigned` | Auto-increment primary key |
| `query_id` | `int unsigned` | FK → `queries(id)`, cascades on delete |
| `host_id` | `int unsigned` | FK → `hosts(id)`, cascades on delete |
| `created_at` | `timestamp` | Defaults to `CURRENT_TIMESTAMP` |

A unique index on `(query_id, host_id)` prevents duplicate associations.

## Usage Example

```go

// Manual invocation (within a transaction)
```

The migration is idempotent (`CREATE TABLE IF NOT EXISTS`), so re-running it against an existing schema is safe.
