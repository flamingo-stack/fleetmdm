Database migration that removes the `policy_membership_history` table and replaces it with a streamlined `policy_membership` table, retaining only the most recent policy evaluation result per host.

## Key Components

| Function | Description |
|---|---|
| `Up_20211202092042` | Applies the migration: drops the old view, removes foreign keys, creates the new table, migrates latest records, and drops the history table |
| `Down_20211202092042` | No-op rollback (migration is intentionally irreversible) |

## Migration Steps

The `Up` function performs the following in order:

1. **Drops** the existing `policy_membership` view (idempotent)
2. **Removes foreign key constraints** from `policy_membership_history` referencing `policies` and `hosts`
3. **Creates** a new `policy_membership` table with:
   - Composite primary key on `(policy_id, host_id)`
   - Cascading foreign keys to `policies` and `hosts`
   - Indexes on `passes`, `policy_id`, and `(host_id, passes)` for query performance
4. **Migrates** only the latest record per `(policy_id, host_id)` pair from the history table
5. **Drops** `policy_membership_history`

## Notes

- The migration is **idempotent** — safe to re-run due to `DROP VIEW IF EXISTS`, `CREATE TABLE IF NOT EXISTS`, and `DROP TABLE IF EXISTS` guards
- The rollback (`Down`) is a **no-op** since history data is permanently discarded during the upgrade
