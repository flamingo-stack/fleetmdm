Database migration that creates the `teams` and `user_teams` tables, and extends `hosts` and `users` tables to support multi-team functionality in FleetMDM.

## Key Components

- **`Up_20210601000001`** — Applies the migration with the following idempotent changes:
  - Creates the `teams` table with `id`, `created_at`, `name` (unique), and `description` columns
  - Creates the `user_teams` join table mapping users to teams with a role, referencing both `users` and `teams` via cascading foreign keys
  - Adds a nullable `team_id` foreign key column to `hosts` (with `ON DELETE SET NULL`)
  - Adds a nullable `global_role` column to `users`
- **`Down_20210601000001`** — No-op rollback (schema changes are not reversed)
- **`init`** — Registers the migration with `MigrationClient`

## Schema Overview

```text
teams           → id, created_at, name (UNIQUE), description
user_teams      → user_id (FK), team_id (FK), role  [composite PK]
hosts           → + team_id (FK → teams.id, SET NULL on delete)
users           → + global_role (VARCHAR 64, nullable)
```

## Usage Example

This migration is run automatically by the migration client at startup or via the database migration CLI. It is safe to run multiple times due to `IF NOT EXISTS` guards and explicit column/FK existence checks:

```go
// Registered automatically via init()
MigrationClient.AddMigration(Up_20210601000001, Down_20210601000001)

// Manually invoking within a transaction (for testing)
if err := Up_20210601000001(tx); err != nil {
    log.Fatal("migration failed:", err)
}
```

## Notes

- All tables use `InnoDB` with `utf8mb4_unicode_ci` collation
- Column and FK additions use `columnExists`/`fkExists` helpers to ensure idempotency on re-runs
