Database migration that modifies the `host_mdm_managed_certificates.type` column to allow `NULL` values and removes the `'ndes'` default, enabling certificate ingestion flows where the CA type is unknown.

## Key Components

| Symbol | Description |
|---|---|
| `Up_20260522195234` | Alters `host_mdm_managed_certificates.type` to `NULL DEFAULT NULL`, removing the forced `'ndes'` default |
| `Down_20260522195234` | No-op rollback; column schema change is considered safe to leave in place |

## Migration Details

**Table affected:** `host_mdm_managed_certificates`  
**Column affected:** `type`  
**Type:** `ENUM('digicert', 'custom_scep_proxy', 'ndes', 'smallstep')`

**Before:** `NOT NULL DEFAULT 'ndes'`  
**After:** `NULL DEFAULT NULL`

This migration is **idempotent** — safe to re-run. It addresses non-proxied MDM certificate ingestion flows (introduced in PR 2.2) where Fleet is not in the issuance path and cannot determine the CA type. Previously, such rows would receive a misleading `'ndes'` default; they now receive `NULL`.

> All existing `INSERT` call sites specify `type` explicitly, so removing the default does not affect existing behavior.
