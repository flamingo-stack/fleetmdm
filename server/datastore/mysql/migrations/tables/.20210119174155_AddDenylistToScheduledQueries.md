Database migration that adds a nullable `denylist` column to the `scheduled_queries` table, allowing scheduled queries to be excluded from query result aggregation.

## Key Components

- **`Up20210119174155`** — Idempotent `ALTER TABLE` that adds a `TINYINT(1) DEFAULT NULL` column named `denylist` to `scheduled_queries`. Skips execution if the column already exists.
- **`Down20210119174155`** — Drops the `denylist` column from `scheduled_queries`, reverting the migration.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Applied automatically by the migration runner.
// To run manually via the Fleet CLI:
// fleet prepare db --config /etc/fleet/fleet.yml

// The resulting schema change:
// ALTER TABLE scheduled_queries
//   ADD COLUMN denylist TINYINT(1) DEFAULT NULL;
```

## Notes

- The `Up` migration is **idempotent** — safe to run multiple times without error, guarded by `columnExists()`.
- A `NULL` value is intentional as the default, distinguishing "not set" from explicit `true`/`false` denylist states.
