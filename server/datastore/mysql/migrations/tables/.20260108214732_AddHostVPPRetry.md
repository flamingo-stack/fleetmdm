Database migration that adds a `retry_count` column to the `host_vpp_software_installs` table to support tracking VPP software installation retry attempts.

## Key Components

- **`Up_20260108214732`** — Idempotent migration that adds `retry_count INT NOT NULL DEFAULT 0` to `host_vpp_software_installs` if the column does not already exist.
- **`Down_20260108214732`** — No-op rollback; the column is not removed on downgrade.
- **`init`** — Registers the migration with `MigrationClient`.

## Usage Example

This migration is applied automatically via the Fleet migration runner. No manual invocation is required.

```bash
# Apply all pending migrations (includes this one)
fleet prepare db --config /etc/fleet/fleet.yml
```

To verify the migration was applied:

```sql
SHOW COLUMNS FROM host_vpp_software_installs LIKE 'retry_count';
```

Expected result:

```text
+-------------+------+------+-----+---------+-------+
| Field       | Type | Null | Key | Default | Extra |
+-------------+------+------+-----+---------+-------+
| retry_count | int  | NO   |     | 0       |       |
+-------------+------+------+-----+---------+-------+
```

## Notes

- The migration is **idempotent** — safe to run multiple times; it checks for column existence via `columnExists` before executing the `ALTER TABLE`.
- The empty `Down` function means this migration is intentionally **irreversible** without a manual schema change.
