Database migration that converts the Fleet MySQL database and all its tables from `utf8` to `utf8mb4` character set encoding, enabling full Unicode support including 4-byte characters (e.g., emoji).

## Key Components

- **`changeCharacterSet(tx *sql.Tx, charset string) error`** — Core helper that alters the database default character set and iterates over all tables in the current schema, converting each to the specified charset with `utf8mb4_unicode_ci` collation. Skips execution when the `FLEET_TEST_DISABLE_COLLATION_UPDATES` environment variable is set (used during collation testing).

- **`Up_20170306075207(tx *sql.Tx) error`** — Applies the migration by upgrading to `utf8mb4`. Marked as idempotent.

- **`Down_20170306075207(tx *sql.Tx) error`** — Rolls back the migration by reverting to standard `utf8`.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client — no direct invocation is needed.

```go
// Registered automatically on package import:
MigrationClient.AddMigration(Up_20170306075207, Down_20170306075207)

// To disable collation updates during tests:
os.Setenv("FLEET_TEST_DISABLE_COLLATION_UPDATES", "1")
```

## Notes

- The `FLEET_TEST_DISABLE_COLLATION_UPDATES` env var provides a test escape hatch to bypass schema-level charset changes without skipping the migration entirely.
- The rollback downgrades to `utf8` (3-byte MySQL variant), which does **not** restore full 4-byte character support — rollback is lossy if 4-byte characters were stored.
