Database migration that creates the `host_users` table for tracking user accounts associated with managed hosts.

## Key Components

- **`Up_20210708143152`** — Creates the `host_users` table (idempotent via `CREATE TABLE IF NOT EXISTS`) with columns for host association, Unix user attributes (`uid`, `username`, `groupname`), lifecycle timestamps (`created_at`, `removed_at`), and user type classification. Enforces a unique constraint on `(host_id, uid, username)` and cascading deletes tied to the parent `hosts` record.
- **`Down_20210708143152`** — No-op rollback; the table is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Schema

```text
host_users
├── id            INT UNSIGNED AUTO_INCREMENT PK
├── host_id       INT UNSIGNED → hosts(id) ON DELETE CASCADE
├── uid           INT UNSIGNED
├── username      VARCHAR(255)
├── groupname     VARCHAR(255)
├── created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP
├── removed_at    TIMESTAMP NULL
├── user_type     VARCHAR(255)
└── UNIQUE        (host_id, uid, username)
```

## Notes

- `removed_at` being nullable allows soft-deletion tracking — a non-`NULL` value indicates the user was observed as removed from the host.
- The cascade delete on `host_id` ensures user records are cleaned up automatically when a host is deregistered.
