Database migration that transitions the `policies` table from referencing shared queries via a `query_id` foreign key to storing proprietary (self-contained) query data directly on each policy record.

## Key Components

**`Up_20211116184030(tx *sql.Tx) error`**
The primary migration function that performs the following steps in order:
1. Adds columns `name`, `query`, `description`, `author_id`, and `platforms` to `policies` (idempotent check via `columnsExists`)
2. Creates indexes `idx_policies_author_id` and `idx_policies_team_id`
3. Adds a foreign key constraint linking `author_id` to `users(id)` with `ON DELETE SET NULL`
4. Migrates existing data from the shared `queries` table into the new `policies` columns via a `JOIN` update
5. Resolves duplicate policy names (caused by multiple policies sharing the same `query_id`) by appending ` (id)` suffixes
6. Adds a unique index `idx_policies_unique_name` on the `name` column
7. Removes the foreign key reference to `queries` and drops the `query_id` column entirely

**`Down_20211116184030(tx *sql.Tx) error`**
No-op rollback — returns `nil` immediately (migration is irreversible by design).

**`indexNameByColumnName(tx *sql.Tx, table, column string) (string, error)`**
Helper that queries `INFORMATION_SCHEMA.STATISTICS` to resolve the index name associated with a given column, used before dropping the `query_id` index.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
func init() {
    MigrationClient.AddMigration(Up_20211116184030, Down_20211116184030)
}
```

The migration runner invokes `Up_20211116184030` within a transaction. All DDL and DML steps are guarded by existence checks (`columnsExists`, `indexExistsTx`, `constraintExists`) making the migration safe to re-run.
