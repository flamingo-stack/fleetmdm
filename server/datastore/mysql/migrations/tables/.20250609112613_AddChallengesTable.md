Database migration that creates the `challenges` table for storing single-use, randomly generated challenge strings used in authentication or verification flows.

## Key Components

- **`Up_20250609112613`** — Creates the `challenges` table if it does not already exist (idempotent). The table stores base64 URL-encoded 32-character challenge strings as the primary key, with `created_at` and `updated_at` timestamps.
- **`Down_20250609112613`** — No-op rollback; the table is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient` at package load time.

## Table Schema

| Column | Type | Notes |
|---|---|---|
| `challenge` | `CHAR(32)` | Primary key; base64 URL-encoded random string |
| `created_at` | `TIMESTAMP(6)` | Set on insert |
| `updated_at` | `TIMESTAMP(6)` | Auto-updated on row change |

Engine: `InnoDB`, charset: `utf8mb4_unicode_ci`.

> **Design note:** Challenges are intended for single-use. Once a challenge is validated it must be deleted from this table to prevent replay attacks.
