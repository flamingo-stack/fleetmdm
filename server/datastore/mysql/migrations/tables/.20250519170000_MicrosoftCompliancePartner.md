Database migration that creates tables and modifies schema to support Microsoft Compliance Partner integration, enabling device compliance status tracking and conditional access policy control via Microsoft Intune and Entra ID.

## Key Components

- **`Up_20250519170000`** — Applies the migration, creating two new tables and adding a column to `policies`:
  - `microsoft_compliance_partner_integrations` — Stores Microsoft tenant credentials and setup state (one row per tenant, unique on `tenant_id`)
  - `microsoft_compliance_partner_host_statuses` — Tracks per-host Entra `device_id`, `user_principal_name`, and last reported `managed`/`compliant` status
  - `conditional_access_enabled` column added to `policies` — Boolean flag to include/exclude a policy from conditional access evaluation
- **`Down_20250519170000`** — No-op rollback (tables are not dropped)
- **`init`** — Registers both migration functions with `MigrationClient`

## Schema Details

| Table | Primary Key | Notable Constraints |
|---|---|---|
| `microsoft_compliance_partner_integrations` | `id` (auto-increment) | `UNIQUE` on `tenant_id` |
| `microsoft_compliance_partner_host_statuses` | `host_id` | Mirrors `hosts.id` |

## Usage Example

This migration runs automatically via the Fleet migration client. To apply manually:

```go
// Executed by the Fleet migration runner — not called directly.
// To run all pending migrations:
fleet db migrate
```

All three schema changes are **idempotent** (`CREATE TABLE IF NOT EXISTS`, `columnExists` guard), so re-running the migration is safe.
