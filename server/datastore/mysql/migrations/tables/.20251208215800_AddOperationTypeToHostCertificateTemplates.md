Database migration that adds an `operation_type` column and foreign key constraint to the `host_certificate_templates` table, enabling tracking of whether a certificate is being installed or removed — consistent with other MDM profile tables.

## Key Components

- **`Up_20251208215800`** — Idempotent migration that performs two guarded schema changes:
  - Adds `operation_type VARCHAR(20)` column (defaulting to `'install'`) if it does not already exist
  - Adds a foreign key constraint referencing `mdm_operation_types.operation_type` with `ON UPDATE CASCADE` if not already present
- **`Down_20251208215800`** — No-op rollback; the migration is not reversed
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration is applied automatically by the Fleet migration runner. To apply or inspect it manually:

```bash
# Apply all pending migrations (includes this one)
fleet prepare db --config /etc/fleet/fleet.yml

# Verify the column was added
mysql -u fleet -p fleet -e "DESCRIBE host_certificate_templates;"
```

After migration, the `host_certificate_templates` table will have:

```text
| Column         | Type        | Default   | Notes                        |
|----------------|-------------|-----------|------------------------------|
| operation_type | VARCHAR(20) | 'install' | FK → mdm_operation_types     |
```

## Notes

- Both schema changes use idempotency guards (`columnExists`, `constraintExists`) making the migration safe to re-run
- `VARCHAR(20)` with a FK is used for consistency with other MDM profile tables; an `ENUM('install', 'remove')` would be more efficient
