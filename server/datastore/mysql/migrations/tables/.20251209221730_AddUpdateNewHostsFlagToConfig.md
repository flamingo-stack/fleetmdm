Database migration that adds the `UpdateNewHosts` flag to macOS MDM update configurations in both global app config and per-team configs, setting it based on whether macOS updates are already configured.

## Key Components

- **`Up_20251209221730`** — Applies the migration by setting `MDM.MacOSUpdates.UpdateNewHosts` to `true` if `MacOSUpdates` is already configured, for both global `AppConfig` and all team configs. Idempotent by design.
- **`Down_20251209221730`** — No-op rollback; the migration is not reversible.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the Fleet migration client. No manual invocation is needed, but the core logic follows this pattern:

```go
// Global config update
updateAppConfigJSON(tx, func(config *fleet.AppConfig) error {
    config.MDM.MacOSUpdates.UpdateNewHosts = optjson.SetBool(
        config.MDM.MacOSUpdates.Configured(),
    )
    return nil
})

// Per-team config update
var config fleet.TeamConfig
json.Unmarshal(rawTeamConfig, &config)
config.MDM.MacOSUpdates.UpdateNewHosts = optjson.SetBool(
    config.MDM.MacOSUpdates.Configured(),
)
b, _ := json.Marshal(config)
tx.Exec(`UPDATE teams SET config = ? WHERE id = ?`, b, teamID)
```

## Notes

- The migration is **idempotent**: re-running it produces the same result since `UpdateNewHosts` is derived directly from `Configured()`.
- Team configs are loaded, unmarshalled, updated, and re-persisted in a loop within the same transaction.
- `Down_20251209221730` is intentionally empty — backfilled boolean fields do not require reversal.
