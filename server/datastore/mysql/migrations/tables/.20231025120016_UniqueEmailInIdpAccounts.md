Database migration that enforces email uniqueness in the `mdm_idp_accounts` table by removing duplicate entries, adding a unique index, and introducing `created_at`/`updated_at` timestamp columns.

## Key Components

- **`Up_20231025120016`** — Idempotent forward migration that performs three operations:
  - Deletes duplicate email rows, keeping the lexicographically largest `uuid` per email group
  - Adds a `UNIQUE KEY unique_idp_email` on the `email` column (skipped if already exists)
  - Adds `created_at` and `updated_at` `TIMESTAMP` columns (skipped if already present)
- **`Down_20231025120016`** — No-op rollback; uniqueness constraints and timestamps are not reversed
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration is auto-registered and run by the migration client. No direct invocation is needed.

```go
// Migration is registered automatically via init()
// To apply all pending migrations:
MigrationClient.Up(db)
```

To verify the migration applied correctly, inspect the table schema:

```sql
SHOW INDEX FROM mdm_idp_accounts WHERE Key_name = 'unique_idp_email';
SHOW COLUMNS FROM mdm_idp_accounts LIKE 'created_at';
```

## Notes

- The duplicate-deletion strategy is **arbitrary by design** — `MAX(uuid)` uses lexicographic comparison; no semantic ordering is implied
- All three steps are **idempotent**: index and column additions are guarded by `indexExistsTx` and `columnsExists` helpers
- The rollback is intentionally empty; restoring removed duplicates is not feasible
