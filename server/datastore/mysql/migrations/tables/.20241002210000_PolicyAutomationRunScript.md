Database migration that adds `script_id` column and foreign key constraint to the `policies` table, enabling policy automation to trigger script execution.

## Key Components

- **`Up_20241002210000`** — Idempotent migration that conditionally adds:
  - `script_id INT UNSIGNED DEFAULT NULL` column to the `policies` table
  - Foreign key `fk_policies_script_id` referencing `scripts(id)`
- **`Down_20241002210000`** — No-op rollback (schema changes are not reversed)
- **`init()`** — Registers the migration with `MigrationClient`

## Usage Example

This migration runs automatically via the Fleet migration system. To apply manually:

```bash
fleetctl prepare db --config /etc/fleet/fleet.yml
```

The migration is idempotent — safe to run multiple times using `columnExists` and `fkExists` guards:

```go
// Guards prevent duplicate column/FK errors on re-run
if !columnExists(tx, "policies", "script_id") {
    // ALTER TABLE only executes if column is absent
}

if !fkExists(tx, "policies", "fk_policies_script_id") {
    // FK only added if it doesn't already exist
}
```

After this migration, policies can reference a script to execute when the policy triggers automation:

```sql
-- Link a policy to a remediation script
UPDATE policies SET script_id = 42 WHERE id = 7;
```

## Notes

- `script_id` is nullable (`DEFAULT NULL`), so existing policies remain unaffected
- The referenced `scripts` table must exist before this migration runs
