Database migration that adds `is_kernel` column to `software_titles` table and creates the `kernel_host_counts` table for tracking kernel software across hosts.

## Key Components

- **`Up_20250813205039`** — Applies the migration in three steps:
  1. Adds `is_kernel TINYINT(1)` column to `software_titles` (idempotent guard via `columnExists`)
  2. Backfills existing rows using regex/name matching for Debian/Ubuntu (`linux-image-*`), Amazon Linux (`kernel`), and RHEL (`kernel-core`) packages
  3. Creates `kernel_host_counts` table linking kernel software titles to host counts per OS version and team
- **`Down_20250813205039`** — No-op rollback (destructive schema changes are not reversed)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20250813205039, Down_20250813205039)
```

The `kernel_host_counts` table schema:

```text
kernel_host_counts
├── id                 INT UNSIGNED AUTO_INCREMENT (PK)
├── software_title_id  INT UNSIGNED → software_titles(id) ON DELETE CASCADE
├── software_id        INT UNSIGNED
├── os_version_id      INT UNSIGNED
├── hosts_count        INT UNSIGNED
└── team_id            INT UNSIGNED
    UNIQUE: (os_version_id, team_id, software_id)
```

## Notes

- The `is_kernel` backfill only targets `rpm_packages` and `deb_packages` sources
- Column addition is idempotent; the backfill `UPDATE` always runs on migration apply
