Database migration that creates two tables for managing host identity SCEP (Simple Certificate Enrollment Protocol) certificates: `host_identity_scep_serials` for serial number tracking and `host_identity_scep_certificates` for storing certificate metadata and PEM data.

## Key Components

- **`Up_20250707095725`** — Idempotent migration creating both tables. Serial auto-increment starts at `2` to reserve serial `1` for the CA certificate. Enforces a `CHECK` constraint validating PEM format and a foreign key from certificates to serials.
- **`Down_20250707095725`** — No-op rollback; tables are left in place on downgrade.

## Schema Overview

**`host_identity_scep_serials`**

| Column | Type | Notes |
|---|---|---|
| `serial` | `bigint unsigned` | Auto-increment PK, starts at 2 |
| `created_at` | `DATETIME(6)` | Defaults to `NOW(6)` |

**`host_identity_scep_certificates`**

| Column | Type | Notes |
|---|---|---|
| `serial` | `bigint unsigned` | PK, FK → `host_identity_scep_serials.serial` |
| `host_id` | `int unsigned` | Nullable, indexed |
| `name` | `varchar(255)` | Indexed for quick revocation lookups |
| `not_valid_before` / `not_valid_after` | `datetime` | Certificate validity window |
| `certificate_pem` | `text` | Full PEM (audit/debug only); CHECK enforces `-----BEGIN CERTIFICATE-----` prefix |
| `public_key_raw` | `VARBINARY(100)` | For fast verification without parsing PEM |
| `revoked` | `tinyint(1)` | Revocation flag, default `0` |

## Usage Example

```go
// Applied automatically by the migration client at startup

// Manual invocation within a transaction
if err := Up_20250707095725(tx); err != nil {
    log.Fatalf("migration failed: %v", err)
}
```
