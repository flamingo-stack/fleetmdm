Database migration that creates the `distributed_query_executions` table, which tracks the execution status of distributed queries across hosts.

## Key Components

- **`Up_20161118212515`** — Creates the `distributed_query_executions` table with the following columns:
  - `id` — Auto-incrementing primary key
  - `host_id` — References the host executing the query
  - `distributed_query_campaign_id` — References the parent query campaign
  - `status` — Integer execution status code
  - `error` — Optional error message (up to 1024 chars)
  - `execution_duration` — Duration in nanoseconds/milliseconds as a bigint
  - Unique constraint on `(host_id, distributed_query_campaign_id)` preventing duplicate execution records per host per campaign
- **`Down_20161118212515`** — Drops the `distributed_query_executions` table
- **`init`** — Registers both migration functions with `MigrationClient`
