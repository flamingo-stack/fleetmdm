Adds a `last_restarted_at` column to the `hosts` table and backfills it by calculating the last restart time from existing `uptime` and `detail_updated_at` values.

## Key Components

- **`Up_20251124162948`** — Idempotent migration that adds `last_restarted_at datetime(6)` to `hosts` (if not present), then backfills all rows using `DATE_SUB(detail_updated_at, INTERVAL uptime/1000 MICROSECOND)`. Defaults to `0001-01-01 00:00:00.000000` when `uptime` is zero or `detail_updated_at` is `NULL`.
- **`Down_20251124162948`** — No-op rollback; column removal is left as a manual operation.

## Usage Example

This migration runs automatically via the `MigrationClient` on startup. To apply or roll back manually:

```bash
# Apply
fleet prepare db --config /etc/fleet/fleet.yml

# Roll back (no-op for this migration)
fleet prepare db --config /etc/fleet/fleet.yml --rollback
```

To query the new column after migration:

```sql
SELECT hostname, last_restarted_at
FROM hosts
WHERE last_restarted_at > '0001-01-01 00:00:00.000000'
ORDER BY last_restarted_at DESC;
```

> **Note:** The down migration is intentionally a no-op. Dropping `last_restarted_at` manually requires `ALTER TABLE hosts DROP COLUMN last_restarted_at`.
