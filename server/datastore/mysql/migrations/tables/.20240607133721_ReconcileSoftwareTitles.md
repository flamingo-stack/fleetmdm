Database migration that reconciles `software_titles` by backfilling missing title records and updating stale `title_id` references in the `software` table.

## Key Components

- **`Up_20240607133721`** — Runs the forward migration in two idempotent steps:
  1. Upserts any distinct `(name, source, browser)` combinations from `software` that are missing from `software_titles`
  2. Updates `software.title_id` for rows where the foreign key is `NULL` or points to the wrong title
- **`Down_20240607133721`** — No-op rollback; data reconciliation is considered safe to leave in place
- **`init`** — Registers both functions with `MigrationClient`

## Usage Example

This migration runs automatically via the Fleet migration runner. To execute manually during development:

```go
// Applied as part of the standard migration sequence
fleetctl prepare db --config /etc/fleet/fleet.yml

// Or directly via the migration client
MigrationClient.AddMigration(Up_20240607133721, Down_20240607133721)
```

## Behavior Notes

- **Idempotent**: `ON DUPLICATE KEY UPDATE id = id` prevents duplicate inserts; the `UPDATE` uses a guard condition (`title_id IS NULL OR title_id != st.id`) to skip already-correct rows
- **Target audience**: Instances that do not run the vulnerabilities job, where `software_titles` may fall out of sync with `software`
- Both SQL statements execute within the same transaction `tx`, ensuring atomicity
