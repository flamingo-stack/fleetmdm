Database migration that adds a `require_all` boolean column to `mdm_configuration_profile_labels` and `mdm_declaration_labels` tables, and migrates existing "include all" label filter records accordingly.

## Key Components

- **`Up_20241110152841`** — Idempotent up migration that:
  - Adds `require_all BOOL NOT NULL DEFAULT false` to `mdm_configuration_profile_labels` if not already present
  - Adds `require_all BOOL NOT NULL DEFAULT false` to `mdm_declaration_labels` if not already present
  - Backfills `require_all = true` for all rows where `exclude = false` (preserving the semantic: "include all" label filters)
- **`Down_20241110152841`** — No-op rollback (column removal is not performed)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client. No direct invocation is required.

```go
// Applied automatically during fleet database migrations:
// fleet prepare db --config /etc/fleet/fleet.yml

// Schema change applied:
// ALTER TABLE mdm_configuration_profile_labels
//   ADD COLUMN require_all BOOL NOT NULL DEFAULT false;

// Data backfill applied:
// UPDATE mdm_configuration_profile_labels
//   SET require_all = true WHERE exclude = false;
```

## Notes

- The migration is **idempotent**: `columnExists` guards prevent errors if the column was already added (e.g., from a previous partial run).
- The `require_all` flag distinguishes **"include all"** (`require_all = true`, `exclude = false`) from **"include any"** label filter semantics introduced in this migration.
- The down migration is intentionally empty — schema rollback is left to the operator.
