Database migration that adds an `errors` JSON column to the `cron_stats` table, enabling structured error tracking for cron job statistics.

## Key Components

| Component | Description |
|-----------|-------------|
| `Up_20241126140021` | Applies the migration — idempotently adds an `errors JSON` column to `cron_stats` if it does not already exist |
| `Down_20241126140021` | No-op rollback; the column is intentionally left in place on downgrade |
| `init()` | Registers both migration functions with `MigrationClient` at package load time |

## Behaviour Notes

- **Idempotent** — uses `columnExists` to guard the `ALTER TABLE` statement, making the migration safe to run multiple times without error.
- **Rollback is a no-op** — the down migration does nothing, so the column persists if a rollback is triggered.

## Usage Example

This migration runs automatically via the `MigrationClient` during the standard Fleet database upgrade process. No manual invocation is required.

```go
// Executed automatically by the migration runner on startup.
// To apply manually during development:
err := Up_20241126140021(tx)
if err != nil {
    log.Fatalf("migration failed: %v", err)
}
```

After the migration, the `cron_stats` table gains a nullable `errors` JSON column suitable for storing structured error payloads from cron job runs:

```sql
ALTER TABLE cron_stats ADD COLUMN errors JSON;
```
