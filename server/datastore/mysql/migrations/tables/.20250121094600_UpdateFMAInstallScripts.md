Database migration that updates Fleet Managed App (FMA) install scripts for a set of Fleet-maintained macOS applications, adding graceful app-quit logic and backup handling before overwriting installed `.app` bundles.

## Key Components

- **`Up_20250121094600`** — Main migration function that:
  - Queries `fleet_library_apps` joined with `script_contents` for a predefined set of app tokens
  - Injects a `quit_application` shell function into each install script
  - Inserts a backup step (`mv` existing `.app` to a temp `.bkp`) before the copy step
  - Handles a Docker Desktop special case (`com.electron.dockerdesktop`) for both install and uninstall scripts
  - Patches symlink lines (`/bin/ln`) to guard against missing directories
  - Updates `script_contents` with the modified script and a recalculated MD5 checksum

- **`Down_20250121094600`** — No-op rollback (migration is not reversible)

- **`quitApplicationFunc`** — Embedded shell function that gracefully quits a macOS app by bundle ID using `osascript`, with a 10-second timeout and root/GUI session guard

- **`knownGoodAppFilenames`** — Lookup map correcting `.app` filename mismatches between the `name` field in `fleet_library_apps` and the actual filesystem name (e.g. `"visual-studio-code"` → `"Visual Studio Code.app"`)

## Usage Example

This migration runs automatically via the `MigrationClient` on Fleet server startup. It targets these app tokens:

```go
appTokens := []string{
    "1password", "brave-browser", "docker", "figma",
    "google-chrome", "visual-studio-code", "firefox",
    "notion", "slack", "whatsapp", "postman",
}
```

The migration is idempotent — if `fleet_library_apps` is empty (fresh deployment), it exits cleanly without error.
