Database migration that adds a `previous_token` column and corresponding index to the `host_device_auth` table, enabling token rotation tracking for host device authentication.

## Key Components

- **`Up_20260217200906`** — Idempotent migration that adds a nullable `VARCHAR(255)` column `previous_token` and an index `idx_host_device_auth_previous_token` to `host_device_auth`. Uses `columnExists` and `indexExistsTx` guards to safely re-run without errors.
- **`Down_20260217200906`** — No-op rollback; column and index are left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically via the Fleet migration runner. To apply manually:

```bash
fleetctl prepare db --config /etc/fleet/fleet.yml
```

To inspect the resulting schema:

```sql
DESCRIBE host_device_auth;
-- previous_token | varchar(255) | YES | MUL | NULL |

SHOW INDEX FROM host_device_auth WHERE Key_name = 'idx_host_device_auth_previous_token';
```

## Notes

- The column uses `utf8mb4_unicode_ci` collation, consistent with the rest of the Fleet schema.
- The migration is **idempotent** — safe to run multiple times or in environments where partial migrations may have been applied.
- The empty `Down` function means this migration is **irreversible** by design; manual `ALTER TABLE DROP COLUMN` is required if rollback is needed.
