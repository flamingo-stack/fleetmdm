Adds a nullable `gigs_all_disk_space` decimal column to the `host_disks` table via an idempotent database migration, intended to track total disk space for Linux hosts.

## Key Components

- **`Up_20251015103900`** — Applies the migration by adding the `gigs_all_disk_space DECIMAL(10,2)` column to `host_disks` if it does not already exist. The column is nullable since it is only relevant for Linux hosts.
- **`Down_20251015103900`** — No-op rollback; the column is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the `MigrationClient` on application startup. No manual invocation is needed. To apply or roll back manually during development:

```go
// Apply
err := Up_20251015103900(tx)

// Rollback (no-op)
err := Down_20251015103900(tx)
```

**Resulting schema change:**

```sql
ALTER TABLE host_disks
ADD COLUMN gigs_all_disk_space DECIMAL(10,2);
```

> The migration is idempotent — it checks for column existence before executing `ALTER TABLE`, making it safe to run multiple times without error.
