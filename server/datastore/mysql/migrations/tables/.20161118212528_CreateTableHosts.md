Database migration that creates the `hosts` table, which stores osquery-enrolled host inventory data including hardware specs, OS details, and network identifiers.

## Key Components

- **`Up_20161118212528`** — Creates the `hosts` table with `CREATE TABLE IF NOT EXISTS` (idempotent). Defines columns for host identity, OS metadata, hardware info, and soft-delete support.
- **`Down_20161118212528`** — Drops the `hosts` table via `DROP TABLE IF EXISTS`.
- **`init()`** — Registers both migration functions with `MigrationClient`.

### Table Schema Highlights

| Column | Type | Purpose |
|---|---|---|
| `osquery_host_id` | `varchar(255)` | Unique osquery-assigned identifier |
| `node_key` | `varchar(255)` | Unique enrollment key (binary collation) |
| `host_name` / `uuid` | `varchar(255)` | Host identity fields |
| `platform` / `os_version` | `varchar(255)` | OS metadata |
| `cpu_*` / `hardware_*` | `varchar`/`int` | Hardware inventory |
| `deleted` / `deleted_at` | `tinyint`/`timestamp` | Soft-delete pattern |
| `primary_ip_id` | `INT UNSIGNED` | FK reference to network interfaces |

**Indexes:** Primary key on `id`, unique keys on `node_key` and `osquery_host_id`, fulltext index on `host_name`.
