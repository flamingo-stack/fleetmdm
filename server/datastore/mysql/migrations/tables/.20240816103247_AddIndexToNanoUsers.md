Adds a unique index constraint on the `id` column of the `nano_users` table to satisfy MySQL 8.4.2's foreign key requirements from `nano_enrollments`.

## Key Components

- **`Up_20240816103247`** – Idempotent migration that adds a `UNIQUE` constraint (`idx_unique_id`) on `nano_users.id` if it does not already exist, using `indexExistsTx` to guard against re-application.
- **`Down_20240816103247`** – No-op rollback; the constraint is left in place on downgrade.
- **`init`** – Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the `MigrationClient` during Fleet database schema upgrades. No manual invocation is required.

```go
// Migration is registered on package init and executed by the migration runner:
MigrationClient.AddMigration(Up_20240816103247, Down_20240816103247)

// The Up function guards against duplicate execution:
if !indexExistsTx(tx, "nano_users", "idx_unique_id") {
    _, err := tx.Exec(`ALTER TABLE nano_users ADD CONSTRAINT idx_unique_id UNIQUE (id)`)
}
```

## Notes

- **MySQL 8.4.2 compatibility** – Without this constraint, `nano_enrollments` foreign keys referencing `nano_users.id` fail validation under stricter MySQL 8.4.2 enforcement.
- **Idempotent** – Safe to run multiple times; the `indexExistsTx` check prevents duplicate constraint errors.
