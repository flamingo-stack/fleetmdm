Database migration that adds composite indexes on `name`, `source`, and `browser` columns to the `software_titles` and `software` tables.

## Key Components

- **`Up_20231207102321`** — Applies the migration idempotently using `indexExistsTx` checks before altering tables:
  - Adds a `UNIQUE INDEX` (`idx_sw_titles`) on `software_titles(name, source, browser)`
  - Adds a non-unique `INDEX` (`idx_sw_name_source_browser`) on `software(name, source, browser)`
- **`Down_20231207102321`** — No-op rollback; indexes are not removed on downgrade.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20231207102321, Down_20231207102321)

// Applied during database initialization or migration run
err := MigrationClient.Up(db)
```

To apply manually in a transaction context:

```go
err := Up_20231207102321(tx)
if err != nil {
    log.Fatalf("migration failed: %v", err)
}
```

## Notes

- Both index additions are **idempotent** — safe to run multiple times without error.
- The `software_titles` index enforces **uniqueness**, preventing duplicate `(name, source, browser)` combinations.
- The `software` index is **non-unique**, optimizing lookups and joins on the same column set.
- The `Down` function is intentionally empty — dropping these indexes is considered safe to skip.
