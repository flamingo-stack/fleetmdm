Database migration that adds a `tpm_pin_set` boolean column to the `host_disks` table to track whether a TPM PIN has been configured on a host's disk.

## Key Components

- **`Up_20250803000000`** — Idempotent migration that adds `tpm_pin_set BOOL DEFAULT false` to `host_disks` if the column does not already exist.
- **`Down_20250803000000`** — No-op rollback; the column is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically via the Fleet migration runner. To run manually:

```bash
fleetctl prepare db --config /etc/fleet/fleet.yml
```

The resulting schema change:

```sql
ALTER TABLE host_disks
ADD COLUMN tpm_pin_set bool DEFAULT false;
```

After migration, `host_disks` rows will include `tpm_pin_set = false` by default until explicitly updated when a TPM PIN is detected on the host.

## Notes

- The migration is **idempotent** — safe to run multiple times; `columnExists` guards against duplicate `ALTER TABLE` errors.
- The down migration is intentionally empty to avoid data loss on rollback.
