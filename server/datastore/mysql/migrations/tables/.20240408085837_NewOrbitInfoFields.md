Database migration that adds `desktop_version` and `scripts_enabled` columns to the `host_orbit_info` table.

## Key Components

- **`Up_20240408085837`** — Idempotent migration that alters `host_orbit_info`, adding:
  - `desktop_version VARCHAR(50) DEFAULT NULL` — tracks the Fleet Desktop version on the host
  - `scripts_enabled TINYINT(1) DEFAULT NULL` — indicates whether script execution is enabled on the host
- **`Down_20240408085837`** — No-op rollback; columns are not removed on downgrade
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration runs automatically via the `MigrationClient` during Fleet database schema upgrades. No manual invocation is required.

```go
// Migration is registered on package init and applied by the migration runner:
MigrationClient.AddMigration(Up_20240408085837, Down_20240408085837)
```

```go
// Idempotency check prevents duplicate column errors on re-run:
if !columnsExists(tx, "host_orbit_info", "desktop_version", "scripts_enabled") {
    // ALTER TABLE only executes if columns are absent
}
```

## Notes

- The migration is **idempotent** — safe to run multiple times; the `columnsExists` guard skips the `ALTER TABLE` if columns already exist
- The rollback (`Down`) is intentionally empty; dropping these columns on downgrade is not implemented
