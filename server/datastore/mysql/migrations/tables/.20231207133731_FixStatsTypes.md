Database migration that fixes invalid `last_executed` timestamps and corrects numeric column types in the `scheduled_query_stats` table.

## Key Components

- **`Up_20231207133731`** — Applies the migration in two idempotent steps:
  1. Resets any rows where `last_executed` has a year of `0000` to the Unix epoch (`1970-01-01 00:00:01`)
  2. Alters six statistics columns (`average_memory`, `executions`, `output_size`, `system_time`, `user_time`, `wall_time`) to `BIGINT UNSIGNED NOT NULL`, guarded by a `columnExists` check
- **`Down_20231207133731`** — No-op rollback; the type changes are not reversed
- **`init`** — Registers both functions with `MigrationClient`

## Usage Example

This migration is applied automatically by the Fleet migration runner. To run manually:

```bash
fleetctl prepare db --config /etc/fleet/fleet.yml
```

Or via the Go migration client directly in tests:

```go
// Applying the migration in a test transaction
tx, _ := db.Begin()
if err := Up_20231207133731(tx); err != nil {
    log.Fatal(err)
}
tx.Commit()
```

## Notes

- The `last_executed` fix targets bad data emitted by osquery; the root cause is addressed in a subsequent PR
- The `ALTER TABLE` block is skipped entirely if `average_memory` no longer exists, making the migration safe to re-run
