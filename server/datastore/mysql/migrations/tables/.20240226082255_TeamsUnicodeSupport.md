Database migration that adds Unicode/emoji support to the `teams` table by replacing a standard name index with a binary-collation virtual column and unique index.

## Key Components

- **`Up_20240226082255`** — Idempotent migration that:
  1. Drops the existing `idx_name` index on `teams` if present
  2. Adds a `name_bin` virtual column (`VARCHAR(255) COLLATE utf8mb4_bin`) generated from `name`
  3. Creates a unique index `idx_name_bin` on the virtual column to support emoji and full Unicode uniqueness
- **`Down_20240226082255`** — No-op rollback (returns `nil`)

## Usage Example

This migration runs automatically via the `MigrationClient` on startup:

```go
// Registered in init(); executed by the migration runner
MigrationClient.AddMigration(Up_20240226082255, Down_20240226082255)
```

To apply manually during development:

```bash
fleetctl prepare db --config /etc/fleet/fleet.yml
```

## Notes

- The migration is **idempotent** — each step checks for existence before executing, making it safe to re-run.
- The `utf8mb4_bin` collation enforces byte-level comparison, ensuring emoji characters (e.g., `🚀`) are treated as distinct rather than being collapsed by case-insensitive collation.
- The `Down` migration is intentionally a no-op; restoring the original index would require a separate manual step if needed.
