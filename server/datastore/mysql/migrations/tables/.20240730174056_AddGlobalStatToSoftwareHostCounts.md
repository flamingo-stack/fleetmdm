Database migration that adds a `global_stats` column to the `software_host_counts` table and restructures its primary key to distinguish between global statistics and team-specific host counts.

## Key Components

- **`Up_20240730174056`** — Idempotent upgrade migration that:
  1. Checks if `global_stats` is already part of the primary key (skips if already applied)
  2. Adds a `global_stats tinyint unsigned` column with default `0`
  3. Rebuilds the primary key as `(software_id, team_id, global_stats)`
  4. Marks existing `team_id = 0` rows as global stats (`global_stats = 1`)
  5. Inserts "no team" rows by computing per-software host counts not attributed to any team

- **`Down_20240730174056`** — No-op rollback (migration is not reversible)

## Usage Example

This migration runs automatically via the `MigrationClient` on startup:

```go
// Registered in init()
MigrationClient.AddMigration(Up_20240730174056, Down_20240730174056)
```

To apply manually using `goose` or the Fleet migration runner:

```bash
fleet prepare db --config /path/to/config.yml
```

## Data Model Change

```text
Before:  PRIMARY KEY (software_id, team_id)
After:   PRIMARY KEY (software_id, team_id, global_stats)

global_stats = 1 → aggregate across all teams
global_stats = 0 → scoped count (specific team or "no team")
```

The "no team" count is derived by subtracting all team-specific counts from the global total, using `GREATEST(..., 0)` to prevent negative values in edge cases.
