Database migration that adds managed local account password rotation columns and an index to the `host_managed_local_account_passwords` table.

## Key Components

- **`Up_20260522195225`** — Idempotent migration that adds five new columns and one index to `host_managed_local_account_passwords`:
  - `account_uuid` (`VARCHAR(36)`) — UUID identifying the managed account
  - `auto_rotate_at` (`TIMESTAMP(6)`) — scheduled timestamp for automatic password rotation
  - `pending_encrypted_password` (`BLOB`) — encrypted password awaiting rotation commit
  - `pending_command_uuid` (`VARCHAR(127)`) — UUID of the pending MDM command driving rotation
  - `initiated_by_fleet` (`TINYINT(1)`, default `0`) — flags whether rotation was initiated by Fleet
  - `idx_hmlap_auto_rotate_at` — index on `auto_rotate_at` for efficient rotation scheduling queries

- **`Down_20260522195225`** — No-op rollback (columns are not dropped on revert)

## Usage Example

This migration is registered automatically via `init()` and executed by the Fleet migration runner:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20260522195225, Down_20260522195225)
}
```

To apply manually during development:

```bash
fleet prepare db --config /etc/fleet/fleet.yml
```

## Notes

- Both column and index additions are guarded by `columnsExists` / `indexExistsTx` checks, making the migration safe to re-run.
- The `auto_rotate_at` index is critical for the rotation scheduler to efficiently query upcoming rotations without full-table scans.
