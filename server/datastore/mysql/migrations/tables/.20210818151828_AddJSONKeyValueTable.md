Database migration that creates the `app_config_json` table and migrates existing application configuration from the legacy `app_configs` relational table into a JSON document store.

## Key Components

- **`Up_20210818151828`** — Creates the `app_config_json` table (idempotent via `IF NOT EXISTS`), reads the existing row from `app_configs`, marshals it into JSON, and upserts it into the new table using `ON DUPLICATE KEY UPDATE`.
- **`Down_20210818151828`** — No-op rollback; the table is left in place on downgrade.
- **`testAppConfig`** — Internal struct representing the full application configuration shape, covering org info, SMTP, SSO, host expiry, server settings, host settings, vulnerability settings, and agent options.

## Schema Created

```sql
CREATE TABLE IF NOT EXISTS app_config_json (
    id          int(10) unsigned NOT NULL UNIQUE default 1,
    json_value  JSON NOT NULL,
    created_at  timestamp DEFAULT CURRENT_TIMESTAMP,
    updated_at  timestamp NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id)
)
```

The table is intentionally limited to a single row (`id` defaults to `1`, enforced by `UNIQUE`).

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20210818151828, Down_20210818151828)
}

// Triggered by the migration runner (e.g., at application startup)
err := MigrationClient.Up(db, "")
if err != nil {
    log.Fatal(err)
}
```

## Notes

- The `id` column defaults to `1`, enforcing a singleton row pattern for global app config.
- `vulnPath` is scanned as `*string` to safely handle `NULL` values in the legacy `vulnerability_databases_path` column.
- `EnableHostUsers` defaults to `true` before scanning, preserving backward-compatible behavior when the legacy column is `NULL`.
