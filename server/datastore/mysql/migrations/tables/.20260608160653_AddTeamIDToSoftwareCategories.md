Database migration that adds team-scoping to the `software_categories` table, enabling per-team software category management with emoji-prefixed default names.

## Key Components

- **`Up_20260608160653`** — Forward migration executed in two idempotent steps:
  1. **Schema update**: Modifies `software_categories` to add `team_id`, `created_at`, and `updated_at` columns; drops the old name-only unique index (`idx_software_categories_name`) and replaces it with a composite `(team_id, name)` unique index; renames the six built-in categories to emoji-prefixed forms and pins their timestamps for deterministic schema dumps.
  2. **Backfill**: Copies the six global defaults (`team_id = 0`) into every existing team, then re-points existing category foreign keys in `software_installer_software_categories`, `vpp_app_team_software_categories`, and `in_house_app_software_categories` from the shared global rows to each team's own copy.

- **`Down_20260608160653`** — No-op rollback (returns `nil`).

## Usage Example

This migration is registered automatically via `init()` and run by the Fleet migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20260608160653, Down_20260608160653)
}
```

```bash
# Apply all pending migrations (including this one)
fleet prepare db --config /etc/fleet/fleet.yml
```

After this migration:

- Global defaults (`team_id = 0`) remain as templates.
- Each team gets its own isolated copy of the six default categories (`🌎 Browsers`, `👬 Communication`, `🧰 Developer tools`, `💻 Productivity`, `🔐 Security`, `🛟 Support`).
- All existing software installer, VPP app, and in-house app category links are re-pointed to team-scoped rows.
