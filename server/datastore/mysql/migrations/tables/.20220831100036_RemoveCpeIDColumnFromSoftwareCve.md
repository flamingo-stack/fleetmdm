Database migration that removes the `cpe_id` column and its associated constraints from the `software_cve` table, and purges placeholder CPE entries from `software_cve`.

## Key Components

- **`Up_20220831100036`** — Applies the migration in three steps:
  1. Batch-deletes `software_cpe` rows where `cpe` matches the `none:%` pattern (10,000 rows per iteration)
  2. Drops the foreign key from `software_cve` to `software_cpe`, handling both MySQL (`software_cve_ibfk_1`) and MariaDB (`fk_software_cve_cpe_id`) FK naming conventions
  3. Drops the `unique_cpe_cve` index and the `cpe_id` column from `software_cve` — each step is idempotent via `indexExistsTx` / `columnExists` guards

- **`Down_20220831100036`** — No-op rollback; the column removal is intentionally irreversible

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20220831100036, Down_20220831100036)
}
```

To apply manually during development:

```bash
# Run all pending migrations (includes this one)
fleet prepare db --config /etc/fleet/fleet.yml
```

## Notes

- All `ALTER TABLE` statements use `ALGORITHM=INPLACE, LOCK=NONE` to minimize locking on large tables
- The batch deletion loop avoids long-running transactions on potentially large `software_cpe` datasets
- The down migration is intentionally a no-op — restoring the dropped column would require recreating data that no longer exists
