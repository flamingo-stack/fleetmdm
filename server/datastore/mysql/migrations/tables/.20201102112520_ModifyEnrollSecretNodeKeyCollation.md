Database migration that modifies the character set and collation of the `secret` column in `enroll_secrets` and the `node_key` column in `hosts` to `utf8mb4_bin`, enabling case-sensitive, binary comparisons for these security-sensitive fields.

## Key Components

- **`Up_20201102112520`** — Alters `enroll_secrets.secret` and `hosts.node_key` to use `utf8mb4` character set with `utf8mb4_bin` collation. Uses `columnExists` checks to make the migration idempotent.
- **`Down_20201102112520`** — No-op rollback; collation changes are not reversed.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20201102112520, Down_20201102112520)

// Applied during database migration run
err := Up_20201102112520(tx)
if err != nil {
    log.Fatal(err)
}
```

## Notes

- Uses `utf8mb4_bin` collation to enforce **binary (case-sensitive, byte-exact) comparisons** on enroll secrets and node keys — critical for security token integrity.
- The `columnExists` guard makes each `ALTER TABLE` idempotent, so re-running the migration on an already-updated schema is safe.
- The down migration is intentionally a no-op, as reverting collation could introduce inconsistencies with existing stored data.
