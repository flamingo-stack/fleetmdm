Database migration that replaces an inefficient index on `host_script_results` with an optimized one to improve query performance for hosts with large numbers of script execution records.

## Key Components

- **`Up_20250816115553`** — Creates a new composite index `idx_host_script_canceled_created_at` on `(host_id, script_id, canceled, created_at DESC)` and drops the old `idx_host_script_created_at` index. Both operations are idempotent via `indexExistsTx` checks.
- **`Down_20250816115553`** — No-op; rollback is not implemented.

## Usage Example

This migration runs automatically via the `MigrationClient` on startup. No manual invocation is needed.

```go
// Registered automatically in init()
MigrationClient.AddMigration(Up_20250816115553, Down_20250816115553)
```

The new index improves two scenarios:

- **Filtered queries** — Including `canceled` in the index enables index-only scans when filtering by cancellation status, avoiding full row lookups.
- **"Find latest" queries** — `created_at DESC` ordering in the index aligns with typical queries fetching the most recent script results, reducing sort overhead.

This is particularly impactful for hosts with 40,000+ script execution records where the old index caused noticeable performance degradation.
