Database migration that creates the `secret_variables` table for storing named secret values with automatic timestamps.

## Key Components

- **`Up_20241209164540`** — Creates the `secret_variables` table if it does not already exist (idempotent). Defines columns for `id`, `name`, `value` (BLOB, 64KB max), `created_at`, and `updated_at`.
- **`Down_20241209164540`** — No-op rollback; the table is not dropped on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Schema Details

| Column | Type | Notes |
|---|---|---|
| `id` | `INT UNSIGNED AUTO_INCREMENT` | Primary key |
| `name` | `VARCHAR(255)` | Unique constraint (`idx_secret_variables_name`) |
| `value` | `BLOB` | Up to 64KB |
| `created_at` | `DATETIME(6)` | Defaults to `NOW(6)`; uses `DATETIME` over `TIMESTAMP` to avoid Y2K38 |
| `updated_at` | `DATETIME(6)` | Auto-updated via `ON UPDATE NOW(6)` |

Engine: `InnoDB`, charset: `utf8mb4_unicode_ci`.

## Usage Example

This migration runs automatically via the `MigrationClient` during database initialization. No manual invocation is needed:

```go
// Migration is self-registering via init()
// Executed as part of the standard migration sequence:
err := MigrationClient.Up(db)
if err != nil {
    log.Fatal(err)
}
```
