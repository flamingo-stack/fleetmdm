Database migration that removes the `host_expiry` MySQL event scheduler event from the schema.

## Key Components

- **`Up_20211202181033`** — Drops the `host_expiry` event using `DROP EVENT IF EXISTS`, making the migration safe to run multiple times (idempotent).
- **`Down_20211202181033`** — No-op rollback; the event is not recreated on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the Fleet migration client. No manual invocation is required.

```go
// Executed internally by the migration runner
Up_20211202181033(tx)   // Drops host_expiry event if it exists
Down_20211202181033(tx) // No-op rollback
```

> **Note:** The rollback is intentionally empty — restoring the `host_expiry` event would require knowing its original definition, which is not preserved here. Ensure downstream logic that previously relied on this event has been replaced before applying this migration.
