Database migration that adds an `executable_sha256` column to the `host_software_installed_paths` table for storing SHA-256 hashes of installed software executables.

## Key Components

- **`Up_20250519161614`** — Idempotent migration that adds a `CHAR(64)` nullable column `executable_sha256` to `host_software_installed_paths`. Uses `CHAR` instead of `VARCHAR` since SHA-256 hashes are always a fixed 64 characters. Checks for column existence before altering to ensure safe re-runs.
- **`Down_20250519161614`** — No-op rollback; the column addition is not reversed.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Migration is registered automatically via init() and run by the migration client.
// The Up function guards against duplicate execution:
if !columnExists(tx, "host_software_installed_paths", "executable_sha256") {
    // ALTER TABLE only runs if the column does not yet exist
}
```

**Resulting schema change:**

```sql
ALTER TABLE host_software_installed_paths
ADD COLUMN executable_sha256 CHAR(64) COLLATE utf8mb4_unicode_ci NULL;
```

## Notes

- Column is nullable (`NULL`) to accommodate existing rows where no hash has been computed yet.
- `utf8mb4_unicode_ci` collation is consistent with the rest of the Fleet schema.
- The empty `Down_` function means this migration is intentionally irreversible in automated rollbacks.
