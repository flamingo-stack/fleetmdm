Database migration that adds two indices to the `queries` table to improve query performance and enforce uniqueness constraints.

## Key Components

- **`Up_20230726115701`** — Applies the migration by adding two indices to the `queries` table (idempotent; checks for existence before applying):
  - `idx_name_team_id_unq` — Unique index on `(name, team_id_char)`
  - `idx_team_id_saved_auto_interval` — Composite index on `(team_id, saved, automations_enabled, schedule_interval)`
- **`Down_20230726115701`** — No-op rollback; indices are not removed on downgrade.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client. No manual invocation is needed.

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20230726115701, Down_20230726115701)
```

To apply manually within a transaction:

```go
db, _ := sql.Open("mysql", dsn)
tx, _ := db.Begin()

if err := Up_20230726115701(tx); err != nil {
    tx.Rollback()
    log.Fatal(err)
}
tx.Commit()
```

## Notes

- The migration is **idempotent** — it checks `indexExistsTx` before running `ALTER TABLE`, making it safe to re-run.
- The rollback (`Down`) is intentionally empty; dropping these indices would need to be added explicitly if rollback support is required.
