Database migration that adds `type` and `ca_name` columns to the `host_mdm_managed_certificates` table to support multiple certificate authority types in MDM managed certificate workflows.

## Key Components

- **`Up_20250313163430`** — Applies the migration idempotently, adding two columns to `host_mdm_managed_certificates`:
  - `type` — An enum column supporting `'digicert'`, `'custom_scep_proxy'`, or `'ndes'` (defaults to `'ndes'`)
  - `ca_name` — A `varchar(255)` column for the CA display name (defaults to `'NDES'`)
- **`Down_20250313163430`** — No-op rollback; column removal is not performed.
- **Idempotency check** — Uses `columnsExists` to skip execution if both columns already exist, making the migration safe to re-run.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client during database upgrades.

```bash
# Apply migrations (example using Fleet's migration tooling)
fleet prepare db --config /etc/fleet/fleet.yml
```

```go
// Migration is auto-registered on package import
func init() {
    MigrationClient.AddMigration(Up_20250313163430, Down_20250313163430)
}
```

## Notes

- Both columns use `utf8mb4` / `utf8mb4_unicode_ci` collation for full Unicode support.
- The `Down` migration is intentionally a no-op — destructive rollbacks (dropping columns) are avoided to prevent data loss.
