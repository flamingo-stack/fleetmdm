Database migration that adds a `skipped` column to the `host_mdm_apple_bootstrap_packages` table and enforces a mutual-exclusivity constraint between `skipped` and `command_uuid`.

## Key Components

- **`Up_20251229000020`** — Applies the migration idempotently:
  - Adds a `skipped TINYINT(1) NOT NULL DEFAULT 0` column
  - Adds a `CHECK` constraint (`ck_skipped_or_commanduuid`) ensuring `skipped` and `command_uuid` are mutually exclusive — exactly one must be set at a time
  - Relaxes `command_uuid` from `NOT NULL` to nullable (`varchar(127)`)
- **`Down_20251229000020`** — No-op rollback (intentionally empty)
- **`init`** — Registers both migration functions with `MigrationClient`

## Migration Logic

The constraint enforces:

```text
skipped = 0  →  command_uuid IS NOT NULL  (active bootstrap package)
skipped = 1  →  command_uuid IS NULL      (package was skipped)
```

## Usage Example

This migration runs automatically via the Fleet migration client. To apply manually:

```bash
fleet prepare db --config /path/to/fleet.yml
```

To verify the column and constraint were added:

```sql
SHOW COLUMNS FROM host_mdm_apple_bootstrap_packages LIKE 'skipped';
SHOW CREATE TABLE host_mdm_apple_bootstrap_packages\G
```

> **Note:** The migration is idempotent — re-running it is safe. The `columnExists` guard prevents duplicate `ALTER TABLE` execution if the column already exists.
