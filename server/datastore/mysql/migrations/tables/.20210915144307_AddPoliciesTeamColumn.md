Database migration that adds a `team_id` column and foreign key constraint to the `policies` table, enabling team-scoped policies.

## Key Components

- **`Up_20210915144307`** — Idempotent migration that:
  - Adds `team_id INT UNSIGNED` column to the `policies` table (if not already present)
  - Creates a foreign key `fk_policies_team_id` referencing `teams(id)` with `ON DELETE CASCADE ON UPDATE CASCADE`
- **`Down_20210915144307`** — No-op rollback (migration is not reversible)

## Usage Example

This migration is automatically registered and executed by the migration client at startup:

```go
// Registered via init()
MigrationClient.AddMigration(Up_20210915144307, Down_20210915144307)
```

The migration is idempotent — safe to run multiple times without error:

```go
// Column check before ALTER
if !columnExists(tx, "policies", "team_id") { /* ... */ }

// FK check before ALTER
if !fkExists(tx, "policies", "fk_policies_team_id") { /* ... */ }
```

## Notes

- **Cascade behavior**: Deleting or updating a team automatically removes or updates associated policies via `ON DELETE CASCADE ON UPDATE CASCADE`
- **Nullable column**: `team_id` has no `NOT NULL` constraint, allowing policies to remain unscoped (global) when `team_id` is `NULL`
