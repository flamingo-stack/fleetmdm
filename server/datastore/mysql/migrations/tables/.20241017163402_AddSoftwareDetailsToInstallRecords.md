Database migration that adds software detail columns (`installer_filename`, `version`, `software_title_id`, `software_title_name`) to the `host_software_installs` table and updates foreign key constraints to support nullable installer references.

## Key Components

- **`Up_20241017163402`** — Idempotent migration that:
  - Adds `installer_filename` (VARCHAR 255, default `[deleted installer]`)
  - Adds `version` (VARCHAR 255, default `unknown`)
  - Adds `software_title_id` (INT UNSIGNED, nullable FK → `software_titles.id`)
  - Adds `software_title_name` (VARCHAR 255, default `[deleted title]`)
  - Makes `software_installer_id` nullable (previously `NOT NULL`)
  - Drops and re-adds `fk_host_software_installs_installer_id` with `ON DELETE SET NULL` (was previously cascade/restrict)
  - Adds `fk_host_software_installs_software_title_id` foreign key
  - Backfills all new columns from joined `software_installers` and `software_titles` data

- **`Down_20241017163402`** — No-op rollback

## Usage Example

This migration runs automatically via the migration client at application startup:

```go
// Registered automatically via init()
MigrationClient.AddMigration(Up_20241017163402, Down_20241017163402)
```

To apply manually during development:

```bash
fleet db migrate
```

## Notes

- All `ALTER TABLE` operations are guarded by `columnExists` / `fkExists` checks, making the migration safe to re-run
- The backfill `UPDATE` uses `i.updated_at = i.updated_at` to suppress automatic timestamp changes
- `installer_filename` is set to empty string for uninstall records; `version` defaults to `unknown` for uninstalls or installs predating the installer's upload timestamp
