Idempotent database migration that adds X.509 certificate validity tracking columns and an index to the `host_certificate_templates` table.

## Key Components

- **`Up_20260106000000`** — Adds three nullable columns and one index to `host_certificate_templates`:
  - `not_valid_before` (`DATETIME`) — certificate validity start, per RFC 5280 second-precision
  - `not_valid_after` (`DATETIME`) — certificate expiration, used for renewal queries
  - `serial` (`VARCHAR(40)`, utf8mb4) — X.509 certificate serial number
  - `idx_host_certificate_templates_not_valid_after` — index on `not_valid_after` for efficient renewal lookups
- **`Down_20260106000000`** — No-op rollback (columns are not dropped)
- **`init`** — Registers the migration with `MigrationClient`

## Notes

- All schema changes are guarded by `columnExists` / `indexExistsTx` checks, making the migration safe to re-run
- `DATETIME` (not `DATETIME(6)`) is intentional — X.509 certificate validity timestamps have a maximum of 1-second precision as defined by [RFC 5280](https://datatracker.ietf.org/doc/html/rfc5280)
- The rollback is intentionally left as a no-op; dropping columns in production requires a separate, deliberate migration

## Usage Example

```go
// Applied automatically by the migration runner at startup.

if err := MigrationClient.Up(db, "20260106000000"); err != nil {
    log.Fatalf("migration failed: %v", err)
}
```
