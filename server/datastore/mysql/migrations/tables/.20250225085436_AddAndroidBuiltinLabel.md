Database migration that adds a built-in "Android" label to the Fleet MDM `labels` table, enabling automatic grouping of Android hosts.

## Key Components

- **`Up_20250225085436`** — Inserts the Android built-in label using `INSERT IGNORE` for idempotency. Uses hard-coded timestamps (`2025-02-25`) to keep `schema.sql` stable. Returns a descriptive error if a duplicate label name already exists (MySQL `ER_DUP_ENTRY`).
- **`Down_20250225085436`** — No-op rollback; the label is not removed on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the Fleet migration client. No manual invocation is needed.

```go
// Migration is registered on package init and executed by the migration runner:
MigrationClient.AddMigration(Up_20250225085436, Down_20250225085436)

// The Up function inserts a row equivalent to:
// INSERT IGNORE INTO labels (name, description, query, platform, label_type,
//   label_membership_type, created_at, updated_at)
// VALUES ('Android', 'All Android hosts', '', 'android', 1, 1,
//   '2025-02-25 00:00:00', '2025-02-25 00:00:00');
```

**Duplicate name handling:** If a user-created label already uses the name defined by `fleet.BuiltinLabelNameAndroid`, the migration returns an actionable error prompting the operator to rename it before re-running.
