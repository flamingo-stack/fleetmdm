Database migration that scans existing Apple MDM configuration profiles to extract and persist Fleet variable references into the `mdm_configuration_profile_variables` lookup table.

## Key Components

| Symbol | Description |
|--------|-------------|
| `Up_20250430112622` | Forward migration — batch-loads Apple configuration profiles and maps discovered Fleet variables to their definitions |
| `Down_20250430112622` | No-op rollback (migration is idempotent) |
| `varDef` | Struct representing a row from `fleet_variables` (ID, Name, IsPrefix) |
| `saveConfigProfileVars` | Inserts `(profile_uuid, fleet_variable_id)` pairs into `mdm_configuration_profile_variables` |
| `findFleetVariables` | Parses a profile's mobileconfig content and returns a deduplicated set of Fleet variable names |
| `findFleetVariablesKeepDuplicates` | Regex-based extractor supporting both `$FLEET_VAR_NAME` and `${FLEET_VAR_NAME}` syntax |
| `profileVariableRegex` | Compiled regex matching both `$FLEET_VAR_<name>` and `${FLEET_VAR_<name>}` patterns |

## Migration Behaviour

- **Batch size:** Profiles are loaded 100 at a time using keyset pagination on `profile_uuid` to avoid excessive memory use with large `MEDIUMBLOB` columns.
- **Prefix matching:** Variable definitions with `is_prefix = true` are matched against any variable whose name starts with `def.Name`.
- **Idempotent:** The migration is safe to re-run; `Down` is intentionally a no-op.

## Usage Example

This file is invoked automatically via the migration registry — no direct calls are needed:

```go
// Registered automatically via init()
MigrationClient.AddMigration(Up_20250430112622, Down_20250430112622)
```

Variable extraction used internally during the migration:

```go
mobileconfig := `<string>$FLEET_VAR_SERIAL_NUMBER</string>`

// Returns map["FLEET_VAR_SERIAL_NUMBER": struct{}{}]
vars := findFleetVariables(mobileconfig)
```
