Database migration that introduces software category support by creating three new tables and seeding default category values.

## Key Components

- **`Up_20250501162727`** — Creates `software_categories`, `software_installer_software_categories`, and `vpp_app_team_software_categories` tables, then seeds four default categories. All `CREATE TABLE` statements use `IF NOT EXISTS` for idempotency.
- **`Down_20250501162727`** — No-op rollback; tables are not dropped on downgrade.
- **`init`** — Registers the migration pair with `MigrationClient`.

## Schema Overview

```text
software_categories
  id   (PK, AUTO_INCREMENT)
  name (VARCHAR 63, UNIQUE)

software_installer_software_categories
  id                   (PK)
  software_installer_id → software_installers.id  (CASCADE DELETE)
  software_category_id  → software_categories.id  (CASCADE DELETE)
  UNIQUE (software_installer_id, software_category_id)

vpp_app_team_software_categories
  id                   (PK)
  vpp_app_team_id       → vpp_apps_teams.id        (CASCADE DELETE)
  software_category_id  → software_categories.id   (CASCADE DELETE)
  UNIQUE (vpp_app_team_id, software_category_id)
```

## Default Seed Data

```text
Productivity | Browsers | Communication | Developer tools
```

Inserted via `INSERT IGNORE`, so re-running the migration is safe.

## Usage Example

```go
// Applied automatically by the migration runner on startup.
// To run manually during development:
fleet db migrate --config fleet.yml
```

> **Note:** The down migration is intentionally empty. Dropping these tables on rollback would cause irreversible data loss. Manual cleanup is required if a rollback is needed.
