Database migration that creates two tables — `calendar_events` and `host_calendar_events` — to support calendar event scheduling per host.

## Key Components

- **`Up_20240314085226`** — Creates the `calendar_events` and `host_calendar_events` tables if they don't exist (idempotent).
- **`Down_20240314085226`** — No-op rollback; tables are not dropped on down migration.
- **`init`** — Registers both migration functions with `MigrationClient`.

### `calendar_events` Table

| Column | Type | Notes |
|---|---|---|
| `id` | `INT UNSIGNED` | Auto-increment PK |
| `email` | `VARCHAR(255)` | Unique — one event per email |
| `start_time` | `TIMESTAMP` | Event start |
| `end_time` | `TIMESTAMP` | Event end |
| `event` | `JSON` | Full event payload |

### `host_calendar_events` Table

| Column | Type | Notes |
|---|---|---|
| `id` | `INT UNSIGNED` | Auto-increment PK |
| `host_id` | `INT UNSIGNED` | Unique — one event per host |
| `calendar_event_id` | `INT UNSIGNED` | FK → `calendar_events(id)` CASCADE DELETE |
| `webhook_status` | `TINYINT` | Tracks webhook delivery state |

## Notes

- Both tables use `utf8mb4_unicode_ci` collation (via `calendar_events`).
- The `UNIQUE KEY` on `email` and `host_id` enforces a one-event-per-email and one-event-per-host constraint respectively.
- Deleting a `calendar_event` cascades to remove associated `host_calendar_events` rows.
