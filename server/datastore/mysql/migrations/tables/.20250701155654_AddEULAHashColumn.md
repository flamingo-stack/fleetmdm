Database migration that adds a `sha256` binary column to the `eulas` table and backfills it with SHA-256 hashes computed from existing EULA byte content.

## Key Components

- **`Up_20250701155654`** — Idempotent up migration that:
  1. Adds a `sha256 binary(32)` column to the `eulas` table if it doesn't already exist
  2. Selects all existing EULA records
  3. Computes a SHA-256 hash of each record's `bytes` field and writes it back
- **`Down_20250701155654`** — No-op rollback; the column is left in place on downgrade
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration is applied automatically by the Fleet migration runner. No manual invocation is required.

```go
// Migration is registered on package init and run via MigrationClient
// Up migration applies the schema change and backfills hashes:
err := Up_20250701155654(tx)
if err != nil {
    log.Fatal(err)
}

// Down migration is intentionally a no-op:
err = Down_20250701155654(tx)
// err == nil always
```

> **Note:** The migration is idempotent — running `Up_20250701155654` multiple times is safe. The `sha256` column is only added if it does not already exist, guarded by the `columnExists` helper.

## Notes

- The `sha256` column stores the raw 32-byte binary hash (`binary(32)`), not a hex-encoded string.
- Existing rows with empty `bytes` will receive the SHA-256 hash of an empty input (`e3b0c44...`).
