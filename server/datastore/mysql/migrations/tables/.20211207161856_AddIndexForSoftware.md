Database migration that adds a composite index on the `software` table to optimize software listing queries.

## Key Components

- **`Up_20211207161856`** — Creates the `software_listing_idx` index on `(name, id)` columns of the `software` table. The migration is idempotent; it checks for the index's existence before attempting creation.
- **`Down_20211207161856`** — No-op rollback; the index is left in place on downgrade.

## Usage Example

```go
// Registered automatically via init(); no manual invocation required.
// The migration client applies this during schema upgrades:
MigrationClient.AddMigration(Up_20211207161856, Down_20211207161856)
```

```sql
-- Index created by this migration:
CREATE INDEX software_listing_idx ON software(name, id);
```

The idempotency guard uses `indexExistsTx` to prevent duplicate-index errors if the migration is re-run:

```go
if !indexExistsTx(tx, "software", "software_listing_idx") {
    tx.Exec(`create index software_listing_idx on software(name, id);`)
}
```

> **Note:** The downward migration is intentionally empty. Removing this index on rollback was deemed unnecessary, as doing so could degrade query performance on the `software` table.
