Database migration that creates a unified activity queue system for scheduling host-level operations (script execution, software installs, VPP app installs), along with a collation update to `utf8mb4_unicode_ci`.

## Key Components

### Functions

- **`Up_20250127162751`** — Applies the migration: updates database/table collation to `utf8mb4_unicode_ci`, then creates four new tables.
- **`Down_20250127162751`** — No-op rollback (tables are not dropped on down migration).
- **`changeCollation2025`** — Helper that alters the database and all applicable tables to the specified charset/collation. Excludes `hosts` and `enroll_secrets` tables (which have column-level collation overrides). Respects the `FLEET_TEST_DISABLE_COLLATION_UPDATES` environment variable for testing.

### Tables Created

| Table | Purpose |
|---|---|
| `upcoming_activities` | Core queue table; tracks host, priority, type, `execution_id`, and `payload` for each pending activity |
| `script_upcoming_activities` | Activity-type detail table for script runs; links to `scripts`, `script_contents`, `policies`, and `setup_experience_scripts` |
| `software_install_upcoming_activities` | Detail table for software installs; links to `software_installers`, `policies`, and `software_titles` |
| `vpp_app_upcoming_activities` | Detail table for VPP app installs; links to `vpp_apps`, `vpp_tokens`, and `policies` |

## Usage Example

This file is automatically registered via `init()` and executed by the migration runner:

```go
// Registration happens automatically on package import:
func init() {
    MigrationClient.AddMigration(Up_20250127162751, Down_20250127162751)
}

// Run via the migration client (typically at server startup):
if err := MigrationClient.Up(db); err != nil {
    log.Fatal("migration failed:", err)
}
```

> **Note:** All detail tables (`script_upcoming_activities`, `software_install_upcoming_activities`, `vpp_app_upcoming_activities`) cascade-delete when their parent `upcoming_activities` row is removed, while references to related entities (scripts, policies, users) use `SET NULL` to preserve audit history.
