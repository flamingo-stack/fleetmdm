Database migration that strips query parameters from MDM server URLs, deduplicates MDM solutions with equivalent base URLs, and updates related `host_mdm` records to maintain referential consistency.

## Key Components

- **`Up_20230602111827`** — Idempotent migration that:
  1. Fetches all rows from `mobile_device_management_solutions`
  2. Parses and normalizes each `server_url` by removing query parameters (`RawQuery = ""`)
  3. Identifies duplicate solutions sharing the same clean URL
  4. Redirects `host_mdm` rows from duplicate solution IDs to the canonical solution
  5. Deletes duplicate `mobile_device_management_solutions` rows
  6. Upserts the canonical solutions with their cleaned URLs

- **`Down_20230602111827`** — No-op rollback (migration is considered irreversible)

- **`mdmSolution`** — Internal struct mapping `id`, `server_url`, and `name` from the DB

## Usage Example

This migration runs automatically via the migration client on startup:

```go
// Registered automatically via init()
MigrationClient.AddMigration(Up_20230602111827, Down_20230602111827)
```

To apply manually during development:

```bash
# Run all pending migrations (including this one)
fleet prepare db --mysql_address=localhost:3306 --mysql_database=fleet
```

## Notes

- **Idempotent:** Uses `INSERT ... ON DUPLICATE KEY UPDATE` so re-running is safe
- **Deduplication order:** Solutions are fetched `ORDER BY created_at DESC`; the first encountered clean URL wins as the canonical record
- Malformed URLs are skipped with a warning log rather than failing the migration
