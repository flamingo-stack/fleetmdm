Database migration that creates the `software_update_schedules` table and adds a `timezone` column to the `hosts` table to support scheduled software auto-updates per team.

## Key Components

| Component | Description |
|---|---|
| `Up_20251229000010` | Applies the migration: creates `software_update_schedules` table and conditionally adds `timezone` to `hosts` |
| `Down_20251229000010` | No-op rollback (migration is not reversed) |
| `software_update_schedules` | New table linking teams to software titles with a time-windowed update schedule |

### `software_update_schedules` Schema

| Column | Type | Description |
|---|---|---|
| `id` | `INT UNSIGNED AUTO_INCREMENT` | Primary key |
| `team_id` | `INT UNSIGNED` | References a Fleet team |
| `title_id` | `INT UNSIGNED` | FK to `software_titles(id)`, cascades on delete |
| `enabled` | `BOOLEAN` | Whether the schedule is active (default: `false`) |
| `start_time` | `char(5)` | Schedule window start (e.g., `"09:00"`) |
| `end_time` | `char(5)` | Schedule window end (e.g., `"17:00"`) |

A unique constraint on `(team_id, title_id)` ensures one schedule per software title per team.
