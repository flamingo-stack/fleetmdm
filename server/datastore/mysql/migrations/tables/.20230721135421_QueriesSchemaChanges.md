Database migration that modifies the `queries` and `scheduled_queries` tables to support team-scoped queries with scheduling metadata.

## Key Components

- **`Up_20230721135421`** — Applies the migration with full idempotency guards:
  - Adds `team_id_char CHAR(10)` to `scheduled_queries` for composite FK support
  - Drops legacy unique indexes (`idx_query_unique_name`, `constraint_query_name_unique`) from `queries`
  - Extends the `queries` table with columns: `team_id`, `team_id_char`, `platform`, `min_osquery_version`, `schedule_interval`, `automations_enabled`, `logging_type`
  - Creates a new composite unique index `idx_team_id_name_unq (team_id_char, name)` on `queries`
  - Adds FK `fk_queries_team_id` linking `queries.team_id → teams.id` with `ON DELETE CASCADE`
  - Replaces the old name-based FK on `scheduled_queries` with a composite FK `fk_scheduled_queries_queries (team_id_char, query_name) → queries (team_id_char, name)`

- **`Down_20230721135421`** — No-op rollback (schema changes are not reversed)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20230721135421, Down_20230721135421)
```

To apply manually during development:

```bash
fleet db prepare --dev
# or
fleet db migrate
```

## Notes

- All schema changes use `columnExists`, `columnsExists`, `fkExists`, and `indexExistsTx` guards, making the migration safe to re-run
- The uniqueness constraint on `queries` shifts from name-only to `(team_id_char, name)`, enabling the same query name to exist across different teams
