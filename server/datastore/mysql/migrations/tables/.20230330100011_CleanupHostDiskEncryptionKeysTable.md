Database migration that removes orphaned disk encryption key records for hosts where disk encryption is disabled.

## Key Components

- **`Up_20230330100011`** — Deletes rows from `host_disk_encryption_keys` where the corresponding `host_disks` record has `encrypted = 0`. The operation is idempotent and safe to re-run.
- **`Down_20230330100011`** — No-op rollback; deleted rows are not restored.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Behavior

The migration performs a joined `DELETE` across two tables:

```sql
DELETE hdek
    FROM host_disk_encryption_keys hdek
    JOIN host_disks hd ON hdek.host_id = hd.host_id
WHERE hd.encrypted = 0
```

Any host that Fleet knows is **not** encrypted should not retain a key record. This cleans up stale or inconsistent data that may have accumulated before this constraint was enforced.

## Usage Example

This migration runs automatically via the Fleet migration client. No manual invocation is needed:

```go
// Registered automatically on package import via init()
MigrationClient.AddMigration(Up_20230330100011, Down_20230330100011)
```

To apply manually during development:

```bash
fleetctl prepare db --config /etc/fleet/fleet.yml
```

## Notes

- **Idempotent** — Running this migration multiple times produces the same result; rows already absent are unaffected.
- **No rollback** — `Down_20230330100011` is a no-op because the deleted rows cannot be meaningfully reconstructed.
