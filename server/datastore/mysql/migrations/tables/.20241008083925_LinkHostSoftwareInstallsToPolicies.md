Database migration that adds a `policy_id` foreign key column to the `host_software_installs` table, linking software installations to Fleet policies.

## Key Components

- **`Up_20241008083925`** — Idempotent migration that:
  - Adds `policy_id INT UNSIGNED DEFAULT NULL` column to `host_software_installs` if it doesn't already exist
  - Creates foreign key `fk_software_install_policy_id` referencing `policies(id)` with `ON DELETE SET NULL` behavior
- **`Down_20241008083925`** — No-op rollback (schema changes are not reversed)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Applied automatically by MigrationClient during fleet db prepare
MigrationClient.AddMigration(Up_20241008083925, Down_20241008083925)
```

After this migration, software installs can be associated with a policy:

```go
// Insert a policy-triggered software install
_, err := db.Exec(`
    INSERT INTO host_software_installs (host_id, software_installer_id, policy_id)
    VALUES (?, ?, ?)
`, hostID, installerID, policyID)
```

> **Note:** The migration is idempotent — safe to re-run. Deleting a referenced policy sets `policy_id` to `NULL` on associated install records rather than cascading a delete.
