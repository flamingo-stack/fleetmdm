Database migration that updates the foreign key constraint on the `scheduled_queries` table to support cascading deletes and updates.

## Key Components

- **`Up20180620175055`** — Idempotently replaces the `scheduled_queries_query_name` foreign key constraint on `scheduled_queries.query_name → queries.name` with `ON DELETE CASCADE ON UPDATE CASCADE` behavior.
- **`Down20180620175055`** — No-op rollback; the original constraint is not restored.

## Migration Logic

The `Up` function follows a safe, idempotent two-step pattern:

1. **Drop** the existing `scheduled_queries_query_name` foreign key if it exists.
2. **Re-add** the constraint (only if absent) with cascade rules.

This ensures the migration can be re-run safely without errors if partially applied.
