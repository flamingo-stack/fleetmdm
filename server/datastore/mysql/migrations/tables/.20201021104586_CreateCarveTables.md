Database migration that creates two tables (`carve_metadata` and `carve_blocks`) to support osquery file carving functionality, storing carve session metadata and block data respectively.

## Key Components

- **`Up_20201021104586`** — Creates the `carve_metadata` and `carve_blocks` tables. Uses `CREATE TABLE IF NOT EXISTS` for idempotency.
- **`Down_20201021104586`** — No-op rollback; tables are left in place on downgrade.
- **`init`** — Registers the migration with `MigrationClient`.

### Schema Overview

| Table | Purpose |
|---|---|
| `carve_metadata` | Tracks carve sessions: host, block count/size, carve size, session/request IDs, expiry |
| `carve_blocks` | Stores individual binary blocks (`LONGBLOB`) keyed by `(metadata_id, block_id)` |

**Key constraints:**
- `carve_metadata.host_id` → `hosts(id)` (`ON DELETE CASCADE`)
- `carve_blocks.metadata_id` → `carve_metadata(id)` (`ON DELETE CASCADE`)
- Unique indexes on `session_id` and `name` in `carve_metadata`

## Usage Example

This migration is invoked automatically by the migration runner at startup or via the CLI migration command:

```bash
# Run all pending migrations (including this one)
fleetctl prepare db --config fleet.yml
```

To reference this migration programmatically:

```go
// Registered automatically via init()
MigrationClient.AddMigration(Up_20201021104586, Down_20201021104586)
```
