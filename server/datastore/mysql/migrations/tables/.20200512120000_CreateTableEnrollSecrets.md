Database migration that creates the `enroll_secrets` table, migrates existing enrollment secrets from `app_configs`, and updates the `hosts` table schema to support named enrollment secrets.

## Key Components

- **`Up_20200512120000`** — Applies the migration with four idempotent steps:
  1. Creates the `enroll_secrets` table (`name`, `secret`, `active`, `created_at`)
  2. Copies any existing `osquery_enroll_secret` from `app_configs` into `enroll_secrets` as the `"default"` entry
  3. Adds `enroll_secret_name` column to `hosts` (if not already present)
  4. Drops the now-redundant `osquery_enroll_secret` column from `app_configs` (if still present)

- **`Down_20200512120000`** — No-op rollback; schema changes are not reversed.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20200512120000, Down_20200512120000)
}

// Run all pending migrations (typical usage at app startup)
err := MigrationClient.Up(db, "")
if err != nil {
    log.Fatal("migration failed:", err)
}
```

## Schema Changes

| Table | Change |
|---|---|
| `enroll_secrets` | Created with `name` (PK), `secret`, `active`, `created_at` |
| `hosts` | Column `enroll_secret_name VARCHAR(255)` added |
| `app_configs` | Column `osquery_enroll_secret` dropped |

> All `Up` steps use `IF NOT EXISTS` / `INSERT IGNORE` / `columnExists` guards, making the migration safe to re-run.
