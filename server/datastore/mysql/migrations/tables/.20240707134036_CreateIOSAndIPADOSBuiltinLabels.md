Database migration that creates built-in manual labels for iOS and iPadOS devices, backfills label membership for existing hosts, and updates MDM profile statuses from "verifying" to "verified" for those platforms.

## Key Components

| Function | Description |
|---|---|
| `Up_20240707134036` | Applies the migration: creates iOS/iPadOS labels, inserts label membership for existing hosts, and corrects MDM profile statuses |
| `createBuiltinManualIOSAndIPadOSLabels` | Inserts two built-in manual labels (`fleet.BuiltinLabelIOS`, `fleet.BuiltinLabelIPadOS`) with stable timestamps for schema consistency; returns their generated IDs |
| `Down_20240707134036` | No-op rollback (labels are not removed on downgrade) |

## Usage Example

This file is auto-registered via `init()` and executed by the migration client — no direct invocation is needed.

```go
// Registered automatically at startup:
MigrationClient.AddMigration(Up_20240707134036, Down_20240707134036)
```

The migration performs three idempotent steps:

```go
// 1. Create builtin labels (INSERT IGNORE — safe to re-run)
iOSLabelID, iPadOSLabelID, err := createBuiltinManualIOSAndIPadOSLabels(tx)

// 2. Backfill label_membership for all existing iOS/iPadOS hosts
tx.Exec(`INSERT IGNORE INTO label_membership ... WHERE platform = 'ios' OR platform = 'ipados'`)

// 3. Promote 'verifying' MDM profiles to 'verified' on iOS/iPadOS
//    (no osquery agent on these platforms, so verification cannot happen)
tx.Exec(`UPDATE host_mdm_apple_profiles ... SET hmap.status = 'verified'`)
```

## Notes

- **Duplicate label guard:** If a user-created label already shares a name with `BuiltinLabelIOS` or `BuiltinLabelIPadOS`, the migration returns a descriptive error instructing the user to rename it before retrying.
- **Stable timestamps:** `createBuiltinManualIOSAndIPadOSLabels` uses a hard-coded `time.Date(2024, 6, 28, ...)` to keep `schema.sql` deterministic across environments.
