Database migration that creates two tables for storing app configurations: `vpp_app_configurations` for VPP (Volume Purchase Program) apps and `in_house_app_configurations` for in-house apps.

### `vpp_app_configurations`

| Column | Type | Notes |
|---|---|---|
| `id` | `INT UNSIGNED` | Auto-increment primary key |
| `application_id` | `VARCHAR(255)` | References `vpp_apps.adam_id` |
| `team_id` | `INT UNSIGNED` | Team scope for the config |
| `platform` | `VARCHAR(10)` | References `vpp_apps.platform` |

| `created_at` / `updated_at` | `timestamp(6)` | Auto-managed timestamps |

Unique constraint: `(team_id, application_id, platform)` — one configuration per app per team per platform.

### `in_house_app_configurations`

| Column | Type | Notes |
|---|---|---|
| `id` | `INT UNSIGNED` | Auto-increment primary key |
| `in_house_app_id` | `INT UNSIGNED` | References `in_house_apps.id` |
| `configuration` | `MEDIUMTEXT` | App configuration payload |

Unique constraint: `(in_house_app_id)` — one configuration per in-house app.

Both tables use `CASCADE` deletes tied to their parent app records.
