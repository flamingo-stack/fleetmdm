Database migration that adds a nullable `host_deleted_at` timestamp column to the `host_script_results` table to support soft-delete functionality for hosts.

## Key Components

- **`Up_20240612150059`** — Idempotent migration that adds `host_deleted_at TIMESTAMP NULL` to `host_script_results` if the column does not already exist.
- **`Down_20240612150059`** — No-op rollback; the column addition is not reversed.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically via the Fleet migration client:

```go
// Applied as part of the standard migration run
MigrationClient.AddMigration(Up_20240612150059, Down_20240612150059)
```

The `Up` function is idempotent — safe to run multiple times:

```go
// Internally checks for column existence before altering the table
if !columnExists(tx, "host_script_results", "host_deleted_at") {
    tx.Exec(`ALTER TABLE host_script_results ADD COLUMN host_deleted_at TIMESTAMP NULL`)
}
```

## Notes

- The `host_deleted_at` column allows host script results to be soft-deleted, preserving historical records while marking the associated host as removed.
- The down migration is intentionally empty — no destructive rollback is performed.
