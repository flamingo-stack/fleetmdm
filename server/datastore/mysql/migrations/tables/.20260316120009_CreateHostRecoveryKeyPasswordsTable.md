Database migration that creates the `host_recovery_key_passwords` table for storing encrypted host recovery key passwords with MDM delivery tracking.

## Key Components

- **`Up_20260316120009`** — Creates the `host_recovery_key_passwords` table (idempotent via `CREATE TABLE IF NOT EXISTS`) with the following schema:
  - `host_uuid` — Primary key, identifies the host
  - `encrypted_password` — BLOB storing the encrypted recovery key password
  - `status` / `operation_type` — MDM delivery state, foreign-keyed to `mdm_delivery_status` and `mdm_operation_types`
  - `error_message` — Captures failure details
  - `deleted` — Soft-delete flag
  - `created_at` / `updated_at` — Microsecond-precision timestamps with auto-update
- **`Down_20260316120009`** — No-op rollback (table is not dropped)

## Notes

- The migration is **idempotent** — safe to run multiple times without error.
- Foreign key constraints enforce valid values for `status` and `operation_type` via `ON UPDATE CASCADE`.
- Indexes on `status`, `operation_type`, and `deleted` support efficient MDM delivery state queries.
- The rollback (`Down`) is intentionally a no-op; dropping this table would require a separate explicit migration.
