Database migration that adds a composite index on `host_script_results` to improve query performance when filtering or sorting by host, script, and creation time.

## Key Components

- **`Up_20231009094541`** — Idempotently adds the index `idx_host_script_created_at` on columns `(host_id, script_id, created_at)` to the `host_script_results` table. Uses `indexExistsTx` to skip creation if the index already exists.
- **`Down_20231009094541`** — No-op rollback; the index is left in place on downgrade.

## Usage Example

This migration runs automatically via the `MigrationClient` on application startup. To apply or roll back manually:

```bash
# Apply
fleetctl db migrate --up 20231009094541

# Rollback (no-op for this migration)
fleetctl db migrate --down 20231009094541
```

## Notes

- The migration is **idempotent** — safe to run multiple times without error.
- The composite index `(host_id, script_id, created_at)` optimises queries that look up script execution history per host ordered by time.
