Database migration that creates the `software_title_icons` table, which stores custom icon metadata for software titles scoped by team.

## Key Components

- **`Up_20250905090000`** — Creates the `software_title_icons` table (idempotent via `CREATE TABLE IF NOT EXISTS`) with the following schema:

| Column | Type | Description |
|---|---|---|
| `id` | `INT AUTO_INCREMENT` | Primary key |
| `team_id` | `INT UNSIGNED` | Team scoping for the icon |
| `software_title_id` | `INT UNSIGNED` | FK to `software_titles(id)`, cascades on delete/update |
| `storage_id` | `VARCHAR(64)` | Object storage reference |
| `filename` | `VARCHAR(255)` | Original icon filename |
| `created_at` | `TIMESTAMP(6)` | Creation timestamp with microsecond precision |

- **`Down_20250905090000`** — Drops the `software_title_icons` table if it exists.

**Indexes:**
- `UNIQUE KEY` on `(team_id, software_title_id)` — enforces one icon per software title per team
- `INDEX` on `(storage_id, team_id)` — supports storage lookups scoped by team

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20250905090000, Down_20250905090000)

// Applied by the migration runner (up)
err := Up_20250905090000(tx)

// Rolled back by the migration runner (down)
err := Down_20250905090000(tx)
```

## Notes

- Each `(team_id, software_title_id)` pair may have exactly one icon, enforced at the DB level.
- Deleting a `software_titles` row will cascade-delete the associated icon record.
