Database migration that creates two tables supporting File Integrity Monitoring (FIM): `file_integrity_monitorings` (sections/categories) and `file_integrity_monitoring_files` (individual monitored files with a cascading foreign key to the parent section).

## Key Components

| Function | Description |
|---|---|
| `Up_20170109094020` | Creates `file_integrity_monitorings` and `file_integrity_monitoring_files` tables using `IF NOT EXISTS` (idempotent) |
| `Down_20170109094020` | Drops both FIM tables in dependency order (files first, then sections) |

### Schema Overview

**`file_integrity_monitorings`**
- `id` — auto-increment primary key
- `section_name` — unique, indexed section identifier
- `description` — human-readable description

**`file_integrity_monitoring_files`**
- `id` — auto-increment primary key
- `file` — unique file path (BTREE indexed)
- `file_integrity_monitoring_id` — FK → `file_integrity_monitorings.id` with `ON DELETE CASCADE`

## Notes

- Migration uses `CREATE TABLE IF NOT EXISTS` making `Up` safe to re-run
- Child table (`file_integrity_monitoring_files`) is dropped before the parent in `Down` to respect the foreign key constraint
