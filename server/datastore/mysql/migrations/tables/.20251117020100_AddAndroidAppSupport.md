Database migration that adds Android app support by widening `adam_id` columns to `VARCHAR(255)` across VPP-related tables and making `vpp_token_id` nullable in `vpp_apps_teams`.

## Key Components

| Function | Description |
|---|---|
| `Up_20251117020100` | Applies the migration: drops/re-adds FKs, widens `adam_id` columns, makes `vpp_token_id` nullable |
| `Down_20251117020100` | No-op rollback (intentionally empty) |

## Schema Changes

**Tables modified:**

| Table | Change |
|---|---|
| `vpp_apps_teams` | `vpp_token_id` made nullable (`INT UNSIGNED`); `adam_id` widened to `VARCHAR(255)` |
| `vpp_apps` | `adam_id` widened to `VARCHAR(255) utf8mb4` |
| `vpp_app_upcoming_activities` | `adam_id` widened to `VARCHAR(255) utf8mb4` |
| `host_vpp_software_installs` | `adam_id` widened to `VARCHAR(255) utf8mb4` |

**Foreign keys temporarily dropped and re-added:**
- `fk_vpp_app_upcoming_activities_adam_id_platform`
- `host_vpp_software_installs_ibfk_3`
- `vpp_apps_teams_ibfk_3`

## Usage Example

This migration runs automatically via the `MigrationClient` on startup:

```go
// Registered via init()
MigrationClient.AddMigration(Up_20251117020100, Down_20251117020100)
```

The migration is **idempotent** — each step checks for column/FK existence using `columnExists` and `fkExists` helpers before executing, making it safe to re-run.
