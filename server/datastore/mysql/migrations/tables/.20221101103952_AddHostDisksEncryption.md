Database migration that adds an `encrypted` column to the `host_disks` table to track disk encryption status per host.

## Key Components

- **`Up_20221101103952`** — Idempotent migration that adds a nullable `TINYINT(1)` column `encrypted` to the `host_disks` table. Uses `columnExists` to guard against re-application.
- **`Down_20221101103952`** — No-op rollback; the column is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically via the Fleet migration runner. To apply or roll back manually:

```bash
# Apply all pending migrations
fleetctl prepare db --config /etc/fleet/fleet.yml

# The migration adds:
# ALTER TABLE host_disks ADD COLUMN encrypted TINYINT(1) NULL
```

The resulting schema change:

```text
host_disks
├── ... (existing columns)
└── encrypted  TINYINT(1)  NULL   ← added by this migration
```

The `encrypted` field reflects host-level disk encryption state (not per-partition), consistent with how disk space data is stored in the same table. A `NULL` value indicates the encryption status has not yet been collected from the host.

## Notes

- **Idempotent**: Safe to run multiple times; the `columnExists` check prevents duplicate-column errors.
- **Rollback is a no-op**: Downward migration does not drop the column to avoid data loss on accidental rollback.
