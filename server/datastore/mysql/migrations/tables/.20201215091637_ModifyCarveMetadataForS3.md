Database migration that modifies the `carve_metadata` table to support S3-based file carving by adding a `max_block` column and expanding the `session_id` field size.

## Key Components

- **`Up_20201215091637`** — Idempotent migration that adds a `max_block INT DEFAULT -1` column and widens `session_id` from `VARCHAR(64)` to `VARCHAR(255)` on the `carve_metadata` table.
- **`Down_20201215091637`** — Reverts the migration by dropping `max_block` and restoring `session_id` to `VARCHAR(64)`.
- **`init()`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically via the migration client. No direct invocation is needed.

```go
// Applied automatically on schema upgrade
MigrationClient.AddMigration(Up_20201215091637, Down_20201215091637)
```

To apply or roll back manually using the migration CLI:

```bash
# Apply migration
fleet prepare db --dev

# Rollback (if supported)
fleet prepare db --rollback
```

## Notes

- The `Up` function checks for the existence of `max_block` via `columnExists` before altering the table, making it safe to re-run.
- The `session_id` expansion to `VARCHAR(255)` accommodates longer S3-compatible session identifiers.
