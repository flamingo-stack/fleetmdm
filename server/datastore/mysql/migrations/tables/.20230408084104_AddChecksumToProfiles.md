Database migration that adds a `checksum` column (`BINARY(16)`) to the `mdm_apple_configuration_profiles` and `host_mdm_apple_profiles` tables, then populates it with MD5 hashes of profile content.

## Key Components

- **`Up_20230408084104`** — Idempotent migration that:
  1. Adds `checksum BINARY(16) NOT NULL` to `mdm_apple_configuration_profiles` (if not present)
  2. Adds `checksum BINARY(16) NOT NULL` to `host_mdm_apple_profiles` (if not present)
  3. Populates `mdm_apple_configuration_profiles.checksum` via `UNHEX(MD5(mobileconfig))`
  4. Backfills `host_mdm_apple_profiles.checksum` by joining against the parent profile table

- **`Down_20230408084104`** — No-op rollback (column removal not implemented)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20230408084104, Down_20230408084104)
```

To apply manually during development:

```bash
# Run all pending migrations
fleet prepare db --config /etc/fleet/config.yml
```

## Notes

- The `columnExists` guard makes the `ALTER TABLE` steps idempotent — safe to re-run if the migration was partially applied.
- Checksums use MD5 stored as raw bytes (`BINARY(16)`) via `UNHEX`, not hex strings — compare with `UNHEX(MD5(...))` in queries.
- The rollback (`Down`) is intentionally empty; dropping the column would require a separate migration to avoid data loss.
