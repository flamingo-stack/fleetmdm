Database migration that creates the `sessions` table for managing user authentication sessions in Fleet MDM.

## Key Components

- **`Up_20161118212656`** — Creates the `sessions` table with the following schema:
  - `id` — Auto-incrementing unsigned integer primary key
  - `created_at` — Timestamp set to `CURRENT_TIMESTAMP` on insert
  - `accessed_at` — Timestamp auto-updated on each row modification (tracks last activity)
  - `user_id` — Foreign reference to the owning user (unsigned int)
  - `key` — Unique session token (varchar 255)
  - Unique index on `key` for fast session lookups
  - InnoDB engine with `utf8mb4_unicode_ci` collation
- **`Down_20161118212656`** — Drops the `sessions` table if it exists
- **`init()`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration is executed automatically by the migration client during `fleet prepare db`. It is idempotent — safe to run multiple times due to `CREATE TABLE IF NOT EXISTS`.

```go
// Manually applying within a transaction (handled by MigrationClient internally)
db, _ := sql.Open("mysql", dsn)
tx, _ := db.Begin()

if err := Up_20161118212656(tx); err != nil {
    tx.Rollback()
    log.Fatal(err)
}

tx.Commit()
```

## Notes

- The `accessed_at` column uses `ON UPDATE CURRENT_TIMESTAMP`, automatically tracking the last time a session was accessed without requiring application-level updates.
- The unique index on `key` enforces session token uniqueness at the database level.
