Database migration that adds a `global_stats` column to the `vulnerability_host_counts` table, enabling differentiation between global vulnerability statistics and team-specific host counts.

## Key Components

- **`Up_20240730171504`** — Applies the migration with the following idempotent steps:
  1. Adds `global_stats` (`tinyint(1)`, default `0`) column if absent
  2. Drops the old `cve_team_id` unique index if present
  3. Creates a new `cve_team_id_global_stats` unique index on `(cve, team_id, global_stats)`
  4. Marks existing `team_id = 0` rows as global stats (`global_stats = 1`)
  5. Inserts "no team" rows (`team_id = 0, global_stats = 0`) representing counts for hosts not assigned to any team, calculated by subtracting team-specific counts from the global total

- **`Down_20240730171504`** — No-op rollback; schema changes are not reversed

## Schema Change Summary

| Change | Detail |
|---|---|
| New column | `global_stats tinyint(1) NOT NULL DEFAULT 0` |
| Dropped index | `cve_team_id` |
| New unique index | `cve_team_id_global_stats (cve, team_id, global_stats)` |
