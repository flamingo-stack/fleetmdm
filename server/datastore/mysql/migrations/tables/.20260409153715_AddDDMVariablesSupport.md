Database migration that adds DDM (Declarative Device Management) variables support by extending the `host_mdm_apple_declarations` and `mdm_configuration_profile_variables` tables.

## Key Components

- **`Up_20260409153715`** — Applies the migration with the following idempotent schema changes:
  - Adds `variables_updated_at DATETIME(6)` to `host_mdm_apple_declarations` to track when variables last changed, enabling declaration token regeneration
  - Adds `apple_declaration_uuid VARCHAR(37)` column to `mdm_configuration_profile_variables`
  - Creates a unique index `idx_mdm_config_profile_vars_apple_decl_variable` on `(apple_declaration_uuid, fleet_variable_id)`
  - Adds foreign key `fk_mdm_configuration_profile_variables_apple_declaration_uuid` referencing `mdm_apple_declarations(declaration_uuid)` with `ON DELETE CASCADE`
  - Drops the old `ck_mdm_configuration_profile_variables_apple_or_windows` check constraint
  - Adds a new `ck_mdm_configuration_profile_variables_exactly_one` check constraint enforcing that exactly one of `apple_profile_uuid`, `windows_profile_uuid`, or `apple_declaration_uuid` is non-null

- **`Down_20260409153715`** — No-op rollback (returns nil)

## Usage Example

This migration is registered automatically via `init()` and executed by the Fleet migration runner:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20260409153715, Down_20260409153715)
```

To apply manually during development:

```bash
fleet prepare db --config /etc/fleet/fleet.yml
```

## Notes

All schema changes use `columnExists` and `constraintExists` guards, making the migration safe to re-run. The new check constraint replaces the binary Apple/Windows choice with a three-way exclusive constraint, extending Fleet MDM's variable support to Apple DDM declarations.
