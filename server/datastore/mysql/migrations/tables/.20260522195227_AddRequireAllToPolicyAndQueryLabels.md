Database migration that adds a `require_all` boolean column to the `policy_labels` and `query_labels` tables, enabling label matching logic to distinguish between "any label matches" and "all labels must match" semantics.

## Key Components

| Symbol | Description |
|---|---|
| `Up_20260522195227` | Adds `require_all TINYINT(1) NOT NULL DEFAULT 0` column to `policy_labels` and `query_labels` if not already present |
| `Down_20260522195227` | No-op rollback (column removal is not performed) |

## Behavior Notes

- Uses `ALGORITHM=INSTANT` for zero-downtime, metadata-only schema changes (MySQL 8+)
- Guards each `ALTER TABLE` with `columnExists()` to make the migration idempotent
- `require_all` defaults to `0` (false), preserving existing "any match" behavior for all current rows

## Usage Example

```go
// Applied automatically by the migration runner at startup.
// To run manually during development:
fleet prepare db --dev
```

The column controls label evaluation logic — when `require_all = 1`, a policy or query is only targeted at a host if the host matches **every** associated label rather than at least one.
