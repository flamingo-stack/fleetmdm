Database migration that expands the `vendor` column width in the `software` table from `varchar(32)` to `varchar(114)` while preserving existing data and updating the uniqueness constraint.

## Key Components

- **`Up_20220818101352`** — Applies the migration via a multi-step column rename strategy:
  1. Adds a temporary `vendor_wide varchar(114)` column
  2. Copies existing `vendor` data into the temp column
  3. Adds a new `UNIQUE` constraint on `(name, version, source, release, vendor_wide, arch)`
  4. Drops the old `name` index
  5. Renames original `vendor` → `vendor_old` (preserves old `varchar(32)`)
  6. Renames `vendor_wide` → `vendor` (promotes wide column to production)

- **`Down_20220818101352`** — No-op rollback (intentionally empty).

- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is executed automatically by the migration client. No manual invocation is required.

```bash
# Applied automatically during Fleet server startup or via the migrate command
fleetctl prepare db
```

```go
// Registration (handled automatically via init())
MigrationClient.AddMigration(Up_20220818101352, Down_20220818101352)
```

## Notes

- Uses `ALGORITHM=INPLACE, LOCK=NONE` for online DDL — minimizes table locking on large datasets.
- All steps are idempotent: `columnExists` and `indexExistsTx` guards prevent re-applying partial migrations.
- The rollback (`Down`) is intentionally empty; reverting would require a separate migration to avoid data loss.
