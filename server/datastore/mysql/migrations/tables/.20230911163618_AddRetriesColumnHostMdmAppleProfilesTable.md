Database migration that adds a `retries` column to the `host_mdm_apple_profiles` table to track the number of retry attempts for MDM Apple profile installations.

## Key Components

- **`Up_20230911163618`** — Idempotent migration that adds `retries TINYINT(3) UNSIGNED NOT NULL DEFAULT 0` to `host_mdm_apple_profiles` if the column does not already exist.
- **`Down_20230911163618`** — No-op rollback; the column is not removed on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Applied automatically by the migration client at startup.
// To run manually via the Fleet CLI:
// fleet db migrate --config /etc/fleet/config.yml

// The resulting schema change:
// ALTER TABLE host_mdm_apple_profiles
//     ADD COLUMN retries TINYINT(3) UNSIGNED NOT NULL DEFAULT 0;
```

## Notes

- The migration is **idempotent** — it checks for column existence via `columnExists` before executing the `ALTER TABLE`, making it safe to run multiple times without error.
- The `retries` column uses an unsigned 3-digit tiny integer (0–255) with a default of `0`, suitable for counting delivery retry attempts per profile per host.
- The empty `Down` function means this migration is **irreversible** through the migration client; manual intervention is required to drop the column if needed.
