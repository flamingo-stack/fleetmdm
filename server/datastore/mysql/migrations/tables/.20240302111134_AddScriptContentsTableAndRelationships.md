Database migration that creates the `script_contents` table and migrates script content from `host_script_results` and `scripts` tables into a deduplicated, MD5-indexed central store.

## Key Components

- **`Up_20240302111134`** — Creates the `script_contents` table and backfills it from existing `host_script_results` and `scripts` rows, then adds `script_content_id` FK columns to both source tables
- **`createScriptContentsEntries`** — Batched loader (1,000 rows/batch) that reads script content from a source table, computes MD5 checksums, inserts deduplicated entries into `script_contents` using `ON DUPLICATE KEY UPDATE id = LAST_INSERT_ID(id)`, and builds checksum-to-ID lookup maps
- **`updateScriptContentIDInBatches`** — Writes the resolved `script_content_id` back to source tables in batches of up to 10,000 rows, preserving `updated_at` timestamps
- **`md5ChecksumScriptContent`** — Computes an uppercase hex MD5 checksum of script content for use as the deduplication key
- **`Down_20240302111134`** — No-op rollback (intentionally empty)

## Usage Example

This migration runs automatically via the `MigrationClient` on application startup. The core deduplication pattern can be understood as:

```go
// MD5 checksum computed per script body
hexChecksum := md5ChecksumScriptContent(scriptBody)

// Insert with dedup — returns existing row's ID on collision
res, err := txx.Exec(`
    INSERT INTO script_contents (md5_checksum, contents)
    VALUES (UNHEX(?), ?)
    ON DUPLICATE KEY UPDATE id = LAST_INSERT_ID(id)
`, hexChecksum, scriptBody)
id, _ := res.LastInsertId()

// FK back-filled in source tables
txx.Exec(`UPDATE host_script_results SET script_content_id = ? WHERE id IN (?)`, id, ids)
```

> **Note:** The original `script_contents` column is intentionally **not dropped** in this migration to avoid breaking in-flight application code. Removal is deferred to a subsequent migration once the feature is fully live.

## Design Notes

| Decision | Rationale |
|---|---|
| MD5 stored as `BINARY(16)` | Space-efficient; deduplication only, not security |
| Batch reads instead of cursor iteration | MySQL requires a separate connection for concurrent read+write on the same table |
| `updated_at = updated_at` in UPDATE | Prevents timestamp drift during migration |
| `testBatchSize` package var | Allows smaller batch sizes in unit tests |
