Database migration that adds `checksum` and `secrets_updated_at` columns to the `mdm_windows_configuration_profiles` and `host_mdm_windows_profiles` tables, and backfills checksum values from profile definitions.

## Key Components

- **`Up_20250318165922`** — Applies the migration with idempotency guard. Adds:
  - `checksum BINARY(16)` — a stored generated column computed as `MD5(syncml)` on `mdm_windows_configuration_profiles`
  - `checksum BINARY(16)` — a regular column backfilled from the profile definition on `host_mdm_windows_profiles`
  - `secrets_updated_at DATETIME(6)` — nullable timestamp on both tables
  - `created_at` / `updated_at DATETIME(6)` — audit timestamps on `host_mdm_windows_profiles`
  - Modifies `created_at` and `uploaded_at` precision on `mdm_windows_configuration_profiles`
- **`Down_20250318165922`** — No-op; migration is not reversed
- **`columnsExists`** — Pre-flight idempotency check; skips execution if all target columns already exist

// Registered automatically via init(); runs as part of the migration chain.

## Notes

- The `checksum` column on `mdm_windows_configuration_profiles` is a **stored generated column** — it is recomputed automatically when `syncml` changes, requiring no application-level updates.
- The `UPDATE` statement backfills existing `host_mdm_windows_profiles` rows using `COALESCE(..., 0)` to handle profiles with no matching configuration entry.
