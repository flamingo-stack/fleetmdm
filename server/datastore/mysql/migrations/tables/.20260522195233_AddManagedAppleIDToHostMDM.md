Adds the `managed_apple_id` column to the `host_mdm` table and backfills it for existing personal (BYOD/User Enrollment) hosts using their IdP account email.

## Key Components

- **`Up_20260522195233`** — Idempotent migration that:
  1. Adds `managed_apple_id VARCHAR(255)` (nullable, `utf8mb4_unicode_ci`) after `fleet_enroll_ref` if not already present.
  2. Backfills the new column for existing personal enrollment hosts by joining `host_mdm_idp_accounts` → `mdm_idp_accounts` and copying the IdP email — mirroring the behaviour of `TokenUpdate` for new enrollments so hosts don't need to re-enroll for VPP user provisioning.
- **`Down_20260522195233`** — No-op rollback; the column is left in place on downgrade.

## Usage Example

This migration is registered automatically via `init()` and applied by the Fleet migration runner. No manual invocation is required.

```go
// Registered automatically on package import:
MigrationClient.AddMigration(Up_20260522195233, Down_20260522195233)
```

To apply manually during development:

```bash
# Run all pending migrations
fleetctl prepare db --config /etc/fleet/fleet.yml
```

## Notes

- The `ALTER TABLE` step is guarded by `columnExists`, making the migration safe to re-run.
- The backfill only targets rows where `is_personal_enrollment = 1`, `managed_apple_id IS NULL`, and the IdP email is non-empty — existing corporate enrollments are unaffected.
