Database migration that adds a `critical` boolean column to the `policies` table, enabling policies to be flagged as critical.

## Key Components

- **`Up_20221130114928`** — Idempotent migration that adds a `critical TINYINT(1) NOT NULL DEFAULT FALSE` column to the `policies` table. Uses `columnExists` to guard against re-running on already-migrated schemas.
- **`Down_20221130114928`** — No-op rollback; the column is not dropped on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically via the migration client. No manual invocation is required.

```go
// Migration is registered on package init and executed by the migration runner.
// To apply manually during development:
MigrationClient.AddMigration(Up_20221130114928, Down_20221130114928)
```

After running migrations, the `policies` table will have the new column:

```sql
ALTER TABLE policies ADD COLUMN critical TINYINT(1) NOT NULL DEFAULT FALSE;
```

## Notes

- The migration is **idempotent** — safe to run multiple times due to the `columnExists` check.
- Rollback (`Down`) is intentionally a no-op; dropping the column on rollback could cause data loss and is left to manual intervention if needed.
