Database migration that removes foreign key constraints referencing the `hosts` table from `host_additional`, `host_users`, and `policy_membership` tables.

## Key Components

- **`Up_20220107155700`** — Iterates over the three target tables and calls `removeHostIDFK` for each; idempotent by design.
- **`Down_20220107155700`** — No-op rollback; FK removal is treated as irreversible.
- **`removeHostIDFK`** — Looks up existing FK constraints that reference `hosts` on a given table, then drops each one if it still exists (checked via `fkExists`).

## Usage Example

This migration runs automatically via the `MigrationClient` registered in `init()`. To apply it manually with [goose](https://github.com/pressly/goose) or a similar tool:

```bash
# Apply the migration
fleet prepare db --config /path/to/config.yml

# Verify FK removal on a target table
mysql -e "SHOW CREATE TABLE host_additional\G"
```

To exercise the helpers directly in a test:

```go
func TestRemoveHostIDFK(t *testing.T) {
    tx, _ := db.Begin()
    defer tx.Rollback()

    err := Up_20220107155700(tx)
    require.NoError(t, err)

    // Confirm no FK constraints remain for the hosts table
    constraints, _ := constraintsForTable(tx, "host_users", map[string]struct{}{"hosts": {}})
    assert.Empty(t, constraints)
}
```

> **Note:** `Down_20220107155700` is intentionally a no-op. Recreating dropped foreign keys is not guaranteed to be safe during a downgrade, so rollback is left as a manual operation if needed.
