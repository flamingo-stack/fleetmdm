Database migration that adds three performance indexes to the `cve_meta` and `vulnerability_host_counts` tables, targeting full-table scans on the vulnerabilities and software versions API endpoints.

## Key Components

**`Up_20260608202705(tx *sql.Tx) error`**
Idempotent migration that creates three online indexes using `ALGORITHM=INPLACE, LOCK=NONE` (non-blocking):

| Index | Table | Columns | Purpose |
|---|---|---|---|
| `idx_cve_meta_exploit` | `cve_meta` | `(cisa_known_exploit, cve)` | Turns `cisa_known_exploit = 1` filter into a range scan |
| `idx_cve_meta_cvss_score` | `cve_meta` | `(cvss_score, cve)` | Supports `cvss_score >= ?` range filter on software versions |
| `idx_vhc_scope_cve` | `vulnerability_host_counts` | `(global_stats, team_id, host_count, cve)` | Covering index for `ListVulnerabilities` / `CountVulnerabilities` scope filters |

**`Down_20260608202705(tx *sql.Tx) error`**
No-op rollback (indexes are left in place on downgrade).

**Idempotency**
Each statement is guarded by `indexExistsTx(tx, table, name)` — re-running the migration skips already-present indexes rather than erroring.

## Usage Example

This migration runs automatically via the `MigrationClient` registered in `init()`:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20260608202705, Down_20260608202705)
```

To apply manually during development:

```bash
fleetctl prepare db --config /path/to/fleet.yml
```
