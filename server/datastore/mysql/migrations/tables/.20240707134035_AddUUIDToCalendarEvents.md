Database migration that adds a UUID column to the `calendar_events` table and backfills existing rows with generated UUIDs.

## Key Components

- **`Up_20240707134035`** — Idempotent migration that:
  1. Adds a `uuid VARCHAR(36)` column (UTF8MB4) if it doesn't already exist
  2. Backfills existing rows using MySQL's `UUID()` function, preserving the original `updated_at` timestamp
  3. Adds a unique constraint `idx_calendar_events_uuid_unique` on the new column
- **`Down_20240707134035`** — No-op rollback; the migration is not reversed
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This file runs automatically as part of the Fleet database migration pipeline. No direct invocation is needed. The migration is idempotent — safe to re-run:

```go
// Column and constraint existence are checked before applying changes
if !columnExists(tx, "calendar_events", "uuid") {
    // ADD COLUMN + backfill only runs once
}

if !constraintExists(tx, "calendar_events", "idx_calendar_events_uuid_unique") {
    // UNIQUE constraint only added if missing
}
```

## Notes

- The UUID format follows the standard `8-4-4-4-12` pattern (`xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`)
- `updated_at = updated_at` in the `UPDATE` statement prevents MySQL from auto-updating the timestamp column during backfill
