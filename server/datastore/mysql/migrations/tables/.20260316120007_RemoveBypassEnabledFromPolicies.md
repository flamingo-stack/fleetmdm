Database migration that removes the `conditional_access_bypass_enabled` column from the `policies` table, first promoting qualifying bypass-enabled policies to `critical` status when Okta conditional access is fully configured.

## Key Components

- **`Up_20260316120007`** — Idempotent up migration that:
  1. Skips entirely if `conditional_access_bypass_enabled` column no longer exists
  2. Promotes policies with `conditional_access_bypass_enabled = TRUE` to `critical = TRUE` when the policy's team has `conditional_access_enabled` and Okta is globally configured (all four Okta fields populated in `app_config_json`)
  3. Drops the `conditional_access_bypass_enabled` column from `policies`

- **`Down_20260316120007`** — No-op rollback; the column removal is not reversed

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20260316120007, Down_20260316120007)
}
```

Policies are promoted to `critical` only when **all** of the following are true:

- `conditional_access_bypass_enabled = TRUE` on the policy
- The policy's team has `integrations.conditional_access_enabled = true` in its config
- The global `app_config_json` contains non-empty values for all four Okta fields:
  - `okta_idp_id`
  - `okta_assertion_consumer_service_url`
  - `okta_audience_uri`
  - `okta_certificate`

## Notes

- The migration is **idempotent**: re-running after the column is dropped is safe and returns immediately
- The `Down` migration is intentionally empty — schema rollback is not supported for this change
