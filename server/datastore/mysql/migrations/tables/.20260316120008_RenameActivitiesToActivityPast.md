Database migration that renames the `activities` table to `activity_past` and `host_activities` to `activity_host_past`, reflecting a naming convention update for historical activity records.

## Key Components

- **`Up_20260316120008`** — Executes the migration by renaming both activity tables. Idempotent: skips if `activities` no longer exists, preventing errors on re-run.
- **`Down_20260316120008`** — No-op rollback; the rename is considered a one-way schema change.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the migration client during schema upgrades:

```go
// Triggered internally by MigrationClient during fleet server startup or migration run.
// Manual invocation (for testing):
db, _ := sql.Open("mysql", dsn)
tx, _ := db.Begin()

if err := Up_20260316120008(tx); err != nil {
    tx.Rollback()
    log.Fatal(err)
}
tx.Commit()
```

## Notes

- **Idempotency** is handled by checking `tableExists(tx, "activities")` before executing `RENAME TABLE`. If the table has already been renamed (e.g., migration is re-applied), the function exits cleanly with `nil`.
- Both tables are renamed atomically in a single `RENAME TABLE` statement, ensuring consistency.
- The rollback (`Down`) is a deliberate no-op — reversing this rename would require a separate migration.
