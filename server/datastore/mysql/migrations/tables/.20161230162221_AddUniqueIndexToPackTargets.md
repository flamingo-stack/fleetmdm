Database migration that adds a unique composite index on the `pack_targets` table to prevent duplicate pack target entries.

## Key Components

- **`Up_20161230162221`** — Idempotently adds a `UNIQUE` constraint (`constraint_pack_target_unique`) on the `(pack_id, target_id, type)` column combination in `pack_targets`, skipping execution if the constraint already exists.
- **`Down_20161230162221`** — Drops the `constraint_pack_target_unique` index, reverting the migration.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically via the migration client. To run manually:

```go
// Applied as part of the standard migration chain
MigrationClient.AddMigration(Up_20161230162221, Down_20161230162221)
```

The `Up` function is idempotent — safe to run multiple times:

```go
// Internally checks before applying
if !constraintExists(tx, "pack_targets", "constraint_pack_target_unique") {
    tx.Exec("ALTER TABLE `pack_targets` ADD CONSTRAINT ...")
}
```

## Notes

- The unique constraint spans three columns: `pack_id`, `target_id`, and `type`, ensuring no two rows can define the same target of the same type for the same pack.
