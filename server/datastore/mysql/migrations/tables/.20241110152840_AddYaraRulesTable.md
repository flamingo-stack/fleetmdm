Database migration that creates the `yara_rules` table for storing YARA threat detection rules.

## Key Components

- **`Up_20241110152840`** — Creates the `yara_rules` table if it does not already exist (idempotent). Defines three columns: an auto-incrementing `id`, a unique `name` (VARCHAR 255), and `contents` (MEDIUMTEXT) for the raw rule body. Uses InnoDB engine with `utf8mb4_unicode_ci` collation.
- **`Down_20241110152840`** — No-op rollback; the table is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Schema

```text
yara_rules
├── id       INT UNSIGNED  AUTO_INCREMENT  PRIMARY KEY
├── name     VARCHAR(255)  NOT NULL        UNIQUE
└── contents MEDIUMTEXT    NOT NULL
```

## Usage Example

This migration runs automatically via the `MigrationClient` on application startup. To apply or roll back manually:

```go
// Apply
err := Up_20241110152840(tx)

// Rollback (no-op)
err := Down_20241110152840(tx)
```

## Notes

- The `UNIQUE KEY` on `name` prevents duplicate rule entries and enables fast lookups by rule name.
- `MEDIUMTEXT` supports YARA rule files up to ~16 MB.
- The rollback is intentionally empty — dropping the table on downgrade would cause data loss and is left to operator discretion.
