Database migration that adds an index on the `token` field, a `resync` column, and cleans up invalid `remove` operation rows in the `host_mdm_apple_declarations` table.

## Key Components

- **`Up_20250513162912`** — Applies three idempotent changes to `host_mdm_apple_declarations`:
  - Adds `idx_token` index on the `token` column (enables efficient lookup of identical declarations)
  - Adds a `resync` (`TINYINT(1)`, default `0`) column to trigger forced `DeclarativeManagement` resyncs in edge cases
  - Deletes stale rows where `operation_type = 'remove'` and `status IN ('verifying', 'verified')` — invalid states per MDM protocol, left over from [fleetdm/fleet#27979](https://github.com/fleetdm/fleet/issues/27979)
- **`Down_20250513162912`** — No-op rollback; changes are not reversed.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client during schema upgrades:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20250513162912, Down_20250513162912)
}

// Applied during fleet database migration
fleet db migrate
```

The `Up` function guards schema changes with `indexExistsTx` and `columnExists` checks, making it safe to re-run without errors.

## Notes

- **Source:** [`server/datastore/mysql/migrations/tables/20250513162912_HostMDMAppleDeclarationsToken.go`](https://github.com/flamingo-stack/fleetmdm/blob/main/server/datastore/mysql/migrations/tables/20250513162912_HostMDMAppleDeclarationsToken.go)
- `remove` operations are only valid with `nil` or `pending` status; rows in `verifying`/`verified` state represent data corruption requiring cleanup.
- Rollback is intentionally a no-op — index and column removal would require additional safety checks.
