Database migration that adds a `display_version` column to the `operating_systems` table and updates the unique index to include the new column.

## Key Components

- **`Up_20240110134315`** — Idempotent migration that:
  1. Adds `display_version VARCHAR(10)` column (UTF8MB4, NOT NULL, default `''`) if it doesn't already exist
  2. Drops the existing `idx_unique_os` unique index
  3. Recreates `idx_unique_os` including `display_version` in the uniqueness constraint
- **`Down_20240110134315`** — No-op rollback (column removal not implemented)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20240110134315, Down_20240110134315)
```

The updated unique index covers:

```text
(name, version, arch, kernel_version, platform, display_version)
```

## Notes

- The migration is **idempotent** — guarded by `columnExists()` to safely re-run without error
- The existing unique index is dropped and recreated to incorporate `display_version`, ensuring OS records with differing display versions (e.g. Windows feature updates like `22H2`) are treated as distinct entries
- Rollback is a no-op; manual intervention is required to reverse this schema change
