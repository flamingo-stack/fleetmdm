Database migration that fixes incorrect `last_enrolled_at` values for macOS hosts affected by a bug introduced in Fleet v4.51.0, where MDM re-enrollment incorrectly reset the field to `2000-01-01 00:00:00`.

## Key Components

- **`Up_20240710155623`** — Updates `hosts.last_enrolled_at` using `host_disks.created_at` as an approximation for darwin hosts where the value was incorrectly set to the sentinel "Never" date. The `updated_at` field is preserved by self-assigning to prevent triggering timestamp auto-updates.
- **`Down_20240710155623`** — No-op rollback; the original enrollment date cannot be recovered.

## Usage Example

This migration runs automatically via the `MigrationClient` on `fleet prepare db` or server startup:

```go
// Registered automatically via init()
MigrationClient.AddMigration(Up_20240710155623, Down_20240710155623)
```

The core fix applied:

```sql
UPDATE hosts h
JOIN host_disks hd ON h.id = hd.host_id
SET h.last_enrolled_at = hd.created_at,
    h.updated_at = h.updated_at
WHERE h.platform = 'darwin'
  AND h.last_enrolled_at = '2000-01-01 00:00:00';
```

> **Note:** This migration is idempotent — running it multiple times is safe. Only macOS (`darwin`) hosts with the sentinel date `2000-01-01 00:00:00` are affected.
