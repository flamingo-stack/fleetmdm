Database migration that adds the `fim_file_accesses` column to the `app_configs` table, enabling File Integrity Monitoring (FIM) file access configuration storage.

## Key Components

- **`Up20170831234303`** — Idempotent migration that adds `fim_file_accesses` as a `VARCHAR(255) NOT NULL DEFAULT ''` column to `app_configs`. Checks for column existence before applying to prevent duplicate-column errors.
- **`Down20170831234303`** — Rolls back the migration by dropping the `fim_file_accesses` column from `app_configs`.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Migrations are registered automatically via init() and run by the migration client.
// To apply manually within a transaction:
func applyMigration(db *sql.DB) error {
    tx, err := db.Begin()
    if err != nil {
        return err
    }

    if err := Up20170831234303(tx); err != nil {
        tx.Rollback()
        return err
    }

    return tx.Commit()
}

// To roll back:
func rollbackMigration(db *sql.DB) error {
    tx, err := db.Begin()
    if err != nil {
        return err
    }

    if err := Down20170831234303(tx); err != nil {
        tx.Rollback()
        return err
    }

    return tx.Commit()
}
```

> **Note:** The `Up` function is idempotent — safe to run multiple times. The `Down` function does not check for column existence before dropping, so it will error if run against a schema where the column is already absent.
