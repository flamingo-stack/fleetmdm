Database migration that updates the `scheduled_queries` table schema by adding a `query_name` foreign key column, `name`/`description` metadata columns, and removes the deprecated `created_by` column from `packs`.

## Key Components

- **`Up_20171219164727`** — Applies the migration with full idempotency checks:
  - Adds `query_name` column to `scheduled_queries`, populated via join with the `queries` table
  - Removes orphaned scheduled queries (where no matching query exists)
  - Applies a `NOT NULL` constraint to `query_name`
  - Adds a foreign key constraint (`scheduled_queries_ibfk_1`) referencing `queries(name)`
  - Adds `name` and `description` columns (UTF8MB4) to `scheduled_queries`
  - Drops the `created_by` column from `packs`
- **`Down_20171219164727`** — No-op rollback (migration is not reversible)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registration happens automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20171219164727, Down_20171219164727)
}

// Idempotency guards prevent duplicate column/FK creation
if !columnExists(tx, "scheduled_queries", "query_name") {
    // Safe to run on already-migrated databases
}
```

## Notes

- All schema changes are guarded by `columnExists`, `columnsExists`, and `fkExists` helpers, making re-runs safe
- Orphaned scheduled queries (referencing non-existent query IDs) are purged before the `NOT NULL` constraint is applied
- The rollback (`Down`) is intentionally empty — data cleanup from the `DELETE` step cannot be safely reversed
