Database migration that enforces the `ForceEnableInSetupAssistant` key in existing FileVault MDM configuration profiles stored in Fleet's database.

## Key Components

- **`init()`** — Registers the migration with `MigrationClient` using the `Up` and `Down` functions.
- **`setKeyInPayloadContent(original, destType, key, value)`** — Parses a plist mobileconfig payload, locates the entry matching `destType` inside `PayloadContent`, injects or updates the specified `key`/`value`, and re-serialises to XML plist format.
- **`Up_20240725152735(tx)`** — Selects all FileVault profiles (`com.fleetdm.fleet.mdm.filevault`) from `mdm_apple_configuration_profiles`, sets `ForceEnableInSetupAssistant = true` on the `com.apple.MCX.FileVault2` payload, and updates the row including a recalculated MD5 checksum. The migration is idempotent.
- **`Down_20240725152735(tx)`** — No-op rollback; the change is non-reversible by design.

## Usage Example

This migration runs automatically via Fleet's migration client. It is not called directly, but the helper `setKeyInPayloadContent` illustrates the plist manipulation pattern:

```go
original := []byte(`<?xml version="1.0"?>...`) // existing mobileconfig bytes

updated, err := setKeyInPayloadContent(
    original,
    "com.apple.MCX.FileVault2",       // target PayloadType
    "ForceEnableInSetupAssistant",    // key to set
    true,                             // value
)
if err != nil {
    log.Fatal(err)
}
// updated is a valid XML plist with the new key injected
```
