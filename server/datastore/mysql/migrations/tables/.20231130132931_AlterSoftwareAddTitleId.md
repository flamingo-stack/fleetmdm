Database migration that adds a `title_id` foreign key column and index to the `software` table.

## Key Components

- **`Up_20231130132931`** — Idempotent migration that adds an unsigned nullable `INT(10)` column `title_id` and a corresponding index to the `software` table. Guards each step with existence checks to prevent duplicate column/index errors on re-run.
- **`Down_20231130132931`** — No-op rollback; the column and index are left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Applied automatically by the migration runner at startup.
// Manual execution via goose or equivalent:
goose up   // runs Up_20231130132931
goose down // runs Down_20231130132931 (no-op)
```

The migration is safe to re-apply:

```go
// columnExists and indexExistsTx guard each DDL statement,
// so re-running Up_20231130132931 against an already-migrated
// database will skip both ALTER TABLE calls without error.
if !columnExists(tx, "software", "title_id") {
    tx.Exec(`ALTER TABLE software ADD COLUMN title_id INT(10) UNSIGNED DEFAULT NULL`)
}
if !indexExistsTx(tx, "software", "title_id") {
    tx.Exec(`ALTER TABLE software ADD INDEX (title_id)`)
}
```

## Notes

- The column is intentionally nullable (`DEFAULT NULL`) to allow gradual back-fill of existing rows.
