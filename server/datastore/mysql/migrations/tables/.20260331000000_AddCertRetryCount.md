Adds a `retry_count` column to the `host_certificate_templates` table via an idempotent database migration.

## Key Components

- **`Up_20260331000000`** — Adds an `INT UNSIGNED NOT NULL DEFAULT 0` column named `retry_count` to `host_certificate_templates`. Uses a `columnExists` guard to ensure the migration is safe to re-run.
- **`Down_20260331000000`** — No-op rollback; the column is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically by the Fleet migration runner. No manual invocation is required.

```go
// Migration is registered on package import via init()
// and executed by the migration client in order:
MigrationClient.AddMigration(Up_20260331000000, Down_20260331000000)
```

To verify the column was added after running migrations:

```sql
SELECT retry_count FROM host_certificate_templates LIMIT 1;
```

## Notes

- The migration is **idempotent**: if `retry_count` already exists (e.g., after a partial run), the `ALTER TABLE` is skipped.
- The default value of `0` ensures existing rows are unaffected by the schema change.
