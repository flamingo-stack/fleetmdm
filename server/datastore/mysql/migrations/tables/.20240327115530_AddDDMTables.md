Database migration that creates four tables supporting Apple Declarative Device Management (DDM) in the MDM subsystem.

## Key Components

### `Up_20240327115530`
Creates the following tables (idempotent via `IF NOT EXISTS`):

| Table | Purpose |
|---|---|
| `mdm_apple_declarations` | Stores DDM declaration definitions with UUID, team scoping, JSON payload, and MD5 checksum |
| `mdm_declaration_labels` | Maps declarations to Fleet labels, preserving label names even after label deletion |
| `mdm_apple_declaration_activation_references` | Tracks cross-references between declarations (activation dependencies) |
| `host_mdm_apple_declarations` | Tracks per-host declaration delivery state, operation type, and checksum |

### `Down_20240327115530`
No-op rollback — tables are not dropped.

## Schema Notes

- **`mdm_apple_declarations`** enforces uniqueness per `(team_id, identifier)` and `(team_id, name)`, supporting multi-tenant isolation.
- **`mdm_declaration_labels`** uses `ON DELETE SET NULL` on `label_id` and `ON DELETE CASCADE` on the declaration FK, enabling "broken" label state detection in the UI.
- **`host_mdm_apple_declarations`** references `mdm_delivery_status` and `mdm_operation_types` lookup tables via cascading FK constraints.
