Database migration that updates the `mdm_apple_delivery_status` table, renaming the `applied` status value to `verifying`.

## Key Components

- **`Up_20230421155932`** — Executes an idempotent `UPDATE` statement that renames the `status` column value from `'applied'` to `'verifying'` across all matching rows in `mdm_apple_delivery_status`.
- **`Down_20230421155932`** — No-op rollback; the status rename is not reversed.
- **`init`** — Registers both migration functions with the `MigrationClient`.

## Usage Example

This migration is applied automatically by the Fleet migration runner. No manual invocation is required.

```go
// Registered automatically on package init
MigrationClient.AddMigration(Up_20230421155932, Down_20230421155932)
```

To apply manually in a test context:

## Notes

- **Idempotent**: Safe to run multiple times — rows already set to `'verifying'` are unaffected by the `WHERE status = 'applied'` filter.
- **No rollback**: `Down_20230421155932` is a no-op, so this status rename is considered a one-way data migration.
