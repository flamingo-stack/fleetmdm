Database migration that converts the `calendar_events` table's UUID storage from a plain `VARCHAR` column to an efficient `BINARY(16)` column, with the original `uuid` field replaced by a virtual generated column.

## Key Components

- **`Up_20240709132642(tx *sql.Tx) error`** — Applies the migration in three idempotent steps:
  1. Adds a `uuid_bin BINARY(16)` column and populates it using `UNHEX(REPLACE(uuid,'-',''))` for all existing rows.
  2. Adds a unique constraint `idx_calendar_events_uuid_bin_unique` on `uuid_bin`.
  3. Drops the original `uuid VARCHAR` column and re-adds it as a `VIRTUAL GENERATED` column derived from `uuid_bin` using MySQL `INSERT`/`HEX` string formatting.
- **`Down_20240709132642(_ *sql.Tx) error`** — No-op rollback; migration is intentionally irreversible.
- **`init()`** — Registers both directions with `MigrationClient`.

## Usage Example

This migration runs automatically via the migration client. To apply manually during development:

```bash
fleet db migrate
```

To verify the resulting schema:

```sql
SHOW COLUMNS FROM calendar_events LIKE 'uuid%';
-- uuid_bin  | binary(16) | NO  | UNI | NULL    |
-- uuid      | varchar(36)| YES |     | NULL    | VIRTUAL GENERATED
```

## Notes

- **Idempotent**: Guards on `columnExists` and `constraintExists` make the migration safe to re-run.
- **`updated_at` preservation**: The `UPDATE` statement explicitly sets `updated_at = updated_at` to prevent MySQL from auto-updating the timestamp.
- Design follows the [MySQL UUID binary storage pattern](https://dev.mysql.com/blog-archive/storing-uuid-values-in-mysql-tables/).
