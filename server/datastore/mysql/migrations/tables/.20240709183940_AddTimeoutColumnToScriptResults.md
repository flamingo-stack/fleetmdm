Database migration that adds a `timeout` column to the `host_script_results` table, enabling per-script custom timeout configuration instead of the previously hardcoded 300-second default.

## Key Components

| Symbol | Description |
|--------|-------------|
| `Up_20240709183940` | Adds `timeout INT DEFAULT NULL` column to `host_script_results` and backfills existing rows with `300` (the prior hardcoded value). Idempotent — skips if the column already exists. |
| `Down_20240709183940` | No-op rollback; the column is left in place on downgrade. |
| `init` | Registers both migration functions with `MigrationClient`. |

## Usage Example

This migration is applied automatically by the Fleet migration runner. To run manually:

```bash
# Apply migration
fleetctl prepare db --config /etc/fleet/fleet.yml

# Verify column was added
mysql -u fleet -p fleet -e "DESCRIBE host_script_results;"
```
