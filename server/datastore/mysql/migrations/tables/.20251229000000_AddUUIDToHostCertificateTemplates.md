Database migration that adds a nullable `uuid` column of type `BINARY(16)` to the `host_certificate_templates` table.

## Key Components

- **`Up_20251229000000`** — Applies the migration. Checks for column existence before altering the table, making the operation idempotent. Adds a `uuid BINARY(16) NULL` column to `host_certificate_templates`.
- **`Down_20251229000000`** — No-op rollback; the migration is not reversed.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically via the `MigrationClient` when running database migrations:

```go
// Migration is self-registering via init()
// Triggered by the migration runner at startup or via CLI

// Up: adds uuid column if not present (idempotent)
Up_20251229000000(tx)

// Down: no-op, column is not removed on rollback
Down_20251229000000(tx)
```

## Notes

- The `uuid` column is **nullable** (`NULL`), so existing rows are unaffected after migration.
- Idempotency is enforced via `columnExists()` — safe to re-run without error.
- No rollback logic is implemented; dropping the column on downgrade must be handled manually if required.
