Database migration that adds a unique MD5 checksum column to the `policies` table, replacing the old unique index on `name` with a hash-based uniqueness constraint scoped to `(team_id, name)`.

## Key Components

- **`Up_20240131083822`** — Idempotent migration that:
  1. Adds a `checksum BINARY(16)` column to `policies`
  2. Backfills existing rows using `UNHEX(MD5(CONCAT_WS(CHAR(0), COALESCE(team_id, ''), name)))`
  3. Alters the column to `NOT NULL` and adds a unique index `idx_policies_checksum`
  4. Drops the legacy `idx_policies_unique_name` index if present
- **`Down_20240131083822`** — No-op rollback
- **Idempotency guards** — Uses `columnExists` and `indexExistsTx` helpers to safely re-run without errors

## Checksum Design

The checksum is computed using MD5 (consistent with Fleet's `software` table and configuration profiles) over a null-byte-separated concatenation of `team_id` and `name`. This shifts uniqueness enforcement from `name` alone to the `(team_id, name)` pair, enabling policies with the same name across different teams.

The authoritative runtime logic lives in `mysql.policiesChecksumComputedColumn`; the migration intentionally inlines the SQL to remain stable if that function changes.
