Database migration (2024-08-26) that adds a `removed` column to `host_software_installs` and `host_vpp_software_installs` tables, then backfills existing records where software is no longer installed on the host.

## Key Components

- **`Up_20240826160025`** — Idempotent up migration that:
  1. Adds `removed TINYINT NOT NULL DEFAULT 0` to `host_software_installs` (if not already present)
  2. Adds `removed TINYINT NOT NULL DEFAULT 0` to `host_vpp_software_installs` (if not already present)
  3. Backfills `removed = 1` for package installs where software is confirmed installed elsewhere but absent from the specific host's `host_software` records, and the host detail query has run since installation
  4. Backfills `removed = 1` for VPP installs under the same absence criteria

- **`Down_20240826160025`** — No-op rollback; column removal is not performed

## Backfill Logic

The backfill queries use three key conditions to identify "removed" installs:

| Condition | Purpose |
|---|---|
| Software exists in `software` table for another host | Confirms the title is detectable (avoids false positives for undetectable software) |
| No matching row in `host_software` for the target host | Confirms the software is absent on that host |
| `updated_at < h.detail_updated_at` | Confirms a full detail refresh occurred after install |

## Usage Example

This migration runs automatically via the migration client at startup:

```go
// Registered automatically via init()
MigrationClient.AddMigration(Up_20240826160025, Down_20240826160025)
```

To apply manually during development:

```bash
fleet prepare db --dev
```
