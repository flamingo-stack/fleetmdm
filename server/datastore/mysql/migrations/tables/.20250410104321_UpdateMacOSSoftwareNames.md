Database migration that strips `.app` suffixes from macOS application software names in `software_titles` and `software` tables, deduplicates software records by merging host associations, and adds a `name_source` column to track naming conventions.

## Key Components

| Function | Description |
|---|---|
| `Up_20250410104321` | Applies the migration: strips `.app` suffixes, merges duplicate software records, and adds `name_source` column |
| `Down_20250410104321` | No-op rollback (migration is not reversible) |

## Migration Steps

The `Up` function executes the following sequence:

1. **Strip `.app` suffixes** from `software_titles.name` for rows where `source = 'apps'`
2. **Detect duplicates** — identifies `software` rows that will share the same checksum after renaming, grouping by `(version, source, bundle_identifier, release, arch, vendor, browser, extension_id)`
3. **Merge host associations** — for each duplicate group, re-points `host_software` and `host_software_installed_paths` records to the canonical (selected) software ID in batches of up to 10,000 hosts
4. **Delete duplicate records** — removes orphaned rows from `software_cve`, `host_software`, and `software`
5. **Update software names and checksums** — strips `.app` and recomputes `MD5` checksum on the canonical rows
6. **Add `name_source` column** — idempotently adds `name_source ENUM('basic', 'bundle_4.67') DEFAULT 'basic'` to `software`

## Usage Example

This migration is registered automatically via `init()` and run by the migration client:

```go
func init() {
    MigrationClient.AddMigration(Up_20250410104321, Down_20250410104321)
}
```

No manual invocation is required. The migration client executes `Up_20250410104321` during the standard database upgrade sequence.

> **Note:** `Down_20250410104321` is a no-op. The `.app` suffix stripping and record deduplication are not rolled back on downgrade.
