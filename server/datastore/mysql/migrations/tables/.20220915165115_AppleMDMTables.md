Database migration file that creates Apple MDM-related tables by applying embedded SQL schemas for SCEP, NanoMDM, and NanoDEP, along with Fleet-specific enrollment and installer tables.

## Key Components

- **`Up_20220915165115`** — Applies the full Apple MDM schema in sequence:
  1. SCEP schema (`20220915165115_AppleMDMTables_scep.sql`)
  2. NanoMDM core schema (`20220915165115_AppleMDMTables_nanomdm.sql`)
  3. Unique constraint on `nano_users.id` (applied idempotently via `indexExistsTx`)
  4. NanoDEP schema (`20220915165115_AppleMDMTables_nanodep.sql`)
  5. Fleet-specific tables: `mdm_apple_enrollment_profiles` and `mdm_apple_installers`

- **`Down_20220915165115`** — No-op rollback (migration is not reversible).

- **Embedded SQL files** — Three `.sql` files are embedded at compile time via `//go:embed` directives for SCEP, NanoMDM, and NanoDEP schemas.

## Tables Created

| Table | Purpose |
|---|---|
| `mdm_apple_enrollment_profiles` | Stores automatic/manual enrollment profiles with optional DEP profile JSON |
| `mdm_apple_installers` | Stores MDM installer binaries, manifests, and URL tokens |

## Usage Example

This migration runs automatically via the `MigrationClient` registered in `init()`. To apply manually:

```go
// Typically invoked by the migration runner, not called directly.
// The migration is registered on package init:
MigrationClient.AddMigration(Up_20220915165115, Down_20220915165115)
```

The `Up` function is idempotent — all tables use `CREATE TABLE IF NOT EXISTS` and the `nano_users` unique constraint is guarded by `indexExistsTx`.
