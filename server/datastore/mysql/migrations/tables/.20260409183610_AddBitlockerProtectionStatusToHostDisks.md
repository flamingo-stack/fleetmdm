Database migration that adds a nullable `bitlocker_protection_status` column to the `host_disks` table, enabling storage of BitLocker drive encryption protection status per host disk.

## Key Components

- **`Up_20260409183610`** — Idempotent migration that adds `bitlocker_protection_status TINYINT(1) NULL DEFAULT NULL` to `host_disks` if the column does not already exist.
- **`Down_20260409183610`** — No-op rollback; the column is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Applied automatically by the migration runner at startup.
// To run manually using the Fleet migration CLI:
```

```bash
fleetctl prepare db --config /etc/fleet/fleet.yml
```

The migration is guarded by `columnExists`, making it safe to re-run:

```go
if !columnExists(tx, "host_disks", "bitlocker_protection_status") {
    tx.Exec(`ALTER TABLE host_disks ADD COLUMN bitlocker_protection_status TINYINT(1) NULL DEFAULT NULL`)
}
```

## Notes

- **Column type:** `TINYINT(1)` — stores tri-state values (`NULL` = unknown, `0` = unprotected, `1` = protected).
- **Idempotent:** Uses `columnExists` guard; safe for repeated execution in multi-instance deployments.
- **Rollback:** `Down` is intentionally empty — no destructive action is taken on downgrade.
