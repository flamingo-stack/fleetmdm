Database migration that renames the `updated_at` column to `uploaded_at` (as a nullable `TIMESTAMP`) in both the `mdm_windows_configuration_profiles` and `mdm_apple_configuration_profiles` tables.

## Key Components

- **`Up_20240205095928`** — Idempotent upgrade migration that checks for the existence of the `updated_at` column before renaming it to `uploaded_at` on each MDM profile table. Safe to re-run; skips the `ALTER` if the column has already been renamed.
- **`Down_20240205095928`** — No-op rollback; the rename is not reversed.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the migration client at startup or during a manual `fleet prepare db` command. No direct invocation is needed, but the underlying SQL is:

```go
// Up migration (executed per table only if updated_at still exists)
ALTER TABLE mdm_windows_configuration_profiles
    CHANGE COLUMN updated_at uploaded_at TIMESTAMP NULL;

ALTER TABLE mdm_apple_configuration_profiles
    CHANGE COLUMN updated_at uploaded_at TIMESTAMP NULL;
```

## Notes

- The column is kept **nullable** intentionally — enforcing `NOT NULL` would risk failures if any existing rows had `NULL` values set manually or by a prior bug.
- Idempotency is guaranteed via the `columnExists` helper, making re-application safe in all environments.
