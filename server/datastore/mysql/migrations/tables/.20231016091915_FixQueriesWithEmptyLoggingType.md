Database migration that fixes queries with empty `logging_type` values by setting them to `fleet.LoggingSnapshot` as the default.

## Key Components

- **`Up_20231016091915`** — Updates all rows in the `queries` table where `logging_type` is an empty string, replacing them with `fleet.LoggingSnapshot`. The migration is idempotent and safe to re-run.
- **`Down_20231016091915`** — No-op rollback; the fix is non-reversible by design.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the Fleet migration framework. No manual invocation is required.

```go
// Migration is registered on package init and executed by the migration client:
MigrationClient.AddMigration(Up_20231016091915, Down_20231016091915)

// Internally, Up applies:
UPDATE queries SET logging_type = 'snapshot' WHERE logging_type = '';
```

## Notes

- The fix targets a data integrity issue where queries were stored without a `logging_type`, which could cause undefined behavior in log processing.
- `fleet.LoggingSnapshot` is the default logging mode, making it a safe fallback for all affected rows.
