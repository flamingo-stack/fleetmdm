Database migration that adds an `orbit_debug_until` nullable timestamp column to the `hosts` table, enabling time-bounded debug mode scheduling for Orbit agents.

## Key Components

| Symbol | Description |
|---|---|
| `Up_20260522195231` | Forward migration — idempotently adds `orbit_debug_until TIMESTAMP(6) NULL DEFAULT NULL` to `hosts` |
| `Down_20260522195231` | Rollback stub — no-op (column removal omitted intentionally) |
| `init()` | Registers both migration functions with `MigrationClient` |

## Usage Example

```go
// Applied automatically by the Fleet migration runner.
// To run manually during development:
fleet db migrate --env development

// The resulting column allows scheduling debug windows per host:
UPDATE hosts
SET orbit_debug_until = NOW() + INTERVAL 1 HOUR
WHERE id = 42;
```

## Notes

- **Idempotent**: uses `columnExists` guard so re-running the migration is safe.
- **Precision**: `TIMESTAMP(6)` stores microsecond-level timestamps, suitable for precise debug window expiry checks.
- **Rollback**: `Down_` is intentionally a no-op; dropping columns destructively in a rollback is avoided per Fleet migration conventions.
