Database migration that removes orphaned records from host-related tables where the referenced host no longer exists in the `hosts` table.

## Key Components

- **`Up_20220323152301`** — Iterates over 11 host-related tables and deletes any rows whose `host_id` has no corresponding entry in `hosts`. The operation is idempotent and safe to re-run.
- **`Down_20220323152301`** — No-op rollback; deleted orphan records are not restored.

### Affected Tables

| Table | Table |
|---|---|
| `host_seen_times` | `label_membership` |
| `host_software` | `policy_membership` |
| `host_users` | `host_mdm` |
| `host_emails` | `host_munki_info` |
| `host_additional` | `host_device_auth` |
| `scheduled_query_stats` | |

## Usage Example

This migration runs automatically via the `MigrationClient` on `fleet prepare db` or equivalent startup:

```go
// Registered in init(); executed by the migration runner
MigrationClient.AddMigration(Up_20220323152301, Down_20220323152301)
```

The core cleanup pattern applied to each table:

```go
DELETE target
FROM host_seen_times target
WHERE NOT EXISTS (
  SELECT 1 FROM hosts h
  WHERE h.id = target.host_id
)
```

## Notes

- All deletes share a single parameterized statement template (`delStmt`) formatted with `fmt.Sprintf` per table name.
- Any per-table failure wraps the error with context (e.g., `"delete from host_software"`) and aborts the migration transaction.
