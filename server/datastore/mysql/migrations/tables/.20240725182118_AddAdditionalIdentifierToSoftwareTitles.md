Database migration that adds a virtual `additional_identifier` column to the `software_titles` table and updates its unique index to include the new column.

## Key Components

- **`Up_20240725182118`** — Applies the migration:
  - Adds a `VIRTUAL` generated column `additional_identifier` (`TINYINT UNSIGNED`) derived from the `source` and `bundle_identifier` fields:
    - `1` → `ios_apps`
    - `2` → `ipados_apps`
    - `0` → any source with a non-null `bundle_identifier`
    - `NULL` → all other cases
  - Drops the existing `idx_software_titles_bundle_identifier` unique index if present
  - Recreates the index as a composite unique key on `(bundle_identifier, additional_identifier)`
  - Guards against re-runs using `columnExists` and `indexExistsTx` checks (idempotent)

- **`Down_20240725182118`** — No-op rollback (returns `nil`)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20240725182118, Down_20240725182118)
}
```

The `additional_identifier` column disambiguates software titles that share a `bundle_identifier` across platforms (e.g., the same bundle ID used by both an iOS and iPadOS app), allowing the unique index to correctly scope uniqueness per source platform.

## Notes

- The column is `VIRTUAL` — no storage cost; computed at read time
- Migration is fully idempotent: safe to re-run without side effects
- `Down` is intentionally a no-op; schema rollback is not supported for this migration
