Database migration that adds a `platform` column to the `vpp_apps` and `vpp_apps_teams` tables, enabling multi-platform support for VPP (Volume Purchase Program) apps beyond macOS.

## Key Components

- **`Up_20240730374423`** — Applies the migration with the following steps:
  - Adds `platform VARCHAR(10)` column to `vpp_apps` and `vpp_apps_teams`
  - Backfills existing rows with `fleet.MacOSPlatform`
  - Drops and recreates the `vpp_apps` primary key as a composite `(adam_id, platform)`
  - Manages foreign key constraints on `vpp_apps_teams` and `host_vpp_software_installs`
  - Updates unique index `idx_global_or_team_id_adam_id` to include `platform`
  - Recreates the `adam_id` index to cover `(adam_id, platform)`
  - Adds a new foreign key referencing the updated composite primary key
- **`Down_20240730374423`** — No-op rollback (schema changes are not reversed)

## Usage Example

This migration is registered automatically via `init()` and executed by the Fleet migration runner:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20240730374423, Down_20240730374423)
}
```

To apply manually during development:

```bash
fleet prepare db --config /etc/fleet/fleet.yml
```

## Notes

- **Idempotent**: The `Up` function checks whether the `platform` column already exists in both tables before applying any changes, making it safe to re-run.
- **Foreign key ordering**: `vpp_apps_teams_ibfk_1` and `host_vpp_software_installs_ibfk_2` are dropped before altering the primary key to avoid MySQL constraint conflicts. The latter is restored in a subsequent migration.
