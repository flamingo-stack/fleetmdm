Database migration that increases the precision of the `created_at` column in the `activities` table from standard `TIMESTAMP` to microsecond precision (`TIMESTAMP(6)`).

## Key Components

- **`Up_20240618142419`** — Alters the `activities.created_at` column to `TIMESTAMP(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)`, enabling microsecond-level timestamp precision. The migration is idempotent, checking for column existence before executing.
- **`Down_20240618142419`** — No-op rollback; the downgrade is intentionally left as a no-op.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Applied automatically by the migration runner on startup.
// To run manually using the Fleet migration CLI:
//
//   fleetctl prepare db --config /etc/fleet/fleet.yml
//
// The migration guard ensures safety:
if columnExists(tx, "activities", "created_at") {
    tx.Exec(`ALTER TABLE activities MODIFY COLUMN created_at TIMESTAMP(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)`)
}
```

> **Note:** This migration is idempotent — if `created_at` does not exist, the `ALTER TABLE` is skipped without error. The rollback (`Down`) is a no-op because reverting timestamp precision could cause data loss and is generally unnecessary in practice.
