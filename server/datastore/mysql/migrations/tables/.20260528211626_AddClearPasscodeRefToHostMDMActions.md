Database migration that adds a `clear_passcode_ref` column to the `host_mdm_actions` table, enabling tracking of pending passcode-clear operations for Android MDM hosts.

## Key Components

- **`Up_20260528211626`** — Adds `clear_passcode_ref VARCHAR(36)` (nullable, `utf8mb4_unicode_ci`) to `host_mdm_actions`. Idempotent via `columnExists` guard. For Android hosts, this column stores the `command_uuid` of an AMAPI `RESET_PASSWORD` command; `HostLockWipeStatus.IsPendingClearPasscode` reads it to determine the "clearing passcode" device status. Non-Android platforms leave the column `NULL`.
- **`Down_20260528211626`** — No-op rollback (column removal not implemented).
- **`init`** — Registers the migration pair with `MigrationClient`.

## Usage Example

```go
// Applied automatically by the Fleet migration runner.
// The new column mirrors lock_ref and wipe_ref in host_mdm_actions:

// host_mdm_actions schema (relevant columns after migration):
// lock_ref          VARCHAR(36) DEFAULT NULL
// wipe_ref          VARCHAR(36) DEFAULT NULL
// clear_passcode_ref VARCHAR(36) DEFAULT NULL  ← added by this migration

// Android usage: when a RESET_PASSWORD AMAPI command is dispatched,
// clear_passcode_ref is set to mdm_android_commands.command_uuid.
// HostLockWipeStatus checks:
if action.ClearPasscodeRef != nil {
    // host is in "clearing passcode" state
}
```
