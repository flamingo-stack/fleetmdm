Database migration that removes the `host_id` column from the `operating_system_vulnerabilities` table and restructures its indexes to key vulnerabilities by `operating_system_id` instead.

## Key Components

- **`Up_20240119091637`** — Applies the migration with idempotent steps:
  1. Truncates `operating_system_vulnerabilities` (table was previously unused, so truncation is safe)
  2. Drops legacy indexes `idx_operating_system_vulnerabilities_unq_cve` and `idx_operating_system_vulnerabilities_operating_system_id_cve` if they exist
  3. Drops the `host_id` column if it exists
  4. Adds new unique index `idx_os_vulnerabilities_unq_os_id_cve` on `(operating_system_id, cve)` if not already present

- **`Down_20240119091637`** — No-op rollback; the migration is intentionally irreversible since the table was truncated

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20240119091637, Down_20240119091637)
}

// Each structural change is guarded for idempotency
if columnExists(tx, "operating_system_vulnerabilities", "host_id") {
    // DROP COLUMN host_id
}

if !indexExistsTx(tx, "operating_system_vulnerabilities", "idx_os_vulnerabilities_unq_os_id_cve") {
    // ADD UNIQUE INDEX (operating_system_id, cve)
}
```

## Notes

- All DDL operations are guarded with `columnExists`/`indexExistsTx` checks, making the migration safe to re-run
- The rollback (`Down`) is a no-op because restoring truncated data is not feasible; treat this as a one-way migration
