Database migration that creates the `policy_stats` table for caching policy compliance host counts per policy and team.

## Key Components

- **`Up_20231121054530`** — Creates the `policy_stats` table using `CREATE TABLE IF NOT EXISTS` (idempotent). Defines columns for policy/team association and cached passing/failing host counts, with a foreign key to `policies(id)` and a unique constraint on `(policy_id, inherited_team_id)`.
- **`Down_20231121054530`** — No-op rollback; does not drop the table.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Schema Details

| Column | Type | Notes |
|---|---|---|
| `id` | `INT UNSIGNED` | Auto-increment primary key |
| `policy_id` | `INT UNSIGNED` | FK → `policies(id)` ON DELETE CASCADE |
| `inherited_team_id` | `INT UNSIGNED` | `0` = own policy; non-zero = inherited global policy for a team |
| `passing_host_count` | `MEDIUMINT UNSIGNED` | Cached compliant host count |
| `failing_host_count` | `MEDIUMINT UNSIGNED` | Cached non-compliant host count |
| `created_at` / `updated_at` | `TIMESTAMP` | Auto-managed timestamps |

The `inherited_team_id` column uses `0` as a sentinel (not a real team ID) to enable the `UNIQUE KEY` constraint when a policy has no team (`policies.team_id IS NULL`), intentionally avoiding a foreign key on that column.
