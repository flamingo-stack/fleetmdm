Database migration that updates `software_titles` and `software` records to use Fleet Maintained Apps (FMA) canonical names, replacing osquery-reported names where a matching `bundle_identifier` exists for macOS applications.

## Key Components

- **`Up_20260326210603`** — Runs two idempotent `UPDATE` statements:
  1. Updates `software_titles.name` to match `fleet_maintained_apps.name` where `bundle_identifier` aligns and names differ.
  2. Updates `software.name` to match `fleet_maintained_apps.name` for consistency between software versions and their parent titles.
- **`Down_20260326210603`** — No-op; original osquery-reported names cannot be reliably restored, and FMA canonical names are considered correct.
- **`init()`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically via the Fleet migration runner. No manual invocation is required.

```go
// Migration is registered on package load via init()
// and executed by the migration client in sequence.
MigrationClient.AddMigration(Up_20260326210603, Down_20260326210603)
```

**Before migration:**

| `bundle_identifier`        | `name` (osquery-reported) |
|----------------------------|---------------------------|
| `com.microsoft.VSCode`     | `Code`                    |

**After migration:**

| `bundle_identifier`        | `name` (FMA canonical)              |
|----------------------------|-------------------------------------|
| `com.microsoft.VSCode`     | `Microsoft Visual Studio Code`      |

## Notes

- Scoped to `platform = 'darwin'` only.
- Safe to re-run; the `WHERE st.name != fma.name` guard prevents unnecessary writes.
- Relies on `idx_software_titles_bundle_identifier`; a subsequent migration adds `idx_software_bundle_identifier` on `software.bundle_identifier` to avoid full-table scans during the hourly FMA sync.
