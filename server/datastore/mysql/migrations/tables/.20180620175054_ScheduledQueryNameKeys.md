Database migration that enforces name uniqueness and data integrity constraints on the `scheduled_queries` table.

## Key Components

- **`Up_20180620175054`** — Applies the migration in four sequential steps:
  1. Backfills `NULL` values for `name`, `description`, `platform`, and `version` columns
  2. Detects and removes duplicate `(name, pack_id)` pairs, keeping the lowest `id`
  3. Enforces `NOT NULL` and default value constraints on affected columns
  4. Adds a `UNIQUE KEY unique_names_in_packs (name, pack_id)` index
- **`Down_20180620175054`** — No-op rollback (destructive data changes are not reversible)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20180620175054, Down_20180620175054)
}
```

To apply manually during development:

```bash
# Run all pending migrations
fleet prepare db
```

## Notes

- **Idempotent design** — Column modifications are guarded by `columnExists()` and index creation is guarded by `indexExistsTx()`, making re-runs safe
- **Duplicate removal strategy** — Uses a nested `SELECT` subquery to work around MySQL's restriction on deleting from the same table being queried; keeps the earliest record (`ORDER BY id DESC OFFSET 1`)
- **No rollback** — `Down_20180620175054` is a no-op because the deduplication step performs irreversible data deletion
