Adds a `scope` column to Apple MDM-related tables, distinguishing between `System` and `User` enrollment contexts for configuration profiles and declarations.

## Key Components

| Function | Description |
|---|---|
| `Up_20250613103810` | Idempotent migration that adds a `scope ENUM('System', 'User')` column (default `'System'`) to four Apple MDM tables |
| `Down_20250613103810` | No-op rollback; column removal is not implemented |

**Affected tables:**
- `mdm_apple_configuration_profiles`
- `mdm_apple_declarations`
- `host_mdm_apple_profiles`
- `host_mdm_apple_declarations`

## Usage Example

This migration runs automatically via `MigrationClient` on startup. Each `ALTER TABLE` is guarded by `columnExists` to ensure safe re-runs:

```go
// Migration is registered via init()
func init() {
    MigrationClient.AddMigration(Up_20250613103810, Down_20250613103810)
}

// Each ALTER TABLE is idempotent:
if !columnExists(tx, "mdm_apple_configuration_profiles", "scope") {
    tx.Exec(`ALTER TABLE mdm_apple_configuration_profiles
             ADD COLUMN scope ENUM('System', 'User') ... DEFAULT 'System'`)
}
```

> **Note:** The `Down` function is intentionally a no-op. Rolling back this migration will not remove the `scope` columns.
