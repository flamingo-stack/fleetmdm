Database migration that adds `browser` and `extension_id` columns to the `software` table, and drops the `unq_name` unique index to accommodate the schema change.

## Key Components

- **`Up_20231122101320`** — Idempotent up migration that:
  - Adds `browser` (`varchar(255)`) and `extension_id` (`varchar(255)`) columns to the `software` table if they don't already exist
  - Drops the `unq_name` unique index if present, as the index is at its 3072-byte limit and cannot include the new `extension_id` column
- **`Down_20231122101320`** — No-op rollback (documented as comments only); manual reversal would require dropping both new columns and re-adding the `unq_name` unique key

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20231122101320, Down_20231122101320)
}

// The up migration checks for idempotency before altering the table
if !columnsExists(tx, "software", "browser", "extension_id") {
    // ALTER TABLE software ADD COLUMN browser ..., ADD COLUMN extension_id ...
}

// Drops the unq_name index if it exists (3072-byte limit exceeded)
if indexExistsTx(tx, "software", "unq_name") {
    // ALTER TABLE software DROP INDEX unq_name
}
```

## Notes

- Migration is **idempotent** — safe to run multiple times without side effects
- The `unq_name` index drop is intentional and documented as non-critical (development aid only)
