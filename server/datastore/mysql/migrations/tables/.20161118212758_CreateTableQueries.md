Database migration that creates the `queries` table, which stores saved and ad-hoc osquery queries with metadata including authorship and soft-delete support.

## Key Components

- **`Up_20161118212758`** — Creates the `queries` table with the following columns:
  - `id` — Auto-incrementing primary key
  - `created_at`, `updated_at`, `deleted_at` — Timestamp audit fields
  - `deleted` — Soft-delete flag (boolean)
  - `saved` — Indicates if the query is explicitly saved or ad-hoc
  - `name`, `description`, `query` — Query identity and content fields
  - `author_id` — Foreign key to `users.id` (nullable, `SET NULL` on delete)
- **`Down_20161118212758`** — Drops the `queries` table if it exists
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration is applied automatically via the migration client. To run manually:

```go
// Applied as part of the full migration chain
MigrationClient.AddMigration(Up_20161118212758, Down_20161118212758)

// Up: creates the queries table
err := Up_20161118212758(tx)

// Down: drops the queries table
err := Down_20161118212758(tx)
```

## Notes

- The `Up` migration is **idempotent** (`CREATE TABLE IF NOT EXISTS`), making it safe to re-run
- Uses `InnoDB` engine with `utf8mb4_unicode_ci` collation for full Unicode support
- The `author_id` foreign key cascades to `NULL` when the referenced user is deleted, preserving query history
