Database migration that adds VPP (Volume Purchase Program) app install verification tracking columns and indexes to support post-install verification workflows in Fleet MDM.

## Key Components

- **`Up_20250624140757`** — Applies the migration with three idempotent steps:
  1. Adds `verification_command_uuid`, `verification_at`, and `verification_failed_at` columns to `host_vpp_software_installs`, along with a functional index on pending-verification rows
  2. Backfills `verification_at` and `verification_failed_at` for existing rows by joining against `nano_command_results` using `fleet.MDMAppleStatusError` and `fleet.MDMAppleStatusCommandFormatError` sentinel values
  3. Adds a composite index `idx_jobs_name_state` on the `jobs` table if absent

- **`Down_20250624140757`** — No-op rollback (columns are not dropped)

- **`init`** — Registers both migration functions with `MigrationClient`

## Schema Changes

| Table | Change |
|---|---|
| `host_vpp_software_installs` | +`verification_command_uuid VARCHAR(127)`, +`verification_at DATETIME(6)`, +`verification_failed_at DATETIME(6)`, +functional index on pending rows |
| `jobs` | +composite index `idx_jobs_name_state (name, state)` |

## Usage Example

This migration runs automatically via the Fleet migration client. No direct invocation is needed; it executes as part of the standard `fleet prepare db` or server startup migration sequence.

```go
// Migration is self-registered via init()
// MigrationClient discovers and runs Up_20250624140757 in order.

// The functional index targets rows still awaiting verification:
// (verification_at IS NULL AND verification_failed_at IS NULL)

// Backfill maps existing MDM command results to verification timestamps:
// ncr.status = 'Error'              → verification_failed_at = NOW()
// ncr.status = 'CommandFormatError' → verification_failed_at = NOW()
// ncr.status = 'Acknowledged'       → verification_at = NOW()
```

> The migration is idempotent: column and index existence are checked with `columnsExists` and `indexExistsTx` before any `ALTER TABLE` is executed, making it safe to re-run.
