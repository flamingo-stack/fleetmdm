Database migration that populates the `upcoming_activities` unified queue with all currently-pending operations (software installs, software uninstalls, VPP app installs, and script executions), marking them as already activated so they can be immediately processed.

## Key Components

| Function | Description |
|---|---|
| `Up_20250217093329` | Entry point that orchestrates all sub-migrations in sequence |
| `migrateSoftwareInstalls` | Inserts pending `host_software_installs` (status `pending_install`) into `upcoming_activities` and `software_install_upcoming_activities` |
| `migrateSoftwareUninstalls` | Inserts pending `host_software_installs` (status `pending_uninstall`) into both activity tables |
| `recreateNanoViewQueue` | Recreates the `nano_view_queue` SQL view with `SQL SECURITY INVOKER`; idempotent via `CREATE OR REPLACE` |
| `migrateVPPInstalls` | Inserts pending VPP app installs from `host_vpp_software_installs` joined against `nano_view_queue` |
| `migrateScriptExecs` | Inserts pending script executions from `host_script_results` (exit_code IS NULL), skipping uninstall scripts automatically via the left-join deduplication |
| `Down_20250217093329` | No-op rollback (migration is intentionally irreversible) |

## Usage Example

This migration runs automatically via the migration client at startup:

```go
// Registered automatically via init()
MigrationClient.AddMigration(Up_20250217093329, Down_20250217093329)
```

To run manually during development:

```bash
fleet prepare db --dev
```

## Notes

- **Idempotent**: All inserts use `LEFT OUTER JOIN ... WHERE ... IS NULL` guards, so re-running is safe.
- **No ordering guarantee** for pre-existing pending activities; only new activities enqueued after this migration follow the unified queue ordering.
- `recreateNanoViewQueue` is intentionally duplicated from migration `20250728122229_RecreateNanoViewQueue.go` to guard against upgrade edge cases (see upstream issues [#28573](https://github.com/fleetdm/fleet/issues/28573) and [#31141](https://github.com/fleetdm/fleet/issues/31141)).
- Software uninstall scripts share `execution_id` with their parent uninstall record and are deduplicated automatically — no special handling needed.
