Adds the `host_deleted_at` column to the `host_software_installs` table and backfills it for records whose associated host no longer exists.

## Key Components

- **`Up_20240802101043`** — Idempotent migration that:
  1. Adds a nullable `host_deleted_at TIMESTAMP` column to `host_software_installs` if it does not already exist.
  2. Backfills `host_deleted_at = NOW()` for any install records referencing a host that has been deleted (i.e., no matching row in `hosts`).
- **`Down_20240802101043`** — No-op rollback; the column is left in place on downgrade.

## Usage Example

This migration runs automatically via the `MigrationClient` on startup. No manual invocation is required. To apply or roll back manually:

```bash
# Apply
fleetctl prepare db --config fleet.yml

# Rollback (no-op for this migration)
fleetctl prepare db --config fleet.yml --down
```

To inspect the resulting schema change directly:

```sql
-- Verify column exists
SHOW COLUMNS FROM host_software_installs LIKE 'host_deleted_at';

-- Check backfilled rows
SELECT COUNT(*)
FROM host_software_installs
WHERE host_deleted_at IS NOT NULL;
```

> **Note:** This is an out-of-order re-issue of a prior migration. The `columnExists` guard makes it safe to run on databases where the column was already added by the earlier migration.
