Database migration that adds a unique index on the `team_id` column of the `vpp_tokens` table, enforcing one VPP token per team.

## Key Components

- **`Up_20240829165715`** — Idempotently adds a `UNIQUE KEY` (`idx_vpp_tokens_team_id`) on `vpp_tokens.team_id` if it does not already exist.
- **`Down_20240829165715`** — No-op rollback; the constraint is left in place on downgrade.
- **`init`** — Registers the migration with `MigrationClient`.

## Usage Example

```go
// Migration is auto-registered via init(); no manual invocation needed.
// The migration client runs Up/Down functions during fleet migrations:

Up_20240829165715(tx)   // Adds UNIQUE KEY if absent
Down_20240829165715(tx) // No-op
```

## Notes

- The migration is **idempotent**: it checks for the index via `indexExistsTx` before executing the `ALTER TABLE`, making it safe to run multiple times.
- A no-op `Down` function means the unique constraint is **not removed** on rollback — manual intervention is required to undo this change.
