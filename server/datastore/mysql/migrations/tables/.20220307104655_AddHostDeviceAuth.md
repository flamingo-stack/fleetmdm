Database migration that creates the `host_device_auth` table, which stores authentication tokens for host device authorization in Fleet MDM.

## Key Components

- **`Up_20220307104655`** — Creates the `host_device_auth` table with `host_id` (primary key) and a unique-indexed `token` column. Uses `CREATE TABLE IF NOT EXISTS` for idempotent execution.
- **`Down_20220307104655`** — No-op rollback; table removal is not implemented.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Schema Created

```sql
CREATE TABLE IF NOT EXISTS host_device_auth (
    host_id int(10) UNSIGNED NOT NULL,
    token   VARCHAR(255) NOT NULL,
    PRIMARY KEY (host_id),
    UNIQUE INDEX idx_host_device_auth_token (token)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## Usage Example

This migration runs automatically via the migration client. No direct invocation is needed, but the pattern follows:

```go

MigrationClient.AddMigration(Up_20220307104655, Down_20220307104655)
```

After this migration, each host may have exactly one device auth token (enforced by the `PRIMARY KEY` on `host_id`), and tokens must be globally unique (enforced by `idx_host_device_auth_token`).
