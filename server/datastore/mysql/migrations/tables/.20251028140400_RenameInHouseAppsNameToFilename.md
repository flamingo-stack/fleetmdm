Database migration that renames the `name` column to `filename` in the `in_house_apps` table, with idempotent logic to skip the operation if the column has already been renamed.

## Key Components

- **`Up_20251028140400`** — Applies the migration. Checks if the `name` column exists before renaming it to `filename`, making it safe to run multiple times.
- **`Down_20251028140400`** — No-op rollback; the rename is not reversed.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Applied automatically by the migration client on startup.
// Manual invocation (within a transaction):
tx, _ := db.Begin()
if err := Up_20251028140400(tx); err != nil {
    tx.Rollback()
}
tx.Commit()
```

## Notes

- The migration is **idempotent**: it uses `columnExists(tx, "in_house_apps", "name")` to guard the `ALTER TABLE` statement, so re-running it after the column has been renamed is safe.
- The rollback (`Down`) is intentionally empty — restoring the column name would require additional context to avoid data loss.
- Part of the [`tables`](https://github.com/flamingo-stack/fleetmdm/blob/main/db/migrations/tables) migration package.
