Adds `created_at` and `updated_at` timestamp columns to the `vpp_apps_teams` database table via an idempotent schema migration.

## Key Components

- **`Up_20250219100000`** — Applies the migration: conditionally adds microsecond-precision timestamp columns to `vpp_apps_teams`, then backfills their values by joining against existing timestamps from the `vpp_apps` table.
- **`Down_20250219100000`** — No-op rollback; timestamp columns are left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Behavior Notes

- **Idempotent**: Uses `columnsExists` to skip the `ALTER TABLE` if the columns are already present.
- **Backfill strategy**: Approximates historical timestamps by copying `created_at`/`updated_at` from the parent `vpp_apps` row (joined on `platform` and `adam_id`). Exact timestamps would require querying the activity feed, which may have been purged.
- `updated_at` is configured with `ON UPDATE CURRENT_TIMESTAMP(6)` for automatic maintenance.

## Usage Example

This migration runs automatically via the migration client at application startup. No manual invocation is needed.

```go
// Migration is self-registering via init()
// To apply programmatically in tests:
tx, _ := db.Begin()
if err := Up_20250219100000(tx); err != nil {
    log.Fatal(err)
}
tx.Commit()
```
