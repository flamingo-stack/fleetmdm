Database migration that creates two label-association tables — `vpp_app_team_labels` and `software_installer_labels` — enabling label-based include/exclude targeting for VPP apps and software installers.

## Key Components

- **`Up_20241220114904`** — Creates both tables idempotently (`IF NOT EXISTS`):
  - **`vpp_app_team_labels`** — Links VPP app/team assignments to labels via `vpp_app_team_id` → `vpp_apps_teams(id)` (CASCADE delete) and `label_id` → `labels(id)` (RESTRICT delete)
  - **`software_installer_labels`** — Links software installers to labels via `software_installer_id` → `software_installers(id)` (CASCADE delete) and `label_id` → `labels(id)` (RESTRICT delete)
  - Both tables share the same schema pattern: unique composite key on `(entity_id, label_id)`, an `exclude` flag (0 = `include_any`, 1 = `exclude_any`), and microsecond-precision `created_at`/`updated_at` timestamps
- **`Down_20241220114904`** — No-op rollback (tables are not dropped)

## Schema Notes

| Column | Type | Purpose |
|--------|------|---------|
| `exclude` | `TINYINT(1)` | `0` = include_any, `1` = exclude_any targeting |
| `label_id` | `INT UNSIGNED NOT NULL` | Labels cannot be deleted if referenced (RESTRICT) |
| `vpp_app_team_id` / `software_installer_id` | `INT UNSIGNED NOT NULL` | Cascades on parent deletion |
