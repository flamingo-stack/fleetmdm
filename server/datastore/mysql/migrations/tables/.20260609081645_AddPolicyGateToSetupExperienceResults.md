Adds a database migration that introduces a `policy_gated` boolean column to the `setup_experience_status_results` table, enabling policy-gating logic for Windows/Linux setup experience software installers.

## Key Components

- **`Up_20260609081645`** — Idempotently adds a `policy_gated TINYINT(1) NOT NULL DEFAULT 0` column to `setup_experience_status_results`. The column marks setup-experience software items whose installer has at least one team policy with an install-software automation targeting it. The item is skipped only if all gating policies pass, or installed if any fail.
- **`Down_20260609081645`** — No-op rollback; the column is left in place on downgrade.

## Behavior Notes

- **Idempotent**: Uses `columnExists` guard to skip the `ALTER TABLE` if the column is already present, making repeated runs safe.
- **Marker-only**: No specific policy is stored in this column — it acts as a flag. Gating policies are resolved from the installer at decision time, meaning deleting one of several gating policies does not automatically un-gate the item.
- **Internal field**: The corresponding Go struct field uses `json:"-"`, so this introduces no API surface change.
