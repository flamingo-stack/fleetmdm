Database migration that removes orphaned policy membership records where a policy's team assignment doesn't match the associated host's team, or where the host has no team assignment.

## Key Components

- **`Up_20220524102918`** — Executes a `DELETE` against `policy_membership`, joining `policies` and `hosts` to remove rows where a team-scoped policy (`p.team_id IS NOT NULL`) is linked to a host on a different team or no team at all. The migration is idempotent and safe to re-run.
- **`Down_20220524102918`** — No-op rollback; deleted rows are not restored.

## Usage Example

This migration runs automatically via the `MigrationClient` registered in `init()`. To apply it manually during development:

```bash
fleetctl prepare db --config /etc/fleet/fleet.yml
```

Or with the Go migration runner directly:

```go
// Executed internally by MigrationClient
Up_20220524102918(tx)
```

The underlying SQL performs the cleanup:

```sql
DELETE pm
FROM policy_membership pm
LEFT JOIN policies p ON p.id = pm.policy_id
LEFT JOIN hosts h ON h.id = pm.host_id
WHERE p.team_id IS NOT NULL
  AND (p.team_id != h.team_id
       OR h.team_id IS NULL)
```

> **Note:** Only team-scoped policies are affected. Global policies (`team_id IS NULL`) are left untouched.
