Database migration that adds BYOD (Bring Your Own Device) fleet support and ADUE (Apple Device User Enrollment) enrollment tracking by extending the `abm_tokens` table and creating a new `mdm_adue_enrollment_challenges` table.

## Key Components

- **`Up_20260609104220`** — Applies the migration with idempotent guards (`columnExists`, `constraintExists`, `indexExistsTx`) for safe re-runs:
  - Adds `byod_default_team_id` (nullable FK to `teams`) on `abm_tokens`
  - Adds `enrollment_url_token` (unique, length-constrained `VARBINARY(64)`) on `abm_tokens`
  - Backfills all existing ABM tokens with cryptographically secure URL-safe tokens via `fleet.GenerateRandom32ByteEntropyURLSafeToken()`
  - Creates `mdm_adue_enrollment_challenges` table to track ADUE challenge lifecycle (challenge bytes, linked IdP account, ABM token, expiry, and usage timestamps)

- **`Down_20260609104220`** — No-op rollback (returns `nil`); schema changes are not reversed.

## Schema Changes

```sql
-- abm_tokens additions
ALTER TABLE abm_tokens ADD COLUMN byod_default_team_id INT UNSIGNED NULL;
ALTER TABLE abm_tokens ADD COLUMN enrollment_url_token VARBINARY(64) NOT NULL;

-- New table
CREATE TABLE IF NOT EXISTS mdm_adue_enrollment_challenges (
    id               INT UNSIGNED NOT NULL AUTO_INCREMENT,
    challenge        VARBINARY(64) NOT NULL,
    idp_account_uuid VARCHAR(255)  NOT NULL,
    abm_token_id     INT UNSIGNED  NULL,
    expires_at       TIMESTAMP(6)  NOT NULL,
    used_at          TIMESTAMP(6)  NULL,
    created_at       TIMESTAMP(6)  NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    updated_at       TIMESTAMP(6)  NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6),
    PRIMARY KEY (id),
    UNIQUE KEY idx_mdm_adue_challenge (challenge),
    KEY idx_mdm_adue_expires (expires_at)
);
```

## Notes

- All `ALTER TABLE` operations are wrapped in idempotency checks, making this migration safe to re-run.
- The `enrollment_url_token` column drops its `DEFAULT ''` after backfill, enforcing that new tokens must always be explicitly set and pass the `LENGTH > 32` constraint check.
- Foreign keys use `ON DELETE SET NULL` (BYOD team) and `ON DELETE CASCADE` (ADUE challenges) to maintain referential integrity appropriately for each relationship.
