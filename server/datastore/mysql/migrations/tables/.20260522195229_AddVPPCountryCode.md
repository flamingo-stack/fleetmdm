Database migration that adds a nullable `country_code` column to the `vpp_tokens` and `vpp_apps` tables, storing the App Store storefront country as a lowercase ISO 3166-1 alpha-2 code (e.g., `"us"`, `"de"`).

## Key Components

- **`Up_20260522195229`** — Idempotent migration that conditionally adds `country_code VARCHAR(4)` (utf8mb4) to both `vpp_tokens` and `vpp_apps`. Uses `columnExists` guards so re-running is safe.
- **`Down_20260522195229`** — No-op rollback; columns are left in place to avoid data loss.
- **`init`** — Registers both directions with `MigrationClient`.

## Column Semantics

| Table | Meaning of `country_code` |
|---|---|
| `vpp_tokens` | Storefront tied to the Apple Business Manager account; populated from Apple's `/client/config` endpoint on token upload |
| `vpp_apps` | "Anchored" storefront where the app was first added in Fleet; used for all future metadata fetches regardless of which team triggers them |

Both columns are `NULL DEFAULT NULL` so existing rows survive without backfill; values are populated lazily by the API/service layer.

## Usage Example

```go
// Migration is auto-registered via init(); invoked by the migration runner:
if err := MigrationClient.Up(db); err != nil {
    log.Fatal(err)
}

// After migration, set country_code when uploading a VPP token:
_, err := db.Exec(
    `UPDATE vpp_tokens SET country_code = ? WHERE id = ?`,
    "us", tokenID,
)
```
