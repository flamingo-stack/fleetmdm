Database migration that adds a `description` column to the `cve_meta` table, enabling storage of CVE vulnerability descriptions.

## Key Components

- **`Up_20230912101759`** — Idempotent migration that adds a nullable `TEXT` column (`description`) with `utf8mb4_unicode_ci` collation to the `cve_meta` table. Uses `columnExists` to skip the `ALTER TABLE` if the column is already present.
- **`Down_20230912101759`** — No-op rollback; the column is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically by the Fleet migration runner. To run it manually during development:

```bash
# Apply all pending migrations (includes this one)
fleet prepare db --config /etc/fleet/fleet.yml

# Or run directly via the migration client in tests
tx, _ := db.Begin()
Up_20230912101759(tx)
tx.Commit()
```

The resulting schema change:

```text
cve_meta
├── ...existing columns...
└── description  TEXT  COLLATE utf8mb4_unicode_ci  DEFAULT NULL
```

## Notes

- **Idempotent** — safe to run multiple times; checks for column existence before altering.
- **Collation** — `utf8mb4_unicode_ci` ensures full Unicode support, including emoji and multi-byte CVE description text.
- **No rollback** — `Down_` is intentionally a no-op; dropping the column on rollback could cause data loss in production environments.
