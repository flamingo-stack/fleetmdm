Database migration that creates the `host_managed_local_account_passwords` table for storing encrypted local account passwords managed via MDM commands on enrolled hosts.

## Key Components

- **`Up_20260409153717`** — Creates the `host_managed_local_account_passwords` table if it does not already exist (idempotent). Key columns:
  - `host_uuid` — Primary key; identifies the managed host
  - `encrypted_password` — Binary blob storing the encrypted local account password
  - `command_uuid` — References the MDM command that triggered the password operation (indexed via `idx_hmlap_command_uuid`)
  - `status` — Foreign-keyed to `mdm_delivery_status.status` with cascade updates
  - `created_at` / `updated_at` — Microsecond-precision timestamps with automatic `ON UPDATE` tracking

- **`Down_20260409153717`** — No-op rollback; table removal is intentionally omitted to prevent accidental data loss.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20260409153717, Down_20260409153717)
}

// Applied during fleet database migrations, e.g.:
// fleetctl prepare db --config /etc/fleet/fleet.yml
```

## Notes

- The `BLOB` type for `encrypted_password` ensures binary-safe storage of encrypted credentials regardless of encoding.
- The foreign key constraint on `status` ties password delivery state to the shared `mdm_delivery_status` reference table, keeping status values consistent across MDM workflows.
- The down migration is intentionally a no-op — dropping this table would destroy encrypted credential data.
