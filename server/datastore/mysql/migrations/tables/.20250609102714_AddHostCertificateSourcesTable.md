Database migration that creates the `host_certificate_sources` table and backfills existing certificate records with a default `system` source.

## Key Components

- **`Up_20250609102714`** — Creates the `host_certificate_sources` table (idempotent via `CREATE TABLE IF NOT EXISTS`) and backfills all existing `host_certificates` rows with a `source = 'system'` entry using `INSERT IGNORE`.
- **`Down_20250609102714`** — No-op rollback; the migration is intentionally irreversible.

### Table Schema: `host_certificate_sources`

| Column | Type | Notes |
|---|---|---|
| `id` | `BIGINT UNSIGNED` | Auto-increment primary key |
| `host_certificate_id` | `BIGINT UNSIGNED` | FK → `host_certificates(id)` CASCADE DELETE |
| `source` | `ENUM('system', 'user')` | Certificate origin |
| `username` | `VARCHAR(255)` | Associated user (empty string for system certs) |
| `created_at` | `DATETIME(6)` | Defaults to current timestamp |

A unique composite index on `(host_certificate_id, source, username)` prevents duplicate source entries per certificate.

## Usage Example

This migration runs automatically via the `MigrationClient` on startup. To apply manually:

```bash
# Apply the migration
fleet prepare db --config /etc/fleet/fleet.yml

# Verify the table and backfill
mysql -u fleet fleet -e "SELECT source, COUNT(*) FROM host_certificate_sources GROUP BY source;"
```

## Notes

- The backfill uses `INSERT IGNORE` to safely handle re-runs and soft-deleted certificates — every existing `host_certificates` row gets a corresponding `system` source record regardless of deletion state.
