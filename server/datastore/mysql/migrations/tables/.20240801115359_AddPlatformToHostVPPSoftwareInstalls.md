Database migration that adds a `platform` column to the `host_vpp_software_installs` table and updates related indexes and foreign key constraints.

## Key Components

- **`Up_20240801115359`** — Applies the migration with the following steps:
  1. Adds `platform VARCHAR(10)` column (idempotent — skips if column already exists)
  2. Backfills `platform` from the joined `hosts` table
  3. Falls back to backfilling `platform` from `vpp_apps` for records where the host no longer exists
  4. Recreates the `adam_id` index to include `(adam_id, platform)` as a composite index
  5. Drops the old foreign key `host_vpp_software_installs_ibfk_2` and adds a new constraint `host_vpp_software_installs_ibfk_3` referencing `vpp_apps(adam_id, platform)` with `ON DELETE CASCADE`

- **`Down_20240801115359`** — No-op rollback (returns `nil`)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20240801115359, Down_20240801115359)
}

// Applied as part of the standard migration run
err := MigrationClient.Up(db, "")
```

## Notes

- The migration is fully **idempotent**: each DDL step checks for the existence of the column, index, or constraint before applying changes using helpers (`columnExists`, `indexExistsTx`, `fkExists`, `constraintExists`).
- The two-phase backfill handles orphaned install records whose host rows have been deleted, using the `vpp_apps` table as a fallback source for platform data.
