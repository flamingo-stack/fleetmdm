Database migration that adds an `agent_options` JSON column to the `teams` table, executed idempotently by checking for column existence before altering the schema.

## Key Components

- **`Up_20210601000005`** — Applies the migration; conditionally adds `agent_options JSON` to the `teams` table if the column does not already exist.
- **`Down_20210601000005`** — No-op rollback; the column is not dropped on downgrade.
- **`init`** — Registers both migration functions with the `MigrationClient`.

## Usage Example

This migration is automatically registered and executed by the migration runner. No direct invocation is needed.

```go
// Migration is registered automatically via init()
// and applied in sequence by the migration client.
MigrationClient.AddMigration(Up_20210601000005, Down_20210601000005)
```

To apply manually during development:

```bash
# Run all pending migrations
fleet db prepare --env development
```

## Notes

- The migration is **idempotent** — safe to run multiple times without error, using the `columnExists` guard before executing `ALTER TABLE`.
- The rollback (`Down`) is intentionally a no-op; data loss concerns make automatic column drops undesirable.
