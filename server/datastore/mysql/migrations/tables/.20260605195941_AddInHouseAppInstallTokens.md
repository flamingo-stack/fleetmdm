Database migration that creates the `in_house_app_install_tokens` table, enabling temporary token-based installation of in-house (enterprise/sideloaded) apps on managed hosts.

## Key Components

- **`Up_20260605195941`** — Creates the `in_house_app_install_tokens` table with the following columns:
  - `token` (`VARCHAR(36)`) — Primary key; a UUID-style token authorizing an install
  - `software_title_id` — References the in-house app being installed
  - `team_id` — Scopes the token to a Fleet team
  - `host_id` — Scopes the token to a specific managed host
  - `expires_at` — Token expiry timestamp; indexed for efficient cleanup queries
  - `created_at` — Auto-populated creation timestamp
- **`Down_20260605195941`** — No-op rollback (table is left in place on downgrade)

## Schema Notes

- Migration is **idempotent** (`CREATE TABLE IF NOT EXISTS`), safe to re-run
- `expires_at` carries a dedicated index (`idx_in_house_app_install_tokens_expires_at`) to support fast expiry sweeps or TTL-based cleanup jobs
- All text columns use `utf8mb4_unicode_ci` collation; storage engine is `InnoDB`
