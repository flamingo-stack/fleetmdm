Database migration that adds role-based access control support to the invites system by creating a team-invite mapping table and adding a global role column to invites.

## Key Components

- **`Up_20210601000002`** — Applies the migration with two idempotent changes:
  - Creates the `invite_teams` junction table mapping invites to teams with an associated role
  - Adds a nullable `global_role` column to the existing `invites` table
- **`Down_20210601000002`** — No-op rollback (schema changes are not reversed)
- **`init`** — Registers both migration functions with `MigrationClient`

## Schema Changes

**New table: `invite_teams`**

| Column | Type | Notes |
|---|---|---|
| `invite_id` | `INT UNSIGNED` | FK → `invites.id` (cascade) |
| `team_id` | `INT UNSIGNED` | FK → `teams.id` (cascade) |
| `role` | `VARCHAR(64)` | Role assigned within the team |

**Altered table: `invites`**

| Column | Type | Notes |
|---|---|---|
| `global_role` | `VARCHAR(64)` | Nullable; fleet-wide role for the invite |

- Both DDL operations are **idempotent** — safe to run multiple times without side effects
- Cascading deletes/updates ensure referential integrity when parent `invites` or `teams` records are removed
