Database migration that alters the primary key of the `host_mdm_managed_certificates` table to include the `ca_name` column, enabling support for multiple certificate authorities per host/profile combination.

## Key Components

- **`Up_20250317130944`** — Idempotent migration that drops the existing primary key and replaces it with a composite key of `(host_uuid, profile_uuid, ca_name)`. Skips execution if the primary key already includes `ca_name`.
- **`Down_20250317130944`** — No-op rollback; the schema change is not reversed.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Migration is registered automatically via init().
// Applied by the migration runner during schema upgrades:

err := MigrationClient.Up(db, "")
if err != nil {
    log.Fatalf("migration failed: %v", err)
}
```

The idempotency check queries `INFORMATION_SCHEMA.STATISTICS` to verify whether `ca_name` is already part of the primary key before attempting the `ALTER TABLE`, making it safe to run multiple times:

```go
// Internal guard — runs before the ALTER TABLE
SELECT COUNT(*) FROM INFORMATION_SCHEMA.STATISTICS
WHERE TABLE_SCHEMA = DATABASE()
  AND TABLE_NAME   = 'host_mdm_managed_certificates'
  AND INDEX_NAME   = 'PRIMARY'
  AND COLUMN_NAME  = 'ca_name'
```
