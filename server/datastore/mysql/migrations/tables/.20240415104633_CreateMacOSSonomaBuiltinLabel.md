Database migration that creates the built-in `macOS Sonoma+` label, targeting Darwin hosts running macOS 14 (Sonoma) and above using a dynamic osquery membership query.

## Key Components

- **`Up_20240415104633`** — Inserts a new built-in label (`fleet.BuiltinLabelMacOS14Plus`) into the `labels` table using `INSERT IGNORE` for idempotency. Uses a hardcoded timestamp (`2024-04-03`) to keep `schema.sql` stable. Handles duplicate entry errors explicitly, returning a descriptive error prompting the user to rename a conflicting label before re-running.
- **`Down_20240415104633`** — No-op rollback; the label is not removed on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Label Details

| Field | Value |
|---|---|
| Name | `fleet.BuiltinLabelMacOS14Plus` |
| Platform | `darwin` |
| Type | `LabelTypeBuiltIn` |
| Membership | `LabelMembershipTypeDynamic` |
| Query | `select 1 from os_version where platform = 'darwin' and major >= 14;` |

## Usage Example

This migration runs automatically via Fleet's migration client. No manual invocation is needed, but the core insert logic follows this pattern:

```go
_, err := tx.Exec(stmt,
    fleet.BuiltinLabelMacOS14Plus,
    "macOS hosts with version 14 and above",
    `select 1 from os_version where platform = 'darwin' and major >= 14;`,
    "darwin",
    fleet.LabelTypeBuiltIn,
    fleet.LabelMembershipTypeDynamic,
    ts, ts,
)
if driverErr.Number == mysqlerr.ER_DUP_ENTRY {
    return fmt.Errorf("rename conflicting label before migration: %w", err)
}
```
