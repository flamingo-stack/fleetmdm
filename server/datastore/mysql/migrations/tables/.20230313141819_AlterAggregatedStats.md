Database migration that adds a `global_stats` column to the `aggregated_stats` table and updates its primary key to distinguish between global statistics and team-specific aggregations.

## Key Components

- **`Up_20230313141819`** — Idempotent forward migration that:
  1. Adds `global_stats TINYINT(1) NOT NULL DEFAULT 0` column if absent
  2. Updates the primary key to `(id, type, global_stats)` if not already migrated
  3. Backfills existing rows where `id=0` to `global_stats=1`, preserving the semantic shift: `id=0 + global_stats=0` now means "hosts in no team" rather than "all teams/global"
- **`Down_20230313141819`** — No-op rollback (irreversible migration)

## Semantic Change

| `id` | `global_stats` | Meaning (after migration) |
|------|----------------|---------------------------|
| `0`  | `1`            | Global / all teams        |
| `0`  | `0`            | Hosts in no team          |
| `>0` | `0`            | Specific team             |

## Usage Example

Migrations run automatically via the `MigrationClient` at startup. To apply manually:

```bash
# Apply migration
fleet prepare db --config /etc/fleet/fleet.yml

# Verify column and key
mysql -e "DESCRIBE aggregated_stats;"
mysql -e "SHOW INDEX FROM aggregated_stats WHERE Key_name='PRIMARY';"
```

## Notes

- Fully idempotent: checks `INFORMATION_SCHEMA.STATISTICS` before altering the primary key to prevent duplicate-key errors on re-runs
