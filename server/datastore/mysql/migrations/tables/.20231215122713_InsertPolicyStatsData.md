Database migration that seeds initial data into the `policy_stats` table with host passing/failing counts for both inherited global policies (per team) and global/team-scoped policies.

## Key Components

- **`Up_20231215122713`** — Idempotent up migration that populates `policy_stats` only when the table is empty. Executes two INSERT queries:
  - `inheritedStatsQuery` — Computes per-team passing/failing host counts for global policies (where `team_id IS NULL`) using a `CROSS JOIN` against all teams.
  - `globalAndTeamStatsQuery` — Computes aggregate passing/failing host counts for all policies at global scope (`inherited_team_id = 0`).
- **`Down_20231215122713`** — No-op rollback; inserted data is not removed.

## Usage Example

This migration is automatically registered and executed by the migration client at startup:

```go
// Registered via init()
MigrationClient.AddMigration(Up_20231215122713, Down_20231215122713)
```

The up migration guards against re-seeding using a row count check:

```go
// Only inserts if policy_stats is empty
countQuery := `SELECT COUNT(*) FROM policy_stats`
var count int
err := tx.QueryRow(countQuery).Scan(&count)
if count == 0 {
    // run insert queries
}
```

## Notes

- The SQL queries in this migration are intentionally duplicated in [`server/datastore/mysql/policies.go`](https://github.com/flamingo-stack/fleetmdm/blob/main/server/datastore/mysql/policies.go). Any query changes must be reflected in both locations.
- `ON DUPLICATE KEY UPDATE` ensures safe re-runs if the guard condition is bypassed.
- `inherited_team_id = 0` is a sentinel value representing global (non-team) scope.
