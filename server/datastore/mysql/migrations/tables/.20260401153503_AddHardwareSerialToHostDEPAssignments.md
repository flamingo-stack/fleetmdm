Database migration that adds a `hardware_serial` column to the `host_dep_assignments` table, creates an index on it, and backfills existing records from the `hosts` table.

## Key Components

- **`Up_20260401153503`** — Forward migration that:
  - Adds `hardware_serial VARCHAR(255)` (utf8mb4, NOT NULL, default `''`) to `host_dep_assignments` if it doesn't already exist
  - Creates index `idx_hdep_hardware_serial` on the new column if absent
  - Backfills `hardware_serial` for all non-deleted DEP assignment records by joining against the `hosts` table
- **`Down_20260401153503`** — No-op rollback (column removal not implemented)
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

```go
// Applied automatically by the migration runner at startup.
// Manual invocation via goose or the Fleet migration client:
//
//   fleet prepare db --config fleet.yml
//
// The migration is idempotent — safe to re-run if interrupted.
// columnExists and indexExistsTx guards prevent duplicate DDL errors.
```

## Notes

- **Idempotent**: Column and index creation are guarded by `columnExists` / `indexExistsTx` checks, making the migration safe to re-run
- The backfill UPDATE runs unconditionally on every execution; rows already populated are overwritten with the same value (idempotent in practice)
- `Down_20260401153503` is a no-op — dropping the column must be handled manually if a rollback is required
