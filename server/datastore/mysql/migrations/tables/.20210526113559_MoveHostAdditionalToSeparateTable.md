Database migration that moves the `additional` JSON column from the `hosts` table into a dedicated `host_additional` table with a foreign key relationship.

## Key Components

- **`Up_20210526113559`** — Idempotent up migration that:
  1. Creates the `host_additional` table (`host_id`, `additional` JSON) with a cascading foreign key to `hosts`
  2. Seeds it via `INSERT IGNORE ... SELECT` from existing `hosts.additional` data
  3. Drops the `additional` column from `hosts` if it still exists
- **`Down_20210526113559`** — No-op rollback (data migration is one-way)
- **`columnExists`** — Guard check ensuring the `ALTER TABLE DROP COLUMN` is skipped if already removed, making the migration safe to re-run

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20210526113559, Down_20210526113559)

// Resulting schema after Up_20210526113559 runs:
// CREATE TABLE host_additional (
//     host_id   INT UNSIGNED NOT NULL PRIMARY KEY,
//     additional JSON DEFAULT NULL,
//     FOREIGN KEY (host_id) REFERENCES hosts(id)
//         ON DELETE CASCADE ON UPDATE CASCADE
// );
```

## Notes

- The `ON DELETE CASCADE` / `ON UPDATE CASCADE` constraints ensure `host_additional` rows are automatically cleaned up when a host is removed
- `INSERT IGNORE` prevents duplicate-key errors if the migration partially ran before
- The `columnExists` check on `hosts.additional` makes `Up_` fully idempotent
