Database migration that adds a unique constraint on `(batch_execution_id, host_id)` to the `batch_activity_host_results` table, preventing duplicate host result entries per batch execution.

## Key Components

| Symbol | Description |
|--------|-------------|
| `Up_20250814123333` | Idempotently adds the `unique_batch_host_results_execution_hostid` constraint if it does not already exist |
| `Down_20250814123333` | No-op rollback; constraint removal is not implemented |
| `init()` | Registers the migration with `MigrationClient` on package load |

## Usage Example

This migration runs automatically via the Fleet migration runner. No manual invocation is needed; it executes as part of the standard schema upgrade flow:

```bash
# Apply all pending migrations (including this one)
fleet prepare db --config /etc/fleet/fleet.yml
```

To verify the constraint was applied:

```sql
SELECT CONSTRAINT_NAME
FROM information_schema.TABLE_CONSTRAINTS
WHERE TABLE_NAME   = 'batch_activity_host_results'
  AND CONSTRAINT_TYPE = 'UNIQUE';
-- Expected: unique_batch_host_results_execution_hostid
```

## Notes

- **Idempotent**: The `constraintExists` guard makes it safe to re-run without error.
- **One-way migration**: `Down_20250814123333` is intentionally a no-op — dropping the constraint is left as a manual DBA operation if required.
