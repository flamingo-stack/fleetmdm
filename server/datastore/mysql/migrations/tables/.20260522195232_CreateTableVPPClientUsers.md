Database migration that creates the `vpp_client_users` table, which tracks Apple VPP (Volume Purchase Program) client user associations between managed Apple IDs and VPP tokens.

## Key Components

- **`Up_20260522195232`** — Creates the `vpp_client_users` table if it does not already exist (idempotent). Defines columns for VPP token linkage, managed Apple ID, client user UUID, optional Apple user ID, and a lifecycle status enum (`pending`, `registered`, `retired`).
- **`Down_20260522195232`** — No-op rollback; the table is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

### Table Schema Highlights

| Column | Type | Notes |
|---|---|---|
| `id` | `INT UNSIGNED AUTO_INCREMENT` | Primary key |
| `vpp_token_id` | `INT UNSIGNED` | FK → `vpp_tokens(id)` with `ON DELETE CASCADE` |
| `managed_apple_id` | `VARCHAR(255)` | Unique per token |
| `client_user_id` | `VARCHAR(36)` | UUID, unique per token |
| `apple_user_id` | `VARCHAR(255)` | Optional Apple-assigned user ID |
| `status` | `ENUM` | `pending` \| `registered` \| `retired` |
| `created_at` / `updated_at` | `TIMESTAMP(6)` | Microsecond precision, auto-managed |

**Unique constraints:** `(vpp_token_id, managed_apple_id)` and `(vpp_token_id, client_user_id)` prevent duplicate user registrations within the same token scope.
