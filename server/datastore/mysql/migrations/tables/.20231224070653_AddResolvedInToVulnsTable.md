## Notes

- Migration is **idempotent**: skipped if both columns already exist, preventing duplicate-column errors on repeated runs
- `Down` migration is intentionally a no-op — dropping columns risks data loss and is left to manual intervention
- Part of the `tables` migration package registered via `MigrationClient.AddMigration`
