Database migration that clears completed certificate renewal command references in the `nano_cert_auth_associations` table by setting `renew_command_uuid` to `NULL` where the associated command has been acknowledged.

## Key Components

- **`Up_20250326161930`** — Idempotent UP migration that joins `nano_cert_auth_associations` with `nano_command_results` and nullifies `renew_command_uuid` for any renewal commands with a status of `'Acknowledged'`, preventing stale command references from persisting after successful renewal.
- **`Down_20250326161930`** — No-op DOWN migration; the state change (nullifying UUIDs) is not reversible without the original data.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client during schema upgrades:

```bash
# Apply migration
fleet db migrate
```

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20250326161930, Down_20250326161930)
}
```

**SQL executed (UP):**

```sql
UPDATE
    nano_cert_auth_associations ncaa
    JOIN nano_command_results ncr ON renew_command_uuid = command_uuid
        AND ncaa.id = ncr.id
    SET
        renew_command_uuid = NULL
WHERE
    ncr.status = 'Acknowledged'
```

> **Note:** This migration is idempotent — running it multiple times produces the same result, making it safe to re-apply. The DOWN migration is intentionally a no-op since nullified UUIDs cannot be restored without historical data.
