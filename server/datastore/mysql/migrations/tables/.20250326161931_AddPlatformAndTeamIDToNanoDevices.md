Database migration that adds `platform` and `enroll_team_id` columns to the `nano_devices` table, and backfills platform values for existing deleted-host MDM devices.

## Key Components

- **`Up_20250326161931`** — Idempotent up migration that:
  1. Adds `platform VARCHAR(255)` and `enroll_team_id INT UNSIGNED` columns to `nano_devices`
  2. Adds a foreign key constraint linking `enroll_team_id` to `teams(id)` with `ON DELETE SET NULL`
  3. Backfills `platform` for enrolled devices whose host records have been deleted, by parsing the stored MDM `Authenticate` checkin message and inferring `ios`, `ipados`, or `darwin` from `ProductName`
- **`Down_20250326161931`** — No-op rollback (columns are not removed)
- **`init`** — Registers the migration with `MigrationClient`

## Usage Example

This migration is applied automatically via the Fleet migration runner. It is not called directly, but the idempotency guards make manual inspection safe:

```go
// Columns are only added if absent
if !columnsExists(tx, "nano_devices", "platform", "enroll_team_id") {
    // ALTER TABLE runs here
}

// FK is only added if absent
if !constraintExists(tx, "nano_devices", "fk_nano_devices_team_id") {
    // ADD CONSTRAINT runs here
}
```

Platform detection logic for backfill:

```go
platform := "darwin"
if strings.HasPrefix(authMsg.ProductName, "iPhone") {
    platform = "ios"
} else if strings.HasPrefix(authMsg.ProductName, "iPad") {
    platform = "ipados"
}
```

> **Note:** Devices with unparseable `authenticate` payloads are silently skipped during backfill. They will not have a platform set and cannot be automatically re-created on next check-in.
