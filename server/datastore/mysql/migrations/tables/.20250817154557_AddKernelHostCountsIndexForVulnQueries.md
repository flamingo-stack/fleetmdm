Database migration that adds a composite index on the `kernel_host_counts` table to optimize kernel vulnerability queries.

## Key Components

- **`Up_20250817154557`** – Creates the composite index `idx_kernel_host_counts_os_version_software` on `kernel_host_counts(os_version_id, software_id, hosts_count)` if it does not already exist (idempotent via `indexExistsTx` guard).
- **`Down_20250817154557`** – No-op rollback; the index is left in place on downgrade.
- **`init`** – Registers both migration functions with `MigrationClient`.

## Index Details

```sql
CREATE INDEX idx_kernel_host_counts_os_version_software
ON kernel_host_counts (os_version_id, software_id, hosts_count);
```

This composite index supports efficient joins between `software_cve` and `kernel_host_counts` when filtering by `os_version_id` with a `hosts_count > 0` predicate, reducing full-table scans during vulnerability reporting queries.

## Usage Example

This migration runs automatically via the `MigrationClient` on `fleet db migrate`:

```bash
fleet db migrate
```

To verify the index was created:

```sql
SHOW INDEX FROM kernel_host_counts
WHERE Key_name = 'idx_kernel_host_counts_os_version_software';
```

> **Note:** The `Up` function is idempotent — re-running the migration on a database where the index already exists is safe and produces no error.
