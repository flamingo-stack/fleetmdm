Database migration that renames the `checksum` column to `token` in the `host_mdm_apple_declarations` table and drops the `checksum` column from `mdm_apple_declarations` as part of DDM (Declarative Device Management) schema cleanup.

## Key Components

- **`Up_20241231112624`** — Applies the migration idempotently using `columnExists` checks before executing DDL:
  - Renames `checksum` → `token` on `host_mdm_apple_declarations`
  - Drops `checksum` from `mdm_apple_declarations`
- **`Down_20241231112624`** — No-op rollback (destructive changes are not reversible)
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration runs automatically via the Fleet migration client. No manual invocation is needed. It is safe to run multiple times due to the idempotency guards:

```go
// Internally called by the migration runner:
if columnExists(tx, "host_mdm_apple_declarations", "checksum") {
    tx.Exec(`ALTER TABLE host_mdm_apple_declarations
        RENAME COLUMN checksum TO token`)
}

if columnExists(tx, "mdm_apple_declarations", "checksum") {
    tx.Exec(`ALTER TABLE mdm_apple_declarations
        DROP COLUMN checksum`)
}
```

## Notes

- **Idempotent**: Each DDL statement is guarded by a `columnExists` check, making it safe to re-run if the migration was partially applied.
- **Irreversible**: The `Down` function is a no-op — dropped columns cannot be recovered via rollback.
