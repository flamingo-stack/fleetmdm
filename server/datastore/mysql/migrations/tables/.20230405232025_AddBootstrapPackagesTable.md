Database migration that creates the `mdm_apple_bootstrap_packages` table for storing MDM Apple bootstrap package metadata and binary data per team.

## Key Components

- **`Up_20230405232025`** — Creates the `mdm_apple_bootstrap_packages` table (idempotent via `CREATE TABLE IF NOT EXISTS`) with the following columns:
  - `team_id` — Primary key; unsigned int linking the package to a Fleet team
  - `name` — Optional package display name (up to 255 chars)
  - `sha256` — 32-byte binary hash for package integrity verification
  - `bytes` — `longblob` storing the raw package binary
  - `token` — Unique 36-char token (UUID) used for package retrieval
- **`Down_20230405232025`** — No-op rollback; table is left in place on downgrade
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration is auto-registered and executed by the Fleet migration runner. No direct invocation is required.

```go
// Migration runs automatically during database initialization:
// fleet prepare db --config fleet.yml

// To apply manually via goose or the migration client:
MigrationClient.AddMigration(Up_20230405232025, Down_20230405232025)
```

## Notes

- Table uses `utf8mb4` / `utf8mb4_unicode_ci` charset for full Unicode support
- One bootstrap package is stored per `team_id` (enforced by primary key)
- The `token` unique index enables fast token-based lookups for package downloads
- The down migration is intentionally empty; dropping this table would cause data loss
