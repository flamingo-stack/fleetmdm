Database migration that renames and restructures Fleet-maintained app (FMA v2) tables and columns, consolidating the `fleet_library_apps` schema into `fleet_maintained_apps` with a simplified, slug-based structure.

## Key Components

- **`Up_20250320200000(tx *sql.Tx) error`** — Applies the forward migration with the following idempotent steps:
  - Renames `fleet_library_app_id` column to `fleet_maintained_app_id` in `software_installers`
  - Renames `fleet_library_apps` table to `fleet_maintained_apps`
  - Unlinks software installers whose install/uninstall scripts have diverged from their FMA
  - Drops legacy foreign key constraints on `fleet_maintained_apps`
  - Removes columns (`version`, `installer_url`, `sha256`, `install_script_content_id`, `uninstall_script_content_id`) and renames `bundle_identifier` → `unique_identifier` and `token` → `slug`
  - Cleans up orphaned `script_contents` rows no longer referenced by any host scripts, saved scripts, software installers, or setup experience scripts
  - Appends the platform to each FMA slug (e.g., `zoom` → `zoom/darwin`)
  - Resolves a Zoom FMA duplicate by consolidating `zoom-for-it-admins/darwin` → `zoom/darwin`
  - Clears scheduled `maintained_apps` cron stats to force a full resync on next server start

- **`Down_20250320200000(tx *sql.Tx) error`** — No-op rollback; migration is not reversible.

## Usage Example

This migration is registered automatically via `init()` and executed by the Fleet migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20250320200000, Down_20250320200000)
}

// Run via the Fleet migration CLI:
// fleet prepare db --config /path/to/config.yaml
```

> **Note:** The migration is idempotent — column and table renames are guarded by `columnExists`/`tableExists`/`constraintExists` checks, making it safe to re-run if interrupted. The `Down` migration is a no-op; schema rollback must be handled manually if needed.
