Database migration that updates the `software_titles` table by introducing a virtual `unique_identifier` column and replacing the existing unique index with a more robust deduplication strategy.

## Key Components

- **`Up_20250124194347`** — Applies the migration with three idempotent steps:
  1. Adds a virtual `unique_identifier` column computed as `COALESCE(bundle_identifier, name)` — preferring `bundle_identifier` when available, falling back to `name`
  2. Creates a new unique index `idx_unique_sw_titles` on `(unique_identifier, source, browser)`
  3. Rebuilds the existing `idx_sw_titles` index on `(name, source, browser)` as a non-unique index

- **`Down_20250124194347`** — No-op rollback (migration is considered non-reversible)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Applied automatically during fleet database migrations
// Manual invocation via the migration CLI:
// fleetctl prepare db --config /etc/fleet/fleet.yml
```

The migration is fully **idempotent** — each step checks for existence before applying, making it safe to re-run if interrupted:

```go
// Guard pattern used throughout:
if !columnExists(tx, "software_titles", "unique_identifier") {
    // add column only if missing
}

if !indexExistsTx(tx, "software_titles", "idx_unique_sw_titles") {
    // add index only if missing
}
```

## Notes

- The `GENERATED ALWAYS AS ... VIRTUAL` column avoids storing redundant data while enabling indexing on a derived value
- The `COALESCE` strategy ensures macOS/iOS apps with bundle identifiers are deduplicated by that field, while other software falls back to `name`
