Database migration that adds `signup_token` and `pubsub_topic_id` columns to the `android_enterprises` table, and creates the new `android_devices` table for tracking enrolled Android devices.

## Key Components

- **`Up_20250219142401`** — Applies the migration: idempotently adds two columns to `android_enterprises` and creates the `android_devices` table if it doesn't exist.
- **`Down_20250219142401`** — No-op rollback; destructive reversal is not implemented.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Schema Changes

**`android_enterprises` (altered):**

| Column | Type | Description |
|---|---|---|
| `signup_token` | `VARCHAR(64)` | Auth token for enterprise creation callback |
| `pubsub_topic_id` | `VARCHAR(64)` | Google PubSub topic identifier |

**`android_devices` (created):**

| Column | Type | Description |
|---|---|---|
| `id` | `INT UNSIGNED` | Auto-increment primary key |
| `host_id` | `INT UNSIGNED` | Reference to host record (unique) |
| `device_id` | `VARCHAR(32)` | Android device identifier (unique) |
| `enterprise_specific_id` | `VARCHAR(64)` | Identifies personally-owned devices (unique, nullable) |
| `android_policy_id` | `INT UNSIGNED` | Optional policy assignment |
| `last_policy_sync_time` | `DATETIME(3)` | Last MDM policy sync timestamp |
| `created_at` / `updated_at` | `DATETIME(6)` | Audit timestamps |

## Usage Example

```go
// Migration is registered automatically via init().
// Executed by the migration client during Fleet server startup:
if err := MigrationClient.Up(db, ""); err != nil {
    log.Fatal("migration failed:", err)
}
```

## Notes

- The `Up` function is **idempotent**: the `android_enterprises` column additions are guarded by `columnsExists`, and `android_devices` uses `CREATE TABLE IF NOT EXISTS`.
- All string columns use `utf8mb4_unicode_ci` collation for full Unicode support.
