Database migration that adds a `browser` column to the `software_titles` table and removes the `idx_software_titles_name_source` index.

## Key Components

- **`Up_20231207102320`** — Applies the migration with three idempotent steps:
  1. Clears all rows from `software_titles` (repopulated on the next cron run)
  2. Adds a `browser VARCHAR(255)` column (with `utf8mb4_unicode_ci` collation, defaulting to `''`) if it does not already exist
  3. Drops the `idx_software_titles_name_source` index if present
- **`Down_20231207102320`** — No-op rollback; the migration is not reversible
- **`init`** — Registers both functions with `MigrationClient`

## Usage Example

This migration is executed automatically by the migration runner. No manual invocation is needed. To apply it manually during development:

```go
// Run all pending migrations (including this one)
if err := tables.MigrationClient.Up(db, ""); err != nil {
    log.Fatal(err)
}
```

The migration is idempotent — re-running it is safe because each DDL step checks for the existence of the column or index before executing.

## Notes

- The full table truncation ensures stale title records (which lack the new `browser` field) are removed. Fleet repopulates `software_titles` on the next scheduled inventory cron.
