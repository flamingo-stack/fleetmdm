Database migration that creates the `policy_labels` join table, establishing a many-to-many relationship between policies and labels with support for inclusion/exclusion logic.

## Key Components

- **`Up_20250401155831`** — Creates the `policy_labels` table with foreign key constraints referencing `policies` and `labels`, a unique composite key on `(policy_id, label_id)`, and an `exclude` flag for label-based targeting control. The migration is idempotent via `CREATE TABLE IF NOT EXISTS`.
- **`Down_20250401155831`** — No-op rollback; the table is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Schema Created

```text
policy_labels
├── id           INT UNSIGNED AUTO_INCREMENT (PK)
├── policy_id    INT UNSIGNED (FK → policies.id ON DELETE CASCADE)
├── label_id     INT UNSIGNED (FK → labels.id ON DELETE CASCADE)
├── exclude      TINYINT(1) DEFAULT 0
├── created_at   TIMESTAMP
└── updated_at   TIMESTAMP (auto-updated)
```

## Usage Example

This migration runs automatically via the `MigrationClient` during schema upgrades. No direct invocation is needed.

```go
// Applying all pending migrations (typical Fleet startup path)
if err := MigrationClient.Up(db, ""); err != nil {
    log.Fatalf("migration failed: %v", err)
}
```

The `exclude` column allows a policy to either target devices **matching** a label (`exclude=0`) or **exclude** devices matching a label (`exclude=1`), enabling fine-grained scoping of policy enforcement.
