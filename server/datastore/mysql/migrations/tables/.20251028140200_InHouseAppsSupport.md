Database migration that creates two tables to support in-house (enterprise/sideloaded) app management: `in_house_apps` for storing app metadata and `in_house_app_labels` for mapping apps to Fleet labels.

## Key Components

- **`Up_20251028140200`** — Creates the `in_house_apps` and `in_house_app_labels` tables using `IF NOT EXISTS` (idempotent). Enforces a unique constraint on `(global_or_team_id, name, platform)` and a foreign key to `software_titles`.
- **`Down_20251028140200`** — No-op rollback (tables are not dropped).
- **`init`** — Registers the migration with `MigrationClient`.

## Schema Overview

**`in_house_apps`**

| Column | Type | Notes |
|---|---|---|
| `id` | `int unsigned` | Primary key, auto-increment |
| `title_id` | `int unsigned` | FK → `software_titles(id)`, nullable |
| `team_id` | `int unsigned` | Nullable team scope |
| `global_or_team_id` | `int unsigned` | Used in unique constraint |
| `name` | `varchar(255)` | App name |
| `version` | `varchar(255)` | App version |
| `storage_id` | `varchar(64)` | Reference to stored binary |
| `platform` | `varchar(10)` | Target OS platform |
| `bundle_identifier` | `varchar(255)` | e.g., `com.example.app` |

**`in_house_app_labels`** — Maps apps to Fleet labels with optional exclusion (`exclude` flag).
