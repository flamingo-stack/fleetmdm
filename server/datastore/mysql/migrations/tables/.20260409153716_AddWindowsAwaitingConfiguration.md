Database migration that adds `awaiting_configuration` and `awaiting_configuration_at` columns to the `mdm_windows_enrollments` table to track Windows MDM enrollment configuration state.

## Key Components

- **`Up_20260409153716`** – Applies the migration; adds two columns to `mdm_windows_enrollments`:
  - `awaiting_configuration` — `TINYINT(1) NOT NULL DEFAULT 0`, boolean flag indicating a device is pending configuration
  - `awaiting_configuration_at` — `DATETIME(6) DEFAULT NULL`, timestamp of when the device entered the awaiting state
  - Guards against re-application using `columnExists` before altering the table
- **`Down_20260409153716`** – No-op rollback; columns are not removed on downgrade
- **`init`** – Registers both migration functions with `MigrationClient`

## Usage Example

This migration is applied automatically by the Fleet migration runner. To run it manually:

```bash
# Apply migration
fleet prepare db --config /etc/fleet/fleet.yml

# Or via the migration client directly in code
MigrationClient.AddMigration(Up_20260409153716, Down_20260409153716)
```

```go
// Migration is idempotent — safe to call multiple times
err := Up_20260409153716(tx)
if err != nil {
    log.Fatalf("migration failed: %v", err)
}
```

> **Note:** The down migration is intentionally a no-op. Restoring the previous schema requires a manual `ALTER TABLE mdm_windows_enrollments DROP COLUMN awaiting_configuration` if needed.
