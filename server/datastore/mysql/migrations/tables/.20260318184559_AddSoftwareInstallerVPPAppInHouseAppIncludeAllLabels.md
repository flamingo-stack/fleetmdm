Database migration that adds a `require_all` boolean column to three label-association tables, enabling "include all labels" filtering logic for software installers, VPP apps, and in-house apps.

## Key Components

| Function | Description |
|---|---|
| `Up_20260318184559` | Idempotently adds `require_all BOOL NOT NULL DEFAULT false` to `in_house_app_labels`, `software_installer_labels`, and `vpp_app_team_labels` |
| `Down_20260318184559` | No-op rollback (column removal is intentionally skipped) |

## Schema Changes

Each of the following tables receives the new column if it doesn't already exist:

```text
in_house_app_labels      → require_all BOOL NOT NULL DEFAULT false
software_installer_labels → require_all BOOL NOT NULL DEFAULT false
vpp_app_team_labels       → require_all BOOL NOT NULL DEFAULT false
```

The `require_all` flag controls whether a device must match **all** associated labels (logical AND) versus **any** label (logical OR) to be targeted by a software deployment.

## Usage Example

This migration runs automatically via the FleetMDM migration client on startup:

```go
// Registered in init(); executed by the migration runner:
MigrationClient.AddMigration(Up_20260318184559, Down_20260318184559)
```

To apply manually during development:

```bash
fleet prepare db --config /etc/fleet/config.yml
```

## Notes

- **Idempotent**: Each `ALTER TABLE` is guarded by `columnExists()`, making it safe to re-run without errors.
- **Non-destructive rollback**: `Down_` is a no-op; dropping the column must be handled manually if needed.
