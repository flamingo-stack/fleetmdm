Database migration that adds an `agent_options` JSON column to the `app_configs` table and migrates existing osquery options from the legacy `osquery_options` table into the new column.

## Key Components

- **`Up_20210601000006`** — Idempotent migration that conditionally adds the `agent_options` JSON column to `app_configs` and populates it by copying data from the old `osquery_options` table.
- **`Down_20210601000006`** — No-op rollback function.
- **`copyOptions`** — Reads rows from `osquery_options`, maps them into a `fleet.AgentOptions` struct (handling default and platform-level overrides), and returns the result as `json.RawMessage`.
- **`optionsRow`** — Internal struct representing a row from the legacy `osquery_options` table, with fields for override type, identifier, and raw options JSON.

## Usage Example

This migration runs automatically via the `MigrationClient` registered in `init()`. It is not called directly. The schema transformation it performs:

```go
// Before (legacy table)
// osquery_options: { id, override_type, override_identifier, options }

// After (new column on app_configs)
// app_configs.agent_options (JSON):
// {
//   "config": { ...default osquery config... },
//   "overrides": {
//     "platforms": {
//       "darwin": { ...platform-specific config... }
//     }
//   }
// }
```

Override type mapping from the legacy schema:

```go
case 0: // OptionOverrideTypeDefault  → opt.Config
case 1: // OptionOverrideTypePlatform → opt.Overrides.Platforms[identifier]
```

## Notes

- The migration is **idempotent**: it checks for column existence via `columnExists` before applying the `ALTER TABLE`, making it safe to re-run.
