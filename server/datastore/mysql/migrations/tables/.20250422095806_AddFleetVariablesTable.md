Database migration that creates the `fleet_variables` and `mdm_configuration_profile_variables` tables, and seeds initial Fleet variable definitions used for server-side substitution in configuration profiles and scripts.

## Key Components

- **`Up_20250422095806`** — Creates two tables and inserts seed data:
  - `fleet_variables` — Stores named variables (exact-match or prefix-based) that Fleet replaces server-side before applying profiles/scripts. Does **not** store secrets.
  - `mdm_configuration_profile_variables` — Join table linking Apple or Windows MDM configuration profiles to fleet variables, with mutual exclusivity enforced via a `CHECK` constraint (only one of `apple_profile_uuid` / `windows_profile_uuid` may be set per row).
  - Seeds 11 built-in variables (e.g., `FLEET_VAR_HOST_HARDWARE_SERIAL`, `FLEET_VAR_HOST_END_USER_EMAIL_IDP`, prefix-based `FLEET_VAR_DIGICERT_DATA_`) with a deterministic `created_at` timestamp.

- **`Down_20250422095806`** — No-op rollback (returns `nil`).

## Schema Details

| Table | Key Constraints |
|---|---|
| `fleet_variables` | Unique on `(name, is_prefix)` |
| `mdm_configuration_profile_variables` | Unique per Apple/Windows profile + variable; FK cascade deletes; `CHECK` enforces XOR on profile UUID columns |

## Usage Example

This migration is auto-registered via `init()` and executed by the Fleet migration runner:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20250422095806, Down_20250422095806)
}

// Seeded variables available for profile substitution
// FLEET_VAR_HOST_HARDWARE_SERIAL     → exact match
// FLEET_VAR_DIGICERT_DATA_           → prefix match (is_prefix = 1)
// FLEET_VAR_CUSTOM_SCEP_CHALLENGE_   → prefix match (is_prefix = 1)
```

> **Note:** Fleet *secrets* are intentionally excluded from this table. See the upstream tracking issue for details.
