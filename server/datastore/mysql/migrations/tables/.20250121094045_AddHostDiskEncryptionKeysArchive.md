Database migration that creates the `host_disk_encryption_keys_archive` table and updates timestamp precision on disk-related tables.

## Key Components

- **`Up_20250121094045`** — Applies the migration in three steps:
  1. Upgrades `created_at`/`updated_at` columns on `host_disks` and `host_disk_encryption_keys` to microsecond precision (`TIMESTAMP(6)`) if they exist
  2. Creates the `host_disk_encryption_keys_archive` table with a `BIGINT UNSIGNED` auto-increment primary key (sized for long-term retention), storing `host_id`, `hardware_serial`, encrypted key data, and a microsecond `created_at`
  3. Seeds the archive by copying all existing rows from `host_disk_encryption_keys` and backfilling `hardware_serial` via a `JOIN` against `hosts`

- **`Down_20250121094045`** — No-op rollback; the archive table is left in place on downgrade

## Schema — `host_disk_encryption_keys_archive`

| Column | Type | Notes |
|---|---|---|
| `id` | `BIGINT UNSIGNED AUTO_INCREMENT` | Large PK for long-lived data |
| `host_id` | `INT UNSIGNED` | References host |
| `hardware_serial` | `VARCHAR(255)` | Backfilled from `hosts` table |
| `base64_encrypted` | `TEXT` | Encrypted key payload |
| `base64_encrypted_salt` | `VARCHAR(255)` | Encryption salt |
| `key_slot` | `TINYINT UNSIGNED` | Optional key slot |
| `created_at` | `TIMESTAMP(6)` | Microsecond precision |

Index: `(host_id, created_at DESC)` for efficient per-host history queries.

## Usage Example

```go
// Registered automatically via init(); invoked by the migration runner
MigrationClient.AddMigration(Up_20250121094045, Down_20250121094045)

// Apply via Fleet's standard migration tooling
fleetctl prepare db --config /etc/fleet/fleet.yml
```

> **Idempotency:** The `TIMESTAMP(6)` alterations are guarded by `columnExists` checks, and the archive table uses `CREATE TABLE IF NOT EXISTS`, making the migration safe to re-run.
