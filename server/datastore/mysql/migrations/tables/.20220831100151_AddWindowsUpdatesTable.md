Database migration that creates the `windows_updates` table for tracking Windows KB updates per host.

## Key Components

- **`Up_20220831100151`** — Creates the `windows_updates` table (idempotent via `CREATE TABLE IF NOT EXISTS`) with the following schema:

| Column | Type | Description |
|---|---|---|
| `id` | `INT UNSIGNED AUTO_INCREMENT` | Primary key |
| `host_id` | `INT UNSIGNED` | Reference to the host |
| `date_epoch` | `INT UNSIGNED` | Update installation timestamp (Unix epoch) |
| `kb_id` | `INT UNSIGNED` | Windows Knowledge Base article ID |

  **Indexes:**
  - `idx_unique_windows_updates` — Unique constraint on `(host_id, kb_id)`, preventing duplicate update records per host
  - `idx_update_date` — Composite index on `(host_id, date_epoch)` for efficient date-based queries per host

- **`Down_20220831100151`** — No-op rollback; table is left in place on downgrade.

## Usage Example

```go
// Migration is registered automatically via init()
// and executed by the migration client during schema upgrades.

// Querying updates for a specific host ordered by date:
rows, err := db.Query(`
    SELECT kb_id, date_epoch
    FROM windows_updates
    WHERE host_id = ?
    ORDER BY date_epoch DESC
`, hostID)
```

## Notes

- The `Down` migration is intentionally empty — dropping the table on rollback is not implemented, making this a one-way migration.
