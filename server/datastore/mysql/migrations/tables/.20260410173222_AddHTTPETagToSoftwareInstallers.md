Database migration that adds an `http_etag` column and a composite index to the `software_installers` table to support HTTP ETag-based caching for software installer URLs.

## Key Components

- **`Up_20260410173222`** — Idempotent up migration that performs two schema changes:
  - Adds `http_etag VARCHAR(512)` (nullable, `utf8mb4_unicode_ci` collation) to `software_installers` if it does not already exist.
  - Creates a composite index `idx_software_installers_team_url` on `(global_or_team_id, url(255))` if it does not already exist. The 255-byte prefix is a MySQL InnoDB key-length constraint; full URL values are still matched via row comparison.
- **`Down_20260410173222`** — No-op per Fleet forward-only migration convention.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically by the Fleet migration runner. No manual invocation is needed. To run all pending migrations:

```bash
fleetctl prepare db --config /etc/fleet/fleet.yml
```

To verify the schema change was applied:

```sql
SHOW COLUMNS FROM software_installers LIKE 'http_etag';
SHOW INDEX FROM software_installers WHERE Key_name = 'idx_software_installers_team_url';
```

## Notes

- Both DDL operations are guarded by existence checks (`columnExists`, `indexExistsTx`), making the migration safe to re-run.
- The down migration intentionally does nothing — dropping columns or indexes on rollback can cause data loss and is avoided by convention in this codebase.
