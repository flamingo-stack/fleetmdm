Database migration that adds `created_at` and `updated_at` timestamp columns to the `host_device_auth` table.

## Key Components

- **`Up_20220928100158`** — Idempotent migration that adds two timestamp columns to `host_device_auth` if they don't already exist:
  - `created_at`: defaults to `CURRENT_TIMESTAMP` on insert
  - `updated_at`: defaults to `CURRENT_TIMESTAMP` and auto-updates via `ON UPDATE CURRENT_TIMESTAMP`
- **`Down_20220928100158`** — No-op rollback; columns are not removed on downgrade
- **`columnsExists`** — Guard check ensuring the migration is safe to re-run without error

## Usage Example

```go
// Migration is registered automatically via init()
// and applied by the MigrationClient runner.

// Equivalent schema change applied:
ALTER TABLE host_device_auth
    ADD COLUMN created_at timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    ADD COLUMN updated_at timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP;
```

## Notes

- The migration is **idempotent** — running it multiple times against an already-migrated schema is safe due to the `columnsExists` pre-check
- The down migration is intentionally a no-op; dropping audit timestamp columns is considered destructive and is left as a manual operation
