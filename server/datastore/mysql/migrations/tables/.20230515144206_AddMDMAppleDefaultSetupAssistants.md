Database migration that creates the `mdm_apple_default_setup_assistants` table, which stores default macOS Setup Assistant profile UUIDs per team for MDM Apple enrollment flows.

## Key Components

- **`Up_20230515144206`** — Creates the `mdm_apple_default_setup_assistants` table (idempotent via `CREATE TABLE IF NOT EXISTS`) with the following schema:
  - `team_id` — nullable foreign key referencing `teams(id)` with cascade delete/update; `NULL` represents the global/no-team context
  - `global_or_team_id` — non-nullable surrogate used for the unique constraint since `NULL` columns cannot participate in standard unique indexes; `0` for global, otherwise mirrors `team_id`
  - `profile_uuid` — the MDM profile UUID assigned as the default setup assistant
  - Standard `created_at`/`updated_at` timestamps

- **`Down_20230515144206`** — No-op rollback (table is not dropped on downgrade)

- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration runs automatically via the Fleet migration client. To apply manually:

```go
// Executed automatically on fleet db prepare / fleet db migrate
Up_20230515144206(tx)
```

The table enforces at most one default setup assistant per team (or globally), falling back to this record only when no custom setup assistant exists in `mdm_apple_setup_assistants` for that team.

## Notes

- The `global_or_team_id` pattern is a common workaround for MySQL's handling of `NULL` in unique indexes — multiple `NULL` values are permitted in a unique column, so a surrogate `0` is used for the global row instead.
