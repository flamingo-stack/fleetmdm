Database migration that adds an `auto_rotate_at` column and index to the `host_recovery_key_passwords` table to support automatic rotation of viewed recovery lock passwords.

## Key Components

- **`Up_20260326131501`** — Idempotent migration that adds:
  - `auto_rotate_at TIMESTAMP(6) NULL` column — set to 1 hour in the future when a password is viewed via API; used by a cron job to trigger rotation when `auto_rotate_at <= NOW()`
  - `idx_auto_rotate_at` index on the new column for efficient cron queries
- **`Down_20260326131501`** — No-op rollback (column removal omitted intentionally)

## Usage Example

This migration is registered automatically via `init()` and applied by the migration client:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20260326131501, Down_20260326131501)
```

The `Up` function handles three idempotent states:

```go
// Case 1: Column and index both missing → adds both
// Case 2: Column exists, index missing → adds index only
// Case 3: Both exist → no-op
```

After migration, the rotation flow is:

```text
Password viewed via API
    → auto_rotate_at = NOW() + 1 hour

Cron job runs
    → SELECT * FROM host_recovery_key_passwords WHERE auto_rotate_at <= NOW()
    → Rotates matched passwords
```
