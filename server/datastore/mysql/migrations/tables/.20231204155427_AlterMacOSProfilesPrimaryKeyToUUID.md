Database migration that transitions macOS (Apple) MDM configuration profile tables from integer-based primary keys to UUID-based primary keys, while also expanding Windows profile UUID column widths to support a vendor-prefix character.

## Key Components

- **`Up_20231204155427`** — Idempotent forward migration performing four operations:
  1. Expands `profile_uuid` to `VARCHAR(37)` in `host_mdm_windows_profiles` and `mdm_windows_configuration_profiles` to accommodate a `'w'` prefix.
  2. Adds a `profile_uuid VARCHAR(37)` column to `mdm_apple_configuration_profiles` and populates it with `'a'`-prefixed UUIDs (e.g., `axxxxxxxx-xxxx-...`).
  3. Promotes `profile_uuid` to the primary key of `mdm_apple_configuration_profiles`, preserving `profile_id` as a unique index.
  4. Adds `profile_uuid` to `host_mdm_apple_profiles`, back-fills it from the parent profiles table, then replaces the old `(host_uuid, profile_id)` composite primary key with `(host_uuid, profile_uuid)` and drops `profile_id`.

- **`Down_20231204155427`** — No-op rollback; the migration is intentionally irreversible.

## Idempotency Strategy

Each step guards against re-execution using `columnExists`, `indexExistsTx`, and `INFORMATION_SCHEMA.STATISTICS` checks, making the migration safe to run multiple times without error.

## Usage Example

This migration is registered automatically via `init()` and executed by the Fleet migration runner:

