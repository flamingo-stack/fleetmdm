Database migration that creates the `locks` table, used for distributed locking mechanisms within the Fleet MDM application.

## Key Components

- **`Up_20210712155608`** — Creates the `locks` table if it does not already exist (idempotent). Defines columns for `id`, `name`, `owner`, and `expires_at`, with a unique index on `name`.
- **`Down_20210712155608`** — No-op rollback; the table is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Table Schema

| Column | Type | Notes |
|---|---|---|
| `id` | `INT UNSIGNED` | Auto-increment primary key |
| `name` | `VARCHAR(255)` | Unique lock identifier |
| `owner` | `VARCHAR(255)` | Entity holding the lock |
| `expires_at` | `TIMESTAMP` | Defaults to current timestamp |

Engine: `InnoDB`, charset: `utf8mb4_unicode_ci`.

## Usage Example

```go
// Applied automatically by the migration runner at startup.
// To manually run up/down migrations during development:
if err := MigrationClient.Up(db, "20210712155608"); err != nil {
    log.Fatal(err)
}
```

## Notes

- The migration is **idempotent** (`CREATE TABLE IF NOT EXISTS`), making it safe to re-run.
- The `Down` function is intentionally a no-op — dropping the `locks` table on rollback could cause data loss in environments relying on active locks.
