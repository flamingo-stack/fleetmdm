Database migration that removes invalid `mobile_device_management_solutions` entries with empty `server_url` or `name` fields, and cleans up associated `host_mdm` records.

## Key Components

- **`Up_20221227163855`** — Idempotent migration that:
  1. Queries `mobile_device_management_solutions` for rows with an empty `server_url` (unenrolled macOS hosts incorrectly linked to a blank MDM solution) or empty `name` (misidentified Fleet MDM entries)
  2. Deletes the identified rows from `mobile_device_management_solutions`
  3. Cascades the cleanup to `host_mdm` by removing rows referencing the same IDs
  4. Exits early with no error if no invalid entries are found

- **`Down_20221227163855`** — No-op rollback (data is not restored)

## Usage Example

This migration is automatically registered and executed by the migration client on startup via `init()`:

```go
func init() {
    MigrationClient.AddMigration(Up_20221227163855, Down_20221227163855)
}
```

To run manually using the Fleet migration tooling:

```bash
fleet prepare db --config /etc/fleet/fleet.yml
```

## Notes

- **Idempotent**: Safe to run multiple times; a no-op if no invalid records exist.
- Addresses [fleetdm/fleet#9006](https://github.com/fleetdm/fleet/issues/9006), where unenrolled macOS hosts were incorrectly associated with an empty MDM solution.
- The `Down` function is intentionally empty — deleted MDM solution data cannot be meaningfully reconstructed.
