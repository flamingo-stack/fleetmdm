Database migration that adds GitOps exception configuration fields to the `AppConfig` JSON, setting default values that preserve existing behavior for labels and secrets while disabling software exceptions.

## Key Components

- **`Up_20260323144117`** — Applies the migration by calling `updateAppConfigJSON` to set `GitOpsConfig.Exceptions` defaults: `Labels: true`, `Secrets: true`, `Software: false`. The migration is idempotent and safe to re-run.
- **`Down_20260323144117`** — No-op rollback; returns `nil` without modifying state.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Behavior Notes

- **Idempotent** — Uses `UPDATE`/JSON config mutation only; re-running produces the same result.
- **Backwards-compatible defaults** — `Labels` and `Secrets` are set to `true` to match the pre-migration implicit behavior (those fields were no-ops when omitted from GitOps). `Software` defaults to `false`.

## Usage Example

This migration runs automatically via the Fleet migration client. It is not called directly.

```go
// Registered automatically at package init:
MigrationClient.AddMigration(Up_20260323144117, Down_20260323144117)

// Up function modifies AppConfig JSON in-place:
err := Up_20260323144117(tx)

// Resulting GitOpsConfig.Exceptions state after migration:
// config.GitOpsConfig.Exceptions.Labels   = true
// config.GitOpsConfig.Exceptions.Secrets  = true
// config.GitOpsConfig.Exceptions.Software = false
```
