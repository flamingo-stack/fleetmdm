Database migration that adds host activity tracking and extends `host_script_results` with user attribution and sync request metadata.

## Key Components

- **`Up_20240126020643`** — Applies the migration with three idempotent operations:
  - Adds `user_id` (nullable FK to `users`) and `sync_request` (boolean flag) columns to `host_script_results`
  - Adds the `fk_host_script_results_user_id` foreign key constraint with `ON DELETE SET NULL`
  - Creates the `host_activities` join table linking `host_id` to `activities` with cascade delete
  - Backfills `exit_code = -1` for any previously queued scripts lacking a result, preventing them from being unexpectedly re-sent to hosts
- **`Down_20240126020643`** — No-op rollback (destructive schema changes are not reversed)

## Schema Changes

```text
host_script_results
  + user_id       INT UNSIGNED DEFAULT NULL  (FK → users.id ON DELETE SET NULL)
  + sync_request  TINYINT(1) NOT NULL DEFAULT 0

host_activities (new table)
  host_id         INT UNSIGNED NOT NULL
  activity_id     INT UNSIGNED NOT NULL  (FK → activities.id ON DELETE CASCADE)
  PRIMARY KEY (host_id, activity_id)
```

## Usage Example

```go
// Registered automatically via init(); invoked by the migration runner
func init() {
    MigrationClient.AddMigration(Up_20240126020643, Down_20240126020643)

```

> **Design notes:**
> - `user_id` uses `SET NULL` on delete rather than copying user data, since script executions are expected to complete before a user is removed.
> - No FK from `host_activities` to `hosts` is intentional — avoids write contention during high-volume ingestion.
> - The backfill UPDATE preserves `updated_at` to avoid side effects on time-based queries.
