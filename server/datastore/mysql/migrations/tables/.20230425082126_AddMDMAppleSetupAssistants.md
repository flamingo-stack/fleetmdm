Database migration that creates the `mdm_apple_setup_assistants` table, which stores macOS Setup Assistant profiles scoped to either a specific team or globally (no team).

## Key Components

- **`Up_20230425082126`** — Creates the `mdm_apple_setup_assistants` table with idempotent (`IF NOT EXISTS`) DDL. Enforces a one-profile-per-team/global constraint via a unique index on `global_or_team_id`, and cascades deletes/updates from the `teams` foreign key.
- **`Down_20230425082126`** — No-op rollback; table removal is not implemented.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Table Schema Highlights

| Column | Type | Notes |
|---|---|---|
| `id` | `INT UNSIGNED` | Auto-increment primary key |
| `team_id` | `INT UNSIGNED NULL` | `NULL` represents global/no-team scope |
| `global_or_team_id` | `INT UNSIGNED` | `0` = global, otherwise mirrors `team_id`; used for uniqueness |
| `name` | `TEXT` | Human-readable assistant name |
| `profile` | `JSON` | Raw macOS Setup Assistant profile payload |
| `created_at` / `updated_at` | `TIMESTAMP` | Audit timestamps |

## Notes

- `global_or_team_id` solves the MySQL limitation where `UNIQUE` constraints treat `NULL` values as distinct, allowing multiple `NULL` `team_id` rows without this workaround.
- The `ON DELETE CASCADE` on `team_id` ensures setup assistants are automatically removed when their associated team is deleted.
