Database migration that creates the `labels` table, which stores Fleet label definitions used for grouping and targeting hosts.

## Key Components

- **`Up_20161118212557`** — Creates the `labels` table with the following schema:
  - `id` — Auto-incrementing unsigned integer primary key
  - `created_at` / `updated_at` / `deleted_at` — Timestamp audit fields with soft-delete support
  - `deleted` — Boolean soft-delete flag
  - `name` — Required unique label name (indexed with `UNIQUE KEY` and `FULLTEXT` search)
  - `description` — Optional label description
  - `query` — Required osquery SQL query string associated with the label
  - `platform` — Optional platform filter (e.g., `darwin`, `linux`)
  - `label_type` — Unsigned integer defaulting to `fleet.LabelTypeBuiltIn`, distinguishing built-in from custom labels

- **`Down_20161118212557`** — Drops the `labels` table if it exists

## Usage Example

This migration is automatically registered via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20161118212557, Down_20161118212557)
}

// Apply migration
err := Up_20161118212557(tx)

// Rollback migration

```

## Notes

- The migration is **idempotent** (`CREATE TABLE IF NOT EXISTS`), so re-running it is safe
- Uses `InnoDB` engine with `utf8mb4_unicode_ci` collation for full Unicode support
- The `labels_search` `FULLTEXT` index enables efficient label name searches
- `label_type` defaults to `fleet.LabelTypeBuiltIn`, sourced from the [`fleet`](https://github.com/flamingo-stack/fleetmdm/blob/main/server/fleet) package constant
