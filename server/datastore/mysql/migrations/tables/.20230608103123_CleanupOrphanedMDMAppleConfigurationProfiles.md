Database migration that removes orphaned MDM Apple configuration profiles — records in `mdm_apple_configuration_profiles` that reference non-existent teams.

## Key Components

| Function | Description |
|----------|-------------|
| `Up_20230608103123` | Deletes configuration profiles where `team_id` references a team that no longer exists (excludes global profiles where `team_id = 0`) |
| `Down_20230608103123` | No-op rollback; deletion is not reversible |

## Migration Logic

The `UP` migration performs an idempotent `LEFT JOIN` delete:

```sql
DELETE macp
FROM mdm_apple_configuration_profiles macp
LEFT JOIN teams t ON t.id = macp.team_id
WHERE t.id IS NULL AND macp.team_id != 0
```

- Targets profiles where the referenced `team_id` has no matching row in `teams`
- Preserves global profiles (`team_id = 0`)
- Logs the number of affected rows via `logger.Info`

## Usage Example

This migration is registered automatically via `init()` and executed by the Fleet migration runner:

```go
func init() {
    MigrationClient.AddMigration(Up_20230608103123, Down_20230608103123)
}
```

No manual invocation is required. Run all pending migrations using the Fleet CLI:

```bash
fleet prepare db --config /etc/fleet/fleet.yml
```

## Notes

- **Idempotent**: Safe to run multiple times; subsequent runs will delete 0 rows
- **No rollback**: Orphaned profiles cannot be restored after deletion; `Down_` is intentionally a no-op
- **Scope**: Only affects team-scoped profiles (`team_id != 0`); global profiles are untouched
