Database migration that resets invalid `platform` values on the `labels` table to an empty string, retaining only the known-valid platforms.

## Key Components

| Function | Description |
|---|---|
| `Up_20260217141240` | Clears any `platform` values not in the allowed set (`''`, `centos`, `darwin`, `windows`, `ubuntu`) |
| `Down_20260217141240` | No-op — data loss from the `UP` migration is not reversible |

## Allowed Platform Values

After this migration runs, the `platform` column on `labels` will only contain:

```text
''        (empty / cross-platform)
centos
darwin
windows
ubuntu
```

## Usage Example

This migration is registered automatically via `init()` and executed by the Fleet migration runner:

```go
// Registered automatically — no manual invocation needed.
// The migration client picks it up at startup via:
MigrationClient.AddMigration(Up_20260217141240, Down_20260217141240)
```

To apply manually during development:

```bash
fleet prepare db --config /etc/fleet/fleet.yml
```

## Notes

- **Idempotent** — safe to re-run; repeated executions produce the same result since the `WHERE` clause only targets already-invalid rows.
- **No rollback** — `Down_20260217141240` is a no-op. Invalid platform strings are not stored for recovery.
