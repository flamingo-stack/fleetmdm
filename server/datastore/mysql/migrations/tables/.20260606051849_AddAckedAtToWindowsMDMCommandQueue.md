Database migration that adds an `acked_at` soft-dequeue marker column and supporting indexes to the `windows_mdm_command_queue` table, eliminating costly anti-join scans during Windows MDM command acknowledgment.

## Key Components

- **`Up_20260606051849`** — Applies the migration with three idempotent steps:
  1. Adds `acked_at DATETIME(6) NULL` column to `windows_mdm_command_queue`
  2. Creates composite index `idx_win_mdm_cmd_queue_enrollment_acked (enrollment_id, acked_at)` for hot-path pending probes (`WHERE enrollment_id = ? AND acked_at IS NULL`)
  3. Creates single-column index `idx_win_mdm_cmd_queue_acked (acked_at)` for GC range deletes (`WHERE acked_at < ?`)
  4. Backfills `acked_at` from `windows_mdm_command_results.created_at` for already-acknowledged rows to prevent re-delivery on the next session

- **`Down_20260606051849`** — No-op rollback (column and indexes are left in place)

## Performance Context

Before this migration, determining pending commands required an anti-join against `windows_mdm_command_results` per row. Under bulk profile push waves, this became the top writer bottleneck. Stamping `acked_at` at ack time converts the pending predicate to an index probe and the GC cleanup to an index range delete.

## Usage Example

This migration runs automatically via the migration client on startup:

```go
// Registered automatically via init()
MigrationClient.AddMigration(Up_20260606051849, Down_20260606051849)
```

To apply manually during development:

```bash
# Apply all pending migrations
fleet prepare db --config fleet.yml
```
