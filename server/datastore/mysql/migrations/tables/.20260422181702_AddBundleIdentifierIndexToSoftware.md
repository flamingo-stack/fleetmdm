Database migration that adds an index on `software.bundle_identifier` to optimize hourly FMA (Fleet Maintained Apps) sync queries, replacing full-table scans with indexed lookups.

## Key Components

- **`Up_20260422181702`** — Idempotent migration that conditionally adds `idx_software_bundle_identifier` on the `software` table if it does not already exist, using `indexExistsTx` to guard against re-application.
- **`Down_20260422181702`** — No-op rollback; the index is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Context

A previous migration (`20260326210603`) intentionally omitted this index, assuming `bundle_identifier`-based lookups would be infrequent. However, `UpsertMaintainedApp` runs hourly via cron and issues one `UPDATE software ... WHERE bundle_identifier = ?` per Darwin FMA entry (~224 full-table scans/hour), making the index necessary for production performance.

## Usage Example

This migration runs automatically via the Fleet schema migration pipeline. No manual invocation is needed. The guard clause makes it safe to run repeatedly:

```go
// Internal migration runner (simplified)
if err := Up_20260422181702(tx); err != nil {
    log.Fatalf("migration failed: %v", err)
}

// Equivalent DDL applied (only if index is absent):
// ALTER TABLE software ADD INDEX idx_software_bundle_identifier (bundle_identifier);
```
