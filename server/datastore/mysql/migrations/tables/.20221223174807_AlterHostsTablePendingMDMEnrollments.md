Database migration that modifies the `hosts` table to support pending MDM enrollments by making `osquery_host_id` nullable and adding a hardware serial index.

## Key Components

- **`Up_20221223174807`** — Applies two idempotent schema changes to the `hosts` table:
  - Modifies `osquery_host_id` to `VARCHAR(255) NULL` (utf8mb4), allowing hosts enrolled via MDM before osquery is present to have a null identifier
  - Adds `idx_hosts_hardware_serial` index on `hardware_serial` to enable efficient lookups by device serial number
- **`Down_20221223174807`** — No-op rollback; the changes are intentionally not reversed

## Usage Example

```bash
# Applied automatically by the Fleet migration runner on startup
# Manual execution via fleet CLI:
fleet prepare db --config /etc/fleet/fleet.yml
```

```go
// Migration registered automatically via init()
func init() {
    MigrationClient.AddMigration(Up_20221223174807, Down_20221223174807)
}
```

## Notes

- Both checks (`columnExists`, `indexExistsTx`) make this migration **safe to re-run** without errors
- Making `osquery_host_id` nullable is a prerequisite for MDM-enrolled hosts that have not yet bootstrapped the osquery agent
