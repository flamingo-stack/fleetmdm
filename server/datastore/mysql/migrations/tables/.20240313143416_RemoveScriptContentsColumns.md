Database migration that removes the `script_contents` column from the `scripts` and `host_script_results` tables.

## Key Components

- **`Up_20240313143416`** — Drops the `script_contents` column from both `scripts` and `host_script_results` tables. Uses `columnExists` checks to ensure the migration is idempotent (safe to run multiple times).
- **`Down_20240313143416`** — No-op rollback; the column removal is not reversed.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the Fleet migration client. No manual invocation is needed:

```bash
fleetctl prepare db --config /etc/fleet/fleet.yml
```

To verify the migration applied:

```sql
-- Confirm column no longer exists
SHOW COLUMNS FROM scripts;
SHOW COLUMNS FROM host_script_results;
```

## Notes

- **Idempotent**: Each `ALTER TABLE` is guarded by a `columnExists` check, so re-running will not error if the column was already dropped.
- **Irreversible**: `Down_20240313143416` is a no-op — rolling back this migration will not restore the `script_contents` column. Restore from backup if a rollback is needed.
- Script content storage was likely moved to a dedicated table or external reference prior to this migration.
