Database migration that adds LUKS-specific columns (`base64_encrypted_salt` and `key_slot`) to the `host_disk_encryption_keys` table to support Linux LUKS disk encryption metadata.

## Key Components

- **`Up_20241116233322`** — Idempotent migration that adds two columns to `host_disk_encryption_keys`:
  - `base64_encrypted_salt` — `VARCHAR(255)` (utf8mb4), stores the Base64-encoded encrypted LUKS salt, defaults to empty string
  - `key_slot` — `TINYINT UNSIGNED`, stores the LUKS key slot number, nullable
- **`Down_20241116233322`** — No-op rollback; columns are not removed on downgrade
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration is applied automatically by the Fleet migration runner. No manual invocation is required.

```go
// Migration is registered on package init and executed by the migration client:
MigrationClient.AddMigration(Up_20241116233322, Down_20241116233322)

// The Up function guards against re-applying with an idempotency check:
if !columnsExists(tx, "host_disk_encryption_keys", "base64_encrypted_salt", "key_slot") {
    // ALTER TABLE only runs if columns are absent
}
```

## Notes

- The migration is **idempotent** — safe to run multiple times; uses `columnsExists` to skip the `ALTER TABLE` if columns already exist
- The `Down` function is intentionally empty — this is a common pattern in Fleet where destructive rollbacks are avoided to prevent data loss
- Part of the broader Fleet MDM disk encryption feature set, extending support from macOS FileVault to Linux LUKS
