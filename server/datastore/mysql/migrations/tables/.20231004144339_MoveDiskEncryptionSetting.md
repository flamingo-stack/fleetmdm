Database migration that moves the `enable_disk_encryption` setting from `mdm.macos_settings` to the top-level `mdm` namespace in team configurations.

## Key Components

- **`Up_20231004144339`** — Migrates team config JSON by moving `$.mdm.macos_settings.enable_disk_encryption` to `$.mdm.enable_disk_encryption` using `JSON_SET` and `JSON_REMOVE`. Only affects rows where the nested key exists (idempotent).
- **`Down_20231004144339`** — No-op rollback; the migration is not reversible.

## Usage Example

This migration runs automatically via the `MigrationClient` on startup. To apply manually:

```bash
fleet prepare db --config fleet.yml
```

The underlying SQL executed during `Up`:

```sql
UPDATE teams
SET
    config = JSON_SET(config, '$.mdm.enable_disk_encryption',
                           JSON_EXTRACT(config, '$.mdm.macos_settings.enable_disk_encryption')),
    config = JSON_REMOVE(config, '$.mdm.macos_settings.enable_disk_encryption')
WHERE
    JSON_EXTRACT(config, '$.mdm.macos_settings.enable_disk_encryption') IS NOT NULL;
```

## Notes

- **Idempotent** — The `WHERE` clause ensures rows already migrated (where the source key is `NULL`) are skipped safely.
- **No rollback** — `Down` is a no-op; re-running a rollback will not restore the original nested path.
