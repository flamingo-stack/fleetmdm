Database migration that creates the `mdm_configuration_profile_labels` table, linking MDM configuration profiles (Apple or Windows) to Fleet labels for targeted profile deployment.

## Key Components

- **`Up_20240126020642`** — Creates the `mdm_configuration_profile_labels` table with cross-platform profile-to-label associations, including nullable `label_id` to represent a "broken" state when a label is deleted
- **`Down_20240126020642`** — No-op rollback (table is not dropped)

## Table Design Notes

| Field | Purpose |
|---|---|
| `apple_profile_uuid` / `windows_profile_uuid` | Mutually exclusive foreign keys to platform-specific profile tables |
| `label_name` | Persisted independently so deleted labels remain visible in the UI |
| `label_id` | Nullable; `NULL` signals a broken label association in the UI |

**Unique key strategy:** Two separate unique keys (`apple + label_name`, `windows + label_name`) are used instead of a single composite key because `NULL` values are not considered equal in MySQL unique indexes, which would allow duplicate rows for the same nullable UUID.

**CHECK constraint caveat:** The `ck_mdm_configuration_profile_labels_apple_or_windows` constraint enforcing mutual exclusivity is parsed but silently ignored on MySQL 5.7 — enforcement must be handled at the application layer.
