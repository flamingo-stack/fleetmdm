Database migration that adds a `policy_id` foreign key column to the `host_script_results` table, linking script executions to policies.

## Key Components

- **`Up_20241004005000`** — Idempotent migration that adds `policy_id INT UNSIGNED DEFAULT NULL` to `host_script_results` and creates a foreign key (`fk_script_result_policy_id`) referencing `policies(id)` with `ON DELETE SET NULL`
- **`Down_20241004005000`** — No-op rollback; column removal is left unimplemented
- **`init`** — Registers both migration functions with `MigrationClient`

## Notes

- **Idempotent**: Uses `columnExists` and `fkExists` guards so re-running the migration is safe
- **Cascade behavior**: Deleting a policy sets `policy_id` to `NULL` on related script results rather than deleting them
- The empty `Down` function means this migration cannot be automatically reversed — manual intervention is required to drop the column if needed
