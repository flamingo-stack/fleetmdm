Adds an `invite_id` column to the `users` database table via an idempotent schema migration.

## Key Components

- **`Up_20250528115932`** — Applies the migration: adds an unsigned integer `invite_id` column and a unique index to the `users` table. Both operations are guarded by existence checks, making the migration safe to re-run.
- **`Down_20250528115932`** — No-op rollback; the column addition is not reversed.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the `MigrationClient` during the application's schema upgrade process. No manual invocation is required.

```go
// Migration is registered on package init and executed by the migration runner:
MigrationClient.AddMigration(Up_20250528115932, Down_20250528115932)

// The Up function guards against duplicate execution:
if !columnExists(tx, "users", "invite_id") {
    tx.Exec("ALTER TABLE users ADD COLUMN invite_id int unsigned")
}
if !indexExistsTx(tx, "users", "invite_id") {
    tx.Exec("ALTER TABLE users ADD UNIQUE (invite_id)")
}
```

## Notes

- The `invite_id` column is nullable (`int unsigned` with no `NOT NULL` constraint), allowing existing users to remain unaffected.
- The unique constraint ensures one user per invite.
