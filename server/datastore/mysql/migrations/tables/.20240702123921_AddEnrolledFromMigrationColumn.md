Database migration that adds an `enrolled_from_migration` column to the `nano_enrollments` table, tracking whether a device enrollment originated from a migration process.

## Key Components

| Function | Description |
|---|---|
| `Up_20240702123921` | Idempotent migration that adds `enrolled_from_migration TINYINT(1) UNSIGNED NOT NULL DEFAULT '0'` column if it does not already exist |
| `Down_20240702123921` | No-op rollback; column removal is not performed |
| `init` | Registers both migration functions with `MigrationClient` |

## Behavior Notes

- **Idempotent**: Uses `columnExists()` guard before executing `ALTER TABLE`, making the migration safe to run multiple times without error
- **Default value**: New column defaults to `0` (false), meaning existing enrollments are not flagged as migration-sourced
- **Rollback**: Down migration is intentionally empty — dropping the column on rollback is omitted to avoid data loss

## Usage Example

This migration runs automatically via the `MigrationClient` during `fleet prepare db` or equivalent schema upgrade commands. No manual invocation is needed.

```go
// Manually invoking for testing purposes
db, _ := sql.Open("mysql", dsn)
tx, _ := db.Begin()

if err := Up_20240702123921(tx); err != nil {
    tx.Rollback()
    log.Fatal(err)
}
tx.Commit()
```
