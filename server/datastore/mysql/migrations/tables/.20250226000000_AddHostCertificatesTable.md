Database migration that creates the `host_certificates` table for storing TLS/X.509 certificate metadata associated with managed hosts.

## Key Components

- **`Up_20250226000000`** — Creates the `host_certificates` table using `CREATE TABLE IF NOT EXISTS` (idempotent). Stores certificate identity fields (subject/issuer DN components), validity window, cryptographic properties, and a SHA-1 fingerprint. Includes two secondary indexes to support lookups by host+common name and host+expiry date.
- **`Down_20250226000000`** — No-op rollback; the table is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Table Schema Highlights

| Column | Type | Notes |
|---|---|---|
| `host_id` | `INT UNSIGNED` | Foreign key to the host |
| `not_valid_before` / `not_valid_after` | `DATETIME(6)` | Certificate validity window |
| `certificate_authority` | `TINYINT(1)` | Boolean CA flag |
| `sha1_sum` | `BINARY(20)` | Certificate fingerprint |
| `deleted_at` | `DATETIME(6) NULL` | Soft-delete support |

## Usage Example

This migration runs automatically via the Fleet migration client. To apply it manually:

```bash
# Apply up migration
fleet prepare db --config /etc/fleet/fleet.yml

# Verify table creation
mysql -u fleet -p fleet -e "DESCRIBE host_certificates;"
```

```go
// Registration (handled automatically by init)
MigrationClient.AddMigration(Up_20250226000000, Down_20250226000000)
```
