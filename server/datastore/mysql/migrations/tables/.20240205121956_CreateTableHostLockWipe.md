Database migration that creates the `host_mdm_actions` table to track lock and wipe actions for managed hosts, separating this MDM action state from the existing enrollment-focused `host_mdm` table.

## Key Components

- **`Up_20240205121956`** — Creates the `host_mdm_actions` table (idempotent via `CREATE TABLE IF NOT EXISTS`) with the following columns:
  - `host_id` — Foreign reference to the host (primary key)
  - `lock_ref` — UUID of the lock action (MDM command or script execution)
  - `wipe_ref` — UUID of the wipe action (MDM command or script execution)
  - `suspended` — Boolean flag indicating whether further host actions are paused (true while lock/wipe is pending)
- **`Down_20240205121956`** — No-op rollback (table is left in place on downgrade)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client during database setup or upgrade:

```go
// Migrations are applied automatically by the MigrationClient.
// To run all pending migrations:
if err := MigrationClient.Up(db, ""); err != nil {
    log.Fatalf("migration failed: %v", err)
}
```

To inspect the resulting schema:

```sql
DESCRIBE host_mdm_actions;
-- host_id   | int unsigned | NO  | PRI | NULL  |
-- lock_ref  | varchar(36)  | YES |     | NULL  |
-- wipe_ref  | varchar(36)  | YES |     | NULL  |
-- suspended | tinyint(1)   | NO  |     | 0     |
```

## Notes

- The migration is **idempotent** — safe to run multiple times without error.
- `lock_ref` / `wipe_ref` may reference either MDM commands or script execution IDs depending on the host platform.
