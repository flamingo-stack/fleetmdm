Database migration that adds a virtual computed column `has_data` and a composite index to the `query_results` table to optimize query performance.

## Key Components

- **`Up_20260324223334`** — Applies the migration idempotently:
  - Adds `has_data` as a `VIRTUAL` generated column (`data IS NOT NULL`) if absent
  - Adds composite index `idx_query_id_has_data_host_id_last_fetched` on `(query_id, has_data, host_id, last_fetched)` if absent
- **`Down_20260324223334`** — No-op rollback (structural changes are left in place)
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration runs automatically via the migration client during schema upgrades. No manual invocation is required.

```go
// Migration is registered automatically on package import:
// MigrationClient.AddMigration(Up_20260324223334, Down_20260324223334)

// To apply manually in tests or tooling:
db, _ := sql.Open("mysql", dsn)
tx, _ := db.Begin()
if err := Up_20260324223334(tx); err != nil {
    tx.Rollback()
    log.Fatal(err)
}
tx.Commit()
```

## Notes

- The migration is **idempotent** — safe to run multiple times; both `columnExists` and `indexExistsTx` guard against duplicate DDL execution.
- The virtual column avoids storing redundant data while enabling the optimizer to use the composite index for filtered queries on `query_results`.
- The empty `Down` function means this migration is **irreversible** by design.
