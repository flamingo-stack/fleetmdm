Database migration that adds a `vpp_token_id` foreign key column to the `vpp_apps_teams` table, linking VPP app-team associations to a specific VPP token to support multi-token VPP configurations.

## Key Components

- **`Up_20240829170033`** — Idempotent migration that:
  1. Adds `vpp_token_id` (`UNSIGNED INT NOT NULL`) to `vpp_apps_teams` if not present
  2. Looks up the first available VPP token and associates all existing rows with it (handles single-token → multi-token migration)
  3. Cleans orphaned associations if no VPP token exists
  4. Adds a `FOREIGN KEY` constraint (`ON DELETE CASCADE`) referencing `vpp_tokens(id)` if not already present
- **`Down_20240829170033`** — No-op rollback

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20240829170033, Down_20240829170033)
}
```

Migration behavior at runtime:

```text
vpp_apps_teams (before)          vpp_apps_teams (after)
─────────────────────            ───────────────────────────────────────
app_id | team_id                 app_id | team_id | vpp_token_id (FK)
```

## Notes

- **Idempotent**: Both the column addition and FK constraint are guarded by `columnExists` / `fkExists` checks, making the migration safe to re-run.
- **Single-to-multi token upgrade**: Existing rows are bulk-updated to the first token found in `vpp_tokens`. If no token exists, orphaned rows are deleted rather than left with an invalid `vpp_token_id = 0`.
