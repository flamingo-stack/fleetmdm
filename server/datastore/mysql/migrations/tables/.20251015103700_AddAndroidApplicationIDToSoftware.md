Database migration that adds an `application_id` column to the `software_titles` and `software` tables to support Android application identification, and updates the `unique_identifier` generated column to incorporate the new field.

## Key Components

- **`Up_20251015103700`** — Applies the migration with the following idempotent steps:
  1. Adds `application_id VARCHAR(255)` to `software_titles` (if not exists)
  2. Adds `application_id VARCHAR(255)` to `software` (if not exists)
  3. Drops the `idx_unique_sw_titles` unique index (if exists)
  4. Drops and recreates `unique_identifier` as a virtual generated column using `COALESCE(bundle_identifier, application_id, name)`
  5. Recreates `idx_unique_sw_titles` unique index on `(unique_identifier, source, extension_for)`

- **`Down_20251015103700`** — No-op rollback (returns `nil`)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20251015103700, Down_20251015103700)
}

// Manually applying (for testing/debugging)
err := Up_20251015103700(tx)
if err != nil {
    log.Fatalf("migration failed: %v", err)
}
```

## Notes

- All steps are **idempotent** — safe to re-run if a previous attempt partially succeeded.
- The `unique_identifier` virtual column priority order is: `bundle_identifier` → `application_id` → `name`, enabling unified deduplication across iOS, Android, and traditional software sources.
