Database migration that creates the `certificate_authorities` table and migrates existing CA configurations (DigiCert, NDES SCEP Proxy, Custom SCEP Proxy) from legacy `app_config_json` and `ca_config_assets` storage into the new normalized table.

## Key Components

- **`LegacyIntegrationsWithCertAuthorities`** — Struct representing the pre-migration integrations JSON shape, used to deserialize existing `app_config_json` data during migration.
- **`dbCertificateAuthority`** — Internal struct embedding `fleet.CertificateAuthority` with additional encrypted byte fields (`api_token_encrypted`, `password_encrypted`, `challenge_encrypted`, `client_secret_encrypted`) mapped to DB columns.
- **`Up_20250904091745`** — Creates the `certificate_authorities` table, adds a unique composite index on `(type, name)`, reads legacy CA config from `app_config_json` and `ca_config_assets`/`mdm_config_assets`, inserts migrated rows, then removes the migrated keys from `app_config_json`.
- **`Down_20250904091745`** — No-op rollback (table drop not implemented).

## Table Schema Summary

```text
certificate_authorities
├── id           INT AUTO_INCREMENT PK
├── type         ENUM('digicert','ndes_scep_proxy','custom_scep_proxy','hydrant')
├── name         VARCHAR(255)
├── url          TEXT
├── api_token_encrypted, profile_id, certificate_*  -- DigiCert fields
├── admin_url, username, password_encrypted          -- NDES fields
├── challenge_encrypted                              -- Custom SCEP fields
├── client_id, client_secret_encrypted              -- Hydrant fields
└── created_at, updated_at TIMESTAMP
```

## Usage Example

This migration runs automatically via the `MigrationClient` registered in `init()`. It is idempotent due to `CREATE TABLE IF NOT EXISTS` and `INSERT IGNORE`.

```go
// Migration is registered and executed by the migration runner
MigrationClient.AddMigration(Up_20250904091745, Down_20250904091745)
```
