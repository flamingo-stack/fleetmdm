Database migration that creates the `host_mdm_apple_awaiting_configuration` table, tracking which Apple MDM hosts are pending initial configuration setup.

## Key Components

- **`Up_20241025141855`** — Creates the `host_mdm_apple_awaiting_configuration` table using `IF NOT EXISTS` (idempotent). Stores a per-host boolean flag indicating whether the host is awaiting MDM configuration.
- **`Down_20241025141855`** — No-op rollback; table removal is not implemented.
- **`init`** — Registers both migration functions with `MigrationClient`.

### Table Schema: `host_mdm_apple_awaiting_configuration`

| Column | Type | Notes |
|---|---|---|
| `host_uuid` | `VARCHAR(255)` | Primary key |
| `awaiting_configuration` | `TINYINT(1)` | Defaults to `FALSE` |

Charset: `utf8mb4` / `utf8mb4_unicode_ci`

## Usage Example

This migration is applied automatically by the migration client at startup. No direct invocation is needed, but it can be exercised manually:

```go
db, _ := sql.Open("mysql", dsn)
tx, _ := db.Begin()

if err := Up_20241025141855(tx); err != nil {
    tx.Rollback()
    log.Fatal(err)
}
tx.Commit()
```

## Notes

- The migration is **idempotent** — safe to run multiple times without error.
- The down migration is intentionally a no-op; dropping this table in a rollback scenario requires a manual operation.
- See related migrations and table usage in [`server/datastore/mysql/migrations/tables/`](https://github.com/flamingo-stack/fleetmdm/blob/main/server/datastore/mysql/migrations/tables/).
