Database migration that enforces uniform UTF8MB4 collation (`utf8mb4_unicode_ci`) across all Fleet MySQL tables, including deduplication of software, host users, and operating system records that become duplicates when compared under the new collation.

## Key Components

| Function | Description |
|---|---|
| `Up_20230315104937` | Migration entry point; calls `changeCollation` to apply uniform collation |
| `Down_20230315104937` | Rollback function (no-op or reverse collation change) |
| `changeCollation` | Alters database and all table charsets/collations; handles special cases for `hosts` and `enroll_secrets` |
| `fixupSoftware` | Detects and removes duplicate rows in `software`, `software_cve`, `software_host_counts`, and `host_software` |
| `fixupHostUsers` | Detects and removes duplicate rows in `host_users` using collation-aware grouping |
| `fixupOS` | Detects and removes duplicate rows in `operating_systems` using collation-aware grouping |

## Usage Example

This migration runs automatically via the `MigrationClient`:

```go
// Registered in init(); executed by the migration runner
MigrationClient.AddMigration(Up_20230315104937, Down_20230315104937)
```

To skip collation changes during testing:

```bash
export FLEET_TEST_DISABLE_COLLATION_UPDATES=1
```

## Notes

- **Deduplication order matters**: `fixupSoftware`, `fixupHostUsers`, and `fixupOS` run before `ALTER TABLE` to avoid unique-constraint violations after collation normalization.
- **Foreign key checks** are temporarily disabled during table alterations and re-enabled via `defer`.
- The `hosts` table receives column-level `MODIFY` statements rather than a blanket `CONVERT TO`, preserving specific collations on `node_key` and `orbit_node_key`.
- Sort buffer size is increased to `2,560,000,000` bytes for the session during software deduplication to handle large datasets.
