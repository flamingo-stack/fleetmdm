Database migration that adds a `canceled` boolean column to activity-tracking tables and updates computed status enums to include cancellation states.

## Key Components

- **`Up_20250331154206`** — Idempotent migration that adds a `canceled TINYINT(1) NOT NULL DEFAULT '0'` column to three tables and updates generated status columns in `host_software_installs`
- **`Down_20250331154206`** — No-op rollback (column removal is not reversed)
- **`columnExists` guard** — Wraps each `ALTER TABLE` to prevent duplicate-column errors on re-runs

## Affected Tables

| Table | Change |
|---|---|
| `host_script_results` | Adds `canceled` column |
| `host_vpp_software_installs` | Adds `canceled` column |
| `host_software_installs` | Adds `canceled` column + rewrites `execution_status` (VIRTUAL) and `status` (STORED) generated enum columns |

## Updated Enum States

The `execution_status` and `status` generated columns on `host_software_installs` are extended with two new values:

```text
ENUM(
  'pending_install',
  'failed_install',
  'installed',
  'pending_uninstall',
  'failed_uninstall',
  'canceled_install',   -- NEW: canceled=1 AND uninstall=0
  'canceled_uninstall'  -- NEW: canceled=1 AND uninstall=1
)
```

Cancellation is evaluated first in the `CASE` expression, before exit-code or install-state checks.
