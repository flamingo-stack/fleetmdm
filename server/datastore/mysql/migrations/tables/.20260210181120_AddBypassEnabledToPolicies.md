Adds a database migration that introduces the `conditional_access_bypass_enabled` column to the `policies` table.

## Key Components

- **`Up_20260210181120`** — Idempotent migration that adds a `TINYINT(1) NOT NULL DEFAULT 1` column named `conditional_access_bypass_enabled` to the `policies` table. Skips execution if the column already exists.
- **`Down_20260210181120`** — No-op rollback; the column is not removed on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the `MigrationClient` during database schema upgrades. No manual invocation is required.

```go
// Migration is registered on package init and applied by the migration runner:
MigrationClient.AddMigration(Up_20260210181120, Down_20260210181120)
```

To apply manually during development:

```bash
fleet prepare db --config /etc/fleet/fleet.yml
```

## Notes

- **Default value `1`** means bypass is enabled for all existing policies after migration.
- The idempotency check (`columnExists`) ensures safe re-runs without errors.
- The empty `Down` function means this migration is **not reversible** — dropping the column must be handled manually if needed.
