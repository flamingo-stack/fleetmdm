Database migration that creates the `mdm_idp_accounts` table for storing MDM Identity Provider account credentials with password hashing fields.

## Key Components

- **`Up_20230303135738`** — Creates the `mdm_idp_accounts` table (idempotent via `CREATE TABLE IF NOT EXISTS`) with the following schema:

| Column | Type | Description |
|---|---|---|
| `uuid` | `varchar(255)` | Primary key, unique account identifier |
| `username` | `varchar(255)` | IdP account username |
| `salt` | `varchar(255)` | Password hash salt |
| `entropy` | `varchar(255)` | Additional entropy for hashing |
| `iterations` | `int unsigned` | Hash iteration count (e.g. PBKDF2) |

- **`Down_20230303135738`** — No-op rollback; table is left in place on downgrade.

## Usage Example

```go

// The migration client applies pending migrations in order:
MigrationClient.AddMigration(Up_20230303135738, Down_20230303135738)
```

## Notes

- Table uses `InnoDB` engine with `utf8mb4_unicode_ci` collation for full Unicode support.
- The `salt`, `entropy`, and `iterations` fields suggest a [PBKDF2](https://en.wikipedia.org/wiki/PBKDF2)-style key derivation scheme.
- Rollback is intentionally a no-op — dropping credential tables on downgrade would cause data loss.
