Database migration that adds a `user_email` column to the `activities` table and backfills it from the `users` table.

## Key Components

| Function | Description |
|---|---|
| `Up_20231109115838` | Adds `user_email VARCHAR(255) NOT NULL DEFAULT ''` to `activities` and backfills existing rows via an `INNER JOIN` on `users.id` |
| `Down_20231109115838` | No-op rollback (column removal not implemented) |

The migration is **idempotent** — it checks for column existence via `columnExists` before applying the `ALTER TABLE`, making it safe to re-run.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20231109115838, Down_20231109115838)

// Up migration logic (condensed)
if !columnExists(tx, "activities", "user_email") {
    // 1. Add column with safe default
    tx.Exec(`ALTER TABLE activities ADD COLUMN user_email varchar(255) NOT NULL DEFAULT ''`)

    // 2. Backfill from users table
    tx.Exec(`
        UPDATE activities t1
        INNER JOIN users t2 ON t1.user_id = t2.id
        SET t1.user_email = t2.email
    `)
}
```

> **Note:** The rollback (`Down`) is intentionally empty. If a destructive rollback is needed, `ALTER TABLE activities DROP COLUMN user_email` must be added manually.
