Database migration that adds ACME protocol support tables and renames legacy SCEP depot tables to generic identity tables, while also adding a `hardware_attested` column to `nano_enrollments`.

## Key Components

### `Up_20260401153000(tx *sql.Tx) error`
Idempotent up migration performing the following steps:
- Adds `hardware_attested TINYINT(1)` column to `nano_enrollments` (if not already present)
- Renames `scep_serials` → `identity_serials` (if exists)
- Renames `scep_certificates` → `identity_certificates` (if exists)
- Creates five new ACME tables (using `CREATE TABLE IF NOT EXISTS`):

| Table | Purpose |
|---|---|
| `acme_enrollments` | Root enrollment record keyed by `path_identifier` |
| `acme_accounts` | JWK-based accounts linked to an enrollment |
| `acme_orders` | Certificate orders with CSR, status, and issued serial |
| `acme_authorizations` | Per-identifier authorizations for an order |
| `acme_challenges` | Challenge tokens and types for each authorization |

### `Down_20260401153000(tx *sql.Tx) error`
No-op rollback — the migration is intentionally irreversible.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20260401153000, Down_20260401153000)
}

// Run all pending migrations
err := MigrationClient.Up(db, 0)
if err != nil {
    log.Fatal(err)
}
```

## Notes

- All table renames and column additions are guarded by `tableExists`/`columnExists` checks, making the migration safe to re-run.
- ACME tables use cascading foreign keys (`ON DELETE CASCADE ON UPDATE CASCADE`) to maintain referential integrity across the enrollment → account → order → authorization → challenge hierarchy.
