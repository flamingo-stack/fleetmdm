Database migration (2022-10-14) that creates the `host_orbit_info` table for storing Orbit agent version information per host.

## Key Components

- **`Up_20221014084130`** — Creates the `host_orbit_info` table with `host_id` (primary key) and `version` columns, plus an index on `version`. Uses `CREATE TABLE IF NOT EXISTS` for idempotency.
- **`Down_20221014084130`** — No-op rollback; table removal is not implemented.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Schema

```text
host_orbit_info
├── host_id  INT(10) UNSIGNED NOT NULL  [PRIMARY KEY]
└── version  VARCHAR(50) NOT NULL       [INDEX: idx_host_orbit_info_version]
```

## Usage Example

This migration is applied automatically by the Fleet migration runner. To run manually during development:

```go
// Applied via MigrationClient — no direct invocation needed.

err := Up_20221014084130(tx)
```

## Notes

- Engine: `InnoDB`, charset: `utf8mb4` (`utf8mb4_unicode_ci`)
- The index on `version` supports efficient fleet-wide queries filtering hosts by Orbit version (e.g., finding outdated agents)
- The down migration is intentionally a no-op; dropping the table requires a manual step
