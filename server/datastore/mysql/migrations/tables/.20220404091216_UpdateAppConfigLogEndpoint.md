Database migration that updates the osquery log endpoint path in the app configuration JSON, replacing the legacy `/api/v1/osquery/log` path with the new `/api/osquery/log` path.

## Key Components

- **`Up_20220404091216(tx *sql.Tx) error`** — Idempotent migration that reads the current `app_config_json`, finds any occurrences of `/api/v1/osquery/log` within `agent_options`, replaces them with `/api/osquery/log`, and writes the updated config back. Skips execution if no rows exist or if no replacement is needed.
- **`Down_20220404091216(tx *sql.Tx) error`** — No-op rollback; the path change is not reversed.
- **`init()`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the migration client. No manual invocation is required.

```go
// Registered automatically on package import via init()
MigrationClient.AddMigration(Up_20220404091216, Down_20220404091216)
```

The core replacement logic operates at the raw JSON byte level, making it safe across varying config structures:

```go
oldPath = []byte(`"/api/v1/osquery/log"`)
newPath = []byte(`"/api/osquery/log"`)
newOpts := json.RawMessage(bytes.ReplaceAll(oldOpts, oldPath, newPath))
```

> **Note:** The migration is idempotent — if the old path is not present in `agent_options`, the database write is skipped entirely.
