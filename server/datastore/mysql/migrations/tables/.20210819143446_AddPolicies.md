Database migration (2021-08-19) that creates the `policies` table, `policy_membership_history` table, and `policy_membership` view to support policy compliance tracking for hosts.

## Key Components

- **`Up_20210819143446`** — Applies the migration, creating three database objects:
  - `policies` — Stores policy definitions linked to queries via a foreign key to the `queries` table.
  - `policy_membership_history` — Tracks historical pass/fail compliance results per host and policy, with cascading deletes and indexed columns for query performance.
  - `policy_membership` (view) — A virtual view over `policy_membership_history` that surfaces only the latest record per `(host_id, policy_id)` pair.
- **`Down_20210819143446`** — No-op rollback (tables/views are not dropped on downgrade).

## Schema Overview

```text
policies
  id (PK), query_id (FK → queries.id), created_at, updated_at

policy_membership_history
  id (PK), policy_id (FK → policies.id CASCADE), host_id (FK → hosts.id CASCADE),
  passes (BOOL), created_at, updated_at
  INDEX: passes, policy_id, (host_id, passes)

policy_membership (VIEW)
  Latest row per (host_id, policy_id) from policy_membership_history
```
