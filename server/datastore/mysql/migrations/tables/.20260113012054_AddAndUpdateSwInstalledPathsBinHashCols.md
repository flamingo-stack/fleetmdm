Database migration that adds `executable_sha256` and `executable_path` columns to the `host_software_installed_paths` table, and renames the existing `executable_sha256` column to `cdhash_sha256`.

## Key Components

- **`Up_20260113012054`** — Idempotent up migration that performs two sequential schema changes:
  1. Renames `executable_sha256` → `cdhash_sha256` (nullable `CHAR(64)`) if the new column name does not yet exist
  2. Adds `executable_sha256` and `executable_path` columns if neither is present
- **`Down_20260113012054`** — No-op rollback; schema changes are not reversed
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration is applied automatically by the Fleet migration runner. To apply manually:

```bash
fleet prepare db --config /etc/fleet/fleet.yml
```

To verify the resulting schema:

```sql
DESCRIBE host_software_installed_paths;
-- Expected new columns:
-- cdhash_sha256    CHAR(64) NULL   (renamed from executable_sha256)
-- executable_sha256 CHAR(64) NULL  (new)
-- executable_path   TEXT     NULL  (new)
```

## Notes

- The migration is **idempotent** — safe to run multiple times; `columnExists` / `columnsExists` guards prevent duplicate `ALTER TABLE` errors
- `Down_20260113012054` is a no-op, so this migration is **irreversible** via rollback
