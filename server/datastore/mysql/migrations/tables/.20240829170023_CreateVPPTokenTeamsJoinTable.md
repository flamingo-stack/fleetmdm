Database migration that creates the `vpp_token_teams` join table, establishing a many-to-many relationship between VPP tokens and teams while migrating existing team association data from the `vpp_tokens` table.

## Key Components

| Symbol | Description |
|---|---|
| `Up_20240829170023` | Forward migration: creates `vpp_token_teams`, migrates data, and drops legacy columns from `vpp_tokens` |
| `Down_20240829170023` | Reverse migration (no-op) |

## Schema Created

```sql
CREATE TABLE vpp_token_teams (
    id              int unsigned NOT NULL PRIMARY KEY AUTO_INCREMENT,
    vpp_token_id    int unsigned NOT NULL,  -- FK → vpp_tokens(id)
    team_id         int unsigned,           -- FK → teams(id), nullable
    null_team_type  enum('none','allteams','noteam') DEFAULT 'none'
)
```

**Constraints:**
- `UNIQUE KEY` on `team_id` — one token per team (partial; "No team"/"All teams" enforced in Go)
- `ON DELETE CASCADE` for both foreign keys

## Migration Steps

The `Up` function is fully idempotent and runs these steps safely:

1. **Create** `vpp_token_teams` with `IF NOT EXISTS`
2. **Migrate** existing `team_id` / `null_team_type` rows from `vpp_tokens` using `INSERT IGNORE` (only if column exists)
3. **Drop** foreign key `fk_vpp_tokens_team_id` (if exists)
4. **Drop** index `idx_vpp_tokens_team_id` (if exists)
5. **Drop** columns `team_id` and `null_team_type` from `vpp_tokens` (if exist)
