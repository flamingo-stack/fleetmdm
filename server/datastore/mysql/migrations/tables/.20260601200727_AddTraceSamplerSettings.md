Database migration that creates the `trace_sampler_settings` table, a singleton row holding runtime-tunable trace sampling configuration for the Fleet MDM debug subsystem.

## Key Components

| Symbol | Description |
|---|---|
| `Up_20260601200727` | Creates the `trace_sampler_settings` table and inserts the seed singleton row |
| `Down_20260601200727` | No-op rollback (table drop is intentionally omitted) |

### `trace_sampler_settings` Schema

| Column | Type | Default | Description |
|---|---|---|---|
| `id` | `TINYINT UNSIGNED PK` | — | Singleton enforced via `CHECK (id = 1)` |
| `high_volume_ratio` | `DOUBLE` | `0.001` | Sampling ratio for high-volume traces (0–1) |
| `standard_ratio` | `DOUBLE` | `0.02` | Sampling ratio for standard traces (0–1) |
| `force_full` | `TINYINT(1)` | `0` | Boolean flag to force 100% sampling |
| `updated_at` | `TIMESTAMP` | auto-updated | Last modification time |

## Usage Example

This migration runs automatically via the migration client at startup:

```go
// Registered automatically via init()
MigrationClient.AddMigration(Up_20260601200727, Down_20260601200727)
```

Operators tune sampling at runtime via the API — no migration re-run required:

```bash
# Lower standard sampling ratio to 1%
curl -X PATCH /debug/trace_sampler \
  -d '{"standard_ratio": 0.01}'
```

## Design Notes

- **Idempotent** — uses `CREATE TABLE IF NOT EXISTS` and `INSERT IGNORE`, safe to re-run.
- **Fixed `updated_at` seed value** (`2026-06-01 00:00:00`) ensures `make test-schema` produces a deterministic schema dump across all developer environments.
- **Constraint-enforced singleton** — the `CHECK (id = 1)` constraint prevents accidental multi-row inserts.
