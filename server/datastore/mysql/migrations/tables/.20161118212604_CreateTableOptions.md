Database migration that creates the `options` table for storing configurable key-value settings with typed values and read-only protection.

## Key Components

- **`Up_20161118212604`** — Creates the `options` table with the following schema:
  - `id` — Auto-incrementing unsigned integer primary key
  - `name` — Unique VARCHAR(255) identifier for the option
  - `type` — Unsigned integer representing the option's data type
  - `value` — VARCHAR(255) storing the option's value
  - `read_only` — Boolean flag (default `false`) to protect system options
- **`Down_20161118212604`** — Drops the `options` table if it exists
- **`init()`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration is applied automatically by the migration client. To run manually:

```go
// Applied via the migration runner — not called directly.
// The init() function registers it at package load time:
import _ "github.com/flamingo-stack/fleetmdm/db/migrations/tables"

// Migration runner applies Up/Down based on target version:
// Up:   creates the `options` table (idempotent — uses CREATE TABLE IF NOT EXISTS)
// Down: drops the `options` table (safe — uses DROP TABLE IF EXISTS)
```

## Notes

- Migration is **idempotent**: `CREATE TABLE IF NOT EXISTS` prevents errors on re-run
- Uses `InnoDB` engine with `utf8` charset for full transaction support
- The unique index `idx_option_unique_name` enforces option name uniqueness at the database level
