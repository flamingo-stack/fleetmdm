Database migration that updates the `software_host_counts` table to add team-based software tracking by introducing a `team_id` column and restructuring the primary key and indexes.

## Key Components

- **`Up_20220223113157`** — Idempotent migration that modifies `software_host_counts` with three conditional paths:
  1. **Already migrated** — Detects `team_id` in the primary key via `INFORMATION_SCHEMA.STATISTICS` and skips.
  2. **Column missing** — Adds `team_id INT UNSIGNED NOT NULL DEFAULT 0`, rebuilds the primary key as `(software_id, team_id)`, adds `idx_software_host_counts_team_id_hosts_count_software_id`, and drops `idx_software_host_counts_host_count_software_id`.
  3. **Column exists, indexes inconsistent** — Individually adds/drops indexes to reach the target state.
- **`Down_20220223113157`** — No-op rollback; schema changes are not reversed.

## Schema Changes

| Change | Detail |
|---|---|
| New column | `team_id INT(10) UNSIGNED NOT NULL DEFAULT 0` |
| New primary key | `(software_id, team_id)` |
| New index | `idx_software_host_counts_team_id_hosts_count_software_id (team_id, hosts_count, software_id)` |
| Dropped index | `idx_software_host_counts_host_count_software_id` |

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:
