Database migration that adds the `enable_turn_on_windows_mdm_manually` field to the MDM section of the application configuration JSON, defaulting it to `false`.

## Key Components

- **`Up_20251117020200`** — Reads the current `app_config_json` record, unmarshals it, injects `enable_turn_on_windows_mdm_manually: false` into the `mdm` sub-object, and writes the updated JSON back. The migration is idempotent and safely exits if no config row exists.
- **`Down_20251117020200`** — No-op rollback; the field addition is considered non-destructive and is not reversed.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Applied automatically by the migration runner on startup.
// Equivalent manual SQL effect:
// UPDATE app_config_json
// SET json_value = JSON_SET(json_value, '$.mdm.enable_turn_on_windows_mdm_manually', false)
// WHERE id = 1;
```

## Notes

- Targets the `app_config_json` table, which stores the Fleet app config as a single JSON blob.
- Gracefully handles a missing row (`sql.ErrNoRows`) by returning `nil`, making it safe on fresh installs.
- Returns an error if the `mdm` key is absent or not a JSON object, preventing silent corruption of the config.
