Database migration that creates the `host_mdm_apple_bootstrap_packages` table and adds timestamp columns to `mdm_apple_bootstrap_packages` for tracking Apple MDM bootstrap package installations per host.

## Key Components

- **`Up_20230411102858`** — Applies the migration with two idempotent steps:
  1. Creates `host_mdm_apple_bootstrap_packages` table linking host UUIDs to MDM command UUIDs (with a `CASCADE` foreign key to `nano_commands`)
  2. Adds `created_at` and `updated_at` timestamp columns to the existing `mdm_apple_bootstrap_packages` table (guarded by `columnsExists` check)
- **`Down_20230411102858`** — No-op rollback (returns `nil`)

## Schema Changes

```text
host_mdm_apple_bootstrap_packages
├── host_uuid    VARCHAR(127)  PRIMARY KEY
└── command_uuid VARCHAR(127)  FK → nano_commands(command_uuid) ON DELETE CASCADE

mdm_apple_bootstrap_packages (altered)
├── created_at   DATETIME  DEFAULT CURRENT_TIMESTAMP
└── updated_at   DATETIME  DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

## Usage Example

This migration runs automatically via the `MigrationClient` on application startup:

```go
// Registered in init(), applied by the migration runner:
MigrationClient.AddMigration(Up_20230411102858, Down_20230411102858)
```

To apply manually during development:

```bash
fleet prepare db --config /path/to/config.yml
```

> **Note:** Both operations are idempotent — `CREATE TABLE IF NOT EXISTS` and the `columnsExists` guard ensure safe re-runs without errors.
