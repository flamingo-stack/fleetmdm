Database migration that adds a `name` column to the `host_certificate_templates` table and backfills it from the related `certificate_templates` table.

## Key Components

- **`Up_20251217000000`** — Idempotent migration that:
  1. Adds a `name VARCHAR(255)` column (utf8mb4) to `host_certificate_templates` if it does not already exist
  2. Backfills the new column by joining `host_certificate_templates` with `certificate_templates` on `certificate_template_id`
- **`Down_20251217000000`** — No-op rollback (column removal is not performed)
- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration is applied automatically by the Fleet migration runner. No manual invocation is required.

```go
// Migration is registered on package init and executed by the migration client:
MigrationClient.AddMigration(Up_20251217000000, Down_20251217000000)
```

To apply manually during development:

```bash
fleetctl prepare db --config /etc/fleet/fleet.yml
```

## Notes

- The `Up` function is **idempotent**: it checks for column existence via `columnExists` before issuing `ALTER TABLE`, making it safe to re-run.
- The backfill `UPDATE` runs unconditionally on every `Up` execution, which is safe because it only sets values that already match the join condition.
- The `Down` migration is intentionally empty; restoring the previous schema state requires a separate migration if needed.
