Database migration that creates the `host_updates` table for tracking per-host software update timestamps.

## Key Components

- **`Up_20221227163856`** — Creates the `host_updates` table with `host_id` (primary key) and a nullable `software_updated_at` timestamp column. The migration is idempotent via `CREATE TABLE IF NOT EXISTS`.
- **`Down_20221227163856`** — No-op rollback; the table is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Schema

```text
host_updates
├── host_id              INT UNSIGNED  NOT NULL  PRIMARY KEY
└── software_updated_at  TIMESTAMP     NULL
```

The `software_updated_at` column is nullable to allow future extension with additional update-related columns without breaking existing rows.

## Usage Example

## Notes

- **Idempotent** — Safe to re-run; `IF NOT EXISTS` prevents duplicate table errors.
- **Extensible** — Nullable timestamp column signals intent to add more update-tracking columns (e.g., `os_updated_at`) without a schema change to existing rows.
