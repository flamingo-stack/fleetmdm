Database migration that adds a unique MD5 checksum column (`checksum`) to the `software` table for deduplication of software entries.

## Key Components

- **`Up_20231212094238`** — Idempotent migration that:
  - Adds a `BINARY(16)` `checksum` column (stores MD5 hashes via `UNHEX(MD5(...))`)
  - Backfills checksums for existing rows by hashing a `CHAR(0)`-separated concatenation of: `name`, `version`, `source`, `bundle_identifier`, `release`, `arch`, `vendor`, `browser`, `extension_id`
  - Alters the column to `NOT NULL` and adds a unique index (`idx_software_checksum`)
  - If the column already exists, ensures the unique index is present
- **`Down_20231212094238`** — No-op rollback (index/column are left in place)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20231212094238, Down_20231212094238)
}
```

## Notes

- **MD5 is used intentionally** for deduplication only — not for any security purpose. Malicious hash collisions in this context are low-risk since input comes from osquery-extracted data.
- The checksum computation order (columns and separator `\x00`) must remain consistent with `mysql.softwareChecksumComputedColumn` used elsewhere in the codebase.
- The migration is **idempotent**: it checks for column/index existence before applying changes, making it safe to re-run.
