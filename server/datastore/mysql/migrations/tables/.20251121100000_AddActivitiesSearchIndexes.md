Adds database indexes to support efficient search and filtering on the `activities` and `users` tables.

## Key Components

- **`Up_20251121100000`** — Idempotently creates five indexes:
  - `idx_activities_user_name` on `activities(user_name)`
  - `idx_activities_user_email` on `activities(user_email)`
  - `idx_activities_activity_type` on `activities(activity_type)`
  - `idx_activities_type_created` on `activities(activity_type, created_at)` — composite for type-filtered time-range queries
  - `idx_users_name` on `users(name)`
- **`Down_20251121100000`** — No-op rollback; indexes are left in place on downgrade.
- **`init`** — Registers the migration with `MigrationClient`.

## Usage Example

This migration runs automatically via the migration client. To apply manually during development:

```go
db, _ := sql.Open("mysql", dsn)
tx, _ := db.Begin()

if err := Up_20251121100000(tx); err != nil {
    tx.Rollback()
    log.Fatal(err)
}
tx.Commit()
```

## Notes

- Each index creation is guarded by `indexExistsTx`, making the migration safe to re-run without errors.
- The composite index `idx_activities_type_created` benefits queries that filter by `activity_type` and sort or filter by `created_at`.
- The rollback is intentionally a no-op — dropping indexes on downgrade could degrade performance on a live system unexpectedly.
