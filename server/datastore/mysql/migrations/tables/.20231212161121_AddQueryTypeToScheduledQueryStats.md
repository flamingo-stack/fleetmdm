Database migration that adds a `query_type` column to the `scheduled_query_stats` table and updates its primary key to include the new column.

## Key Components

- **`Up_20231212161121`** — Idempotent up migration that:
  1. Adds `query_type TINYINT NOT NULL DEFAULT 0` column if absent
  2. Checks `INFORMATION_SCHEMA.STATISTICS` to verify `query_type` is not already part of the primary key
  3. Drops the existing primary key and recreates it as `(host_id, scheduled_query_id, query_type)`
- **`Down_20231212161121`** — No-op rollback (commented-out DDL shows the intended reversal steps)
- **`init()`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration is automatically applied by the Fleet migration runner. No direct invocation is needed. To run all pending migrations:

```bash
fleetctl prepare db
```

To verify the schema change after migration:

```sql
DESCRIBE scheduled_query_stats;

SELECT COLUMN_NAME, SEQ_IN_INDEX
FROM INFORMATION_SCHEMA.STATISTICS
WHERE TABLE_NAME = 'scheduled_query_stats'
  AND INDEX_NAME = 'PRIMARY';
```

## Notes

- The migration is fully **idempotent** — safe to run multiple times without error
- `query_type` defaults to `0`, preserving existing row semantics
- The rollback (`Down`) is intentionally a no-op; the commented DDL serves as documentation only
