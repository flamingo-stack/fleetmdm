Database migration that adds uninstall package support to the `software_installers` and `host_software_installs` tables, including new columns for uninstall scripts, file extensions, and a computed installation status field.

## Key Components

- **`Up_20240905200000`** — Forward migration that:
  - Adds `package_ids`, `extension`, `uninstall_script_content_id`, and `updated_at` columns to `software_installers`
  - Seeds placeholder uninstall scripts for Linux/macOS and Windows platforms (replaced later by a cron job)
  - Backfills `extension` from filenames and aligns `updated_at` with `uploaded_at`
  - Adds a foreign key from `uninstall_script_content_id` → `script_contents.id`
  - Adds `uninstall_script_output`, `uninstall_script_exit_code`, `uninstall`, and a computed `status` enum column to `host_software_installs`
- **`getOrInsertScript`** — Upserts a script into `script_contents` by MD5 checksum; returns the existing or newly created row ID
- **`Down_20240905200000`** — No-op rollback (intentionally empty)
- **`placeholderUninstallScript` / `placeholderUninstallScriptWindows`** — Temporary placeholder scripts injected at migration time, designed to fail with `exit 1` until replaced by automation

## Usage Example

This migration is registered automatically via `init()` and run by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20240905200000, Down_20240905200000)
}
```

The computed `status` column in `host_software_installs` derives install/uninstall state from exit codes without requiring application-layer updates:

```text
pending_install   → host assigned, uninstall = 0, no exit codes yet
installed         → install_script_exit_code = 0
failed_install    → install_script_exit_code != 0
pending_uninstall → host assigned, uninstall = 1, no exit codes yet
failed_uninstall  → uninstall_script_exit_code != 0
NULL              → removed, or successfully uninstalled
```
