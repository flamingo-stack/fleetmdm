Database migration that creates the `scripts` table and adds a `script_id` foreign key column to `host_script_results`, enabling saved/reusable scripts scoped to teams or globally.

## Key Components

- **`Up_20230906152143`** — Creates the `scripts` table (idempotent via `IF NOT EXISTS`) and conditionally adds `script_id` to `host_script_results`
- **`Down_20230906152143`** — No-op rollback (destructive rollback not implemented)
- **`init`** — Registers the migration with `MigrationClient`

### `scripts` Table Schema

| Column | Type | Notes |
|---|---|---|
| `id` | `INT UNSIGNED` | Auto-increment primary key |
| `team_id` | `INT UNSIGNED NULL` | `NULL` = no team; FK → `teams.id` CASCADE |
| `global_or_team_id` | `INT UNSIGNED` | `0` = global; used for unique constraint (avoids `NULL` in index) |
| `name` | `VARCHAR(255)` | Script filename, unique per team/global scope |
| `script_contents` | `TEXT` | Script body, length limited by Fleet |
| `created_at` / `updated_at` | `TIMESTAMP` | Auto-managed timestamps |

### `host_script_results` Alteration

Adds `script_id INT UNSIGNED NULL` with `ON DELETE SET NULL` — when a saved script is deleted, its execution history entries become anonymous (one-off runs), consistent with `fleetctl run-script` executions.

## Usage Example

```go
// Migration is self-registering via init(); no direct call needed.
// Applied automatically by the MigrationClient at startup:
err := MigrationClient.Up(db, "")
if err != nil {
    log.Fatal(err)
}
```

> **Note:** The `global_or_team_id` pattern (using `0` for global instead of `NULL`) is a deliberate workaround for MySQL's behaviour of allowing duplicate `NULL` values in unique indexes.
