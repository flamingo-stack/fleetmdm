Database migration that creates and populates the `host_issues` table, which tracks per-host issue counts including failing policies and critical vulnerabilities.

## Key Components

| Function | Description |
|---|---|
| `Up_20240613172616` | Creates the `host_issues` table and backfills failing policy counts from `policy_membership` |
| `Down_20240613172616` | No-op rollback (migration is not reversed) |

### Table Schema — `host_issues`

| Column | Type | Description |
|---|---|---|
| `host_id` | `INT UNSIGNED` (PK) | References the host |
| `failing_policies_count` | `INT UNSIGNED` | Number of policies the host is failing |
| `critical_vulnerabilities_count` | `INT UNSIGNED` | Number of critical CVEs on the host |
| `total_issues_count` | `INT UNSIGNED` | Aggregate issue count (indexed) |
| `created_at` / `updated_at` | `TIMESTAMP(3)` | Millisecond-precision audit timestamps |

## Usage Example

This migration runs automatically via the `MigrationClient` on startup. To apply or inspect it manually:

```bash
# Apply all pending migrations (including this one)
fleet prepare db --config /etc/fleet/fleet.yml

# Verify the table was created
mysql -u fleet -p fleet -e "DESCRIBE host_issues;"

# Check backfilled data
mysql -u fleet -p fleet -e "SELECT * FROM host_issues LIMIT 10;"
```

## Notes

- **Idempotent**: Uses `CREATE TABLE IF NOT EXISTS` and `INSERT IGNORE`, making it safe to re-run.
- **No rollback**: `Down_` is a no-op; dropping the table must be handled manually if needed.
- **Backfill logic**: Populates `failing_policies_count` and `total_issues_count` from existing `policy_membership` rows where `passes = 0`.
- **MySQL 8+ note**: `total_issues_count` is maintained manually; a generated column could replace it on newer MySQL versions.
