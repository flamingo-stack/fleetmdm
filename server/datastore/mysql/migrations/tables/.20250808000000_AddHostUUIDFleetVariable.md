Database migration that registers the `FLEET_VAR_HOST_UUID` fleet variable in the `fleet_variables` table, enabling host UUID substitution in Fleet configurations.

## Key Components

| Symbol | Description |
|--------|-------------|
| `Up_20250808000000` | Inserts `FLEET_VAR_HOST_UUID` into `fleet_variables` using `INSERT IGNORE` for idempotency |
| `Down_20250808000000` | No-op rollback; the variable entry is left in place on downgrade |
| `init()` | Registers both migration functions with `MigrationClient` at package load time |

## Usage Example

This migration is applied automatically via the Fleet migration client. No direct invocation is required, but the registered variable becomes available for use in Fleet queries and configurations after the migration runs:

```go
// Applied automatically during fleet db:migrate
// After migration, FLEET_VAR_HOST_UUID is available as a non-prefix fleet variable:
//
// SELECT * FROM hosts WHERE uuid = $FLEET_VAR_HOST_UUID
```

## Notes

- **Idempotent**: Uses `INSERT IGNORE` so re-running the migration on an existing schema is safe.
- **Deterministic timestamp**: `created_at` is hardcoded to `2025-08-08 00:00:00 UTC` to keep the generated schema output consistent across environments.
- **No rollback action**: `Down_20250808000000` is a no-op; removing the variable requires a manual step if needed.
