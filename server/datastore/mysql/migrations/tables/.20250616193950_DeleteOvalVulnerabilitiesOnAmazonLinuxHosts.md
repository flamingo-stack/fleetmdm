Removes OVAL-sourced false-positive CVE entries for Amazon Linux packages from the `software_cve` table, correcting a data quality issue introduced before Fleet v4.56.0.

## Key Components

- **`Up_20250616193950`** — Deletes all `software_cve` rows where `source = 2` (OVAL) and the associated software `vendor` is `'amazon linux'`. This purges incorrect RHEL 6 OVAL vulnerability data that was previously applied to Amazon Linux 2 hosts before Fleet switched to ALAS via `goval-dictionary`.
- **`Down_20250616193950`** — No-op; data removal is not reversible.

## Migration Details

| Field | Value |
|---|---|
| Timestamp | `20250616193950` |
| Direction | Up only (destructive) |
| Idempotent | ✅ Yes |
| Affected table | `software_cve` (joined with `software`) |
| Filter condition | `vendor = 'amazon linux'` AND `source = 2` |

## Usage Example

```bash
# Applied automatically by Fleet's migration runner on startup.
# To run manually during development:
fleet prepare db --config /etc/fleet/fleet.yml
```

```go
// Registered via init() — no direct invocation needed.
// MigrationClient picks up Up/Down functions automatically.
MigrationClient.AddMigration(Up_20250616193950, Down_20250616193950)
```

## Notes

- `source = 2` corresponds to the OVAL vulnerability feed.
- Amazon Linux 2 vulnerability data is now sourced from ALAS (Amazon Linux Security Advisories) via `goval-dictionary` as of Fleet v4.56.0.
- Running `Up` multiple times is safe; if no matching rows exist, the `DELETE` is a no-op.
