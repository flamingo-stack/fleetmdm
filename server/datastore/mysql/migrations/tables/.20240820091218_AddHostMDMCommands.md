Database migration that creates the `host_mdm_commands` table for tracking MDM commands sent to managed hosts, preventing duplicate command delivery.

## Key Components

- **`Up_20240820091218`** — Idempotent migration that creates the `host_mdm_commands` table if it does not already exist
- **`Down_20240820091218`** — No-op rollback; table removal is not implemented
- **`host_mdm_commands` table** — Tracks which MDM command types (e.g., `refetch_apps`) have been dispatched to a given host

### Table Schema

| Column | Type | Notes |
|---|---|---|
| `host_id` | `int unsigned` | References the managed host |
| `command_type` | `VARCHAR(31)` | MDM command identifier (`utf8mb4_unicode_ci`) |
| `created_at` | `TIMESTAMP(6)` | Record creation time |
| `updated_at` | `TIMESTAMP(6)` | Auto-updated on row modification |
| **PK** | `(host_id, command_type)` | Composite primary key enforces one entry per host/command pair |

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20240820091218, Down_20240820091218)
}

// The composite primary key prevents duplicate MDM commands per host:
// INSERT INTO host_mdm_commands (host_id, command_type) VALUES (42, 'refetch_apps')
// A second insert for the same host + command_type will fail or be ignored via INSERT IGNORE.
```
