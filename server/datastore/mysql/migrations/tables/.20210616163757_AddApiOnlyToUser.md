Database migration that adds an `api_only` boolean column to the `users` table, enabling the designation of API-only user accounts.

## Key Components

- **`Up_20210616163757`** — Idempotent migration that adds `api_only TINYINT(1) NOT NULL DEFAULT 0` to the `users` table. Uses `columnExists` to guard against duplicate column errors on re-runs.
- **`Down_20210616163757`** — No-op rollback; the column is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Applied automatically by the migration runner.
// To run manually via goose or the Fleet migration client:
MigrationClient.AddMigration(Up_20210616163757, Down_20210616163757)
```

After the migration runs, the `users` table gains:

```text
Column   | Type        | Null | Default
---------|-------------|------|--------
api_only | TINYINT(1)  | NO   | 0
```

Set `api_only = 1` on a user record to mark it as a service/API account that authenticates programmatically rather than through the UI.

## Notes

- **Idempotent** — Safe to run multiple times; `columnExists` skips the `ALTER TABLE` if the column already exists.
- The down migration is intentionally a no-op to avoid unintended data loss on rollback.
