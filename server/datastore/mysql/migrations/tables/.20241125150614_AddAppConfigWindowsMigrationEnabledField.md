Database migration that adds the `windows_migration_enabled` field (defaulting to `false`) to the `mdm` section of the Fleet app configuration JSON stored in `app_config_json`.

## Key Components

- **`Up_20241125150614`** — Applies the migration by reading the current app config JSON, injecting `windows_migration_enabled: false` into the `mdm` map, and writing it back. The migration is idempotent and safely no-ops if no config row exists.
- **`Down_20241125150614`** — No-op rollback; the field addition does not require a destructive down migration.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Migration is auto-registered via init() and run by the migration client.
// Manual invocation during testing:
func TestUp_20241125150614(t *testing.T) {
    tx, _ := db.Begin()
    defer tx.Rollback()

    // Seed a minimal app_config_json row
    tx.Exec(`INSERT INTO app_config_json (json_value)
        VALUES ('{"mdm":{}}')`)

    if err := Up_20241125150614(tx); err != nil {
        t.Fatal(err)
    }

    var raw []byte
    tx.QueryRow(`SELECT json_value FROM app_config_json LIMIT 1`).Scan(&raw)

    var cfg map[string]interface{}
    json.Unmarshal(raw, &cfg)

    mdm := cfg["mdm"].(map[string]interface{})
    // mdm["windows_migration_enabled"] == false
}
```

## Notes

- The migration guards against a missing `mdm` key by returning an explicit error rather than silently creating the section.
- Setting the field to `false` on every run makes the `Up` function safe to re-execute without side effects.
