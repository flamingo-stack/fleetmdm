Creates the `operating_system_version_vulnerabilities` table and backfills it with Linux kernel vulnerability data aggregated from existing kernel host counts and CVE records.

## Key Components

- **`Up_20251028140000`** — Runs the forward migration: creates the table and backfills two passes of data (per-team and all-teams aggregates).
- **`Down_20251028140000`** — No-op rollback; the table is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

### Table: `operating_system_version_vulnerabilities`

| Column | Description |
|---|---|
| `os_version_id` | References the OS version affected |
| `cve` | CVE identifier |
| `team_id` | `NULL` = all teams, `0` = no team, `>0` = specific team |
| `source` | Vulnerability source (smallint) |
| `resolved_in_version` | First version that resolves the CVE |
| `created_at` / `updated_at` | Microsecond-precision timestamps |

**Indexes:**
- Unique key on `(IFNULL(team_id, -1), os_version_id, cve)` — safe upsert support
- Composite key on `(team_id, os_version_id, cve)` — efficient reads
- Key on `updated_at` — cleanup/expiry queries

## Usage Example

```go
// Applied automatically by the migration runner at startup.
// To invoke manually during testing:
db, _ := sql.Open("mysql", dsn)
tx, _ := db.Begin()

if err := Up_20251028140000(tx); err != nil {
    tx.Rollback()
    log.Fatal(err)
}
tx.Commit()
```

> **Scope:** This table stores **Linux kernel vulnerabilities only**. Non-Linux OS vulnerabilities continue to be served from the `operating_system_vulnerabilities` table.
