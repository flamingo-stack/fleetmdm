Database migration that renames the `cve_scores` table to `cve_meta` and adds a `published` timestamp column to support expanded CVE metadata storage.

## Key Components

- **`Up_20220526123327`** — Idempotent migration that conditionally renames `cve_scores` → `cve_meta` (only if the old table exists) and adds a nullable `published TIMESTAMP` column if not already present.
- **`Down_20220526123327`** — No-op rollback; the rename is not reversed.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Applied automatically by the migration runner at startup.
// The migration is safe to re-run due to idempotency guards:

// Step 1: Renames table only if cve_scores exists
RENAME TABLE cve_scores TO cve_meta;

// Step 2: Adds column only if published does not already exist
ALTER TABLE cve_meta
    ADD published TIMESTAMP NULL DEFAULT NULL;
```

## Notes

- **Idempotent** — Both operations are guarded by `tableExists` / `columnExists` checks, making it safe to run multiple times without error.
- **No rollback** — `Down_` is a no-op; reversing this migration would require manual intervention.
