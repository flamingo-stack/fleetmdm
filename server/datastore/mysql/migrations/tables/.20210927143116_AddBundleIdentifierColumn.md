Adds a `bundle_identifier` column to the `software` table as an idempotent database migration.

## Key Components

- **`Up_20210927143116`** — Applies the migration by adding a `bundle_identifier VARCHAR(255)` column with a default empty string to the `software` table. Checks for column existence first, making the migration safe to run multiple times.
- **`Down_20210927143116`** — No-op rollback; the column is not removed on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is executed automatically by the migration client. No manual invocation is required.

```go
// Migration is registered on package init and run via:
MigrationClient.AddMigration(Up_20210927143116, Down_20210927143116)

// Up migration executes the equivalent of:
ALTER TABLE software ADD COLUMN bundle_identifier VARCHAR(255) DEFAULT '';
```

## Notes

- The migration is idempotent: if `bundle_identifier` already exists on the `software` table, `Up_20210927143116` returns early without error.
- The down migration is intentionally a no-op — dropped columns can cause data loss, so reversal is left to manual intervention if needed.
