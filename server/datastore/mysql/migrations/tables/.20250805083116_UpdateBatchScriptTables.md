Database migration that renames `batch_script_executions` to `batch_activities`, adds tracking columns, backfills default values, creates a status index, and renames the related host results table.

## Key Components

- **`Up_20250805083116`** — Idempotent up migration performing the following steps:
  - Renames `batch_script_executions` → `batch_activities`
  - Adds columns: `job_id`, `num_canceled`, `num_incompatible`, `num_errored`, `num_ran`, `num_pending`, `num_targeted`, `activity_type`, `status`, `completed_at`, `canceled_at`
  - Backfills `status = 'started'` and `activity_type = 'script'` for existing rows
  - Creates index `idx_batch_activities_status` on the `status` column
  - Renames `batch_script_execution_host_results` → `batch_activity_host_results`
- **`Down_20250805083116`** — No-op rollback (irreversible migration)

## Schema Changes Summary

| Before | After |
|---|---|
| `batch_script_executions` | `batch_activities` |
| `batch_script_execution_host_results` | `batch_activity_host_results` |
| No `status` / `activity_type` columns | `status = 'started'`, `activity_type = 'script'` (backfilled) |
| No job tracking columns | `job_id`, `num_*` counters, `completed_at`, `canceled_at` |

> **Note:** The down migration is a no-op. Schema renames and column additions are not automatically reversed. Manual intervention is required to roll back.
