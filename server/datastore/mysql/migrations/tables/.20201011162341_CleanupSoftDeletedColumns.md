Database migration that removes soft-delete columns (`deleted` and `deleted_at`) from core Fleet MDM tables, replacing the soft-delete pattern with hard deletes.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `Up20201011162341` | Migration func | Removes soft-deleted rows then drops `deleted`/`deleted_at` columns from all target tables |
| `Down20201011162341` | Migration func | Restores `deleted` and `deleted_at` columns to all target tables (rollback) |
| `cleanupSoftDeleteFields` | Helper func | Deletes rows where `deleted=true`, then drops both soft-delete columns; tolerates missing columns idempotently |
| `addSoftDeleteFields` | Helper func | Re-adds `deleted TINYINT(1)` and `deleted_at TIMESTAMP` columns for rollback |
| `getTablesForCleanupSoftDeletedColumnsMigration` | Helper func | Returns the list of 8 affected tables |

**Affected tables:** `distributed_query_campaigns`, `labels`, `invites`, `hosts`, `packs`, `queries`, `scheduled_queries`, `users`

## Usage Example

This migration runs automatically via the migration client. To apply or roll back manually:

```go
// Applied automatically on startup via MigrationClient
// Manual invocation (within a transaction):
tx, _ := db.Begin()

// Up: remove soft-delete columns
err := Up20201011162341(tx)

// Down: restore soft-delete columns
err := Down20201011162341(tx)
```

## Notes

- **Idempotent**: Both `cleanupSoftDeleteFields` catches `ER_BAD_FIELD_ERROR` (column missing) and `ER_CANT_DROP_FIELD_OR_KEY` (column already dropped), making the `Up` migration safe to re-run.
- **Destructive**: The `Up` migration permanently hard-deletes any rows flagged as soft-deleted before dropping the columns.
