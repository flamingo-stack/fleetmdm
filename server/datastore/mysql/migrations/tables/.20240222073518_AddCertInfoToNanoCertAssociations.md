Database migration that adds certificate expiry and renewal tracking columns to the `nano_cert_auth_associations` table, then backfills `cert_not_valid_after` timestamps from existing SCEP certificates.

## Key Components

| Function | Description |
|---|---|
| `Up_20240222073518` | Idempotent migration adding `cert_not_valid_after` (TIMESTAMP) and `renew_command_uuid` (VARCHAR) columns, a FK constraint to `nano_commands`, then backfilling certificate expiry data |
| `Down_20240222073518` | No-op rollback |
| `batchUpdateCertAssociationsTimestamps` | Paginates `scep_certificates` in batches of 100 to avoid large in-memory loads |
| `updateCertAssociationTimestamps` | For a batch, decodes PEM certs, computes SHA-256 fingerprints, matches against `nano_cert_auth_associations`, and upserts `cert_not_valid_after` |
| `hashCert` | Returns the hex-encoded SHA-256 of a certificate's raw DER bytes |

## Schema Changes

```sql
-- New columns
ALTER TABLE nano_cert_auth_associations
  ADD COLUMN cert_not_valid_after TIMESTAMP NULL,
  ADD COLUMN renew_command_uuid   VARCHAR(127) COLLATE utf8mb4_unicode_ci NULL;

-- New FK
ADD CONSTRAINT renew_command_uuid_fk
  FOREIGN KEY (renew_command_uuid) REFERENCES nano_commands (command_uuid);
```

## Notes

- **Idempotent**: Each structural change is guarded by `columnExists` / `constraintExists` checks, making the migration safe to re-run.
- **No FK on `cert_not_valid_after`**: Intentional — nanomdm supports non-Fleet CAs, so a hard FK to `scep_certificates` is avoided.
- **Upsert preserves `updated_at`**: The `ON DUPLICATE KEY UPDATE` clause sets `updated_at = updated_at` to prevent timestamp drift during backfill.
