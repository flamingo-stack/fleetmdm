Database migration that updates the `software` field structure in team configurations, converting legacy array-format software data into the new `packages` key format within a map structure.

## Key Components

- **`Up_20240802113716`** — Migrates team configs by detecting when `software` is a plain slice (old format) and wrapping it as `{"packages": <original_value>}`. Idempotent — skips rows where `software` is already a map or absent.
- **`Down_20240802113716`** — No-op rollback; the schema change is considered safe to leave in place.

## Usage Example

```go
// Applied automatically by the migration client on startup.
// Transforms team config stored in DB:

// Before (old format):
// { "software": [ {...}, {...} ] }

// After (new format):
// { "software": { "packages": [ {...}, {...} ] } }

// Manual invocation (e.g. in tests):
db, _ := sql.Open("mysql", dsn)
tx, _ := db.Begin()
if err := Up_20240802113716(tx); err != nil {
    tx.Rollback()
    log.Fatal(err)
}
tx.Commit()
```

## Migration Logic

1. Selects all rows from `teams` with their JSON `config`.
2. Unmarshals each config and checks for a `software` key.
3. If `software` is a `reflect.Slice` (legacy array), wraps it: `{"packages": <slice>}`.
4. Re-marshals and writes back with `UPDATE teams SET config = ?`.

> Rows where `software` is absent, `null`, or already a map are skipped, making the migration safe to re-run.
