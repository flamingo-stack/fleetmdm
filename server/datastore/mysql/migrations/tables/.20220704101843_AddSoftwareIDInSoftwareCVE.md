Database migration that adds a `software_id` column to the `software_cve` table, backfills it from the `software_cpe` table in batches, and creates an index on the new column.

## Key Components

- **`Up_20220704101843(tx *sql.Tx) error`** — Applies the migration in three idempotent steps:
  1. Adds `software_id BIGINT UNSIGNED NULL` column to `software_cve` (if not already present)
  2. Backfills `software_id` by joining `software_cve` → `software_cpe` in batches of 500 rows
  3. Creates index `software_cve_software_id` on the new column (if not already present)

- **`Down_20220704101843(tx *sql.Tx) error`** — No-op rollback; returns `nil`.

- **`init()`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is executed automatically by the migration runner. It is not called directly. The batched update pattern used internally looks like:

```go
const batchSize = 500
start := minVal
for {
    end := start + batchSize
    if end >= maxVal {
        end = maxVal + 1
    }
    tx.Exec(updateStmt, start, end)
    start += batchSize
    if start >= maxVal {
        break
    }
}
```

## Notes

- Uses `ALGORITHM=INPLACE, LOCK=NONE` for online DDL to minimize table locking on large datasets.
- Both the column addition and index creation are guarded by existence checks (`columnExists`, `indexExistsTx`), making the migration safe to re-run.
- The rollback (`Down`) is intentionally a no-op — column and index removal must be handled manually if needed.
