Database migration that unmarks `kernel-core` RPM packages as kernel entries, ensuring only `kernel` is treated as the canonical kernel package on RHEL-family systems.

## Key Components

| Function | Description |
|---|---|
| `Up_20260211200153` | Updates `software_titles` to set `is_kernel = 0` for `kernel-core` RPM packages, then removes associated `kernel_host_counts` entries |
| `Down_20260211200153` | No-op rollback (migration is considered safe to leave in place) |

## Migration Details

**Problem:** Both `kernel` and `kernel-core` were previously marked as kernel packages for RPM-based distributions. On RHEL-family systems (RHEL, AlmaLinux, CentOS, Rocky, Fedora, Amazon Linux), both packages coexist, causing duplicate kernel entries in the OS versions API.

**Solution:** Only `kernel` is marked as the canonical kernel package. This migration:

1. Sets `is_kernel = 0` for all `software_titles` rows where `name = 'kernel-core'` and `source = 'rpm_packages'`
2. Deletes orphaned `kernel_host_counts` rows linked to those `kernel-core` titles

This migration is **idempotent** — safe to re-run without side effects.
