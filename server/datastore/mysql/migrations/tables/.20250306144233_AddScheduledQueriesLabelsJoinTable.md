Database migration that creates the `query_labels` join table, establishing a many-to-many relationship between scheduled queries and labels.

## Key Components

- **`Up_20250306144233`** — Creates the `query_labels` table with foreign keys referencing `queries` and `labels`, cascading deletes, and a unique constraint on `(query_id, label_id)`. The migration is idempotent via `CREATE TABLE IF NOT EXISTS`.
- **`Down_20250306144233`** — No-op rollback; the table is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Schema Created

```text
query_labels
├── id           INT UNSIGNED  PK, AUTO_INCREMENT
├── query_id     INT UNSIGNED  FK → queries(id) ON DELETE CASCADE
├── label_id     INT UNSIGNED  FK → labels(id)  ON DELETE CASCADE
├── created_at   TIMESTAMP     DEFAULT CURRENT_TIMESTAMP
└── updated_at   TIMESTAMP     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

UNIQUE: (query_id, label_id)
```

## Usage Example

This migration is applied automatically by the Fleet migration runner. To apply manually:

```bash
# Apply up migration
fleet prepare db --config /etc/fleet/fleet.yml

# Verify table exists
mysql -u fleet -p fleet -e "DESCRIBE query_labels;"
```

To reference this table in Go:

```go
// Associate a label with a scheduled query
_, err := db.Exec(
    `INSERT INTO query_labels (query_id, label_id) VALUES (?, ?)
     ON DUPLICATE KEY UPDATE updated_at = CURRENT_TIMESTAMP`,
    queryID, labelID,
)
```
