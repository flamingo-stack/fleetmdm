Database migration that queues a background worker job to regenerate and re-register Apple DEP enrollment profiles with `await_device_configured` set to `true`.

## Key Components

- **`Up_20240320145650`** — Inserts a `macos_setup_assistant` job with task `update_all_profiles` into the `jobs` table using `INSERT IGNORE` (idempotent). Uses hardcoded timestamps to keep `schema.sql` stable.
- **`Down_20240320145650`** — No-op rollback; the queued job cannot be meaningfully reversed.
- **`macosSetupAssistantArgs`** — Local struct serialized to JSON as the job payload, containing `task`, optional `team_id`, and optional `host_serial_numbers`.

## Usage Example

This migration runs automatically via the `MigrationClient` on Fleet startup:

```go
// Registered in init(), executed by the migration runner:
MigrationClient.AddMigration(Up_20240320145650, Down_20240320145650)
```

The inserted job record looks like:

```json
{
  "task": "update_all_profiles"
}
```

The Fleet worker picks up the queued job shortly after restart and triggers a full DEP profile regeneration and re-registration with Apple, ensuring `await_device_configured: true` is set on all profiles.

## Notes

- Uses `INSERT IGNORE` to ensure idempotency — safe to run multiple times.
- Avoids calling `worker.QueueMacosSetupAssistantJob` directly to prevent future code changes from breaking this migration.
- Hardcoded timestamp: `2024-03-20 00:00:00 UTC`.
