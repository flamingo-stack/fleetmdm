Database migration that modifies the `software_installers` table to support multiple installer versions per title by restructuring indexes and adding an `is_active` column.

## Key Components

- **`Up_20260218175704`** — Applies the migration with the following changes:
  - Drops legacy indexes `idx_software_installers_team_id_title_id` and `idx_software_installers_platform_title_id`
  - Adds a new unique index `idx_software_installers_team_title_version` on `(global_or_team_id, title_id, version)` to allow multiple versions per title/team
  - Adds `is_active TINYINT(1) NOT NULL DEFAULT 0` column to track which installer is the active one
  - Sets `is_active = 1` for all existing rows (since only one installer per title existed at migration time)
- **`Down_20260218175704`** — No-op rollback; schema changes are not reversed

## Usage Example

This migration is automatically registered and executed by the migration client:

```go
// Registered automatically via init()
MigrationClient.AddMigration(Up_20260218175704, Down_20260218175704)
```

The migration is idempotent — each DDL step checks for index or column existence before applying, making it safe to re-run:

```go
if !columnExists(tx, "software_installers", "is_active") {
    // ADD COLUMN only if missing
}
```
