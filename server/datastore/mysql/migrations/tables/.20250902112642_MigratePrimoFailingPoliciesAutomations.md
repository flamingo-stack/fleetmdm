Database migration that moves failing policy automation settings (webhook, Jira, Zendesk) from the global app config to the "No Team" default team config, applicable only when the Primo partnership feature is enabled.

## Key Components

- **`Up_20250902112642(tx *sql.Tx) error`** — Idempotent up migration that:
  1. Guards execution behind the `FLEET_PARTNERSHIPS_ENABLE_PRIMO` environment variable
  2. Reads and parses `app_config_json` to extract global webhook and integration settings
  3. Separates policy IDs in the global failing-policies webhook into "No Team" vs. other team policies
  4. Strips No Team policy IDs from the global config and writes it back to `app_config_json`
  5. Copies the relevant failing-policies automation settings (webhook, Jira, Zendesk) into `default_team_config_json`

- **`Down_20250902112642(_ *sql.Tx) error`** — No-op; migration is intentionally irreversible

- **`init()`** — Registers both migration functions with `MigrationClient`

## Usage Example

This migration runs automatically via the Fleet migration client. To trigger the data migration (rather than skipping it), set the environment variable before running migrations:

```bash
export FLEET_PARTNERSHIPS_ENABLE_PRIMO=true
fleet prepare db
```

The migration is safe to run multiple times. If `FLEET_PARTNERSHIPS_ENABLE_PRIMO` is not `"true"` or `"1"`, the migration exits early without modifying any data.

```go
// Registered automatically via init():
MigrationClient.AddMigration(Up_20250902112642, Down_20250902112642)
```

## Notes

- **Idempotent** — Re-running does not duplicate or corrupt data because policy IDs are moved (not copied) from the global config
- **Primo-gated** — The `FLEET_PARTNERSHIPS_ENABLE_PRIMO` env var must be set at migration time; it cannot be applied retroactively
- Handles JSON numeric types (`float64`, `int64`, `int`) defensively when deserializing policy and Zendesk group IDs
