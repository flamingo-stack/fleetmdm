Database migration that creates the `cron_stats` table for tracking scheduled job execution statistics, registered with the migration client for automated schema management.

## Key Components

- **`Up_20221115104546`** — Creates the `cron_stats` table (idempotent via `CREATE TABLE IF NOT EXISTS`) with the following schema:

| Column | Type | Description |
|---|---|---|
| `id` | `INT UNSIGNED AUTO_INCREMENT` | Primary key |
| `name` | `VARCHAR(255)` | Cron job name |
| `instance` | `VARCHAR(255)` | Server/process instance identifier |
| `stats_type` | `VARCHAR(255)` | Category of statistics recorded |
| `status` | `VARCHAR(255)` | Execution status |
| `created_at` | `TIMESTAMP` | Record creation time |
| `updated_at` | `TIMESTAMP` | Auto-updated on row change |

  Also creates index `idx_cron_stats_name_created_at` on `(name, created_at)` to support efficient time-range queries per job name.

- **`Down_20221115104546`** — No-op rollback; table is left in place on downgrade.

- **`init()`** — Registers both migration functions with `MigrationClient` at package load time.

## Usage Example

```go
// Applied automatically by the migration runner at startup.
// To run manually via the CLI:
```

```bash
fleetctl db migrate
```

The migration targets InnoDB with `utf8mb4_unicode_ci` collation, consistent with Fleet's standard table configuration.
