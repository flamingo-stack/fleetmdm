Database migration that creates the `host_script_results` table for tracking script execution results on managed hosts.

## Key Components

- **`Up_20230814150442`** — Creates the `host_script_results` table (idempotent via `CREATE TABLE IF NOT EXISTS`) with the following schema:

| Column | Type | Description |
|---|---|---|
| `id` | `INT UNSIGNED` | Auto-increment primary key |
| `host_id` | `INT UNSIGNED` | Reference to the target host |
| `execution_id` | `VARCHAR(255)` | Unique identifier (e.g. UUID) per script run |
| `script_contents` | `TEXT` | Raw script body executed |
| `output` | `TEXT` | Combined stdout/stderr output |
| `runtime` | `INT UNSIGNED` | Execution duration in seconds |
| `exit_code` | `INT NULL` | Exit code; `NULL` = pending, `-1` = abruptly terminated |
| `created_at` / `updated_at` | `TIMESTAMP` | Audit timestamps |

- **`Down_20230814150442`** — No-op rollback (table is not dropped).

## Indexes

- `idx_host_script_results_execution_id` — Unique index on `execution_id` for fast result lookups by execution.
- `idx_host_script_results_host_exit_created` — Composite index on `(host_id, exit_code, created_at)` to efficiently query pending executions per host (where `exit_code IS NULL`) and detect stale/timed-out runs.
