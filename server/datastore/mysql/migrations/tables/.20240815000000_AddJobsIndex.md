Database migration that adds a composite index on the `jobs` table to optimize query performance for job scheduling and state-based lookups.

## Key Components

- **`Up_20240815000000`** — Creates the composite index `idx_jobs_state_not_before_updated_at` on `jobs(state, not_before, updated_at)`. The migration is idempotent, checking for index existence before creation via `indexExistsTx`.
- **`Down_20240815000000`** — No-op rollback; the index is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the Fleet migration client. To apply manually:

```go
// Applied automatically on Fleet server startup
// or via fleet prepare db

// The created index supports queries like:
SELECT * FROM jobs
WHERE state = 'queued'
  AND not_before <= NOW()
ORDER BY updated_at ASC;
```

## Notes

- The index targets the three columns most commonly used together in job scheduling queries: `state` (filter by job status), `not_before` (scheduling gate), and `updated_at` (ordering/recency).
- Idempotency is enforced via `indexExistsTx`, making this safe to re-run.
- The down migration is intentionally a no-op — index removal would require explicit handling if needed.
