Database migration that adds three columns to the `mdm_windows_enrollments` table to support Windows MDM on-demand sync functionality.

## Key Components

| Symbol | Description |
|---|---|
| `Up_20260603120000` | Forward migration — idempotently adds `poll_schedule_relaxed`, `has_pending_commands`, and `fleetd_sync_capable` columns, then backfills `has_pending_commands` from the existing command queue |
| `Down_20260603120000` | Rollback stub — no-op (columns are left in place on rollback) |

### New Columns on `mdm_windows_enrollments`

| Column | Type | Purpose |
|---|---|---|
| `poll_schedule_relaxed` | `TINYINT(1)` | Tracks the intended DMClient poll schedule; set once a fleetd-wakeable host has been relaxed, preventing the management session from re-sending the poll `Replace` each session |
| `has_pending_commands` | `TINYINT(1)` | Denormalized flag indicating queued, unacknowledged commands (excluding internal poll-schedule `Replaces`); read by the orbit config check-in (~every 30s) to avoid a live `EXISTS` scan of the command queue on every poll |
| `fleetd_sync_capable` | `TINYINT(1)` | Last-observed `CapabilityWindowsMDMSync` flag from the `X-Fleet-Capabilities` header; persisted by the orbit-config endpoint since the OMA-DM session carries no capability header |

## Usage Example

This migration runs automatically via the `MigrationClient` on fleet server startup. No manual invocation is required.

```go
// The migration is self-registering via init()
// MigrationClient.AddMigration(Up_20260603120000, Down_20260603120000)

// Forward migration guards against re-application with a column existence check:
if !columnsExists(tx, "mdm_windows_enrollments",
    "poll_schedule_relaxed",
    "has_pending_commands",
    "fleetd_sync_capable") {
    // ALTER TABLE runs only once
}

// Backfill: only flips enrollments that already have unacknowledged commands,
// keeping work proportional to pending commands rather than total fleet size.
```
