Database migration that modifies the `host_users` table's primary key, replacing the auto-increment `id` column with a composite primary key on `(host_id, uid, username)`.

## Key Components

- **`Up_20210903132338`** — Idempotent migration that drops the `id` column and replaces the existing primary key with a composite key on `(host_id, uid, username)`. Checks `INFORMATION_SCHEMA.STATISTICS` before executing to skip if already applied.
- **`Down_20210903132338`** — No-op rollback; the schema change is not reversed.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20210903132338, Down_20210903132338)
}
```

The idempotency check queries the information schema to detect whether `username` is already part of the primary key before altering the table:

```go
// Safe to re-run; exits early if already in target state
err := tx.QueryRow(`SELECT COUNT(*) FROM INFORMATION_SCHEMA.STATISTICS
    WHERE TABLE_SCHEMA = DATABASE()
    AND TABLE_NAME = 'host_users'
    AND INDEX_NAME = 'PRIMARY'
    AND COLUMN_NAME = 'username'`).Scan(&count)
if err == nil && count > 0 {
    return nil // already migrated
}
```

## Notes

- The migration is **idempotent** — safe to run multiple times without side effects.
- The rollback (`Down`) is intentionally a no-op; reverting the primary key restructure is not supported.
