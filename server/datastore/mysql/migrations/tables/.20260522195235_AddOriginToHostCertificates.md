Database migration that adds an `origin` column to the `host_certificates` table, scoping deletion semantics by ingestion source (`osquery` or `mdm`).

## Key Components

- **`Up_20260522195235`** — Idempotent migration that adds an `ENUM('osquery', 'mdm')` column named `origin` to `host_certificates`. Existing rows default to `'osquery'`, preserving backward compatibility. Uses `columnExists` to guard against re-application.
- **`Down_20260522195235`** — No-op rollback (column removal is left unimplemented).
- **`init`** — Registers both migration functions with `MigrationClient`.

## Behavior Notes

The `origin` column is internal and not exposed via the public API. Its purpose is to isolate deletion ownership between ingestion sources:

- An **osquery** sync that omits a certificate row will only soft-delete rows it originally created.
- An **MDM** `CertificateList` sync will only soft-delete rows it owns.
- Neither source will inadvertently purge rows created by the other.

## Usage Example

This migration runs automatically via the `MigrationClient` during schema upgrades. To apply manually:

```bash
# Apply the migration
fleet prepare db --config /etc/fleet/fleet.yml

# Verify the column was added
mysql -e "DESCRIBE host_certificates;" | grep origin
# Expected: origin  enum('osquery','mdm')  NO  ''  osquery  ''
```
