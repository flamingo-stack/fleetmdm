Database migration that creates the `host_mdm_managed_certificates` table, which tracks MDM-managed certificates for hosts and their associated profiles.

## Key Components

| Function | Description |
|---|---|
| `Up_20241009090010` | Creates the `host_mdm_managed_certificates` table (idempotent via `IF NOT EXISTS`) |
| `Down_20241009090010` | No-op rollback — table is not dropped on down migration |

### Table Schema: `host_mdm_managed_certificates`

| Column | Type | Notes |
|---|---|---|
| `host_uuid` | `varchar(255)` | Host identifier |
| `profile_uuid` | `varchar(37)` | Associated MDM profile |
| `challenge_retrieved_at` | `TIMESTAMP(6)` | Nullable; when SCEP challenge was fetched |
| `created_at` | `TIMESTAMP(6)` | Auto-set on insert |
| `updated_at` | `TIMESTAMP(6)` | Auto-updated on row change |

**Primary Key:** composite `(host_uuid, profile_uuid)`

## Usage Example

This migration runs automatically via the `MigrationClient` on startup:

```go
// Registered in init(); executed by the migration runner
MigrationClient.AddMigration(Up_20241009090010, Down_20241009090010)
```

To apply manually during development:

```bash
fleet prepare db --config /path/to/config.yml
```

## Notes

- Migration is **idempotent** — safe to run multiple times without side effects.
- The down migration is intentionally empty; schema rollback requires manual intervention.
- Microsecond precision (`TIMESTAMP(6)`) on all timestamp columns supports fine-grained audit tracking.
