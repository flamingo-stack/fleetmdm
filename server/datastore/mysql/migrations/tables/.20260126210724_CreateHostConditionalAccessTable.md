Database migration that creates the `host_conditional_access` table, which tracks conditional access status and bypass timestamps for individual hosts.

## Key Components

- **`Up_20260126210724`** — Creates the `host_conditional_access` table using `CREATE TABLE IF NOT EXISTS` (idempotent). Schema includes:
  - `id` — Auto-incrementing unsigned primary key
  - `host_id` — Unsigned foreign reference to a host (unique, one record per host)
  - `bypassed_at` — Nullable timestamp recording when conditional access was bypassed
  - `created_at` / `updated_at` — Microsecond-precision audit timestamps with automatic `ON UPDATE` maintenance
- **`Down_20260126210724`** — No-op rollback; the table is left in place on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient` at package load time.

## Usage Example

This migration is applied automatically by the Fleet migration runner. No manual invocation is needed. To run all pending migrations:

```bash
fleetctl prepare db
```

To apply programmatically in tests:

```go
db, _ := sql.Open("mysql", dsn)
tx, _ := db.Begin()

if err := Up_20260126210724(tx); err != nil {
    log.Fatal(err)
}
tx.Commit()
```

## Notes

- The `UNIQUE KEY` on `host_id` enforces a one-to-one relationship between hosts and their conditional access record.
- The down migration is intentionally empty — dropping the table on rollback could cause data loss in production environments.
