Database migration that adds VPP (Volume Purchase Program) app automation support to policies by introducing foreign key relationships between the `policies` and `host_vpp_software_installs` tables.

## Key Components

- **`Up_20250121094700`** — Idempotent migration that applies four schema changes:
  - Adds `vpp_apps_teams_id` column (`INT UNSIGNED`) to `policies`
  - Adds foreign key `fk_policies_vpp_apps_team_id` linking `policies.vpp_apps_teams_id` → `vpp_apps_teams.id`
  - Adds `policy_id` column (`INT UNSIGNED`) to `host_vpp_software_installs`
  - Adds foreign key `fk_host_vpp_software_installs_policy_id` linking `host_vpp_software_installs.policy_id` → `policies.id` with `ON DELETE SET NULL`

- **`Down_20250121094700`** — No-op rollback (columns and FKs are not removed).

## Usage Example

This migration runs automatically via the `MigrationClient` on startup. To apply manually:

```bash
fleetctl db migrate
```

To verify schema changes after migration:

```sql
-- Check new column on policies
SHOW COLUMNS FROM policies LIKE 'vpp_apps_teams_id';

-- Check new column on host_vpp_software_installs
SHOW COLUMNS FROM host_vpp_software_installs LIKE 'policy_id';
```

## Notes

- All changes are guarded by `columnExists` / `fkExists` checks, making the migration safe to re-run.
- The `ON DELETE SET NULL` on `fk_host_vpp_software_installs_policy_id` preserves install records when a linked policy is deleted.
