Database migration that links policies to software installers and tracks installer ownership by adding relational columns and foreign key constraints to support automatic software installation via policies.

## Key Components

- **`Up_20240829170044`** — Idempotent forward migration that applies three schema changes:
  - Adds `software_installer_id` (nullable `INT UNSIGNED`) to the `policies` table
  - Adds foreign key `fk_policies_software_installer_id` referencing `software_installers(id)`
  - Adds `user_id`, `user_name`, and `user_email` columns to `software_installers` to track the uploader (preserving name/email if the user is later deleted)
  - Adds foreign key `fk_software_installers_user_id` referencing `users(id)` with `ON DELETE SET NULL`
- **`Down_20240829170044`** — No-op rollback (schema changes are not reversed)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Migration is registered on package import
MigrationClient.AddMigration(Up_20240829170044, Down_20240829170044)

// Up migration guards against re-application using existence checks
if !columnExists(tx, "policies", "software_installer_id") {
    // ALTER TABLE only runs if column is absent
}

if !fkExists(tx, "policies", "fk_policies_software_installer_id") {
    // FK only added if not already present
}
```

All checks use `columnExists`, `columnsExists`, `fkExists`, and `constraintExists` helpers, making the migration safe to run multiple times without error.

## Notes

- `user_name` and `user_email` are stored denormalized on `software_installers` to retain attribution even after the referenced user is removed from Fleet (`user_id` becomes `NULL` on delete).
