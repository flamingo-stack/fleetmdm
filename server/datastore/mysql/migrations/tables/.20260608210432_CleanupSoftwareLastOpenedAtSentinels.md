Database migration that clears macOS sentinel `last_opened_at` timestamps (1980-01-01 UTC) from the `host_software` table, replacing them with `NULL` to correctly indicate apps that were never opened.

## Key Components

- **`Up_20260608210432`** — Sets `last_opened_at = NULL` for rows where the value equals the DOS/FAT epoch sentinel `1980-01-01 00:00:00`. Targets only this specific known sentinel to avoid corrupting legitimate pre-2001 timestamps from non-macOS sources (e.g. Linux deb/rpm file atimes).
- **`Down_20260608210432`** — No-op rollback; the migration is considered safe to leave applied since cleared sentinel values cannot be meaningfully restored.

## Usage Example

This migration is registered automatically via `init()` and executed by the Fleet migration runner:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20260608210432, Down_20260608210432)
```

The core SQL applied during `Up`:

```sql
UPDATE host_software
SET last_opened_at = NULL
WHERE last_opened_at = '1980-01-01 00:00:00'
```

## Notes

- **Idempotent** — Safe to re-run; a second pass finds no matching rows and is a no-op.
- **Sentinel origin** — macOS reports `315532800.0` Unix seconds (1980-01-01 UTC) for apps installed but never launched. Older Fleet versions persisted this as a real timestamp, causing the UI to display a date decades in the past rather than "Never".
- **Scope** — Intentionally narrow: only the exact sentinel value is cleared. A broad date cutoff (e.g. "before 2001") is avoided because `last_opened_at` is shared with Linux package sources where historic timestamps are valid.
