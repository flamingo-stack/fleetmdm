Adds an `exclude` boolean column to the `mdm_configuration_profile_labels` and `mdm_declaration_labels` tables, enabling label-based exclusion logic for MDM profiles and declarations.

## Key Components

- **`Up_20240703154849`** — Idempotent migration that adds an `exclude TINYINT(1) NOT NULL DEFAULT 0` column to both `mdm_configuration_profile_labels` and `mdm_declaration_labels` if it does not already exist.
- **`Down_20240703154849`** — No-op rollback; the column is not removed on downgrade.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client during schema upgrades:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20240703154849, Down_20240703154849)
```

After this migration runs, both tables gain the `exclude` flag:

```sql
-- mdm_configuration_profile_labels
ALTER TABLE mdm_configuration_profile_labels
  ADD COLUMN exclude TINYINT(1) NOT NULL DEFAULT 0;

-- mdm_declaration_labels
ALTER TABLE mdm_declaration_labels
  ADD COLUMN exclude TINYINT(1) NOT NULL DEFAULT 0;
```

When `exclude = 1`, the associated label marks a device as **excluded** from receiving the profile or declaration, rather than targeting it for assignment.

## Notes

- The migration is **idempotent** — it checks for column existence via `columnExists` before issuing `ALTER TABLE`, making it safe to re-run.
- The rollback (`Down`) is intentionally a no-op; dropping the column is not performed to avoid data loss during downgrades.
