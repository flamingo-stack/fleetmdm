Database migration that adds an `installation_type` column to the `operating_systems` table to differentiate Windows Server Core from full desktop installations, enabling accurate MSRC vulnerability matching.

## Key Components

- **`Up_20260319120000`** — Applies the migration in three idempotent steps:
  1. Truncates `arch` values exceeding 100 characters to prevent strict SQL mode errors
  2. Shrinks `arch` from `VARCHAR(150)` to `VARCHAR(100)` (freeing 200 bytes within the 3072-byte unique index limit)
  3. Adds `installation_type VARCHAR(20)` (values: `""`, `"Client"`, `"Server"`, `"Server Core"`) and rebuilds `idx_unique_os` to include the new column — guarded by `columnExists` to make re-runs a no-op

- **`Down_20260319120000`** — No-op rollback (returns `nil`)

- **`init`** — Registers both migration functions with `MigrationClient`

## Usage Example

```go
// Applied automatically by the MigrationClient at startup.
// Manual invocation (e.g. in tests):
db, _ := sql.Open("mysql", dsn)
tx, _ := db.Begin()
if err := Up_20260319120000(tx); err != nil {
    tx.Rollback()
    log.Fatal(err)
}
tx.Commit()
```

## Notes

- **Idempotent by design**: truncating `arch`, modifying the column, and the `columnExists` guard all ensure safe re-runs.
- The `idx_unique_os` unique index now covers: `name`, `version`, `arch`, `kernel_version`, `platform`, `display_version`, `installation_type`.
