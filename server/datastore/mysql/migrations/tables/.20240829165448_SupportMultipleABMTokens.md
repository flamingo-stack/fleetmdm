Database migration file that introduces the `abm_tokens` table to support multiple Apple Business Manager (ABM) tokens per Fleet instance, migrating any existing single ABM token from the deprecated `mdm_config_assets` storage.

## Key Components

- **`Up_20240829165448`** — Applies the migration:
  - Creates the `abm_tokens` table with per-platform default team assignments (`macos_default_team_id`, `ios_default_team_id`, `ipados_default_team_id`)
  - Adds `abm_token_id` column to `host_dep_assignments` for token-to-host linkage
  - Migrates any existing ABM token from `mdm_config_assets` into the new table, preserving `terms_expired` and default team settings
  - Soft-deletes the deprecated token entry using a `deletion_uuid`
  - Backfills `host_dep_assignments.abm_token_id` for all active DEP enrollments

- **`Down_20240829165448`** — No-op rollback (returns `nil`)

## Usage Example

This migration is registered automatically via `init()` and executed by the Fleet migration runner:

```go
func init() {
    MigrationClient.AddMigration(Up_20240829165448, Down_20240829165448)
}
```

To apply manually during development:

```bash
fleet prepare db --config fleet.yml
```

## Notes

- The migration is **idempotent** — `CREATE TABLE IF NOT EXISTS` and `columnExists` guards prevent failures on re-run.
- `organization_name`, `apple_id`, and `renew_at` are intentionally left blank on migration; the `apple_mdm_dep_profile_assigner` cron job backfills these on first run (requires Apple API access unavailable in a DB migration context).
- Foreign keys on team ID columns use `ON DELETE SET NULL` to safely handle team deletion.
