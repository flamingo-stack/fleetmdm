Database migration that optimizes query performance on the `software_host_counts` table by replacing an outdated index with a new composite index that includes `global_stats` and a descending `hosts_count` ordering.

## Key Components

- **`Up_20251117020000`** — Drops the legacy index `idx_software_host_counts_team_id_hosts_count_software_id` and creates the optimized replacement `idx_software_host_counts_team_global_hosts_desc` on `(team_id, global_stats, hosts_count DESC, software_id)`.
- **`Down_20251117020000`** — No-op rollback; the migration is not reversed.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Index Strategy

The new index is designed to let MySQL:

1. Seek directly to a `team_id` + `global_stats` combination
2. Read rows in descending `hosts_count` order without an additional sort pass
3. Stop early once the `LIMIT` is satisfied

Both the `UP` and index creation steps are idempotent — they check for index existence before acting, making re-runs safe.

## Usage Example

This migration is applied automatically via the migration client:

```go
// Registered automatically on package import via init()
MigrationClient.AddMigration(Up_20251117020000, Down_20251117020000)

// To apply manually in tests or tooling:
err := Up_20251117020000(tx)
if err != nil {
    log.Fatalf("migration failed: %v", err)
}
```
