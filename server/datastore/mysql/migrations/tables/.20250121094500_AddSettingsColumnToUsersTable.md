Database migration that adds a `settings` JSON column to the `users` table, with idempotent up/down logic.

## Key Components

- **`Up_20250121094500`** — Checks if the `settings` column exists on the `users` table before adding it, making the migration safe to re-run. The column is defined as `json NOT NULL DEFAULT (JSON_OBJECT())`.
- **`Down_20250121094500`** — No-op rollback; the column is not removed on downgrade.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration is applied automatically via the `MigrationClient` during schema initialization. No direct invocation is needed.

```go
// Migration is registered on package init and run by the migration client:
MigrationClient.AddMigration(Up_20250121094500, Down_20250121094500)

// Effective SQL applied during Up:
// ALTER TABLE users ADD COLUMN settings json NOT NULL DEFAULT (JSON_OBJECT())
```

## Notes

- The migration is **idempotent**: `columnExists(tx, "users", "settings")` guards against duplicate column errors if the migration is applied more than once.
- The rollback (`Down`) is intentionally a no-op — dropping the column was deemed unnecessary for this migration.
