Database migration that adds the `FLEET_VAR_SCEP_RENEWAL_ID` fleet variable to the `fleet_variables` table, supporting SCEP certificate renewal tracking.

## Key Components

- **`Up_20250430103833`** — Inserts the `FLEET_VAR_SCEP_RENEWAL_ID` row into `fleet_variables` using `INSERT IGNORE` for idempotency. Uses a deterministic `created_at` timestamp (`2025-04-30 UTC`) to ensure reproducible schema generation.
- **`Down_20250430103833`** — No-op rollback; the variable insertion is considered non-destructive to reverse automatically.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

This migration runs automatically via the Fleet migration framework. To apply manually:

```bash
# Apply all pending migrations (includes this one)
fleet prepare db --config /etc/fleet/fleet.yml
```

To verify the variable was inserted:

```sql
SELECT name, is_prefix, created_at
FROM fleet_variables
WHERE name = 'FLEET_VAR_SCEP_RENEWAL_ID';
```

## Notes

- Uses `INSERT IGNORE` — safe to run multiple times without duplicating rows.
- The fixed `created_at` date ensures the generated schema diff is deterministic across environments.
- The rollback is intentionally a no-op; removing this variable would require a separate cleanup migration.
