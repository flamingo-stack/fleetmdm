Database migration that adds a `built_in` boolean column to the `decorators` table, enabling distinction between system-provided and user-created decorator entries.

## Key Components

- **`Up_20170309100733`** — Idempotently adds `built_in TINYINT(1) NOT NULL DEFAULT FALSE` to the `decorators` table. Checks for column existence before executing the `ALTER TABLE` to avoid duplicate-column errors on re-runs.
- **`Down_20170309100733`** — Reverses the migration by dropping the `built_in` column from `decorators`.
- **`init()`** — Registers both migration functions with `MigrationClient` at package load time.

## Usage Example

```go
// Migrations are auto-registered via init() and run by the migration client.
// To apply:
MigrationClient.Up()

// To roll back:
MigrationClient.Down()
```

> The `Up` function is safe to run multiple times — it uses `columnExists` to skip the `ALTER TABLE` if `built_in` is already present.

## Notes

- Column type `TINYINT(1)` is the standard MySQL boolean representation; defaults to `FALSE` (0) for all existing rows on migration.
