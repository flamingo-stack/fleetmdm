Database migration that creates the `mdm_config_assets` table for storing MDM (Mobile Device Management) configuration assets with soft-delete support and checksum integrity tracking.

## Key Components

- **`Up_20240521143023`** — Creates the `mdm_config_assets` table with the following columns:
  - `id` — Auto-increment primary key
  - `name` — Human-readable asset identifier (varchar 256, utf8mb4)
  - `value` — Raw asset data stored as `longblob`
  - `deleted_at` — Nullable timestamp for soft-delete auditing
  - `deletion_uuid` — UUID paired with `deleted_at` to enforce uniqueness of active records
  - `md5_checksum` — Binary MD5 checksum of the `value` column for integrity verification
  - `created_at` — Record creation timestamp
  - **Unique key** on `(name, deletion_uuid)` ensuring only one non-deleted row per asset name
- **`Down_20240521143023`** — No-op rollback (table drop not implemented)

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Migration is registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20240521143023, Down_20240521143023)
}

// Run programmatically during application startup
err := MigrationClient.Up(db, "")
if err != nil {
    log.Fatalf("migration failed: %v", err)
}
```

## Notes

- Migration is **idempotent** — uses `CREATE TABLE IF NOT EXISTS`, safe to run multiple times
- Soft-delete pattern: active records have `deletion_uuid = ''`; deleted records set a non-empty UUID alongside `deleted_at`, allowing the unique constraint to permit multiple deleted entries with the same name
