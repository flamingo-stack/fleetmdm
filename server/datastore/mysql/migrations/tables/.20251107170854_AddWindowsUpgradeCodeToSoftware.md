Database migration that adds `upgrade_code` columns to the `software_titles` and `software` tables to support Windows upgrade code tracking for MSI-based software.

## Key Components

- **`Up_20251107170854`** — Applies the migration:
  - Adds `upgrade_code CHAR(38)` column to `software_titles` and `software` tables (idempotent via `columnExists` checks). The `CHAR(38)` accommodates the standard Windows upgrade code GUID format: 32 hex chars + 4 hyphens + `{}` braces.
  - Sets `upgrade_code = ''` (empty string) for all rows where `source = 'programs'`, distinguishing Windows programs without a GUID from `NULL` (unknown).
  - Updates the `unique_identifier` virtual generated column on `software_titles` to include `NULLIF(upgrade_code, "")` in its `COALESCE` chain, preventing empty-string upgrade codes from being used as unique identifiers.

- **`Down_20251107170854`** — No-op rollback (columns are not removed).

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20251107170854, Down_20251107170854)
```

The resulting `unique_identifier` expression after migration:

```sql
COALESCE(
  bundle_identifier,
  application_id,
  NULLIF(upgrade_code, ""),  -- only used when non-empty
  name
)
```

> **Note:** The migration is idempotent — re-running `Up_20251107170854` safely skips `ALTER TABLE` statements if the columns already exist.
