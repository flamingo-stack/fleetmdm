Database migration that updates the checksum calculation for software records by including the `name` field in the MD5 hash computation for macOS apps with a bundle identifier.

## Key Components

- **`Up_20251015103505`** — Updates the `checksum` column for all rows in the `software` table where `source = 'apps'` and `bundle_identifier` is non-null/non-empty. Recomputes the MD5 hash using `CONCAT_WS` with a null-byte (`CHAR(0)`) separator across: `version`, `source`, `bundle_identifier`, `release`, `arch`, `vendor`, `browser`, `extension_id`, and `name`.
- **`Down_20251015103505`** — No-op rollback; the migration is marked idempotent and safe to re-run.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
MigrationClient.AddMigration(Up_20251015103505, Down_20251015103505)
```

To apply manually during development:

```bash
fleet db migrate
```

## Notes

- **Scope**: Only affects rows where `source = 'apps'` and `bundle_identifier` is populated — targeting macOS application records.
- **Idempotent**: Re-running the `Up` function produces the same result, making it safe for retries.
- **Field added**: `name` is appended as the last field in the `CONCAT_WS` expression, changing how duplicate software is identified/deduplicated.
