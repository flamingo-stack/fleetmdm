Database migration that integrates in-house (custom) iOS apps into the unified activity queue and installation tracking system.

## Key Components

- **`Up_20251028140300`** — Applies three schema changes:
  1. Extends the `upcoming_activities.activity_type` ENUM to include `in_house_app_install`
  2. Creates `in_house_app_upcoming_activities` — links pending in-house app installs to the unified activity queue with FK constraints for cascade cleanup
  3. Creates `host_in_house_software_installs` — tracks MDM command-based in-house app installations per host, mirroring the existing `host_vpp_software_installs` table

- **`Down_20251028140300`** — No-op rollback (intentionally empty)

## Schema Notes

- The ENUM extension is idempotent (guarded by `columnExists` check); `software_uninstall` for in-house apps is intentionally omitted as uninstall was unsupported at migration time
- `in_house_app_upcoming_activities` uses individual FK columns (not JSON) to enable efficient `ON DELETE` cascade processing during activity queue execution
- `host_in_house_software_installs` includes MDM verification tracking fields (`verification_command_uuid`, `verification_at`, `verification_failed_at`) and a functional index on unverified installs
- Both tables use `DATETIME(6)` over `TIMESTAMP` to avoid the Y2K38 overflow issue
