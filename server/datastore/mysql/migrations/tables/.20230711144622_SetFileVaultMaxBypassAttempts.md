Database migration that adds `DeferForceAtUserLoginMaxBypassAttempts` to existing FileVault MDM configuration profiles stored in the `mdm_apple_configuration_profiles` table.

## Key Components

- **`setBypassAttemptsToFileVaultProfile(original []byte) ([]byte, error)`** — Parses a plist mobileconfig, locates the `com.apple.MCX.FileVault2` payload, injects `DeferForceAtUserLoginMaxBypassAttempts = 1`, and re-serializes to XML plist format.
- **`Up_20230711144622(tx *sql.Tx) error`** — Migration up function; fetches all FileVault profiles by identifier `com.fleetdm.fleet.mdm.filevault`, applies the bypass attempts patch, and updates each row including a recalculated MD5 checksum.
- **`Down_20230711144622(tx *sql.Tx) error`** — No-op rollback (migration is intentionally not reversible).

## Usage Example

This migration runs automatically via the migration client registration in `init()`. The core helper can also be used directly:

```go
originalPlist, _ := os.ReadFile("filevault.mobileconfig")

updatedPlist, err := setBypassAttemptsToFileVaultProfile(originalPlist)
if err != nil {
    log.Fatalf("failed to patch profile: %v", err)
}

// updatedPlist now contains DeferForceAtUserLoginMaxBypassAttempts = 1
// under the com.apple.MCX.FileVault2 payload
os.WriteFile("filevault_updated.mobileconfig", updatedPlist, 0644)
```

> **Note:** The migration is idempotent — if no FileVault profiles exist, it exits early without error. The plist round-trip uses `map[string]interface{}` to avoid unintended schema changes during deserialization.
