Database migration that updates the `batch_activities` table schema by adding new columns, renaming an existing column, and dropping an obsolete one.

## Key Components

- **`Up_20250807140441`** — Applies the migration idempotently (checks for column existence before executing). Performs the following changes to `batch_activities`:
  - Adds `started_at` (`datetime NULL`) after `updated_at`
  - Adds `canceled` (`bool DEFAULT false`) after `finished_at`
  - Renames `completed_at` → `finished_at`
  - Drops `canceled_at`
- **`Down_20250807140441`** — No-op rollback; schema changes are not reversed.
- **`init`** — Registers both migration functions with `MigrationClient`.

## Usage Example

```go
// Migration is registered automatically via init().
// Apply via the migration client:
MigrationClient.RunMigrations(db)

// Idempotency check — safe to run multiple times:
// If "started_at" already exists, the ALTER TABLE is skipped.
```

## Notes

- The migration is **idempotent**: it checks for the presence of `started_at` using `columnExists` before executing the `ALTER TABLE` statement, preventing duplicate-column errors on re-runs.
- The `Down` function is intentionally empty — destructive schema changes (column drops/renames) are not automatically reversible.
- Part of the [`flamingo-stack/fleetmdm`](https://github.com/flamingo-stack/fleetmdm/blob/main/db/migrations/tables/20250807140441_UpdateActivityTable.go) migration sequence managed by `MigrationClient`.
