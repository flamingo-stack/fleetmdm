Database migration that updates the `hosts` full-text search index and introduces a dedicated `host_display_names` table for efficient host display name lookups.

## Key Components

- **`Up_20220915165116`** — Applies the migration:
  - Recreates the `hosts_search` fulltext index on `hosts(hostname, uuid, computer_name)` (idempotent drop-then-create)
  - Creates the `host_display_names` table with a primary key on `host_id` and an index on `display_name`
  - Backfills `host_display_names` from existing hosts, using `computer_name` when non-empty, otherwise falling back to `hostname`

- **`Down_20220915165116`** — No-op rollback; the migration is not reversible.

## Schema Changes

```sql
-- Recreated fulltext index
CREATE FULLTEXT INDEX hosts_search ON hosts(hostname, uuid, computer_name);

-- New table
CREATE TABLE host_display_names (
    host_id     int(10) unsigned NOT NULL,
    display_name varchar(255)    NOT NULL,
    PRIMARY KEY (host_id),
    KEY (display_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## Display Name Logic

The backfill query resolves each host's display name using:

```sql
IF(computer_name = '', hostname, computer_name)
```

This ensures human-readable names take priority over raw hostnames where available.

## Notes

- The `Up` migration is **idempotent**: it checks index existence before dropping or creating `hosts_search`, making it safe to re-run.
- `INSERT IGNORE` prevents duplicate-key errors if partial data already exists in `host_display_names`.
- The `Down` migration is intentionally empty — restoring the previous index state is not implemented.
