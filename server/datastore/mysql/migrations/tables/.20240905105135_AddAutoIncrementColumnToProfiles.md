Adds an `auto_increment` column to MDM profile tables to reliably detect row updates from `INSERT ... ON DUPLICATE KEY UPDATE` statements when using the `CLIENT_FOUND_ROWS` MySQL option.

## Key Components

- **`Up_20240905105135`** — Idempotent migration that adds a `BIGINT NOT NULL AUTO_INCREMENT UNIQUE` column named `auto_increment` to:
  - `mdm_windows_configuration_profiles`
  - `mdm_apple_declarations`
- **`Down_20240905105135`** — No-op rollback (column removal is not performed).

## Why This Migration Exists

MySQL's `CLIENT_FOUND_ROWS` flag causes `ROW_COUNT()` to return the number of rows *matched* rather than *changed*, making it impossible to distinguish a true update from a no-op. By checking `LAST_INSERT_ID()` against this auto-increment column, the application can reliably determine whether a row was actually updated by an `INSERT ... ON DUPLICATE KEY UPDATE`.

See: [MySQL 8.4 Docs — INSERT ON DUPLICATE KEY](https://dev.mysql.com/doc/refman/8.4/en/insert-on-duplicate.html)

## Usage Example

This migration runs automatically via the `MigrationClient` on startup. The added column can be used post-insert to detect updates:

```go
// After INSERT ... ON DUPLICATE KEY UPDATE
lastID, err := result.LastInsertId()
if err != nil {
    return err
}
// lastID > 0 means a new row was inserted or the row was updated
if lastID != 0 {
    // row was modified
}
```
