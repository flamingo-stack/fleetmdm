Database migration (timestamp `20240515200020`) that creates two tables — `software_installers` and `host_software_installs` — to support software installer management and per-host installation tracking.

## Key Components

### `Up_20240515200020(tx *sql.Tx) error`
Applies the migration by creating two tables:

- **`software_installers`** — Stores uploaded software installers per team, linked to a software title, with references to install/post-install script contents, pre-install osquery conditions, and a storage ID pointing to the installer bytes.

| Column | Description |
|---|---|
| `team_id` / `global_or_team_id` | Team scoping; `global_or_team_id` enables a unique index since `team_id` allows `NULL` |
| `title_id` | FK → `software_titles` |
| `install_script_content_id` | FK → `script_contents` (required) |
| `post_install_script_content_id` | FK → `script_contents` (optional) |
| `storage_id` | Reference to external installer storage |

- **`host_software_installs`** — Tracks per-host installation execution results including pre-install query output, script exit codes, and the requesting user.

| Column | Description |
|---|---|
| `execution_id` | Unique run identifier (e.g. UUID) |
| `host_id` | Soft reference to `hosts` (deleted in app logic) |
| `software_installer_id` | FK → `software_installers` |
| `install_script_exit_code` / `post_install_script_exit_code` | Exit codes for auditing |

### `Down_20240515200020(tx *sql.Tx) error`
No-op rollback — returns `nil` without dropping tables.

## Usage Example

This migration is registered automatically via `init()` and executed by the migration client:

```go
// Registered automatically on package import
func init() {
    MigrationClient.AddMigration(Up_20240515200020, Down_20240515200020)
}

// Applied by the migration runner — not called directly
err := MigrationClient.Up(db, "")
```

> Both `CREATE TABLE` statements use `IF NOT EXISTS`, making the migration idempotent and safe to re-run.
