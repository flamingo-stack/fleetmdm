Database migration that creates the `decorators` table, used to store osquery decorator configurations that augment query results with additional metadata.

## Key Components

- **`Up_20170108191242`** — Creates the `decorators` table with the following schema:

| Column | Type | Description |
|---|---|---|
| `id` | `INT UNSIGNED AUTO_INCREMENT` | Primary key |
| `created_at` | `TIMESTAMP` | Record creation time |
| `updated_at` | `TIMESTAMP` | Last update time |
| `query` | `VARCHAR(255)` | The decorator SQL query |
| `type` | `INT UNSIGNED` | Decorator type identifier |
| `interval` | `INT UNSIGNED` | Execution interval |

- **`Down_20170108191242`** — Drops the `decorators` table (rollback).
- **`init()`** — Registers both migration functions with `MigrationClient` on package load.

## Usage Example

This migration is applied automatically via the migration client. To run manually:

```go
// Applied as part of the migration chain
MigrationClient.AddMigration(Up_20170108191242, Down_20170108191242)

// Up (apply)
err := Up_20170108191242(tx)

// Down (rollback)
err := Down_20170108191242(tx)
```

> The `Up` function uses `CREATE TABLE IF NOT EXISTS`, making it idempotent and safe to run multiple times.
