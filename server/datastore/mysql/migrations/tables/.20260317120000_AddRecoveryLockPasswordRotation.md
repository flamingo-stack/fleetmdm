Database migration that adds two columns to the `host_recovery_key_passwords` table to support pending password rotation state tracking for MDM-managed recovery keys.

## Key Components

- **`Up_20260317120000`** — Idempotently adds `pending_encrypted_password` (BLOB) and `pending_error_message` (TEXT) columns to `host_recovery_key_passwords`, guarded by a `columnsExists` check
- **`Down_20260317120000`** — No-op rollback; columns are left in place on downgrade
- **`init`** — Registers the migration pair with `MigrationClient`

### New Columns

| Column | Type | Purpose |
|---|---|---|
| `pending_encrypted_password` | `BLOB DEFAULT NULL` | Holds the new password during rotation until MDM confirms success |
| `pending_error_message` | `TEXT utf8mb4_unicode_ci DEFAULT NULL` | Captures rotation-specific errors, separate from install/remove `error_message` |

## Usage Example

This migration runs automatically via the Fleet migration runner. To apply or roll back manually:

```go
// Apply
err := Up_20260317120000(tx)

// Rollback (no-op)
err := Down_20260317120000(tx)
```

To trigger via the Fleet CLI:

```bash
fleet prepare db --config /path/to/fleet.yml
```
