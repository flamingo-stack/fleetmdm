MySQL datastore implementation for managing host upcoming activities and related cleanup operations in the Fleet MDM platform.

## Key Components

- **`ListHostUpcomingActivities`** — Queries a unified virtual queue of pending host tasks (scripts, software installs/uninstalls, VPP apps, in-house apps) by joining multiple task-specific tables via `UNION ALL`. Returns paginated `UpcomingActivity` results with metadata.
- **`CleanupExpiredLiveQueries`** — Deletes expired unsaved live queries in batches of `deleteIDsBatchSize` (1000) to prevent unbounded table growth.
- **`hostUpcomingActivitiesAllowedOrderKeys`** — Empty allowlist enforcing that ordering is handled internally by the query (topmost → priority → created_at).
- **`deleteIDsBatchSize`** — Package-level batch size constant (1000) for bulk delete operations.

## Usage Example

```go
// List upcoming activities for a host with pagination
activities, meta, err := ds.ListHostUpcomingActivities(ctx, hostID, fleet.ListOptions{
    Page:    0,
    PerPage: 20,
})
if err != nil {
    return err
}
for _, a := range activities {
    fmt.Printf("Activity: %s (%s)\n", a.ActivityType, a.UUID)
}
fmt.Printf("Total: %d, HasNext: %v\n", meta.TotalResults, meta.HasNextResults)

// Clean up live queries older than 7 days
if err := ds.CleanupExpiredLiveQueries(ctx, 7); err != nil {
    log.Error("cleanup failed", err)
}
```

## Notes

- The unified queue orders results: activated tasks first (`topmost DESC`), then by `priority DESC`, then oldest-first (`created_at ASC`).
- Activity payloads carry a JSON `details` blob containing type-specific metadata (script names, software titles, policy associations, etc.).
- User attribution falls back to JSON payload fields when the originating user record no longer exists.
