Handles persistent storage operations for user email change requests, providing atomic creation and confirmation of pending email change records in MySQL.

## Key Components

- **`PendingEmailChange`** — Inserts a new email change record into the `email_changes` table, associating a user ID, a verification token, and the desired new email address.
- **`ConfirmPendingEmailChange`** — Atomically validates a token-based email change request, updates the user's email in the `users` table, and deletes the consumed change record — all within a retryable transaction.

## Usage Example

```go
// Create a pending email change request
err := ds.PendingEmailChange(ctx, userID, "newemail@example.com", "secure-token-abc123")
if err != nil {
    log.Fatal(err)
}

// Confirm the change using the token sent to the user
newEmail, err := ds.ConfirmPendingEmailChange(ctx, userID, "secure-token-abc123")
if err != nil {
    log.Fatal(err)
}
fmt.Println("Email updated to:", newEmail)
```

## Notes

- `ConfirmPendingEmailChange` uses `withRetryTxx` to ensure the read-modify-delete sequence is executed atomically, guarding against partial updates on transient failures.
- Returns a `notFound` error if no matching token/user pair exists in `email_changes`, or if the target user row is missing at update time.
- The change record is deleted only after the user update succeeds, preventing orphaned tokens.
