MySQL datastore implementation for managing password reset request lifecycle, including creation, lookup, deletion, and expiration cleanup.

## Key Components

| Function | Description |
|---|---|
| `NewPasswordResetRequest` | Inserts a new password reset record with a 24-hour expiry window |
| `DeletePasswordResetRequestsForUser` | Removes all reset requests associated with a given user ID |
| `FindPasswordResetByToken` | Looks up a valid (non-expired) reset request by token |
| `CleanupExpiredPasswordResetRequests` | Deletes all records where the expiry timestamp has passed |

**Constant:** `PasswordResetRequestDuration = 24 * time.Hour` — token validity window passed to MySQL as minutes via `DATE_ADD`.

## Usage Example

```go
// Create a new reset request
req := &fleet.PasswordResetRequest{
    UserID: 42,
    Token:  "secure-random-token",
}
created, err := ds.NewPasswordResetRequest(ctx, req)

// Validate a token from an incoming request
reset, err := ds.FindPasswordResetByToken(ctx, "secure-random-token")
if err != nil {
    // Token invalid or expired
}

// Clean up after a successful reset
err = ds.DeletePasswordResetRequestsForUser(ctx, reset.UserID)

// Run periodically to purge stale records
err = ds.CleanupExpiredPasswordResetRequests(ctx)
```

## Notes

- Reads use `ds.reader(ctx)`; all writes use `ds.writer(ctx)`, following the datastore's read/write replica pattern.
- `FindPasswordResetByToken` treats `sql.ErrNoRows` as an invalid/expired token error rather than a generic DB error.
- Expiry is enforced at the DB level (`CURRENT_TIMESTAMP < expires_at`), preventing use of tokens beyond the 24-hour window even without running the cleanup job.
