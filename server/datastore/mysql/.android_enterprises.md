MySQL datastore implementation for managing Android Enterprise records, providing CRUD operations against the `android_enterprises` table.

## Key Components

| Function | Description |
|---|---|
| `CreateEnterprise` | Inserts a new enterprise row associated with a user ID, returning the generated record ID |
| `GetEnterpriseByID` | Fetches full enterprise details by primary key |
| `GetEnterpriseBySignupToken` | Fetches full enterprise details by signup token |
| `GetEnterprise` | Returns the first active enterprise (one with a non-empty `enterprise_id`) |
| `UpdateEnterprise` | Updates signup name, enterprise ID, Pub/Sub topic, and signup token for an existing record |
| `DeleteOtherEnterprises` | Removes all enterprise rows except the one matching the given ID |
| `DeleteAllEnterprises` | Transactionally deletes all enterprises and all Android VPP app assignments |

## Usage Example

```go
// Create a new enterprise record tied to a user
enterpriseID, err := ds.CreateEnterprise(ctx, userID)
if err != nil {
    // handle error
}

// Retrieve and update the enterprise
enterprise, err := ds.GetEnterpriseByID(ctx, enterpriseID)
if err != nil {
    // handle error
}
enterprise.EnterpriseID = "LC03..."
enterprise.SignupToken  = "token123"
err = ds.UpdateEnterprise(ctx, enterprise)

// Remove all stale enterprises, keeping only the active one
err = ds.DeleteOtherEnterprises(ctx, enterpriseID)

// Fully reset Android MDM state (enterprises + app assignments)
err = ds.DeleteAllEnterprises(ctx)
```

## Notes

- Read operations use `ds.reader(ctx)` (replica-safe); writes use `ds.Writer(ctx)`.
- `DeleteAllEnterprises` wraps both `DELETE` statements in a transaction via `ds.WithTxx` to keep Fleet's state consistent with AMAPI.
- Not-found conditions return typed `common_mysql.NotFound` errors rather than raw `sql.ErrNoRows`.
