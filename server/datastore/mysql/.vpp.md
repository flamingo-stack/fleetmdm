MySQL datastore implementation for VPP (Volume Purchase Program) app management, providing CRUD operations and status tracking for app store applications across Apple (iOS/iPadOS/macOS) and Android platforms within the Fleet MDM system.

## Key Components

| Function | Description |
|---|---|
| `GetVPPAppMetadataByTeamAndTitleID` | Retrieves full VPP app metadata including labels, categories, configuration, and policies for a given team and title ID |
| `getCategoriesForVPPApp` | Fetches software category names associated with a VPP app team entry |
| `getVPPAppLabels` | Retrieves scoped labels (include/exclude, require-all/any) for a VPP app team entry |
| `GetSummaryHostVPPAppInstalls` | Aggregates install status counts (pending/failed/installed) across hosts for a specific VPP app and team |
| `vppAppHostStatusNamedQuery` | Builds a reusable SQL `CASE` expression for computing per-host VPP install status from `host_vpp_software_installs` and `nano_command_results` |
| `BatchInsertVPPApps` | Transactionally inserts multiple VPP apps, resolving or creating their software title records |
| `getExistingLabels` | Retrieves and categorizes existing scope labels for a VPP app team entry |

## Usage Example

```go
// Get full metadata for a VPP app scoped to a team
teamID := uint(42)
app, err := ds.GetVPPAppMetadataByTeamAndTitleID(ctx, &teamID, titleID)
if err != nil {
    return err
}
fmt.Println(app.Name, app.Platform, app.Categories)

// Summarize install status across hosts for an app
appID := fleet.VPPAppID{AdamID: "123456789", Platform: fleet.IOSPlatform}
summary, err := ds.GetSummaryHostVPPAppInstalls(ctx, &teamID, appID)
if err != nil {
    return err
}
fmt.Printf("Pending: %d, Installed: %d, Failed: %d\n",
    summary.Pending, summary.Installed, summary.Failed)

// Batch insert new VPP apps
err = ds.BatchInsertVPPApps(ctx, []*fleet.VPPApp{app1, app2})
```

## Notes

- Status aggregation uses a CTE pattern separating **upcoming** (queued) and **past** (historical) activities, with upcoming taking precedence via an anti-join.
- `vppAppHostStatusNamedQuery` is kept in sync with `GetSummaryHostVPPAppInstalls` — both must be updated together if status logic changes.
- Android VPP apps skip MDM command result (`nano_command_results`) checks since Android never produces an MDM command record.
