Provides MySQL datastore methods for computing and persisting aggregated performance statistics (p50/p95 percentiles and total executions) for Fleet scheduled queries.

## Key Components

### Constants
- `aggregatedStatsType*` — string identifiers for supported stat categories: Munki versions/issues, OS versions, policy violation days, and partial MDM status/solutions types.
- `scheduledQueryPercentileQuery` — parameterized SQL template computing a percentile value using a row-number approach (compatible with MySQL's lack of native `PERCENTILE_CONT`).
- `scheduledQueryTotalExecutions` — simple aggregate query summing total executions for a scheduled query.

### Functions

| Function | Description |
|---|---|
| `getPercentileQuery` | Returns the correct percentile SQL for a given `AggregatedStatsType` and time metric. |
| `setP50AndP95Map` | Executes p50 and p95 percentile queries for a time metric (e.g., `user_time`) and populates a stats map. |
| `getTotalExecutionsQuery` | Returns the total-executions SQL for a given `AggregatedStatsType`. |
| `walkIdsInTable` | Iterates all IDs in a named table, calling a visitor function for each. |
| `UpdateQueryAggregatedStats` | Walks all query IDs and triggers percentile recalculation for each. |
| `CalculateAggregatedPerfStatsPercentiles` | Core method: computes p50/p95 for `user_time` and `system_time`, fetches total executions, then upserts results into `aggregated_stats`. |

## Usage Example

```go
// Trigger a full recalculation of aggregated stats for all queries
if err := ds.UpdateQueryAggregatedStats(ctx); err != nil {
    log.Fatalf("failed to update aggregated stats: %v", err)
}

// Or recalculate for a single query ID directly
err := ds.CalculateAggregatedPerfStatsPercentiles(
    ctx,
    fleet.AggregatedStatsTypeScheduledQuery,
    queryID,
)
```

Stats are upserted into the `aggregated_stats` table with `global_stats=0`, keyed by `(id, type)`.
