Provides MySQL datastore methods for managing host script execution requests, results, and pending execution queues within the Fleet MDM platform.

## Key Components

| Function | Description |
|---|---|
| `NewHostScriptExecutionRequest` | Enqueues a user-initiated script run for a host |
| `NewInternalHostScriptExecutionRequest` | Enqueues a fleet-initiated script run (bypasses global disable setting) |
| `newHostScriptExecutionRequestPublic` | Shared logic for both public/internal enqueue paths; creates script contents if needed |
| `insertNewHostScriptExecution` | Inserts into `upcoming_activities` and `script_upcoming_activities`, then activates the next pending activity |
| `SetHostScriptExecutionResult` | Stores script output, exit code, and runtime; triggers lock/unlock/wipe/uninstall post-processing |
| `ListPendingHostScriptExecutions` | Returns all queued script executions for a host |
| `ListReadyToExecuteScriptsForHost` | Returns only activated (ready) script executions for a host |
| `IsExecutionPendingForHost` | Checks whether a specific script is already queued for a host |
| `truncateScriptResult` | Trims output to a maximum of 10,000 UTF-8 runes, keeping the trailing portion |

## Usage Example

```go
// Enqueue a user-requested script execution
result, err := ds.NewHostScriptExecutionRequest(ctx, &fleet.HostScriptRequestPayload{
    HostID:          42,
    ScriptContentID: 7,
    UserID:          ptr.Uint(1),
    SyncRequest:     false,
})

// Store the result when the host responds
hsr, action, err := ds.SetHostScriptExecutionResult(ctx, &fleet.HostScriptResultPayload{
    HostID:      42,
    ExecutionID: result.ExecutionID,
    Output:      "script output here",
    ExitCode:    0,
    Runtime:     1.23,
}, nil)

// List scripts ready to run on a host
pending, err := ds.ListReadyToExecuteScriptsForHost(ctx, 42, false)
```

## Notes

- Internal scripts (via `NewInternalHostScriptExecutionRequest`) set `fleet_initiated = true` and are excluded from the user-facing activity feed.
- Script output is truncated to **10,000 runes** (trailing portion preserved) before storage.
- On result receipt, post-processing automatically updates `host_mdm_actions` for lock, unlock, wipe, or uninstall workflows.
- Duplicate result submissions are silently ignored while still advancing the activity queue.
