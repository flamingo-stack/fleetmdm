MySQL datastore implementation for user session and MFA (Multi-Factor Authentication) token management, providing CRUD operations for sessions and verification tokens.

## Key Components

| Function | Description |
|---|---|
| `SessionByMFAToken` | Validates an MFA token, creates a new session, and atomically deletes the consumed token |
| `NewMFAToken` | Generates and stores a cryptographically random URL-safe MFA verification token |
| `SessionByKey` | Retrieves a session by its session key string |
| `SessionByID` | Retrieves a session by its numeric ID |
| `ListSessionsForUser` | Returns all active sessions for a given user ID |
| `NewSession` | Creates a new session for a user with a randomly generated key |
| `makeSessionInTransaction` | Internal helper that inserts a session row within an existing transaction |
| `DestroySession` | Deletes a single session record |
| `DestroyAllSessionsForUser` | Deletes all sessions belonging to a user |
| `MarkSessionAccessed` | Updates the `accessed_at` timestamp for a session |

## Usage Example

```go
// Create a new session
session, err := ds.NewSession(ctx, userID, sessionKeySize)

// Look up session by key (e.g. from request header)
session, err := ds.SessionByKey(ctx, sessionKey)

// MFA flow: issue a token, then exchange it for a session
token, err := ds.NewMFAToken(ctx, userID)
// (send token to user via email/SMS)
session, user, err := ds.SessionByMFAToken(ctx, token, sessionKeySize)

// Invalidate a single session on logout
err = ds.DestroySession(ctx, session)

// Invalidate all sessions (e.g. password reset)
err = ds.DestroyAllSessionsForUser(ctx, userID)

// Refresh accessed_at on each authenticated request
err = ds.MarkSessionAccessed(ctx, session)
```

## Notes

- MFA tokens are 32-byte URL-safe random strings stored in `verification_tokens` and expire after `fleet.MFALinkTTL`.
- `SessionByMFAToken` uses a transaction to ensure the token is only deleted after the session is successfully created.
- `MarkSessionAccessed` triggers a fatal error on MySQL read-only errors to prevent silent failures in replicated setups.
