Implements the `PATCH /debug/trace_sampler` HTTP handler, allowing administrators to dynamically adjust trace sampling ratios and force-full-trace mode without restarting the Fleet server.

## Key Components

- **`traceSamplerPatchRequest`** — PATCH request payload using pointer fields to support partial updates (PATCH semantics); accepts `high_volume_ratio`, `standard_ratio`, and `force_full`.
- **`patchTraceSamplerHandler`** — Returns an `http.HandlerFunc` that validates the viewer context, decodes and validates the request body, performs a read-modify-write on sampler settings via the datastore, logs the change with the acting user ID, and returns the updated settings as JSON.
- **`validateTraceSamplerPatch`** — Ensures at least one field is present and that ratio values fall within `[0, 1]`.
- **`handleServerError`** — Shared helper that logs the error, attaches it to the request context for middleware error tracking, and writes a `500` response to the client.

## Usage Example

```go
// Wire the handler in your debug router setup
mux.Handle("PATCH /debug/trace_sampler", patchTraceSamplerHandler(logger, ds))
```

```bash
# Partially update only the standard sampling ratio
curl -X PATCH https://fleet.example.com/debug/trace_sampler \
  -H "Content-Type: application/json" \
  -d '{"standard_ratio": 0.25}'

# Enable force-full tracing
curl -X PATCH https://fleet.example.com/debug/trace_sampler \
  -H "Content-Type: application/json" \
  -d '{"force_full": true}'
```

> **Note:** Changes are persisted to the datastore immediately, but in-memory samplers on replica nodes pick up the new settings on the next poller tick (default 60 seconds).
