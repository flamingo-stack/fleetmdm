Defines structured service-layer error types used throughout the Fleet MDM service package, providing semantic error classification for client error handling, SSO flows, and GitOps validation.

## Key Components

| Type | Description |
|---|---|
| `alreadyExistsError` | Signals a duplicate entity conflict; implements `IsExists()` and `IsClientError()` |
| `notFoundError` | Signals a missing resource lookup; implements `IsNotFound()` and `IsClientError()` |
| `ssoErrCode` | Typed string constant for classifying SSO failure reasons |
| `ssoError` | Wraps an underlying error with an SSO-specific code; supports `errors.Unwrap()` |
| `gitOpsValidationError` | Captures YAML spec validation failures with optional file path context |

### SSO Error Codes

| Constant | Value |
|---|---|
| `ssoOtherError` | `"error"` |
| `ssoOrgDisabled` | `"org_disabled"` |
| `ssoAccountDisabled` | `"account_disabled"` |
| `ssoAccountInvalid` | `"account_invalid"` |

## Usage Example

```go
// Not-found and already-exists errors
err := newNotFoundError()
if e, ok := err.(interface{ IsNotFound() bool }); ok && e.IsNotFound() {
    // return 404 to client
}

// SSO error with classification code
ssoErr := newSSOError(fmt.Errorf("user not provisioned"), ssoAccountInvalid)
fmt.Println(ssoErr.Error()) // "account_invalid: user not provisioned"

// GitOps validation error with file context
valErr := newGitOpsValidationError("missing required field 'name'")
ctxErr := valErr.WithFileContext("/repo/base", "teams/eng.yml")
fmt.Println(ctxErr) 
// Couldn't edit "teams/eng.yml" at: "/repo/base/teams/eng.yml". missing required field 'name'
```
