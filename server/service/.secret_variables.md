Service layer implementation for managing Fleet secret variables — encrypted configuration values used across MDM profiles and scripts.

## Key Components

| Symbol | Type | Description |
|---|---|---|
| `SecretVariablePrefix` | Constant | Prefix `FLEET_SECRET_` automatically stripped from variable names on creation |
| `CreateSecretVariables` | Method | Batch upsert of secret variables; supports dry-run validation without persistence |
| `CreateSecretVariable` | Method | Creates a single named secret variable and emits an activity log entry |
| `ListSecretVariables` | Method | Paginated listing of secret variable identifiers (names only, not values) |
| `DeleteSecretVariable` | Method | Deletes a secret by ID; returns a conflict error if the secret is still in use |

**Authorization:** All operations require a configured server private key and enforce `ActionWrite` (create/delete) or `ActionRead` (list) via the `authz` middleware.

## Usage Example

```go
// Batch create/update secret variables (e.g., from a gitops spec)
err := svc.CreateSecretVariables(ctx, []fleet.SecretVariable{
    {Name: "FLEET_SECRET_API_KEY", Value: "supersecret"},
    {Name: "DB_PASSWORD", Value: "hunter2"},
}, false /* dryRun */)

// Create a single secret variable
id, err := svc.CreateSecretVariable(ctx, "API_KEY", "supersecret")

// List with pagination
vars, meta, count, err := svc.ListSecretVariables(ctx, fleet.ListOptions{
    Page:    0,
    PerPage: 20,
})

// Delete by ID — returns ConflictError if secret is referenced by a profile/script
err = svc.DeleteSecretVariable(ctx, 42)
```

> **Note:** Variable names are normalized via `fleet.Preprocess` and validated with `fleet.ValidateSecretVariableName`. The `FLEET_SECRET_` prefix is stripped automatically before storage. A missing server private key causes all write operations to fail with a `BadRequestError`.
