Handles the full lifecycle of Fleet user invitations: creating, listing, updating, deleting, and verifying invites, including email dispatch and MFA/SSO validation.

## Key Components

| Symbol | Type | Description |
|---|---|---|
| `InviteNewUser` | Method | Creates a new invite, generates a secure token, and sends an invitation email |
| `ValidateInvite` | Method | Enforces MFA/SSO business rules — MFA requires a Premium license and is incompatible with SSO |
| `ListInvites` | Method | Returns all pending invites with pagination support |
| `UpdateInvite` | Method | Modifies an existing invite's fields, re-validating role and MFA constraints |
| `DeleteInvite` | Method | Removes an invite by ID |
| `VerifyInvite` | Method | Validates an invite token and checks expiry; skips auth since no viewer exists at this point |
| `SSOMFAConflict` | Variable | Sentinel `ConflictError` returned when both SSO and MFA are enabled on the same invite |

## Usage Example

```go
// Create a new user invite
payload := fleet.InvitePayload{
    Email:      ptr.String("newuser@example.com"),
    Name:       ptr.String("Jane Doe"),
    GlobalRole: optjson.SetString("observer"),
    SSOEnabled: ptr.Bool(false),
    MFAEnabled: ptr.Bool(true),
}
invite, err := svc.InviteNewUser(ctx, payload)

// Verify an invite token from the signup link
invite, err := svc.VerifyInvite(ctx, "abc123token")

// Delete a pending invite
err := svc.DeleteInvite(ctx, inviteID)
```

## Notes

- Email addresses are normalized to lowercase on creation.
- Duplicate checks are performed against both existing users and existing pending invites during updates.
- `VerifyInvite` skips authorization explicitly since no authenticated viewer exists during the signup flow.
- Invite token validity period is controlled by `svc.config.App.InviteTokenValidityPeriod`.
