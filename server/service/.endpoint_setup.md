Handles the Fleet server initial setup endpoint, including admin user creation, app configuration, and optional starter library scaffolding via GitOps templates.

## Key Components

| Symbol | Kind | Description |
|---|---|---|
| `setupRequest` | struct | Request payload with admin credentials, org info, server URL, and enroll secret |
| `setupResponse` | struct | Response payload returning created admin, org info, session token, and any error |
| `makeSetupEndpoint` | func | Constructs the `go-kit` endpoint that orchestrates app config creation, initial admin user setup, session login, and starter library application |
| `ApplyStarterLibrary` | func | Scaffolds starter GitOps templates via `fleetctl new` and applies them via `fleetctl gitops`; accepts a `runFleetctl` callback to keep CLI dependencies out of the service package |

## Usage Example

```go
// Wire up the setup endpoint with a custom starter library runner
applyStarterLib := func(ctx context.Context, serverURL, token string) error {
    return service.ApplyStarterLibrary(
        ctx,
        serverURL,
        token,
        logger,
        func(args []string) error {
            return fleetctl.Run(args) // your CLI runner
        },
    )
}

setupEP := makeSetupEndpoint(svc, logger, applyStarterLib)
```

`ApplyStarterLibrary` creates a temporary directory, renders templates with `fleetctl new`, writes a scoped config file with the session token, then runs `fleetctl gitops` against `default.yml` and any team YAML files found under `fleets/` (premium only). Environment variable `FLEET_URL` is injected via `spec.SetEnvOverrides` without polluting the process environment.

## Notes

- Admin creation is intentionally the **last** guarded step; a pre-existing user closes the setup endpoint permanently.
- Login failure after user creation is non-fatal — the response omits the token and the user must log in manually.
- Starter library application is best-effort; errors are logged at `Debug` level and do not fail setup.
