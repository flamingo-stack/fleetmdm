Batched Apple MDM profile reconciliation cron entry point that processes hosts in bounded windows using a Redis-persisted cursor to reduce writer pressure during bulk events.

## Key Components

- **`reconcileAppleProfilesBatchSize`** — Configurable batch size (default `5000`) controlling how many hosts are processed per cron tick; overridable in tests.
- **`ReconcileAppleProfilesBatched`** — Main entry point that orchestrates one tick of the batched reconciliation pipeline:
  - Verifies MDM is enabled and retrieves the SCEP CA certificate
  - Ensures Fleet-managed configuration profiles are in place via `ensureFleetProfiles`
  - Reads the current host UUID cursor from Redis (`GetMDMAppleReconcileCursor`)
  - Fetches a bounded snapshot of hosts, profiles, labels, and current state via `GetAppleProfileReconcileSnapshot`
  - Advances or resets the cursor on completion; leaves it unchanged on error
  - Delegates delta computation to `apple_mdm.ComputeReconcileDeltas` and execution to `apple_mdm.ExecuteReconcileBatch`

## Usage Example

```go
err := service.ReconcileAppleProfilesBatched(
    ctx,
    ds,
    mdmCommander,
    redisKV,
    slog.Default(),
    certProfilesLimit,
)
if err != nil {
    log.Printf("reconcile tick failed: %v", err)
}
```

The cron calls this once per tick. On each call it processes up to `reconcileAppleProfilesBatchSize` hosts starting from the stored cursor. When the batch is smaller than the limit, the cursor resets to `""`, signaling a full pass is complete. On error, the cursor is not advanced, so the same window is retried on the next tick.
