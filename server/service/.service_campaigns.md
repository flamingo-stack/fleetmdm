Manages live query campaign result streaming over WebSocket connections, handling real-time distribution of osquery results from targeted hosts back to Fleet users.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `StreamCampaignResults` | Method | Core WebSocket handler that streams live query results to clients, manages campaign lifecycle, and tracks performance stats |
| `addLiveQueryActivity` | Method | Records live query activity to the Fleet activity feed with aggregated stats after campaign completion |
| `updateStats` | Method | Batch-saves per-host query performance statistics and triggers aggregation when all expected results arrive |
| `calculateOutputSize` | Function | Computes result row output size in bytes for performance tracking |
| `campaignStatus` | Struct | Tracks expected vs. actual results and campaign state (`pending`/`finished`) |
| `statsTracker` | Struct | Manages batched stat accumulation and aggregation state across the streaming loop |
| `targetTotals` | Struct | Holds online/offline/missing host counts for a campaign's target set |

## Usage Example

```go
// Called by the WebSocket handler after authentication
func (svc Service) StreamCampaignResults(
    ctx context.Context,
    conn *websocket.Conn,
    campaignID uint,
) {
    // Authorizes viewer, resolves campaign from DB (with replica lag retry),
    // validates campaign ownership, then streams results:
    //
    // conn receives JSON messages of three types:
    //   {"type": "totals",  "data": {"count": 42, "online": 30, ...}}
    //   {"type": "status",  "data": {"expected_results": 30, "actual_results": 12, ...}}
    //   {"type": "result",  "data": {"host": {...}, "rows": [...]}}
    //
    // Stats are saved in batches of 1000 and aggregated on completion.
}
```

## Notes

- Campaign lookup retries up to **5 seconds** to tolerate DB replication lag (replica reads with ~30 ms sleep between attempts).
- Status updates are throttled to every **5 seconds** via a ticker to reduce frontend rendering pressure.
- Performance stats are written in batches of `statsBatchSize` (1000) and aggregated when all online hosts have reported or the client disconnects.
