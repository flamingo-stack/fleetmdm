Handles activity-related service operations including retrieving webhook settings, managing host upcoming activities (list, cancel), and releasing VPP license seats when app installs are canceled.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `GetActivitiesWebhookSettings` | Method | Fetches activity webhook settings from the app config |
| `ActivateNextUpcomingActivityForHost` | Method | Delegates activation of the next queued activity for a host |
| `NewActivity` | Method | Creates a new activity log entry via the activity service |
| `ListHostUpcomingActivities` | Method | Returns paginated upcoming activities for a host with authorization checks |
| `CancelHostUpcomingActivity` | Method | Cancels a queued host activity; handles VPP seat release and activity logging |
| `releaseVPPSeat` | Method | Disassociates a reserved VPP license seat when a canceled install originally reserved it |
| `listHostUpcomingActivitiesRequest/Response` | Structs | HTTP request/response types for the list endpoint |
| `cancelHostUpcomingActivityRequest/Response` | Structs | HTTP request/response types for the cancel endpoint (returns `204 No Content`) |

## Usage Example

```go
// List upcoming activities for a host
acts, meta, err := svc.ListHostUpcomingActivities(ctx, hostID, fleet.ListOptions{
    Page:    0,
    PerPage: 20,
})

// Cancel a specific upcoming activity
err := svc.CancelHostUpcomingActivity(ctx, hostID, "exec-uuid-1234")
if err != nil {
    log.Error("cancel failed", "err", err)
}

// Record a new activity
err = svc.NewActivity(ctx, currentUser, fleet.ActivityTypeInstalledSoftware{
    HostID:          hostID,
    SoftwareTitle:   "MyApp",
})
```

## Notes

- `ListHostUpcomingActivities` enforces two-phase authorization: first checks general host list permission, then re-checks with the host's `team_id` loaded.
- `CancelHostUpcomingActivity` blocks cancellation of already-activated lock/wipe operations to prevent loss of host access.
- VPP seat release (`releaseVPPSeat`) is best-effort — failures are logged but do not block the cancel response. Personal-enrollment hosts are disassociated by `clientUserId`; device-enrolled hosts by serial number.
