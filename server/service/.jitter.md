Implements a thread-safe, balanced jitter distribution table that assigns stable per-host check-in delay offsets to prevent thundering-herd spikes in a Fleet MDM deployment.

## Key Components

### `jitterHashTable` struct
- `mu` — mutex guarding all reads/writes
- `maxCapacity` — current max hosts allowed per bucket (grows dynamically)
- `bucketCount` — total number of time-slot buckets (e.g., 6 buckets = 6 minutes of jitter at 10% of 1hr)
- `buckets` — tracks current fill count per bucket index
- `cache` — memoizes previously assigned jitter durations by host ID

### `newJitterHashTable(bucketCount int) *jitterHashTable`
Constructor. Defaults `bucketCount` to `1` (no-op jitter) if zero is passed. Initializes `maxCapacity` at `1`.

### `jitterForHost(hostID uint) time.Duration`
Returns a stable `time.Duration` (in whole minutes) for the given host. Uses a preferred-bucket strategy (`hostID % bucketCount`), linearly probing forward on collision. When all buckets are full, increments `maxCapacity` and retries recursively.

## Usage Example

```go
// 6 buckets = up to 6 minutes of jitter spread (10% of a 1-hour interval)
jht := newJitterHashTable(6)

hostIDs := []uint{101, 202, 303, 404, 505, 606, 707}
for _, id := range hostIDs {
    offset := jht.jitterForHost(id)
    fmt.Printf("Host %d checks in after: %v\n", id, offset)
}
// Host 101 checks in after: 5m0s
// Host 202 checks in after: 4m0s
// ...

// Subsequent calls for the same host return the cached value
offset := jht.jitterForHost(101) // always 5m0s
```

## Notes

- Assignment is **per fleet instance** — load-balanced deployments may assign different jitter offsets for the same host across instances, but empirical load testing shows even distribution in practice.
- Set `bucketCount` to `interval * maxJitterPercent` (e.g., `60min × 10% = 6`). Use `bucketCount = interval` for 100% spread to fully eliminate thundering herds.
