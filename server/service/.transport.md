Provides HTTP transport utilities for the Fleet service layer, including response encoding, URL query parameter parsing, and construction of list/filter options for host and resource queries.

## Key Components

| Function | Description |
|---|---|
| `encodeResponse` | Encodes HTTP responses using the common Fleet encoder with JSON marshaling and error handling |
| `jsonMarshal` | Marshals responses to indented JSON via `json.NewEncoder` |
| `uint32FromRequest` | Extracts and parses a `uint32` path variable from a gorilla/mux route |
| `listOptionsFromRequest` | Parses common list query params (`page`, `per_page`, `order_key`, `order_direction`, `after`, `query`) into `fleet.ListOptions` |
| `hostListOptionsFromRequest` | Extends `listOptionsFromRequest` with host-specific filters (status, team, policy, software, OS, MDM, vulnerability, device mapping) |

## Usage Example

```go
// Parse generic list options from an HTTP request
func listHostsEndpoint(ctx context.Context, request interface{}, svc fleet.Service) (fleet.Errorer, error) {
    opts, err := listOptionsFromRequest(r)
    if err != nil {
        return nil, err
    }
    // opts.Page, opts.PerPage, opts.OrderKey, etc. are now populated
}

// Parse host-specific list options with filters
func listHostsHandler(w http.ResponseWriter, r *http.Request) {
    hopt, err := hostListOptionsFromRequest(r)
    if err != nil {
        // handles: invalid status, team_id, policy_id, software_id, mdm_enrollment_status, etc.
        FleetErrorEncoder(r.Context(), err, w)
        return
    }
    // hopt.StatusFilter, hopt.TeamFilter, hopt.PolicyIDFilter, etc. are populated
}

// Parse a uint32 path variable (e.g. /hosts/{id})
id, err := uint32FromRequest(r, "id")
```

## Notes

- `defaultPerPage` is `20`; if `page` is set but `per_page` is omitted, it defaults to `20` automatically
- `disable_failing_policies` is a deprecated alias for `disable_issues`; `disable_issues` takes precedence when both are present
- `os_name` and `os_version` must always be specified together; providing only one returns a `badRequest` error
- `software_status` requires both `software_title_id` and `team_id` to be present
