Metrics middleware wrapper for Fleet's app configuration service methods, recording request counts and latency for `NewAppConfig`, `AppConfigObfuscated`, and `ModifyAppConfig` operations.

## Key Components

| Method | Metric Label | Description |
|---|---|---|
| `NewAppConfig` | `NewOrgInfo` | Tracks creation of a new app configuration |
| `AppConfigObfuscated` | `OrgInfo` | Tracks retrieval of obfuscated app configuration |
| `ModifyAppConfig` | `ModifyOrgInfo` | Tracks modification of existing app configuration |

Each method uses a deferred closure to capture two Prometheus-style metrics via `metricsMiddleware`:
- **`requestCount`** — incremented by 1 per call, labeled with method name and error status
- **`requestLatency`** — records elapsed seconds since the call began

## Usage Example

```go
// metricsMiddleware wraps the core service to instrument app config operations
var svc fleet.Service = metricsMiddleware{
    Service:        coreService,
    requestCount:   requestCount,
    requestLatency: requestLatency,
}

// All app config calls are now automatically instrumented
cfg, err := svc.NewAppConfig(ctx, fleet.AppConfig{})
cfg, err := svc.AppConfigObfuscated(ctx)
cfg, err := svc.ModifyAppConfig(ctx, payload, fleet.ApplySpecOptions{})
```

## Notes

- Follows the standard [middleware/decorator pattern](https://github.com/flamingo-stack/fleetmdm/blob/main/server/service/metrics_appconfig.go) used across the Fleet service layer
- Error status is captured after the underlying service call completes, ensuring accurate `error=true/false` labeling
- Metric label names (`NewOrgInfo`, `OrgInfo`, `ModifyOrgInfo`) reflect legacy naming from when this was called "OrgInfo"
