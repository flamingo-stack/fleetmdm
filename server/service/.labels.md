Service layer for Fleet label management, handling creation, modification, retrieval, and listing of host labels with authorization enforcement and membership type routing.

## Key Components

| Function/Method | Description |
|---|---|
| `(svc *Service) NewLabel` | Creates a new label, supporting dynamic (query-based), manual (host list), and host-vitals criteria membership types |
| `(svc *Service) ModifyLabel` | Updates label name, description, or host membership; prevents modification of built-in labels |
| `(svc *Service) GetLabel` | Retrieves a single label by ID, filtered by team visibility |
| `(svc *Service) ListLabels` | Lists labels with optional team scoping, host counts, and observer inclusion |
| `getTeamIDOrZeroForGlobal` | Parses a team ID string, treating `"global"` as `0` for datastore queries |
| `labelResponseForLabel` | Constructs a `LabelResponse` from a label and optional host ID slice |
| `labelResponseForLabelWithTeamName` | Constructs a `LabelWithTeamNameResponse` including team name metadata |

## Usage Example

```go
// Create a manual label with specific hosts
payload := fleet.LabelPayload{
    Name:    "My Servers",
    HostIDs: []uint{1, 2, 3},
}
label, hostIDs, err := svc.NewLabel(ctx, payload)

// Create a dynamic label with an osquery query
dynamicPayload := fleet.LabelPayload{
    Name:     "Linux Hosts",
    Query:    "SELECT 1 FROM os_version WHERE platform = 'ubuntu';",
    Platform: "linux",
}
label, _, err = svc.NewLabel(ctx, dynamicPayload)

// Modify an existing label
newName := "Updated Label"
modPayload := fleet.ModifyLabelPayload{
    Name:    &newName,
    HostIDs: []uint{4, 5},
}
updated, hostIDs, err := svc.ModifyLabel(ctx, labelID, modPayload)

// List labels scoped to a team
labels, err := svc.ListLabels(ctx, fleet.ListOptions{}, ptr.Uint(42), true)
```

## Notes

- Built-in labels and reserved label names are protected from creation/modification.
- Manual labels support both identifier-based (`hosts`) and ID-based (`host_ids`) host resolution, but not both simultaneously.
- Team-scoped label listing requires a premium license.
- Authorization uses the Fleet `authz` layer; unauthorized label access returns filtered results at the datastore level rather than explicit 403s for reads.
