Middleware for wrapping endpoints and HTTP handlers with structured request logging using `slog` and Fleet's logging context utilities.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `Logged` | `endpoint.Endpoint` wrapper | Captures errors from go-kit endpoints into the logging context |
| `LogRequestEnd` | Function | Returns a `kithttp.ServerFinisher`-compatible func that flushes the logging context after a request |
| `LogResponseEndMiddleware` | `http.Handler` wrapper | Wraps an existing handler and logs after the response is written |
| `NewLoggingMiddleware` | `http.Handler` middleware | Full middleware for raw `http.Handler` routes — initializes logging context, populates request metadata, and logs on completion |

## Usage Example

```go
// Wrap a go-kit endpoint to capture errors
ep := log.Logged(myEndpoint)

// Attach as a go-kit ServerFinisher
server := kithttp.NewServer(
    ep,
    decodeRequest,
    encodeResponse,
    kithttp.ServerAfter(log.LogRequestEnd(logger)),
)

// Use as net/http middleware for non-go-kit handlers
mux := http.NewServeMux()
mux.Handle("/health", healthHandler)

loggedMux := log.NewLoggingMiddleware(logger)(mux)
http.ListenAndServe(":8080", loggedMux)
```

## Notes

- `Logged` handles both direct `error` returns and response objects implementing `Error() error` (Fleet's errorer pattern).
- `NewLoggingMiddleware` uses `kithttp.PopulateRequestContext` to inject standard request fields (method, URI, remote addr) and enriches the context with `ip_addr` and `x_for_ip_addr` extras.
- All logging is deferred to request completion via `LogRequestEnd`, keeping hot-path allocations minimal.
