Provides the core async task infrastructure for Fleet's asynchronous host data processing, managing Redis-backed collectors for label membership, policy membership, host last-seen timestamps, and scheduled query statistics.

## Key Components

- **`Task`** — Central struct holding datastore, Redis pool, clock, per-task configs, and OpenTelemetry flag
- **`NewTask`** — Constructor that maps each `AsyncTaskName` to its `AsyncProcessingConfig` from Fleet's osquery config
- **`StartCollectors`** — Launches background goroutines for each enabled async task; optionally logs per-collector stats on a configurable interval
- **`storePurgeActiveHostID`** — Lua script via Redis: atomically adds a host to a sorted set (keyed by `reportedAt` score) and purges entries older than `purgeOlder`
- **`loadActiveHostIDs`** — Iterates a Redis sorted set via `ZSCAN` in batches to avoid blocking; returns `[]hostIDLastReported`
- **`removeProcessedHostIDs`** — Lua script that safely removes only hosts whose score hasn't changed since the batch was read, preventing loss of in-flight data

## Usage Example

```go
task := async.NewTask(ds, redisPool, clock.C, &fleetConfig)

ctx, cancel := context.WithCancel(context.Background())
defer cancel()

task.StartCollectors(ctx, slogLogger)
// Collectors now run in background goroutines until ctx is cancelled.
// Each enabled task (label membership, policy membership, etc.)
// processes buffered Redis data into the datastore on its configured interval.
```

## Notes

- Collector goroutines respect context cancellation for clean shutdown
- Redis operations use cluster-aware connection binding via `redis.BindConn`
- The `ZSCAN`-based loading approach avoids blocking Redis when 100K+ hosts are tracked
- Score-comparison in `removeProcessedHostIDs` ensures hosts that reported new data during a collection cycle are **not** removed prematurely
