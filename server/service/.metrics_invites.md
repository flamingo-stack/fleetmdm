Metrics middleware wrapper for user invite service methods, instrumenting each operation with request count and latency observations via the `metricsMiddleware` decorator pattern.

## Key Components

| Function | Description |
|---|---|
| `InviteNewUser` | Wraps invite creation, tracking count and latency labeled by method and error state |
| `DeleteInvite` | Wraps invite deletion by ID with the same metrics instrumentation |
| `ListInvites` | Wraps invite listing with pagination options, emits metrics under the `"Invites"` method label |
| `VerifyInvite` | Wraps token-based invite verification with request count and latency tracking |

Each method follows the same pattern:
1. Defers a closure that captures elapsed time and error state as label values (`lvs`)
2. Increments `mw.requestCount` and records `mw.requestLatency` via the labeled metric vectors
3. Delegates to the underlying `mw.Service` implementation

## Usage Example

```go
// metricsMiddleware is typically constructed as a middleware layer around the base service
var svc fleet.Service
svc = newBaseService(ds)
svc = newMetricsMiddleware(svc, requestCount, requestLatency)

// Instrumented call — metrics recorded automatically
invite, err := svc.InviteNewUser(ctx, fleet.InvitePayload{
    Email: ptr.String("user@example.com"),
})

// Metrics emitted:
// requestCount{method="InviteNewUser", error="false"} += 1
// requestLatency{method="InviteNewUser", error="false"} observed duration
```

> **Note:** `ListInvites` uses the method label `"Invites"` (not `"ListInvites"`), which is an intentional label inconsistency to be aware of when querying metrics.
