Jira client wrapper for creating issues and retrieving project details from a Jira instance, with built-in retry logic for transient errors and rate limiting.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `Jira` | struct | Jira client wrapper holding the underlying `go-jira` client and configuration options |
| `JiraOptions` | struct | Configuration for BaseURL, BasicAuth credentials, and ProjectKey |
| `NewJiraClient` | func | Constructs an authenticated `Jira` client using basic auth over a Fleet HTTP transport |
| `GetProject` | method | Fetches project details by key; useful for validating connection and auth |
| `CreateJiraIssue` | method | Creates a Jira issue, automatically injecting the configured project key |
| `JiraConfigMatches` | method | Compares current client config against provided options (used for mock-safe interface matching) |
| `doWithRetry` | func | Internal retry handler respecting `Retry-After` headers, 5xx responses, and network-level errors |

## Usage Example

```go
opts := &externalsvc.JiraOptions{
    BaseURL:           "https://your-org.atlassian.net",
    BasicAuthUsername: "user@example.com",
    BasicAuthPassword: "api-token",
    ProjectKey:        "OPS",
}

client, err := externalsvc.NewJiraClient(opts)
if err != nil {
    log.Fatal(err)
}

// Validate connection and project existence
proj, err := client.GetProject(ctx)
if err != nil {
    log.Fatal(err)
}

// Create an issue
issue := &jira.Issue{
    Fields: &jira.IssueFields{
        Summary: "Detected vulnerability on host",
        Type:    jira.IssueType{Name: "Bug"},
    },
}
created, err := client.CreateJiraIssue(ctx, issue)
```

> **Note:** `doWithRetry` handles `429 Too Many Requests` by honoring the `Retry-After` header, and retries on 5xx responses and temporary network errors up to `maxRetries` attempts.
