Zendesk client wrapper for creating and managing support tickets via the Zendesk API, with built-in retry logic for transient errors and rate limiting.

## Key Components

- **`Zendesk`** — Struct wrapping the `go-zendesk` client with configuration options.
- **`ZendeskOptions`** — Configuration struct holding URL, email, API token, and group ID.
- **`NewZendeskClient(opts)`** — Constructs a production Zendesk client; if `TEST_ZENDESK_CLIENT=true`, delegates to `NewZendeskTestClient`.
- **`GetGroup(ctx)`** — Fetches the configured group, useful for validating credentials and connectivity.
- **`CreateZendeskTicket(ctx, ticket)`** — Creates a ticket, automatically attaching the configured `GroupID`.
- **`ZendeskConfigMatches(opts)`** — Compares current client options against provided options.
- **`doZendeskWithRetry(fn)`** — Internal retry handler using exponential backoff; retries on network errors, 5xx responses, and 429 rate limits (honoring `Retry-After`).
- **`NewZendeskTestClient(opts)`** — Test client that overrides the API endpoint with a full URL instead of subdomain resolution.

## Usage Example

```go
client, err := externalsvc.NewZendeskClient(&externalsvc.ZendeskOptions{
    URL:      "https://yourcompany.zendesk.com",
    Email:    "admin@yourcompany.com",
    APIToken: "your-api-token",
    GroupID:  12345678,
})
if err != nil {
    log.Fatal(err)
}

// Validate connection and group
group, err := client.GetGroup(ctx)
if err != nil {
    log.Fatal(err)
}

// Create a ticket
ticket, err := client.CreateZendeskTicket(ctx, &zendesk.Ticket{
    Subject: "Fleet MDM Alert",
    Comment: &zendesk.TicketComment{Body: "Device policy violation detected."},
})
```

> **Note:** Set `TEST_ZENDESK_CLIENT=true` in your environment to use the test client, which accepts a full base URL instead of a subdomain.
