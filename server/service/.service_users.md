Handles user creation operations for the Fleet MDM service layer, including initial setup user creation and standard new user provisioning with license validation and activity logging.

## Key Components

- **`CreateInitialUser`** – Creates the first admin user during Fleet setup. Skips authorization (no user context exists yet), enforces global admin role, and delegates to `NewUser`.
- **`NewUser`** – Creates a new user with license-aware role validation, password hashing, datastore persistence, and activity log entries for audit trails. Disables MFA for non-premium licenses.
- **`UserUnauthorized`** – Bypasses authorization to look up a user by ID; intended exclusively for middleware use.

## Usage Example

```go
// Create the initial admin user during Fleet setup
user, err := svc.CreateInitialUser(ctx, fleet.UserPayload{
    Name:       ptr.String("Admin"),
    Email:      ptr.String("admin@example.com"),
    Password:   ptr.String("securepassword"),
})

// Create a subsequent user (requires authenticated context)
user, err := svc.NewUser(ctx, fleet.UserPayload{
    Name:       ptr.String("Jane Doe"),
    Email:      ptr.String("jane@example.com"),
    Password:   ptr.String("securepassword"),
    GlobalRole: ptr.String(fleet.RoleObserver),
})
```

## Notes

- `CreateInitialUser` will return an error if any user already exists in the system.
- `NewUser` logs two activity types: `ActivityTypeCreatedUser` and role change activities via `fleet.LogRoleChangeActivities`.
- When called via an invite flow (no admin in context), the created user is treated as the actor for activity logging.
