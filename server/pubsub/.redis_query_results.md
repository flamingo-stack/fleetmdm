Redis-backed implementation of the `fleet.QueryResultStore` interface, enabling real-time distributed query result publishing and consumption via Redis Pub/Sub channels.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `redisQueryResults` | struct | Core type holding a Redis pool, duplicate result flag, and structured logger |
| `NewRedisQueryResults` | constructor | Creates a new `redisQueryResults` instance from a pool, duplicate flag, and logger |
| `WriteResult` | method | Publishes a `DistributedQueryResult` as JSON to a campaign-specific Redis channel; optionally duplicates to `LQDuplicate` |
| `ReadChannel` | method | Subscribes to a campaign's Pub/Sub channel and returns a Go channel streaming deserialized results |
| `receiveMessages` | function | Goroutine helper that forwards raw Redis Pub/Sub messages into an outbound channel, respecting context cancellation |
| `writeOrDone` | function | Non-blocking channel write that returns early if the context is done |
| `HealthCheck` | method | Pings Redis to verify connectivity |
| `pubSubForID` | function | Generates channel names in the format `results_<id>` |

## Usage Example

```go
pool := redis.NewPool(redisConfig)
logger := slog.Default()

store := pubsub.NewRedisQueryResults(pool, false, logger)

// Publish a result
err := store.WriteResult(fleet.DistributedQueryResult{
    DistributedQueryCampaignID: 42,
    Rows: []map[string]string{{"hostname": "host1"}},
})

// Subscribe and stream results
campaign := fleet.DistributedQueryCampaign{ID: 42}
resultCh, err := store.ReadChannel(ctx, campaign)
for msg := range resultCh {
    switch v := msg.(type) {
    case fleet.DistributedQueryResult:
        fmt.Println("result:", v)
    case error:
        fmt.Println("error:", v)
    }
}

// Verify Redis is reachable
if err := store.HealthCheck(); err != nil {
    log.Fatal("Redis unhealthy:", err)
}
```

## Notes

- `ReadChannel` spawns three goroutines: one to receive raw messages, one to decode and forward them, and one to handle cleanup (unsubscribe + connection close) after both finish.
- A `1-hour` receive timeout is set to guard against completely unresponsive Redis connections; delays over 1 minute are logged as warnings.
- `WriteResult` returns a `noSubscriberError` if no clients are subscribed to the campaign channel, allowing callers to distinguish a missing subscriber from a Redis failure.
