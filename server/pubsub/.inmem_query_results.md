In-memory implementation of the `fleet.QueryResultStore` interface for pub/sub query result distribution using Go channels.

## Key Components

| Symbol | Description |
|---|---|
| `inmemQueryResults` | Core struct holding a map of campaign ID → unbuffered channels, protected by a mutex |
| `NewInmemQueryResults()` | Constructor that initializes an empty channel map |
| `WriteResult()` | Non-blocking send of a `DistributedQueryResult` to the campaign's channel; returns `noSubscriberError` if no reader is ready |
| `ReadChannel()` | Returns a receive-only channel for a campaign and registers a goroutine to close and clean up when the context is cancelled |
| `HealthCheck()` | Always returns `nil`; satisfies the store interface for health probing |

## Usage Example

```go
// Initialize the store
store := pubsub.NewInmemQueryResults()

// Consumer: subscribe to results for a campaign
ctx, cancel := context.WithCancel(context.Background())
defer cancel()

ch, err := store.ReadChannel(ctx, fleet.DistributedQueryCampaign{ID: 42})
if err != nil {
    log.Fatal(err)
}

go func() {
    for result := range ch {
        fmt.Printf("received: %v\n", result)
    }
}()

// Producer: write a result
err = store.WriteResult(fleet.DistributedQueryResult{
    DistributedQueryCampaignID: 42,
    // ...
})
if err != nil {
    // noSubscriberError — no reader was ready
    log.Printf("no subscriber: %v", err)
}
```

> **Note:** Channels are unbuffered, so `WriteResult` drops results immediately if no goroutine is blocked on `ReadChannel`. This implementation is suited for single-node, in-process use only. For multi-node deployments, use a Redis-backed store instead.
