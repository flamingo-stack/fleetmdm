Helper functions for creating mock datastore implementations for user lookup operations in tests.

## Key Components

- **`UserByEmailWithUser(u *fleet.User) UserByEmailFunc`** — Returns a mock `UserByEmailFunc` that always returns the provided user, simulating a successful email lookup.
- **`UserWithEmailNotFound() UserByEmailFunc`** — Returns a mock `UserByEmailFunc` that always returns a `"not found"` error, simulating a missing user email lookup.
- **`UserWithID(u *fleet.User) UserByIDFunc`** — Returns a mock `UserByIDFunc` that always returns the provided user, simulating a successful ID-based lookup.

## Usage Example

```go
// Simulate a successful user lookup by email
mockStore := &mock.Store{
    UserByEmailFunc: mock.UserByEmailWithUser(&fleet.User{
        ID:    1,
        Email: "admin@example.com",
    }),
}

// Simulate a user not found scenario
mockStore := &mock.Store{
    UserByEmailFunc: mock.UserWithEmailNotFound(),
}

// Simulate a successful user lookup by ID
mockStore := &mock.Store{
    UserByIDFunc: mock.UserWithID(&fleet.User{
        ID:    42,
        Email: "user@example.com",
    }),
}
```

These helpers reduce boilerplate when writing unit tests that depend on user datastore interactions, allowing tests to focus on business logic rather than mock setup. See the full package at [`server/mock`](https://github.com/flamingo-stack/fleetmdm/blob/main/server/mock).
