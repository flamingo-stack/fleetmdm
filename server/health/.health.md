Health check utilities for service dependencies, exposing an HTTP handler and programmatic checker interface for monitoring backend service availability.

## Key Components

| Symbol | Type | Description |
|---|---|---|
| `Checker` | Interface | Contract for dependency health checks; implementors return a non-nil `error` when unhealthy |
| `Handler` | Function | Returns an `http.HandlerFunc` that runs registered checkers and responds `200 OK` or `500` |
| `CheckHealth` | Function | Iterates all provided checkers, logs failures via `slog`, returns `false` if any check fails |
| `Nop` | Function | Returns a no-op `Checker` that always passes; intended for test use |

## Usage Example

```go
// 1. Implement the Checker interface on a dependency
type DB struct { /* ... */ }
func (db *DB) HealthCheck() error {
    return db.Ping()
}

// 2. Register checkers and mount the handler
db := &DB{}
checkers := map[string]health.Checker{
    "database": db,
    "mail":     mailClient,
}

logger := slog.Default()
mux := http.NewServeMux()
mux.Handle("/healthz", health.Handler(logger, checkers))

// 3. Query a specific checker via ?check= param
// GET /healthz?check=database  → runs only the "database" checker
// GET /healthz                 → runs all registered checkers

// 4. Use Nop() in tests
checkers["fake"] = health.Nop()
healthy := health.CheckHealth(logger, checkers) // always true for Nop
```

## HTTP Behaviour

- **`GET /healthz`** — runs all registered checkers
- **`GET /healthz?check=<name>`** — runs only the named checker(s); multiple `?check=` params are supported
- **`400 Bad Request`** — `check` param is empty or references an unknown checker name
- **`500 Internal Server Error`** — one or more checkers returned an error
- **`200 OK`** — all selected checkers passed
