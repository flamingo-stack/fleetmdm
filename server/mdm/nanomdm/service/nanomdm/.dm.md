HTTP caller for proxying Apple Declarative Device Management (DDM) protocol requests to a backend HTTP endpoint.

## Key Components

### `DeclarativeManagementHTTPCaller`
Struct that holds a base URL and HTTP client used to forward DDM requests.

| Field | Type | Description |
|-------|------|-------------|
| `url` | `*url.URL` | Base URL prefix for the backend DDM handler |
| `client` | `*http.Client` | HTTP client used to make outbound requests |

### `NewDeclarativeManagementHTTPCaller`
Constructor that parses the given URL prefix and returns a configured caller instance.

### `DeclarativeManagement`
Core method implementing the DDM service interface. Resolves the full endpoint URL by combining the base prefix with the message endpoint path, then:
- Issues a `GET` if no request body data is present
- Issues a `PUT` with `application/json` content type if data is included
- Attaches the enrollment ID via the `X-Enrollment-ID` header
- Returns response body bytes, or a typed `HTTPStatusError` for non-200 responses

## Usage Example

```go
import (
    "net/http"
    nanomdm "github.com/flamingo-stack/fleetmdm/server/mdm/nanomdm"
)

caller, err := nanomdm.NewDeclarativeManagementHTTPCaller(
    "https://ddm-backend.example.com/ddm/",
    &http.Client{Timeout: 10 * time.Second},
)
if err != nil {
    log.Fatal(err)
}

// caller satisfies the DeclarativeManagement service interface
// and can be registered with a NanoMDM service mux
```

## Notes

- The `X-Enrollment-ID` header carries the device enrollment ID (`r.ID`) to the backend, allowing the backend to identify which device originated the request.
- Non-200 HTTP responses are wrapped in `service.HTTPStatusError`, preserving the status code for upstream error handling.
