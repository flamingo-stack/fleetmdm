Certificate authentication middleware for NanoMDM that validates and associates MDM client certificates with device enrollments using SHA-256 certificate hashing.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `ErrNoCertReuse` | `error` | Returned when a certificate is already associated with a different enrollment |
| `ErrNoCertAssoc` | `error` | Returned when an enrollment has no certificate association |
| `ErrMissingCert` | `error` | Returned when a request contains no MDM certificate |
| `CertAuth` | `struct` | Middleware wrapping `CheckinAndCommandService` to enforce cert-based auth |
| `New()` | `func` | Constructor accepting the next service, storage backend, and options |
| `HashCert()` | `func` | Computes a hex-encoded SHA-256 fingerprint of an `x509.Certificate` |
| `WithLogger()` | `Option` | Attaches a logger to `CertAuth` |
| `WithAllowRetroactive()` | `Option` | Permits cert associations on existing enrollments (not just new `Authenticate` check-ins) |

### Behavioral Flags on `CertAuth`

| Flag | Effect |
|------|--------|
| `allowDup` | Permits one certificate to be reused across multiple enrollments (embedded identity profiles) |
| `allowRetroactive` | Allows cert-hash associations outside of the initial `Authenticate` message |
| `warnOnly` | Logs auth failures without rejecting requests — **WARNING: allows client spoofing** |

## Usage Example

```go
import (
    "github.com/fleetdm/fleet/v4/server/mdm/nanomdm/certauth"
    "github.com/micromdm/nanolib/log/stdlogfmt"
)

// Wrap your CheckinAndCommandService with certificate authentication.
authService := certauth.New(
    nextService,
    certStorage,
    certauth.WithLogger(stdlogfmt.New()),
    certauth.WithAllowRetroactive(),
)

// Compute a cert hash independently (e.g. for storage lookups).
hash := certauth.HashCert(tlsCert.Leaf)
```

> Errors `ErrNoCertAssoc` and `ErrNoCertReuse` are wrapped as HTTP `403 Forbidden`; `ErrMissingCert` becomes `400 Bad Request` via `service.NewHTTPStatusError`.
