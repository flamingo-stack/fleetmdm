Implements the `CertAuth` middleware service layer, wiring certificate-based authentication checks into each MDM protocol handler before delegating to the next service in the chain.

## Key Components

| Method | Auth Strategy | Description |
|---|---|---|
| `Authenticate` | `associateForNewEnrollment` | Handles initial device enrollment, associating the client cert with a new enrollment record |
| `TokenUpdate` | `validateOrAssociateForExistingEnrollment` | Validates or re-associates cert for token update requests |
| `CheckOut` | `validateOrAssociateForExistingEnrollment` | Validates cert on device check-out |
| `UserAuthenticate` | `validateOrAssociateForExistingEnrollment` | Validates cert for user-level authentication |
| `SetBootstrapToken` | `validateOrAssociateForExistingEnrollment` | Validates cert before storing a bootstrap token |
| `GetBootstrapToken` | `validateOrAssociateForExistingEnrollment` | Validates cert before retrieving a bootstrap token |
| `DeclarativeManagement` | `validateOrAssociateForExistingEnrollment` | Validates cert for DDM (Declarative Device Management) requests |
| `GetToken` | `validateOrAssociateForExistingEnrollment` | Validates cert for token retrieval |
| `CommandAndReportResults` | `validateOrAssociateForExistingEnrollment` | Validates cert on command result reporting |

## Usage Example

`CertAuth` sits as middleware in a handler chain. Each method validates the enrollment certificate, then passes the request downstream:

```go
// CertAuth wraps another MDM service, intercepting each protocol message
certAuthMiddleware := certauth.New(storage, nextService)

// On first enrollment, associateForNewEnrollment runs
certAuthMiddleware.Authenticate(req, &mdm.Authenticate{...})

// On all subsequent requests, validateOrAssociateForExistingEnrollment runs
certAuthMiddleware.TokenUpdate(req, &mdm.TokenUpdate{...})
certAuthMiddleware.CommandAndReportResults(req, &mdm.CommandResults{...})
```

## Notes

- `Authenticate` is the only method using `associateForNewEnrollment` — all others use `validateOrAssociateForExistingEnrollment`, reflecting the distinction between initial enrollment and ongoing session validation.
- All methods follow the middleware pattern: fail fast on auth error, otherwise delegate to `s.next`.
