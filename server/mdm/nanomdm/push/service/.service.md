Retrieves MDM push notification details from storage and dispatches APNs pushes to enrolled devices, handling both single and multi-topic push scenarios.

## Key Components

| Symbol | Type | Description |
|---|---|---|
| `PushService` | struct | Core service that coordinates push cert retrieval, provider caching, and APNs dispatch |
| `New` | constructor | Creates a `PushService` with a push store, cert store, provider factory, and logger |
| `Push` | method | Public entry point — resolves enrollment IDs to push tokens and dispatches notifications |
| `getProvider` | method | Returns a cached `PushProvider` for a topic, refreshing it if the push cert is stale |
| `pushSingle` | method | Synchronously sends a push to a single `mdm.Push` entry |
| `pushMulti` | method | Concurrently fans out pushes across multiple APNs topics using goroutines |
| `ErrIdNotFound` | error | Returned in the response map when storage has no push data for a requested enrollment ID |

## Usage Example

```go
import (
    "context"
    "log"

    "github.com/fleetdm/fleet/v4/server/mdm/nanomdm/push/service"
)

// Wire up dependencies
pushSvc := service.New(
    pushStore,       // storage.PushStore
    certStore,       // storage.PushCertStore
    providerFactory, // push.PushProviderFactory
    logger,
)

// Send APNs pushes to one or more enrolled devices by enrollment ID
ctx := context.Background()
responses, err := pushSvc.Push(ctx, []string{"enrollment-id-1", "enrollment-id-2"})
if err != nil {
    log.Printf("push error: %v", err)
}

for id, resp := range responses {
    if resp.Err != nil {
        log.Printf("failed to push to %s: %v", id, resp.Err)
    }
}
```

**Notes:**
- Provider instances are cached per APNs topic in `providers` and protected by a `sync.RWMutex`.
- A single-enrollment fast path (`pushSingle`) avoids goroutine overhead when only one device is targeted.
- Token-to-ID remapping is performed after push responses are collected, since APNs providers operate on tokens rather than enrollment IDs.
