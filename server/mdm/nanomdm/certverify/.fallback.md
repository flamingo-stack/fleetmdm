Certificate verification utility implementing a fallback chain pattern, where multiple `CertVerifier` implementations are tried in sequence and verification succeeds if any single verifier passes.

## Key Components

- **`CertVerifier`** — Interface requiring a `Verify(context.Context, *x509.Certificate) error` method
- **`FallbackVerifier`** — Struct holding an ordered slice of `CertVerifier` implementations
- **`NewFallbackVerifier`** — Constructor accepting variadic `CertVerifier` arguments
- **`Verify`** — Iterates verifiers; returns `nil` on first success, or a combined error string if all fail

## Usage Example

```go
// Implement the CertVerifier interface
type SystemVerifier struct{}

func (s *SystemVerifier) Verify(ctx context.Context, cert *x509.Certificate) error {
    opts := x509.VerifyOptions{}
    _, err := cert.Verify(opts)
    return err
}

type PinnedVerifier struct{ expected []byte }

func (p *PinnedVerifier) Verify(_ context.Context, cert *x509.Certificate) error {
    if !bytes.Equal(cert.Raw, p.expected) {
        return errors.New("certificate does not match pinned cert")
    }
    return nil
}

// Chain verifiers with fallback — passes if either succeeds
verifier := certverify.NewFallbackVerifier(
    &SystemVerifier{},
    &PinnedVerifier{expected: pinnedCertDER},
)

if err := verifier.Verify(ctx, incomingCert); err != nil {
    log.Fatalf("all verifiers failed: %v", err)
}
```

## Behavior Notes

- **Short-circuits on first pass** — remaining verifiers are skipped once one returns `nil`
- **Aggregates all failures** — if every verifier fails, errors are joined as `"fallback error (0): ...; fallback error (1): ..."`
- An empty verifier list will always return `nil` (no errors collected)
