Provides HTTP handler functions that bridge Apple MDM protocol requests to the NanoMDM service layer, handling both device check-in and command/result reporting flows.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `CheckinHandler` | `func` | HTTP handler for MDM device check-in requests |
| `CommandAndReportResultsHandler` | `func` | HTTP handler for MDM command dispatch and result reporting |
| `CheckinAndCommandHandler` | `func` | Multiplexer that routes to check-in or command handler based on `Content-Type` |
| `mdmReqFromHTTPReq` | `func` (internal) | Converts an `*http.Request` into an `*mdm.Request` including certificate, params, and auth |

## Usage Example

```go
// Wire up handlers in your HTTP router
mux := http.NewServeMux()

// Combined handler — routes by Content-Type automatically
mux.Handle("/mdm", mdm.CheckinAndCommandHandler(svc, logger))

// Or mount handlers separately
mux.Handle("/mdm/checkin", mdm.CheckinHandler(checkinSvc, logger))
mux.Handle("/mdm/connect", mdm.CommandAndReportResultsHandler(connectSvc, logger))
```

## Error Handling

All handlers follow a consistent error pattern:

- **Timeout errors** → `408 Request Timeout`
- **`service.HTTPStatusError`** → uses the embedded HTTP status code
- **All other errors** → `500 Internal Server Error`
- Errors are logged via context-aware `ctxlog.Logger` before responding

## Routing Logic

`CheckinAndCommandHandler` inspects the `Content-Type` header:

- `application/x-apple-aspen-mdm-checkin` → delegates to `CheckinHandler`
- Any other content type → treated as a command/report-results request
