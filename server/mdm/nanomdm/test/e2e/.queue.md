E2E test helpers for MDM command queue behavior, providing utilities to enqueue commands, send device reports, and assert expected command replies in sequence.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `queueDevice` | interface | Combines `CMDDoReportAndFetch`, `NewCommandReport`, and `IDer` for queue-capable test devices |
| `enqueue` | func | Enqueues a raw MDM command to a specific device ID via `NanoMDMAPI` |
| `simpleCmd` | func | Creates an `*mdm.Command` where `CommandUUID` and `RequestType` are both set to the provided string |
| `sendReportExpectCommandReply` | func | Sends a command report and asserts the returned command matches the expected command ID |
| `enqueueSimple` | func | Convenience wrapper that enqueues a `simpleCmd` to the device's own ID |
| `queue` | func | Top-level test runner with `basic` and `notnow` sub-tests covering standard queue drain and `NotNow` deferral behavior |

## Usage Example

```go
// Run the full queue test suite against a device and API
func TestMDMQueue(t *testing.T) {
    ctx := context.Background()
    device := newTestDevice(t, ctx, api)
    queue(t, ctx, device, api)
}

// Or use individual helpers in a custom test
func TestCustomEnqueue(t *testing.T) {
    ctx := context.Background()
    enqueueSimple(t, ctx, device, api, "InstallProfile")
    sendReportExpectCommandReply(t, ctx, device, "", "Idle", "InstallProfile")
    sendReportExpectCommandReply(t, ctx, device, "InstallProfile", "Acknowledged", "")
}
```

## Test Scenarios

- **`basic`** — Verifies FIFO ordering: enqueue two commands, drain via `Acknowledged` reports, confirm empty queue.
- **`notnow`** — Verifies `NotNow` deferral: a `NotNow` response suppresses the command until the next `Idle` report resets it.
