Provides a thin wrapper around an MDM enrollment for use in end-to-end tests, simplifying command creation, result reporting, and the check-in/fetch cycle.

## Key Components

| Symbol | Description |
|---|---|
| `device` | Struct embedding `*enrollment.Enrollment`; the primary test helper |
| `newDeviceFromCheckins` | Constructor that builds a `device` from check-in HTTP endpoints |
| `newCommand` | Helper that constructs an `*mdm.Command` from a UUID and request type; returns `nil` if both are empty |
| `NewCommandReport` | Builds an `*mdm.CommandResults` representing a device's response to a command |
| `CMDDoReportAndFetch` | Sends a command result to the server and decodes the next pending command from the plist response body |
| `Limit1MiB` | Read limit (`1 048 576` bytes) applied to all MDM response bodies |

## Usage Example

```go
// Construct a test device
d, err := newDeviceFromCheckins(httpClient, "https://mdm.example.com", "/auth", "/token-update")
if err != nil {
    t.Fatal(err)
}

// Acknowledge a command and fetch the next one
report := d.NewCommandReport("cmd-uuid-123", "Acknowledged", nil)
nextCmd, err := d.CMDDoReportAndFetch(ctx, report)
if err != nil {
    t.Fatal(err)
}

if nextCmd != nil {
    fmt.Println("Next command:", nextCmd.Command.RequestType)
}

// Build a standalone command (e.g. to inspect its fields)
cmd := newCommand("cmd-uuid-456", "ProfileList")
```

## Notes

- Capped reads via `io.LimitReader` prevent unbounded memory allocation on malformed or adversarial server responses.
- An empty response body is valid — `CMDDoReportAndFetch` returns `nil, nil` when the server has no pending command, matching the MDM protocol's idle state.
