Delegates `RetrieveMigrationCheckins` to the first store in the `MultiAllStorage` store slice, logging a notice that only the primary store is used during migration.

## Key Components

| Symbol | Description |
|--------|-------------|
| `RetrieveMigrationCheckins` | Method on `MultiAllStorage` that proxies the migration checkin retrieval to `stores[0]` |

## Usage Example

```go
ms := &MultiAllStorage{
    stores: []AllStorage{primaryStore, secondaryStore},
    logger: logger,
}

checkins := make(chan interface{})

go func() {
    for item := range checkins {
        // process migrated checkin
        _ = item
    }
}()

// Only primaryStore (stores[0]) will be used; secondary stores are skipped
if err := ms.RetrieveMigrationCheckins(ctx, checkins); err != nil {
    log.Fatal(err)
}
```

## Notes

- Only `stores[0]` is ever read during migration — secondary stores are intentionally skipped.
- A contextual info log (`"only using first store for migration"`) is emitted via [`ctxlog`](https://github.com/micromdm/nanolib) to make this behaviour visible in logs.
- The caller is responsible for draining or closing the `chan<- interface{}` passed in.
