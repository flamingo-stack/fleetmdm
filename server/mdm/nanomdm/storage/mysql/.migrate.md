Implements the `RetrieveMigrationCheckins` method for `MySQLStorage`, enabling bulk retrieval of MDM check-in messages (Authenticate and TokenUpdate) from device and user records to support data migration between storage backends.

## Key Components

- **`RetrieveMigrationCheckins(ctx, c)`** — Queries `nano_devices` for `authenticate` and `token_update` blobs, then `nano_users` for `token_update` blobs. Each raw byte payload is decoded via `mdm.DecodeCheckin` and sent to the provided channel as either a decoded message or an error.

## Usage Example

```go
ch := make(chan interface{})

go func() {
    defer close(ch)
    if err := storage.RetrieveMigrationCheckins(ctx, ch); err != nil {
        log.Fatal(err)
    }
}()

for item := range ch {
    switch v := item.(type) {
    case error:
        log.Printf("decode error: %v", v)
    default:
        // process decoded MDM check-in message (Authenticate or TokenUpdate)
        process(v)
    }
}
```

## Notes

- Results are streamed via a channel rather than returned as a slice, keeping memory usage low for large datasets.
- Per the inline TODO, TokenUpdate messages that omit the latest `UnlockToken` are not yet synthesized — this is a known gap for migrations where unlock token fidelity is required.
- Both device-level and user-enrollment check-ins are covered in a single call.
