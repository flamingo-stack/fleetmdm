Filesystem-based MDM enrollment storage backend that persists MDM protocol messages and enrollment state as flat files on disk.

## Key Components

**`FileStorage`** — Main struct holding the root storage path. Created via `New(path string)`.

**`enrollment`** — Internal helper struct scoping file operations to a specific enrollment directory (`<root>/<enrollmentID>/`).

**Constants** — Well-known filenames for each stored artifact:

| Constant | File |
|---|---|
| `AuthenticateFilename` | `Authenticate.plist` |
| `TokenUpdateFilename` | `TokenUpdate.plist` |
| `UnlockTokenFilename` | `UnlockToken.dat` |
| `IdentityCertFilename` | `Identity.pem` |
| `BootstrapTokenFile` | `BootstrapToken.dat` |
| `DisabledFilename` | `Disabled` (marker file) |

**Key Methods on `FileStorage`:**

- `StoreAuthenticate` — Saves the MDM Authenticate message, identity cert, serial number, resets the token tally, and removes any stale bootstrap token.
- `StoreTokenUpdate` — Saves the TokenUpdate message, persists the unlock token separately, increments the tally counter, links user-channel sub-enrollments, and removes the disabled marker.
- `StoreUserAuthenticate` — Saves UserAuthenticate messages, routing digest responses to a separate file.
- `Disable` — Writes a zero-byte `Disabled` marker for a device and all its sub-enrollments, then removes the sub-enrollment directory.
- `RetrieveTokenUpdateTally` — Returns how many TokenUpdate messages have been received for an enrollment.

## Usage Example

```go
import "github.com/fleetdm/fleet/v4/server/mdm/nanomdm/storage/file"

// Initialize storage rooted at /var/mdm/enrollments
store, err := file.New("/var/mdm/enrollments")
if err != nil {
    log.Fatal(err)
}

// Store an Authenticate message (called by MDM handler)
err = store.StoreAuthenticate(request, authenticateMsg)

// Check token update count for an enrollment
tally, err := store.RetrieveTokenUpdateTally(ctx, "UDID-1234")
```

> **Note:** `ExpandEmbeddedSecrets`, `ExpandHostSecrets`, `SetRecoveryLockFailed`, and `BulkDeleteHostUserCommandsWithoutResults` are stubbed with no-op implementations.
