Entry point for the NanoMDM server that initializes storage, configures MDM/API HTTP endpoints, and starts the HTTP listener.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `main()` | `func` | Parses CLI flags, wires up MDM services, registers HTTP routes, and starts the server |
| `newTraceID()` | `func` | Generates a random 8-byte hex string used as a per-request trace ID |
| `endpointMDM`, `endpointCheckin`, etc. | `const` | URL path constants for MDM and API routes |
| `EnrollmentIDHeader`, `TraceIDHeader` | `const` | Custom HTTP headers propagated by the auth proxy |

**HTTP Endpoints registered:**

| Endpoint | Purpose |
|----------|---------|
| `/mdm` | Core MDM check-in and command handler |
| `/checkin` | Optional separate check-in handler (`-checkin` flag) |
| `/authproxy/` | Reverse proxy for MDM-authenticated requests |
| `/v1/pushcert` | Upload/store APNs push certificate (API-key protected) |
| `/v1/push/` | Send APNs push notifications (API-key protected) |
| `/v1/enqueue/` | Enqueue raw MDM commands (API-key protected) |
| `/migration` | Enrollment migration check-in endpoint |
| `/version` | Returns server version string |

## Usage Example

```bash
# Minimal run with file-based storage
nanomdm \
  -storage file \
  -storage-dsn /var/db/nanomdm \
  -ca /etc/nanomdm/ca.pem \
  -api supersecretkey \
  -listen :9000

# With webhook, declarative management, and separate check-in endpoint
nanomdm \
  -storage file \
  -storage-dsn /var/db/nanomdm \
  -ca /etc/nanomdm/ca.pem \
  -api supersecretkey \
  -webhook-url https://hooks.example.com/mdm \
  -dm https://dm.example.com/declarations/ \
  -checkin \
  -debug
```
