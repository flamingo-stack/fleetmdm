Provides test helpers for driving the maintained apps sync flow against an in-memory HTTP server that serves testdata from the repository's `ee/maintained-apps/outputs` directory. This package must only be imported from test code.

## Key Components

| Export | Type | Description |
|---|---|---|
| `SyncApps` | Function | Spins up a local HTTP server, syncs the full apps list into the datastore, and returns all ingested `fleet.MaintainedApp` records |
| `ExpectedAppSlugs` | Function | Reads `apps.json` from the outputs directory and returns the expected slug for every app entry |
| `SyncAndRemoveApps` | Function | Full lifecycle test: seeds the DB, removes one app, re-syncs, then removes all apps — asserting correct DB state at each step |
| `outputsDir` | Internal | Resolves the absolute path to `ee/maintained-apps/outputs` via `runtime.Caller` |

## Usage Example

```go
func TestMaintainedApps(t *testing.T) {
    ds := setupTestDatastore(t)

    // Seed the datastore and retrieve all synced apps
    apps := maintainedappstest.SyncApps(t, ds)

    // Verify all expected slugs are present
    expectedSlugs := maintainedappstest.ExpectedAppSlugs(t)
    require.Len(t, apps, len(expectedSlugs))

    // Exercise add/remove lifecycle against the same datastore
    maintainedappstest.SyncAndRemoveApps(t, ds)
}
```

## Notes

- The package overrides `FLEET_DEV_MAINTAINED_APPS_BASE_URL` and `FLEET_DEV_MAINTAINED_APPS_FALLBACK_BASE_URL` via `dev_mode.SetOverride` (not `t.Setenv`) so the values are cleared immediately on function return, not deferred to test cleanup.
- `SyncAndRemoveApps` validates the `fleet.NoMaintainedAppsInDatabaseError` sentinel error when the datastore is fully emptied.
