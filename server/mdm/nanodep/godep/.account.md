Provides Apple DEP account detail retrieval and related data structures for interacting with the Device Enrollment Program (DEP) API.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `AccountResponse` | struct | Maps to Apple's `AccountDetail` API response, containing organization and server metadata |
| `URL` | struct | Maps to Apple's `Url` structure, describing available API endpoints with their HTTP methods and rate limits |
| `Limit` | struct | Maps to Apple's `Limit` structure, holding default and maximum request limits for an endpoint |
| `AccountDetail` | method | Calls the DEP `/account` endpoint to retrieve account details for the current auth token |
| `IsTermsNotSigned` | function | Helper to detect whether an error indicates unsigned DEP Terms & Conditions (`T_C_NOT_SIGNED`) |

## Usage Example

```go
client := godep.NewClient(/* ... */)

// Fetch account details for a named DEP token
account, err := client.AccountDetail(ctx, "my-dep-token")
if err != nil {
    if godep.IsTermsNotSigned(err) {
        log.Fatal("DEP Terms and Conditions must be accepted before continuing")
    }
    log.Fatalf("failed to get account detail: %v", err)
}

fmt.Printf("Org: %s (%s)\n", account.OrgName, account.OrgID)
fmt.Printf("Server: %s [%s]\n", account.ServerName, account.ServerUUID)

// Inspect available API endpoints and their limits
for _, u := range account.URLs {
    if u.Limit != nil {
        fmt.Printf("Endpoint %s — max %d req/batch\n", u.URI, u.Limit.Maximum)
    }
}
```

## Notes

- `AccountDetail` delegates to `doWithAfterHook`, which handles DEP session token renewal automatically.
- `IsTermsNotSigned` checks both HTTP-level and auth-level error responses for the `T_C_NOT_SIGNED` code, as Apple may return it through either path.
- Full Apple DEP API reference: [Get Account Detail](https://developer.apple.com/documentation/devicemanagement/get_account_detail)
