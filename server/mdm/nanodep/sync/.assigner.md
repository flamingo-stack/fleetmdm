Handles automatic assignment of Apple DEP profile UUIDs to devices discovered during DEP sync operations.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `AssignerProfileRetriever` | Interface | Retrieves the assigner profile UUID and modification time for a given DEP name |
| `Assigner` | Struct | Core type that wraps a DEP client and handles profile assignment logic |
| `NewAssigner` | Constructor | Creates an `Assigner` with a DEP client, name, store, and optional configuration |
| `WithAssignerLogger` | Option | Sets a custom logger on the `Assigner` |
| `WithDebug` | Option | Enables verbose debug logging for device-level detail |
| `ProcessDeviceResponse` | Method | Processes a DEP `DeviceResponse`, filtering devices by `op_type` and calling the Apple DEP assign API |
| `logCountsForResults` | Helper | Aggregates assignment results (`success`, `not_accessible`, `failed`, `other`) into loggable key-value pairs |

## Usage Example

```go
client := godep.NewClient(depStorage, http.DefaultClient)

assigner := sync.NewAssigner(
    client,
    "my-dep-name",
    myProfileStore,
    sync.WithAssignerLogger(myLogger),
    sync.WithDebug(),
)

// Called during a DEP sync loop after fetching/syncing devices
err := assigner.ProcessDeviceResponse(ctx, deviceResponse)
if err != nil {
    log.Fatal(err)
}
```

## Behaviour Notes

- Only devices with `op_type == "added"` or an empty `op_type` (initial `FetchDevices` call without a cursor) are assigned a profile — other op types are intentionally ignored to avoid redundant assignments.
- If no profile UUID is configured in the store, assignment is skipped silently (debug log only, to avoid false alarms during initial setup).
