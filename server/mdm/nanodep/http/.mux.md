HTTP method-based request multiplexer that routes incoming requests to handlers registered for specific HTTP methods (GET, POST, etc.), returning `405 Method Not Allowed` for unregistered methods.

## Key Components

| Symbol | Description |
|--------|-------------|
| `MethodMux` | Struct that maps HTTP method strings to `http.Handler` implementations, protected by a `sync.RWMutex` |
| `NewMethodMux()` | Constructor returning a new, empty `*MethodMux` |
| `Handle(method, handler)` | Registers a handler for a given HTTP method; panics on empty method, nil handler, or duplicate registration |
| `ServeHTTP(w, r)` | Dispatches the request to the matched method handler, or writes a `405` response if no match is found |

## Usage Example

```go
mux := http.NewMethodMux()

mux.Handle(http.MethodGet, http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("GET response"))
}))

mux.Handle(http.MethodPost, http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("POST response"))
}))

// Mount on a path using the standard library mux
http.Handle("/api/resource", mux)
```

> Duplicate method registration causes a panic at startup, making misconfiguration immediately visible rather than silently overwriting existing handlers.

## Notes

- Thread-safe: uses `sync.RWMutex` so handlers can be read concurrently without contention
- Implements `http.Handler`, making it composable with any standard library router
