One-shot startup helper that backfills the `country_code` column for VPP tokens and apps that predate the multi-region storefront feature.

## Key Components

### `BackfillLegacyCountries(ctx, ds, logger)`

The single exported function. Runs three sequential steps:

1. **List tokens** — fetches all VPP tokens via `ds.ListVPPTokens`; exits early if none have a `NULL` country.
2. **Backfill token countries** — for each token missing a country code, calls Apple's `/client/config` endpoint via `GetConfig` in parallel (capped at 8 concurrent goroutines) and persists the result with `ds.UpdateVPPTokenCountryCode`. Failures are logged and the row stays `NULL` so the next boot retries.
3. **Backfill app countries** — runs `ds.BackfillVPPAppCountriesFromTokens`, a single SQL `UPDATE` that copies each token's country onto associated `vpp_apps` rows (joined via `vpp_apps_teams.vpp_token_id`) that still have `NULL` country.

## Usage Example

```go
// Called once at server startup — runs in a goroutine so boot is not blocked.
go vpp.BackfillLegacyCountries(ctx, datastore, slogLogger)
```

## Behavior Notes

| Scenario | Outcome |
|---|---|
| No tokens with `NULL` country | Returns immediately after step 1 |
| `GetConfig` fails for a token | Logged as warning; retried on next boot |
| Empty country returned by Apple | Logged as warning; column stays `NULL` |
| All countries already populated | Step 3 is a SQL no-op; completes silently |
