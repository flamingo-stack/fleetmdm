Validates and decodes binary property list (plist) data with strict size, depth, and object-count bounds before passing to the standard decoder — protecting against malformed or adversarial input.

## Key Components

| Symbol | Type | Description |
|---|---|---|
| `BoundedPlistUnmarshal` | `func` | Primary entry point; detects binary plists by magic prefix and runs bounds checks before decoding |
| `checkBinaryPlistBounds` | `func` | Parses the 32-byte trailer, validates the offset table, then walks the object graph via `plistBounder` |
| `plistBounder` | `struct` | Stateful walker that recurses into arrays and dicts, enforcing depth and node-count limits |
| `plistCursor` | `struct` | Forward-only byte reader scoped to a single object's region within the raw buffer |
| `maxPlistObjects` | `const` | 65,536 — maximum entries in the offset table |
| `maxPlistDepth` | `const` | 16 — maximum reference nesting depth |
| `maxPlistNodes` | `const` | 65,536 — maximum total objects after reference expansion |
| `errPlistTooComplex` | `var` | Returned when any structural limit is exceeded |
| `errMalformedPlist` | `var` | Returned when structural fields point outside the data region |

## Usage Example

```go
// Decode an MDM device-info response into a flat struct.
// Binary plists are bounds-checked; XML plists pass through directly.
type DeviceInfo struct {
    DeviceName string
    OSVersion  string
    UDID       string
}

func parseDeviceInfo(body []byte) (*DeviceInfo, error) {
    var info DeviceInfo
    if err := apple_mdm.BoundedPlistUnmarshal(body, &info); err != nil {
        return nil, fmt.Errorf("plist decode: %w", err)
    }
    return &info, nil
}
```

## Notes

- XML plists bypass structural checks; caller is responsible for bounding the raw request body size upstream.
- The magic prefix check accepts any `bplist0<digit>` version header (e.g., `bplist00`, `bplist01`).
- All offset arithmetic uses `uint64` with explicit overflow checks to prevent wraparound exploits.
