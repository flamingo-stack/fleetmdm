Defines the HTTP request and response types used exclusively by the ACME service module's endpoint handler, along with a shared nonce-generation helper and a JWS request container for authenticated ACME operations.

## Key Components

### Helper Function
- **`generateAndRenderNonce`** — Creates and stores a new nonce in Redis, then sets `Replay-Nonce` and `Cache-Control` headers on the response.

### Request / Response Pairs

| Endpoint | Request Type | Response Type |
|---|---|---|
| New Nonce | `GetNewNonceRequest` | `GetNewNonceResponse` |
| Directory | `GetDirectoryRequest` | `GetDirectoryResponse` |
| New Account | `CreateNewAccountRequest` | `CreateNewAccountResponse` |
| New Order | `CreateNewOrderRequest` | `CreateNewOrderResponse` |
| Get Order | `GetOrderRequest` / `GetOrderDecodedRequest` | `GetOrderResponse` |
| Get Authorization | `GetAuthorizationRequest` / `GetAuthorizationDecodedRequest` | `GetAuthorizationResponse` |
| List Orders | `ListOrdersRequest` / `ListOrdersDecodedRequest` | `ListOrdersResponse` |
| Get Certificate | `GetCertificateRequest` / `GetCertificateDecodedRequest` | `GetCertificateResponse` |
| Do Challenge | `DoChallengeRequest` / `DoChallengeDecodedRequest` | `DoChallengeResponse` |

### Shared Container
- **`JWSRequestContainer`** — Decodes and validates JWS (JSON Web Signature) payloads common to all authenticated ACME requests; exposes the resolved `JSONWebKey` or `KeyID` for downstream auth.

### Interfaces Implemented
Each response type implements one or more of:
- `Error() error` — `platform_http.Errorer`
- `BeforeRender(ctx, w)` — Emits a fresh nonce header (and `Location` where applicable) before the response is written, skipping nonce generation on fatal errors.
- `Status() int` — Returns the correct HTTP status code.
- `HijackRender` (`GetCertificateResponse`) — Writes the PEM certificate chain directly with `Content-Type: application/pem-certificate-chain`.

## Usage Example

```go
// Typical response flow (handled by the framework):
resp := &CreateNewOrderResponse{
    OrderResponse: orderResp,
    Nonces:        redisNoncesStore,
}

// BeforeRender is called automatically before serialization:
// 1. Generates a fresh nonce → sets Replay-Nonce header
// 2. Sets Location header if an order URL is present
// 3. Returns 201 Created via Status()
```

> **Note:** Authenticated endpoints use a pair of types — a raw `JWSRequestContainer`-based request (URL path params + raw JWS body) and a decoded request (e.g., `GetOrderDecodedRequest`) that carries the parsed account context after JWS validation.
