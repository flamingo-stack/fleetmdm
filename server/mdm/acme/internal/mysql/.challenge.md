MySQL datastore implementation for ACME challenge operations, providing read and write access to `acme_challenges` records with cascading status updates across the ACME order lifecycle.

## Key Components

| Function | Description |
|---|---|
| `GetChallengesByAuthorizationID` | Fetches all challenges for a given authorization ID |
| `GetChallengeByID` | Fetches a single challenge, scoped to a specific account for ownership validation |
| `UpdateChallenge` | Atomically updates challenge status and propagates state changes to parent authorization and order records |

## Usage Example

```go
// Fetch all challenges for an authorization
challenges, err := ds.GetChallengesByAuthorizationID(ctx, authorizationID)
if err != nil {
    // handle types.ChallengeDoesNotExistError or types.MalformedError
}

// Fetch a single challenge, validated against the requesting account
challenge, err := ds.GetChallengeByID(ctx, accountID, challengeID)
if err != nil {
    // handle not found or ownership mismatch
}

// Update challenge status and cascade to authorization + order
challenge.Status = "valid"
updated, err := ds.UpdateChallenge(ctx, challenge)
if err != nil {
    // handle update failure
}
```

## Notes

- `UpdateChallenge` runs inside a retryable transaction (`WithRetryTxx`), updating three tables atomically:
  1. Sets `acme_challenges.status`
  2. Derives `acme_authorizations.status` from the challenge outcome (`valid` → `valid`, otherwise `invalid`)
  3. Advances `acme_orders.status` to `ready` on valid, or `invalid` on failure — guarded against overwriting an already-`invalid` order
- `GetChallengeByID` joins through `acme_authorizations` and `acme_orders` to enforce that the challenge belongs to the requesting account, preventing cross-account access.
