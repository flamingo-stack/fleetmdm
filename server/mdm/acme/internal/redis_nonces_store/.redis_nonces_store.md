Redis-backed ACME nonce store implementing creation, expiration, and single-use consumption of nonces for the ACME protocol in the Fleet MDM server.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `RedisNoncesStore` | struct | Redis-backed store implementing the ACME nonce interface |
| `New` | func | Constructor accepting a `acme.RedisPool` and returning a `*RedisNoncesStore` |
| `Store` | method | Writes a nonce key to Redis with a configurable TTL using `SET ... PX` |
| `Consume` | method | Atomically validates and deletes a nonce via `DEL`; returns `true` only if the key existed |
| `DefaultNonceExpiration` | const | Default nonce TTL — `1 hour` |
| `prefix` | const | Key namespace `"acmenonce:"` to avoid collisions with other Redis key domains |

## Usage Example

```go
import (
    redisnonces "github.com/flamingo-stack/fleetmdm/server/mdm/nonces/redis_nonces_store"
)

// Initialize the store with an existing Redis pool
store := redisnonces.New(redisPool)

// Store a new nonce with the default expiration
nonce := "abc123xyz"
err := store.Store(ctx, nonce, redisnonces.DefaultNonceExpiration)
if err != nil {
    log.Fatal(err)
}

// Consume the nonce (validates + deletes atomically)
valid, err := store.Consume(ctx, nonce)
if err != nil {
    log.Fatal(err)
}
if !valid {
    // nonce was already used or never existed
}

// Second call always returns false — nonce is gone
valid, _ = store.Consume(ctx, nonce) // false
```

## Notes

- Nonce keys are namespaced under `acmenonce:` to avoid collisions with other Fleet Redis key domains (e.g. live queries, calendar locks).
- `Consume` is an atomic delete — a nonce cannot be reused regardless of concurrent requests.
- The `testPrefix` field allows isolated key spaces during testing to prevent cross-test key collisions.
