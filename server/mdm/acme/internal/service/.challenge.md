Validates ACME challenge responses for device attestation workflows, specifically handling Apple enterprise device attestation statements as part of the MDM enrollment process.

## Key Components

### `ValidateChallenge`
Primary entry point that retrieves a pending challenge by ID, dispatches to the appropriate validation handler based on challenge type, persists the result, and returns a populated `ChallengeResponse` with status, token, and URL.

### `validateDeviceAttestationChallenge`
Decodes and parses the raw base64url+CBOR attestation payload, validates its structure, and routes to the format-specific validator (currently only `"apple"` format is supported).

### `validateAppleDeviceAttestationStatement`
Core Apple attestation logic:
- Builds a certificate chain using the embedded **Apple Enterprise Attestation Root CA**
- Verifies the leaf certificate chains up to the Apple root
- Extracts the Apple-specific OID extensions: `OIDAppleSerialNumber` and `OIDAppleNonce`
- Confirms the nonce matches `sha256(challenge.Token)` using constant-time comparison
- Confirms the certificate serial number matches `enrollment.HostIdentifier`
- Verifies the device is DEP-enrolled via `s.providers.IsDEPEnrolled`
- Calls `challenge.MarkValid()` or `challenge.MarkInvalid()` by reference

## Usage Example

```go
// Called by the ACME HTTP handler after receiving a POST to /challenges/{id}
response, err := svc.ValidateChallenge(ctx, enrollment, account, challengeID, rawPayload)
if err != nil {
    // returns typed errors: MalformedError, BadAttestationStatementError, etc.
    handleACMEError(w, err)
    return
}
// response.Status == "valid" on success
```

## Notes

- `TestAppleRootCAs` can be injected on the `Service` struct to override the embedded root CA in tests
- Challenge status, authorization status, and order status are all updated atomically via `store.UpdateChallenge`; this assumes a 1:1:1 order→authorization→challenge relationship
