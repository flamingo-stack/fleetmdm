Handles Android MDM Pub/Sub push notifications from Google's Android Management API (AMAPI), routing enrollment, status report, and command notification types to their respective handlers.

## Key Components

### Types & Constants
- `PubSubPushRequest` — HTTP request struct carrying the PubSub token (query param) and message body
- `DeviceOwnershipCompanyOwned` / `DeviceOwnershipPersonallyOwned` — AMAPI device ownership constants

### Endpoint
- `pubSubPushEndpoint` — Fleet transport-layer endpoint that delegates to `ProcessPubSubPush`

### Service Methods
- `ProcessPubSubPush` — Entry point; decodes base64 message data and dispatches to the correct handler based on `notificationType`
- `authenticatePubSub` — Validates the incoming PubSub token against the stored `MDMAssetAndroidPubSubToken` asset
- `getClientAuthenticationSecret` — Retrieves the Android Fleet server secret from MDM config assets
- `handlePubSubCommand` — Processes AMAPI `COMMAND` notifications; correlates the operation name to a Fleet command row and transitions its status to `acknowledged` or `error`
- `handleAndroidWipeAckUnenroll` — Post-WIPE-ack cleanup: flips `host_mdm.enrolled`, clears BYO wipe refs, and emits `mdm_unenrolled` activity
- `clearAndroidBYOWipeRef` — Removes `host_mdm_actions` for BYO (personally-owned) devices after wipe so the "Wiped" badge is not shown incorrectly

## Usage Example

```go
// Registered as a Fleet HTTP endpoint; called by Google Cloud Pub/Sub push subscription
req := &PubSubPushRequest{
    Token: "your-pubsub-token",
    PubSubMessage: android.PubSubMessage{
        Data: base64.StdEncoding.EncodeToString(rawPayload),
        Attributes: map[string]string{
            "notificationType": "ENROLLMENT",
        },
    },
}
err := svc.ProcessPubSubPush(ctx, req.Token, &req.PubSubMessage)
```
