Handles construction and persistence of Android MDM policy request objects, bridging Google Android Management API payloads with Fleet's internal datastore models.

## Key Components

| Function | Description |
|---|---|
| `newAndroidDeviceRequest` | Creates an `MDMAndroidPolicyRequest` from a raw `androidmanagement.Device` object |
| `newAndroidPolicyApplicationsRequest` | Builds a request to modify (add/update) app policies on an Android management policy |
| `newAndroidPolicyRemoveApplicationsRequest` | Builds a request to remove applications from an Android management policy by package name |
| `newAndroidPolicyRequest` | Constructs a full policy request including settings-origin metadata for profile tracking |
| `recordAndroidRequestResult` | Persists the result of an Android API call (success or error) to the Fleet datastore |
| `applyFleetEnforcedSettings` | Injects mandatory Fleet-controlled `StatusReportingSettings` into a policy before it is pushed |

## Usage Example

```go
// Build a policy request with metadata
policy := &androidmanagement.Policy{ /* ... */ }
metadata := map[string]string{"someKey": "profileA"}
req, err := newAndroidPolicyRequest(policyID, policyName, policy, metadata)

// Apply Fleet-enforced reporting settings before sending
applyFleetEnforcedSettings(policy)

// After calling the Google AMAPI, record the result
skip, err := recordAndroidRequestResult(ctx, ds, req, policyResult, nil, apiErr)
if skip {
    // policy was not modified; skip downstream processing
}
```

## Notes

- `recordAndroidRequestResult` handles `*googleapi.Error` unwrapping to capture HTTP status codes.
- The "not modified" (`304`) path sets `skip = true` but is treated as non-critical per inline comments — policy version comparison is the authoritative change signal.
- `applyFleetEnforcedSettings` always overrides `StatusReportingSettings`, ensuring Fleet telemetry fields cannot be disabled by user-defined profiles.
