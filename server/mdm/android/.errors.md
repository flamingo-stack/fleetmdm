Defines custom error types for the Android MDM package, providing structured error handling for resource conflict scenarios.

## Key Components

### `ConflictError`

A struct that wraps a standard `error` and signals a resource conflict (e.g., attempting to create a resource that already exists).

| Method | Description |
|---|---|
| `IsConflict() bool` | Returns `true`, implementing the `conflictErrorInterface` from `transport_error.go` |
| `IsClientError() bool` | Returns `true`, ensuring the error is logged at `info`/`debug` level rather than `error` level in server logs |

### `NewConflictError(err error) *ConflictError`

Constructor that wraps an existing `error` in a `ConflictError`.

## Usage Example

```go
func createDevice(deviceID string) error {
    if deviceExists(deviceID) {
        return android.NewConflictError(fmt.Errorf("device %s already enrolled", deviceID))
    }
    // ...
    return nil
}

// Caller can type-check the error
if err := createDevice("device-123"); err != nil {
    var conflictErr *android.ConflictError
    if errors.As(err, &conflictErr) {
        // Handle conflict gracefully — logged at info/debug level
    }
}
```

## Notes

- `ConflictError` integrates with Fleet's transport error classification system via `conflictErrorInterface` defined in `transport_error.go`
- Marking the error as a client error prevents noisy `error`-level log entries for expected client-side conflicts
