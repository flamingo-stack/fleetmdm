Defines the `User` value type and `UserProvider` interface for the activity bounded context, enabling user data lookup without direct coupling to the legacy user service.

## Key Components

| Symbol | Kind | Description |
|--------|------|-------------|
| `User` | struct | Minimal user projection (ID, Name, Email, Gravatar, APIOnly) shared across the activity context |
| `UserProvider` | interface | Port for fetching and searching users; implemented by an ACL adapter |
| `UsersByIDs` | method | Batch-fetches users by ID slice, used to enrich activity records |
| `FindUserIDs` | method | Returns user IDs matching a name/email prefix, powering `query` parameter searches |

## Usage Example

```go
// Implement UserProvider in your ACL adapter:
type fleetUserAdapter struct {
    svc fleet.Service
}

func (a *fleetUserAdapter) UsersByIDs(ctx context.Context, ids []uint) ([]*activity.User, error) {
    users, err := a.svc.ListUsersByIDs(ctx, ids)
    if err != nil {
        return nil, err
    }
    out := make([]*activity.User, len(users))
    for i, u := range users {
        out[i] = &activity.User{
            ID:    u.ID,
            Name:  u.Name,
            Email: u.Email,
        }
    }
    return out, nil
}

func (a *fleetUserAdapter) FindUserIDs(ctx context.Context, query string) ([]uint, error) {
    return a.svc.SearchUserIDs(ctx, query)
}
```

## Notes

- `User` is intentionally minimal — only fields required by the activity context are included, following the [ACL pattern](https://martinfowler.com/bliki/AnticorruptionLayer.html) to avoid bleeding legacy domain concepts inward.
- `APIOnly` signals service-account users that may need special handling in activity feeds.
