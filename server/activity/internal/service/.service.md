Service implementation for the activity bounded context, providing paginated listing and audit log streaming of organization-wide and host-specific activities.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `Service` | struct | Core service implementing `api.Service`; holds authorizer, datastore, data providers, and logger |
| `NewService` | func | Constructor for `Service` |
| `ListActivities` | method | Returns paginated organization-wide activities, optionally enriched with user data and filtered by search query |
| `ListHostPastActivities` | method | Returns paginated past activities for a specific host with two-phase authorization (list then read) |
| `StreamActivities` | method | Cursor-paginated batch streaming of unstreamed activities to an audit `JSONLogger` |
| `enrichWithUserData` | method | Hydrates activity records with actor email, gravatar, full name, and API-only flag via a bulk user lookup |
| `applyListOptionsDefaults` | func | Sets sane ordering and per-page defaults on `api.ListOptions` |
| `idCursor` | func | Converts a `uint` activity ID to a string cursor for cursor-based pagination |
| `streamBatchSize` | const | Batch size (500) used when fetching activities during streaming |

## Usage Example

```go
svc := service.NewService(authz, store, providers, logger)

// List org-wide activities
activities, meta, err := svc.ListActivities(ctx, api.ListOptions{
    MatchQuery: "deploy",
    PerPage:    25,
})

// List past activities for a host
hostActivities, meta, err := svc.ListHostPastActivities(ctx, hostID, api.ListOptions{})

// Stream unstreamed activities to an audit sink (typically called by a cron job)
err = svc.StreamActivities(systemCtx, auditLogger)
```

## Notes

- **Authorization** follows a two-phase pattern for host endpoints: first a generic `ActionList` on `Host`, then `ActionRead` on the resolved host (to enforce team-scoped access).
- **Cursor-based pagination** in `StreamActivities` prevents skipped records caused by shrinking result sets or replica lag as activities are marked streamed.
- **Error handling** in `StreamActivities` uses `go-multierror` to accumulate both streaming and mark-as-streamed errors, stopping on the first stream failure to allow retry on the next cron iteration.
