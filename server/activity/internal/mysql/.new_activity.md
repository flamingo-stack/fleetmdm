Persists a new activity record to the MySQL database, handling user attribution, automation flags, host associations, and webhook pre-processing validation within a retryable transaction.

## Key Components

- **`NewActivity`** — Inserts an activity into `activity_past` and optionally into `activity_host_past` for host-linked activities. Enforces that the activity webhook context key has been set prior to storage (must be called via `svc.NewActivity`, not directly).

## Behavior Details

| Condition | Behavior |
|---|---|
| `user == nil` | System/automated activity; `user_email` omitted (defaults to empty) |
| `user.Deleted == true` | `user_id` set to `nil` but `user_name`/`user_email` preserved |
| Implements `AutomatableActivity` | `user_name` set to automation author constant; `fleet_initiated = true` |
| Implements `ActivityHostOnly` | `host_only = true` |
| Implements `ActivityHosts` | Bulk-inserts `(host_id, activity_id)` rows into `activity_host_past` |

## Usage Example

```go
// Called indirectly via the service layer (never call ds.NewActivity directly)
err := svc.NewActivity(ctx, user, fleet.ActivityTypeInstalledSoftware{
    HostID:   42,
    Software: "ExampleApp",
}, createdAt)
if err != nil {
    log.Fatal(err)
}
```

> **Note:** The webhook context key (`types.ActivityWebhookContextKey`) **must** be set in `ctx` before this method is invoked. Calling `ds.NewActivity` directly without going through the service layer will return an error.
