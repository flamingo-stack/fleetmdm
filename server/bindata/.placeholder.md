Provides stub implementations of the `bindata` asset functions that panic at runtime, enabling Fleet to be imported as a Go library without requiring embedded assets (active only when the `full` build tag is absent).

## Key Components

| Function | Signature | Description |
|---|---|---|
| `Asset` | `(name string) ([]byte, error)` | Stub for retrieving a binary asset by name |
| `AssetDir` | `(name string) ([]string, error)` | Stub for listing asset names within a directory |
| `AssetInfo` | `(name string) (os.FileInfo, error)` | Stub for retrieving file metadata for a named asset |

All three functions panic immediately with the message `"Assets may not be used when running Fleet as a library"`.

## Build Tag Behavior

```text
Build tag:  !full  →  this file is compiled (library/placeholder mode)
Build tag:   full  →  this file is excluded (real asset bindings are used)
```

The `//go:build !full` constraint ensures these stubs are replaced by the actual generated `bindata` implementations when building Fleet as a full standalone binary.

## Usage Example

```bash
# Import Fleet as a library (placeholder stubs are active)
go get github.com/flamingo-stack/fleetmdm
```

```go
// Calling any asset function outside a full build will panic:
data, err := bindata.Asset("templates/email.html")
// panic: Assets may not be used when running Fleet as a library

// To enable real assets, build with the full tag:
// go build -tags full ./...
```

> **Note:** These placeholders exist solely to satisfy the Go package interface during library consumption. Never call these functions at runtime unless building with `-tags full`.
