Defines authorization error types for the `authz` package, providing structured errors for forbidden access and missing authorization checks.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `ForbiddenErrorMessage` | `const` | Intentionally vague client-facing error message (`"forbidden"`) |
| `Forbidden` | `struct` | Authorization error carrying internal detail, subject, object, and action |
| `ForbiddenWithInternal` | `func` | Constructs a `Forbidden` error with a rich internal message hidden from clients |
| `CheckMissing` | `type alias` | Deprecated alias for `platform_http.CheckMissing` |
| `CheckMissingWithResponse` | `var` | Deprecated alias for `platform_http.CheckMissingWithResponse` |

**`Forbidden` implements:**
- `error` — returns the vague `"forbidden"` string publicly
- `StatusCode() int` — returns `http.StatusForbidden` (403)
- `IsClientError() bool` — signals this is a 4xx client error
- `Internal() string` — exposes detailed message for server-side logging only
- `LogFields() []interface{}` — structured log fields (subject email, object, action)

## Usage Example

```go
import "github.com/fleetdm/fleet/v4/server/authz"

func (svc *Service) DeleteHost(ctx context.Context, host *fleet.Host) error {
    subject, _ := viewer.FromContext(ctx)

    if !subject.CanPerform("delete", host) {
        return authz.ForbiddenWithInternal(
            "user lacks delete permission on host",
            subject.User,
            host,
            "delete",
        )
    }
    // ...
}
```

The client receives only `"forbidden"` (403), while the server logs the full context via `Internal()` and `LogFields()` — preventing information leakage without losing observability.

> **Note:** `CheckMissing` and `CheckMissingWithResponse` are deprecated aliases. Prefer importing directly from `platform_http`.
