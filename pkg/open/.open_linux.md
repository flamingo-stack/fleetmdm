Linux-specific implementation for opening URLs in the user's default browser using `xdg-open`, with environment variable resolution from running desktop session processes.

## Key Components

| Function | Description |
|---|---|
| `browser(url string)` | Launches `xdg-open` asynchronously with a merged environment suitable for desktop session awareness |
| `getProcessesByName(exePath string)` | Returns processes matching a given executable path that are owned by the current user |
| `localEnv()` | Returns the current process environment as a `map[string]string` |
| `getEnvironmentVariablesFromNamedProcess(exePaths, envvars...)` | Reads specific env vars from named running processes owned by the current user |
| `newEnvironmentWithVariablesFromNamedProcesses(exePaths, envvars...)` | Merges current environment with env vars scraped from target processes; returns a slice for use with `exec.Cmd.Env` |
| `envVarsToCopy` | Allowlist of XDG/desktop-related variables copied from `xdg-desktop-portal` and `Xwayland` processes |

## Usage Example

```go
// Open a URL in the user's default browser on Linux.
// Internally resolves XDG env vars from xdg-desktop-portal and Xwayland processes.
err := browser("https://example.com")
if err != nil {
    log.Fatal().Err(err).Msg("failed to open browser")
}

// Build an environment slice for a custom command, merging env vars
// from a running desktop session process.
env := newEnvironmentWithVariablesFromNamedProcesses(
    []string{"xdg-desktop-portal", "Xwayland"},
    "XDG_CURRENT_DESKTOP", "XDG_RUNTIME_DIR", "PATH",
)
cmd := exec.Command("some-tool")
cmd.Env = env
```

## Notes

- `browser()` uses `cmd.Start()` (not `Run()`) to avoid blocking if `xdg-open` spawns and holds the browser process.
- `_` and `LD_LIBRARY_PATH` are explicitly stripped from the constructed environment to prevent interference.
- KDE sessions have `XDG_CURRENT_DESKTOP` unset before invoking `xdg-open` to avoid version-specific KDE detection bugs; `xdg-open` falls back to generic browser-launch behavior.
