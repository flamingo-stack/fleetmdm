Provides a thread-safe retry manager that limits function call attempts per unique key and enforces a cooldown period after the maximum retry count is reached.

## Key Components

### Types

| Name | Description |
|------|-------------|
| `ExcessRetriesError` | Error returned when retries are exhausted and cooldown has not yet elapsed; includes time until next retry |
| `LimitedWithCooldown` | Thread-safe struct tracking retry counts and cooldown windows per hash key |

### Functions

| Name | Signature | Description |
|------|-----------|-------------|
| `NewLimitedWithCooldown` | `(maxRetries int, cooldown time.Duration) *LimitedWithCooldown` | Constructs a new instance with the given limits |
| `Do` | `(hash string, fn func() error) error` | Executes `fn` under retry/cooldown constraints for the given hash key |

## Usage Example

```go
// Allow up to 3 retries, then enforce a 5-minute cooldown
retryer := retry.NewLimitedWithCooldown(3, 5*time.Minute)

err := retryer.Do("update-agent-v1.2.3", func() error {
    return downloadAndInstall("v1.2.3")
})

if err != nil {
    var excessErr *retry.ExcessRetriesError
    if errors.As(err, &excessErr) {
        log.Printf("Skipping update: %v", excessErr)
        // Output: "max retries exceeded, retrying again in 4m32s"
    } else {
        log.Printf("Attempt failed: %v", err)
    }
}
```

## Behavior Notes

- **Cooldown reset**: on a successful `fn` execution, both the retry count and cooldown timer for that hash are cleared
- **Cooldown trigger**: the cooldown clock starts when `retries[hash]` first reaches `maxRetries`
- **Thread safety**: a `sync.Mutex` guards all map reads and writes, making this safe for concurrent use by the `fleetd` updater
