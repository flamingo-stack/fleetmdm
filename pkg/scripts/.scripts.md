Defines shared timeout constants used by both fleetd and the Fleet server to coordinate script execution lifecycle limits.

## Key Components

| Constant | Value | Description |
|---|---|---|
| `MaxHostExecutionTime` | `5m` | Maximum time a script may run on a host before termination |
| `MaxServerWaitTime` | `6m` | Server-side wait cap during synchronous execution, includes a 1-minute buffer for notification delivery |
| `MaxHostSoftwareInstallExecutionTime` | `1h` | Per-step timeout for software installer scripts (install, post-install, uninstall); excludes download time |

## Usage Example

```go
import (
    "time"
    "github.com/flamingo-stack/fleetmdm/scripts"
)

// Enforce host-side script timeout
ctx, cancel := context.WithTimeout(ctx, scripts.MaxHostExecutionTime)
defer cancel()

// Wait for synchronous script result with server buffer
ctx, cancel = context.WithTimeout(ctx, scripts.MaxServerWaitTime)
defer cancel()

// Apply extended timeout for software installer steps
ctx, cancel = context.WithTimeout(ctx, scripts.MaxHostSoftwareInstallExecutionTime)
defer cancel()
```

## Notes

- `MaxServerWaitTime` deliberately exceeds `MaxHostExecutionTime` by 1 minute to absorb latency in the notification delivery path between server and host.
- `MaxHostSoftwareInstallExecutionTime` applies uniformly to **each individual step** of the install lifecycle, not the total operation.
