Defines the deprecated GitOps YAML key mapping registry and the migration logic that renames deprecated keys to their canonical equivalents during GitOps input processing.

## Key Components

- **`DeprecatedKeyMapping`** — Struct holding an `OldPath`/`NewPath` pair using dot notation, where `[]` denotes iteration over array elements (e.g., `org_settings.mdm.apple_business[].macos_team`).
- **`DeprecatedGitOpsKeyMappings`** — Authoritative slice of all deprecated-to-current key renames, used by both runtime migration (`ApplyDeprecatedKeyMappings`) and YAML serialization alias generation (`buildAliasRules` in `generate_gitops.go`).
- **`ApplyDeprecatedKeyMappings(data, logFn)`** — Entry point that iterates every mapping and applies migrations in order. Returns an error if a user specifies both the old and new key simultaneously.
- **`migrateKeyPath` / `migrateKeyPathRecursive`** — Recursive traversal helpers that split dot-separated paths and handle both nested maps and array elements via the `[]` suffix convention.
- **`migrateLeafKey`** — Performs the actual rename: copies the old value to the new key, deletes the old key, and emits a deprecation warning via the provided `Logf` function (guarded by `logging.DeprecatedFieldTopic`).

## Usage Example

```go
data := map[string]any{
    "team_settings": map[string]any{"features": "..."},
    "queries":       []any{},
}

err := spec.ApplyDeprecatedKeyMappings(data, func(format string, args ...any) {
    fmt.Printf(format, args...)
})
if err != nil {
    log.Fatal(err)
}
// data now contains "settings" and "reports"; "team_settings" and "queries" are removed.
```

> **Adding a deprecation:** append a `DeprecatedKeyMapping` entry to `DeprecatedGitOpsKeyMappings`. Order matters — rename parent keys before their children so nested paths resolve correctly after the parent is moved.
