ESLint configuration for the FleetMDM frontend, defining linting rules, parser settings, and plugin integrations for a mixed TypeScript/JavaScript React codebase.

## Key Components

- **Extends**: Inherits from `airbnb`, `jest`, `react-hooks`, `@typescript-eslint`, `prettier`, and `storybook` rule sets
- **Parser**: Uses `@typescript-eslint/parser` for TypeScript support
- **Plugins**: `jest`, `react`, `@typescript-eslint`
- **Environments**: `node`, `mocha`, `browser`, and `jest/globals`
- **Import Resolver**: Webpack-based resolver pointing to `webpack.config.js`

## Notable Rule Overrides

| Rule | Setting | Reason |
|------|---------|--------|
| `@typescript-eslint/ban-ts-comment` | `off` | Allows `ts-ignore` for unconverted JS modules (TS7016) |
| `@typescript-eslint/explicit-module-boundary-types` | `off` | Mixed JS/TS codebase compatibility |
| `no-shadow` / `@typescript-eslint/no-shadow` | base `off`, TS `error` | Avoids duplicate reports; uses TS-aware version |
| `no-use-before-define` / `@typescript-eslint/no-use-before-define` | base `off`, TS `error` | Same pattern — TS rule replaces base rule |
| `jsx-a11y/heading-has-content` & `anchor-has-content` | `off` | Known bug in `jsx-a11y` v5.1.1 |
| `react/jsx-filename-extension` | `.jsx`, `.tsx` | Restricts JSX to typed extensions only |

## Usage Example

```bash
# Run ESLint against the frontend source
npx eslint frontend/src --ext .js,.jsx,.ts,.tsx
```

ESLint picks up this config automatically from the project root. To lint a single file:

```bash
npx eslint frontend/src/components/MyComponent.tsx
```
