Sails.js bootstrap function that seeds initial application data and manages database state before the app lifts. It handles version-controlled data initialization, environment-aware migration guards, and optional Stripe billing setup.

## Key Components

- **`HARD_CODED_DATA_VERSION`** — Integer version flag; increment to force a fresh data seed on next boot
- **`bootstrapLastRunInfoPath`** — Tracks last bootstrap run metadata at `.tmp/bootstrap-version.json`
- **Migration guard** — Skips destructive operations when `NODE_ENV=production` or `migrate: 'safe'` is set
- **Platform record check** — Asserts at most one `Platform` record exists to maintain freeze/unfreeze consistency
- **Admin user seed** — Creates a default `admin@example.com` superadmin with a Fleet sandbox config and 30-day premium trial license
- **Stripe integration** — Conditionally registers the seed user as a Stripe customer when `enableBillingFeatures` is enabled
- **Bootstrap version persistence** — Writes run metadata back to `.tmp/bootstrap-version.json` to skip redundant re-runs

## Usage Example

Bootstrap runs automatically on `sails lift`. To force a re-seed:

```bash
# Force via migration strategy
sails lift --drop

# Force via test environment
sails lift --environment=test
```

To bump the seed data, increment `HARD_CODED_DATA_VERSION` in the file:

```javascript
var HARD_CODED_DATA_VERSION = 2; // triggers re-seed on next lift
```

To conditionally enable Stripe customer creation, set in `config/custom.js`:

```javascript
module.exports.custom = {
  enableBillingFeatures: true,
};
```

> **Note:** The bootstrap deliberately skips creating a `Platform` record to prevent consistency violations with the branch-freeze logic.
