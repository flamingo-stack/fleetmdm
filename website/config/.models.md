Global Sails.js ORM configuration that defines project-wide default settings for all models, including schema enforcement, migration strategy, base attributes, encryption keys, and cascade behavior.

## Key Components

| Setting | Value | Description |
|---|---|---|
| `schema` | `true` | Rejects unrecognized attributes not defined in the model |
| `migrate` | `alter` | Auto-rebuilds schema on lift; forced to `safe` in production |
| `attributes` | `createdAt`, `updatedAt`, `id` | Base fields injected into every model automatically |
| `dataEncryptionKeys` | `default` key | DEK used for attributes marked `encrypt: true` |
| `cascadeOnDestroy` | `true` | Automatically cleans up associated records on delete |

## Usage Example

These settings apply automatically to all models. Override any setting per-model by redeclaring it in the model file:

```javascript
// api/models/Device.js - overrides schema enforcement for this model only
module.exports = {
  schema: false, // allow unrecognized attributes for this model
  attributes: {
    hostname: { type: 'string', required: true },
    enrolledAt: { type: 'number' },
    secretToken: { type: 'string', encrypt: true }, // encrypted using default DEK
  }
};
```

> **MongoDB users:** Replace the default `id` attribute in `models.js` with:
> ```javascript
> id: { type: 'string', columnName: '_id' }
> ```

## Notes

- **Production safety:** `migrate: 'alter'` is automatically overridden to `migrate: 'safe'` in production, preventing accidental schema changes.
- **Encryption key rotation:** Multiple DEKs can be added alongside `default`; only `default` is used for new writes.
- **Cascade cleanup:** `cascadeOnDestroy: true` uses a polyfill — consider disabling it in production if your database handles FK constraints natively.
