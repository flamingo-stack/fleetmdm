Registers the `edit-profile` parasails page, handling form state and submission for updating a user's full name and email address.

## Key Components

| Member | Type | Description |
|---|---|---|
| `syncing` | Data | Loading/syncing state flag for the page |
| `formData` | Data | Holds `fullName` and `emailAddress` input values |
| `formErrors` | Data | Tracks client-side validation errors per field |
| `formRules` | Data | Validation rules requiring `fullName` and a valid `emailAddress` |
| `cloudError` | Data | Stores server-side error messages |
| `beforeMount` | Lifecycle | Pre-populates form with current user data, preferring `emailChangeCandidate` if present |
| `submittedForm` | Method | Handles successful form submission and redirects to `/account` |

## Usage Example

```javascript
// Form rules enforce both fields are required, with email format validation
formRules: {
  fullName:     { required: true },
  emailAddress: { required: true, isEmail: true },
}

// beforeMount pre-fills the form from the current user session
this.formData.fullName = this.me.fullName;
this.formData.emailAddress = this.me.emailChangeCandidate
  ? this.me.emailChangeCandidate
  : this.me.emailAddress;

// On successful submission, syncing is kept true to show spinner
// during the navigation redirect
submittedForm: async function() {
  this.syncing = true;
  this.goto('/account');
}
```

> **Note:** The `emailChangeCandidate` field takes precedence over `emailAddress` in the pre-fill logic, supporting pending email change workflows where the new address awaits verification.
