Parasails page controller for the "new password" flow, handling form validation and submission for users setting a new password via a reset token.

## Key Components

| Member | Type | Description |
|--------|------|-------------|
| `syncing` | `Boolean` | Loading/spinner state during async operations |
| `formData` | `Object` | Holds `password`, `confirmPassword`, and `token` fields |
| `formErrors` | `Object` | Tracks client-side validation failures per field |
| `formRules` | `Object` | Validation rules for `password` and `confirmPassword` |
| `cloudError` | `String` | Stores server-side error messages |
| `submittedForm` | `Method` | Handles post-submission redirect to `/customers/login` |

## Validation Rules

The `password` field enforces:
- Required, 12–48 characters
- Custom regex requiring at least one digit and one special character:

```javascript
value.match(/^(?=.*\d)(?=.*[^A-Za-z0-9]).{12,48}$/)
```

The `confirmPassword` field enforces the same length constraints plus `sameAs: 'password'` to ensure both fields match.

## Usage Example

```javascript
// The page auto-injects the reset token from the server-rendered context
// on mount, then waits for form submission.

mounted: async function() {
  this.formData.token = this.token; // token passed from server context
},

// On successful form submission, syncing stays true during redirect
submittedForm: async function() {
  this.syncing = true;
  this.goto('/customers/login');
}
```

## Notes

- The `token` value is sourced from a server-provided page prop and injected into `formData` on mount, ensuring it is included in the API request.
- The spinner (`syncing`) intentionally remains active through page navigation to avoid a flash of unsecured UI.
