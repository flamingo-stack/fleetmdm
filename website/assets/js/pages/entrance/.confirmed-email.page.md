Registers the `confirmed-email` parasails page component, which handles the post-email-confirmation landing view shown to users after they verify their email address.

## Key Components

| Member | Type | Description |
|---|---|---|
| `data` | Object | Reactive state for the confirmed email page |
| `beforeMount` | Lifecycle hook | Runs synchronously before the component mounts |
| `mounted` | Lifecycle hook | Async setup logic executed after the component mounts |
| `methods` | Object | Page-specific interaction handlers |

## Usage Example

```javascript
// Extending the page with custom confirmation logic
parasails.registerPage('confirmed-email', {
  data: {
    redirectUrl: '/',
    message: 'Your email has been confirmed!'
  },

  beforeMount: function() {
    // Pre-mount setup, e.g. read server-injected locals
  },

  mounted: async function() {
    // Trigger redirect or fetch post-confirmation data
    await this.$nextTick();
    window.location = this.redirectUrl;
  },

  methods: {
    handleContinue() {
      window.location = this.redirectUrl;
    }
  }
});
```

## Notes

- Registered via [`parasails.registerPage`](https://github.com/mikermcneil/parasails), which wires the component into the Fleet MDM frontend lifecycle.
- The page scaffold is minimal by default — logic is added as needed for post-confirmation UX flows (e.g. redirects, success messaging, or account setup prompts).
- Source: [`flamingo-stack/fleetmdm`](https://github.com/flamingo-stack/fleetmdm)
