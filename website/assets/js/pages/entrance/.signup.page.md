Parasails page component for the Fleet signup flow, handling user registration form state, validation, and post-signup analytics tracking and redirection.

## Key Components

**Form State**
- `formData` — Collects user input (firstName, lastName, emailAddress, password)
- `formErrors` — Tracks client-side validation failures per field
- `formRules` — Enforces required fields, email format, and password complexity (12–48 chars, must include a digit and special character)
- `syncing` / `cloudError` — Loading and server error states

**Lifecycle Hooks**
- `beforeMount` — Reads `window.location.hash` to conditionally redirect to `/new-license` (`#purchaseLicense`) or `/try-fleet` (`#tryfleet`) after registration; defaults to `/try`
- `mounted` — Reserved for async initialization

**Methods**
- `clickResetForm` — Clears cloud/form errors and re-renders the full form
- `typeClearOneFormError(field)` — Removes a single field's validation error on keypress
- `submittedSignUpForm` — Fires Google Analytics (`fleet_website__sign_up`) and conversion events, fires LinkedIn Campaign Manager conversion, then redirects to `pageToRedirectToAfterRegistration`

## Usage Example

```javascript
// Hash-based redirect targeting (set before navigating to /signup)
window.location.href = '/signup#purchaseLicense';
// → After registration, user lands on /new-license

window.location.href = '/signup#tryfleet';
// → After registration, user lands on /try-fleet

// Default (no hash)
// → After registration, user lands on /try
```

## Notes

- Password validation requires at minimum one digit, one special character, and a length of 12–48 characters via a custom regex rule
- Analytics events are guard-checked (`window.gtag`, `window.lintrk`) before firing to avoid runtime errors in environments without those scripts loaded
- `syncing` is intentionally left `true` after form submission to keep the spinner active during page navigation
