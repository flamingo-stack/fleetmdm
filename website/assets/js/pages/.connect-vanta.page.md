Registers the `connect-vanta` parasails page, handling the OAuth-style authorization flow that links a Fleet instance to Vanta for compliance monitoring.

## Key Components

**Form Data & Validation**
- `formData` — Collects `emailAddress`, `fleetInstanceUrl`, and `fleetApiKey`
- `formRules` — Validates email format, requires Fleet URL to start with `http://` or `https://`, and requires a non-empty API key
- `formErrors` / `cloudError` — Tracks field-level and server-side errors

**State**
- `syncing` — Boolean flag set to `true` when redirecting to Vanta after form submission
- `vantaAuthorizationRequestURL` — Stores the OAuth authorization URL returned from the cloud action

## Key Methods

| Method | Description |
|---|---|
| `handleSubmittingAuthorizationForm(argins)` | Calls `Cloud.createVantaAuthorizationRequest` with form values and stores the returned authorization URL |
| `submittedAuthorizationForm()` | Sets `syncing: true` then redirects the user to the stored Vanta authorization URL |
| `clickClearErrors()` | Resets `cloudError` and `formErrors`, then forces a re-render |

## Usage Example

```javascript
// The page is auto-registered via parasails and rendered server-side.
// The form submission flow works as follows:
parasails.registerPage('connect-vanta', {
  methods: {
    handleSubmittingAuthorizationForm: async function(argins) {
      // Step 1: Fetch the Vanta OAuth URL from the backend
      this.vantaAuthorizationRequestURL =
        await Cloud.createVantaAuthorizationRequest.with(argins);
    },
    submittedAuthorizationForm: async function() {
      // Step 2: Redirect the user to Vanta's authorization page
      this.syncing = true;
      this.goto(this.vantaAuthorizationRequestURL);
    },
  }
});
```
