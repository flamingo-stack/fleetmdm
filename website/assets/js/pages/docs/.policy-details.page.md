Parasails page component for the `policy-details` route that handles SQL syntax highlighting for osquery policy code blocks and copy-to-clipboard functionality.

## Key Components

**Data**
- `contributors` — Array for policy contributor data
- `selectedTab` — Controls active tab view, defaults to `'sql'`

**`mounted()`**
- Sorts `columnNamesForSyntaxHighlighting` and `tableNamesForSyntaxHighlighting` by length (longest first) to ensure greedy keyword matching
- Applies custom `hljs` syntax highlighting: table names are wrapped in `hljs-attr` spans, column names in `hljs-string` spans, then `highlightElement` runs on the full block
- Adds `has-linebreaks` or `no-linebreaks` CSS class based on whether the SQL block is multi-line
- Wires up `[purpose="copy-button"]` click handlers to copy visible code block text to the clipboard and briefly apply a `copied` CSS state for 2 seconds

## Usage Example

```javascript
// The page is registered via parasails and driven by server-injected template data.
// Syntax highlighting keywords are passed as page-level props:

// Example props expected by the page:
columnNamesForSyntaxHighlighting: ['pid', 'name', 'path'],
tableNamesForSyntaxHighlighting: ['processes', 'users'],

// Copy button wiring (HTML side):
// <div purpose="codeblock">
//   <pre><code class="sql">SELECT * FROM processes;</code></pre>
//   <button purpose="copy-button">Copy</button>
// </div>
```

## Notes

- Shell/PowerShell blocks (`.ps`, `.sh` classes) skip custom keyword injection and go directly to `hljs.highlightElement`
- Keyword matching uses `innerHTML` regex replacement, so order of operations (tables before columns) matters to avoid double-wrapping
