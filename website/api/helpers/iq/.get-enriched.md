Searches for and returns enriched contact and employer data by querying the Coresignal API using available identifiers (email, LinkedIn URL, or name/organization).

## Key Components

- **Inputs**: `emailAddress`, `linkedinUrl`, `firstName`, `lastName`, `organization`, `includeEmployerHeadquartersInformation`
- **Output (`success` exit)**: Structured `person` and `employer` objects containing LinkedIn URLs, name, title, organization size, email domain, and company LinkedIn page
- **`fn` async function**: Core logic that orchestrates multi-step enrichment:
  1. Parses email domain and LinkedIn slug from raw inputs
  2. Falls back to a name/domain/org search if no LinkedIn URL is provided
  3. Fetches detailed profile data by LinkedIn person ID or slug
  4. Resolves current employer via Elasticsearch DSL query against Coresignal's company API

## Usage Example

```javascript
const report = await sails.helpers.getEnriched({
  emailAddress: 'jane.doe@acme.com',
  firstName: 'Jane',
  lastName: 'Doe',
  organization: 'Acme Corp',
  includeEmployerHeadquartersInformation: false,
});

console.log(report.person.linkedinUrl);        // e.g. "linkedin.com/in/janedoe"
console.log(report.employer.numberOfEmployees); // e.g. 500
```

## Notes

- Requires `sails.config.custom.iqSecret` (Coresignal API key) to be set
- Personal/banned email domains (e.g. Gmail) are stripped from search criteria automatically
- Coresignal does **not** provide emails or phone numbers — only publicly available professional data
- API errors are tolerated gracefully; missing data results in empty/undefined fields rather than thrown exceptions
- See [Coresignal FAQ](https://coresignal.com/faq/) for data availability details
