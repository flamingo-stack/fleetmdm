Checks whether a specific GitHub issue record exists in a BigQuery table within the `github_metrics` dataset, returning a boolean result.

## Key Components

**Inputs**

| Parameter | Type | Required | Description |
|---|---|---|---|
| `repo` | string | ✅ | Repository name (e.g., `"fleetdm/fleet"`) |
| `issueNumber` | number | ✅ | GitHub issue number |
| `gcpServiceAccountKey` | ref | ✅ | GCP service account credentials object |
| `tableId` | string | ✅ | Target BigQuery table name |
| `additionalCondition` | string | ❌ | Optional extra `WHERE` clause fragment |

**Exits**

- `success` — Returns a `boolean`: `true` if a matching record exists, `false` otherwise

**Error Handling**

Gracefully handles BigQuery-specific errors without throwing:

- `PartialFailureError` — Logs affected rows
- `404` — Table/dataset not found; returns `false`
- `403` — Permission denied; returns `false`
- All other errors — Logs and returns `false`

## Usage Example

```javascript
const exists = await sails.helpers.checkIfRecordExists({
  repo: 'fleetdm/fleet',
  issueNumber: 1234,
  gcpServiceAccountKey: serviceAccountJson,
  tableId: 'issue_snapshots',
  additionalCondition: 'AND status = "open"'
});

if (exists) {
  sails.log.info('Record already exists, skipping insert.');
} else {
  sails.log.info('No record found, proceeding with insert.');
}
```

## Notes

- Queries are scoped to the hardcoded `github_metrics` dataset
- Uses parameterized queries (`@repo`, `@issueNumber`) to prevent SQL injection
- The `additionalCondition` string is interpolated directly into the query — ensure it is sanitized before use
