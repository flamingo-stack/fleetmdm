Resolves a Salesforce User ID associated with a geographic territory by querying the Salesforce Apex REST API with location inputs.

## Key Components

- **Inputs:** `state` (string), `city` (string), `country` (string, required)
- **Output:** `territoryUserId` — the Salesforce User ID for the matched territory
- **Exit:** `success` — returns the resolved user ID string

## Behavior Notes

- Throws immediately if `country` is not provided
- City is only forwarded to Salesforce when `state` is `"california"` (case-insensitive) — the only state split across multiple territories
- Authenticates via `jsforce` using credentials from `sails.config.custom.salesforceIntegrationUsername` and `salesforceIntegrationPasskey`
- Calls the custom Apex endpoint `/territory-lookup` with query parameters built from the provided location fields
- Returns the `userId` from the first user in the Salesforce response

## Usage Example

```javascript
let userId = await sails.helpers.salesforce.getTerritoryUserId.with({
  country: 'United States',
  state: 'California',
  city: 'San Francisco',
});
// userId => '0051a000003abcDEF'
```

## Error Handling

Throws descriptive errors in three cases:
1. Missing `country` input
2. Salesforce response does not include a `users` array
3. The first user in the response is missing a `userId` field

All errors include the original inputs and/or raw Salesforce response for debugging.

## Dependencies

| Dependency | Purpose |
|---|---|
| `jsforce` | Salesforce API authentication and Apex REST calls |
| `sails.helpers.flow.build` | Wraps async calls with structured error interception |
