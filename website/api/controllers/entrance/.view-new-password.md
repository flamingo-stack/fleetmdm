Handles the display of the "New Password" page by validating a password reset token before rendering the recovery form.

## Key Components

- **`token`** *(input)*: The password reset token extracted from the email link, used to look up and validate the requesting user.
- **`success`** *(exit)*: Renders `pages/entrance/new-password` with the token passed as a view local.
- **`invalidOrExpiredToken`** *(exit)*: Returns an `expired` response type when the token is missing, not found in the database, or has passed its expiry time.
- **`fn`**: Core handler that validates the token presence, queries the `User` model by `passwordResetToken`, and checks the `passwordResetTokenExpiresAt` timestamp before proceeding.

## Usage Example

This action is typically mapped to a GET route in `config/routes.js`:

```javascript
// config/routes.js
'GET /entrance/new-password': { action: 'entrance/view-new-password' }
```

A user arrives via a reset link structured like:

```text
https://your-app.com/entrance/new-password?token=4-32fad81jdaf$329
```

On success, the token is forwarded to the view for use in the form submission. On failure (missing, unknown, or expired token), the user is redirected to the `expired` response handler.
