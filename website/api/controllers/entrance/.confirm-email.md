Handles email address confirmation for both new user sign-ups and existing user email change requests, then redirects to the appropriate page based on the user's email status.

## Key Components

### Inputs
- **`token`** — The email confirmation token sent to the user's inbox (e.g., `4-32fad81jdaf$329`)

### Exits
| Exit | Description |
|------|-------------|
| `success` | Email confirmed, user logged in (JSON response) |
| `redirect` | Email confirmed, browser redirect issued |
| `invalidOrExpiredToken` | Token is missing, expired, or already consumed |
| `emailAddressNoLongerAvailable` | Email was claimed by another user during the confirmation window (HTTP 409) |

### Core Logic (`fn`)
Two primary flows based on `user.emailStatus`:

- **`unconfirmed`** — First-time confirmation: sets status to `confirmed`, clears the proof token, logs the user in, and redirects to `/email/confirmed`
- **`change-requested`** — Email change confirmation: validates the candidate email is still available, optionally updates the Stripe billing email, applies the new address, and redirects to `/account`

## Usage Example

```javascript
// Triggered via a tokenized link sent to the user's email:
// GET /email/confirm?token=4-32fad81jdaf$329

// JSON clients receive an empty 200 on success.
// Browser clients are redirected based on flow:
//   New users     → /email/confirmed
//   Existing users → /account

// On failure:
//   Missing/expired token → 'expired' response type
//   Email already taken   → HTTP 409
```

> **Note:** The email uniqueness check for `change-requested` is a manual guard — no database-level uniqueness constraint protects the `emailChangeCandidate` field, making this check critical for data integrity.
