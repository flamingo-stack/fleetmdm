Finalizes the password recovery flow by validating a reset token, hashing the new password, clearing the token, and establishing an authenticated session for the user.

## Key Components

**Inputs**
- `password` — The new plaintext password to be hashed and stored
- `token` — The password reset token previously issued by `sendPasswordRecoveryEmail`

**Exits**
- `success` — Password updated and user session established
- `invalidToken` — Token is missing, not found in the database, or has expired; responds with `expired` response type

**Core Logic (`fn`)**
- Validates token presence and looks up the matching `User` record
- Checks `passwordResetTokenExpiresAt` against `Date.now()` to enforce token expiry
- Hashes the new password via `sails.helpers.passwords.hashPassword`
- Clears `passwordResetToken` and `passwordResetTokenExpiresAt` to prevent token reuse
- Sets `req.session.userId` to log in the user immediately after reset

## Usage Example

```javascript
// Called internally by a Sails.js route, e.g. POST /api/v1/account/update-password-and-login
const result = await sails.helpers.updatePasswordAndLogin
  .with({
    password: 'myNewSecurePassword123',
    token: 'gwa8gs8hgw9h2g9hg29hgwh9asdgh9q34$$$$$asdgasdggds'
  })
  .intercept('invalidToken', () => res.expired());
```

> **Security note:** The reset token is invalidated immediately after use by setting both `passwordResetToken` and `passwordResetTokenExpiresAt` to empty/zero, preventing replay attacks.
