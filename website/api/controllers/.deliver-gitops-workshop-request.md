Handles GitOps workshop interest form submissions by validating the submitter's email domain, then creating or updating the corresponding Salesforce contact, account, campaign membership, and historical event records.

## Key Components

**Inputs**

| Field | Type | Required | Notes |
|---|---|---|---|
| `firstName` | string | ✅ | Contact first name |
| `lastName` | string | ✅ | Contact last name |
| `emailAddress` | string (email) | ✅ | Validated against domain denylist |
| `location` | string | ✅ | Submitter's location |
| `numberOfHosts` | string | ✅ | Expected host count |
| `managedPlatforms` | object | ✅ | Map of platform keys to booleans |
| `willingToHost` | string | ❌ | Whether they'd host a workshop |

**Exits**

- `success` — Submission processed successfully
- `invalidEmailDomain` — Email domain is on the configured denylist (`badRequest`)

**Salesforce Operations**

1. `updateOrCreateContactAndAccount` — Upserts the contact with source `Website - GitOps`
2. `createCampaignMember` — Adds contact to campaign `701UG00000bLCLpYAO` *(2026_01-FE-GitOps_Workshop_Interest)*
3. `createHistoricalEvent` — Logs an `Intent signal` event tied to the account and contact

## Usage Example

```javascript
await sails.helpers.deliver.gitopsWorkshopRequest.with({
  firstName: 'Jane',
  lastName: 'Doe',
  emailAddress: 'jane.doe@acme.com',
  location: 'Austin, TX',
  numberOfHosts: '3',
  managedPlatforms: { macos: true, linux: true, windows: false },
  willingToHost: 'yes',
});
```

> **Note:** CRM update failures are tolerated — errors are logged as warnings via `sails.log.warn` without failing the request. The marketing attribution cookie (`marketingAttribution`) is forwarded to Salesforce automatically if present.
