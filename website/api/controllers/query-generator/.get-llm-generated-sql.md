A Sails.js helper that converts natural language IT admin questions into platform-specific osquery SQL queries using a two-stage LLM pipeline.

## Key Components

- **`naturalLanguageQuestion`** *(input)*: The plain-English question from an IT admin to be translated into SQL
- **Schema filtration stage**: Uses `claude-haiku-4-5` to prune the full osquery schema down to only relevant tables before the main generation step
- **SQL generation stage**: Uses `claude-sonnet-4-6` to produce per-platform queries (macOS, Windows, Linux, ChromeOS) with associated caveats
- **WebSocket support**: Joins the requester to a unique room and broadcasts `queryGenerated` or `error` events for real-time delivery
- **`couldNotGenerateQueries` exit**: Returns a `badRequest` response when the LLM determines no valid query can be constructed

## Usage Example

```javascript
// HTTP request (returns JSON directly)
const result = await sails.helpers.getLlmGeneratedSql({
  naturalLanguageQuestion: 'Which macOS hosts have FileVault disabled?'
});
// result =>
// {
//   macOSQuery: "SELECT * FROM disk_encryption WHERE ...",
//   windowsQuery: "",
//   linuxQuery: "",
//   chromeOSQuery: "",
//   macOSCaveats: "...",
//   windowsQuery: "",
//   ...
// }

// Socket request: listen for broadcast events
socket.on('queryGenerated', ({ result }) => console.log(result));
socket.on('error', ({ error }) => console.error(error));
```

## Query Generation Rules Applied by the LLM

1. No SQL `AS` aliases — always use full table names
2. `LIKE` operators must include wildcard characters
3. App/program queries prefer `LIKE` over exact matches
4. Unsupported platforms for a question return an empty string
5. Yes/no questions return one row for "yes", zero for "no"
6. Only schema-documented tables and columns are used per platform
