Handles device compliance status updates by routing data to Microsoft Entra (Azure AD) via the Graph API, supporting both Windows and macOS device flows.

## Key Components

**Inputs**

| Parameter | Type | Description |
|---|---|---|
| `entraTenantId` | string | Microsoft Entra tenant identifier |
| `fleetServerSecret` | string | Shared secret for tenant lookup |
| `deviceId` | string | Device ID in Entra |
| `deviceManagementState` | boolean | Whether device is MDM-enrolled |
| `deviceName` | string | Display name in Fleet |
| `os` / `osVersion` | string | OS platform and version |
| `userPrincipalName` | string | UPN (required for macOS) |
| `compliant` | boolean | Device compliance result |
| `lastCheckInTime` | number | Last Fleet sync time (Unix seconds) |

**Exits**

- `success` — Compliance status sent successfully
- `missingUserPrincipalName` — macOS request missing UPN (`badRequest`)

**OS-specific flows**

- **Windows** — Authenticates via OAuth2 client credentials, sends a `PATCH` to the Graph API devices endpoint to update `isManaged` and `isCompliant` directly
- **macOS** — Uses the `microsoftProxy.getAccessTokenAndApiUrls` helper to obtain tokens, resolves the user's GUID from UPN via Graph API, then sends a `PUT` with a structured payload containing two entity types (device inventory `EntityType: 1` and compliance data `EntityType: 4`) to the Manage API sync URL

## Usage Example

```javascript
await sails.helpers.updateOneDevicesComplianceStatus.with({
  entraTenantId: 'xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx',
  fleetServerSecret: 'fleet-secret-value',
  deviceId: 'entra-device-id',
  deviceManagementState: true,
  deviceName: 'LAPTOP-CORP-001',
  os: 'macOS',
  osVersion: '14.4.1',
  userPrincipalName: 'jane.doe@company.com',
  compliant: true,
  lastCheckInTime: 1718000000
});
// Returns: { message_id: '<uuid>' }
```
