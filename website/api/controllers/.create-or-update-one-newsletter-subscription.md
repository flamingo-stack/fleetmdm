Handles creation or updating of newsletter subscriptions, validating email domains and syncing contact data to Salesforce CRM in the background.

## Key Components

- **`emailAddress`** *(input)* — Required, validated email string used to create or update the subscription record
- **`invalidEmailDomain`** *(exit)* — Thrown when the email's domain matches a configured denylist
- **`fn`** — Core handler that:
  - Validates the email domain against `sails.config.custom.bannedEmailDomainsForWebsiteSubmissions`
  - Upserts a `NewsletterSubscription` record and sets `isSubscribedToReleases: true`
  - Resolves ad attribution from session data (within a 7-day window) or falls back to `'Website - Newsletter'`
  - Fires background Salesforce helpers to sync contact/account data and log a historical intent event

## Usage Example

```javascript
// Called as a Sails action from a route (e.g., POST /newsletter/subscribe)
await sails.helpers.createOrUpdateOneNewsletterSubscription.with({
  emailAddress: 'user@example.com',
});
```

```javascript
// Example route binding in config/routes.js
'POST /newsletter/subscribe': { action: 'create-or-update-one-newsletter-subscription' },
```

## Notes

- Salesforce sync runs **asynchronously** via `.exec()` — failures are logged as warnings but do not surface to the user
- Ad attribution is applied only if `req.session.visitedSiteFromAdAt` falls within the last **7 days**
- Duplicate email addresses are silently tolerated via `.tolerate('E_UNIQUE')` on the initial `create` call
