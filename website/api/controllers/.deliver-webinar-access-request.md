Handles webinar access form submissions by validating the requester's email domain and asynchronously syncing contact/account data and historical intent signals to Salesforce CRM.

## Key Components

- **`friendlyName`** – `'Deliver webinar access request'`
- **Inputs**
  - `firstName` / `lastName` – Requester's name (required strings)
  - `emailAddress` – Validated email address (required, `isEmail`)
  - `webinarName` – Name of the requested webinar (required string)
- **Exits**
  - `success` – Request processed successfully
  - `invalidEmailDomain` – Email domain is on the denylist; returns `badRequest`
- **`fn`** – Core logic: validates domain, reads marketing attribution cookie, then fires a background CRM sync via `sails.helpers.flow.build`

## Usage Example

```javascript
await sails.helpers.deliverWebinarAccessRequest.with({
  firstName: 'Jane',
  lastName: 'Doe',
  emailAddress: 'jane.doe@example.com',
  webinarName: 'Fleet MDM Deep Dive 2025',
});
```

### CRM Background Flow

```javascript
// Internally, the helper:
// 1. Upserts a Salesforce Contact + Account
// 2. Creates a historical "Intent signal" event
await sails.helpers.salesforce.updateOrCreateContactAndAccount.with({ ... });
await sails.helpers.salesforce.createHistoricalEvent.with({
  eventType: 'Intent signal',
  intentSignal: 'Requested webinar recording',
  eventContent: webinarName,
});
```

> **Note:** CRM sync runs in a non-blocking background task via `sails.helpers.flow.build(...).exec(...)`. Failures are logged as warnings but do not surface errors to the caller. Banned email domains are configured in `sails.config.custom.bannedEmailDomainsForWebsiteSubmissions`.
