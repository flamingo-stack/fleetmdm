Processes and delivers contact form submissions to internal notification channels, handling spam filtering, CRM record management, and email delivery.

## Key Components

- **`websiteUrl` (honeypot)** — Silently discards bot submissions if this hidden field is populated
- **Email domain validation** — Checks the submitter's email domain against `sails.config.custom.bannedEmailDomainsForContactFormSubmissions`
- **Fleet Premium detection** — Looks up the authenticated user's `Subscription` record and prepends billing/org details to the message if found
- **Salesforce CRM sync** — Calls `updateOrCreateContactAndAccount` and `createHistoricalEvent` helpers to maintain contact records and log intent signals; failures are tolerated and logged as warnings
- **Marketing attribution** — Forwards the `marketingAttribution` cookie to the Salesforce helpers for campaign tracking
- **Email delivery** — Sends the `email-contact-form` template to the internal `fromEmailAddress`, with `replyTo` set to the submitter

## Usage Example

```javascript
await sails.helpers.deliverContactFormMessage.with({
  emailAddress: 'hermione@hogwarts.edu',
  firstName: 'Hermione',
  lastName: 'Granger',
  message: 'I would like to learn more about Fleet Premium.',
  // websiteUrl: intentionally omitted (honeypot)
});
```

## Error Exits

| Exit | Description |
|---|---|
| `success` | Message delivered (or silently dropped via honeypot) |
| `invalidEmailDomain` | Submitter's domain is on the denylist; returns `400 Bad Request` |

> **Note:** CRM sync and email sending run in a detached background task via `sails.helpers.flow.build`. Failures do not surface to the caller — they are logged as `sails.log.warn` entries to ensure the user always receives a success response.
