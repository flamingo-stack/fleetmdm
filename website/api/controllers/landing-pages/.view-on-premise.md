Sails.js action that renders the on-premise landing page by returning an empty response object and delegating rendering to the configured view template.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `friendlyName` | `string` | Human-readable action label: `'View on-premise'` |
| `description` | `string` | Brief action summary |
| `exits.success` | `object` | Maps successful response to `pages/landing-pages/on-premise` view template |
| `fn` | `async function` | Action handler — returns an empty object, triggering the `success` exit |

## Usage Example

```javascript
// Registered as a route in config/routes.js
'GET /on-premise': { action: 'view-on-premise' }
```

When a `GET` request hits `/on-premise`, Sails.js invokes this action, which returns `{}` through the `success` exit, rendering the `pages/landing-pages/on-premise` view template with no additional data passed to the view.

## Notes

- No inputs are defined — this is a pure display action with no parameters
- No authentication or policy guards are declared within the action itself; access control should be configured at the route or policy level
- To pass data to the view (e.g., dynamic content), extend the `fn` return value and update the view template accordingly
