Sails.js action that handles the "App Library" page by filtering and sorting MDM-managed applications by platform (macOS and Windows) from pre-built static content.

## Key Components

| Export | Type | Description |
|---|---|---|
| `friendlyName` | `string` | Human-readable action name: `'View app library'` |
| `description` | `string` | Action purpose description |
| `exits.success` | `object` | Renders `pages/docs/app-library` view template |
| `exits.badConfig` | `object` | Returns `badConfig` response if static content is misconfigured |
| `fn` | `async function` | Core action handler |

### `fn` Logic

1. **Validates** `sails.config.builtStaticContent.appLibrary` exists and is a valid array — throws `badConfig` if not
2. **Filters** all apps into `macOsApps` (`platform === 'darwin'`) and `windowsApps` (`platform === 'windows'`)
3. **Sorts** each platform list alphabetically by `app.name` (case-insensitive)
4. **Returns** view locals: `allApps`, `windowsApps`, `macOsApps`, and `algoliaPublicKey`

## Usage Example

```javascript
// Sails.js router binding (config/routes.js)
'GET /app-library': { action: 'view-app-library' }

// Expected shape of sails.config.builtStaticContent.appLibrary
sails.config.builtStaticContent.appLibrary = [
  { name: 'Slack', platform: 'darwin',  version: '4.35.0' },
  { name: 'Zoom', platform: 'windows', version: '5.17.0' },
];

// View locals returned on success
{
  allApps:          [...],   // All apps unfiltered
  macOsApps:        [...],   // darwin apps, A–Z
  windowsApps:      [...],   // windows apps, A–Z
  algoliaPublicKey: '...',   // For client-side search
}
```

## Notes

- Depends on `builtStaticContent` being populated at boot time (typically via a Sails hook or build script)
- Algolia public key is passed to the view to support client-side search on the library page
- Source: [`view-app-library.js`](https://github.com/flamingo-stack/fleetmdm/blob/main/view-app-library.js)
