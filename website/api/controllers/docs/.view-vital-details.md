A Sails.js page controller that retrieves and renders detailed information for a specific Fleet "vital" (built-in osquery query) identified by its slug.

## Key Components

- **Input:** `slug` (string, required) — unique identifier for the vital query (e.g., `get-macos-disk-free-space-percentage`)
- **Exits:**
  - `success` — renders `pages/docs/vital-details` view
  - `notFound` — 404 when slug doesn't match any query
  - `badConfig` — 500 when `builtStaticContent` is misconfigured
- **Main logic (`fn`):**
  - Validates `builtStaticContent.queries` and `queryLibraryYmlRepoPath` are present in Sails config
  - Looks up the vital by slug from the static content store
  - Resolves related osquery table docs and extracts `keywordsForSyntaxHighlighting` and table/column name arrays for syntax highlighting
  - Splits all built-in vitals into platform-specific lists: `macOsVitals`, `windowsVitals`, `linuxVitals`, `chromeVitals`
  - Constructs SEO meta title and description from the vital's name/description

## Usage Example

```javascript
// Triggered by a route such as: GET /vitals/:slug
// Sails routing config example:
'GET /vitals/:slug': { action: 'view-vital-details' }

// The controller resolves the slug and passes data to the view:
// {
//   thisVital,
//   macOsVitals, windowsVitals, linuxVitals, chromeVitals,
//   queryLibraryYmlRepoPath,
//   pageTitleForMeta, pageDescriptionForMeta,
//   columnNamesForSyntaxHighlighting,
//   tableNamesForSyntaxHighlighting,
//   algoliaPublicKey
// }
```

## Notes

- Syntax highlighting data is derived by intersecting query words against all known osquery table names, then pulling each table's `keywordsForSyntaxHighlighting` (column names)
- Platform filtering splits on `", "` within the `platform` field, supporting multi-platform vitals
