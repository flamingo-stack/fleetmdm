Sails.js action that serves the Report Library page, filtering pre-built static query content into platform-specific report lists (macOS, Windows, Linux).

## Key Components

- **`fn`** — Async handler that validates static content config, partitions reports by platform, and returns view data
- **`exits.success`** — Renders `pages/docs/report-library` view template
- **`exits.badConfig`** — Thrown when `builtStaticContent.queries` is missing or malformed

## Platform Filtering Logic

Reports are filtered by splitting the comma-separated `platform` field and checking for platform identifiers:

| Platform | Identifier |
|----------|------------|
| macOS | `darwin` |
| Windows | `windows` |
| Linux | `linux` |

> Note: A single report can appear in multiple platform lists if it supports multiple platforms.

## Usage Example

```javascript
// Invoked automatically by Sails router — example route binding in config/routes.js
'GET /docs/report-library': { action: 'view-report-library' }

// View template receives:
{
  macOsReports:     [...],  // reports with 'darwin' in platform field
  windowsReports:   [...],  // reports with 'windows' in platform field
  linuxReports:     [...],  // reports with 'linux' in platform field
  algoliaPublicKey: '...'   // for client-side search
}
```

## Dependencies

- **`sails.config.builtStaticContent.queries`** — Pre-built static content array; must be populated at build time
- **`sails.config.custom.algoliaPublicKey`** — Passed to the view to enable Algolia-powered search on the report library page
