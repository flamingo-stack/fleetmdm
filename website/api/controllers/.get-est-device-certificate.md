Handles device certificate issuance for Linux devices by validating an IdP auth token and CSR via the EST (Enrollment over Secure Transport) protocol, then returning a signed certificate.

## Key Components

**Inputs**
| Parameter | Description |
|---|---|
| `csrData` | PEM-encoded Certificate Signing Request |
| `authToken` | Bearer token from the Identity Provider (IdP) |
| `introspectEndpoint` | IdP token introspection URL |
| `idpClientId` | Client ID for IdP introspection |
| `estEndpoint` | EST protocol server URL |
| `estClientId` / `estClientKey` | Credentials for EST Basic Auth |

**Exits**
| Exit | Status | Meaning |
|---|---|---|
| `success` | 200 | Returns `{ certificate: string }` |
| `invalidToken` | 403 | Token inactive or email/username mismatch |
| `invalidCsr` | 400 | CSR missing email SAN or username prefix mismatch |

**Core Logic**

1. **Token introspection** — POSTs to the IdP endpoint; throws `invalidToken` if the token is inactive
2. **CSR parsing** — Uses `jsrsasign` to extract `rfc822` (email) and UPN OID `1.3.6.1.4.1.311.20.2.3` (username) from the CSR's Subject Alternative Name extensions
3. **Identity cross-check** — Validates that the CSR email matches the IdP token's username
4. **EST certificate request** — Strips PEM headers, POSTs raw PKCS#10 data to the EST endpoint with Basic Auth, then re-wraps the response in PEM headers

## Usage Example

```javascript
const result = await sails.helpers.getEstDeviceCertificate.with({
  csrData: '-----BEGIN CERTIFICATE REQUEST-----\n...\n-----END CERTIFICATE REQUEST-----',
  authToken: 'eyJhbGciOiJSUzI1NiJ9...',
  introspectEndpoint: 'https://idp.example.com/oauth2/v1/introspect',
  idpClientId: 'my-idp-client-id',
  estEndpoint: 'https://est.example.com/.well-known/est/simpleenroll',
  estClientId: 'est-client',
  estClientKey: 'est-secret',
});
// result.certificate => '-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----'
```
