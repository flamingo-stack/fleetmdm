Handles the OAuth callback for Vanta authorization, validating state/cookies, exchanging the authorization code for an access token, and updating the `VantaConnection` record in Fleet.

## Key Components

**Inputs**
- `state` — OAuth state parameter returned by Vanta to verify request integrity
- `code` — Authorization code exchanged for a Vanta access token

**Exits**
- `success` → renders `pages/vanta-authorization` with a success or error state
- `redirect` → redirects the user to a post-setup URL if one was set during initialization

**Core Logic (`fn`)**
1. Validates required signed cookies (`vantaSourceId`, `state`)
2. Compares the `state` cookie against the `state` query param to prevent CSRF
3. Looks up the `VantaConnection` record by `vantaSourceId`
4. If already connected, returns a success view immediately
5. POSTs to `https://api.vanta.com/oauth/token` to exchange the code for tokens
6. Updates the `VantaConnection` record with `vantaAuthToken`, `vantaRefreshToken`, and expiry
7. Optionally redirects to `redirectAfterSetup` cookie URL

## Usage Example

This action is invoked automatically by Vanta's OAuth redirect URI. Configure it in `sails.config.custom`:

```javascript
// config/custom.js
module.exports.custom = {
  vantaAuthorizationClientId: 'YOUR_CLIENT_ID',
  vantaAuthorizationClientSecret: 'YOUR_CLIENT_SECRET',
  baseUrl: 'https://your-fleet-instance.example.com',
};
```

The redirect URI registered with Vanta must match:

```text
https://your-fleet-instance.example.com/vanta-authorization
```

Vanta redirects the user here with `?state=...&code=...` after they approve the connection.
