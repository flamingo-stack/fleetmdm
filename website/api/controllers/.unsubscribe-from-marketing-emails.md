Sails.js action that unsubscribes a user from marketing/nurture email automation by updating both the local database and Salesforce CRM records.

## Key Components

### Inputs
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `emailAddress` | `string` | ✅ | Email address to unsubscribe |

### Exits
| Exit | Type | Description |
|------|------|-------------|
| `userNotFound` | `badRequest` | No Fleet user account matches the provided email |
| `success` | — | User successfully opted out of marketing emails |

### Core Logic (`fn`)
- **User lookup** — Finds the user record by email; throws `userNotFound` if no match exists
- **Nurture email suppression** — Sets `stageThreeNurtureEmailSentAt`, `stageFourNurtureEmailSentAt`, and `stageFiveNurtureEmailSentAt` to `1`, excluding the user from future runs of `deliver-nurture-emails`
- **Salesforce sync** *(production only)* — Logs into Salesforce via `jsforce`, locates the matching `Contact` record, and sets `Unsubscribed_from_email_contact__c: true`
- **Redirect** — Returns the user to `/#unsubscribed` on completion

## Usage Example

```javascript
// Called via Sails.js routing, e.g. GET /unsubscribe?emailAddress=user@example.com
await sails.helpers.unsubscribeFromMarketingEmails.with({
  emailAddress: 'user@example.com'
});
```

## Notes

- Salesforce integration only runs in `production` environment and requires `salesforceIntegrationUsername` and `salesforceIntegrationPasskey` in `sails.config.custom`
- A future improvement is noted in the code to add a dedicated `subscribedToNurtureEmails` attribute to the `User` model rather than using timestamp sentinel values
