Handles user logout by clearing session data and redirecting browser clients to the homepage.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `friendlyName` | `string` | Human-readable action name: `'Logout'` |
| `exits.success` | `object` | Returned for API/JSON clients after session is cleared |
| `exits.redirect` | `object` | Redirects browser clients to `/` after logout |
| `fn` | `async function` | Core handler that deletes session keys and responds |

**Session keys cleared:**
- `req.session.userId` — authenticated user identity
- `req.session.primaryBuyingSituation` — personalization data

## Usage Example

```javascript
// Called automatically by Sails.js routing — example route binding in config/routes.js
'GET /api/v1/account/logout': { action: 'account/logout' }

// Browser clients receive a redirect to '/'
// API/JSON clients receive a 200 success response

// Example client-side API call
await fetch('/api/v1/account/logout', {
  headers: { 'Accept': 'application/json' }
});
```

## Notes

- This is a **Sails.js machine-style action** — it relies on `this.req` rather than receiving `req` as a parameter
- Logout is a **no-op** if the user was not logged in; no error is thrown
- Actual session garbage collection depends on the configured [session store TTL](https://sailsjs.com/docs/reference/configuration/sails-config-session)
- Source: [`logout.js`](https://github.com/flamingo-stack/fleetmdm/blob/main/logout.js)
