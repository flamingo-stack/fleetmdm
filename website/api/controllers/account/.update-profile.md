Updates the profile of the currently authenticated user, handling name, organization, and email address changes with support for immediate updates, pending change flows, and Stripe billing sync.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `friendlyName` | `string` | `'Update profile'` |
| `inputs` | `object` | Accepts `firstName`, `lastName`, `organization`, `emailAddress` |
| `exits.emailAlreadyInUse` | `409` | Thrown when the new email conflicts with an existing user |
| `fn` | `async function` | Core handler; resolves email change intent, updates the DB, and syncs Stripe |

### Email Change Logic

The handler resolves one of five `desiredEmailEffect` states:

| Value | Condition |
|-------|-----------|
| `''` | No email change needed |
| `change-immediately` | Email verification disabled, or account is unconfirmed |
| `begin-change` | Verification enabled; starts a pending change |
| `modify-pending-change` | Replaces an existing pending change |
| `cancel-pending-change` | Reverts to the current confirmed email |

## Usage Example

```javascript
// POST /api/v1/account/update-profile
await superagent.patch('/api/v1/account/update-profile')
  .send({
    firstName: 'Jane',
    lastName: 'Doe',
    organization: 'Acme Corp',
    emailAddress: 'jane.doe@acme.com'
  });

// On success: 200 OK
// On duplicate email: 409 emailAlreadyInUse
```

## Notes

- `emailAddress` input is normalized to lowercase before processing.
- Stripe billing email is synced only when `change-immediately` is the resolved effect and `enableBillingFeatures` is `true`.
- The `begin-change` / `modify-pending-change` email confirmation path is **not implemented** for fleetdm.com and throws an explicit `Error` if reached.
