Sails.js action that handles routing and rendering for the Fleet handbook section, serving both the handbook landing page and individual handbook content pages.

## Key Components

- **`urlWildcardSuffix`** — Captures the URL path segment after `/handbook` to resolve the target page
- **`inputs.pageUrlSuffix`** — String input representing the relative path (e.g., `handbook/release-process`); defaults to empty string for the landing page
- **`exits`** — Four outcomes: `success` (renders `pages/handbook/basic-handbook`), `badConfig`, `notFound`, and `redirect`
- **`fn`** — Core handler that looks up the matching markdown page from `sails.config.builtStaticContent.markdownPages`, with URL normalization (lowercase, deduped slashes) and redirect logic for malformed URLs

## Usage Example

```javascript
// Triggered automatically by a Sails route like:
// 'GET /handbook/*': { action: 'view-basic-handbook' }

// Landing page request: GET /handbook
// → renders with thisPage matching url: '/handbook'

// Content page request: GET /handbook/release-process
// → renders with thisPage matching url: '/handbook/release-process'

// Malformed URL: GET /Handbook/Release-Process
// → normalized to '/handbook/release-process'
// → throws redirect to corrected URL

// View receives:
// {
//   thisPage,               // matched markdown page object
//   markdownPages,          // all available pages
//   pageTitleForMeta,       // e.g. "Release process | Fleet handbook"
//   pageDescriptionForMeta, // from page meta or generic fallback
//   rituals,                // handbook ritual data
//   openPositions,          // job listings
//   algoliaPublicKey,       // search integration
// }
```

## Notes

- Validates `builtStaticContent` config on every request; throws `badConfig` if malformed
- URL normalization only triggers a redirect (not a render) to keep canonical URLs clean
- Based on the same pattern as `view-basic-documentation.js`
