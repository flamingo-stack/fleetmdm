Handles whitepaper download form submissions by validating the requester's email domain and asynchronously syncing contact, account, and intent signal data to Salesforce CRM.

## Key Components

**Inputs**

| Field | Type | Notes |
|---|---|---|
| `firstName` | string | Required |
| `lastName` | string | Required |
| `emailAddress` | string | Required, validated as email |
| `whitepaperName` | string | Required |

**Exits**

- `success` — Request processed successfully
- `invalidEmailDomain` — Email domain is on the configured denylist; returns `badRequest`

**Core Logic**

- `emailDomain` check — Validates the submitter's domain against `sails.config.custom.bannedEmailDomainsForWebsiteSubmissions`
- `updateOrCreateContactAndAccount` — Upserts a Salesforce contact/account with source `Website - Gated document`
- `createHistoricalEvent` — Logs an `Intent signal` event of type `Requested whitepaper download` tied to the resolved account and contact
- Marketing attribution cookie (`marketingAttribution`) is forwarded to the Salesforce helper if present

## Usage Example

```javascript
// Called as a Sails action from a form POST
await sails.helpers.deliverWhitepaperDownloadRequest.with({
  firstName: 'Jane',
  lastName: 'Doe',
  emailAddress: 'jane.doe@company.com',
  whitepaperName: 'Zero Trust Security Guide',
});
```

> **Note:** Salesforce sync runs as a background task via `sails.helpers.flow.build`. Failures are logged as warnings but do not surface errors to the end user.
