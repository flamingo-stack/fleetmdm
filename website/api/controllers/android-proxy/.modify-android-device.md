Modifies an Android Enterprise device by proxying PATCH requests to the Google Android Management API, with Bearer token authentication and enterprise-level validation.

## Key Components

**Inputs**
- `androidEnterpriseId` — ID of the Android Enterprise to target
- `deviceId` — ID of the specific device to modify

**Exits**
| Exit | Response Type | Description |
|---|---|---|
| `success` | 200 | Device updated successfully |
| `missingAuthHeader` | 401 | No Bearer token in request |
| `unauthorized` | 401 | Token does not match stored secret |
| `notFound` | 404 | Enterprise not found or no longer managed |
| `deviceNoLongerManaged` | 404 | Device removed from enterprise |
| `invalidPolicyName` | 400 | Bad `policy_name` value in request body |

**Authentication Flow**
1. Extracts Bearer token from `Authorization` header
2. Looks up `AndroidEnterprise` record by `androidEnterpriseId`
3. Compares token against stored `fleetServerSecret`
4. Verifies the enterprise is still managed by Fleet via `androidProxy.getIsEnterpriseManagedByFleet`

**API Call**
Calls `androidmanagement.enterprises.devices.patch` using a Google service account, forwarding `req.body` directly as `requestBody`. Intercepts 429 rate-limit errors (with a `p1` alert log) and specific error strings for `deviceNoLongerManaged` and `invalidPolicyName`.

## Usage Example

```bash
curl -X PATCH https://your-host/api/v1/android/enterprises/{androidEnterpriseId}/devices/{deviceId} \
  -H "Authorization: Bearer <fleetServerSecret>" \
  -H "Content-Type: application/json" \
  -d '{ "policy_name": "enterprises/my-enterprise/policies/my-policy" }'
```

> **Note:** `req.body` is forwarded directly to the Google API — an intentional pattern unique to this endpoint to avoid overwriting previously set device fields with `undefined` values.
