Middleware policy that validates incoming requests to Microsoft proxy endpoints by checking for a valid `MS-API-KEY` header against configured cloud customer shared secrets.

## Key Components

- **`MS-API-KEY` header check** — Reads the request header and validates it against two allowed secrets:
  - `sails.config.custom.cloudCustomerCompliancePartnerSharedSecret`
  - `sails.config.custom.alternateCompliancePartnerSharedSecret`
- **`proceed()`** — Allows the request to continue if a matching secret is found
- **`res.unauthorized()`** — Rejects requests with no header or an invalid key

## Usage Example

```javascript
// config/policies.js
module.exports.policies = {
  'microsoft-proxy/submit-compliance-event': ['is-cloud-customer'],
};
```

```javascript
// Example valid request (e.g. from a cloud customer integration)
fetch('/api/v1/microsoft-proxy/submit-compliance-event', {
  method: 'POST',
  headers: {
    'MS-API-KEY': 'your-shared-secret-here',
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ eventData }),
});
```

## Notes

- Supports two valid secrets simultaneously, enabling secret rotation without downtime
- Requests missing the `MS-API-KEY` header or providing an unrecognized value receive a `401 Unauthorized` response
- Configured via `sails.config.custom` — set both secret values in your environment-specific Sails config
