Implements a custom 404 Not Found response handler for the Sails.js framework, rendering an HTML error page or falling back to a JSON/text response based on request type.

## Key Components

- **`notFound()`** — Main exported function attached to `res.notFound()`. Handles 404 responses by:
  - Setting HTTP status to `404`
  - Returning `sendStatus(404)` for JSON-expecting requests or environments without view support
  - Rendering the `404` view template with `hideFooter: true` for browser requests
  - Gracefully falling back to `sendStatus(404)` if the view fails to render, with appropriate logging

## Usage Example

```javascript
// In a Sails.js controller or policy
module.exports = {
  find: async function (req, res) {
    const record = await MyModel.findOne({ id: req.param('id') });

    if (!record) {
      return res.notFound();
    }

    return res.ok(record);
  }
};

// With an optional error passed
return res.notFound(err);

// With a custom view path
return res.notFound(err, 'some/specific/notfound/view');
```

> **Note:** Sails.js will call `res.notFound()` automatically when a request does not match any explicit routes in `config/routes.js` or any blueprint shadow routes.

## Error Handling

| Scenario | Behavior |
|---|---|
| View missing (`E_VIEW_FAILED`) | Logs verbose warning, falls back to `sendStatus(404)` |
| Other view render error | Logs `warn`-level message, falls back to `sendStatus(404)` |
| JSON request (`wantsJSON`) | Returns `sendStatus(404)` immediately, skips view |
