Alternative entry point for starting the Sails.js application without the Sails CLI, enabling standard Node.js process management workflows.

## Key Components

- **`process.chdir(__dirname)`** — Normalizes the working directory to the project root so relative paths resolve correctly regardless of where the process is launched from
- **`sails` / `rc`** — Imported from the local `node_modules`; `rc` loads configuration from `.sailsrc` files
- **`sails.lift(rc('sails'))`** — Bootstraps and starts the Sails.js server with resolved runtime config

## Usage Example

```bash
# Standard start
node app.js

# Via npm start script
npm start

# With environment and port overrides
NODE_ENV=production node app.js --port=80 --verbose

# With a process manager
forever start app.js
pm2 start app.js
```

```javascript
// Error handling — if sails is not locally installed, the process
// logs actionable instructions and exits gracefully before lifting
try {
  sails = require('sails');
  rc = require('sails/accessible/rc');
} catch (err) {
  console.error(err.stack);
  return; // exits before sails.lift()
}
```

## Notes

- Requires Sails to be installed **locally** (`./node_modules/sails`) — a global install alone is not sufficient for `node app.js`
- Functionally equivalent to `sails lift`; useful for PaaS deployments (e.g., Heroku) or containerized environments where the Sails CLI is unavailable
- See the full source at [`app.js`](https://github.com/flamingo-stack/fleetmdm/blob/main/app.js)
