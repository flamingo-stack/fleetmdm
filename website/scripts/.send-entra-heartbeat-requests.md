Sends periodic heartbeat requests to all active Microsoft Entra compliance tenants to keep the MDM integration alive, updating each tenant's `lastHeartbeatAt` timestamp on success.

## Key Components

- **`allActiveEntraTenants`** — Queries all `MicrosoftComplianceTenant` records where `setupCompleted: true`
- **`errorReportById`** — Per-tenant error accumulator; prevents a single tenant failure from halting the entire run
- **`getAccessTokenAndApiUrls`** — Microsoft proxy helper that fetches a Bearer token and the tenant-specific sync URL
- **Heartbeat PUT request** — Sends to `PartnerTenantHeartbeat` endpoint with a current ISO timestamp
- **`ResyncTimestamp`** — Parsed from the response; handling is currently a no-op (marked TODO)
- **`MicrosoftComplianceTenant.updateOne`** — Stamps `lastHeartbeatAt: Date.now()` after a successful heartbeat
- **Error summary log** — After all tenants are processed, warns via `sails.log.warn` for each failed tenant

## Usage Example

This is a Sails.js machine invoked as a scheduled job (e.g., via `cron` or Sails' built-in scheduler):

```javascript
// Typically called from config/bootstrap.js or a cron runner
await sails.helpers.flow.build(
  require('./scripts/send-entra-heartbeat-requests')
).fn();

// Or via Sails machine runner directly
await sails.hooks.custom.sendEntraHeartbeatRequests();
```

## Error Handling Pattern

Errors are tolerated per-tenant using `.tolerate()` and collected into `errorReportById`. After all tenants are processed, failures are logged as `p1` warnings without interrupting other tenants:

```javascript
// Errors surface after the loop, not during
sails.log.warn('p1: An error occurred while sending a heartbeat request...');
```

## Notes

- Processes all tenants **simultaneously** via `sails.helpers.flow.simultaneouslyForEach`
- If token acquisition fails, the heartbeat step is skipped for that tenant via early `return`
