Provisions a Fleet Sandbox instance for the longest-waiting user on the sandbox waitlist, updates their user record with instance details, and sends a notification email.

## Key Components

- **`earliestCreatedUserCurrentlyOnWaitlist`** — Queries for the single oldest user with `inSandboxWaitlist: true`, sorted ascending by `createdAt`
- **`fleetSandboxCloudProvisioner.provisionNewFleetSandboxInstance`** — Sails helper that creates the sandbox instance and returns URL, expiry, and demo key
- **`User.updateOne`** — Updates the user record with sandbox details (`fleetSandboxURL`, `fleetSandboxExpiresAt`, `fleetSandboxDemoKey`) and sets `inSandboxWaitlist: false`
- **`sendTemplateEmail`** — Sends the `email-sandbox-ready-approved` template to notify the user their instance is ready

## Usage Example

This is a Sails.js script invoked from the command line or a scheduled job:

```bash
sails run provision-sandbox-instance-for-one-user-and-deliver-email
```

Each invocation processes **one user** (FIFO order). To drain the waitlist, run the script repeatedly or schedule it:

```bash
# Example: run via cron every 5 minutes
*/5 * * * * cd /path/to/app && sails run provision-sandbox-instance-for-one-user-and-deliver-email
```

## Notes

- If the waitlist is empty, the script exits early with a log message and no side effects
- Provisioning errors are intercepted and rethrown with the affected user's ID for easier debugging
- Processes exactly one user per execution — call multiple times to handle multiple waitlisted users
