Hourly script that collects host and user data from Fleet instances and synchronizes it with Vanta's compliance platform, handling OAuth token refresh, paginated host retrieval, and per-connection error isolation.

## Key Components

- **`allActiveVantaConnections`** — Queries all `VantaConnection` records where `isConnectedToVanta: true`
- **`errorReportById`** — Per-connection error accumulator that prevents a single failure from halting the entire sync
- **`hostApiErrorReportById`** — Tracks per-host detail-endpoint errors; affected hosts are skipped rather than failing the run
- **Token refresh** — POSTs to `https://api.vanta.com/oauth/token` using the stored refresh token, then persists the new `access_token`, `refresh_token`, and expiry to the database
- **User sync** — Fetches `/api/v1/fleet/users`, maps each user to a Vanta-shaped object with `authMethod` (`SSO`, `TOKEN`, or `PASSWORD`), `permissionLevel` (`ADMIN`, `EDITOR`, or `BASE`), and MFA metadata
- **Host pagination** — Iterates the Fleet `/api/v1/fleet/hosts` endpoint in pages of 100 until exhausted, with a 30-second timeout guard
- **Platform filtering** — Splits hosts into `macOsHosts` (darwin) and `windowsHosts`, then processes macOS hosts in parallel batches of 25
- **Connection-specific filtering** — Special-cases connection IDs `64` and `77` to restrict hosts to specific team IDs

## Usage Example

```javascript
// Invoked as a Sails.js script (hourly via scheduler)
await sails.helpers.scripts.sendDataToVanta();

// Required Sails config:
// sails.config.custom.vantaAuthorizationClientId
// sails.config.custom.vantaAuthorizationClientSecret

// Required VantaConnection fields:
// vantaRefreshToken, fleetInstanceUrl, fleetApiKey
```

## Notes

- All HTTP requests use `User-Agent: Fleet/Vanta Updater`
- 503/504 responses on the Vanta token endpoint are automatically retried
- Errors are collected and logged after the full run rather than throwing immediately
