Configures the `grunt-hash` Grunt task to implement cache-busting for minified CSS and JavaScript assets by appending SHA1-based content hashes to filenames.

## Key Components

- **`hash.options`** — Global hash configuration:
  - `hashLength` — Output hash truncated to 8 characters
  - `hashFunction` — Custom SHA1 implementation via Node's `crypto` module; throws a descriptive error if `source` or `encoding` are falsy
- **`hash.js`** — Hashes all minified JS files from `.tmp/public/min/*.js` → `.tmp/public/hash/`
- **`hash.css`** — Hashes all minified CSS files from `.tmp/public/min/*.css` → `.tmp/public/hash/`

## Usage Example

```javascript
// This task runs automatically as part of the Sails.js production asset pipeline.
// To use a custom version of grunt-hash instead of the built-in one:

// 1. Install the plugin
// $ npm install grunt-hash --save-dev --save-exact

// 2. Load it manually in your Gruntfile or this config file:
grunt.loadNpmTasks('grunt-hash');

// The hash task targets can then be run individually:
// $ grunt hash:js   — hashes minified JS files
// $ grunt hash:css  — hashes minified CSS files
```

## Notes

- Hashed output files land in `.tmp/public/hash/`, separate from the `.tmp/public/min/` source directory
- The custom `hashFunction` provides explicit error messaging to aid debugging when inputs are unexpectedly empty — a common pain point during asset pipeline failures
- Remove this file entirely to opt out of cache-busting in your Sails app
