Provides file integrity verification for the update package by computing and comparing SHA-512/SHA-256 hashes of local files against TUF (The Update Framework) target metadata.

## Key Components

| Function | Description |
|---|---|
| `checkFileHash` | Validates a local file's hash against TUF `TargetFileMeta`; returns an error on mismatch |
| `fileHashes` | Resolves the expected and actual hashes, using a cached `.sha512` sidecar file for `.tar.gz` archives when available |
| `selectHashFunction` | Picks the best available hash algorithm from TUF metadata — SHA-512 preferred, SHA-256 fallback |
| `readCachedHash` | Reads a pre-computed hex hash from a `<path>.sha512` file written during packaging |

## Usage Example

```go
import "github.com/flamingo-stack/fleetmdm/pkg/update"

// Verify a downloaded component against TUF metadata
meta := &data.TargetFileMeta{
    FileMeta: data.FileMeta{
        Hashes: data.Hashes{
            "sha512": expectedHashBytes,
        },
    },
}

if err := checkFileHash(meta, "/tmp/component.tar.gz"); err != nil {
    log.Fatal().Err(err).Msg("integrity check failed")
}
```

## Hash Resolution Order

```text
.tar.gz file?
    └── .sha512 sidecar exists? → use cached hash
    └── no sidecar             → read + hash file contents
non-.tar.gz file               → read + hash file contents
```

Algorithm preference: **SHA-512 → SHA-256 → error**. The `.sha512` sidecar pattern supports scenarios where the original archive is deleted after packaging to save disk space, allowing integrity checks without re-reading large files.
