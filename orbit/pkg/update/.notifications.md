Handles Fleet orbit config notifications for MDM enrollment lifecycle events on macOS and Windows, implementing middleware receivers that react to server-sent flags to renew enrollment profiles, enroll/unenroll Windows MDM, and trigger on-demand Windows OMA-DM sync sessions.

## Key Components

### Types & Interfaces

- **`runCmdFunc`** — Function type for executing shell commands (mockable in tests)
- **`checkEnrollmentFunc`** — Function type for querying MDM enrollment status
- **`checkAssignedEnrollmentProfileFunc`** — Function type for verifying Apple Business Manager profile assignment
- **`execWinAPIFunc`** — Function type wrapping Windows MDM WinAPI calls
- **`execSyncFunc`** — Function type for triggering an on-demand OMA-DM sync session
- **`OrbitNodeKeyGetter`** — Interface providing `GetNodeKey() (string, error)` for Windows MDM auth

### Middleware Receivers

| Receiver | Constructor | Platform |
|---|---|---|
| `renewEnrollmentProfileConfigReceiver` | `ApplyRenewEnrollmentProfileConfigFetcherMiddleware` | macOS |
| `windowsMDMEnrollmentConfigReceiver` | `ApplyWindowsMDMEnrollmentFetcherMiddleware` | Windows |
| `windowsMDMSyncConfigReceiver` | `ApplyWindowsMDMSyncFetcherMiddleware` | Windows |

Each implements `fleet.OrbitConfigReceiver` via a `Run(*fleet.OrbitConfig) error` method.

## Usage Example

```go
// macOS: wrap an OrbitConfigFetcher to handle enrollment profile renewal
receiver := update.ApplyRenewEnrollmentProfileConfigFetcherMiddleware(
    fetcher,
    15*time.Minute,
    "https://fleet.example.com",
)

// Windows: handle MDM enroll/unenroll notifications
winReceiver := update.ApplyWindowsMDMEnrollmentFetcherMiddleware(
    15*time.Minute,
    hostUUID,
    nodeKeyGetter,
)

// Windows: handle on-demand OMA-DM sync requests
syncReceiver := update.ApplyWindowsMDMSyncFetcherMiddleware(5 * time.Minute)

// Each receiver is called with the latest OrbitConfig from the Fleet server
if err := receiver.Run(orbitConfig); err != nil {
    log.Error().Err(err).Msg("notification handler failed")
}
```

> **Concurrency:** All receivers use `sync.Mutex.TryLock` to ensure at most one operation runs at a time, silently dropping concurrent triggers rather than queuing them.
