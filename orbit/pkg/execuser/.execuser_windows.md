Implements Windows-specific process execution logic for launching child processes as the currently logged-in user from a SYSTEM-level Windows service context.

## Key Components

### Windows API Bindings
Lazy-loaded DLL procedures from `wtsapi32.dll`, `kernel32.dll`, `advapi32.dll`, and `userenv.dll` for session management and process creation:

| Procedure | Purpose |
|---|---|
| `WTSEnumerateSessionsW` | List all active terminal sessions |
| `WTSGetActiveConsoleSessionId` | Fallback to get active console session |
| `WTSQueryUserToken` | Retrieve user token for a session |
| `DuplicateTokenEx` | Duplicate token as primary token |
| `CreateEnvironmentBlock` | Build environment for target user |
| `CreateProcessAsUserW` | Spawn process under user context |

### Core Functions

- **`run`** — Entry point; sets up the sync channel, applies environment variables from `opts.env`, assembles the command line, and delegates to `startProcessAsCurrentUser`.
- **`startProcessAsCurrentUser`** — Orchestrates session lookup → token duplication → environment block creation → `CreateProcessAsUserW` call.
- **`getCurrentUserSessionId`** — Resolves the active session ID by enumerating sessions or falling back to `WTSGetActiveConsoleSessionId`.
- **`duplicateUserTokenFromSessionID`** — Queries and duplicates the user token for a given session as a primary token (`SecurityImpersonation` → `TokenPrimary`).
- **`setupSyncChannel`** — Creates a named kernel event object (`Global\comm-<channelId>`) used for child process termination signalling, with a security descriptor granting SYSTEM full control and Authenticated Users `SYNCHRONIZE` access.
- **`runWithOutput`** — Stub; returns `errors.New("not implemented")`.

## Usage Example

```go
opts := eopts{
    env: [][2]string{{"MY_VAR", "my_value"}},
    args: [][2]string{{"--flag", "value"}},
}

lastLogs, err := run(`C:\path\to\app.exe`, opts)
if err != nil {
    log.Fatalf("failed to launch process as user: %v", err)
}
```

> **Note:** This file uses `unsafe` extensively for Windows API interop and is intended to run only within a SYSTEM-level Windows service (e.g., Fleet orbit). The sync channel created by `setupSyncChannel` intentionally holds its handle open for the lifetime of the service.
