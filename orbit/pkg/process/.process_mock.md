Provides testify-based mock implementations of the `OsProcess` and `ExecCmd` interfaces for use in unit tests within the `process` package.

## Key Components

| Type | Implements | Methods |
|------|-----------|---------|
| `mockOsProcess` | `OsProcess` | `Signal(os.Signal) error`, `Kill() error` |
| `mockExecCmd` | `ExecCmd` | `Start() error`, `Wait() error`, `OsProcess() OsProcess` |

Both types embed `mock.Mock` from [testify](https://github.com/stretchr/testify) to enable call tracking and return value configuration.

## Usage Example

```go
func TestSomething(t *testing.T) {
    // Mock OsProcess
    proc := &mockOsProcess{}
    proc.On("Kill").Return(nil)
    proc.On("Signal", os.Interrupt).Return(nil)

    // Mock ExecCmd
    cmd := &mockExecCmd{}
    cmd.On("Start").Return(nil)
    cmd.On("Wait").Return(nil)
    cmd.On("OsProcess").Return(proc)

    // Use mocks in test subject
    err := cmd.Start()
    assert.NoError(t, err)

    p := cmd.OsProcess()
    assert.NoError(t, p.Signal(os.Interrupt))

    proc.AssertExpectations(t)
    cmd.AssertExpectations(t)
}
```

## Notes

- Both mocks are unexported (lowercase), restricting their use to the `process` package only.
- `nil` error returns are handled explicitly to avoid interface boxing issues — a common Go gotcha where a typed `nil` is not equal to an untyped `nil`.
