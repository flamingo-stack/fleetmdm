Fleet orbit script execution engine. Handles retrieval, local execution, and result reporting of host scripts requested by the Fleet server.

## Key Components

- **`Client` interface** — Defines the two API methods required to interact with the Fleet server: `GetHostScript` and `SaveHostScriptResult`. Satisfied by `fleet.OrbitClient`.
- **`Runner` struct** — Core type coordinating the full script lifecycle: fetch → write to temp dir → execute → save result.
- **`Run(execIDs []string) error`** — Entry point that processes a batch of scripts by execution ID in order, stopping on fetch errors to preserve queue order.
- **`runOne`** — Handles a single script: creates a temp directory, writes the script file (`.ps1` on Windows), executes it with a configurable timeout, trims output, and saves the result back to the server.
- **`runOneDisabled`** — Short-circuits execution when scripts are disabled on the host, saving a result with exit code `-2` (recognized by `fleetctl`).
- **`createRunDir`** — Creates a per-execution temp directory using `os.MkdirTemp`, restricted to the current user.

## Usage Example

```go
runner := &scripts.Runner{
    Client:                 orbitClient,
    ScriptExecutionEnabled: true,
    ScriptExecutionTimeout: 30 * time.Second,
}

// Process a batch of pending script execution IDs
if err := runner.Run([]string{"exec-id-1", "exec-id-2"}); err != nil {
    log.Error().Err(err).Msg("script runner error")
}
```

## Notes

- Output is capped at `10,000 UTF-8 runes` before being sent to the server.
- Set `FLEET_PREVENT_SCRIPT_TEMPDIR_DELETION=1` to retain temp directories after execution (useful for debugging).
- `execCmdFn`, `tempDirFn`, and `removeAllFn` fields are test hooks for mocking OS interactions without modifying production paths.
