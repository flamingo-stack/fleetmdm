Windows-specific implementation of script execution using PowerShell as the interpreter.

## Key Components

### `ExecCmd`
```text
func ExecCmd(ctx context.Context, scriptPath string, env []string) (output []byte, exitCode int, err error)
```
Executes a script file on Windows via PowerShell with the following behavior:
- Runs scripts using `powershell -MTA -ExecutionPolicy Bypass -File <scriptPath>`
- Initializes `exitCode` to `-1` as a sentinel for processes that never start
- Applies a 1-second `WaitDelay` to allow graceful shutdown
- Converts Windows 32-bit unsigned exit codes to signed `int32` — mapping `0xFFFFFFFF` to `-1` for consistency with Unix semantics and database column constraints
- Preserves `exitCode = -1` when the context is cancelled, since forcibly killing processes on Windows does not reliably reflect in the reported exit code

## Usage Example

```go
ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()

output, exitCode, err := scripts.ExecCmd(ctx, `C:\scripts\deploy.ps1`, os.Environ())
if err != nil {
    log.Printf("script error: %v", err)
}
if exitCode == -1 {
    log.Println("process did not complete or was cancelled")
}
log.Printf("exit: %d, output: %s", exitCode, output)
```

## Notes

- Build-constrained to `//go:build windows` — only compiled on Windows targets
- The signed 32-bit cast handles the Windows convention of returning `0xFFFFFFFF` for killed processes ([reference](https://en.wikipedia.org/wiki/Exit_status#Windows))
- Context cancellation intentionally keeps `exitCode` at `-1` to ensure consistent user-facing messaging regardless of what the OS reports
