Transforms WiX Heat-generated XML output by applying security descriptor (SDDL) permissions to packaged files before writing the modified XML back to disk.

## Key Components

### Types

| Type | Description |
|------|-------------|
| `node` | Generic XML node with name, attributes, character data, and children |
| `attrs` | Slice of `*xml.Attr` with a helper `Get(name)` method for attribute lookup |

### Functions

| Function | Description |
|----------|-------------|
| `TransformHeat(path string) error` | Entry point — reads, unmarshals, transforms, and rewrites a WiX XML file |
| `transform(cur *node, stack *[]*node) error` | Recursive tree walker that strips XML namespaces and injects `PermissionEx` nodes |
| `xmlAttr(name, value string) *xml.Attr` | Convenience constructor for a local-name XML attribute |
| `xmlNode(name string, attrs ...*xml.Attr) *node` | Convenience constructor for a named XML node |

## Usage Example

```go
// Transform a Heat-generated WiX fragment in-place
if err := wix.TransformHeat("path/to/heat-output.wxs"); err != nil {
    log.Fatalf("transform failed: %v", err)
}
```

## Permission Rules Applied

For every `<File>` element encountered, a child `<PermissionEx>` node is injected with an SDDL string that:

- **Disables permission inheritance**
- Grants **SYSTEM** and **Administrators** full access (`FA`)
- Grants **Users** read/execute (`0x1200a9`)

Files whose `Source` attribute ends in `secret.txt` receive a stricter SDDL that **removes Users access entirely**, matching the permissions of a manually hardened Windows file.

## Notes

- Carriage returns (`\r`) are stripped before XML parsing to avoid artefacts from Windows line endings.
- The file is removed before rewriting to avoid permission errors on some Linux configurations.
- Output is pretty-printed with two-space indentation via `xml.MarshalIndent`.
