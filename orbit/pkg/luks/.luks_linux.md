Linux-only implementation of LUKS (Linux Unified Key Setup) disk encryption key escrow for Fleet's orbit agent. It handles prompting users for their LUKS passphrase, generating a new random escrow key, adding it to an available key slot, and sending the result to Fleet for escrow.

## Key Components

| Symbol | Type | Description |
|---|---|---|
| `LuksRunner.Run` | method | Entry point: checks for `cryptsetup`, selects a dialog tool (zenity/kdialog), finds the root LUKS partition, and orchestrates the escrow flow |
| `LuksRunner.getEscrowKey` | method | Inspects LUKS metadata, prompts the user for their passphrase, validates it, generates a random escrow passphrase, and adds it to a new key slot |
| `GetLuksDump` | func | Runs `cryptsetup luksDump` with JSON output (handling pre-2.4 flag differences) and returns parsed `LuksDump` metadata |
| `getNextAvailableKeySlot` | func | Scans existing key slots from LUKS metadata and returns the lowest unused slot index (max 8 slots) |
| `generateRandomPassphrase` | func | Generates a cryptographically random 32-character passphrase in `XXXXXXXX-XXXXXXXX-XXXXXXXX-XXXXXXXX` format |
| `dialogCopyForEncryptionType` | func | Returns UI dialog strings tailored to the detected encryption type (TPM2/recovery key vs. standard passphrase) |
| `getSaltforKeySlot` | func | Retrieves the KDF salt for a specific key slot from LUKS metadata |
| `removeKeySlot` | func | Removes a LUKS key slot via `cryptsetup luksKillSlot` (used for cleanup on failure) |
| `passphraseIsValid` | method | Validates a passphrase against a specific key slot using `go-blockdevice` |

## Usage Example

```go
runner := &LuksRunner{
    escrower: myEscrower, // implements SendLinuxKeyEscrowResponse
}

orbitConfig := &fleet.OrbitConfig{
    Notifications: fleet.OrbitConfigNotifications{
        RunDiskEncryptionEscrow: true,
    },
}

if err := runner.Run(orbitConfig); err != nil {
    log.Fatal().Err(err).Msg("LUKS escrow failed")
}
```

## Notes

- Requires `cryptsetup` and either `zenity` or `kdialog` to be installed on the host
- Key slot 0 is assumed to hold the user's passphrase; escrow keys are added to the next available slot (1–7)
- Handles `cryptsetup` versions below 2.4 by using `--debug-json` and extracting embedded JSON from debug output
- TPM2-backed volumes (Ubuntu 23.10+ FDE) show recovery-key–specific dialog copy instead of the standard passphrase prompt
