Darwin-only osquery table plugin that exposes NVRAM firmware variables as queryable data, specifically reporting whether Apple Mobile File Integrity (AMFI) enforcement is enabled on the system.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `Columns()` | `[]table.ColumnDefinition` | Declares the table schema with a single `amfi_enabled` integer column |
| `Generate()` | query handler | Called by osquery at runtime to populate table rows |
| `getAMFIEnabled()` | internal | Runs `nvram -p` and checks for the `amfi_get_out_of_my_way=1` flag |
| `runCommand()` | internal | Executes a subprocess with a 5-second context timeout |

### AMFI Detection Logic

| NVRAM output contains `amfi_get_out_of_my_way=1` | `amfi_enabled` |
|--------------------------------------------------|----------------|
| No (AMFI enforced) | `"1"` |
| Yes (AMFI bypassed) | `"0"` |
| Command failed | `""` |

## Usage Example

Register the table with an osquery extension server:

```go
package main

import (
    "github.com/osquery/osquery-go"
    nvram "github.com/flamingo-stack/fleetmdm/path/to/nvram_info"
)

func main() {
    server, _ := osquery.NewExtensionManagerServer(
        "nvram_info",
        "/var/osquery/osquery.em",
    )
    server.RegisterPlugin(table.NewPlugin("nvram_info", nvram.Columns(), nvram.Generate))
    server.Run()
}
```

Then query from osqueryi:

```sql
SELECT amfi_enabled FROM nvram_info;
```

## Notes

- **Darwin only** — guarded by `//go:build darwin`; will not compile on Linux or Windows
- Command timeout is hardcoded at **5 seconds** via `context.WithTimeout`
- Errors are logged at `DEBUG` level using `zerolog`; the caller receives the raw error
