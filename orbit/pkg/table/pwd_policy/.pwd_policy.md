A macOS-only osquery virtual table plugin that exposes local password policy settings by invoking `pwpolicy` and parsing its XML output.

## Key Components

| Symbol | Description |
|---|---|
| `Columns()` | Returns the osquery table schema with five integer columns |
| `Generate()` | Executes `/usr/bin/pwpolicy -getaccountpolicies` as the console user and parses the result |

**Table columns:**

| Column | Source policy attribute |
|---|---|
| `max_failed_attempts` | `policyAttributeMaximumFailedAuthentications` |
| `expires_every_n_days` | `policyAttributeExpiresEveryNDays` |
| `days_to_expiration` | `policyAttributeDaysUntilExpiration` |
| `history_depth` | `policyAttributePasswordHistoryDepth` |
| `min_mixed_case_characters` | `minimumMixedCaseCharacters` |

## Usage Example

Register the table with an osquery plugin server:

```go
plugin := table.NewPlugin("pwd_policy", pwd_policy.Columns(), pwd_policy.Generate)
server.RegisterPlugin(plugin)
```

Query from osquery shell:

```sql
SELECT * FROM pwd_policy;
```

Expected output:

```text
max_failed_attempts | expires_every_n_days | days_to_expiration | history_depth | min_mixed_case_characters
5                   | 90                   | 14                 | 5             | 1
```

## Notes

- **Darwin only** — guarded by the `//go:build darwin` build tag; will not compile on Linux or Windows.
- `Generate` impersonates the console user via `syscall.Credential` so that `pwpolicy` returns account-level (not root) policies.
- A 5-second context timeout prevents hanging if `pwpolicy` is unresponsive.
- Missing individual policy values are silently set to `""` rather than failing the entire query.
