A Darwin-only osquery extension table that computes SHA-256 hashes for macOS application bundle executables, supporting both exact path and wildcard (`LIKE`) queries.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `Columns()` | `func` | Returns the table schema with three columns: `path`, `executable_path`, and `executable_sha256` |
| `Generate()` | `func` | osquery query handler; extracts the `path` constraint and returns hash results |
| `processFile()` | `func` | Resolves paths (with optional glob expansion) and coordinates executable discovery and hashing |
| `computeFileSHA256()` | `func` | Opens a file and returns its SHA-256 digest as a hex string |
| `getExecutablePath()` | `func` | Reads `CFBundleExecutable` from an app bundle's `Info.plist` and returns the full binary path |
| `fileInfo` | `struct` | Internal result type holding `Path`, `ExecPath`, and `ExecSha256` |

## Usage Example

Query the table from osquery with an exact path:

```sql
SELECT path, executable_path, executable_sha256
FROM executable_hashes
WHERE path = '/Applications/Safari.app';
```

Or use a wildcard to scan multiple bundles:

```sql
SELECT path, executable_path, executable_sha256
FROM executable_hashes
WHERE path LIKE '/Applications/%.app';
```

The table resolves each bundle's executable via `defaults read ... CFBundleExecutable`, decodes any UTF-16 surrogate-pair escape sequences (e.g. emoji in bundle names via `fleet.DecodeUnicodeEscapes`), then streams the binary through `crypto/sha256` to produce the hash.

> **Note:** The `path` constraint is required. Omitting a `WHERE path = ...` or `WHERE path LIKE ...` clause returns an error.
