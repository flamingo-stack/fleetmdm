Line-by-line output parser for `firmwarepasswd` command output, converting structured text into key-value maps using configurable matchers.

## Key Components

### Types

- **`Matcher`** — Defines a rule for extracting data from a single line, composed of three functions:
  - `Match(string) bool` — Determines if a line is relevant
  - `KeyFunc(string) (string, error)` — Extracts the key from the line
  - `ValFunc(string) (string, error)` — Extracts the value from the line

- **`OutputParser`** — Holds a slice of `Matcher` rules and a `zerolog.Logger` instance

### Functions

- **`NewParser(logger, matchers)`** — Constructor returning a configured `*OutputParser`
- **`(*OutputParser).Parse(input)`** — Scans a `bytes.Buffer` line by line, applies all matchers, and returns `[]map[string]string`

## Usage Example

```go
matchers := []firmwarepasswd.Matcher{
    {
        Match: func(line string) bool {
            return strings.HasPrefix(line, "Password Enabled:")
        },
        KeyFunc: func(line string) (string, error) {
            return "password_enabled", nil
        },
        ValFunc: func(line string) (string, error) {
            parts := strings.SplitN(line, ":", 2)
            if len(parts) < 2 {
                return "", fmt.Errorf("unexpected format")
            }
            return strings.TrimSpace(parts[1]), nil
        },
    },
}

parser := firmwarepasswd.NewParser(logger, matchers)
results := parser.Parse(&outputBuffer)
// results: []map[string]string{{"password_enabled": "Yes"}}
```

## Behavior Notes

- Empty lines are silently skipped
- Lines matching no `Matcher` are logged at `Debug` level and excluded from results
- Key/value extraction errors are logged at `Debug` level and skip only that matcher, not the whole line
- Based on [`kolide/launcher`](https://github.com/kolide/launcher) osquery table patterns
