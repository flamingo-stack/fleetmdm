Windows-specific osquery plugin registration that initializes Fleet's custom table extensions for Windows platforms, conditionally including MDM bridge support based on whether the host is a Windows Server.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `PlatformTables` | `func(PluginOpts) ([]osquery.OsqueryPlugin, error)` | Returns all Windows-specific osquery table plugins |
| `IsWindowsServer` | `func() (bool, error)` | Detects Windows Server via registry `InstallationType` key |

### Registered Tables

| Table Name | Source Package | Notes |
|---|---|---|
| `adobe_plugins` | `adobe_plugins` | Adobe product inventory |
| `cis_audit` | `cis_audit` | CIS benchmark audit results |
| `bitlocker_key_protectors` | `bitlocker_key_protectors` | BitLocker key protector info |
| `windows_updates` | `windowsupdatetable` | Windows Update history |
| `mdm_bridge` | `mdm_bridge` | MDM enrollment data (non-Server only) |

## Usage Example

```go
plugins, err := table.PlatformTables(table.PluginOpts{})
if err != nil {
    log.Fatal().Err(err).Msg("failed to load Windows table plugins")
}

// Register with osquery extension server
for _, plugin := range plugins {
    server.RegisterPlugin(plugin)
}
```

```go
// Check if running on Windows Server
isServer, err := table.IsWindowsServer()
if err != nil {
    log.Error().Err(err).Msg("failed to detect Windows edition")
}
// mdm_bridge table is excluded on Server editions
```

## Notes

- The `mdm_bridge` table is **excluded on Windows Server** editions, as MDM enrollment APIs behave differently in server contexts.
- Server detection reads `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\InstallationType` from the Windows registry.
- Build tag `//go:build windows` ensures this file only compiles on Windows targets.
