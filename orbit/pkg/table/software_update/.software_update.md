Darwin-only osquery table plugin that checks macOS software update availability by running `softwareupdate -l` and exposing the result as a queryable integer column.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `Columns()` | `[]table.ColumnDefinition` | Defines the table schema with a single `software_update_required` integer column |
| `Generate()` | osquery handler | Entry point called at query time; returns `1` if updates are available, `0` if not, empty string on error |
| `isNewSoftwareAvailable()` | internal | Invokes `softwareupdate -l` and parses stdout/stderr for the "No new software available" string |
| `runCommand()` | internal | Executes an arbitrary command with a 30-second timeout using `exec.CommandContext` and `CombinedOutput` |

## Usage Example

Register the plugin with an osquery extension server:

```go
package main

import (
    "github.com/flamingo-stack/fleetmdm/ee/tables/software_update"
    osquery "github.com/osquery/osquery-go"
    "github.com/osquery/osquery-go/plugin/table"
)

func main() {
    server, _ := osquery.NewExtensionManagerServer(
        "software_update_ext",
        "/var/osquery/osquery.em",
    )

    server.RegisterPlugin(
        table.NewPlugin("software_update", software_update.Columns(), software_update.Generate),
    )

    server.Run()
}
```

Query from osquery shell:

```sql
SELECT software_update_required FROM software_update;
-- Returns: 1 (updates pending) or 0 (up to date)
```

## Notes

- **Build constraint:** Darwin only (`//go:build darwin`). Will not compile on Linux or Windows.
- **Timeout:** `runCommand` enforces a 30-second deadline — double the typical observed execution time — to handle slower Intel machines where `softwareupdate -l` can be sluggish.
- **Output parsing:** Uses `CombinedOutput` (not `Output`) to capture stderr on Intel machines where results may arrive on the error stream.
