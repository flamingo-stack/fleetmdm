Implements an osquery table plugin (`falconctl_options`) that queries CrowdStrike Falcon sensor configuration by executing `falconctl -g` with allowlisted option flags and flattening the parsed output into osquery rows.

## Key Components

| Symbol | Type | Description |
|---|---|---|
| `falconctlOptionsTable` | struct | Table plugin struct holding logger, table name, and exec function |
| `NewFalconctlOptionTable` | func | Constructs and registers the osquery table plugin |
| `generate` | method | Core query handler; validates requested options, execs `falconctl`, parses and flattens output |
| `optionAllowed` | func | Allowlist check for individual `falconctl` option flags |
| `allowedOptions` | var | Allowlisted flags: `--aid`, `--cid`, `--tags`, `--version`, etc. |
| `execFunc` | type | Abstracted exec function signature, enabling test injection |

## Usage Example

Query all default options via osquery:

```sql
SELECT * FROM falconctl_options;
```

Query specific options using the `options` constraint:

```sql
SELECT * FROM falconctl_options WHERE options = "--aid --cid";
```

The `options` column accepts a space-separated list of flags from the allowlist. Flags not in `allowedOptions` (e.g. `--provisioning-token`) are silently skipped. Errors from `falconctl` execution or parsing are surfaced as `_error` keys in the result rows rather than failing the query.

## Notes

- Binary path is fixed to `/opt/CrowdStrike/falconctl`
- Execution timeout is 30 seconds
- `--systags` and `--provisioning-token` are intentionally excluded from the allowlist
- Based on the [kolide/launcher](https://github.com/kolide/launcher) osquery tables pattern
