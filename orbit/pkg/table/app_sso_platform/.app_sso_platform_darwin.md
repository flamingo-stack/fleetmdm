macOS-only osquery table plugin that queries Apple's Platform SSO state, exposing device and user registration data from the `app-sso platform --state` command.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `Columns()` | Function | Defines the osquery table schema with six columns: `extension_identifier`, `realm`, `device_id`, `user_principal_name`, `registration_completed`, `login_type` |
| `Generate()` | Function | osquery table entry point; validates required constraints, retrieves the GUI-logged-in user, and returns Platform SSO state rows |
| `executeAppSSOPlatform()` | Function | Runs `/usr/bin/app-sso platform --state` as the logged-in user via `launchctl asuser` + `sudo -iu` |
| `parseAppSSOPlatformCommandOutput()` | Function | Parses raw command output, extracting Device and User Configuration JSON blocks |
| `extractJSONSections()` | Function | Uses regex to isolate `Device Configuration` and `User Configuration` JSON from the unstructured command output |
| `appSSOPlatformData` | Struct | Internal data transfer type holding all parsed SSO fields |

## Usage Example

This table is queried via osquery SQL. Both `extension_identifier` and `realm` are **required** equality constraints:

```sql
SELECT
  device_id,
  user_principal_name,
  registration_completed,
  login_type
FROM app_sso_platform
WHERE
  extension_identifier = 'com.microsoft.CompanyPortalMac.ssoextension'
  AND realm = 'KERBEROS.MICROSOFTONLINE.COM';
```

The plugin returns an empty result set (no error) when:
- No user is logged in via the GUI
- The device is not registered with Platform SSO
- The `extension_identifier` or `realm` does not match the configured SSO extension

The `device_id` is extracted from the `CommonName` of the base64url-encoded `deviceSigningCertificate` X.509 certificate embedded in the Platform SSO state output.
