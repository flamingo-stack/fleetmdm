Windows-specific implementation of the `go_binaries` osquery table plugin that discovers Go binaries installed in user home directories.

## Key Components

- **`GenerateGoBinaries`** — Table query handler called by osquery at runtime. Retrieves Windows user home directories and delegates binary scanning to the shared `generateForDirs` function.
- **`windowsHomeDirs`** — Enumerates real user directories under `%SystemDrive%\Users` (defaulting to `C:\Users`), filtering out system/pseudo-user directories: `Public`, `Default`, `Default User`, and `All Users`.

## Usage Example

```go
// Register the table with osquery-go
plugin := table.NewPlugin("go_binaries", go_binaries.GoBinariesColumns(), go_binaries.GenerateGoBinaries)
```

At query time, osquery calls `GenerateGoBinaries`, which resolves user home directories like `C:\Users\alice` and `C:\Users\bob`, then scans for Go binaries within them.

**Directory resolution logic:**

```text
SystemDrive env var (or "C:" default)
  └── \Users\
        ├── alice\   ← included
        ├── bob\     ← included
        ├── Public\  ← skipped
        └── Default\ ← skipped
```

## Notes

- Build-tagged with `//go:build windows` — only compiled on Windows targets.
- Errors from `windowsHomeDirs` are logged at debug level and return a nil result rather than propagating the error, preventing osquery query failures.
- Relies on the cross-platform `generateForDirs` function defined elsewhere in the `go_binaries` package.
