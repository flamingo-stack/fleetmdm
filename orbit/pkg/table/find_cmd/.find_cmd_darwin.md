macOS-only osquery table plugin that wraps `/usr/bin/find` to efficiently query filesystem paths with optional `-type` and `-perm` filters, avoiding the CPU/memory overhead of osquery's built-in `file` table for large file sets.

## Key Components

| Symbol | Description |
|--------|-------------|
| `Columns()` | Defines the table schema with four columns: `directory`, `type`, `perm`, and `path` |
| `Generate()` | Executes `/usr/bin/find` at query time and returns matching paths as rows |
| `permRegexp` | Compiled regex (`[-+]*\d+`) validating the `-perm` argument format |

### Table Schema

| Column | Description |
|--------|-------------|
| `directory` | Required absolute path where `find` starts searching |
| `type` | Optional `-type` flag (`b`, `c`, `d`, `f`, `l`, `p`, `s`) |
| `perm` | Optional `-perm` flag (e.g., `644`, `-755`, `+111`) |
| `path` | Each matched filesystem path returned by `find` |

## Usage Example

```go
// Register the table with an osquery extension server
plugin := table.NewPlugin("find_cmd", find_cmd.Columns(), find_cmd.Generate)
server.RegisterPlugin(plugin)
```

```sql
-- Query via osquery SQL
SELECT path FROM find_cmd
WHERE directory = '/var/log'
  AND type = 'f'
  AND perm = '-644';
```

## Behavior Notes

- **`directory`** is required and must be an absolute path; omitting it returns an error.
- **`type`** and **`perm`** are optional; omitting either skips the corresponding `find` flag.
- Permission errors from `find` (e.g., `Operation not permitted`) are silently logged at debug level and do not fail the query, matching real-world macOS root execution behavior.
- Only `OperatorEquals` constraints are honored; range/inequality operators are ignored.
