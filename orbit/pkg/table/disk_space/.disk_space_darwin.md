macOS-specific fleetd osquery table plugin that reports disk capacity using `NSURLVolumeAvailableCapacityForImportantUsageKey` — the same "Available" space shown in macOS Finder's "Get Info" dialog.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `Columns()` | `[]table.ColumnDefinition` | Declares two `BIGINT` columns: `bytes_available` and `bytes_total` |
| `Generate()` | osquery table handler | Entry point called by osquery to return a single-row result |
| `getDiskSpace()` | internal helper | Shells out to `osascript` (JXA) to query `NSURL` volume resource keys |

## Usage Example

Register the table with an osquery-go plugin server:

```go
import (
    "github.com/flamingo-stack/fleetmdm/path/to/disk_space"
    "github.com/osquery/osquery-go"
    "github.com/osquery/osquery-go/plugin/table"
)

plugin := table.NewPlugin("disk_space", disk_space.Columns(), disk_space.Generate)
server.RegisterPlugin(plugin)
```

Query from osquery:

```sql
SELECT bytes_available, bytes_total FROM disk_space;
```

## Implementation Notes

- **Build constraint:** `//go:build darwin` — compiles on macOS only.
- **JXA script:** Calls `NSURLVolumeAvailableCapacityForImportantUsageKey` (matches Finder) and `NSURLVolumeTotalCapacityKey` for the root volume (`/`).
- **Timeout:** `osascript` subprocess is bounded to **5 seconds** via `context.WithTimeout`.
- **Error surfacing:** Both `stderr` and `stdout` are captured and included in error messages to aid debugging; non-fatal errors are also logged at `DEBUG` level via `zerolog`.
