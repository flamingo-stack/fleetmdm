Provides osquery table plugins for parsing structured data files (Plist, JSON, JSONL, XML, INI) into queryable rows using the `dataflatten` package.

## Key Components

| Export | Type | Description |
|---|---|---|
| `DataSourceType` | `int` enum | Constants identifying supported data formats (`PlistType`, `JsonType`, `JsonlType`, `XmlType`, `IniType`, `KeyValueType`) |
| `Table` | `struct` | Core table implementation holding flatten functions, logger, and configuration |
| `AllTablePlugins` | `func` | Convenience helper returning all five default format plugins |
| `TablePlugin` | `func` | Constructs a single osquery plugin for a given `DataSourceType` |
| `generate` | `method` | Resolves path constraints (including glob patterns) and dispatches to `generatePath` |
| `generatePath` | `method` | Runs the appropriate flatten function against a resolved file path and returns structured rows |

## Usage Example

```go
// Register all built-in file-parsing table plugins with an osquery extension server
import (
    "github.com/fleetdm/fleet/v4/orbit/pkg/table/dataflattentable"
    "github.com/rs/zerolog"
)

logger := zerolog.New(os.Stdout)

plugins := dataflattentable.AllTablePlugins(logger)
server.RegisterPlugin(plugins...)

// Or register a single format plugin
jsonPlugin := dataflattentable.TablePlugin(logger, dataflattentable.JsonType)
server.RegisterPlugin(jsonPlugin)
```

Once registered, tables are queryable via osquery SQL:

```sql
-- Query a JSON file, filtering nested keys
SELECT * FROM parse_json WHERE path = '/etc/config.json' AND query = 'settings/network';

-- Glob across multiple plists
SELECT * FROM parse_plist WHERE path LIKE '/Library/Preferences/%.plist';
```

## Notes

- `path` constraints support SQL `%` wildcards, which are internally converted to glob `*` patterns via `filepath.Glob`.
- The `query` constraint uses `/`-delimited paths to drill into nested data structures via `dataflatten.WithQuery`.
- `KeyValueType` is defined but not wired in `AllTablePlugins`; use `TablePlugin` directly for custom exec-based or key-value tables.
