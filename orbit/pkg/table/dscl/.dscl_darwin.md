Darwin-only osquery table plugin that executes `dscl read` commands against the local domain and returns structured key/value results.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `Columns()` | Function | Defines the osquery table schema with `command`, `path`, `key`, and `value` columns |
| `Generate()` | Function | Query handler that validates constraints, executes `dscl`, and returns results |
| `parseDSCLReadOutput()` | Function | Parses raw `dscl` stdout into a single string value pointer |

## Schema

| Column | Required | Notes |
|--------|----------|-------|
| `command` | ✅ | Only `read` is currently supported |
| `path` | ✅ | dscl path (e.g. `/Users/alice`) |
| `key` | ✅ | Attribute key to read |
| `value` | — | Parsed output value; empty string if key not found |

## Usage Example

```go
// osquery SQL query against this table
SELECT value FROM dscl
WHERE command = 'read'
  AND path = '/Users/alice'
  AND key = 'UniqueID';
```

```go
// Registering the plugin with an osquery extension
plugin := table.NewPlugin("dscl", dscl.Columns(), dscl.Generate)
server.RegisterPlugin(plugin)
```

## Behavior Notes

- **Build constraint:** Darwin only (`//go:build darwin`)
- `Generate` requires all three constraint columns (`command`, `path`, `key`) with `=` operators; missing any returns an error
- `parseDSCLReadOutput` returns `nil, nil` for empty output or `No such key:` responses, leaving `value` as an empty string rather than erroring
- Unsupported commands return an explicit error listing valid options
