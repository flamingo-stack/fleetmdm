Linux-specific implementation for detecting GUI-logged-in users via `loginctl`, providing user session inspection for the `user` package.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `User` | struct | Holds a user's `Name` (string) and `ID` (UID as int64) |
| `UserDisplaySession` | struct | Holds a session's `Type` (`GuiSessionType`) and `Active` (bool) status |
| `GuiSessionType` | type | Enum: `GuiSessionTypeX11`, `GuiSessionTypeWayland`, `GuiSessionTypeTty` |
| `UserLoggedInViaGui()` | func | Returns the username string of the active GUI user, or `nil` |
| `LoggedInGuiUser()` | func | Returns the full `User` struct for the active GUI user, or `nil` |
| `GetUserDisplaySessionType()` | func | Queries `loginctl` to resolve session type and active status for a given UID |
| `getLoginUsers()` | func | Executes `loginctl list-users` and returns all logged-in users |
| `parseLoginctlUsersOutput()` | func | Parses `loginctl` text output into `[]User` |
| `getDisplaySessionFor()` | func | Filters system/display-manager users and checks for an active GUI session |

## Usage Example

```go
// Get the username of the currently active GUI user
username, err := user.UserLoggedInViaGui()
if err != nil {
    log.Fatal(err)
}
if username == nil {
    fmt.Println("No active GUI session found")
} else {
    fmt.Printf("Active GUI user: %s\n", *username)
}

// Get full User struct including UID
u, err := user.LoggedInGuiUser()
if err != nil {
    log.Fatal(err)
}
if u != nil {
    fmt.Printf("User: %s (UID: %d)\n", u.Name, u.ID)
}

// Inspect a specific user's display session
session, err := user.GetUserDisplaySessionType("1000")
if err != nil {
    log.Fatal(err)
}
fmt.Printf("Session type: %s, Active: %v\n", session.Type, session.Active)
```

## Notes

- **Build constraint:** Linux only (`//go:build linux`)
- System accounts (`gdm`, `root`, `gdm-greeter`, `sddm`) are explicitly excluded from GUI session detection
- Session type resolution follows three sequential `loginctl` calls: Display ID → Type → Active status
- TTY sessions are treated as non-GUI even when active
