Windows-specific implementation for redirecting stderr to a file, enabling panic logs to be captured on Windows systems by manipulating Win32 standard handles via `kernel32.dll`.

## Key Components

### Package-Level Variables
- **`kernel32`** — Loaded reference to `kernel32.dll` via `syscall.MustLoadDLL`
- **`procSetStdHandle`** / **`procGetStdHandle`** — Resolved procedure addresses for Win32 `SetStdHandle` and `GetStdHandle`

### Functions

| Function | Signature | Description |
|---|---|---|
| `dupFD` | `(fd uintptr) (syscall.Handle, error)` | Duplicates a file descriptor into a Windows `HANDLE` using `DuplicateHandle`, mirroring Unix `dup2` semantics |
| `getStdHandle` | `(stdHandle int32) (syscall.Handle, error)` | Retrieves the current Windows standard handle (stdin/stdout/stderr) via `GetStdHandle` |
| `setStdHandle` | `(stdhandle int32, handle syscall.Handle) error` | Replaces a standard handle using `SetStdHandle` |
| `redirectStderr` | `(f *os.File) (UndoFunction, error)` | Saves the current `STD_ERROR_HANDLE`, duplicates the target file's handle, and points stderr at it. Returns an `UndoFunction` to restore the original handle |

## Usage Example

```go
// Open a log file for panic output
logFile, err := os.OpenFile("panic.log", os.O_CREATE|os.O_WRONLY|os.O_APPEND, 0644)
if err != nil {
    log.Fatal(err)
}
defer logFile.Close()

// Redirect stderr (and thus panics) to the log file
undo, err := redirectStderr(logFile)
if err != nil {
    log.Fatal(err)
}
defer undo() // Restore original stderr on exit
```

## Notes

- Build-constrained to **Windows only** (`//go:build windows`)
- The `UndoFunction` type is defined in the platform-agnostic portion of the `paniclog` package
- Inspired by the [minix implementation](https://play.golang.org/p/kLtct7lSUg); handle duplication follows the pattern from [`syscall/exec_windows.go`](https://github.com/golang/go/blob/go1.8/src/syscall/exec_windows.go#L303)
