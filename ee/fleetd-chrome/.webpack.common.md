Shared Webpack configuration for a Chrome extension build, defining common entry points, loaders, plugins, and optimization settings used across development and production builds.

## Key Components

| Export | Purpose |
|--------|---------|
| `entry` | Defines two entry points: `background.ts` (service worker) and `popup.ts` (extension UI) |
| `module` | TypeScript loader rule via `ts-loader` for `.ts`/`.tsx` files |
| `resolve` | File extension resolution order (`.tsx`, `.ts`, `.js`) |
| `plugins` | Three plugins: env vars injection, static asset copying, and HTML generation |
| `devtool` | Inline source maps enabled in both dev and prod for easier debugging |
| `optimization` | TerserPlugin with mangling disabled — removes dead code only |
| `output` | Outputs `[name].bundle.js` to `dist/`, using CommonJS chunk format |

## Plugin Behavior

- **`webpack.DefinePlugin`** — injects all variables from `.env` into the bundle at compile time
- **`CopyWebpackPlugin`** — copies `manifest.json` (with `description`/`version` synced from `package.json`), `schema.json`, and icon assets to `dist/`
- **`HtmlWebpackPlugin`** — generates `popup.html` from `./src/popup.html` template, injecting only the `popup` chunk

## Usage Example

```javascript
// webpack.dev.js
import { merge } from "webpack-merge";
import * as common from "./webpack.common.js";

export default merge(common, {
  mode: "development",
});

// webpack.prod.js
import { merge } from "webpack-merge";
import * as common from "./webpack.common.js";

export default merge(common, {
  mode: "production",
});
```

## Notes

- Mangling is intentionally disabled — bundle size increases (~350KB vs ~70KB) but debugging is significantly easier since the extension is source-available
- `__dirname` is reconstructed manually since this config uses ES modules (`import.meta.url`)
- Source: [webpack.common.js](https://github.com/flamingo-stack/fleetmdm/blob/main/webpack.common.js)
