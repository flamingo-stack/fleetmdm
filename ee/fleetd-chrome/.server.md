A simple local development HTTP file server for serving Chrome extension files, with automatic `Content-Type` handling for `.crx` files.

## Key Components

- **`myfileserver`** — Custom HTTP handler that logs each incoming request and sets the `application/x-chrome-extension` content type for `.crx` file requests before delegating to the standard file server.
- **`main`** — Starts the HTTP server on `localhost:1337`, routing all requests through `myfileserver`.
- **`tFile`** — Compiled regex (`\.crx$`) used to detect Chrome extension file requests.
- **`fileserver`** — Standard `http.FileServer` serving the current directory (`.`).

## Usage Example

```bash
# Navigate to your Chrome extension directory
cd path/to/extension

# Run the development server
go run server.go

# Access files in your browser
# http://localhost:1337/manifest.json
# http://localhost:1337/extension.crx
```

> **Note:** For most local development workflows, Chrome's built-in **"Load unpacked"** option (`chrome://extensions` → Load unpacked) is simpler. This server is useful when you specifically need to serve a packaged `.crx` file over HTTP.
