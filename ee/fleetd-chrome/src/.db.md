Provides an in-memory SQLite virtual database for a Chrome extension environment, registering custom virtual tables that expose device and system information queryable via SQL.

## Key Components

- **`VirtualDatabase`** — Main class wrapping a `wa-sqlite` in-memory database instance
- **`init()`** — Static async factory method that bootstraps the WebAssembly SQLite engine and returns a ready `VirtualDatabase` instance
- **`register()`** — Static helper that registers a virtual table module with the SQLite engine
- **`query()`** — Executes a SQL string and returns rows as `Record<string, string>[]`, normalizing all column values to strings
- **`ChromeResponse`** — Return type for `query()`, containing `data` rows and optional `warnings` for partial failures
- **Registered virtual tables** — `chrome_extensions`, `disk_info`, `geolocation`, `network_interfaces`, `os_version`, `osquery_info`, `privacy_preferences`, `screenlock`, `system_info`, `system_state`, `users`

## Usage Example

```typescript
import VirtualDatabase from "./db";

// Initialize the in-memory database (loads WASM engine)
const vdb = await VirtualDatabase.init();

// Query a virtual table
const { data, warnings } = await vdb.query(
  "SELECT * FROM system_info"
);

if (warnings?.length) {
  console.warn("Query warnings:", warnings);
}

// All values are normalized to strings
data.forEach((row) => {
  console.log(row); // e.g. { hostname: "my-mac", cpu_type: "arm64", ... }
});
```

> All column values are coerced to strings; booleans become `"1"` or `"0"`, and non-serializable values are set to `null` with a warning appended to the response.
