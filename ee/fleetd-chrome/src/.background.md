The service worker entry point for a Chrome extension that manages Fleet MDM enrollment, live query execution, and SQLite-backed virtual database lifecycle — coordinating periodic polling via alarms and mutex-protected execution.

## Key Components

| Export / Symbol | Description |
|---|---|
| `main()` | Orchestrates enrollment check and live query execution per cycle |
| `mainLoop()` | Recursive polling loop (10s interval) wrapped in mutex protection |
| `enroll()` | Registers the host with Fleet using hardware serial/UUID and managed enroll secret |
| `live_query()` | Reads distributed queries from Fleet, runs them against the virtual DB, and writes results back |
| `request()` / `authenticatedRequest()` | HTTP POST helpers; authenticated variant auto-reenrolls on `node_invalid` responses |
| `initDB()` | Initializes the `VirtualDatabase` (wa-sqlite) singleton and exposes it as `globalThis.DB` |
| `NodeInvalidError` | Custom error signaling Fleet rejected the node key, triggering automatic reenrollment |
| `mutexWithTimeout` | 60-second mutex preventing concurrent `main()` executions |
| `MAIN_ALARM` | Chrome alarm (`"main"`) fires every minute to keep the service worker alive |

## Usage Example

The module is self-executing — `mainLoop()` runs immediately on load:

```typescript
// Execution flow (automatic on service worker start):
// 1. mainLoop() called → acquires mutex → calls main()
// 2. main() checks platform (Chrome OS only) + initializes DB if needed
// 3. Enrolls with Fleet if no node_key in chrome.storage.local
// 4. Runs live_query(): reads queries, executes via VirtualDatabase, writes results
// 5. Schedules next mainLoop() after 10s; Chrome alarm fires every 60s as keepalive

// Error recovery:
// - E_ALREADY_LOCKED  → skips current cycle (mutex held)
// - MEMORY_RUNTIME_ERROR_MESSAGE → reinitializes wa-sqlite DB and continues
// - NodeInvalidError  → clears stored node_key, reenrolls, retries request once
```
