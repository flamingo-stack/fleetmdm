Implements a virtual osquery-compatible table that retrieves ChromeOS screen lock settings via the `chrome.idle.getAutoLockDelay` API, normalizing the response to match osquery's macOS `screenlock` schema.

## Key Components

- **`TableScreenLock`** — Extends `Table` to expose a `screenlock` virtual table with two columns:
  - `enabled` — `"1"` if auto-lock is active, `"0"` otherwise
  - `grace_period` — lock delay in seconds, or `"-1"` if disabled
- **`generate()`** — Async method that:
  - Returns a warning (not an error) if `chrome.idle.getAutoLockDelay` is unavailable (non-ChromeOS environment)
  - Calls the Chrome API and maps the numeric delay to osquery-compatible string values
  - Throws if the API returns an unexpected type

## Usage Example

```typescript
import TableScreenLock from "./screenlock";

const table = new TableScreenLock();
const result = await table.generate();

// On ChromeOS with screen lock enabled (e.g., 30s delay):
// { data: [{ enabled: "1", grace_period: "30" }] }

// On ChromeOS with screen lock disabled:
// { data: [{ enabled: "0", grace_period: "-1" }] }

// On non-ChromeOS:
// { data: [], warnings: [{ column: "enabled", error_message: "..." }] }
```

## Notes

- API availability is ChromeOS-only; the guard clause ensures graceful degradation on other platforms
- Output format mirrors the osquery `screenlock` table schema for cross-platform query compatibility
