Implements the `chrome_extensions` osquery-compatible virtual table by querying the Chrome Extensions Management API to enumerate all installed browser extensions.

## Key Components

- **`TableChromeExtensions`** — Extends `Table` to expose installed Chrome extensions as queryable rows, matching osquery's `chrome_extensions` schema.
- **`generate()`** — Fetches all extensions via `chrome.management.getAll()`, merges `permissions` and `hostPermissions` into a single list (mirroring osquery behavior), and returns structured row data.

### Columns

| Column | Description |
|---|---|
| `browser_type` | Always `"chrome"` |
| `name` | Extension display name |
| `identifier` | Extension ID |
| `version` | Extension version string |
| `description` | Extension description |
| `update_url` | Update manifest URL |
| `permissions` | Merged permissions as comma-separated string |
| `permissions_json` | Merged permissions as JSON array |
| `state` | `"1"` if enabled, `"0"` if disabled |
| `path` | Always empty (not available in browser context) |

## Usage Example

```typescript
import TableChromeExtensions from "./chrome_extensions";

const table = new TableChromeExtensions();
const result = await table.generate();

// result.data contains one row per installed extension
console.log(result.data);
// [{ browser_type: "chrome", name: "uBlock Origin", identifier: "cjpalhdlnbpafiamejdnhcphjbkeiagm", state: "1", ... }]
```

## Notes

- Requires the `management` permission in the extension's `manifest.json`.
- `permissions` and `hostPermissions` are merged to match osquery's behavior, where both types are combined into a single column.
- `path` is intentionally empty — the on-disk install path is not accessible from the browser extension API.
