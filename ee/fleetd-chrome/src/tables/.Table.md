Abstract base class that maps low-level SQLite virtual table methods (`wa-sqlite`) to a clean abstraction, allowing concrete table implementations to focus only on defining their `name`, `columns`, and `generate()` function.

## Key Components

- **`Table` (abstract class)** — Implements `SQLiteModule` and handles all SQLite virtual table lifecycle methods. Subclasses must implement `generate()`.
- **`generate()`** — Abstract method that subclasses override to return `ChromeResponse` (rows + optional warnings).
- **`cursorState`** — Tracks `rowIndex` and `rows` per active SQLite cursor, managed in a `Map<number, cursorState>`.
- **`ChromeResponse` / `ChromeWarning`** — Typed interfaces for table data and per-column error reporting.
- **`CONCAT_CHROME_WARNINGS()`** — Utility that flattens an array of `ChromeWarning` objects into a single human-readable string for UI display.
- **SQLite vtab methods** — `xConnect`, `xOpen`, `xClose`, `xFilter`, `xNext`, `xEof`, `xColumn`, `xRowid`, `xBestIndex`, `xDisconnect`, `xDestroy` — all implemented here so subclasses don't have to.

## Usage Example

```typescript
import Table from "./Table";
import type { ChromeResponse } from "./Table";

class ProcessesTable extends Table {
  name = "processes";
  columns = ["pid", "name", "cpu_usage"];

  async generate(
    idxNum: number,
    idxStr: string,
    values: number[]
  ): Promise<ChromeResponse> {
    const processes = await fetchRunningProcesses();
    return {
      data: processes.map((p) => ({
        pid: String(p.pid),
        name: p.name,
        cpu_usage: String(p.cpuUsage),
      })),
    };
  }
}

// Register with wa-sqlite
const table = new ProcessesTable(sqlite3, db);
sqlite3.create_module(db, "processes", table);
```

> **Note:** Errors thrown inside `generate()` are caught in `xFilter` and return `SQLITE_ERROR` rather than propagating — this prevents WASM stack exhaustion. See [wa-sqlite issue #156](https://github.com/rhashimoto/wa-sqlite/issues/156#issuecomment-1942477704) for context.
