Custom Jest environment extending `JSDOMEnvironment` to polyfill native `fetch` APIs missing from jsdom, enabling fetch-based tests without mocking.

## Key Components

- **`JSDOMWithFetch`** — Default export class extending `JSDOMEnvironment` that injects `fetch`, `Headers`, `Request`, and `Response` from the Node.js global scope into the jsdom environment.

## Usage Example

Configure in your Jest config to use this environment globally or per-file:

```typescript
// jest.config.ts
export default {
  testEnvironment: "./jsdomwithfetch.ts",
};
```

Or as a per-file docblock:

```typescript
// mytest.test.ts
/**
 * @jest-environment ./path/to/jsdomwithfetch
 */

it("fetches data", async () => {
  const res = await fetch("https://api.example.com/data");
  expect(res.ok).toBe(true);
});
```

## Notes

- Requires Node.js 18+ (or a global `fetch` polyfill) so that `fetch`, `Headers`, `Request`, and `Response` are available in the Node global scope at environment setup time.
- Based on the community workaround from [jsdom#1724](https://github.com/jsdom/jsdom/issues/1724).
- Source: [`jsdomwithfetch.ts`](https://github.com/flamingo-stack/fleetmdm/blob/main/jsdomwithfetch.ts)
