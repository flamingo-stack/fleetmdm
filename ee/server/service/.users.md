Handles SSO user lifecycle management for the premium Fleet service tier, including Just-In-Time (JIT) provisioning of new users and role synchronization from SAML assertion attributes.

## Key Components

- **`GetSSOUser`** — Core SSO handler that either retrieves an existing user (updating roles if JIT provisioning is enabled) or creates a new user on first login. Defaults new users to `RoleObserver` if no SAML role attributes are present.
- **`rolesChanged`** — Pure utility that compares old and new global/team roles, returning `true` only if a meaningful change is detected. Assumes no duplicate team entries.
- **`userRolesFromSSOAttributes`** — Translates a parsed `fleet.SSORolesInfo` struct into `GlobalRole` and `[]fleet.UserTeam` values suitable for assignment to a `fleet.User`.

## Usage Example

```go
// Typical call during SSO callback handling
user, err := svc.GetSSOUser(ctx, auth)
if err != nil {
    // Handle not-found, invalid email, or provisioning errors
}
// user is either retrieved and role-synced, or freshly JIT-provisioned
```

## Behavior Summary

| Scenario | JIT Enabled | Outcome |
|---|---|---|
| User exists, roles unchanged | Any | Return existing user |
| User exists, roles differ | Yes | Update roles + log activity |
| User exists | No | Return existing user as-is |
| User not found | Yes | Create user, log `UserAddedBySSO` |
| User not found | No | Return `NotFoundError` |

> **Note:** SAML role attributes that are present but empty are coerced to `null` with a warning log. If no role attributes are set at all for a new user, `observer` is assigned as the default global role.
