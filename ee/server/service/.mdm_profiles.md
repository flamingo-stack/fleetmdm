Go templates for generating Apple FileVault and Windows OS Update MDM configuration profiles, used internally by the Fleet MDM service layer.

## Key Components

### Types

| Type | Description |
|------|-------------|
| `fileVaultProfileOptions` | Template data struct with `PayloadIdentifier`, `PayloadName`, and `Base64DerCertificate` fields |
| `windowsOSUpdatesProfileOptions` | Template data struct with `Deadline` (days) and `GracePeriod` (days) fields |

### Templates

| Variable | Description |
|----------|-------------|
| `fileVaultProfileTemplate` | Apple `.mobileconfig` plist that enables FileVault 2 with deferred enforcement, recovery key escrow to Fleet, and a bundled DER certificate for escrow encryption |
| `windowsOSUpdatesProfileTemplate` | SyncML `<Atomic>` block targeting the `./Device/Vendor/MSFT/Policy/Config/Update/` CSP namespace to configure feature/quality update deadlines, grace period, auto-update, and disable pause access |

## Usage Example

```go
// Render a FileVault profile
var buf bytes.Buffer
err := fileVaultProfileTemplate.Execute(&buf, fileVaultProfileOptions{
    PayloadIdentifier:    "com.fleetdm.filevault",
    PayloadName:          "Fleet FileVault",
    Base64DerCertificate: base64.StdEncoding.EncodeToString(derCert),
})

// Render a Windows OS Updates profile
var buf bytes.Buffer
err := windowsOSUpdatesProfileTemplate.Execute(&buf, windowsOSUpdatesProfileOptions{
    Deadline:    7,
    GracePeriod: 2,
})
```

## Notes

- Both templates use `missingkey=error` to fail fast on missing struct fields.
- The FileVault template hard-codes `DeferForceAtUserLoginMaxBypassAttempts: 0` and `ForceEnableInSetupAssistant: true`, ensuring FileVault is enforced at first login with no bypass allowed.
- The Windows template sets `AllowAutoUpdate=1`, `SetDisablePauseUXAccess=1`, and `ConfigureDeadlineNoAutoReboot=1` as fixed policy values alongside the configurable deadline/grace-period.
- Payload type constants (`FleetFileVaultPayloadType`, `FleetRecoveryKeyEscrowPayloadType`, `FleetCustomSettingsPayloadType`) are sourced from [`mobileconfig`](https://github.com/flamingo-stack/fleetmdm/blob/main/server/mdm/apple/mobileconfig) to keep identifiers consistent across the codebase.
