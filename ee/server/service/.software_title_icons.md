Manages CRUD operations for software title icons in the Fleet MDM service, handling icon retrieval, upload, deletion, and activity logging across software installers, VPP apps, and in-house apps.

## Key Components

- **`GetSoftwareTitleIcon`** — Retrieves icon bytes, size, and filename for a given team/title combination. Falls back to a VPP icon URL redirect if no stored icon exists.
- **`UploadSoftwareTitleIcon`** — Validates the target title belongs to a known installer/VPP/in-house app, deduplicates icon storage via SHA-256, persists the icon, and emits an edit activity on change.
- **`DeleteSoftwareTitleIcon`** — Removes a title's icon record and emits an edit activity only when a record was actually deleted (idempotent-safe).
- **`userHasAccessToStorageID`** — Checks whether the calling user's team has write access to an existing icon identified by its storage ID, enabling safe icon reuse across titles.
- **`generateEditActivityForSoftwareTitleIcon`** — Dispatches the appropriate activity event (`ActivityEditedAppStoreApp` or `ActivityTypeEditedSoftware`) based on whether the title is backed by a VPP app, software installer, or in-house app.

## Usage Example

```go
// Upload an icon for a software title
payload := &fleet.UploadSoftwareTitleIconPayload{
    TeamID:   42,
    TitleID:  7,
    Filename: "myapp.png",
    IconFile: iconReader, // io.ReadSeeker
}
icon, err := svc.UploadSoftwareTitleIcon(ctx, payload)

// Retrieve the icon
imageBytes, size, filename, err := svc.GetSoftwareTitleIcon(ctx, 42, 7)

// Delete the icon
err = svc.DeleteSoftwareTitleIcon(ctx, 42, 7)
```

Icon deduplication relies on SHA-256 hashing; if another team already stores the same binary and the caller has write access to that team, the existing blob is reused without re-uploading. All mutations require `fleet.ActionWrite` authorization on `fleet.SoftwareTitleIcon`.
