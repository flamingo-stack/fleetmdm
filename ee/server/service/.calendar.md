Handles Google Calendar webhook processing for Fleet's calendar integration, including event validation, distributed lock management, and asynchronous event queue processing.

## Key Components

- **`CalendarWebhook`** — Entry point for Google Calendar push notifications. Validates the webhook source, checks for recent updates, acquires a distributed lock, and routes events to either synchronous or async processing.
- **`processCalendarEvent`** — Core event handler that evaluates host policy compliance, regenerates event body content, and updates or stops calendar events via the `UserCalendar` interface.
- **`getCalendarLock`** — Acquires a distributed lock for a given event UUID, with support for a "reserved" lock state (used by cron) and optional queue enrollment on contention.
- **`releaseCalendarLock`** — Releases a previously acquired distributed lock, logging errors on failure.
- **`processCalendarAsync`** — Background goroutine that drains the event queue, re-processing events that received callbacks while locked.

## Usage Example

```go
// CalendarWebhook is invoked by the HTTP handler when Google sends a push notification
err := svc.CalendarWebhook(ctx, eventUUID, channelID, resourceState)
if err != nil {
    // handle error
}

// Internally, processCalendarEvent is called to update the event based on policy state
err = svc.processCalendarEvent(ctx, eventDetails, googleCalendarIntegrationConfig, userCalendar)

// Async queue drain is triggered automatically when queued events exist
go svc.processCalendarAsync(ctx, eventIDs)
```

## Concurrency Model

A global `asyncCalendarProcessing` flag guarded by `asyncMutex` prevents multiple goroutines from draining the queue simultaneously. Distributed locks (`LockKeyPrefix+eventUUID`) coordinate across service instances, and a `RecentUpdateKeyPrefix` key suppresses redundant processing of self-triggered webhook callbacks.
