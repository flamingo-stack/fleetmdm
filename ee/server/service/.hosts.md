Provides premium-tier host management operations for the Fleet MDM service, extending the base service with elevated capabilities for host retrieval, OS version details, and cross-platform lock/unlock/wipe lifecycle management.

## Key Components

### Premium Host Retrieval
- **`GetHost`** — Wraps the base `GetHost` with CVE scores, policies, and critical vulnerability counts enabled.
- **`HostByIdentifier`** — Wraps the base lookup with CVE scores and policies included.
- **`OSVersions`** / **`OSVersion`** — Delegates to base service with premium vulnerability options enabled.

### Host Lifecycle Management
- **`LockHost`** — Queues a lock request for a host after validating platform support, MDM enrollment, and pending action state. Handles macOS/iOS/iPadOS, Windows, Linux, and Android with platform-specific prerequisites (MDM enrollment, script execution capability).
- **`UnlockHost`** — Queues an unlock request; returns the PIN for macOS hosts in a pending-unlock state instead of rejecting the request.
- **`WipeHost`** — Queues a remote wipe after verifying MDM configuration and enrollment status; blocks personal-enrollment hosts from being wiped.

### Authorization Pattern
All three lifecycle methods perform a **two-step authorization**: first against `fleet.Host{}` for list access, then against `fleet.MDMCommandAuthz{TeamID: ...}` once the host's team is loaded.

## Usage Example

```go
// Lock a host, optionally retrieving the unlock PIN
pin, err := premiumSvc.LockHost(ctx, hostID, viewPIN)
if err != nil {
    // Handle platform-specific errors, pending actions, or MDM config issues
}

// Unlock a macOS host (returns PIN if pending unlock)
pin, err := premiumSvc.UnlockHost(ctx, hostID)

// Wipe a host
err = premiumSvc.WipeHost(ctx, hostID, metadata)
```

> **Note:** Lock/unlock/wipe operations validate that no conflicting pending actions exist (e.g., a pending wipe blocks a lock request) before enqueuing the command.
