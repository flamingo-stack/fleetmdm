HTTP message signature verification for host identity authentication using TPM-backed certificates and ECDSA public keys.

## Key Components

- **`HTTPSig`** — Core struct implementing `httpsig.KeyFetcher`. Wraps a Fleet datastore and logger to resolve signing keys by ID during request verification.
- **`KeySpecer`** — Adapter struct pairing a `HostIdentityCertificate` with an `httpsig.KeySpec`, implementing the `httpsig.KeySpecer` interface.
- **`NewHTTPSig(ds, logger)`** — Constructor for `HTTPSig`.
- **`FetchByKeyID(ctx, header, keyID)`** — Resolves a hex-encoded serial number to a host identity certificate, unmarshals the ECDSA public key, and maps it to either `Algo_ECDSA_P256_SHA256` (P-256) or `Algo_ECDSA_P384_SHA384` (P-384).
- **`Verifier()`** — Returns a configured `httpsig.Verifier` using Fleet's shared verifier factory.
- **`VerifyHostIdentity(ctx, ds, host)`** — Validates that the host identity certificate extracted from context matches the authenticated host's node key and host ID.

## Usage Example

```go
// Initialize the HTTPSig key fetcher
httpSig := httpsig.NewHTTPSig(datastore, slogLogger)

// Build a verifier for incoming requests
verifier, err := httpSig.Verifier()
if err != nil {
    log.Fatal(err)
}

// After signature verification, validate host identity in a handler
err = httpsig.VerifyHostIdentity(ctx, datastore, host)
if err != nil {
    http.Error(w, err.Error(), http.StatusUnauthorized)
    return
}
```

## Notes

- Only P-256 and P-384 elliptic curves are supported; other curves return an error.
- `Fetch()` (header-based key lookup) is not implemented — all lookups must use `FetchByKeyID`.
- `VerifyHostIdentity` expects a `HostIdentityCertificate` to be present in the request context (populated upstream by middleware). Missing or mismatched certificates result in authentication errors.
