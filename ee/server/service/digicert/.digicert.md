REST client implementation for the DigiCert mPKI API, providing certificate issuance and profile validation for Fleet MDM's DigiCert CA integration.

## Key Components

- **`Service`** — Core struct implementing `fleet.DigiCertService`, configured with a logger and HTTP timeout via functional options.
- **`NewService(opts ...Opt)`** — Constructor accepting optional `WithTimeout` and `WithLogger` options.
- **`VerifyProfileID(ctx, config)`** — Validates a DigiCert profile ID by issuing a `GET` to the mPKI v2 profile endpoint, confirming the profile exists and has `Active` status.
- **`GetCertificate(ctx, config)`** — Full certificate issuance flow: generates a 2048-bit RSA key pair, builds a CSR, POSTs to the mPKI v1 certificate endpoint, and returns the resulting cert bundled as a password-protected PKCS12 (`.pfx`) payload. Optionally includes UPN SANs for user seat types.

## Usage Example

```go
import "github.com/flamingo-stack/fleetmdm/server/service/digicert"

svc := digicert.NewService(
    digicert.WithLogger(logger),
    digicert.WithTimeout(30 * time.Second),
)

config := fleet.DigiCertCA{
    URL:                   "https://one.digicert.com",
    APIToken:              "your-api-token",
    ProfileID:             "your-profile-guid",
    Name:                  "MyCA",
    CertificateCommonName: "user@example.com",
    CertificateSeatID:     "seat-id",
}

// Validate the profile before issuing
if err := svc.VerifyProfileID(ctx, config); err != nil {
    log.Fatal(err)
}

// Issue a certificate and receive a PKCS12 bundle
cert, err := svc.GetCertificate(ctx, config)
if err != nil {
    log.Fatal(err)
}
// cert.PfxData and cert.Password are ready for MDM payload delivery
```

## Notes

- Serial number validation enforces the DigiCert spec: a non-empty hex string up to 40 characters (20 bytes).
- HTTP 401/403 responses surface actionable error messages referencing the CA name and status code.
- UPN SANs are only added when at least one non-blank UPN is present, matching DigiCert's user seat type requirement.
