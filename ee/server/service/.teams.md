This file implements team management operations for the Fleet MDM service layer, handling team creation, modification, secret obfuscation, and MDM configuration updates.

## Key Components

| Function/Method | Description |
|---|---|
| `obfuscateSecrets` | Masks enrollment secrets for observers, technicians, and non-team members |
| `NewTeam` | Creates a new team with name validation, conflict detection, and default secret generation |
| `ModifyTeam` | Updates team configuration including name, MDM settings, disk encryption, and OS update policies |
| `teamNameConflictErrMsg` | Constant error message for case-insensitive team name conflicts |

## Usage Example

```go
// Create a new team
teamName := "Engineering"
team, err := svc.NewTeam(ctx, fleet.TeamPayload{
    Name:        &teamName,
    Description: ptr.String("Engineering team devices"),
})

// Modify an existing team's macOS update settings
minVersion := optjson.SetString("14.0")
deadline := optjson.SetString("2024-12-01")
updated, err := svc.ModifyTeam(ctx, teamID, fleet.TeamPayload{
    MDM: &fleet.TeamPayloadMDM{
        MacOSUpdates: &fleet.MacOSUpdates{
            MinimumVersion: minVersion,
            Deadline:       deadline,
        },
    },
})
```

## Notes

- Team names are reserved-word checked and must be unique regardless of letter case
- `ModifyTeam` with `teamID == 0` delegates to `modifyDefaultTeamConfig` for the "No team" group
- MDM disk encryption changes are validated against whether Apple MDM or Windows MDM is configured
- OS update settings conflict with custom profile declarations — both cannot coexist
