Registers and configures the SCIM (System for Cross-domain Identity Management) server within the Fleet HTTP mux, wiring up resource types, schemas, and middleware.

## Key Components

- **`RegisterSCIM`** — Main entry point that initializes the SCIM server and registers routes on the provided `http.ServeMux` for both `/api/v1/fleet/scim/` and `/api/latest/fleet/scim/`.
- **`userSchema`** — RFC 7643 §4.1 User schema defining `userName`, `name`, `emails`, `active`, and `groups` attributes, plus the full Enterprise User extension (§4.3) to accept IdP PATCH payloads without 400 errors.
- **`groupSchema`** — RFC 7643 §4.2 Group schema with `displayName` and `members` attributes.
- **`resourceTypes`** — Slice wiring schemas to their handlers (`NewUserHandler`, `NewGroupHandler`) and HTTP endpoints (`/Users`, `/Groups`).
- **`applyMiddleware`** — Chains middleware in order: OTEL instrumentation → authorization → debug payload dump → authentication → last-request tracking → response logging → request context.

## Usage Example

```go
mux := http.NewServeMux()

err := scim.RegisterSCIM(
    mux,
    datastore,
    fleetService,
    slog.Default(),
    &config.FleetConfig{...},
)
if err != nil {
    log.Fatal(err)
}
```

## Notes

- `maxResults` is capped at `100` to bound list responses.
- The Enterprise User extension declares all RFC 7643 §4.3 attributes (e.g., `department`, `manager`) so IdPs like Okta/Azure AD don't receive 400s for unsupported fields — the handler silently drops anything it doesn't need.
- Microsoft Entra ID does not properly support `$ref` on group members; that sub-attribute is intentionally omitted from `groupSchema`.
- Go's `http.StripPrefix` does not support wildcards, so both versioned path prefixes (`v1` and `latest`) are registered explicitly.
