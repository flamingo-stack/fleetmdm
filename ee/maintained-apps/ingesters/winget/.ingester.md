Orchestrates the ingestion of Windows application metadata from the WinGet package repository on GitHub, parsing manifests to produce structured app data for Fleet's maintained apps system.

## Key Components

- **`IngestApps`** – Entry point that reads JSON input files from a directory, validates required fields, and delegates to `wingetIngester` for each app.
- **`wingetIngester`** – Struct holding a GitHub API client used to fetch installer and locale manifests from `microsoft/winget-pkgs`.
- **`wingetVersionManifestDirs`** – Filters GitHub directory listings to valid semver-style version folders, excluding non-numeric and bare year-only entries (e.g. `2010`, `2013`).
- **`ingestOne`** – Core ingestion logic: resolves the correct version directory, downloads installer and locale YAML manifests, selects the matching installer by architecture/scope/type/locale, and assembles an `FMAManifestApp` output.

## Usage Example

```go
apps, err := winget.IngestApps(
    ctx,
    slog.Default(),
    "./inputs",   // directory of *.json input files
    "firefox",    // optional slug filter; "" = ingest all
)
if err != nil {
    log.Fatal(err)
}
for _, app := range apps {
    fmt.Printf("Ingested: %s v%s\n", app.Name, app.Version)
}
```

Each JSON input file must provide `slug`, `uniqueIdentifier`, `name`, `packageIdentifier`, `installerArch`, `installerScope`, and `installerType`. Optional fields include `installScriptPath`, `uninstallScriptPath`, and `installerLocale`.

Installer type normalization handles WiX (`wix` → `msi`) and Burn (`burn` → `exe`). MSI machine-scope installs auto-generate install/uninstall scripts, with upgrade-code-based uninstall scripts preferred when an `UpgradeCode` is present in the manifest's `AppsAndFeaturesEntries`.
