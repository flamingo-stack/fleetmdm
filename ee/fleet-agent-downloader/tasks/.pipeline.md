Defines the ordered asset injection pipeline for the Sails.js application, specifying which CSS, JavaScript, and HTML template files are linked as `<link>` and `<script>` tags during asset compilation.

## Key Components

- **`cssFilesToInject`** — Ordered array of CSS glob patterns; loads dependency stylesheets (e.g. Bootstrap) before custom `styles/**/*.css` files.
- **`jsFilesToInject`** — Ordered array of JS glob patterns with explicit load order: `sails.io` → `lodash` → `jquery` → `vue` → `vue-router` → other dependencies → `cloud.setup.js` → components/utilities → remaining app scripts.
- **`templateFilesToInject`** — Glob pattern for client-side HTML templates (`templates/**/*.html`) precompiled into a single `<script>` tag via JST (lodash/underscore).
- **`module.exports`** — Resolves all glob paths relative to `.tmp/public/` (JS/CSS) or `assets/` (templates), with correct handling for negation patterns (`!`).

## Usage Example

```javascript
// Consumed internally by Grunt tasks (e.g. sails-linker).
// To add a new dependency before Vue loads:
var jsFilesToInject = [
  'dependencies/sails.io.js',
  'dependencies/lodash.js',
  'dependencies/jquery.min.js',
  'dependencies/my-new-lib.js', // added here, before vue
  'dependencies/vue.js',
  // ...
];

// To exclude a specific file using negation:
var cssFilesToInject = [
  'dependencies/**/*.css',
  '!dependencies/unwanted-theme.css', // negation prefix is preserved
  'styles/**/*.css'
];
```

> **Note:** This file only affects projects using Sails.js automatic asset linking. If you manage assets manually (e.g. via Webpack or Vite), this file has no effect. See the [source file](https://github.com/flamingo-stack/fleetmdm/blob/main/tasks/pipeline.js) for full glob configuration.
