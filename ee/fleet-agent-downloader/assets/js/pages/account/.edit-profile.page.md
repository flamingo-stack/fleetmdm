Registers the `edit-profile` parasails page, managing form state and submission logic for updating a user's profile (full name and email address).

## Key Components

**Data Properties**
- `syncing` — Loading/spinner state flag
- `formData` — Holds `fullName` and `emailAddress` input values
- `formErrors` — Tracks client-side validation errors per field
- `formRules` — Validation rules: `fullName` (required), `emailAddress` (required, valid email)
- `cloudError` — Stores server-side error messages

**Lifecycle Hooks**
- `beforeMount` — Pre-populates `formData` from the current user (`me`), using `emailChangeCandidate` if a pending email change exists
- `mounted` — Async hook (reserved for future use)

**Methods**
- `submittedForm` — On successful form submission, keeps spinner active and redirects to `/account`

## Usage Example

```javascript
// The page is registered via parasails and auto-initialized by the framework.
// Form pre-population on load:
beforeMount: function() {
  this.formData.fullName = this.me.fullName;
  this.formData.emailAddress = this.me.emailChangeCandidate
    ? this.me.emailChangeCandidate
    : this.me.emailAddress;
},

// After successful submission, redirects to account page:
submittedForm: async function() {
  this.syncing = true;
  window.location = '/account';
}
```

## Notes

- A pending email change (`emailChangeCandidate`) takes precedence over the confirmed `emailAddress` in the form pre-fill, allowing users to see and re-submit their pending change.
- The `syncing` flag is intentionally left `true` after submission to keep the loading spinner visible during page navigation.
