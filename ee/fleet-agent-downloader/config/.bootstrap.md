Runs once before the Sails.js app lifts to manage database seeding and versioned fake data initialization for development and test environments.

## Key Components

- **`HARD_CODED_DATA_VERSION`** — Integer version flag; increment to force a re-seed on next lift
- **`bootstrapLastRunInfoPath`** — Path to `.tmp/bootstrap-version.json`, which tracks when the bootstrap last ran locally
- **Version check logic** — Compares the current `HARD_CODED_DATA_VERSION` against the last recorded run; skips seeding if already up-to-date
- **Production/safe guard** — Exits early when `NODE_ENV=production` or `migrate: safe` is set to prevent accidental data loss
- **Model wipe loop** — Destroys all records across every registered Sails model when a re-seed is triggered
- **Seed data** — Creates a default super-admin user (`admin@example.com`) with a hashed password
- **Bootstrap version writer** — Persists the current version and timestamp to `.tmp/bootstrap-version.json` after a successful run

## Usage Example

```javascript
// Force a re-seed in development by running with --drop:
// sails lift --drop

// Or simulate a test environment:
// sails lift --environment=test

// To trigger a re-seed without --drop, increment the version constant:
var HARD_CODED_DATA_VERSION = 1; // was 0

// Default seed creates this user:
// email:    admin@example.com
// password: abc123
// role:     superAdmin
```

## Notes

- The bootstrap will **skip silently** if the same version has already run on the current machine
- Seeding is **never triggered** in production or with `migrate: safe` — safe by default
- To add more seed records, extend the `User.createEach([...])` call or add similar blocks for other models beneath it
