Handles content negotiation for expired or invalid token responses, serving either a JSON `498` status message or an HTML error page depending on the request type.

## Key Components

- **`expired()`** — Custom Sails.js response function attached to `res.expired()`. Checks `req.wantsJSON` to determine response format:
  - **JSON clients** → `498 Token Expired/Invalid` plain text response
  - **Browser clients** → `498` status with rendered `498` view template

## Usage Example

```javascript
// Basic usage in a controller action
return res.expired();

// With actions2 exits
exits: {
  badToken: {
    description: 'Provided token was expired, invalid, or already used up.',
    responseType: 'expired'
  }
}
```

## Notes

- Uses HTTP status code `498` (non-standard, Token Expired/Invalid)
- Logs verbose output via `sails.log.verbose` on each invocation
- Follows the [Sails.js custom response](https://sailsjs.com/documentation/concepts/extending-sails/custom-responses) pattern using `this.req` and `this.res`
- Source: [`api/responses/expired.js`](https://github.com/flamingo-stack/fleetmdm/blob/main/api/responses/expired.js)
