Sails.js custom hook that runs server-start-time initialization and per-request middleware logic for authentication, session management, and third-party service configuration.

## Key Components

- **`initialize()`** — Runs on app lift; validates Stripe/SendGrid config, sets `enableBillingFeatures` flag, and configures both service clients after the `organics` hook loads
- **`routes.before['/*']`** — Per-request middleware that:
  - Attaches `_environment` and `me` view locals for GET/HEAD requests
  - Redirects mismatched hostnames to the configured `baseUrl` in staging/production
  - Sets `Cache-Control: no-cache, no-store` headers to prevent stale bundle references
  - Resolves the logged-in user from session, exposes it as `req.me` and `res.locals.me`
  - Sanitizes the user record (strips `protect: true` fields and passwords) before view exposure
  - Lazily updates `lastSeenAt` in the background (buffered to 60 seconds)

## Usage Example

```javascript
// This hook loads automatically from api/hooks/custom/index.js
// No manual registration needed in Sails.js

// Accessing attached locals in a view (EJS/Pug):
// <%= me.emailAddress %>
// <%= isBillingEnabled %>

// Accessing the user in an action:
module.exports = {
  fn: async function (inputs, exits) {
    // req.me is populated by this hook for authenticated requests
    return exits.success({ user: this.req.me });
  }
};
```

## Configuration Dependencies

| Key | Purpose |
|-----|---------|
| `sails.config.custom.stripeSecret` | Enables billing features |
| `sails.config.custom.stripePublishableKey` | Enables billing features |
| `sails.config.custom.sendgridSecret` | Enables email features |
| `sails.config.custom.internalEmailAddress` | Enables email features |
| `sails.config.custom.baseUrl` | Hostname redirect target in staging/production |
