A Sails.js middleware policy that gates route access to authenticated users only.

## Key Components

- **`req.me`** — Checks for the presence of the custom `req.me` property (set by the app's custom hook at `api/hooks/custom/index.js`) to determine if the request originates from a logged-in user
- **Okta integration check** — When `sails.config.custom.oktaClientSecret` is configured, performs an additional `req.isUnauthenticated()` validation to enforce Okta session state
- **`proceed()`** — Passes control to the next policy or action when authentication is confirmed
- **`res.unauthorized()`** — Returns a `401` response for unauthenticated requests

## Usage Example

Apply this policy to controllers or actions in `config/policies.js`:

```javascript
// config/policies.js
module.exports.policies = {
  // Protect all actions in UserController
  UserController: {
    '*': 'is-logged-in',
  },

  // Protect a specific action
  DashboardController: {
    index: 'is-logged-in',
  },
};
```

## Notes

- Relies on `req.me` being populated upstream — ensure the custom hook (`api/hooks/custom/index.js`) is in place
- When Okta is enabled via `sails.config.custom.oktaClientSecret`, session validity is double-checked using Passport's `req.isUnauthenticated()`, preventing stale or invalidated Okta sessions from passing through
- For unauthenticated requests, always returns `res.unauthorized()` regardless of the Okta configuration
