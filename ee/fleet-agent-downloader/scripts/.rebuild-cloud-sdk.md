A Sails.js custom script that introspects the app's route configuration to regenerate `cloud.setup.js`, the browser-side AJAX/WebSocket SDK, and optionally writes a JSON snapshot for automated tests.

## Key Components

- **Route Iteration** — Loops over `sails.config.routes`, skipping redirects, string targets, and routes without an `action` property
- **Method Name Derivation** — Converts the bare action name (e.g., `view-dashboard`) to camelCase for the SDK method name
- **View Route Handling** — Routes targeting views are excluded from the main SDK but captured in `extraEndpointsOnlyForTestsByMethodName` for test convenience
- **Actions2 Argument Inference** — Inspects `def.inputs` (or `def.args`) on actions2 definitions to generate ordered argument lists
- **WebSocket Detection** — Sets `protocol: 'io.socket'` when the route target includes `isSocket` or `hasSocketFeatures`
- **`cloud.setup.js` Writer** — Overwrites `assets/js/cloud.setup.js` with the serialized endpoint map using `sails.helpers.fs.write`
- **Test Snapshot Writer** — If a `test/` directory exists, writes `test/private/CLOUD_SDK_METHODS.json` merging both endpoint maps

## Usage Example

```bash
# Run from the project root via Sails CLI
sails run rebuild-cloud-sdk
```

```javascript
// Resulting shape inside assets/js/cloud.setup.js
Cloud.setup({
  methods: {
    "login": { verb: "POST", url: "/api/v1/entrance/login", args: ["emailAddress", "password"] },
    "getDashboard": { verb: "GET", url: "/dashboard" },
    "subscribeToUpdates": { verb: "GET", url: "/api/v1/updates", protocol: "io.socket" }
  }
});
```

## Notes

- Must be executed within a running Sails.js app context (`sails run`)
- The output file path is resolved relative to `sails.config.appPath`
