Webpack build configuration for the FleetMDM frontend, handling asset bundling, TypeScript/JSX transpilation, SCSS compilation, and environment-specific optimizations for both development and production builds.

## Key Components

- **Entry Point** — `frontend/index.jsx` compiled to `assets/bundle.js` (or `bundle-[contenthash].js` in production)
- **TypeScript Checking** — `ForkTsCheckerWebpackPlugin` runs type checks in a separate process
- **HTML Template** — `HtmlWebpackPlugin` generates `frontend/templates/react.tmpl` from an EJS template, injecting an `isProduction` flag
- **CSS Extraction** — `MiniCssExtractPlugin` outputs `bundle.css` (dev) or `bundle-[contenthash].css` (prod)
- **Module Rules**:
  - `.tsx?` / `.jsx?` — transpiled via `esbuild-loader` targeting ES2016, with `babel-loader` for JSX files
  - `.scss` — processed through `sass-loader` (with Bourbon mixins and glob imports) → `postcss-loader` → `css-loader` → extracted CSS
  - `.css` — extracted via `MiniCssExtractPlugin` with PostCSS
  - Assets (images, fonts, video) — emitted as `[name]@[hash][ext]`
  - Shell scripts (`.sh`, `.ps1`) — inlined as source strings
- **Resolve Aliases** — `node-sql-parser` aliased to a custom SQLite UMD build; `frontend/` directory added as a module resolution root
- **Source Maps** — `eval-source-map` enabled in development only
- **Minification** — enabled only for production builds

## Usage Example

```bash
# Development build with watch
NODE_ENV=development npx webpack --watch

# Production build with content hashing and minification
NODE_ENV=production npx webpack
```
