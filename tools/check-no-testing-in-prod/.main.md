A build-time guard that fails the build if any Fleet-owned package reachable from production binaries directly imports Go's `testing` package, preventing test scaffolding from being linked into shipping binaries.

## Key Components

- **`roots`** — The three production entry points audited: `./cmd/fleet`, `./cmd/fleetctl`, and `./orbit/cmd/orbit`
- **`fleetModulePrefix`** — Constant (`github.com/fleetdm/fleet/v4/`) used to filter only first-party packages from the full dependency graph
- **`pkgInfo`** — Struct that deserializes the relevant fields (`ImportPath`, `Imports`, `Standard`) from `go list -json` output
- **`main()`** — Orchestrates the check: runs `go list -tags full,fts5,netgo -e -deps -json` across all roots, streams the JSON output, and collects any Fleet package that lists `"testing"` as a direct import

## Usage Example

```bash
# Run directly
go run ./tools/check-no-testing-in-prod

# Wired into the lint target (see Makefile)
make lint-go
```

## Behavior

On success (no offenders), the program exits with code `0` silently. On failure, it prints the offending package paths to `stderr` and exits with code `1`:

```text
check-no-testing-in-prod: the following Fleet packages are reachable from
the production binaries (cmd/fleet, cmd/fleetctl, orbit/cmd/orbit) AND import
the "testing" package directly. Move the test-only code into a sibling
*test subpackage or a _test.go file.

  - github.com/fleetdm/fleet/v4/server/somepackage
```

> **Note:** Third-party dependencies (e.g. pkcs7 forks, `apache/thrift`) are intentionally excluded — only `github.com/fleetdm/fleet/v4/...` packages are checked.
