Serves as the entry point for a Google Calendar load-test HTTP server, configuring a SQLite-backed handler and starting a local HTTP listener for calendar integration testing.

## Key Components

| Element | Description |
|---|---|
| `main()` | Parses CLI flags, initializes the calendar test handler, and starts the HTTP server |
| `--port` flag | Port to listen on (default: `8083`) |
| `--db` flag | Path to the SQLite database file (default: `./calendar.db`) |
| `calendartest.Configure()` | Sets up the SQLite-backed HTTP handler for calendar load testing |
| `calendartest.Close()` | Deferred teardown of the calendar test resources |

## Usage Example

```bash
# Run with defaults (port 8083, ./calendar.db)
go run calendar.go

# Run with custom port and database path
go run calendar.go --port 9090 --db /tmp/test-calendar.db
```

```go
// Server is configured with conservative timeouts suitable for load testing
server := &http.Server{
    Addr:         ":8083",
    ReadTimeout:  5 * time.Second,
    WriteTimeout: 10 * time.Second,
    IdleTimeout:  15 * time.Second,
}
```

## Notes

- Requires CGo and the `go-sqlite3` driver (imported as a side-effect via `_`)
- Intended for local/load-test environments only — not a production server
- Source: [`ee/server/calendar/load_test/`](https://github.com/flamingo-stack/fleetmdm/blob/main/ee/server/calendar/load_test)
