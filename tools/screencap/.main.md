This is the entry point for a headless Chrome-based screenshot automation tool that captures Fleet MDM UI pages, supporting multiple authentication methods, built-in page workflows, and custom recordable workflows.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `modal` | struct | Describes a UI modal with a trigger button selector and optional tabs to cycle through |
| `modalTab` | struct | A named tab inside a modal with its CSS selector |
| `pageEntry` | struct | A URL path paired with a list of modals to interact with before screenshotting |
| `addHostsModal` | var | Pre-defined modal config for the "Add Hosts" dialog including platform tabs |
| `fullPages` | var | Built-in ordered list of all Fleet MDM pages and their modal interactions |
| `main()` | func | CLI entry point; parses flags, manages Chrome profile, handles auth, and dispatches to record or run mode |
| `recordWorkflow()` | func | Interactive recorder that injects JS listeners and saves user interactions as replayable workflow steps |

## Usage Example

```bash
# Run the built-in full screenshot workflow with email/password auth
go run ./tools/screencap/main.go \
  -email admin@example.com \
  -password secret \
  -workflow full \
  https://fleet.example.com

# Use an existing session cookie
go run ./tools/screencap/main.go \
  -cookie "abc123token" \
  https://fleet.example.com

# Record a custom workflow interactively (opens visible browser)
go run ./tools/screencap/main.go \
  -record my-workflow \
  -email admin@example.com \
  -password secret \
  https://fleet.example.com

# Replay a saved workflow
go run ./tools/screencap/main.go \
  -workflow my-workflow \
  https://fleet.example.com

# List all saved workflows
go run ./tools/screencap/main.go -list https://fleet.example.com
```

Screenshots are saved under `screenshots/<date>-<workflow>-<host>/`.

## Notes

- A persistent Chrome profile is used so sessions survive across runs; a `SingletonLock` cleanup is performed on startup to recover from crashed previous runs
- Pass `-insecure` to bypass TLS certificate validation for self-signed development certificates
- SSO or `-login` flag forces a visible (non-headless) browser window
