Defines the workflow action system for GitHub issue automation, providing typed action constants, bulk action builders, composite workflow helpers, and an asynchronous execution engine that streams status updates over a channel.

## Key Components

### Types

| Type | Description |
|------|-------------|
| `ActionType` | String alias representing a discrete operation (e.g., `ATAddLabel`, `ATSetStatus`) |
| `Action` | Struct holding an action type, target issue, and optional fields (project, label, status, sprint, source project) |
| `Status` | Struct returned per-action by `AsyncManager` containing an index and state string (`"success"` / `"error"`) |

### Action Type Constants

`ATAddLabel` · `ATRemoveLabel` · `ATAddIssueToProject` · `ATRemoveIssueFromProject` · `ATSetStatus` · `ATSyncEstimate` · `ATSetSprint` · `ATCloseIssue`

### Bulk Action Builders

| Function | Purpose |
|----------|---------|
| `CreateBulkAddLableAction` | Add a label to many issues |
| `CreateBulkRemoveLabelAction` | Remove a label from many issues |
| `CreateBulkAddIssueToProjectAction` | Add issues to a project |
| `CreateBulkRemoveIssueFromProjectAction` | Remove issues from a project |
| `CreateBulkSetStatusAction` | Set project status on issues |
| `CreateBulkSyncEstimateAction` | Copy estimate from source to target project |
| `CreateBulkSetSprintAction` | Assign current sprint to issues |
| `CreateBulkMoveToCurrentSprintIfNotReadyQA` | Filters out issues in "ready"/"qa" statuses before setting sprint |

### Composite Workflow Helpers

| Function | Orchestrates |
|----------|-------------|
| `CreateBulkSprintKickoffActions` | Add to project → `:release` label → sync estimate → set sprint → remove `:product` → remove from draft |
| `CreateBulkMilestoneCloseActions` | Stories → move to draft + `:product` label + status; bugs/sub-tasks → close |
| `CreateBulkKickOutOfSprintActions` | Move to draft → set status → sync estimate → `:product` label → remove `:release` → remove from sprint project |

### Execution Engine

`AsyncManager(actions []Action, statusChan chan<- Status)` — processes actions sequentially, dispatches each to the appropriate GitHub API call, and sends a `Status` result per action. The channel is closed when all actions are complete.

## Usage Example

```go
issues := []ghapi.Issue{ /* ... */ }

// Build a sprint kickoff action plan
actions := ghapi.CreateBulkSprintKickoffActions(issues, sourceProjectID, targetProjectID)

// Execute asynchronously with live status updates
statusChan := make(chan ghapi.Status, len(actions))
go ghapi.AsyncManager(actions, statusChan)

for s := range statusChan {
    fmt.Printf("Action %d: %s\n", s.Index, s.State)
}
```

> **Extending the workflow:** Add a new `ActionType` constant, a bulk builder function, and a corresponding `case` in `AsyncManager`'s switch statement (marked with `// newworkflow` comments throughout the file).
