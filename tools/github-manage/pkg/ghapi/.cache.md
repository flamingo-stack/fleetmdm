Thread-safe in-memory caching layer for GitHub API (`ghapi` package) project metadata, reducing redundant GraphQL calls for project node IDs, project item IDs, and project field mappings.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `MapProjectFieldNameToField` | `map[int]map[string]ProjectField` | Public cache mapping project ID → field name → `ProjectField` metadata |
| `ClearProjectNodeIDCache()` | func | Clears the project number → GraphQL node ID cache |
| `ClearProjectItemIDCache()` | func | Clears the (issue, project) → item ID cache |
| `ClearProjectFieldsCache()` | func | Clears the project field metadata cache |
| `ClearAllCaches()` | func | Convenience wrapper clearing all three caches |
| `GetCacheStats()` | func | Returns entry counts for all caches as `map[string]interface{}` |
| `InvalidateProjectItemID()` | func | Removes a single project item entry from cache by issue and project ID |

Internal vars `projectNodeIDCache` and `projectItemIDCache` are protected by dedicated `sync.RWMutex` instances. `MapProjectFieldNameToField` is unguarded — callers must synchronize externally if accessed concurrently.

## Usage Example

```go
// Check cache health at startup or in diagnostics
stats := ghapi.GetCacheStats()
fmt.Printf("Cached node IDs: %d, item IDs: %d, fields: %d\n",
    stats["project_node_ids"],
    stats["project_item_ids"],
    stats["project_fields"],
)

// Invalidate stale entry after an item is moved between projects
ghapi.InvalidateProjectItemID(42, 7)

// Full reset between test runs or after bulk operations
ghapi.ClearAllCaches()
```

## Notes

- `projectNodeIDCache` and `projectItemIDCache` use `sync.RWMutex` — safe for concurrent reads.
- Cache keys for project items are formatted as `"issueNumber:projectID"` via `generateProjectItemCacheKey`.
- `MapProjectFieldNameToField` is exported directly; no mutex guards it — avoid concurrent writes without external locking.
