Provides filtering logic for the TUI issue list, enabling real-time search across GitHub issue fields and managing the mapping between filtered and original issue indices.

## Key Components

| Function | Description |
|---|---|
| `applyFilter()` | Filters `m.choices` by the current `m.filterInput` value, updating `m.filteredChoices` and `m.originalIndices`; resets cursor if out of bounds |
| `matchesFilter()` | Case-insensitive substring match against issue number, title, body, labels, type, author, and assignees |
| `getCurrentChoices()` | Returns `m.filteredChoices` when a filter is active, otherwise `m.choices` |
| `getOriginalIndex()` | Maps a filtered list index back to its original index in `m.choices` |

## Usage Example

```go
// User types a search term into the filter input
m.filterInput = "bug"
m.applyFilter()

// Iterate over the filtered results
for i, issue := range m.getCurrentChoices() {
    originalIdx := m.getOriginalIndex(i)
    fmt.Printf("Filtered[%d] -> Original[%d]: %s\n", i, originalIdx, issue.Title)
}

// Clear the filter to restore the full list
m.filterInput = ""
m.applyFilter() // m.filteredChoices == m.choices, all indices identity-mapped
```

## Notes

- Sorting via `ghapi.SortIssuesForDisplay` is applied to the base list before filtering, ensuring consistent display order whether or not a filter is active.
- `m.originalIndices` preserves the pre-filter index of each matched issue, allowing selection actions to reference the correct item in `m.choices`.
- All comparisons are lowercased, making the filter case-insensitive by default.
