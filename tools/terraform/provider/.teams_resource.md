Terraform resource implementation for the `fleetdm_teams` resource type, handling full CRUD lifecycle management of FleetDM teams via the FleetDM API.

## Key Components

| Symbol | Description |
|---|---|
| `teamsResource` | Struct implementing the Terraform resource with a `FleetDMClient` reference |
| `NewTeamsResource()` | Constructor function registered with the Terraform provider |
| `teamModelToTF()` | Helper that converts a `TeamGetResponse` API response into a `TeamModel` Terraform state struct |
| `Create()` | Creates a team, then optionally applies agent options in a second API call with cleanup on failure |
| `Read()` | Fetches current team state from the Fleet API and syncs it to Terraform state |
| `Update()` | Diffs plan vs. state and applies changes to name, description, and/or agent options |
| `Delete()` | Deletes the team via API and removes it from Terraform state |
| `ImportState()` | Accepts a team name, resolves it to an ID via `TeamNameToID`, then delegates to `Read()` |

## Usage Example

```hcl
resource "fleetdm_teams" "engineering" {
  name        = "Engineering"
  description = "Engineering team devices"
  agent_options = jsonencode({
    config = {
      options = {
        logger_plugin = "tls"
      }
    }
  })
}
```

```bash
# Import an existing team by name
terraform import fleetdm_teams.engineering "Engineering"
```

## Notes

- **Agent options atomicity**: `Create` is a two-step API operation (team creation + agent options). On agent options failure, the resource attempts to delete the newly created team. This cleanup is best-effort and may require manual intervention if it also fails.
- **Import**: Accepts a team name string and resolves it to an integer ID before delegating to `Read`.
