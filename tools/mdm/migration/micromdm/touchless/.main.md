Extracts and migrates device enrollment data from a MicroMDM BoltDB database, generating SQL insertion statements for NanoMDM-compatible tables and exporting SCEP certificate/key files.

## Key Components

### Types
- **`Authenticate`** — Plist-serializable struct representing an MDM Authenticate message with device metadata fields
- **`TokenUpdate`** — Plist-serializable struct representing an MDM TokenUpdate message containing APNS push credentials and tokens

### Constants
- **`referenceTime`** — Canary timestamp (`2000-01-01 00:00:00`) used to detect and skip records already modified in the target database

### `main()`
Two self-contained closures handle distinct migration phases:

1. **Device/Enrollment Export** — Reads devices, APNS push info, and SCEP identity certificates from MicroMDM BoltDB; generates upsert SQL for `nano_devices`, `nano_enrollments`, and `nano_cert_auth_associations`, writing output to `dump.sql`
2. **SCEP Key/Cert Export** — Loads or creates the SCEP CA key and certificate from BoltDB, writing PEM-encoded files as `scep.key` and `scep.cert`

## Usage Example

```bash
# Build the migration tool
go build -o micromdm-migrate ./main.go

# Run against an existing MicroMDM database
./micromdm-migrate -db /var/db/micromdm/micromdm.db

# Apply the generated SQL to your NanoMDM-compatible MySQL instance
mysql -u fleet -p fleet < dump.sql
```

**Outputs:**
| File | Contents |
|---|---|
| `dump.sql` | Idempotent upsert SQL for device, enrollment, and cert association tables |
| `scep.key` | RSA private key (PEM, PKCS#1) |
| `scep.cert` | SCEP CA certificate (PEM) |

> **Note:** The SQL uses `ON DUPLICATE KEY UPDATE` with a `referenceTime` guard — records whose `updated_at` differs from the canary value are left untouched, making the migration safe to re-run.
