A minimal HTTP server designed to simulate slow webhook responses by introducing a configurable delay before responding to any incoming request.

## Key Components

- **`DELAY` constant** — Controls the simulated response latency (default: `10s`). Adjust to mimic slow webhook endpoints during testing.
- **HTTP handler (`/`)** — Catches all incoming requests, logs the method, path, and request body, sleeps for `DELAY`, then returns an empty response.
- **`SERVER_PORT` env var** — Overrides the default listen port (`:4648`).
- **Graceful shutdown** — Listens for `SIGINT`/`SIGTERM` signals to cleanly stop the server.

## Usage Example

```bash
# Run with default port and delay
go run main.go

# Run on a custom port
SERVER_PORT=:8080 go run main.go
```

Incoming requests are logged to stdout:

```text
POST /webhook | BODY: {"event":"mdm_enrolled","host_id":42}
```

To change the simulated delay, edit the `DELAY` constant before building:

```go
const DELAY = 30 * time.Second // simulate a very slow webhook
```

## Notes

- This is a **testing/development utility**, not production middleware.
- The handler accepts all routes and methods — useful for catching arbitrary Fleet webhook payloads.
- `ReadHeaderTimeout` is set to `30s` to prevent slow-header attacks while still allowing the body delay simulation to proceed normally.
