A webhook server that listens for Fleet device unenrollment events and removes the corresponding device from Jamf MDM management by serial number.

## Key Components

| Component | Description |
|---|---|
| `jamfClient` | HTTP client struct that holds the Jamf instance URL and bearer token |
| `newJamfClient` | Constructor that authenticates with Jamf and returns an initialized client |
| `getBearerToken` | Authenticates via Basic Auth against `POST /api/v1/auth/token` and returns a JWT |
| `getJamfID` | Looks up a Jamf computer record by hardware serial number via the Classic API (XML) |
| `unmanageDevice` | Sends an `UnmanageDevice` command to Jamf for a given computer ID |
| `main` | Starts the HTTP webhook server on the configured port |

## Usage Example

Build and run the server, pointing it at your Jamf instance:

```bash
go build -o jamf-unenroll .
./jamf-unenroll \
  --username admin \
  --password secret \
  --url https://yourcompany.jamfcloud.com \
  --port 4648
```

Fleet should be configured to POST a webhook payload to this server on device unenrollment. The server expects a JSON body matching the Fleet host webhook format:

```json
{
  "host": {
    "hardware_serial": "C02XG123JGH7"
  }
}
```

On receipt, the server will:
1. Resolve the serial number to a Jamf computer ID via `GET /JSSResource/computers/serialnumber/{serial}`
2. Issue `POST /JSSResource/computercommands/command/UnmanageDevice/id/{id}`

## CLI Flags

| Flag | Required | Default | Description |
|---|---|---|---|
| `--username` | ✅ | — | Jamf Pro username |
| `--password` | ✅ | — | Jamf Pro password |
| `--url` | ✅ | — | Jamf instance base URL |
| `--port` | ❌ | `4648` | Local server listen port |
