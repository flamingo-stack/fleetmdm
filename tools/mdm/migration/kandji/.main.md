A webhook server that listens for Fleet host events and automatically unenrolls devices from Kandji MDM by serial number via the Kandji REST API.

## Key Components

- **`main()`** — Starts an HTTP server (default port `:4648`, overridable via `SERVER_PORT` env var) with a single `POST` handler that parses Fleet webhook payloads and triggers Kandji unenrollment.
- **`unenroll(serialNumber string) error`** — Looks up a device in Kandji by serial number, then issues a `DELETE` request to remove it, which triggers MDM unenrollment.
- **`--subdomain`** flag — Kandji account subdomain (e.g. `acme` → `acme.api.kandji.io`).
- **`--api-token`** flag — Kandji Bearer token for API authentication.

## Usage Example

```bash
# Build and run the webhook server
go build -o kandji-unenroll .
./kandji-unenroll --subdomain=acme --api-token=your-kandji-token

# Override the default port
SERVER_PORT=:8080 ./kandji-unenroll --subdomain=acme --api-token=your-kandji-token
```

Configure Fleet to send a webhook to `http://your-server:4648/` on host events. The server expects a JSON body matching Fleet's webhook format:

```json
{
  "host": {
    "hardware_serial": "C02XJ0AAJGH5"
  }
}
```

On receipt, the server calls the [Kandji Devices API](https://api-docs.kandji.io/#78209960-31a7-4e3b-a2c0-95c7e65bb5f9) to resolve the serial to a `device_id`, then calls the [Delete Device endpoint](https://api-docs.kandji.io/#97deb582-d86c-444a-aa3b-3528b9a8478f) to unenroll it. Returns `204 No Content` on success.
