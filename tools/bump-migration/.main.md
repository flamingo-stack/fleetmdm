Updates the timestamp of a Fleet MDM database migration file and its associated test file, replacing all timestamp references in code and optionally regenerating the schema.

## Key Components

### `main()`
Entry point accepting two CLI flags:
- `--source-migration` *(required)* — filename of the migration to bump
- `--regen-schema` *(optional)* — runs `make dump-test-schema` after bumping

### `renameMigrationFiles()`
Renames the migration `.go` file and its corresponding `_test.go` file (if present) by substituting the old timestamp with the current UTC time in `YYYYMMDDHHmmss` format.

### `updateMigrationCode()`
Performs in-place string replacement within the renamed files, updating:
- `MigrationClient.AddMigration(Up_<ts>, Down_<ts>)` references
- `func Up_<ts>` / `func Down_<ts>` function signatures
- `func TestUp_<ts>` test function signatures

## Usage Example

```bash
# From the repository root — bump a migration timestamp
go run ./tools/bump-migration/main.go \
  --source-migration 20231015120000_add_hosts_table.go

# Bump and regenerate the DB schema
go run ./tools/bump-migration/main.go \
  --source-migration 20231015120000_add_hosts_table.go \
  --regen-schema
```

The migration directory is resolved relative to the working directory:

```text
server/datastore/mysql/migrations/tables/<timestamp>_<name>.go
server/datastore/mysql/migrations/tables/<timestamp>_<name>_test.go  ← renamed if present
```

> **When to use:** Run this tool when a PR's migration timestamp is older than an already-merged migration in `main`, to avoid ordering conflicts in the migration sequence.
