A testing utility that simulates Fleet's Orbit script execution pipeline on a host, allowing developers to test script execution locally without deploying Orbit or enrolling in a Fleet server.

## Key Components

| Component | Description |
|---|---|
| `main()` | Entry point; parses CLI flags, configures the script runner, and executes one or more scripts |
| `mockClient` | Stub implementation of the Fleet client interface; returns a hardcoded script payload and prints results to stdout |
| `scripts.Runner` | Orbit's script runner (from `orbit/pkg/scripts`), used directly to replicate production execution behavior |

**CLI Flags**

| Flag | Default | Description |
|---|---|---|
| `-exec-id` | _(auto-generated)_ | Execution ID for the script |
| `-content` | `echo "Hello"` | Script content to execute |
| `-scripts-disabled` | `false` | Simulates scripts being disabled on the host |
| `-scripts-count` | `1` | Number of scripts to run concurrently (IDs auto-generated when > 1) |

## Usage Example

```bash
# Run the default script (echo "Hello")
run-scripts

# Run a custom script with a specific execution ID
run-scripts -exec-id my-exec-id -content 'echo "Hello, world!"'

# Simulate scripts being disabled on the host
run-scripts -scripts-disabled -content 'echo "Hello, world!"'

# Run 10 scripts in sequence with auto-generated execution IDs
run-scripts -scripts-count 10
```

**Example output:**

```text
Script result for "a1b2c3d4-...":
  Exit code: 0
  Runtime:   1 second(s)
  Output:
Hello
---
```

## Notes

- When `-scripts-count` > 1 or `-exec-id` is empty, UUIDs are auto-generated via `github.com/google/uuid`.
- `mockClient.SaveHostScriptResult` prints results to stdout rather than reporting back to a Fleet server.
