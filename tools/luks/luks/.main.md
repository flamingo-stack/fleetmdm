Linux-only entry point that discovers the root disk, prompts the user for their existing LUKS passphrase via a Zenity GUI dialog, and escrows a fixed Fleet passphrase into an available LUKS key slot.

## Key Components

| Symbol | Description |
|---|---|
| `main()` | Orchestrates root-disk discovery, passphrase prompting, and LUKS key escrow |
| `lvm.FindRootDisk()` | Resolves the block device path for the root disk |
| `zenity.New()` / `prompt.ShowEntry()` | Renders a GUI entry dialog to collect the user's current LUKS passphrase |
| `luks.New(luks.AESXTSPlain64Cipher)` | Creates a LUKS device handle using the AES-XTS-Plain64 cipher |
| `device.AddKey()` | Adds the escrow key to the next free key slot (slots 1–7), retrying on bad passwords or occupied slots |
| `escrowPassPhrase` | Hardcoded Fleet escrow passphrase (`"fleet123"`) written into the selected key slot |

## Usage Example

This binary is built and run directly on a Linux host (build tag enforced). It requires `zenity` to be installed for the GUI prompt.

```bash
# Build (Linux only)
GOOS=linux go build -o luks-escrow ./main.go

# Run as root (LUKS device access requires elevated privileges)
sudo ./luks-escrow
```

**Flow at runtime:**

```text
1. Detect root disk  →  e.g. /dev/sda3
2. Prompt user       →  "Enter your existing LUKS passphrase"
3. Attempt AddKey    →  key slot 1 (increment on occupied slot)
4. Retry prompt      →  on ErrEncryptionKeyRejected (wrong passphrase)
5. Success           →  "Key escrowed successfully."
```

> **Note:** The escrow passphrase is hardcoded. In production usage this should be replaced with a dynamically provisioned secret supplied by the Fleet server. See the [repository source](https://github.com/flamingo-stack/fleetmdm/blob/main/main.go) for the full context.
