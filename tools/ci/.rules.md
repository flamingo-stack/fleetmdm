Defines static analysis rules for `go-ruleguard`, enforcing Fleet-specific code quality constraints during linting. Only compiled when the `ruleguard` build tag is active.

## Key Components

### `fmtErrorfWithoutArgs`
Flags `fmt.Errorf(msg)` calls with no format arguments and suggests replacing them with `errors.New(msg)` — avoiding unnecessary `fmt` import overhead.

### `createHttpClient`
Detects direct instantiation of `http.Client`, `http.Transport` (via struct literal or `new()`) and reports that `fleethttp.NewClient` should be used instead for consistent client configuration.

### `txCheck`
Enforces correct transaction handling within `mysql.Datastore` methods. Reports violations when:
- `withTx`, `withRetryTxx`, or `WithRetryTxx` callbacks directly access `ds.reader`/`ds.writer` instead of the provided transaction
- Datastore methods receiving a `sqlx.ExtContext` or `sqlx.ExecContext` as the first or second parameter bypass it by accessing `ds.reader`/`ds.writer`
- Anonymous function literals receiving a transaction interface access `ds.reader`/`ds.writer` directly

## Usage Example

These rules are applied via `golangci-lint` or `ruleguard` directly using the `ruleguard` build tag:

```bash
ruleguard -rules rules.go ./...
```

Or configured in `.golangci.yml`:

```yaml
linters-settings:
  gocritic:
    settings:
      ruleguard:
        rules: "path/to/rules.go"
```

> **Note:** The `txCheck` rule has a known limitation — it cannot recursively verify that callees of a Datastore method also avoid direct reader/writer access. See the inline TODO referencing [Fleet PR #8621](https://github.com/flamingo-stack/fleetmdm/pulls).
