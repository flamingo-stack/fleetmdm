Implements the `write` subcommand for the `redis-stress` tool, running a steady SET-only load against a Redis instance or cluster using configurable concurrency and throughput.

## Key Components

- **`runWrite(args []string)`** — Parses CLI flags, creates a Redis connection pool, spawns concurrent worker goroutines, and prints a summary of operations after the run completes.
- **`validateWriteFlags(...)`** — Pure validation helper that checks worker count, rate, duration, and key TTL bounds, returning the computed per-worker ticker period. Extracted for unit testability without a live Redis pool.

## Flags

| Flag | Default | Description |
|---|---|---|
| `-addr` | `127.0.0.1:6379` | Redis address (cluster node OK; auto-detected) |
| `-workers` | `1` | Concurrent SET goroutines |
| `-rate` | `1.0` | SETs per worker per second |
| `-duration` | `10m` | Total run time (`-wait` is a legacy alias) |
| `-key-prefix` | `stress_write_` | Key name prefix |
| `-key-ttl` | `10m` | Per-key Redis expiration |
| `-index-start` | `0` | Starting counter value per worker |
| `-debug` | `false` | Log every SET attempt |

## Usage Example

```bash
# Run 4 workers at 50 SETs/sec each for 2 minutes against a cluster node
redis-stress write \
  -addr 127.0.0.1:7000 \
  -workers 4 \
  -rate 50 \
  -duration 2m \
  -key-ttl 30s
```

```text
================ summary ================
elapsed:     2m0.012s
sets:        24001
errors:      0
ops/sec:     200.0
```

Each worker generates unique keys in the form `<prefix>w<id>_<index>` and issues `SET key 1 PX <ttl_ms>` commands via a time-based ticker. Atomic counters (`sets`, `errs`) aggregate results safely across goroutines without locks.
