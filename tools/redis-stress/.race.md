Implements a Redis SET-then-GET race detection mode (`race`) that identifies cases where a GET returns nil immediately after a successful SET, mimicking Fleet's `RedisKeyValue.Set`/`.Get` connection pool usage pattern.

## Key Components

- **`raceStats`** — Thread-safe counters using `atomic.Int64` tracking SET/GET counts, errors, nil-after-SET races, and stale reads.
- **`runRace(args []string)`** — Entry point that parses flags, builds a Redis pool, spawns concurrent workers, and prints a summary report. Exits with code `1` if any nil-after-SET race is observed.
- **`validateRaceFlags(workers, iterations int, ttl time.Duration) error`** — Validates CLI flag bounds independently of pool creation; ensures TTL is at least 1ms (Redis `PX 0` is invalid).
- **`raceOnce(...)`** — Core per-iteration logic: acquires two separate pool connections (one for SET, one for GET), optionally marks the GET connection read-only before wrapping it with `ConfigureDoer`, then records any nil or stale response.

## Usage Example

```bash
# Basic race detection against a local Redis cluster node
go run . race \
  -addr 127.0.0.1:7001 \
  -workers 100 \
  -iterations 2000 \
  -ttl 2m

# Test replica read lag explicitly (cluster mode)
go run . race \
  -addr 127.0.0.1:7001 \
  -cluster-read-from-replica=true \
  -explicit-readonly=true \
  -workers 50 \
  -iterations 1000
```

**Key flag notes:**
- `-explicit-readonly` must be set before `ConfigureDoer` wraps the connection — applying it after is a silent no-op in cluster mode.
- Exit code `0` = no race observed; exit code `1` = at least one nil-after-SET detected.
