Brief description: A CLI test tool that simulates the Fleet worker processor's Jira integration by creating Jira tickets for CVE vulnerabilities or failing policies, as if triggered by a real Fleet integration.

## Key Components

- **`main()`** — Entry point that parses CLI flags, validates inputs, wires up a mock Fleet datastore, and invokes the `worker.Jira` processor.
- **Mock datastore (`mock.Store`)** — Stubs `HostsByCVEFunc`, `AppConfigFunc`, and `TeamLiteFunc` to simulate Fleet's data layer without a live database.
- **`worker.Jira`** — The Fleet worker that builds and submits Jira issues; initialized with `FleetURL`, `Datastore`, `Log`, and a `NewClientFunc` backed by `externalsvc.NewJiraClient`.
- **`argsJSON`** — Dynamically constructed JSON payload passed to `jira.Run()`, shaped as either a `vulnerability` or `failing_policy` job argument.

## Usage Example

```bash
# Create a Jira ticket for a CVE vulnerability
export JIRA_PASSWORD="your-api-token"

go run main.go \
  -jira-url https://yourorg.atlassian.net \
  -jira-username user@example.com \
  -jira-project-key SEC \
  -fleet-url https://fleet.example.com \
  -cve CVE-2024-1234 \
  -epss-probability 0.85 \
  -cvss-score 9.1 \
  -cisa-known-exploit \
  -hosts-count 5 \
  -premium

# Create a Jira ticket for a failing policy
go run main.go \
  -jira-url https://yourorg.atlassian.net \
  -jira-username user@example.com \
  -jira-project-key OPS \
  -failing-policy-id 42 \
  -failing-policy-team-id 7 \
  -hosts-count 3
```

## Flags

| Flag | Required | Description |
|---|---|---|
| `-jira-url` | ✅ | Jira instance URL |
| `-jira-username` | ✅ | Jira username |
| `-jira-project-key` | ✅ | Jira project key |
| `-cve` OR `-failing-policy-id` | ✅ | Ticket trigger (mutually exclusive) |
| `JIRA_PASSWORD` (env) | ✅ | Jira API token |
| `-fleet-url` | No | Fleet server URL (default: `https://localhost:8080`) |
| `-hosts-count` | No | Number of affected hosts to simulate |
| `-premium` | No | Simulate a Fleet premium license |
