Defines the `dibble activities` command tree, which seeds fake Fleet activity rows directly into MySQL — one per activity type per batch — bypassing the Fleet service layer.

## Key Components

| Symbol | Description |
|--------|-------------|
| `categoryHelp` | Map from `seed.ActivityCategory` constants to human-readable descriptions used in subcommand `Long` help text. |
| `newActivitiesCmd()` | Constructs the root `activities` cobra command and registers all subcommands: `all` plus one per category defined in `seed.ActivityCategories`. |
| `addCommonFlags()` | Closure that attaches shared flags (`--dsn`, `--actor-id`, `--actor-name`, `--actor-email`, `--host-id`, `--batches`) to any subcommand. |
| `runCategory()` | Closure factory that returns a `cobra.Command.RunE` handler; reads flags, calls `seed.Activities`, prints a summary, and surfaces any errors. |

## Usage Example

```bash
# Seed one row of every activity type using default local DSN
dibble activities all

# Seed only script-related activities, two full batches
dibble activities scripts --batches 2

# Point at a non-default MySQL instance with a custom actor
dibble activities hosts \
  --dsn "fleet:secret@tcp(db.internal:3306)/fleet" \
  --actor-id 42 \
  --actor-name "*Ops Bot" \
  --actor-email "*ops@example.com" \
  --host-id 7
```

## Notes

- **Non-idempotent by design** — every run inserts a fresh batch tagged with a unique run ID; re-running produces new, distinguishable rows visible in the Fleet activity feed.
- All seeded name-like values are prefixed with `*` to make them easy to identify in the UI.
- Requires direct MySQL access; the default DSN (`fleet:insecure@tcp(localhost:3306)/fleet`) matches the local `docker-compose` dev environment.
- Invoking `dibble activities` with no subcommand prints help (mirrors `kubectl` conventions).
