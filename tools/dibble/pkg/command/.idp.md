Implements the `dibble idp` subcommand, which seeds IDP (Identity Provider) account data by writing directly to MySQL — creating `mdm_idp_accounts` rows for recently seeded users and assigning them round-robin to existing hosts via `host_mdm_idp_accounts`.

## Key Components

| Symbol | Description |
|---|---|
| `newIDPCmd()` | Factory function returning a configured `*cobra.Command` for the `idp` subcommand |
| `--dsn` | MySQL DSN flag; defaults to the local docker-compose dev environment (`fleet:insecure@tcp(localhost:3306)/fleet`) |
| `--user-count` | Number of recently seeded users to create IDP accounts for (default: `3`) |
| `--host-count` | Number of hosts to receive round-robin IDP account assignments (default: `5`) |
| `seed.IDP(...)` | Core seeder from the `seed` package that performs the MySQL writes |

## Usage Example

```bash
# Seed IDP accounts using default dev DSN
dibble idp

# Target a custom MySQL instance
dibble idp --dsn "fleet:password@tcp(db.internal:3306)/fleet"

# Expand coverage — 10 users, 20 hosts
dibble idp --user-count 10 --host-count 20
```

```go
// Internal wiring — registered in the root command
rootCmd.AddCommand(newIDPCmd())
```

> **Note:** This command requires direct MySQL access. Hosts must already be enrolled before running — use `dibble hosts` to provision them first. Users are fetched from the Fleet API sorted by `created_at DESC`, so dibble-seeded users appear ahead of the bootstrap admin.
