Implements the `dibble software` CLI command and its subcommands (`custom`, `maintained`, `all`) for seeding software installers and Fleet-maintained apps into a Fleet instance for testing purposes.

## Key Components

### `newSoftwareCmd() *cobra.Command`
Constructs the root `software` cobra command and registers three subcommands. Shared flags (`--team-id`, `--team-name`, `--maintained-count`) are injected into each subcommand via the internal `addCommonFlags` helper. The internal `mkSub` factory handles client initialization, team resolution, and delegates execution to the appropriate `seed` package function.

**Subcommands:**
| Subcommand | Description |
|---|---|
| `custom` | Uploads bundled installer fixtures (`.pkg`, `.deb`, `.msi`, `.exe`, `.rpm`, `.tar.gz`, `.ipa`) |
| `maintained` | Fetches and registers apps from the Fleet server's maintained-app catalog |
| `all` | Runs both `custom` and `maintained` sequentially |

### `resolveSoftwareTeamID(cmd *cobra.Command, c *Client) (uint, error)`
Resolves the target team ID with the following precedence:
1. `--team-name` — case-insensitive name lookup via `listExistingTeams`
2. `--team-id` — explicit integer ID (`0` = global/no-team scope)
3. Auto-pick — first team returned by Fleet; falls back to global scope if no teams exist

## Usage Example

```bash
# Upload custom installers to the first available team
dibble software custom

# Add 5 Fleet-maintained apps to a specific team by name
dibble software maintained --team-name "Engineering" --maintained-count 5

# Seed everything into the global (no-team) scope
dibble software all --team-id 0

# Target a specific team by ID
dibble software custom --team-id 3
```
