Seeds fake certificate authorities directly into a MySQL database by wiring the `dibble cas` subcommand to the `seed.CAs` function, bypassing the Fleet service layer entirely.

## Key Components

| Component | Description |
|---|---|
| `newCAsCmd()` | Constructs and returns the `cobra.Command` for the `cas` subcommand |
| `--dsn` flag | MySQL DSN connection string (default: `fleet:insecure@tcp(localhost:3306)/fleet`) |
| `--count` flag | Number of batches to write; each batch inserts one row per non-NDES CA type (default: `1`) |
| `seed.CAs(...)` | Underlying seeder that performs the direct MySQL writes |

## CA Types Seeded Per Batch

Each batch inserts one row for each of the following types:

- `custom_scep_proxy`
- `custom_est_proxy`
- `digicert`
- `hydrant`
- `smallstep`

A single `NDES` row is inserted once at run start (Fleet enforces a one-row limit for NDES).

> **Note:** Encrypted secret columns are left `NULL`. Seeded CAs appear cleanly in the Fleet UI but will fail any `request_certificate` call — intentional for seeding/testing purposes. Names are prefixed with `*` plus a per-run tag to distinguish dibble-planted rows from real data.

## Usage Example

```bash
# Seed one batch of CAs using the default DSN
dibble cas

# Seed 5 batches against a custom MySQL instance
dibble cas --count 5 --dsn "fleet:secret@tcp(db.internal:3306)/fleet"
```
