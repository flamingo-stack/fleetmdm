Seeds MDM configuration profiles for both Apple (`.mobileconfig`) and Windows (`.xml`) platforms via the Fleet API, gating uploads based on which MDM stacks are enabled.

## Key Components

### `Profiles(c Client, log Logger, theme themes.Theme, teams []Team, count int) Result`
Main entry point. Checks MDM enablement via `GET /api/latest/fleet/config`, then posts `count` global profiles (alternating Apple/Windows) and one Apple + one Windows profile per team using `POST /api/latest/fleet/configuration_profiles`.

### `mdmConfigSubset`
Minimal struct for deserializing only the MDM-relevant fields from `GET /config`, avoiding the overhead of the full response.

### `randomUUIDv4() string`
Generates a cryptographically random RFC 4122 v4 UUID using `crypto/rand`. Used to give each Apple profile a unique `PayloadIdentifier`, preventing macOS install collisions across seed runs.

### `sanitizeProfileName(s string) string`
Normalizes a theme-picked name into a filesystem/identifier-safe string (lowercase, spaces/punctuation replaced with hyphens).

### Embedded Templates
- `templates/profile.mobileconfig.tmpl` — Apple profile template with `{{NAME}}`, `{{IDENT}}`, `{{UUID}}` placeholders
- `templates/profile.windows.xml.tmpl` — Windows profile template with `{{NAME}}`, `{{LOCURI}}` placeholders

## Usage Example

```go
teams := []seed.Team{{ID: 1}, {ID: 2}}

result := seed.Profiles(client, logger, themes.Default, teams, 10)

fmt.Printf("Created: %d, Skipped: %d, Errors: %d\n",
    result.Created, result.Skipped, len(result.Errors))
```

> Profile names are derived from the `theme` via `themes.Pick`, ensuring each seed run produces distinct, human-readable identifiers. If neither Apple nor Windows MDM is configured, the function returns early without making any upload requests.
