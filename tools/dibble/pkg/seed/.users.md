Creates and seeds Fleet user accounts with cycling roles (observer → admin → gitops) for development and testing environments.

## Key Components

### Constants & Variables

- **`SeededUserPassword`** – Shared password (`DibbleSeed123!`) assigned to all seeded users. Never use against production deployments.
- **`seededRoles`** – Ordered slice of Fleet roles that cycle round-robin across created users: `observer`, `observer_plus`, `maintainer`, `admin`, `gitops`.

### Functions

- **`Users(c Client, log Logger, theme themes.Theme, count int) Result`** – Creates `count` users via `POST /api/latest/fleet/users/admin`. Names and emails are derived from the provided theme. GitOps users are automatically flagged `api_only: true`. Skips users that already exist rather than erroring.

## Usage Example

```go
result := seed.Users(client, logger, themes.FantasyTheme, 10)

fmt.Printf("Created: %d, Skipped: %d, Errors: %d",
    result.Created,
    result.Skipped,
    len(result.Errors),
)
```

## Behavior Notes

| Role | `api_only` | Auth Method |
|---|---|---|
| `observer` / `observer_plus` / `maintainer` / `admin` | `false` | Password |
| `gitops` | `true` | API token only |

Roles are assigned by index modulo (`i % len(seededRoles)`), so a `count` of 5 produces exactly one user per role; `count` of 11 wraps around and produces two observers, two `observer_plus`, etc.
