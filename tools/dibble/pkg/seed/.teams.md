Provides team seeding logic for the Fleet MDM database, creating a specified number of named teams via the Fleet API and returning their IDs for use by downstream seeders.

## Key Components

- **`Team`** — Minimal struct holding a team's integer `ID` and `Name`, passed to downstream seeders (policies, profiles, scripts).
- **`Teams()`** — Main seeder function. Creates `count` teams using theme-generated names. Handles three cases per team: successful creation, name conflict (skips and resolves the existing team's ID), or hard error.
- **`findTeamByName()`** — Fetches up to 500 teams from the API and returns the matching `Team` by name. Supports both `teams` and `fleets` response keys for API version compatibility.
- **`errTeamNotFound`** — Sentinel error type for a missing team lookup, allowing callers to distinguish "not found" from network/auth failures using `errors.As`.
- **`teamCreateResp` / `listTeamsResp`** — Internal response structs that handle both `team`/`fleet` and `teams`/`fleets` JSON keys across API versions.

## Usage Example

```go
client := seed.NewClient(baseURL, token)
logger := seed.NewLogger(os.Stdout)

teams, result := seed.Teams(client, logger, themes.Aviation, 5)
if len(result.Errors) > 0 {
    log.Fatalf("team seeding errors: %v", result.Errors)
}

// Pass team IDs to downstream seeders
for _, t := range teams {
    seed.Policies(client, logger, t, 3)
}
```

## Notes

- Both `team` and `fleet` JSON response keys are supported, accommodating Fleet API version differences.
- A name-conflict on creation triggers a non-fatal lookup; if the team has since been deleted, the entry is silently skipped rather than blocking the run.
- `findTeamByName` fetches a maximum of 500 teams in a single page — runs seeding more teams than this limit may not resolve conflicts correctly.
