Seeds saved scripts into Fleet MDM by posting shell (`.sh`) and PowerShell (`.ps1`) scripts globally and per-team via multipart upload to the Fleet scripts API.

## Key Components

### `Scripts(c Client, log Logger, theme themes.Theme, teams []Team, count int) Result`

Main seeder function that creates themed script entries across global and team scopes. Alternates between `.sh` and `.ps1` extensions based on index, generating minimal stub content for each script type.

**Parameters:**

| Parameter | Description |
|-----------|-------------|
| `c` | Fleet API client used to POST multipart requests |
| `log` | Logger for progress output |
| `theme` | Theme source for generating script names |
| `teams` | List of teams to receive one seeded script each |
| `count` | Number of global scripts to create |

**Returns:** A `Result` with `Created`, `Skipped`, and `Errors` counts.

## Usage Example

```go
result := seed.Scripts(
    client,
    logger,
    themes.Default,
    []seed.Team{{ID: 1, Name: "Engineering"}},
    5,
)
fmt.Printf("created=%d skipped=%d errors=%d\n",
    result.Created, result.Skipped, len(result.Errors))
```

## Notes

- Global scripts cycle through `.sh` and `.ps1` by `i % 2`
- Each team receives exactly one script (index `0`, always `.sh`)
- Multipart form uses field name `"script"` with the filename carrying the extension
- Team scoping uses the `fleet_id` field (Fleet's internal rename from `team_id`)
- Duplicate scripts are silently skipped via `IsAlreadyExists` check
- Script bodies are minimal stubs: `echo 'dibble was here'` (bash) or `Write-Host 'dibble was here'` (PowerShell)
