A minimal mTLS (mutual TLS) test server that generates a self-signed server certificate at startup and requires clients to present a certificate signed by a specified CA.

## Key Components

| Component | Description |
|---|---|
| `main()` | Entry point; parses flags, loads the client CA pool, generates a self-signed server cert, and starts an HTTPS server with `tls.RequireAndVerifyClientCert` |
| `mtlsHandler()` | HTTP handler that extracts the peer certificate from the TLS state and returns the client's CN, issuer, and subject as an HTML response |
| `generateSelfSignedCert()` | Generates an ephemeral 2048-bit RSA key pair and a self-signed X.509 certificate valid for 24 hours, supporting both DNS names and IP SANs |

## CLI Flags

| Flag | Default | Description |
|---|---|---|
| `--ca-cert` | `ca.crt` | Path to the CA certificate used to verify client certificates |
| `--addr` | `:8443` | Address and port to listen on |

## Usage Example

```bash
# Start the server with a custom CA cert and address
go run main.go --ca-cert /path/to/ca.crt --addr :9443

# Test with curl, providing a client certificate signed by the CA
curl --cacert /dev/null -k \
  --cert client.crt \
  --key client.key \
  https://localhost:9443/
```

> **Note:** The server cert is self-signed and ephemeral — regenerated on every startup. Pass `-k` or `--insecure` in curl (or supply the server cert explicitly) to bypass server cert verification during testing.
