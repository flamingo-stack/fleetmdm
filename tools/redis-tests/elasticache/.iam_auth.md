A CLI test tool for validating IAM-based authentication connectivity to an AWS ElastiCache (Redis) endpoint. Intended for development and debugging, not production use.

## Key Components

- **CLI Flags** — Accepts connection parameters via flags: `-addr`, `-user`, `-pass`, `-tls`, `-assume-role`, `-external-id`, `-region`, and `-cache-name`
- **`redis.PoolConfig`** — Constructs a Fleet Redis pool configuration with optional STS assume-role, TLS, and IAM credentials
- **`redis.NewPool`** — Initializes the Redis connection pool using the provided config
- **PING Test** — Executes a `PING` command via `redigo` to verify the connection is live

## Usage Example

```bash
go run iam_auth.go \
  -addr "my-cluster.abc123.cache.amazonaws.com:6379" \
  -user "fleet-iam-user" \
  -tls \
  -region "us-east-1" \
  -cache-name "my-elasticache-cluster" \
  -assume-role "arn:aws:iam::123456789012:role/MyRole" \
  -external-id "my-external-id"
```

On success:

```text
✅ PING successful: PONG
```

On failure (missing address):

```text
Fatal: ElastiCache address is required (-addr flag)
```

## Notes

- The `-addr` flag is the only required argument; all others are optional
- STS assume-role (`-assume-role`) and external ID (`-external-id`) support cross-account IAM auth scenarios
- The `gocritic` linter is suppressed via `//nolint:gocritic` since this is a test/debug tool
