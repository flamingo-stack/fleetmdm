Entry point for the Fleet Slack bot that wires together all service clients, registers Slack handlers, and starts the application with GitHub webhook support.

## Key Components

| Export / Instance | Description |
|---|---|
| `github` | `GitHubClient` instance for reading/writing files in the GitOps repo |
| `mcpClient` | `McpClient` instance connected to the Fleet MCP server for tool queries |
| `claude` | `ClaudeClient` instance backed by Anthropic, with MCP tool access |
| `app` | Slack Bolt `App` running in Socket Mode with custom HTTP routes |
| `read_gitops_file` | Local MCP tool that lets Claude safely read files from the GitOps repo via the GitHub API |

**Custom HTTP Routes**

| Route | Method | Purpose |
|---|---|---|
| `/healthz` | GET | Liveness probe returning `{ ok: true }` |
| `/github/webhook` | POST | Receives GitHub webhook events for CI auto-fix |

## Usage Example

```bash
# Start the bot (entry point is called directly by Node)
node app.js
```

The startup sequence runs in this order:

```javascript
// 1. MCP connection is attempted (non-fatal if it fails)
await mcpClient.connect();

// 2. Slack app starts in Socket Mode
await app.start();

// Output confirms active configuration:
// Fleet is running!
//   Repo: your-org/your-repo
//   Branch: main
//   MCP: https://mcp.example.com
//   Webhook: /github/webhook (port 3000)
//   CI auto-fix: enabled (check: fleet-check)
```

> **Note:** MCP connection failures are non-fatal — the bot starts regardless, but Fleet tool queries via Claude will be unavailable until the MCP server is reachable.

## Path Safety — `read_gitops_file`

The local tool enforces a strict allowlist before proxying any file read through the GitHub API:

```javascript
// Only these paths are permitted:
// - default.yml          (root config)
// - fleets/**            (fleet definitions)
// - lib/**               (shared policy libraries)

// Absolute paths and directory traversal (../) are always rejected.
```
