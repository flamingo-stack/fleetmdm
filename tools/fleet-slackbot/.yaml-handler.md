Utility module for parsing, serializing, diffing, and validating YAML files used in the FleetMDM GitOps workflow — covering fleet team configs and policy definitions.

## Key Components

| Export | Description |
|---|---|
| `parseYaml(content)` | Parses a YAML string into a JavaScript object using `js-yaml` |
| `dumpYaml(obj)` | Serializes a JS object back to a YAML string with consistent formatting (2-space indent, no line wrapping) |
| `generateDiffSummary(filePath, original, modified, maxLen?)` | Produces a unified diff string between two file versions, truncated to `maxLen` (default 2800 chars) for Slack display |
| `validateTeamYaml(content, filePath?)` | Validates fleet team YAML structure; allows `unassigned.yml` to omit the `name` field |
| `validatePolicyYaml(content)` | Validates policy YAML entries for required fields (`name`, `query`, `critical`, `description`, `resolution`) and valid `platform` values |
| `validateProposedChanges(changes)` | Guards against committing placeholder or suspiciously short content; throws on the first violation |
| `validateResolvedChanges(changes)` | Runs schema validation on a batch of resolved changes, routing to team or policy validators based on file path |

## Usage Example

```javascript
const {
  parseYaml,
  dumpYaml,
  generateDiffSummary,
  validateProposedChanges,
  validateResolvedChanges,
} = require("./yaml-handler");

// Parse and round-trip a YAML file
const obj = parseYaml(rawYamlString);
obj.name = "Updated Team";
const updated = dumpYaml(obj);

// Preview a diff before posting to Slack
const diff = generateDiffSummary("fleets/engineering.yml", rawYamlString, updated);
console.log(diff);

// Validate before committing
validateProposedChanges([
  { filePath: "fleets/engineering.yml", content: updated, isNewFile: false }
]);

// Schema-level validation on resolved changes
const warnings = validateResolvedChanges([
  { relPath: "fleets/engineering.yml", content: updated }
]);
if (warnings.length) console.warn(warnings);
```

## Notes

- `generateDiffSummary` handles new files (no `original`) by previewing the first 30 lines.
- `validateProposedChanges` rejects content matching placeholder patterns (`UNABLE_TO_GENERATE`, `PLACEHOLDER`, `TODO`, etc.) or content shorter than 50 characters for existing files.
- Valid `platform` values for policies: `darwin`, `windows`, `linux`, `chrome`.
