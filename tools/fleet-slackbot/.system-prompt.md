Defines the system prompt string for the Fleet AI assistant, instructing it on how to answer questions about a Fleet MDM deployment and propose GitOps configuration changes.

## Key Components

- **`SYSTEM_PROMPT`** — A single exported string constant containing all behavioral instructions for the LLM, covering:
  - **Mode selection logic** — Rules for choosing between informational (tool-based) and config-change (JSON GitOps PR) response modes
  - **Fleet MCP tool guidance** — Preferred tools, call ordering, efficiency limits, and chaining strategies
  - **Vulnerability investigation strategy** — Step-by-step playbook using `get_vulnerability_impact`, `get_vulnerability_hosts`, `run_live_query`, and `web_search`
  - **Repository structure** — The `it-and-security/` GitOps directory layout and file conventions
  - **YAML schemas** — Full schema references for fleet files, policy YAMLs, query YAMLs, software package YAMLs, and `default.yml`

## Usage Example

```javascript
import { SYSTEM_PROMPT } from './system-prompt.js';
import Anthropic from '@anthropic-ai/sdk';

const client = new Anthropic();

const response = await client.messages.create({
  model: 'claude-opus-4-5',
  max_tokens: 4096,
  system: SYSTEM_PROMPT,
  messages: [{ role: 'user', content: 'How many macOS endpoints do we have?' }],
  tools: fleetMcpTools,
});
```

## Notes

- The prompt enforces a hard rule against directing users to the Fleet UI or REST API directly — the assistant must answer using its tools
- Tool call efficiency is capped at ~12 calls per response to prevent runaway loops
- The `truncated: true` flag on vulnerability responses must be surfaced explicitly in answers
- See [`system-prompt.js`](https://github.com/flamingo-stack/fleetmdm/blob/main/system-prompt.js) for the full prompt source
