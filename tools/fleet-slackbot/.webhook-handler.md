Handles incoming GitHub webhook events for a Fleet GitOps bot, routing and processing PR comments and CI check failures to trigger AI-powered file revisions via Claude.

## Key Components

### `verifySignature(rawBody, signatureHeader, secret)`
Validates GitHub webhook payloads using HMAC-SHA256 signature verification with timing-safe comparison to prevent timing attacks.

### `sanitizeErrorMessage(err)`
Filters internal error details before surfacing messages to users, returning safe, user-friendly strings for AI service errors, rate limits, and unexpected failures.

### `createWebhookHandler(config, github, claude)`
Factory function returning the main HTTP request handler. Handles:
- Raw body streaming (capped at 1MB)
- Signature verification
- Event routing: `ping`, `check_run`, `issue_comment`, `pull_request_review_comment`
- Bot loop prevention (skips own comments)
- Author trust validation (OWNER, MEMBER, COLLABORATOR only)

### `processComment({ prNumber, commentBody, commentId, event, mentionedBot }, config, github, claude)`
Core comment processing pipeline — only activates when the bot is `@mentioned`. Fetches PR files, sends revision requests to Claude, validates proposed changes (path traversal, YAML schema), commits updates to the PR branch, and replies with a summary.

### `handleCheckRun(payload, config, github, claude)`
Responds to failed CI check runs on PRs. Includes loop prevention (max 2 consecutive auto-fix attempts) and delegates fix logic to Claude.

## Usage Example

```javascript
const { createWebhookHandler } = require("./webhook-handler");

const handler = createWebhookHandler(
  {
    webhook: { secret: process.env.WEBHOOK_SECRET },
    github: { botUsername: "fleet-bot", gitopsBasePath: "gitops" },
    ci: { autoFix: true, checkName: "validate-yaml" },
  },
  githubClient,
  claudeClient
);

// Attach to an HTTP server
const server = require("http").createServer(handler);
server.listen(3000);
```
