Generates realistic chart data for development and testing by writing rows to the `host_scd_data` table. Supports two backfill modes (accumulate/snapshot) and is safe to re-run via `ON DUPLICATE KEY UPDATE`.

## Key Components

| Symbol | Description |
|--------|-------------|
| `main()` | Entry point; parses CLI flags, connects to MySQL, resolves host/entity IDs, and invokes `backfill` |
| `backfill()` | Dispatcher that routes to `backfillHourly` or `backfillSnapshot` based on `snapshotDatasets` |
| `backfillHourly()` | Accumulate mode — writes one SCD row per hour per entity with a bounded `valid_from`/`valid_to` window |
| `backfillSnapshot()` | Snapshot mode — models per-entity state segments with occasional churn; final segment uses the open sentinel |
| `snapshotCardinality()` | Returns a long-tail random affected-host count mimicking real-world CVE distribution |
| `randomSubset()` | Returns a uniformly random `n`-sized subset of a host ID pool |
| `churn()` | Evolves a host set by dropping and adding a fraction of members, modeling patch/discovery events |
| `snapshotDatasets` | Registry of datasets using the snapshot model (`"cve"`) |
| `scdOpenSentinel` | `9999-12-31` timestamp used as `valid_to` to mark currently-open SCD rows |

## Usage Example

```bash
# Backfill 30 days of uptime data for all hosts
go run ./tools/charts-backfill --dataset uptime --days 30

# Backfill for specific hosts
go run ./tools/charts-backfill --dataset uptime --days 7 --host-ids 1,2,3

# Backfill CVE snapshot data using live tracked CVEs
go run ./tools/charts-backfill --dataset cve --days 30 --use-tracked-cves

# Custom MySQL connection
go run ./tools/charts-backfill \
  --mysql-dsn "fleet:fleet@tcp(localhost:3306)/fleet?parseTime=true" \
  --dataset cve --days 14
```
