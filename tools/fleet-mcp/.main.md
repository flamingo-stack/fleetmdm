Entry point for the Fleet MCP server. Handles CLI flag parsing, configuration validation, transport selection (SSE or stdio), and HTTP server setup with security middleware.

## Key Components

- **`limitBodyMiddleware`** — HTTP middleware that caps request bodies at 1 MiB (`maxRequestBodyBytes`) to prevent memory-exhaustion attacks from oversized payloads.
- **`main`** — Bootstraps the server: loads config, validates required env vars, initializes the Fleet client, sweeps leftover temp queries, then starts either a stdio or SSE transport.

## Transport Modes

| Flag | Behavior |
|---|---|
| `--transport=sse` (default) | HTTP server with bearer auth, rate limiting, and hardened timeouts |
| `--transport=stdio` | JSON-RPC over stdin/stdout; logs routed to stderr |
| `--seed` | Seeds Fleet with standard saved queries then exits |

## Middleware Stack (SSE only)

Applied outermost-first:

```text
Per-IP rate limiter → Body size limit → Route guard → Bearer auth → SSE handler
```

## Usage Example

```bash
# SSE mode (default)
FLEET_BASE_URL=https://fleet.example.com \
FLEET_API_KEY=your-api-key \
MCP_AUTH_TOKEN=your-token \
./fleet-mcp --transport=sse

# stdio mode (for MCP clients like Claude Desktop)
./fleet-mcp --transport=stdio

# Seed Fleet with standard queries and exit
./fleet-mcp --seed
```
